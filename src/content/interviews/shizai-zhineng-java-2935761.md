### 《参考解析》

1. **HashMap 结构**：数组加链表加红黑树。key 的 hash 高 16 位与低 16 位异或后对容量取模定位桶，链表长度到 8 且容量到 64 转红黑树，负载因子 0.75 触发扩容，扩容时按高位拆分节点。容量取 2 的幂是为了用位运算替代取模。

2. **线程安全替代**：`ConcurrentHashMap`。JDK 8 用 CAS 加 synchronized 锁单个桶头节点，只锁冲突的那一段而不是整表，读操作基本无锁（volatile 保证可见性），size 用 baseCount 加 CounterCell 分散计数。

3. **ArrayList 与 LinkedList**：ArrayList 基于数组，随机访问 O(1)、中间插入删除要搬移元素，扩容约 1.5 倍；LinkedList 基于双向链表，头尾操作快但随机访问 O(n)，每个节点额外存两个指针，缓存不友好。实际业务里 ArrayList 用得更多。

4. **线程池核心参数**：核心线程数、最大线程数、空闲存活时间、时间单位、工作队列、线程工厂、拒绝策略。执行顺序是先核心线程、再入队、队列满才扩到最大线程、再满才拒绝。队列要有界，否则最大线程数形同虚设。

5. **synchronized 原理**：修饰代码块用 monitorenter/monitorexit，修饰方法用 ACC_SYNCHRONIZED 标志；锁状态从无锁、偏向锁、轻量级锁（CAS 自旋）到重量级锁（操作系统互斥量）逐级升级，升级不可逆。

6. **公平锁**：`ReentrantLock(true)` 是公平锁，按等待队列顺序获取；`ReentrantLock(false)` 和非公平的 synchronized 都允许插队，吞吐更高但可能饥饿。公平锁维护队列有额外开销。

7. **ThreadLocal 内存泄漏**：ThreadLocalMap 的 key 是弱引用，value 是强引用。ThreadLocal 对象被回收后 key 变成 null，但 value 还被线程持有，线程池里线程长期存活就一直不释放。所以用完必须 `remove()`。

8. **JVM 内存区域**：线程私有的程序计数器、虚拟机栈、本地方法栈；线程共享的堆和方法区（元空间）。堆分新生代（Eden + 两个 Survivor）和老年代。要能接上「对象什么时候进老年代」（年龄达到阈值、大对象直接进、动态年龄判断）。

9. **InnoDB 与 B+ 树**：数据按主键组织成聚簇索引，叶子节点存整行；二级索引叶子存主键值，查非索引列要回表。B+ 树层级低、非叶子只存键、叶子有链表，适合范围查询和排序。

10. **隔离级别**：读未提交、读已提交、可重复读、串行化。MySQL 默认可重复读，靠 MVCC 加间隙锁在一定程度上避免幻读。

11. **索引失效**：函数或运算作用于索引列、隐式类型转换、前导模糊匹配、or 连接非索引列、联合索引不满足最左前缀、区分度太低时优化器放弃索引。最终以执行计划为准。

12. **Redis 为什么快**：纯内存操作、单线程避免锁竞争和上下文切换、IO 多路复用处理连接、高效的数据结构（SDS、跳表、listpack）、合理的编码切换。

13. **使用场景**：缓存、分布式锁、计数器与限流、会话、排行榜（zset）、消息队列（stream）、去重（set/布隆过滤器）。

14. **RDB 与 AOF**：RDB 是定时快照，文件小、恢复快，但可能丢最后一次快照后的数据；AOF 追加写命令，实时性好、可配置每秒同步，文件大、恢复慢。生产常用混合持久化。

15. **穿透、击穿、雪崩**：穿透是查不存在的数据，用布隆过滤器或空值缓存；击穿是热点 key 过期瞬间大量请求回源，用互斥锁或逻辑过期；雪崩是大量 key 同时失效或 Redis 整体故障，用过期时间打散、多级缓存和熔断降级。

16. **Kafka 消息丢失**：生产端要 `acks=all` 并处理发送失败；broker 端要足够的副本和 `min.insync.replicas`；消费端要处理完再提交位点，失败进重试或死信。丢消息一定是这三段之一。

17. **保证顺序**：同一业务 key 发到同一分区（按 key 哈希），单分区内天然有序；消费端单线程处理该分区，或者按 key 做本地队列串行消费。要扩分区就会破坏全局顺序，只能保证分区内有序。
