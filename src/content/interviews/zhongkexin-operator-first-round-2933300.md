### 《参考解析》

**矩阵乘优化的答题框架是「从算法到硬件」**：算法层用分块（tiling）提高数据复用、减少访存；循环层做循环交换 / 展开（loop unrolling）、寄存器分块、软件流水；内存层用 shared memory / L1 暂存 A、B 的子块，避免重复从全局内存读；指令层用向量化（AVX / NEON）或 Tensor Core 的 MMA 指令；并行层用 OpenMP 多线程按行 / 列切分、MPI 在节点间按 2D 网格切分（Cannon / SUMMA 算法），GPU 上用 CUDA 的 thread block tile + 共享内存 + 双缓冲。性能分析工具要具体说：CPU 上 perf / VTune 看 cache miss 与 IPC，GPU 上用 Nsight Compute 看 occupancy、内存吞吐、Tensor Core 利用率，MPI 用各自的 tracing 工具看通信占比。

**稠密 vs 稀疏的核心差异是「访存模式」**：稠密矩阵乘规整、连续、可以靠 tile 与向量化把算力打满，瓶颈是计算；稀疏矩阵大多不规则、有大量零、压缩存储（CSR/CSC/COO、块稀疏），瓶颈变成访存与负载不均——优化思路转向「减少无效计算」（跳零、合并行）、「提升访存局部性」（按非零分布重排、块化）、「负载均衡」（按非零数分块而不是按行数）、以及选对 SpMV / SpGEMM 的并行策略（行并行、非零并行、超节点）。一句话：稠密优化「让算力不空转」，稀疏优化「让内存不白读」。

**「懂 OpenMP / MPI 吗」这种开放问法最好给「用过 + 场景 + 踩过什么坑」**：OpenMP 是共享内存多线程（`#pragma omp parallel for` 加调度策略 static/dynamic/guided，注意伪共享与数据竞争），MPI 是分布式进程间通信（点对点、集合通信，注意通信与计算重叠、避免 all-reduce 成瓶颈），两者常组合成混合并行；CUDA 则要说清 grid-block-thread 层级、共享内存与同步、warp 分歧、合并访存。

**论文投稿周期类问题看着水，其实在确认「这篇论文是不是你自己做的」**：能说出投稿到几轮审稿、审稿意见具体提了什么、你怎么改的，比只报录用结果可信得多。
