### 《面试题目》

1. 缓存穿透怎么答？
2. 穿透、击穿、雪崩怎么区分？
3. 你的回答主线是什么？
4. 参数校验放在哪一层？能挡掉多少？
5. 空值缓存的 TTL 设多长？踩过什么坑？
6. 布隆过滤器的边界是什么？本地布隆还是 Redis 布隆？
7. 空值缓存和布隆冲突吗？
8. 如果攻击者每次用不同 key 呢？
9. 一句话总结这道题怎么答？

### 《参考解析》

**先划清三个概念**：穿透是查的数据在缓存和 DB 里都不存在，请求每次绕过缓存打到 DB，通常是恶意构造不存在的 key；击穿是单个热点 key 过期瞬间大量并发回源；雪崩是大批 key 同时失效或 Redis 整体不可用。穿透的关键特征是「数据本来就不存在」，所以没法靠预热缓存解决，因为压根没东西可预热。

**入口层**：最便宜的一层。key 是用户 ID 就校验非数字、负数、超出业务范围的 ID 直接返回参数错误，根本不让它进缓存逻辑。这一层能挡掉相当一部分脚本乱扫，成本几乎为零，放在最前面说。

**缓存层（空值缓存）**：查 DB 为空时也写一个占位值，TTL 给 30 到 60 秒。两个坑：TTL 设长了，数据后来真被写进 DB，用户会在这段时间看到「查无此人」，帖主第一次设了 10 分钟，测试造数据后一直刷不出来，排查半天才发现是空值缓存没过期；大量随机 key 会把 Redis 内存打满，等于把穿透转成了内存压力。修正做法是空值统一压到一分钟以内、写操作成功后主动删除对应 key、并监控空值 key 的占比。

**布隆过滤器**：放在缓存前面，判断「一定不存在」或「可能存在」。它有误判率（可能把不存在的判成存在），但没有漏判，所以是「宁可放过，不会错杀」；标准实现不支持删除，key 被删了过滤器里还留着，得用计数布隆或定期重建；数据量大时还要选本地布隆还是 Redis 布隆——本地省一次网络调用但多实例不同步，放 Redis 则每次多一跳。帖主项目数据量不大，没用布隆，用的是空值缓存加参数校验；被问「为什么不用」时如实说规模没到、引入布隆的运维与重建成本不划算，这种取舍说明反而加分。

**兜底层**：穿透往往是恶意的，挡不完。接口层要有限流（按 IP 或用户维度），DB 前面有连接池上限，出问题时降级返回默认值或友好提示，别让 DB 被打挂。这一层是保险，不是主力。

**两个追问**：「空值缓存和布隆冲突吗」——不冲突，是互补，空值缓存解决「已经查过一次的不存在 key」，布隆解决「第一次来的不存在 key」。「攻击者每次用不同 key 呢」——这正是空值缓存的软肋，每个新 key 都要打一次 DB 才能确认不存在，此时布隆的意义才出来，先靠布隆加限流顶住，事后离线分析日志把异常 key 段拉黑。

**一句话收尾**：穿透的本质是「查不存在的数据」，思路是尽量在到达 DB 之前判定它不存在——参数校验挡明显非法的、布隆挡大概率不存在的、空值缓存挡已经确认不存在的、限流兜住挡不完的。先把三类问题分清楚，再讲自己真正用了哪几层、为什么没用另一层，比背完整方案清单可信。
