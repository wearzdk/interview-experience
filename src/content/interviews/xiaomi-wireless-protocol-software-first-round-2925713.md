### 《面试题目》

> 原帖是一篇投递与面试记录，没有逐题清单，正文提到的考查点如下：

1. 深挖简历上的 3GPP 项目：项目做了什么、你负责哪一部分。
2. 协议层内容，尤其是 38.3×× 系列协议文本的理解。
3. 不只是读懂协议，还要能梳理出具体步骤并落地实现。
4. C 语言开发的基础知识。

### 《参考解析》

**38.3×× 指的是哪一层，先把这个坐标站稳**：3GPP 的 38 系列是 NR（5G 空口）的技术规范，其中 38.3×× 集中在层二与层三：38.300 是 NR 总体描述与流程，38.331 是 RRC（无线资源控制）协议，38.321 是 MAC，38.322 是 RLC，38.323 是 PDCP。面试官说「需要你不仅能读懂协议，还要能梳理具体步骤并落地实现」，意思是别停在「某个 IE 有哪些字段」这种查阅式理解上，而要能讲清一段完整流程：涉及哪几层、消息怎么在层间传递、状态机从哪个状态走到哪个状态、哪些定时器在起作用、失败分支怎么处理。准备时挑一条主线流程吃透，比通读规范有效得多，例如小区搜索与随机接入、RRC 连接建立与释放、切换（测量上报到切换完成）、调度请求与缓冲区状态上报。以随机接入为例，要能说清：UE 在什么条件下发起、MSG1 的前导码怎么选、MSG2 的响应里带什么、MSG3 里承载什么内容、竞争解决怎么做、每一步依赖哪份规范里的哪个过程，以及超时会触发什么。能把这条线按顺序讲完并指出实现落在哪个模块，基本就过掉了这轮最核心的考察。

**把「协议文本」翻译成「代码实现」才是这个岗位的真考点**：协议栈的实现大多用 C，规范里描述的是「功能和约束」，代码里体现的是状态机、消息队列、缓冲区与定时器。被问「这一步在代码里怎么实现」时，可用的框架是：状态在哪定义（枚举与状态迁移表）、消息怎么排队（中断与任务之间的环形缓冲或消息队列）、跨层调用怎么组织（函数指针表或回调注册）、定时器怎么管（一个统一的定时器轮，或者按协议规定的时长挂到调度器）。另外，规范里的「可选」「由实现决定」这类措辞正是面试官爱追问的地方——同一个字段不同厂商实现的取舍不同，答的时候可以说清你们版本的取舍和原因，而不是含糊过去。

**C 语言基础在协议栈场景里考什么**：这里的 C 题和互联网后台的 C 题不太一样，重点往往落在和协议报文打交道的部分。一是位域与打包：协议头是按比特定义的，`struct` 里的位域怎么写、编译器怎么排布、能不能保证跨平台一致（很多栈会选择手工移位拼装而不是依赖位域布局）。二是字节序：网络序是大端，本地可能是小端，收发两侧都要显式转换，漏一处就表现为「字段值明显偏大」。三是内存与边界：报文长度来自对端，任何按长度拷贝的地方都要先做范围校验，缓冲区溢出在协议栈里是安全问题；同时要说清发送缓冲什么时候能释放、为什么不能只存指针。四是 `const`、`volatile`、`static` 的用途：`volatile` 用在被中断改写、编译器不该优化的变量上，`static` 用于限制符号可见性，这类问题几乎每轮都会问。

**简历项目怎么讲，才扛得住「深挖」**：面试形式是飞书视频、全程围绕简历上的 3GPP 项目，所以项目介绍的准备方式应当是先划清边界——哪些模块是你写的、哪些是复用已有代码、你改动的接口和上下游。然后准备三条线：数据流（一条消息从哪进来、经过哪些函数、最后发到哪里去）、状态流（协议状态怎么迁移、谁触发）、问题线（遇到过的具体问题：时序不对、定时器超时、字段解析错误，怎么定位、怎么验证修复）。项目里如果有仿真或仪表工具（协议栈仿真、日志分析、抓包工具），一定要说清自己用它做过什么，这是这个方向和纯软件开发最能区分开的经验。原帖作者在 10 月 12 日一面后仍在等待结果，面试中的项目深挖与基础考察顺序也和这类岗位的常见节奏一致：先顺着简历往里问，再用 C 语言基础确认工程能力。
