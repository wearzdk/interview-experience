### 《参考解析》

**Stream**：Stream 是对集合的元素序列做声明式处理的抽象，本身不存储数据。中间操作（`filter`、`map`、`sorted`、`distinct`）是惰性的，只记录处理链；终止操作（`collect`、`forEach`、`reduce`、`count`）才触发实际计算。短路操作（`findFirst`、`anyMatch`、`limit`）可以在满足条件时提前结束。并行流基于 ForkJoinPool 的公共线程池拆分任务，适合计算密集且无共享可变状态的处理，涉及 IO 或需要顺序保证时不宜使用。还要注意装箱开销（用 `mapToInt` 等原始类型流）与在流中修改外部集合这类副作用。

**日志框架的分层**：SLF4J 是日志门面，负责统一 API；Logback、Log4j2 是实现。面试官追问「底层框架」时，答的是实现层。项目里通常用 SLF4J 的 API 打日志，由 Spring Boot 默认装配的 Logback 或替换后的 Log4j2 落盘，这样换实现不需要改业务代码。回答时把门面与实现分清，比只报一个名字完整。

**给老项目加日志**：先确认项目是否已有日志门面与实现，避免引入第二套。做法是定义注解（如 `@LogOperation`）标注需要记录的方法，用 Spring AOP 的环绕通知统一采集入参、返回值、耗时与异常，通过 MDC 写入 traceId 与用户标识，日志走异步 Appender。要注意切面不要切到基础设施自身造成递归、入参中的敏感字段要脱敏、异常要原样抛出不能被切面吞掉。

**日志策略**：按环境设级别，生产以 INFO 为主、异常打 ERROR 并带堆栈；按大小与时间双策略滚动（如单文件 100MB、按天归档），设置保留天数与总量上限防止磁盘打满；高并发场景用异步 Appender 与有界队列，明确队列满时的丢弃或阻塞策略；服务退出时确保刷盘。日志内容要包含时间、线程、traceId、模块与错误码，并对手机号、身份证等字段脱敏。

**在 Linux 上读大日志**：实时看用 `tail -f`，翻页用 `less`（`shift+F` 跟随）；按关键字查用 `grep -n`，配合 `-A` / `-B` / `-C` 看上下文；归档文件用 `zgrep` 直接查压缩包；按时间范围取用 `sed -n '/2026-11-10 10:00/,/2026-11-10 11:00/p'`，或用 `awk` 比较时间列做区间过滤；系统日志用 `journalctl --since`。文件极大时先用 `grep` 缩小范围再 `less` 查看，避免整文件载入。

**`#` 与 `$`**：`#{}` 是预编译占位符，MyBatis 会生成 `?` 交给 PreparedStatement，由驱动做参数绑定，能防 SQL 注入，也能复用执行计划；`${}` 是字符串直接替换，拼接后参与 SQL 解析。排序字段、表名这类不能作为参数绑定的位置只能用 `${}`，此时必须用白名单校验取值，不能接受用户原样输入。
