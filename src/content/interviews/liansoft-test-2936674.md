### 《参考解析》

**HTTP 与 HTTPS 的差别要落到「加密在哪一层、代价是什么」。** HTTP 明文传输，内容可被中间人窃听与篡改，默认 80 端口；HTTPS 是 HTTP over TLS，在应用层与传输层之间加了 TLS 握手，用非对称加密协商出对称密钥、之后用对称加密传数据，同时通过证书链验证服务端身份，默认 443。要能补三点：HTTPS 解决的是机密性、完整性、身份认证三件事，不解决「服务端本身有漏洞」；TLS 握手带来额外 RTT 与计算开销，所以有会话复用、TLS 1.3 的 1-RTT/0-RTT；证书过期、证书链不全、域名不匹配是线上最常见的 HTTPS 故障。

**三次握手的目的不是「确认两次」，而是双方都确认「自己的发送和接收都正常」并同步初始序列号。** 客户端发 SYN（带自己的 ISN），服务端回 SYN+ACK（带自己的 ISN、确认客户端的），客户端再回 ACK。少一次会怎样：两次握手时服务端无法确认客户端收到了自己的 SYN，历史上失效的连接请求到达会让服务端白白建立连接。四次挥手是因为 TCP 是全双工，一方发 FIN 只表示「我没有数据要发了」，另一方可能还有数据，所以要先 ACK、等自己数据发完再发 FIN，最后 ACK 并进入 TIME_WAIT。被追问 TIME_WAIT 为什么是 2MSL：保证最后一个 ACK 能到达（丢了对方会重发 FIN）、并让旧连接的报文在网络中消散，避免影响新连接。

**OSI 七层从下往上：物理、数据链路、网络、传输、会话、表示、应用。** 每层给一个典型协议和一句职责：物理层传比特（网线、光模块）；数据链路层成帧与差错检测、MAC 寻址（以太网、ARP）；网络层路由与 IP 寻址（IP、ICMP）；传输层端到端可靠或不可靠传输（TCP、UDP）；会话层建立与管理会话；表示层做编码、压缩、加密；应用层是 HTTP、DNS、SMTP。实战里更常用 TCP/IP 四层模型，被问到时要能说出对应关系（应用层对应 OSI 的上三层）。

**数据库与 Redis 这题通常会顺着项目问，准备一个「什么数据放 MySQL、什么放 Redis」的判断。** MySQL 存需要事务、复杂查询、强一致的数据；Redis 存热点读、计数器、排行榜（ZSet）、分布式锁、会话与限流令牌。要能说出 Redis 的常用数据结构与场景（String 缓存/计数、Hash 存对象、List 做队列、Set 做去重与交并集、ZSet 做排行榜与延时队列）、过期策略（惰性删除 + 定期删除）与内存淘汰策略（LRU/LFU/随机/TTL），以及缓存穿透、击穿、雪崩的应对。

**完整测试流程按阶段讲：需求评审 → 测试计划 → 用例设计与评审 → 环境与数据准备 → 执行与缺陷跟踪 → 回归 → 测试报告 → 上线验证与复盘。** 每一阶段说一句产出物：计划出排期与资源、用例评审出覆盖结论、执行出缺陷单与进度、报告出质量结论与风险评估。要强调「需求评审阶段就介入」和「缺陷要能复现、带日志与环境信息」，这两点体现工程习惯。

**测试用例的要点：** 用例编号、标题、优先级、前置条件、测试数据、操作步骤、预期结果、实际结果、备注（关联需求与缺陷）。好的用例要可重复执行、步骤无歧义、预期结果可判定；避免把多个验证点塞进一条用例。

**用例设计方法：** 等价类划分、边界值分析、判定表、因果图、正交实验、错误推测、状态迁移、场景法。场景法是从用户的真实使用路径出发，把业务流程拆成基本流（正常走通）与备选流（分支与异常），每条流串成一个场景再设计用例。举例：登录的基本流是输入正确账号密码验证码后进入首页；备选流包括密码错误、验证码过期、账号被锁、网络中断、重复提交。场景法的价值是覆盖「多个功能串起来才会出现」的问题，单功能用例测不出来。

**pytest 的用例发现规则：** 默认收集 `test_*.py` 或 `*_test.py` 文件里以 `test_` 开头的函数、以及 `Test` 开头类里以 `test_` 开头的方法。要自定义就在项目根目录或 `pytest.ini` / `pyproject.toml` / `setup.cfg` 里配 `python_functions`、`python_classes`、`python_files`，例如 `python_functions = check_*`。命令行的 `-k` 是按名字筛选执行、`-m` 按 marker 筛选，别和「发现规则」混淆。还要知道 fixture 的作用域（function/class/module/session）与 `conftest.py` 的生效范围。

**面向对象三大特性：** 封装是把数据与操作包在一起、只暴露必要接口并隐藏实现；继承是复用与扩展父类的行为，注意组合优于继承；多态是同一接口在不同实现上有不同行为，运行时多态靠虚函数/接口，编译期多态靠重载与泛型。面试官常追问「重载和重写的区别」「抽象类和接口怎么选」，准备一句即可。

**AI 工具这题不要只报名字，要给对比结论。** 可以按用途分：写代码与重构用一类（更擅长长上下文与多文件改动）、查资料与总结用一类（联网检索强）、生成测试用例与边界条件用一类。说清你在什么场景下用哪个、为什么，以及遇到过什么坑（比如生成的用例只覆盖正常流、需要自己补异常分支），比笼统说「都好用」有信息量。
