### 《参考解析》

**无领导小组讨论：银行这类群面的评分点不是「说得多」。** 面试官记录的是角色贡献与协作行为：谁在破题、谁在推进时间、谁在整合分歧、谁在总结。稳妥的打法是开场 30 秒内给出一个结构化框架（比如按人群分、按场景分、按可行性排序），中途主动做「记录 + 归类」，最后争取做 1 分钟总结发言把结论收口；被追问「刚才发言较少」时不要辩解，直接说明自己承担了记录与归纳的角色、并复述小组最终共识，通常反而加分。浦发那道「袜子与哪些科技结合」的题是典型开放题，判分看的是方案是否落到具体人群与可执行性，而不是创意本身有多花哨——每组给出 3 个方案时，要包含目标人群、使用场景和为什么这个人群会买单。

**Spring 相关：IOC、AOP、Bean 与注解要串成一条线。** IOC 是控制反转，把对象的创建与依赖装配交给容器，实现方式主要是依赖注入（构造器、setter、字段注入），好处是解耦与可测试；Bean 的生命周期大致是实例化 → 属性填充 → `BeanPostProcessor` 前置处理 → 初始化（`@PostConstruct`、`InitializingBean`）→ 后置处理（AOP 代理就在这里织入）→ 使用 → 销毁，作用域默认单例，要注意单例 Bean 里注入原型依赖或用可变成员变量带来的线程安全问题。AOP 是把横切关注点（日志、事务、权限、埋点）从业务代码里抽出来，Spring 用 JDK 动态代理（接口）或 CGLIB（类）在运行期生成代理对象，`@Transactional` 失效的常见原因就是自调用不走代理、方法非 public、异常被吞或类型不匹配。反射是运行期获取类信息并调用成员的能力，`Class.forName`、`getDeclaredMethod` 配合 `setAccessible` 是很多框架的底座，代价是性能与封装破坏，所以会有缓存 Method 对象、`MethodHandle` 等优化。常用注解按职责记：`@Component/@Service/@Repository/@Controller` 注册 Bean，`@Autowired/@Qualifier/@Value` 注入，`@Configuration/@Bean` 配置类，`@Transactional` 事务，`@RequestMapping` 系列做 Web 映射。

**分布式锁与缓存一致性：先说清场景再选方案。** 分布式锁的常见实现是 Redis（`SET key value NX PX` 加唯一 value，释放时用 Lua 比对 value 再删，防止误删别人的锁；锁续期可用看门狗机制）和 Zookeeper（临时顺序节点，天然处理会话失效）；要讲清三件事——加锁的粒度与超时时间怎么定、业务执行超过锁过期时间怎么办（续期或幂等兜底）、以及「锁只能减少竞争不能保证绝对互斥」（主从切换或网络分区下可能双持锁），所以关键操作仍要做幂等与乐观锁版本号。缓存一致性常见的是「先更新数据库再删除缓存」，配合延迟双删、消息队列补偿或订阅 binlog（Canal）异步失效；更稳的是在业务上接受最终一致并设置缓存过期时间兜底，把「读旧数据的窗口」压在业务可接受范围内。Redis 的搭建要能说出部署形态（单机、主从加哨兵、Cluster 分片），集群下多 key 操作要用 hash tag 让相关 key 落到同一槽位。

**数据库优化、线程池、MyBatis 拦截器与 HTTP 链路。** 数据库优化从 SQL 到架构分层答：SQL 层做执行计划分析（`explain` 看 type、key、rows、Extra）、避免函数包列与 `select *`、深分页改用游标或延迟关联；索引层按最左前缀与区分度设计联合索引、用覆盖索引减少回表、注意索引失效场景；表结构层做冷热分离与归档；架构层加缓存、读写分离与分库分表，并说清引入它们的代价（一致性、运维复杂度）。线程池要能讲清七个参数（核心数、最大数、空闲时间、时间单位、队列、线程工厂、拒绝策略）与执行顺序（先核心、再入队、队列满后扩到最大、再满则拒绝），以及为什么生产上要用有界队列（防内存打爆）和自定义拒绝策略（降级或落库重试）；线程数的经验取值要说明依据。MyBatis 拦截器（`Interceptor` 加 `@Intercepts`）基于 JDK 动态代理拦截 Executor、StatementHandler、ParameterHandler、ResultSetHandler 四个点，常用于分页、SQL 改写、多租户与审计，注意多拦截器时插件的包装顺序会影响执行次序。HTTP 请求链路可以用「DNS 解析 → 建立 TCP（含 TLS 握手）→ 发送请求 → 网关与负载均衡 → 应用处理（鉴权、参数校验、业务、缓存与数据库）→ 组装响应 → 回传并渲染」这条主线讲，中间补上连接复用、超时与重试、以及为什么不重试非幂等请求。

**动机与薪资类问题的答法。** 「为什么投递这家」「为什么这个岗位」在银行面试里权重很高，答法要落到具体：稳定性与业务场景、技术积累方向与岗位职责的对应、以及你了解到的该行在做什么（数字化、核心系统、数据中台均可）。被问「为什么填这么多期望年薪」不要改口，给出口径（同岗位公开薪资区间 + 城市生活成本 + 自身经历），并说明可协商的部分；被问「你有哪些不足」要挑真实的、且已有改进动作的短板，把重点放在改进行为上，别用「我太追求完美」这类套话。「接不接受转岗」这类问题先问清转岗的性质（是入职分配还是长期定岗），再给出有条件的肯定答复，同时了解清楚技术岗的通道是否还在。民生的二面问代码量与课程成绩，属于典型的背景核验，简历上写过的数字要能对上。
