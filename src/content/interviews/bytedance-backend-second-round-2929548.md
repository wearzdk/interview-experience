### 《面试题目》

1. 如何设计一个会议纪要 Agent？
2. 语音转录出现问题怎么解决？
3. 不考虑模型本身，从 Agent 角度出发怎么处理？
4. 如果某个节点重试多次还是出错怎么办？
5. 可能由什么原因导致？怎么解决？
6. 模型能力不足、执行出错或存在幻觉怎么解决？
7. 如何让模型拥有自进化能力？
8. 只沉淀成功案例吗？不考虑 badcase 吗？
9. 如何搭建知识库？
10. 文档输入很多怎么办？比如公司多年沉淀的业务文档非常庞大。
11. 算法：输出所有最长回文子串。
12. 算法：高并发数百万访问，统计输出访问次数前十的 IP 地址。

### 《参考解析》

**会议纪要 Agent** 可以拆成录音/转写、说话人分离、分段摘要、行动项抽取、纪要生成和回写六个环节。转写质量问题先做音频预处理（降噪、VAD、重采样），再考虑领域词表、热词和自定义语言模型；从 Agent 角度要加校验节点，比如用第二遍转写或关键词回查，低置信度片段标出来而不是硬编。

**重试与幻觉**：节点重试要有上限、退避和幂等，多次失败后走降级路径（跳过、标记人工、换模型），并把失败原因结构化记录。幻觉靠检索增强、引用约束、结构化输出和答案校验（规则 + 模型自检 + 人工抽检）控制；自进化不是让模型自己改自己，而是把 badcase 回流到评测集、提示词和工具链，定期回归。

**知识库**：文档先清洗、去重、按结构切片，保留元数据和权限；大规模文档用分层索引（目录/摘要/正文）、混合检索和按需加载，避免一次性全量 embedding。回答时先检索再生成，带引用，权限在检索前过滤。

**算法**：最长回文子串用中心扩展 O(n²) 或 Manacher O(n)，要求输出所有最长解时记录最大长度并收集同长度结果。Top10 IP 用哈希分片加小根堆：先分片统计每个 IP 的计数，再对各分片的 Top10 归并；内存不够就多轮分片或使用 Count-Min Sketch 加精确二轮。
