### 《参考解析》

**灰度数据要能自洽。** 200 多 UV、10% 灰度，推全量约两三千 UV，这个换算面试官当场做了，说明他在核对数字之间是否对得上。回答指标时先给口径：UV 按去重用户还是设备、统计窗口是哪几天、灰度是按用户哈希还是按流量比例。业务指标看任务完成率、攻略采纳率、商品点击与转化、用户留存与追问率；技术指标看首字延迟、端到端响应时间、token 消耗、工具调用成功率、错误率与降级率。

**工具调用成功率不等于准确率。** 成功率只能说明请求返回了 200，准确率要看返回内容是否满足用户约束。统计方式包括：在工具层校验参数（日期、地点、价格区间是否合法）、对结果做规则校验（距离排序、库存状态）、用模型或人工抽样评估、在线上埋点记录用户是否采纳与是否追问。发现不准确要靠抽样回放、负反馈入口、以及把「用户改口」当作信号。兜底手段是前置约束（把可选范围收窄）、结果校验失败时重试或换工具、最终由模型说明无法满足。

**RAG 的切分与检索。** 旅游知识库包含攻略、景点介绍、票务规则、FAQ，切分要按结构（标题层级、表格、条目）而不是固定字数，保留元数据（城市、景点、适用日期、来源），对长文档做父子块或摘要索引。检索可以用 BM25 加向量混合，再加重排；优化方向是查询改写、同义词与实体识别、按元数据过滤、调整 chunk 大小与重叠、评估召回率与答案忠实度。

**语义相似与自注意力。** 模型把 token 映射成向量，经过多层自注意力，每个位置根据与其他位置的相似度加权聚合信息，从而得到上下文相关的表示。自注意力用 Q、K、V：`Attention(Q,K,V) = softmax(QK^T / sqrt(d_k)) V`；点积衡量 query 与 key 的匹配程度，除以 `sqrt(d_k)` 防止维度大时点积过大导致 softmax 饱和。两句话的相似度通常取句向量余弦相似度，而不是直接比较 token 点积。

**Coze 工作流与 Agent 的差别。** 工作流把步骤、分支、工具调用写在编排里，行为可预测、易调试、成本可控，适合流程稳定的业务；Agent 让模型根据观察自主选择下一步，灵活但路径不确定、调试与成本控制更难。生产系统常用「工作流兜底 + 局部自主」的混合方式。

**自研与 SDK 的取舍。** 自研能贴合业务、控制提示与工具协议、便于排查；现成 SDK 在记忆、工具调用、重试、可观测性上更成熟，迭代快。判断标准是团队维护成本与业务差异化程度，不是「自研一定更好」。面试官质疑自研效果时，用评测数据回答：同一批任务下成功率、平均步数、延迟与成本各是多少。

**高并发活动页的优化分层。** 前端：静态资源 CDN、接口合并与缓存、按钮防重、限流与排队页、骨架屏。后端：无状态扩容、读写分离、热点缓存、异步化与消息队列削峰、连接池与线程池隔离、熔断降级。数据库：分库分表、索引优化、库存扣减用乐观锁或队列串行化、热点行拆分。运维：压测与容量规划、弹性伸缩、监控告警、灰度与预案。回答时先判断瓶颈在哪一层，再给手段，不要把所有方案堆一遍。
