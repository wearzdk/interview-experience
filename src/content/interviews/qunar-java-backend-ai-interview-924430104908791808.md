### 《面试题目》

1. JVM 为什么要进行堆内存分代？分代回收和垃圾对象的生命周期有什么关系？
2. 在高并发场景中，大量 CAS 操作持续失败会带来什么问题？应该如何优化？
3. CAS 如何避免 ABA 问题？版本号一定能够彻底解决 ABA 吗？
4. MySQL InnoDB 为什么选择 B+ 树作为索引结构，而不是普通 B 树或哈希表？
5. 为什么存储同样数量的数据时，B+ 树通常比 B 树更矮？
6. 在 MySQL 的单值等值查询中，为什么 B+ 树可能不会比树高更低的树结构慢？
7. 如果两个线程同时修改进程内的同一个全局变量，会产生什么问题？仅使用 volatile 是否足够？
8. 微服务架构中如何实现全链路 TraceId 透传和日志关联？

### 《参考解析》

1. 这类问题建议结合自己的项目经历和岗位要求准备具体案例，突出思考过程而非死记结论，面试官更看重解决问题的逻辑。
2. CAS通过比较并交换实现无锁更新，失败后需要重试；库存扣减等高竞争场景可以引入版本号或分段计数减少冲突概率，避免忙等消耗过多CPU。
3. 算法题先明确边界条件与不变量，再选择合适的数据结构；双指针、哈希表、递归/迭代是常见工具，目标是把复杂度控制在线性或对数级别。
4. 进程是资源分配的基本单位，线程是CPU调度的基本单位，协程是用户态的轻量级调度单位，切换成本远低于线程，但需要语言/运行时支持。
