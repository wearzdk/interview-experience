### 《参考解析》

**线程池与 submit**：核心参数是核心线程数、最大线程数、空闲存活时间与单位、工作队列、线程工厂、拒绝策略。提交任务时，核心线程未满就新建线程；核心满了进队列；队列满了且未到最大线程数就新建非核心线程；再满则执行拒绝策略。`submit` 内部把 Runnable/Callable 包装成 FutureTask，调用 `execute`；`FutureTask` 用 AQS 的 state 表示任务状态，`get()` 在未完成时把当前线程包装成等待节点挂起，任务完成时通过 `finishCompletion` 唤醒等待者，所以不是回调，而是状态加等待队列的线程间通信。`execute` 直接抛异常，`submit` 会把异常吞进 Future，调用 `get()` 才抛出。

**锁与升级**：Java 的锁包括 synchronized（JVM 内置，自动释放）、ReentrantLock（AQS，可中断、可超时、可公平）、读写锁、StampedLock（乐观读）、CAS 自旋。synchronized 的优化包括偏向锁、轻量级锁、自旋、锁消除、锁粗化。升级路径是无锁→偏向锁→轻量级锁→重量级锁：偏向锁把线程 ID 写进 Mark Word；竞争时在安全点撤销，升级为轻量级锁，线程在栈帧建 Lock Record 并用 CAS 指向它；自旋失败膨胀为重量级锁，进入 monitor 的等待队列。ReentrantLock 公平锁在 `tryAcquire` 里先检查队列是否有前驱，非公平锁直接 CAS 抢一次，抢不到再排队，因此非公平锁吞吐更高但可能饥饿。

**ThreadLocal 与泄漏**：每个 Thread 持有 ThreadLocalMap，key 是 ThreadLocal 的弱引用，value 是强引用。ThreadLocal 对象被回收后 key 变 null，但 value 仍被 Entry 强引用；线程池里的线程长期存活，这些 value 就一直无法回收，造成泄漏。`get`/`set` 会顺带清理部分 key 为 null 的 Entry，但不能保证清干净，所以用完必须 `remove`。异步线程拿不到主线程的 ThreadLocal，因为 ThreadLocalMap 挂在各自线程上；解决方案是手动把用户信息作为参数传递、用 `TaskDecorator` 在任务提交时捕获并回填、或使用 TransmittableThreadLocal（阿里 TTL）做线程池场景的传递。

**GC**：以 G1 为例，堆划分为大小相等的 Region，逻辑上分 Eden、Survivor、Old、Humongous。年轻代回收是 STW 的复制算法，存活对象复制到 Survivor 或晋升老年代；老年代达到阈值触发并发标记周期，先初始标记（STW）、再并发标记、重新标记（STW）、筛选回收，按回收收益选择 Region 做 Mixed GC。新生代对象朝生夕死、存活率低，适合复制算法，代价是浪费一部分空间；老年代存活率高，复制成本大，适合标记—清除或标记—整理，前者有碎片、后者停顿长。ZGC 用染色指针与读屏障做并发整理，把停顿压到毫秒级。

**并发累加**：10 个线程各加 100 次，最终值不确定，通常小于 1000，因为 `i++` 不是原子操作（读、加、写三步），会出现丢失更新。要精确得到 1000，可以用 synchronized、ReentrantLock、AtomicInteger 的 CAS、LongAdder 分段累加，或把每个线程的结果收集后汇总。线程数升高时 CAS 自旋冲突加剧，LongAdder 用 Cell 分散热点更合适；再往上可以考虑分片批处理、减少共享状态。

**事务隔离与索引**：四种隔离级别是读未提交（脏读）、读已提交（不可重复读）、可重复读（幻读）、串行化。InnoDB 默认可重复读，通过 MVCC 快照读避免不可重复读，用间隙锁/next-key lock 在当前读时尽量避免幻读。索引是 B+ 树：非叶子只存键、叶子存数据并用链表相连，扇出大、树高低、范围查询友好。页 16KB，bigint 主键 8 字节加 6 字节指针约 14 字节，一个非叶子页约存 1100 多个键，三层大约能支撑千万到亿级行，具体随行大小变化；回答时给出估算过程比背「三层」更好。

**Workflow 到 MCP 的升级**：Workflow 是固定编排，路径可预测但扩展新能力要改代码；MCP 把工具标准化暴露给模型，由模型按任务动态选择，适合工具多、组合不确定的场景。升级时把原有步骤拆成独立工具，定义输入输出、错误码与幂等语义，保留关键节点的确定性校验，用评测集对比升级前后的成功率与成本。风险是模型选错工具或参数，需要权限分级、只读与写工具分离、关键动作人工确认。

**Agent 执行模式**：常见有固定工作流、ReAct（推理—行动—观察循环）、Plan-and-Execute（先规划再逐步执行）、多 Agent 分工（规划者、执行者、评审者），以及带人工介入的 Human-in-the-loop。选型看任务开放程度与容错要求：流程稳定用工作流，开放任务用 ReAct，长任务用规划加分步验证。

**时钟夹角**：3:15 时，分针指向 3，为 90°；时针在 3 点基础上走了 15 分钟，即 15×0.5°=7.5°，位于 97.5°；两者夹角 7.5°。这类题先分别算两个针相对 12 点的角度再相减，注意时针连续移动。
