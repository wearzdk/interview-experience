### 《面试题目》

1. Java 面向对象的三大特性是什么？
2. 类和对象的区别是什么？
3. 索引的基本原理是什么？查询优化怎么做？
4. 哪些场景适合用 Redis 做缓存？
5. 缓存穿透、缓存击穿、缓存雪崩分别是什么，怎么解决？

### 《参考解析》

**三大特性**：封装把属性与行为包在类里、隐藏实现细节，通过访问修饰符与 getter/setter 控制访问，目的是降低耦合、便于维护；继承让子类复用父类的属性与方法，Java 类单继承、接口多实现，目的是复用与建立层次；多态是同一调用在不同对象上表现不同，方法重写是运行时多态、方法重载是编译时多态，目的是面向接口编程、便于扩展。产品经理答这题不必写代码，但要能说清「封装对应信息隐藏、继承对应复用、多态对应扩展点」。

**类与对象**：类是模板，定义属性、方法与构造器，不占实例内存；对象是按类创建出来的实例，有具体属性值、占用内存。用 `new` 创建，引用指向堆上的对象。这个区分在讨论「配置项与实例」「模板与具体活动」时可以直接借用。

**索引原理与查询优化**：InnoDB 用 B+ 树，非叶节点只存键、叶节点存数据并用链表相连，三层可支撑千万级数据；聚簇索引叶子存整行，二级索引叶子存索引列加主键，查非索引列要回表；联合索引遵循最左前缀，索引下推能在引擎层提前过滤。优化套路：先开慢查询日志定位 SQL，用 EXPLAIN 看 type、key、rows、Extra，判断是缺索引、索引失效、回表多还是排序开销；再建联合索引或覆盖索引、改写 SQL、避免在索引列上做函数运算、深分页改游标；数据量大再考虑分表、缓存、读写分离。产品经理理解这层，能在需求评审时判断「这个筛选条件会不会拖垮列表页」。

**Redis 的适用场景**：读多写少的热点数据（商品详情、配置、字典）、高频计数（点赞、阅读量、库存）、会话与验证码、分布式锁、排行榜（ZSet）、去重（Set、布隆过滤器）、简单队列（List、Stream）。不适合强一致且不能丢的数据、数据量远大于内存、写多读少且命中率低的场景。

**穿透、击穿、雪崩**：穿透是查一个库和缓存都没有的数据（如 id=-1），每次都打到库，解法是缓存空值、布隆过滤器、参数校验与限流；击穿是单个热点 key 过期瞬间大量并发回源，解法是互斥锁只放一个线程回源、逻辑过期后台异步重建、热点 key 不过期加定时刷新；雪崩是大量 key 同时失效或缓存服务宕机，解法是过期时间加随机值、集群高可用、多级缓存、限流降级与预热。三者的区别用一句话记：穿透查的是不存在的数据，击穿是一个 key 失效，雪崩是一批 key 失效或服务挂了。
