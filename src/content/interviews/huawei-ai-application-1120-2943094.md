### 《参考解析》

**Agent 的整体架构要能分层说清**：接入层（会话、鉴权、限流）、编排层（任务规划、状态机或图、工具路由）、能力层（工具集、检索、记忆）、模型层（模型选择、Prompt 模板、结构化输出）、可观测层（每步的工具、参数、结果、耗时、token 留痕）。面试官追问「任务流怎么编排」时，要落到具体的图结构：哪些节点是模型决策、哪些是确定性代码、条件边怎么判定、失败怎么回到上一步、循环上限是多少。把「模型只负责理解与决策、排序与校验交给程序」讲出来，比罗列框架名更有说服力。

**LangChain 与 LangGraph 的区别**：LangChain 提供的是链式组合与工具、检索、模型的统一封装，适合线性或简单分支的流程；LangGraph 把流程表达成带状态的图，节点是函数或模型调用，边可以是条件边，天然支持循环、人工介入（中断后恢复）、状态持久化与回放，适合需要多轮修正、长时间运行、或多 Agent 协作的场景。选择依据是流程里有没有环、需不需要在中断后恢复状态、需不需要可视化与逐步调试；简单问答用 LangChain 更轻，复杂任务用图更容易控制。

**记忆的分层**：短期记忆是当前会话的消息窗口（按 token 预算裁剪或摘要压缩）；长期记忆是持久化的用户画像与历史结论，需要写入策略（什么值得记）、检索策略（按什么召回）与遗忘策略（过期与冲突如何处理）；此外还有偏好记忆（输出风格、禁用词）与任务记忆（进行中的计划与中间结果）。工程上最容易出问题的是「全量塞进上下文」导致成本与干扰，正确做法是按需检索、把结构化事实与原文分开存。

**RAG 的完整链路**：文档解析（PDF 的版面、表格、扫描件 OCR）→ 切分（按标题层级或语义边界）→ 向量化与索引（向量库 + 关键词索引）→ 查询处理（改写、多路召回、过滤）→ 重排（cross-encoder 或模型打分）→ 组装上下文（控制长度、标注来源）→ 生成（要求引用、无依据时明说）。每个环节都能被追问：切分粒度怎么定、召回多少条、如何评估召回率、上下文冲突时听谁的。

**幻觉的来源与缓解**：预训练语料的统计拟合并不能保证事实正确，模型在知识缺失时会用流畅的语言补全；指令微调会强化「必须给出答案」的行为；上下文过长或检索到的内容自相矛盾时也会放大幻觉。缓解手段分三层：检索侧提高召回质量并给出处、生成侧要求「只依据给定材料、找不到就说不知道」并允许拒答、验证侧做事后校验（与来源比对、数值与实体核对、必要时用第二个模型或规则审查）。评测上要用「有答案 / 无答案」两类样本分别看，只测前者会把「敢于编造」误判成能力强。

**编辑距离**：`dp[i][j]` 表示把 `word1` 前 i 个字符变成 `word2` 前 j 个字符的最少操作数，转移是 `dp[i][j] = min(dp[i-1][j]+1, dp[i][j-1]+1, dp[i-1][j-1] + (word1[i-1] != word2[j-1]))`，边界是 `dp[i][0]=i`、`dp[0][j]=j`。时间与空间都是 O(mn)，空间可以用两行滚动数组压到 O(n)。面试里常接着问变体：只允许插入删除（最长公共子序列）、带权编辑距离、或是拼写纠错里的候选排序。

**Transformer 与 KNN 的对比**：Transformer 靠自注意力在序列内建模任意两个位置的关系，参数在训练时学得、推理时对每个输入做前向计算；KNN 是非参数方法，把样本存起来、推理时按距离找最近邻投票，无需训练但推理成本随样本量线性增长、对高维稀疏数据效果差。两者的连接点在于检索：RAG 的向量召回本质就是 KNN 的近似（HNSW、IVF），区别是距离度量与索引结构。被问到「底层算法」时要能给复杂度：暴力 KNN 是 O(Nd)，近似索引把查询降到亚线性但牺牲召回。

**研发过程的讲述框架**：需求与指标（要解决什么问题、怎么衡量）→ 方案选型（对比了哪些、为什么选这个）→ 实现与踩坑（数据、训练、服务化的具体问题）→ 上线与观测（灰度、指标、告警）→ 复盘（哪里做得不好、后来怎么改）。主管面尤其看重「你个人的判断」而不是团队做了什么，每一段都要能指出「这是我的决定，依据是什么」。

**主管面的常见题怎么答**：最难的技术问题要选一个「有明确卡点、你定位到根因、方案有取舍」的案例，讲清排查路径与验证方式，不要选「需求太急」这类非技术问题。跨团队配合要给出具体机制：接口对齐的方式、联调与排期的做法、出现分歧时的决策依据。为什么选华为要落到具体业务与个人规划，避免空泛地夸公司；「最近在学什么」要说清学了什么、为什么学、做出了什么。
