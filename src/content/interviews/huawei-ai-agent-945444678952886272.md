### 《面试题目》

1. 一面从简历和自我介绍里逐条往外挖，涉及的 Agent 与算法八股有哪些？
2. 手撕：有一堆石子，每次可以取的数量是一个不连续的集合，问先手是否必胜。

### 《参考解析》

**不连续取数的取石子：别套巴什，直接 DP**

经典巴什博弈里每次可以取 1~m 个，结论是 `n % (m+1) == 0` 时先手必败。但这题允许取的数量是一个不连续的集合（比如只能取 1、4、5 个），取模公式就失效了，必须回到状态转移。

设 `f[i]` 表示还剩 i 个石子、轮到当前行动者时是否必胜，则 `f[i] = 存在 k ∈ K 且 k ≤ i，使得 f[i-k] == false`。初始 `f[0] = false`（无子可取即输）。K 排序后可以提前 break：只要找到一个必败后继就立刻判定必胜。复杂度 O(n·|K|)，n 到 1e6 量级完全够用。

面试时可加分的地方有两处。一是说明「不连续集合」为什么让巴什公式失效：巴什公式本质上依赖可取的是一段连续区间，任何余数都能被覆盖，一旦有空洞，某些余数就成了必败点。二是如果 n 很大（1e9 以上），可以指出 f 是最终周期序列，先用 DP 打出前若干项、找周期再做快速幂——但这属于追问，主答案用 DP 就够。

**哈希手撕：把「会写」变成「写对」**

二面那道哈希题原文没有记下具体题面，但这类题（两数之和、找重复、字符计数、LRU）考的是同一组动作：一次遍历、用 `unordered_map` / `dict` 记「见过什么」，把 O(n²) 降到 O(n)。写的时候把边界说清楚——空输入、只有单个元素、存在多个答案时返回哪一个、哈希冲突在语言层面怎么处理。面试官看的是你写完能不能自己举一个反例跑一遍，而不是能不能默出模板。

**二面「写代码才会考虑的点」大概指什么**

原帖说二面问得很细，「很多都是要具体写代码才会考虑的点」。这类追问通常集中在：并发下这段代码会不会读到中间态、失败重试能不能幂等、边界输入（空、超长、超时）怎么处理、这段逻辑放到分布式里还成不成立。回答的套路是先给结论，再给一个具体的失败场景，最后给兜底方案；只讲「我们会加锁」会被继续追。

**主管面**

主管面基本是通用问题：自我介绍、对 AI 的看法、价值观、为什么选华为。这一轮不考技术，考的是表达是否稳定、对行业有没有自己的判断。原帖作者的总结是面试强度不低、和互联网差不多，只是手撕没写出来也可能通过，所以通过率偏高——这句话对准备下一场的读者有参考价值：华为技术面更看项目深度与思路表达，手撕是加分项而不是生死线。
