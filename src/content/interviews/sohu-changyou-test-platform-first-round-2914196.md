### 《面试题目》

1. 自我介绍。
2. 先手撕一道代码题。
3. 围绕代码的具体实现方式追问（怎么实现的、复杂度、边界情况）。
4. 开发相关的其他问题。

> 原帖说明：问的和字节的差不多，主要问代码实现的具体方式，以及开发相关内容；未记录具体题目与后续流程。

### 《参考解析》

**测试平台开发岗到底考什么**

「测试平台开发」和「测试开发」只差一个字，但考察重心有明显偏移：这个岗位日常产出的是**平台和工具**（用例管理平台、接口测试平台、Mock 服务、流量回放、数据工厂、报告看板），所以面试会当**后端/全栈开发**来考——手撕算法、编码规范、接口设计、数据库设计、并发与性能，测试知识反而只占一小部分。原帖里「先手撕、再问实现方式、再问开发相关」这个顺序，正是标准的开发岗节奏。

准备方向：

- **语言与基础**：Java（集合、并发、JVM 基础）或 Python（GIL、装饰器、异步），看 JD 写哪个就深挖哪个。
- **后端**：HTTP 与 RESTful 设计、鉴权（Session/JWT/OAuth）、幂等与重试、事务、缓存（Redis 常见用法与穿透/击穿/雪崩）、消息队列。
- **数据库**：表设计与索引、慢查询分析、分页与批处理。
- **前端基础**：平台通常有 Web 界面，Vue/React 的基本概念、组件通信、路由与状态管理会被带到。
- **工程化**：Git 工作流、CI/CD（Jenkins/GitLab CI）、容器与部署。
- **测试域知识**：接口测试框架（pytest + requests、TestNG + RestAssured）、用例组织与数据驱动、断言与报告、Mock（WireMock、moco）、流量录制回放（GoReplay、jvm-sandbox-repeater）、覆盖率采集（Jacoco）。

**手撕题怎么讲「实现方式」**

面试官说「问代码实现的具体方式」，其实是想听三件事：**你的思路有没有结构、你对复杂度有没有概念、你对边界有没有意识**。写完代码后的讲解模板：

1. **一句话说清思路**：用了什么算法/数据结构（双指针、哈希表、滑动窗口、二分、栈、DP），为什么选它。
2. **复杂度**：时间 O(?) 空间 O(?)，并说明推导依据（比如哈希表把查找从 O(n) 降到 O(1)）。
3. **边界与健壮性**：空输入、单元素、全相同、极值、整数溢出、重复元素、非法输入——主动说，而不是等对方问。
4. **可优化点**：能否用空间换时间、能否提前退出、能否流式处理（大数据量下不一次读进内存）。测试平台的数据往往量大（用例、日志、报告），**「能不能流式/分批处理」是很好的加分回答**。
5. **可测性**：如果这是平台里的一个函数，你会怎么写单测（正例、反例、边界），这直接把话题引向测试思维。

被追问「为什么不用另一种写法」时，不要 defensively 辩护，给取舍即可：另一种写法的好处是什么、在什么场景下更合适、当前约束下为什么选现在这个。

**「和字节问的差不多」意味着什么**

原帖提到字节那场也是问「代码实现的具体方式」，说明这类公司的高频考点集中在**工程实现细节**而不是八股背诵。结合字节测试开发常见题型，可以重点准备：

- **接口测试框架怎么设计**：用例模型（请求、断言、变量提取、依赖）、数据驱动、环境与配置管理、并发执行、报告生成、与 CI 集成、失败重试与隔离。
- **覆盖率怎么落地**：Jacoco 探针挂载方式（代理/插件）、增量覆盖率、覆盖率与用例的关联。
- **平台设计题**：让你设计一个「用例管理平台」或「定时巡检系统」，要讲清表结构、接口、权限、状态机、以及关键流程（谁创建、谁执行、结果怎么回传、失败怎么通知）。
- **性能与稳定性**：任务队列与并发控制、限流、幂等；平台本身也是系统，面试官会问「同时跑 500 个任务会怎样」。

**开发相关的追问怎么答**

最后那类「开发相关」的问题通常围绕你简历上的项目展开。准备两个方向：一是**你写过的工具或脚本**（哪怕是内部小工具），说清解决了谁的什么问题、省了多少时间；二是**你踩过的工程坑**（线上 bug、并发问题、数据不一致），用「现象 → 排查 → 根因 → 修复 → 预防」的结构讲。测试平台岗尤其喜欢听「我自己也被工具坑过，所以我做了 X」，因为那说明你既有开发能力又有测试视角。
