9. 为什么箭头函数不能当构造函数？

11. document.addEventListener() 有几个参数，分别代表什么？

### 《参考解析》

**内存泄漏与循环引用**：内存泄漏是「已经不再需要的对象仍被可达引用链持有」，V8 靠可达性判断（从根出发能不能遍历到），所以泄漏的本质是**意外的强引用**。常见形态：未解绑的事件监听、未清理的定时器与闭包、全局变量缓存、脱离 DOM 的元素仍被 JS 引用、订阅未取消。
循环引用在现代 JS 里**不会**造成泄漏——标记清除算法能处理环，只要整个环都不可达就会被回收。历史上 IE 的引用计数实现时代，JS 对象和 DOM 对象互相引用会泄漏，现代浏览器已经不是问题。但要注意：循环引用如果被一个长期存活的根持有（比如全局 map），那泄漏的原因是根持有，不是环。

**事件流与冒泡顺序**：DOM 事件流分捕获、目标、冒泡三阶段。默认 `addEventListener` 在冒泡阶段触发，第三参 `true` 或在 options 里写 `{capture:true}` 走捕获。三个盒子嵌套时，点击最里面：捕获阶段 A→B→C，目标阶段 C，冒泡阶段 C→B→A。如果有的监听器设了捕获，完整顺序是 A(捕获)→B(捕获)→C(目标)→C(冒泡)→B(冒泡)→A(冒泡)。

**事件委托**：把子元素的事件监听挂到父元素上，利用冒泡统一处理，用 `event.target` 判断来源。好处是减少监听器数量（内存与初始化开销）、动态新增的子元素自动生效、不需要手动解绑。代价是事件目标可能被内部元素干扰（用 `closest()` 修正）、有些事件不冒泡（`focus`/`blur` 要用捕获或 `focusin`/`focusout`）、过度委托会让判断逻辑分散。

**垃圾回收**：主流是**标记清除**——从根集合（全局对象、当前调用栈、闭包引用）出发标记可达对象，未标记的回收，能处理循环引用。V8 进一步做了**分代回收**：新生代用 Scavenge（把存活对象在两个半空间之间复制，牺牲空间换速度），老生代用标记-清除/标记-整理，并配合增量标记减少停顿。**引用计数**只被用在少数场景（早期 IE、某些原生互操作），缺点就是处理不了环。

**new 做了什么**：四步——创建一个新对象；把它的 `__proto__` 指向构造函数的 `prototype`；以新对象为 `this` 执行构造函数；如果构造函数返回的是对象则用返回值，否则返回这个新对象。

**箭头函数与普通函数的差别**：没有自己的 `this`（沿用词法作用域的 this，且无法通过 call/apply/bind 改变）、没有 `arguments`（要用剩余参数）、没有 `prototype`、不能被 `new`、不能用作 generator。**不能当构造函数**的根因就是没有 `prototype` 且没有自己的 `this`——`new` 需要给新对象装原型并绑定 this，这两件事它都做不了。

**call / apply / bind**：三者都用来显式指定 `this`。`call(thisArg, a, b)` 参数逐个传、立即执行；`apply(thisArg, [a, b])` 参数用数组传、立即执行；`bind(thisArg, a)` 返回一个绑定了 this 和部分参数的新函数，不立即执行，且绑定后不可再次改变（用 `new` 调用时除外）。典型用途：借用方法、固定回调里的 this、偏函数。

**addEventListener 的参数**：`type`（事件名）、`listener`（回调，也可以是带 `handleEvent` 的对象）、`options`（对象或布尔值）——对象里可含 `capture`（捕获阶段触发）、`once`（只触发一次后自动移除）、`passive`（承诺不调用 preventDefault，用于滚动性能优化）、`signal`（传 AbortSignal 便于统一取消）。
