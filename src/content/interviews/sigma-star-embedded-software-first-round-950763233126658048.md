### 《参考解析》

**移植 U-boot 的「具体做了什么」，按四步讲。** 一是板级适配：在 `board/<厂商>/<板名>` 下建目录，改 DDR 初始化参数（时序、容量、位宽）、时钟树、引脚复用；二是配置：从相近的 defconfig 复制一份，打开需要的驱动（串口、MMC、网络、SPI Flash）；三是设备树：写或改 `arch/arm/dts/<板名>.dts`，描述内存、外设地址、启动介质；四是验证：串口能打出启动日志、能通过网络 tftp 下载内核、能从 eMMC/SD 启动。内核侧对应的是改 dts、选 defconfig、编译出 zImage 与 dtb、配 rootfs 与启动参数（`bootargs` 里的 `console=`、`root=`、`rootfstype=`）。

**rootfs 的搭建路径。** 最小系统用 BusyBox 编出 `/bin`、`/sbin` 的基础命令，加 glibc 或 musl 的库、`/etc/inittab` 与 `/etc/init.d/rcS` 决定启动流程，`/dev` 用 devtmpfs 自动生成；再按需加应用与依赖库。存储形式上，量产常用只读的 squashfs 或 erofs 加一个可写的 overlay（或单独的数据分区），避免掉电损坏；调试阶段用 NFS 挂载最方便。要能说清分区表怎么划（boot、kernel、rootfs、data）、启动参数怎么指定根分区、以及第一次启动时怎么生成 `/etc` 下的可写内容。

**bootloader 引导 Linux 的完整链条。** 上电后 CPU 从固化 ROM 里的代码开始跑，加载 SPL（或一级 bootloader）到片内 SRAM，SPL 初始化 DDR 后把完整的 U-Boot 搬到 DDR；U-Boot 初始化外设、读环境变量，按启动顺序（eMMC、SD、网络）把内核镜像与设备树加载到内存，设置 `bootargs` 与入口地址，跳转到内核；内核解压自身、解析设备树、初始化内存管理与驱动，最后挂载 rootfs 并执行 `/sbin/init`（PID 1）。回答时把「谁加载谁、在哪一级初始化 DDR」讲清楚，是最容易被追问的点。

**串口传输了什么。** 项目里通常有两类：一是调试串口，传 U-Boot 与内核的启动日志、登录 shell 的输入输出；二是业务串口，传传感器数据、控制命令、协议帧（Modbus、自定义帧头帧尾加校验）。回答要具体到波特率、帧格式、是否有 DMA、协议怎么定界与校验。

**公司要求与交付边界那题，考的是你对项目角色的认知。** 按「需求来源—我方实现—交付物」三段说：哪些指标是公司定的（功耗、启动时间、成本）、公司提供了什么（硬件板、芯片手册、参考设计、测试设备）、自己交付了什么（驱动、应用、测试报告、文档）。这题答得清楚，说明你在项目里不是只写代码的人。

**Cortex-A 与 Cortex-M 的区别按六个维度答。** 应用场景：A 跑 Linux/Android 等富操作系统，M 跑裸机或 RTOS；MMU：A 有 MMU 支持虚拟内存，M 通常只有 MPU；缓存：A 有 L1/L2 cache，M 一般没有；指令集与流水线：A 支持多发射、乱序、NEON，M 是低功耗的顺序执行、支持 Thumb-2；中断：A 用 GIC，M 用 NVIC（向量表偏移、尾链优化）；功耗与成本：M 更低。另外 A 有多个异常等级（EL0–EL3）与 TrustZone，M 有特权/非特权两级。

**ARM 寄存器数量要区分架构。** 32 位 ARM（AArch32）有 16 个通用寄存器 R0–R15，其中 R13 是栈指针 SP、R14 是链接寄存器 LR、R15 是程序计数器 PC，另有一个状态寄存器 CPSR（以及各异常模式下的 SPSR）；R0–R3 用于传参与返回值，R4–R11 是 callee-saved。64 位 AArch64 有 31 个 64 位通用寄存器 X0–X30（低 32 位可写作 W0–W30），加独立的 SP、PC 和 PSTATE，X30 兼作链接寄存器。回答时说明「你项目用的是哪一版」，避免只背数字。

**专利那题按「问题—方案—效果」讲。** 说清要解决的技术问题、你的方案与关键创新点、以及相对现有方案的效果（指标或成本上的改善），不必展开权利要求书。
