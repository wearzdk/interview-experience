### 《参考解析》

**Ontology、Action 与 MCP**：把 HTTP/JSF 接口直接交给模型的问题在于语义与约束都不可控——接口名是给工程师看的，参数是技术类型，模型不知道业务含义、也不知道哪些组合合法。Ontology 提供领域概念与关系的统一语义（同名异义、异名同义在这里对齐），Action 在接口之上包一层「模型能理解的意图 + 收敛过的入参 Schema + 副作用声明」，柔性引擎负责编排、校验与降级。Action Schema 太宽，模型会乱填参数、越权调用；太严，覆盖不了真实业务组合，模型只能失败重试。MCP 解决的是「工具如何被发现与调用」的协议问题，不解决业务语义建模；直接上 MCP 等于把一堆无约束接口暴露给模型，所以要在其上加 Ontology 与治理层。

**数据处理的 OOM 与并行**：12 小时且 OOM，通常是把全量数据读进内存或一次性构造巨大对象。优化顺序是先降内存再提并行——流式读取（游标/生成器）+ 分块处理，把峰值内存从「全量」降到「一块」；用生成器或 `yield` 避免中间列表；把 Python 的 GIL 问题用多进程绕开，但进程数受内存与 IO 限制。并行度不是越高越好：每进程都要一份内存和文件句柄，先确认单块内存占用与下游承载，再按 CPU 核数、IO 带宽、下游限流三者取最小值。12 小时到 2 小时靠的是分块 + 并行 + 减少重复解析，每一步都要有耗时拆解来证明收益来自哪里。

**DDD 怎么落地**：从需求出发先划限界上下文（按业务能力与团队边界，不按技术分层），在每个上下文里找聚合根（一个一致性边界，外部只能通过聚合根访问内部实体），再区分实体（有标识、状态会变）与值对象（无标识、不可变），领域服务承载跨聚合的逻辑，应用层只做编排与事务，基础设施层实现仓储与技术细节。防腐层（ACL）把外部系统或遗留模型转换成自己的领域语言，避免外部变更污染核心模型。贫血模型把数据与行为分开，业务规则散落在服务里；充血模型把规则放进实体与聚合，更适合复杂业务，简单 CRUD 用贫血反而清晰。

**KV Cache 与并行训练**：自回归生成每一步只新增一个 token，KV Cache 缓存历史 token 的 Key/Value，避免重复计算注意力，把每步复杂度从 O(n²) 降到 O(n)。它也带来显存占用（随序列长度与 batch 线性增长）和状态绑定——请求迁移或扩缩容时缓存不在新机器上，需要重算或做缓存传输，所以推理调度会尽量把同一会话固定在同一个实例。数据并行每张卡持有完整模型、切分数据、梯度 all-reduce；张量并行把单层矩阵按维度切到多卡，通信频繁、适合单机内 NVLink；流水线并行按层切分到多机，用微批填满流水线，代价是气泡与调度复杂度。

**Redisson 分布式锁**：`RLock` 用 Lua 脚本保证「判断不存在 + 写入 + 设过期」的原子性；value 存「客户端 ID + 线程 ID」，解锁时先比对再删除，避免 A 的锁过期后被 B 拿到、A 回来误删 B 的锁。看门狗（Watchdog）在持锁期间定时续期，解决业务执行时间超过锁租期的问题，默认 30 秒租期、每 10 秒续一次；代价是客户端宕机后要等租期自然过期。可重入用 Hash 结构记录重入次数。强一致场景还要考虑主从切换丢锁的问题，必要时用 RedLock 或改用带 fencing token 的方案。

**一致性哈希**：普通取模在节点增减时几乎所有 key 都要迁移；一致性哈希把节点和 key 都映射到同一个环上，key 顺时针找到第一个节点，增删节点只影响相邻区间。节点少时分布不均，用虚拟节点（每个物理节点映射几百个虚拟位置）把负载摊平。它解决的是「缓存/分片的路由稳定性」，不解决热点 key 与数据倾斜，后者要靠热点探测与副本。

**JVM 与算法**：运行时数据区中线程私有的有程序计数器、虚拟机栈、本地方法栈，线程共享的有堆与方法区（元空间）。栈溢出来自递归过深或栈帧过大，抛 `StackOverflowError`；堆 OOM 来自对象持续增长且 GC 回收不掉，抛 `OutOfMemoryError: Java heap space`。海量数据求中位数：数据能进内存时用 Quickselect，平均 O(n)、最坏 O(n²)（随机化 pivot 可规避），不需要全排序；数据进不了内存时用分桶或双堆。Quickselect 每轮只递归包含中位数的那一侧，另一侧直接丢弃。

**「你为什么比别人做得更好」**：这类问题不要空谈努力。给一个可验证的差异：你习惯把系统从入口追到出口（比如做 Agent 平台时同时看协议层、模型层与业务层），遇到问题先定位到层再动手；或者你有把一件事从 0 做到上线并复盘的完整经历，能说清取舍与代价。落到团队：能补别人不愿意碰的脏活（可观测性、灰度、回滚），并把经验沉淀成文档或工具。
