### 《面试题目》

1. 请做一下自我介绍。
2. 你是自动化专业，为什么选择走纯软方向？
3. 讲讲你拿到一个任务，从需求拆解到交付的过程？
4. 系统在设计模式上有哪些设计？
5. 前端实时显示为什么用 HTTP 不用 WebSocket？
6. 前端会不会有卡顿的问题，有做什么优化吗？
7. 前端有用什么组件吗？
8. 中间件这块 MySQL、Redis 和 Docker 是都在项目里使用过吗？
9. Java 有哪些特性？C++ 也有吗？
10. IoC 和 AOP 都是做什么的？

### 《参考解析》

**专业与方向的选择。** 这类问题面试官想确认的是「不是随便投的」以及「基础是自学补上的」。可以从一门课或一个项目讲起：自动化里接触到的控制、信号处理、上位机开发让自己对软件实现产生兴趣，于是系统补了数据结构、操作系统、网络这些课，再通过实习验证了能独立交付；把「自动化背景带来的优势」也说一句（懂硬件、懂控制、能跟底层联调），比单纯表忠心更有说服力。

**从需求到交付的过程。** 用固定框架讲：先明确目标与验收标准（谁用、什么场景、成功怎么衡量），再拆解成可独立验证的模块并标出依赖与风险；设计阶段定接口、数据模型、异常与边界；实现时先打通最小闭环再补细节，关键路径写单测；联调阶段和上下游对接口、压测、灰度；交付时给文档与回滚方案，上线后看监控指标并复盘。举一个自己真实做过的例子，说清每一步的产出物和踩过的坑，比背流程有效。

**设计模式。** 不要罗列名词，讲项目里真实用到的两三处：策略模式用于把计费/风控/路由规则拆成可替换实现（新增规则不改主流程）；工厂或建造者用于复杂对象的组装；模板方法用于把流程骨架固定、差异点下放；观察者/发布订阅用于事件解耦；单例用于配置与连接池（注意线程安全）；责任链用于审批或参数校验。说清「不用它会怎样」——比如大量 if-else、改动牵一发动全身——才能体现你理解模式解决的问题而不是背定义。

**HTTP 还是 WebSocket。** 判断依据是「谁发起、多频繁、是否需要服务端主动推」。如果只是页面定时刷新状态（轮询间隔几秒、数据量小、实时性要求不高），HTTP 短轮询实现简单、复用现有鉴权和网关、无长连接维护成本，够用就别上 WebSocket。如果需要服务端在事件发生时立即推送、消息频繁且双向（聊天、协同编辑、实时行情、在线状态），长轮询或 SSE 也可以，但 WebSocket 的全双工和低开销更合适。要能说出取舍：WebSocket 需要处理心跳、断线重连、连接数扩容、网关超时，运维复杂度更高。

**前端卡顿优化。** 先定位再优化：用 Performance 面板看是长任务、频繁重排、还是渲染量过大。常见手段：列表虚拟滚动、分页/懒加载、`requestAnimationFrame` 合并高频更新、对输入做防抖节流、把重计算放 Web Worker、减少不必要的响应式依赖和大对象深拷贝、图片懒加载与合适的尺寸、避免在渲染函数里做同步 IO。实时数据场景还要控制更新频率（批量合并、按帧节流），否则再快的渲染也扛不住每秒上百次 setState。

**Java 特性与 C++ 对照。** Java 的核心特性：跨平台（JVM 字节码）、自动内存管理（GC）、纯面向对象（除基本类型）、单继承多接口、反射与注解、泛型（类型擦除）、丰富的标准库与生态。C++ 有 RAII 与析构函数做确定性资源释放、模板（编译期泛型、无类型擦除）、运算符重载、多重继承、手动内存管理（智能指针辅助）、零成本抽象，但没有 GC 和反射（有限）。回答时点出「Java 用 GC 换开发效率，C++ 用确定性换性能与可控性」这条主线。

**IoC 与 AOP。** IoC（控制反转）是把对象的创建与依赖装配交给容器：你声明需要什么（构造器/字段注入），容器负责实例化、注入、管理生命周期，好处是解耦、易替换、易测试。AOP（面向切面）是把横切关注点（日志、事务、权限、埋点、限流）从业务代码里抽出来，用动态代理在方法调用前后织入，业务只写业务。二者常配合：Spring 的事务 `@Transactional` 就是 AOP 代理实现的，而代理对象由 IoC 容器创建和管理。要注意的坑：同类内部方法调用不走代理导致事务失效、代理模式下 final 方法和 private 方法无法增强。
