### 《面试题目》

1. 自我介绍。
2. 介绍简历上的两个项目：你在项目中做了什么？
3. 项目中遇到了哪些问题，怎么解决的？
4. 项目的数据是怎么找的？是官方 API 接口还是其他方式？
5. 接口的连接是怎么找到的？
6. 手写代码：实现一个链表，并完成前插操作。

### 《参考解析》

**项目中的数据来源**：面试官问这个是在判断项目是否真实、你是否理解数据链路。回答要具体：数据来自哪个平台的哪个接口、是官方开放 API 还是页面接口、如何鉴权（token、cookie、签名）、请求频率与分页方式、字段如何解析与清洗、异常（限流、字段变更、空数据）怎么处理。若用的是页面接口，要说明如何定位（浏览器开发者工具 Network 面板看请求、分析请求参数与签名、确认返回结构），以及这样做在合规与稳定性上的风险。不要含糊地说「爬的」或「调接口拿的」。

**接口连接怎么找到**：描述定位过程：打开目标页面 → 开发者工具 Network → 筛选 XHR/Fetch → 观察请求的 URL、方法、请求头（Referer、Cookie、自定义签名）、请求体与响应结构 → 对比不同操作下的参数变化 → 在代码里复现并处理分页、重试、限流。若涉及签名或加密参数，说明如何分析（搜索关键字、断点调试、查看混淆代码）以及是否遵守了平台规则。

**项目难点**：选一个与数据或工程相关的问题，例如接口字段不稳定导致解析失败、分页与去重、并发请求被限流、数据量增长后的存储与查询。讲清现象、定位、方案与验证，避免只说「查阅资料解决了」。

**链表前插手撕**：前插分两种语义——在链表头部插入（头插法）与在指定节点前插入。头插的核心是新建节点、`next` 指向原头、更新头指针；若用带哨兵头节点，则插入到 `head->next` 之前，代码更简单且不用特判空表。指定节点前插入需要先找到前驱，或在已知前驱时直接改指针；单链表无法 O(1) 在任意节点前插入（除非交换值，但那改变节点语义）。写代码时注意：参数校验（空指针）、内存分配失败、头指针是二级指针还是返回值、以及释放逻辑。面试没写完时，把思路与边界讲清比硬写更重要，之后补上完整实现并自测。

**面试反馈的启示**：帖主自评表现不佳却进入 HR 面，说明一面更看重基础与潜力，算法题未完成不必然淘汰；但链表这类基础数据结构应当练到能默写，包括头插、尾插、删除、反转、找中点、判环。
