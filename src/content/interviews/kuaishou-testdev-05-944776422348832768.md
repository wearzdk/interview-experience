### 《参考解析》

**线程生命周期**：NEW → RUNNABLE（就绪/运行）→ BLOCKED（等锁）/ WAITING（wait/join/park）/ TIMED_WAITING（sleep/带超时的 wait）→ TERMINATED。状态由 JVM 维护，`getState()` 可查；注意 RUNNABLE 包含等待 CPU 和正在跑。

**浏览器输入到页面**：URL 解析 → 缓存检查 → DNS → TCP 三次握手 → TLS → HTTP 请求 → 服务端响应 → 解析 HTML/CSS/JS → 渲染树 → 布局 → 绘制 → 合成；JS 可能阻塞解析。

**自动化提效度量**：用例数、覆盖场景数、执行频率、发现缺陷数、回归耗时下降、人工工时节省；用「自动化发现的有效 bug / 总 bug」和「回归从 X 小时降到 Y 分钟」说话，比报百分比可信。

**HTTP 状态码**：2xx 成功（200、201、204），3xx 重定向（301、302、304），4xx 客户端错误（400、401、403、404、429），5xx 服务端错误（500、502、503、504）。

**TCP 握手挥手**：三次握手同步序列号、确认双方收发能力；四次挥手因为 TCP 全双工，两个方向各自关闭；TIME_WAIT 等 2MSL 保证最后的 ACK 能到达并让旧报文消失。滑动窗口做流量控制，拥塞控制有慢启动、拥塞避免、快重传、快恢复。

**索引建立**：在 WHERE、JOIN、ORDER BY、GROUP BY 常用且区分度高的列上建；联合索引按最左前缀设计；避免在低区分度列和频繁更新的列上建；用 EXPLAIN 验证。
