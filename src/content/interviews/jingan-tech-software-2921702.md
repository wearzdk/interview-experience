### 《核心观点》

1. 这场一面没有项目追问，全程围绕基础知识提问。
2. 题目占比最大的是计算机网络。
3. 计算机基础是第二块重点，操作系统相关内容尤其容易深入。
4. 数据结构有单独提问，通常落在选型与复杂度上。
5. 多线程方向问得比较细，不只停在 API 层面。
6. 运维排查方向同样在考察范围内。
7. Java 八股是必考项，不会因为专业是网络工程就跳过。
8. 面试官态度好、没有压力面，但面试者自评整体回答情况很差。

### 《参考解析》

1. **为什么全是八股**：第一轮把时间全给基础题，通常说明岗位偏初级或校招，面试官先确认知识底盘再谈项目。这种场次的准备方式和项目面相反——项目讲得好只能兜住一部分，基础题答不上来是直接减分，必须按知识点逐个过一遍，而不是指望用项目经历把话题引开。

2. **计算机网络被抓着问是常态**：网络工程专业出身反而更容易被追问，因为面试官默认你该会。高频落在几个链条上：TCP 三次握手与四次挥手的状态迁移、TIME_WAIT 与 CLOSE_WAIT 各自的成因和处置；拥塞控制的慢启动、快重传，以及 CUBIC 与 BBR 的思路差异；HTTP/1.1 的队头阻塞与 HTTP/2 多路复用的改进，再到 HTTP/3 为什么改用基于 UDP 的 QUIC；HTTPS 握手流程与证书链校验；DNS 的递归与迭代查询、各级缓存与 TTL。答题时把分层串起来讲，比背单点结论更容易拿分。

3. **计算机基础以操作系统为主**：进程与线程的区别、协程与用户态调度的价值、上下文切换的开销从哪来；用户态与内核态的切换代价；零拷贝的几种实现（mmap、sendfile、splice）以及各自省掉了哪一次拷贝；内存分页、缺页中断与虚拟内存；IO 多路复用里 select、poll、epoll 的差异，以及水平触发与边缘触发的使用区别。这些题目在运维排查场景里还会被二次追问，属于必须能画图讲清的部分。

4. **数据结构考的是选型**：很少直接问定义，多数是「这个场景你用什么结构、为什么」。要能说清哈希表的扩容与冲突解决、跳表和红黑树在有序集合里的取舍、堆与优先队列的应用、并查集与 Trie 的适用边界、B 树与 B+ 树的区别，以及常见排序的稳定性与复杂度。手撕题也大多从这部分出，写之前先讲清思路和边界条件。

5. **多线程要讲到设计动机**：线程池的核心参数与拒绝策略、任务队列的选择、AQS 与锁的升级过程、synchronized 与 ReentrantLock 的差异、volatile 与内存屏障、JMM 与 happens-before、CAS 与 ABA 问题、ThreadLocal 的内存泄漏成因。面试官追问的方向通常是「为什么这么设计」和「什么情况下会出问题」，只背 API 会被追穿。

6. **运维排查考的是手感**：CPU 飙高先用 top -H 定位线程再与 jstack 的线程号对齐；内存问题用 jmap dump 配合 MAT 看支配树和大对象；频繁 Full GC 看 GC 日志与堆参数；接口变慢看链路追踪、慢查询日志与连接池水位；磁盘与句柄问题看 df、lsof、iostat。回答时给出「先看什么、再看什么、怎么确认」的排查顺序，比罗列一堆命令更有说服力。

7. **Java 八股是底线题**：集合部分重点是 HashMap 的扩容与树化阈值、ConcurrentHashMap 的并发方案演进；JVM 部分是内存区域、类加载与双亲委派、GC 算法与常见收集器、对象头与锁状态；框架部分会问 IOC 与 AOP 的实现原理、Bean 生命周期、事务失效的典型场景；数据库部分则是索引与最左前缀、explain 执行计划、隔离级别与 MVCC、锁的粒度。这些属于筛人题，答不上来基本止步第一轮。

8. **无压力面容易高估自己**：面试官态度好，不代表回答得好。复盘时要按「有没有答到点上、能不能讲出取舍、被追问后守不守得住」自评，而不是按交流氛围判断，否则会把一次失利的面试当成发挥正常。
