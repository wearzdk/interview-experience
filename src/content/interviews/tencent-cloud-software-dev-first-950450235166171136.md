### 《参考解析》

**static**：修饰局部变量时改变存储期（放静态区、只初始化一次、生命周期到程序结束），作用域仍在函数内；修饰全局变量或函数时改变链接属性（内部链接，仅本文件可见）；修饰类成员变量时属于类而不属于对象，所有对象共享一份，需要在类外定义；修饰类成员函数时没有 `this` 指针，只能访问静态成员，可直接用类名调用。C++11 起函数内的 static 局部变量初始化是线程安全的。

**内存分区**：栈（局部变量、函数参数、返回地址，自动分配释放，向下增长）、堆（`new`/`malloc`，手动释放，向上增长）、全局/静态区（已初始化的 `.data`、未初始化的 `.bss`，程序启动即存在）、常量区（字符串字面量、`const` 全局）、代码段（`.text`，只读的机器指令）。此外还有线程局部存储（TLS）与内存映射区（共享库、`mmap`）。

**ACID**：原子性（事务内的操作要么全做要么全不做）、一致性（事务前后数据满足约束与业务规则）、隔离性（并发事务互不干扰，靠锁与 MVCC）、持久性（提交后即使宕机也不丢，靠 redo log）。四个特性里「一致性」是目的，另外三个是手段。

**内存泄漏**：申请了堆内存但丢失了所有指向它的指针，无法释放，进程占用持续增长。排查：Linux 用 Valgrind（`--leak-check=full`）、AddressSanitizer（`-fsanitize=address`）、`mtrace`；生产环境看 RSS 曲线、`/proc/<pid>/status`、heaptrack；C++ 还可以重载 `operator new/delete` 记录分配栈。处理：优先用 RAII 与智能指针；容器存裸指针要明确所有权；注意异常路径与提前 return 的释放；循环引用用 `weak_ptr` 打破。

**C++ 容器**：序列式 `vector`（连续内存、随机访问、尾部增删快）、`deque`（分段连续、头尾都快）、`list`（双向链表、任意位置插入删除 O(1)、不支持随机访问）、`forward_list`（单向）。关联式 `map`/`set`（红黑树、有序、O(log n)）、`unordered_map`/`unordered_set`（哈希、平均 O(1)、无序）。容器适配器 `stack`、`queue`、`priority_queue`（默认用 `deque` 或 `vector` 实现）。选择依据是访问模式、插入删除位置、是否需要有序。

**先进先出的队列**：`std::queue`（适配器，底层默认 `deque`，也可指定 `list`）；环形缓冲区（固定容量、无动态分配、适合高频生产消费）；阻塞队列（多线程下的生产者消费者，配条件变量）；无锁队列（CAS 实现的 MPMC 队列，适合高性能场景）。

**DNS 与 TCP/UDP**：DNS 把域名解析成 IP，递归查询 + 迭代查询，有缓存（浏览器、系统、本地 DNS、权威服务器），记录类型有 A/AAAA/CNAME/MX/TXT。TCP 面向连接、可靠、有序、有流量控制与拥塞控制，代价是握手与重传延迟；UDP 无连接、不保证可靠与顺序、开销小、支持广播组播，适合实时音视频、游戏状态同步、DNS 查询本身。

**vector 的底层与扩容**：三段指针（begin/end/capacity_end）管理一块连续内存，`size` 是元素个数、`capacity` 是容量。扩容时按倍数（通常是 1.5 或 2 倍）申请新内存、移动或拷贝元素、释放旧内存，所有迭代器、指针、引用失效。`reserve` 可以预分配避免多次扩容；`shrink_to_fit` 请求回收多余容量（非强制）。删除中间元素会移动后续元素，O(n)。

**vector 为什么访问快**：内存连续，随机访问是一次指针偏移（O(1)）；连续访问时 CPU 缓存行命中率高、预取器有效；没有链表那样的指针追逐与额外内存开销。

**vector 与 list**：vector 随机访问 O(1)、尾部插入摊还 O(1)、中间插入删除 O(n)、缓存友好、内存紧凑；list 任意位置插入删除 O(1)（前提是已有迭代器）、不支持随机访问、每个节点额外两个指针、缓存不友好。实践中绝大多数场景用 vector，即使中间插入，因为移动连续内存比链表指针跳转快。

**哈希**：哈希函数把 key 映射到桶下标，理想情况 O(1)。冲突解决：链地址法（每个桶挂链表/红黑树，`unordered_map` 用这个）、开放寻址法（线性探测、二次探测、双重哈希）、再哈希。负载因子过高时扩容并重新哈希。好的哈希函数要分布均匀、计算快；恶意构造的 key 会造成哈希碰撞攻击，所以有的实现会加随机种子。

**找出出现次数最多的数字（只遍历一次）**：用哈希表计数，遍历时同步维护当前最大值，O(n) 时间、O(k) 空间（k 为不同数字个数）。如果数字范围有限（如 0–1000），可以直接用数组当计数器，空间 O(范围)。「只能遍历一次」的要求正好对应「边计数边更新最大值」，不需要第二遍扫描。

**前 k 高的元素**：维护一个大小为 k 的小顶堆，遍历数组，堆未满就插入，满了就比较堆顶，比堆顶大就替换并下沉。时间 O(n log k)、空间 O(k)。也可以用快速选择（平均 O(n)）后再排序前 k 个；数据量小直接排序 O(n log n) 也可以。要能说清楚「为什么用小顶堆而不是大顶堆」——小顶堆的堆顶是当前 k 个里最小的，最容易淘汰。
