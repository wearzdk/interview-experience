### 《参考解析》

**虚拟列表与阈值切换**

核心是只渲染视口内的项、上下各留一段缓冲。实现先按项高算总高度撑起滚动容器（固定高度最省事，不定高要测量并缓存高度），监听滚动拿 scrollTop 反算可见区间，叠加缓冲区后只渲染这一段，用 transform 或占位保持滚动条不跳。以 30 条为阈值是合理取舍：条目少时全量渲染在滚动、搜索、锚点跳转上都更简单，上虚拟列表反而引入测量与「跳到某条历史消息」的对齐问题。切换体验容易崩在两点：两种模式的行高与滚动位置必须可换算，切换瞬间按 scrollTop 还原；更平滑的是同一个组件内部切换渲染方式，而不是 v-if 换掉整个组件。

**SSE 流式对话与断点续传**

SSE 是一条长连接、服务端单向推送 text/event-stream，浏览器侧可用 EventSource，也可用 fetch 加 ReadableStream 自己解析（后者才能自定义 header 和用 POST）。它比 WebSocket 轻，自带重连和 Last-Event-ID 语义。断点续传要两端配合：每条消息带自增序号或 event id，服务端保留已生成内容或能从存储恢复；客户端断开时记下最后收到的序号与已渲染长度，重连时把位置带上，服务端从该点继续推，前端把新片段追加进同一条消息而不是新建气泡。配套还要有指数退避重连、切后台节流、重复片段按序去重合并，以及生成失败时的终止事件，让这条消息可重试。

**Tool Calling、MCP 与 CoI 的边界**

Tool Calling 是模型能力：把函数签名以 schema 交给模型，模型决定调哪个并产出结构化参数，应用执行后回灌结果。MCP 是协议标准：定义 client 与 server 的通信，把工具、资源、提示词以统一形式暴露，一个 client 接上任意 server 就能用那批工具，解决 M 个模型接 N 个工具要写 M×N 份适配的问题。CoI 属于推理与指令这一层，是提示策略，不解决工具接入。选型上：应用内几个稳定工具直接 Tool Calling 链路最短；工具来源多、要跨应用复用、需要动态发现和权限隔离时，才值得上 MCP server。MCP 不负责让模型变强，鉴权、超时、结果裁剪仍要自己做。

**RAG 链路与重排成本**

基础链路是「解析与切块 → 建索引（倒排加向量）→ 查询改写 → 混合召回 → 融合 → 重排 → 组装上下文 → 生成并带引用」。BM25 与向量互补，用 RRF 按排名融合，避免两套分数量纲对不齐。重排常用 Cross-Encoder 精排、模型打分（pointwise 或 listwise）、规则加权（时间、来源、点击反馈）。用模型逐条打分确实贵，降本组合是：先用便宜召回和 RRF 把候选压到 20~50 条只重排这一批；在业务数据上微调或蒸馏一个小 Cross-Encoder 替代大模型打分；高频 query 缓存重排结果；再退一步用 listwise 一次给多条候选让模型输出排序。要能说清精度与成本的取舍点。

**LangChain、LangGraph 与 checkpoint**

LangChain 面向线性调用链：Prompt、Model、Parser、Retriever 用 LCEL 串起来，适合固定流水线。LangGraph 面向有状态、有分支和循环的图：显式定义 State、节点、边与条件跳转，能表达重试、回退、人工审批。Checkpoint 是它的持久化：每个 superstep 结束把 State 快照写进 checkpointer（内存、SQLite、Postgres 均可），thread_id 区分会话、checkpoint_id 标版本，于是能断点续跑、回放、等人工输入后继续。代码上就是编译图传 checkpointer、调用带 thread_id，写入时机在节点更新完 State 之后。

**脚本阻塞、事件循环与并发调度**

同步执行的 script 会阻塞 HTML 解析，因为它可能改 DOM。不阻塞的办法：defer（并行下载、解析完按序执行）、async（下载完即执行、顺序不保证）、动态创建 script 或动态 import、type=module（默认 defer 语义），重计算搬进 Web Worker。await new Promise(r => setTimeout(r, 0)) 让出的原理是把后续代码作为宏任务放进定时器队列，同步栈清空后事件循环先清微任务再取宏任务，浏览器因此有机会渲染——它是让出主线程，不是睡 0 毫秒。并发调度器搭在这之上：队列加并发上限，任务结束释放槽位取下一个；带依赖的任务按拓扑排序分批，批内并行、批间串行。

**渲染流水线、stacking context 与合成层**

HTML 到像素大致经过：解析 HTML 与 CSS 建 DOM、CSSOM，合成渲染树、布局、绘制、分层光栅化、GPU 合成输出。谁盖住谁发生在绘制与合成阶段：同层按 stacking context 与 z-index 排序，跨层由合成顺序决定。stacking context 由定位加 z-index、transform、opacity 小于 1、filter、will-change 等创建，子元素 z-index 只在该上下文内比较。提升到合成层通常因为 3D transform、will-change、video 或 canvas、opacity 动画；层爆炸即滥用 will-change 让大量小元素各自成层，导致内存暴涨、合成变慢。

**HTTP/3、QUIC 与 TCP 拥塞控制**

HTTP/2 的多路复用解决了 HTTP/1.1 的队头阻塞，但阻塞跑到 TCP 层：所有流共用一个连接，丢一个包后续所有流都要等重传，因为 TCP 保证字节流有序交付。HTTP/3 把传输换到基于 UDP 的 QUIC，在用户态实现流级可靠性与拥塞控制：每个流独立序号与重传，一条流丢包不影响其他流；TLS 1.3 并入握手，1-RTT 甚至 0-RTT 建连；连接迁移靠 connection id 而非四元组。TCP 这边慢启动按 RTT 指数扩窗，到阈值转拥塞避免线性增长；超时会降到 1 重走慢启动，收到三个重复 ACK 则快重传立即重发，快恢复把窗口减半、不跌回 1。

**双 Token 无感刷新与安全**

单 token 的困境是过期短则频繁掉线、长则泄露后长期可用，双 token 把两者拆开：access token 短期、随请求走，refresh token 长期、只用于换 access token。落位是 access token 放内存（刷新即丢、靠 refresh 恢复），refresh token 放 HttpOnly、Secure、SameSite 的 Cookie，让 JS 读不到，压缩 XSS 面。无感刷新的关键是并发去重：遇到 401 或临近过期，不能每个失败请求各刷一次，要用共享的刷新 Promise 让同批请求一起等，成功后重放原请求，失败则清状态跳登录。刷新时轮换 refresh token、检测重复使用即判定泄露并吊销会话。

**Canvas 与 X6 渲染树的性能优化**

分层通常是：X6 负责图模型、交互、事件和节点边的业务渲染，canvas 用于高频定制绘制或整体位图渲染，分层的目的是让交互层与绘制层解耦、各自独立重绘。视口裁切的意义在于节点数增长后全量绘制会把每帧开销拉到不可接受，只绘制视口加缓冲内的节点和边，每帧成本就只跟可见量相关。1000 节点压测要造随机拓扑数据，用 performance 或自写帧计时对比开关裁切前后的平均帧时长与长任务数，判据是绘制次数与帧耗时随总节点数近似不变。预加载提前准备视口外一圈的数据与图片；Web Worker 跑不该占主线程的计算——这里是最小割集，求使源点与汇点分离所需移除的最小边集合。

**埋点与性能指标采集**

埋点分三类：事件（点击、曝光，聚合出 PV/UV）、业务漏斗、性能指标。性能侧 FCP 是首次内容绘制、LCP 是最大内容元素绘制完成、TTFB 是首字节到达、INP 衡量交互响应、CLS 衡量布局偏移；采集优先用 PerformanceObserver 订阅 paint、LCP、layout-shift，老浏览器退回 performance.timing。Vue 里记录 FCP 一般放在全局初始化处：入口挂载前注册 observer，或根组件 mounted 后读 getEntriesByType，但要说明 SPA 里这只反映首屏。上报用 sendBeacon 避免阻塞卸载；离散度大时报 P75/P95 而非均值，并按设备与网络分层。

**自研 Agent 框架：ReAct、容错与上下文**

ReAct 是「思考 → 行动 → 观察 → 再思考」，一轮完整处理是：拼上下文与工具 schema → 模型输出 → 解析思考与工具调用 → 校验参数并执行 → 结果写回 → 判断终止条件。工具输出不是标准 JSON 是常态，容错顺序是严格 JSON 解析、失败再抽取代码块或首个 JSON 子串、仍失败就把原文与解析错误一起回给模型重发，同时限次数并记样本调 prompt。多 Agent 按职责或数据边界拆，子 Agent 预定义还是动态创建取决于任务是否可枚举：固定流水线用预定义，开放任务由主 Agent 派生，产物用统一格式交接，避免中间推理污染主上下文。熔断不能只看步数，同工具同参数连续出现或状态无变化就要强制换策略或收尾。
