### 《面试题目》

1. 自我介绍。
2. 围绕研究生方向的课题深入提问（原帖称「拷打」）。

### 《参考解析》

**这场面试实际发生了什么**

原帖记录的信息很有限，但足够看出性质：线下面试，岗位是工业 Agent，流程只走了「自我介绍 + 拷打研究生方向的课题」两步，约十分钟结束；面试官直接建议作者不要往 Agent 方向挤；作者自评对方完全不想要人，同时听说该岗位加班强度是 896，也就没有继续争取的意愿。这是一篇典型的「岗位匹配度失败」复盘，而不是技术能力被否定。

**十分钟结束通常意味着什么**

面试时长过短、且没有进入技术细节，往往不是候选人答得差，而是简历与岗位模型在第一轮就没对上。工业场景的 Agent 岗和互联网 Agent 岗要的人差别很大：前者通常要能落到设备、产线、工艺和质量体系上，看重的是控制与自动化背景、边缘部署、实时性与可靠性、以及对工业数据和协议（OPC UA、Modbus、PLC、MES）的理解；纯做 LLM 应用编排、RAG 问答、Agent 平台的经历在这类岗位上是加分项但很难是主线。面试官说「别往 Agent 方向挤」，多半是在表达「我们这个岗位其实不是你想的那种 Agent 岗」。

**课题被拷打时怎么答**

研究生课题是这类面试唯一能深挖的抓手，答法要结构化：先用一句话说清研究问题是什么、为什么重要，再讲你的具体贡献（哪部分是别人做的基础、哪部分是你做的），然后是方法与实验设计，最后给量化结论和局限。关键是把课题翻译成岗位语言——如果课题里有控制、优化、数据建模、异常检测、部署上线的部分，就重点讲这些，而不是只讲论文的学术创新点。提前准备两三个「这个课题在电池制造场景里能怎么用」的迁移点，比背论文细节有用得多。

**遇到明显不匹配的面试怎么处理**

① 当场争取信息而不是争取情绪：可以礼貌反问「这个岗位日常交付的产物是什么、团队现在最缺什么能力」，十分钟的面试里这句话可能比后面所有回答都值钱；② 不要为了迎合而否定自己的方向，也不要因为对方否定就怀疑简历；③ 把这次面试当样本——同一家公司不同事业部的 Agent 岗差别可能极大（研发数字化、智能制造、工业软件是三条线），投递前查清团队归属。至于 896 这类强度信息，属于个人取舍，不必在面试里追问，但可以记进自己的公司清单。
