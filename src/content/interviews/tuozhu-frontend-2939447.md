### 《参考解析》

**事件循环**：浏览器的事件循环以任务为单位推进。取一个宏任务执行，执行完毕后清空微任务队列，随后进入渲染时机（`requestAnimationFrame` 回调在样式计算与布局之前执行），再取下一个宏任务。宏任务包括整段脚本、`setTimeout` / `setInterval`、`MessageChannel`、I/O 回调与用户交互事件；微任务包括 `Promise.then`、`queueMicrotask`、`MutationObserver`，以及 `async` 函数中 `await` 之后的续体。回答时要讲清「微任务在同一个宏任务结束后一次性清空」，这是判断输出顺序的依据。

**代码输出题的方法**：先逐行标出同步代码、微任务与宏任务，再按「同步 → 微任务 → 宏任务」排序。三个常见陷阱：`new Promise(executor)` 的 executor 是同步执行的；`await` 会把后续代码注册成微任务，而不是立即执行；定时器的延迟只保证不早于该时间，多个同延迟定时器按注册顺序执行。若代码中有 `async` 函数先于 `await` 的部分，同样属于同步代码。

**Vue 与 React 中的事件循环**：Vue 的 `nextTick` 把同一轮数据变更后的 DOM 更新合并到微任务中执行，因此连续修改多个响应式变量只触发一次 patch。React 18 的自动批处理与并发调度由 Scheduler 承担，时间切片通过 `MessageChannel` 把让出主线程后的续体排成宏任务，使高优先级更新（输入、点击）可以插队；`useEffect` 的回调在提交阶段之后异步执行，`useLayoutEffect` 则在绘制前同步执行。

**key 的作用**：React 与 Vue 都用 key 在同层子节点之间做身份匹配，决定复用现有节点还是销毁重建。用数组索引作 key，在插入、删除、排序时索引与节点身份发生错位，组件内部状态会挂到错误的数据上（受控输入内容串行、动画重置、展开状态错乱），diff 也会退化为逐个位置比较。key 应使用稳定且唯一的业务 id，且只需在兄弟节点之间唯一。

**workflow 与工具权限**：workflow 若指工作流引擎，要讲清节点编排、状态流转、失败重试与补偿、人工审批节点；若指 AI 编排平台，则讲节点、变量传递、工具调用与调试方式。没有接触过时如实说明，并给出可迁移的理解：把流程拆成节点、为每个节点定义输入输出与失败处理。工具权限设计的要点是最小权限、按角色与资源授权、危险操作二次确认、凭据不进入前端、服务端逐次校验、操作留痕可审计；面向 Agent 的工具还要加工具白名单、参数校验与沙箱执行。

**对称二叉树**：递归比较左右子树是否互为镜像，`mirror(a, b)` 在两者都为空时返回真，否则要求值相等且 `mirror(a.left, b.right)` 与 `mirror(a.right, b.left)` 同时成立，时间 O(n)、空间 O(h)。迭代写法用队列成对入队，空节点也要入队，否则会漏判结构不对称。
