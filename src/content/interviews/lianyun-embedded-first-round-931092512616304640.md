### 《面试题目》

1. 你做的驱动上下层接口怎么定，哪一层允许阻塞？
2. 从复位到进 main，哪些事必须在 C 运行环境准备好之前做完？
3. 只读查找表写成 const，为什么有时仍占 RAM？怎样让它留在 Flash？
4. 函数里的 static 局部变量什么时候初始化？两个任务同时第一次调用安全吗？
5. 很大的数组从局部变量改成文件内静态，栈和上电时间会怎样？
6. 栈和堆相向生长时，链接阶段怎么防止它们撞在一起？
7. 定长内存池的空闲块怎么串？分配和释放的复杂度是多少？
8. 中断里为什么不能做长逻辑？后半段你放哪？
9. DMA 缓冲区和普通变量挤在同一条 Cache 行里会怎样？
10. 循环里条件很难预测时，流水线会怎样？代码上怎么减少？
11. 头文件里定义了全局变量，多个源文件包含后链接会怎样？怎么改？

### 《参考解析》

**驱动分层的阻塞边界**：最底层只做寄存器读写、收发和中断置标志，绝不等结果、不调业务回调里的长逻辑；中间层负责组包、超时和重试，这里才允许阻塞，且必须限定在任务上下文、带超时返回；上层只面对完整帧或错误码，不直接碰寄存器。中断里只投递事件，真正处理回到任务，避免在 ISR 里睡眠。错误一律用返回值区分忙、超时、参数错，不要用全局变量偷偷报错——那会让调用方无法判断是哪一次调用失败的。

**复位到 main 之间必须做完的事**：先设栈指针，否则后面任何函数调用都没有栈可用；再把已初始化数据从 Flash 拷到 RAM（.data），把未初始化区清零（.bss）；时钟和看门狗策略要在大量 C 代码跑起来之前定下来，避免中途切时钟失败；如果要改向量表基址（VTOR），必须在开中断前写完。这些做完才调 C 库初始化并进 main——在此之前不能假设全局变量已经是 C 语义下的初值。

**const、静态数组与内存段**：const 只保证「程序不该写」，具体放哪一段由链接脚本决定。有的工程为了访问速度把只读段也拷进 RAM，表一大就挤占内存；想留在 Flash，就把该段映射到只读区、启动代码不再拷贝它。表要给 DMA 当源时，先确认 DMA 能不能读 Flash，不能才有理由拷到 RAM。改完段用 map 文件核对符号地址，确认落在 Flash 而不是 RAM。局部大数组改成文件内 static 后，栈压力消失（调用链再深也不占栈），但 RAM 总量没省，只是搬到 BSS/数据段；没有显式初值就要在启动时清零，数组越大进 main 前耗时越长；它的生存期变成全程，不能随函数返回释放，多任务共用还得约定谁能写。

**static 局部变量的初始化与可重入**：它有静态生存期，不在栈上，存储位置和全局变量同类。C 语言里初始化只在第一次执行到该声明时做一次，不是每次进函数；标准并不保证这次初始化是原子的，两个任务同时第一次进来会抢（那是 C++11 的线程安全静态初始化语义，裸机 C 别指望）。初始化完成之后，变量本身若还会被改写，仍要另做互斥。这种隐藏状态还会让函数不可重入，中断和任务同时调用要单独评估。

**中断、DMA 与 Cache 一致性**：中断抢占优先级，里面耗时会拉高其他中断和任务的延迟，所以 ISR 只清中断源、搬少量数据、置标志，不打印、不等待、不分配堆；后半段用信号量或队列交给任务，队列满时要有明确策略（丢新数据还是记溢出计数），绝不能在 ISR 里阻塞等空位。DMA 缓冲区要和普通变量隔离：Cache 以行为单位装入和写回，CPU 改了行内另一个变量再写回，可能把 DMA 刚写入的数据盖掉；反过来为读 DMA 数据作废整行，也会丢掉 CPU 尚未写回的相邻变量。做法是按 Cache 行对齐并让缓冲区末尾垫满一行，维护方向要分清——CPU 写给 DMA 之前先 clean，DMA 写给 CPU 之后先 invalidate 再读。

**定长内存池、栈堆布局与流水线**：定长内存池上电时把整块内存切成固定大小，空闲块用指针串成链表、头指针指向第一块，分配就是摘下头结点、释放就是插回头部，都是 O(1) 且时间可预期；代价是块大小固定，大请求要么失败要么浪费，也无法合并相邻空闲块，释放时要校验地址确实在池内且按块对齐，防止野指针插进空闲链。栈堆相向生长的问题要在链接脚本里解决：写明栈顶、堆底和两者必须保留的空隙，RAM 不够就让链接器直接报错，而不是产出一份能下载但会撞内存的镜像；运行时再用填充图案或 MPU 保护区验证有没有越界，中断嵌套和 printf 这类隐式用栈的路径都要算进最小栈保留量。至于分支预测：条件难预测时猜错要丢掉已取进的指令、从正确地址重新取，管线越深空拍越多；热路径写成顺序执行、把冷门错误处理挪到分支另一边，极短的选择可以用无分支写法，但只在实测更快时用。
