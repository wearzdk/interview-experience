### 《参考解析》

**SVG 图谱卡顿怎么优化**：先定位瓶颈——DOM 节点数量（几千个 SVG 元素必然卡）、每帧的重排重绘、事件监听数量。手段：只渲染视口内的节点（虚拟化/视锥裁剪），缩放时按层级聚合（LOD，把远处的节点合并成簇）；把静态内容用 Canvas/WebGL 替代 SVG（SVG 适合少量交互元素，Canvas 适合海量绘制）；减少重绘范围（分层渲染、`requestAnimationFrame` 合批）；事件用委托而不是每个节点绑一个；布局计算（力导向）放到 Worker 里，主线程只做绘制；必要时用成熟的图可视化库（G6、Cytoscape、Sigma.js）而不是自研。

**Web Worker**：是把 JS 计算放到独立的线程执行，不阻塞主线程渲染，但它不能直接操作 DOM，所以「计算」和「绘制」要分开。交互靠 `postMessage`/`onmessage` 传递结构化克隆的数据（大对象有拷贝成本），也可以用 `Transferable` 转移 ArrayBuffer 的所有权（零拷贝）。适合放进去的：布局计算、图算法、大数组排序/过滤、解析大 JSON、加解密、编解码；不适合：频繁的小任务（消息传递开销大于计算）、需要访问 DOM 的操作。判断阈值要看单次计算是否超过十几毫秒（一帧 16.7ms 的预算），以及是否会阻塞用户交互。

**全量绘制与按需加载**：图形渲染常见错误是「任何状态变化都重绘全部节点」。正确做法是分层（背景层、边层、节点层、交互层）与差量更新：只重绘变化的节点，维护节点与图形对象的映射；用脏矩形或场景图；对不可见区域不绘制。按需加载：先加载一层概览（聚合节点），用户展开或缩放到某个区域时再请求下一层详情；数据分页 + 缓存已加载的子图；用接口带上「视图范围 + 层级」参数，服务端只返回可见部分。

**Monorepo**：一个仓库管理多个包（应用、组件库、工具库、配置），共享依赖与构建配置，改动可以原子提交、跨包联调方便。代价是仓库变大、CI 变慢、依赖版本容易漂移。常见工具是 pnpm workspace + Turborepo/Nx（增量构建与缓存）。组件库的发布：每个包独立版本（Changesets 管理），内部 NPM（Verdaccio/Nexus）或私有 registry。

**基础包升级后依赖包怎么跟**：两条路线——固定版本（依赖包显式声明 A 的版本，升级要手动改，稳定但滞后）与 workspace 协议 + 统一版本（`workspace:*`，发布时替换为实际版本，基础包改动后所有依赖包一起发版）。实践里常用「Changesets 记录变更 → CI 自动升版本 → 发布时按依赖关系拓扑排序」，并把 peerDependency 用于 React 这类宿主依赖，避免重复打包。

**发包触发**：本地手动发容易漏、容易版本冲突；主流是 CI 流水线触发，判据有打 tag（`v1.2.3`）、Changesets 的变更文件、或 commit message 约定（conventional commits + semantic-release）。发布前跑构建、测试、类型检查，发布后打 git tag 并生成 changelog。要能说出「怎么防止重复发布」——registry 会拒绝同版本号，CI 里先查版本是否存在。

**Agent 工具调用链路**：把「模型决定调用什么工具 → 参数校验 → 执行 → 结果回填 → 继续推理」串起来，涉及工具注册与 schema、权限与沙箱、超时重试、结果截断、轨迹记录。知识图谱在这里的作用是给 Agent 提供结构化的事实与关系，让它能查到「实体 A 和 B 是什么关系」而不是只靠向量相似度。

**流式渲染的问题**：SSE/WebSocket 分块到达，可能出现半句话、Markdown 未闭合（代码块、表格）、频繁 setState 导致卡顿、滚动位置跳动、用户上滑查看历史时被强制拉回底部。处理：按帧合批更新（buffer + requestAnimationFrame）、增量解析 Markdown、未闭合的代码块先按纯文本渲染、滚动到底部只在用户位于底部时自动跟随、消息结束再整体重排一次。

**零代码平台的边界**：生成网页/应用、部署到子域名、代码归属与私有化迁移，这些是产品与法务问题，不是纯技术问题。技术上的迁移难点：生成物依赖平台运行时（组件库、后端 API、鉴权、存储），私有化要打包运行时与数据导出；复杂应用（商城）还涉及支付、订单、库存等外部依赖。回答时先分清「平台托管」与「客户自持」两种模式，再说各自的交付物。

**数组拍平**：递归实现最简单：遍历数组，元素是数组就递归，否则 push 到结果；可以带深度参数 `depth`。要能说出 `Array.prototype.flat(depth)` 的存在、以及用 `reduce` + `concat` 的写法；注意稀疏数组、循环引用（会栈溢出）、大数组的栈深度问题（改用显式栈迭代）。

**vibe coding 与手写代码**：面试官问这个是在确认「你还能不能自己写」。答法：AI 提高的是产出速度，基本功决定你能不能 review 和定位问题；平时刻意保留手写练习（算法、核心模块），并举例说明你改过 AI 生成的哪段错误代码。
