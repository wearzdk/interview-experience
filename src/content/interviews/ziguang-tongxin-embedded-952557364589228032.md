### 《面试题目》

1. AD7606 驱动的技术细节是什么？FMC 与 DMA 是怎么配合的？
2. D-Cache 是什么？在采集链路里要注意什么？
3. 为什么要做零点补偿与增益补偿？
4. 项目中参考了 AUTOSAR 的哪些架构？
5. 是否实际接触过 AUTOSAR？

### 《参考解析》

**AD7606 经 FMC 与 DMA 的数据搬运**：AD7606 是并行输出的多通道 ADC，`BUSY`、`CONVST`、`RESET`、`CS`、`RD` 等控制脚由 GPIO 驱动，数据总线接到 FMC（或 FSMC）的地址空间上，CPU 或 DMA 以「读外部存储器」的方式取数。FMC 需配置为异步 SRAM 时序，地址建立时间、数据保持时间与总线宽度（常见 16 位）要按手册的读写波形留出余量，时序过紧会读到毛刺或错位数据。采集流程是拉低 `CONVST` 启动转换、等待 `BUSY` 变低、再连续读取各通道；高采样率场景用外部中断或定时器触发，不在主循环里裸轮询。DMA 通常配置为存储器到存储器或外设到存储器（把 FMC 映射地址作为源），一次把整帧多通道数据搬到 SRAM 的环形缓冲区，在半传输与全传输中断里做帧切换。缓冲区要求地址对齐、长度固定，与算法核之间用双缓冲或环形队列交接，避免边采边算踩同一块内存。调试顺序是先以 GPIO 位带读写验证时序，再打开 DMA；用示波器看 `CONVST`、`BUSY`、`RD` 的相位关系，用逻辑分析仪核对实际采样率是否稳定。

**D-Cache 与 DMA 的一致性**：Cortex-M7 这类内核带数据缓存，CPU 的读写先经过 Cache，不保证立刻与真实 SRAM 或外设可见内容一致。DMA 直接写内存时绕过 Cache，CPU 若命中旧缓存行就会读到过期数据，因此处理前要对 DMA 缓冲区做 Invalidate，且按地址与缓存行大小对齐，否则会误失效相邻数据。反向地，CPU 写完配置或描述符再交给 DMA 读取时，要先 Clean，把 Cache 内容写回内存，否则 DMA 读到的是旧值。工程上有两种策略择一贯彻：把采集缓冲放在非缓存区（用 MPU 配置为 Device 或 Non-cacheable），或者强制 32 字节对齐并成对执行 Clean 与 Invalidate。共享内存场景（双核 IPC、OpenAMP）同样遵循「谁写谁 Clean、谁读谁 Invalidate」，否则双核之间的数据偶发错乱极难定位。Cache 关闭能规避问题，但会明显拖慢算法核，通常不作为首选。

**零点与增益补偿的必要性**：ADC 前端的运放失调、ADC 自身的失调、基准电压偏差、PCB 漏电都会引入零点偏移，运放增益电阻的误差与基准漂移则带来斜率误差。零点补偿的做法是在输入端短接或接入已知零基准时采一批点求平均，得到固定偏置并在后续采样中扣除，否则小信号始终带一个直流台阶，做积分或阈值判断时会持续累积。增益补偿用已知满量程或两点校准算出比例系数，把原始码值映射为真实物理量。温度、供电与器件老化会让这两个参数漂移，因此产线做两点校准，运行中可选配温漂表分段修正。补偿环节要放在标定之后、滤波与业务算法之前，并把参数固化到 Flash，否则每块板的绝对值对不上，通道之间也无法对齐。

**参考 AUTOSAR 的分层与通信设计**：分层上借鉴 MCAL（ADC、FMC、DMA、CAN 驱动）到 ECU 抽象层、服务层（通信、诊断、存储）再到应用层的划分，上层不直接操作寄存器。通信参考 PDU Router 与 COM 的思路，把信号打包成 PDU 并做路由，应用只收发信号，不关心底层是 CAN 还是其他总线。诊断参考 UDS 与 DCM 的服务划分（会话、DID、例程），与 CAN TP 的分段传输配合。调度上采用周期性任务加事件触发，把采集、通信、算法拆成独立任务，避免所有逻辑揉进一个大循环。配置与代码分离，通道、波特率、标定参数表项化，接近 AUTOSAR 用配置生成行为的方式。需要说明这是项目级的简化实现，不是完整的 Vector 协议栈，面试中把「借鉴了什么、简化了什么、为什么这样简化」讲清楚比声称做过完整 AUTOSAR 更可信。

**是否接触过 AUTOSAR**：如实区分「读过规范、做过分层借鉴」与「在量产项目里配置过工具链」。后者要能说出具体工具（如 DaVinci、EB tresos）、配置了哪些模块、生成代码与手写代码如何集成、诊断与通信栈的调试过程。若只是借鉴，就说明借鉴的边界与遇到的不一致之处，例如简化后缺少运行环境（RTE）的接口生成，任务间通信改为直接调用队列接口。
