### 《参考解析》

「出现次数最多的公共前缀」是这场的怪题：正常做法是后缀数组 + LCP，即先对日志做后缀数组（O(n log n) 的倍增或 SA-IS），再用 Kasai 算法线性求相邻后缀的最长公共前缀，然后统计每个前缀出现的次数——把 LCP 转成「区间取 min」的结构（笛卡尔树或单调栈）就能算出每个候选前缀的覆盖次数，取最大。面试官给了方向说明他想要的是「你知道后缀数组能解字符串统计类问题」，答不出细节也别沉默，把「先建后缀数组、再用 LCP 统计前缀覆盖」的主线讲清楚比胡诌强。

连接池考的是资源与延迟：建连接要 TCP 握手、认证、初始化会话，成本远高于一次查询，连接池把连接复用起来并给并发数设上限，防止流量峰值把数据库打挂。策略上要讲最大值/最小空闲、获取超时、空闲回收、健康检查（校验失效连接）、以及「池大小不是越大越好」——超过数据库承载能力后只是把排队从应用挪到数据库。

余额并发这题的标准答案是数据库层面的原子更新（`UPDATE ... SET balance = balance - ? WHERE id = ? AND balance >= ?`）加事务，或者乐观锁版本号；如果坚持在应用内加锁，就要说清锁的粒度、只锁单用户（分段锁或按用户 ID 取模）、以及多实例部署时本地锁无效必须用分布式锁。追问「适用条件」就答：本地锁只在单进程有效，分布式锁依赖外部组件可用性并引入额外延迟，所以钱这类强一致场景优先把判断交给数据库的一条原子语句。

日志表只有用户 ID、时间戳两个单列索引，典型问题是「按用户 + 时间范围」查询会走其中一个索引再回表过滤，扫描量大、回表多；解法是建联合索引 (user_id, timestamp)（把范围列放后面、等值列放前面），必要时把常查字段放进索引做覆盖查询；也要提醒索引不是越多越好，写放大和优化器选择都会变差。

强连通分量判循环依赖：把任务建成有向图（任务为点，依赖为有向边），跑 Tarjan 或 Kosaraju 求 SCC，任何大小大于 1 的 SCC 就是环；单点自环也算。实际工程里更轻的做法是 Kahn 拓扑排序——能排完就无环，剩下的点就在环上，还能顺手拿到一个可执行的调度顺序。

Python 文件 IO 的异常清单要能脱口而出：`FileNotFoundError`、`PermissionError`、`IsADirectoryError`、`UnicodeDecodeError`、`OSError`（含磁盘满、句柄耗尽），读网络或管道还会有超时。正确写法是 `with open(...)` 保证关闭，只捕获预期异常并记日志，把「重试 / 跳过 / 上报」明确区分，别用一个裸 `except` 吞掉所有错误。

pandas 识别低信息量字段有一套固定动作：`df.isna().mean()` 看缺失率、`nunique()` 看基数、`std()` 或 `value_counts(normalize=True)` 看是否恒定，一次性生成特征体检表。处理策略要与模型对齐：高缺失高基数的直接丢；缺失率中等且有信息（缺失本身有含义）就补一个「是否缺失」指示列；恒定值字段无条件删。要提醒的是「缺失 95%」在树模型里未必没用，先看业务含义再做决定，别机械套阈值。

行为题是 AI 面的重头，特点是追问会顺着你的上一句继续挖，所以每段经历都要提前准备到第三层：你做了什么、别人因此发生了什么变化、为什么是你出面、结果怎么衡量。英文部分两题都能用「时间 + 事件 + 处理 + 结果」或「观点 + 理由 + 例子」的骨架撑住，练的关键是开口不要停顿、句子短、连接词稳定。
