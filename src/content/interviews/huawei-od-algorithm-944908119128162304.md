### 《参考解析》

**卷积输出尺寸**：`out = floor((in + 2*padding - kernel) / stride) + 1`。这个公式要能当场心算，并且知道它的来源——输出位置的数量等于窗口在输入上能滑动的次数加一。空洞卷积把 kernel 换成 `dilation * (kernel - 1) + 1` 代入即可。

**感受野与参数量**：两层 3×3 堆叠的感受野等于 5×5，但参数量是 `2 × 3 × 3 = 18`，一层 5×5 是 25，而且两层多了两次非线性，表达能力更强。这就是 VGG 用连续小卷积核替代大卷积核的理由。感受野的递推公式是 `RF_i = RF_{i-1} + (k_i - 1) × stride_{累计}`。

**BN 在训练和推理时的行为完全不同**，这是那场面里卡住的地方。训练时对当前 batch 做归一化（减 batch 均值、除 batch 标准差），同时用滑动平均更新全局的 running_mean 和 running_var；推理时不再看当前 batch，而是用训练阶段存下来的这两个统计量做归一化。所以推理的行为取决于训练时有没有正确更新滑动平均，这也是「训练时用大 batch、推理时单条」不会出问题的原因。如果推理时误用了当前 batch 的统计量（比如 batch size 为 1 时方差为 0），输出会完全错乱。

**dropout 除以 keep_prob 是为了保持期望不变**：训练时以概率 p 把神经元置零，如果不做缩放，下一层的输入期望会变成原来的 (1-p) 倍；除以 (1-p)（即 keep_prob）把期望拉回原值。这样训练和推理的激活值尺度一致，推理时就可以直接关掉 dropout 而不用做任何调整。

**过拟合的判断与处理**：判断看训练集与验证集的指标差距是否随 epoch 扩大。处理除了加数据，还有数据增强、正则化（L2、dropout）、早停、降低模型容量、批归一化、以及标签平滑。工业场景里最有效的往往不是换模型，而是把数据分布做对——训练集和线上不一致时，再强的正则化也救不回来。

**anchor-based 与 anchor-free**：前者在特征图上预设一组不同尺度和长宽比的先验框，网络回归相对先验的偏移量，代表是 Faster R-CNN、YOLOv3/v4；后者直接预测关键点或中心点到边界的距离，代表是 CenterNet、FCOS、YOLOv8 之后的主线。anchor-free 省掉了调 anchor 超参和大量先验框带来的正负样本失衡，但对密集小目标有时不如精心设计的 anchor。

**NMS 的完整流程**：把候选框按置信度降序排列 → 取最高分的框加入保留列表 → 计算它与剩余所有框的 IoU → 删掉 IoU 超过阈值的框 → 重复直到候选为空。工程上要注意的点：同类内做还是跨类做（通常按类别分别做）、IoU 阈值的选择（0.5 还是 0.7 影响很大）、以及大量框时的性能（先按分数阈值粗筛，或用 soft-NMS 缓解遮挡场景的漏检）。

**mAP 的计算**：先把预测按置信度排序，逐个累加算出 TP、FP，得到 Precision-Recall 曲线；AP 是 PR 曲线下的面积（实践中用插值或积分近似）；mAP 是所有类别 AP 的平均。COCO 还会在多个 IoU 阈值（0.5 到 0.95，步长 0.05）上取平均，所以同一个模型报「mAP@0.5」和「mAP@[.5:.95]」数值差很多，比较时必须对齐口径。

**Focal Loss 解决的是正负样本与难易样本的失衡**：标准交叉熵对易分样本也会产生不小的 loss，数量占优的背景样本会主导梯度。Focal Loss 乘以 `(1 - p_t)^γ`，让易分样本的权重衰减，γ 一般取 2；再配一个 α 平衡正负类。样本极度不均衡时的组合拳是：Focal Loss + 重采样（过采样少数类或欠采样多数类）+ 难例挖掘（OHEM）+ 调整分类阈值。

**INT8 量化的动机是带宽与算力**：8 位整数的访存和矩阵乘吞吐都比 FP16/FP32 好，边缘设备上通常能带来 2 到 4 倍加速。精度掉了怎么救：用训练后量化（PTQ）先看敏感层，对敏感层保留高精度；做逐通道量化而不是逐张量；用一小批真实数据做校准（而不是随便挑图）；必要时上量化感知训练（QAT），在训练时模拟量化误差。

**从训练框架到边缘设备**：导出（PyTorch → ONNX）→ 图优化（算子融合、常量折叠、去掉训练专用节点）→ 量化/编译（TensorRT、TFLite、厂商工具链）→ 算子适配（不支持的算子要替换或自己写）→ 精度与性能验证（对齐输出、测延迟与内存）。这中间最容易出问题的是预处理和后处理——归一化参数、通道顺序（RGB/BGR）、resize 的插值方式、NMS 的阈值，任一处不一致都会导致精度断崖。

**「测试集 98% 上线 80%」这个场景题，答案的顺序比答案本身重要**。合理的排查顺序是：先确认模型有没有真的生效（是不是还在跑旧版本）→ 再查线上线下预处理是否一致（resize、归一化参数、通道顺序这三处最容易对不上）→ 再看现场数据分布与训练集的差异（光源、来料批次、相机角度）→ 最后看漏检的分布：如果集中在某一类，大概率是该类样本不足，回去补采补训；如果全类都掉，多半是前两个环节的问题。答这题时如果能补一句「我会先确认模型根本没换上来」，会显得真的在生产环境里踩过坑。

**机考的准备策略**：三道题看总分，150 过线，所以目标不是做出 hard，而是「简单题拿满、中等题拿到大部分用例、难题写出框架骗部分分」。那位同学专攻 hard 刷了一个多月，考场上反而一道 hard 都没出——这是很典型的走偏。刷题范围应该按题型覆盖（模拟、哈希、贪心、DP、图搜索、并查集、二分），而不是按难度。

**主管面不谈技术，谈的是稳定性**：为什么换、能不能去这个城市、有没有读博打算、期望薪资、家里意见——这几问背后是一个判断：你会不会干两年就走。「有没有读博打算」答「没有，想在工程上往深走」是清晰的答案，含糊会让对方担心你随时回去读书。

**关于「打标」这个劝退说法的拆解**：数据、部署、落地是这条链上最贵的三段，标注只是链条最前端、可替代性最高的一环。判断自己在这条链上的位置，可以问三个问题：标注规则是谁定的？模型从训练到在设备上跑起来中间那段谁做？上线后准确率掉了谁去现场？三问的答案如果都指向你，那你做的是工程落地而不只是打标。
