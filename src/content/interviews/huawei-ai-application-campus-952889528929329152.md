### 《参考解析》

**机试分值要按权重折算**。华为机试的三道题通常按难度给不同权重，最终得分是各题得分乘权重之和，而不是简单加总。所以「前两题满分、第三题拿一半」的最终分可能远低于直觉。策略上要优先保证高权重题的通过率：先把高权重题的边界与性能测通，再回头补低权重题；不要在一道题上死磕到超时，机试按通过用例给分，部分通过也有分。

**有重复元素的全排列**。标准做法是「排序 + 回溯 + 同层去重」：先对数组排序，回溯时用 `used` 数组标记，遇到 `i > 0 && nums[i] == nums[i-1] && !used[i-1]` 就跳过——这句的含义是「同一层里相同的值只用一次」。用 `next_permutation` 直接过题在笔试里没问题，但面试官让你讲递归思路时要能写出上面的剪枝条件，并说明为什么必须排序（让相同元素相邻）以及 `!used[i-1]` 的方向为什么不能反（决定是「同层去重」还是「同枝去重」）。复杂度 O(n · n!)。

**编译过程**。四步：预处理（宏展开、头文件包含、条件编译，产出 `.i`）、编译（词法 / 语法 / 语义分析，生成中间代码并优化，产出 `.s`）、汇编（汇编代码转机器码，产出 `.o`）、链接（符号解析与重定位，合并目标文件与库，产出可执行文件）。要能说清静态链接与动态链接的区别，以及 `-I`、`-L`、`-l`、`-O2`、`-g` 这些常用参数分别作用在哪一步。

**gcc 与编译工具链**。gcc 是 GNU 的编译器集合（GCC 的 C 前端驱动），负责把源码编译成目标文件并调用链接器。除 gcc 外还有：clang / LLVM（错误信息更友好、工具链生态好）、MSVC（Windows）、icc / icx（Intel）、tcc（极快的轻量编译器）、以及交叉编译工具链（arm-none-eabi-gcc 等）。构建系统层面还有 make、cmake、bazel、ninja。回答时区分「编译器」与「构建系统」，能体现概念清晰。

**摄像头意外关闭怎么解释**。如实说明原因（设备驱动 / 系统休眠 / 权限弹窗），说明当时如何处置（重新打开、继续作答），并提供可核对的证据（机试平台的日志、录制片段、当时的截图）。不要编造，也不要把责任推给平台；重点是证明没有作弊行为且未影响作答。

**RAG 是什么**。检索增强生成：把外部知识切块、向量化存入索引，查询时先检索相关片段，再连同问题一起送进模型生成答案。它解决的是模型参数里没有的私有知识与时效性问题，代价是引入检索链路的不确定性（召回不全就会答错）。要能说清离线建库（切块、embedding、索引）与在线查询（改写、召回、重排、拼上下文、生成）两段。

**向量检索**。把文本映射成高维向量，用余弦相似度或内积衡量语义接近程度；工程上用 ANN（HNSW、IVF-PQ）在召回率与延迟之间取舍。要点：embedding 模型要与语料领域匹配；切块大小影响召回粒度；纯向量对精确匹配（编号、型号、函数名）弱，通常与 BM25 混合；召回后要重排（cross-encoder）提升精度。

**RAG 与微调怎么选**。RAG 适合知识频繁变化、需要引用出处、数据量大的场景，改动成本低、可解释；微调适合改变模型的风格、格式、领域用语和推理模式，不适合注入易变事实（容易过时且难以删除）。实践里常常两者结合：微调教「怎么说」，RAG 提供「说什么」。判断依据是「知识是否高频变化」与「需要的是知识还是能力」。

**幻觉怎么处理**。三层：检索侧保证证据充分（召回不足时不硬答）、生成侧用提示词约束「只依据给定材料，材料不足就说明」并要求引用、后处理侧做一致性校验（关键实体与数字回查原文、用第二个模型做事实核查）。产品侧要给用户可见的出处与置信提示。要承认幻觉无法彻底消除，能做的是降低发生率并让用户可验证。

**超大代码仓怎么处理**。不能把整个仓库塞进上下文。做法是分层检索：先用目录结构与文件摘要建立索引（每个文件的职责、导出符号），再按需求定位到相关文件（关键词 + 向量 + 依赖图），只把相关片段与接口签名送进模型；跨文件理解靠调用图与类型信息补全；改动前先让模型输出「涉及哪些文件、每个文件改什么」的计划，再逐个文件生成 diff 并跑测试。必要时用 AST 做结构化检索，而不是纯文本切片。

**最长递增子序列**。O(n²) 的动态规划是 `dp[i] = max(dp[j]) + 1`（`j < i` 且 `nums[j] < nums[i]`）。O(n log n) 的贪心 + 二分维护一个 `tails` 数组：`tails[k]` 表示长度为 k+1 的递增子序列的最小结尾值，遍历每个数用 `lower_bound` 找到第一个大于等于它的位置并替换，找不到就追加。要说明 `tails` 不是真正的 LIS，只是长度正确；如果要还原序列需要额外记录前驱。面试里被追问「为什么贪心是对的」，可以从「结尾越小越容易接上后续元素」解释。
