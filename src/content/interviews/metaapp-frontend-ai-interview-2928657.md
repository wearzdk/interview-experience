### 《参考解析》

**call、apply、bind**：三者都用于改变函数执行时的 this。call 和 apply 立即执行，区别只在传参形式：call 逐个传，apply 传数组或类数组；bind 不立即执行，返回一个绑定了 this 和部分参数的新函数，且这个绑定不可再被 call/apply 覆盖（new 调用时除外）。手写实现时要处理几个边界：非函数调用报错、this 为 null/undefined 时在非严格模式指向全局对象、bind 返回的函数要保留原函数的 prototype 以便 new、以及 length 和 name 的修正。

**事件冒泡与委托**：事件流分捕获、目标、冒泡三个阶段。addEventListener 的第三个参数可以是布尔值（true 表示捕获）或对象，常用选项有 `capture`、`once`、`passive`、`signal`。`once` 让监听器只触发一次，`passive: true` 告诉浏览器不会调用 preventDefault，滚动性能更好，`signal` 用来批量移除。事件委托是把子元素的监听器挂到共同父级，通过 `event.target` 判断实际点击的是谁，优点是减少监听器数量、动态新增子元素也能生效，缺点是并非所有事件都冒泡（focus、blur 要用 capture），且层级过深时 target 判断要小心。

**内存泄漏**：指对象已经不再使用，但仍被可达引用链持有，GC 无法回收。常见场景：未解绑的事件监听器、未清理的定时器与 setInterval、闭包长期持有大对象、全局变量意外挂载、脱离 DOM 的节点仍被 JS 引用、Map/Set 只增不删、以及第三方库的缓存没有上限。循环引用本身在现代标记清除算法下不是问题，因为 GC 看的是从根是否可达，而不是引用计数；但如果循环引用的对象仍被根引用，那它本来就不该回收。排查用 Chrome DevTools 的 Memory 面板做堆快照对比，看 Detached DOM 和对象增长。

**垃圾回收**：常见有标记清除、引用计数、分代回收、增量与并发回收。V8 把堆分为新生代和老生代：新生代用 Scavenge，把存活对象在两个半区之间复制；老生代用标记清除加标记整理，避免碎片。引用计数的优点是及时，缺点是无法处理循环引用且维护成本高，所以主流引擎只把它当辅助。

**个人项目与协作**：回答项目题的关键是“能自证”。协作方式要讲清 issue 模板、PR 流程、代码规范、CI 检查、版本号与 changelog；版本控制要讲分支模型和发布标准（比如按语义化版本，功能合并到 main 后打 tag，CI 通过才发）。落地成绩不要夸大，star 数、用户数、真实使用场景都可以如实说，重点讲你从 0 到 1 做了什么决策、遇到什么困难、怎么验证效果。被问“怎么确认学会了”，可以答“能不看资料给别人讲清楚、能在一个新场景里复用、能定位并修复相关 bug”，比“看完了文档”有说服力。
