### 《参考解析》

**GRPO 去掉的是 PPO 里的 Critic**。PPO 用价值网络估计基线，GRPO 改成对同一 prompt 采样一组回复、用组内奖励的均值（和标准差）做归一化当优势，省掉一个和策略同规模的模型，显存和训练稳定性都更好。代价是组内样本要足够、奖励尺度要稳，组太小方差大，组太大采样成本高。回答时把「组内归一化 → 优势 → 重要性采样比 → clip」这条链路讲清楚。

**Reward 设计要能回答「为什么是这些项、权重怎么定」**。规则 Reward 可解释、稳定、便宜，适合格式、长度、工具调用是否合法这类硬约束；Reward Model 能覆盖语义质量但会引入偏置和刷分空间。常见组合是规则打底 + 模型打语义分，再加 KL 惩罚防止偏离底座太远。Reward Hacking 的典型表现是模型在某一维度刷分、其他维度悄悄退化，处理办法是加对抗性检查、定期人工抽检、多指标联合评估，而不是只加一个惩罚项。

**DPO 的 reference model 是「不许走太远」的锚**。DPO 直接在偏好对上优化，loss 里用 policy 与 reference 的 log 概率比做隐式奖励，reference 固定为 SFT 模型，KL 约束被写进目标函数里，所以不需要在线采样和 Critic。它的问题是依赖偏好数据质量、对分布外样本泛化有限，长尾场景仍要靠在线 RL 补。

**Top-k 与 Top-p 一起用时先截断候选集再按累积概率截断**：Top-k 固定保留概率最高的 k 个 token，适合控制候选数量；Top-p 保留累积概率达到 p 的最小集合，能随分布形状自适应。两者叠加的顺序不同结果不同，工程上一般先 top-k 再 top-p，temperature 在 logits 上先做缩放。

**线上验证不能只看离线指标**。做法是灰度 + 对照：同流量分桶、固定评测集与人工评审口径、看业务指标（完成率、采纳率、投诉率）而不只是 loss 或 BLEU；同时监控延迟、成本和失败率，离线涨点但线上不涨，通常说明评测集和真实分布有偏。
