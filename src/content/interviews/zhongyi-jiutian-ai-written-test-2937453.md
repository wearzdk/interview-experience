### 《面试题目》

1. 选择题主要考哪些内容（15 道）？
2. AI Coding 题的评分方式是怎样的？
3. 编程题：有 n 天，每天来一个人，第 i 天来的人每天消耗 a(i) 的食物；小牛可以拒绝，同意的话这个人在接下来的天数里每天都会消耗 a(i)。小牛共有 m 的食物，问最多能让多少人来？

### 《参考解析》

**编程题的本质是带权选择。** 关键是把「同意第 i 天来的人」的代价算清楚：他在第 i 天到第 n 天每天消耗 a(i)，所以总消耗是 `cost(i) = (n - i + 1) * a(i)`，与是否同意其他人无关（每个人的消耗是独立的，题目没有说食物消耗会互相影响）。于是问题变成：从 n 个物品中选出尽可能多的物品，使总代价不超过 m。每个物品价值都是 1，所以最优策略是「按代价从小到大取」——取 k 个物品的最小总代价一定是取代价最小的 k 个，前缀和一旦超过 m 就停。复杂度 O(n log n)，来自排序。

```python
def max_people(n, m, a):
    cost = sorted((n - i) * a[i] for i in range(n))  # i 从 0 开始，(n - i) 即剩余天数
    total = 0
    count = 0
    for c in cost:
        if total + c > m:
            break
        total += c
        count += 1
    return count
```

需要向面试官确认的边界有三个：其一，「接下来的天数」是否包含当天（包含则乘 `n - i`，不包含则乘 `n - i - 1`）；其二，如果某天拒绝了一个人，后面的人是否照常来（按题意是照常来）；其三，a(i) 是否可能为 0（为 0 则代价为 0，应优先选）。如果题意改成「同意后只在当天消耗一次」，那代价就是 a(i)，同样是排序贪心；如果改成「总食物按天扣减、人可以中途离开」，就变成带时间维度的调度问题，需要另一套建模。笔试里先把题意复述一遍再动手，能避免整道题方向错。

**贪心的正确性怎么说明。** 用交换论证：假设最优解选了 k 个人，其总代价为 S；如果存在一个未被选的人，其代价比某个已选的人更小，把已选的那个换成他，总代价不会增加，人数不变，所以存在一个最优解恰好由代价最小的 k 个人组成。因此按代价升序取到不能取为止，得到的就是最大人数。

**AI Coding 题的应对。** 国企开始考 AI Coding，评分按 0 到 1 打分，通常看几个维度：需求是否被正确理解、代码能否运行、边界是否处理、以及是否体现了与 AI 协作的过程（提示是否清晰、是否验证、是否修正）。稳妥的做法是先用自然语言把需求拆成输入、输出、约束、边界四块，再让 AI 生成骨架，自己补边界与测试用例，最后跑几个手写样例验证。交付时附上运行结果与已知限制，比只给一段没有验证过的代码得分更高。

**选择题的复习范围。** 这类国企 AI 岗的选择题通常覆盖机器学习基础（过拟合与正则、常用损失、评估指标）、深度学习常识（Transformer、注意力、归一化）、大模型应用（提示工程、RAG、微调）、以及少量编程与数据结构。复习时优先把「指标的含义与适用场景」弄清楚（准确率、召回、F1、AUC、困惑度），这部分最容易出易混淆的选项。
