### 《面试题目》

一面：

1. 自我介绍，当前处于什么阶段（哪一届、什么时候毕业）？
2. 你现在找的是日常实习对吧？能实习多长时间、一周几天？现在人在哪个城市？
3. 之前 2024、2025 的两段实习都是本科期间做的吗？
4. 能不能演示一下之前开发过的页面或项目（不涉及敏感信息）？
5. 你最近没有在实习，对吧？
6. 某个项目是什么时候做的？你在这个项目里具体负责哪些工作？
7. 能介绍一下你开发的 Agent 项目吗？为什么要做、主要解决什么问题？
8. 做这个项目时遇到的最困难、挑战最大的地方是什么？
9. 你现在主要用什么 AI Coding 工具？买的是多少钱的？用的是 VS Code 里的 Codex 插件吗？你们平时是不是也重度使用 AI 工具？
10. 手撕：输入一个字符串，按规则删除其中的 B 和 AC，输出处理后的字符串。（追问：能不能用一种常用的数据结构解决？）
11. 设计一个类似百度的搜索框，用户输入关键词后下面自动展示联想词，从前端视角需要注意哪些问题？
12. 用户连续快速输入时，如何处理频繁的后端请求？
13. 防抖和节流有什么区别？
14. 如果先发出的请求 5 秒才返回、后发出的请求 0.5 秒就返回，如何避免旧请求结果覆盖新结果？
15. Skill 和 MCP 有什么区别？你平时封装过什么 Skill 或 MCP？能看看你的 skillhub 吗？
16. 你希望在这份实习中做哪些事情？未来整体的职业规划是什么？为什么希望往 Agent 和全栈方向发展？
17. 最近有没有用过让你印象特别深刻的 AI 产品？介绍一下。
18. 反问：团队负责什么业务（火山引擎、豆包搜索等）？团队是往全栈发展还是有专职前端？和北京做机器学习平台的部门有什么区别？你觉得我还有哪些不足？

二面：

1. 你从某段时间至今做的几个项目，分别是基于什么目的开展的？
2. 为什么要做图片检索 Agent？主要想解决什么问题？
3. 整个图片的存储和检索是怎么实现的？
4. 图片内容理解是怎么实现的？用了什么 Embedding 模型？模型叫什么名字？
5. 不同 Embedding 模型的向量维度、向量化方案有什么区别？应该如何选择最合适的？
6. 猜测一下，图片 Embedding 模型会把图片的哪些信息向量化存储？
7. 为什么选择 LangGraph 实现从搜索意图理解到 RAG 回答的整个工作流？
8. 为什么选择 BERT 进行分词？
9. 了解 BERT 自身的架构吗？
10. BERT 分词之后，怎么识别哪些词是重要关键词？怎么清洗不重要的词？

12. 了解 Electron 的整体架构吗？为什么它能实现跨平台？

19. 假设 Agent 正在执行一条指令，用户突然想到遗漏了信息又发来一条补充指令，Agent 如何在不中断执行的情况下处理新指令？
20. 如果采用暂存方式处理新指令，正在执行的上一条指令应该怎么处理？
21. 例如 Agent 正在排查服务器卡顿，执行过程中用户补充「重点关注内存」，第二条指令应该怎么和正在执行的指令合并？
22. 如果 Agent 陷入无限死循环，应该如何感知？又该如何退出？

24. 手撕：用 TypeScript/React 实现一个递归树形组件，每个节点显示内容并支持点击展开收起。

### 《参考解析》

这场的价值在于它展示了「AI 全栈」这个岗位现在到底在考什么：项目真实性、技术选型的理由、Agent 运行时的工程细节、以及手写前端组件的基本功。

一面的主体是验证真实性。「能不能演示一下」「这个项目什么时候做的」「你具体负责哪块」这些问题连在一起，就是为了确认简历上的东西你真做过。演示环节作者因为电脑环境没准备好只能无实物讲，这在面试里是明显减分项——面试前把项目跑起来、准备好截图或录屏，是这类面的必做动作。

「删除 B 和 AC」这题的正确解法是栈：顺序扫描，字符是 B 就丢，是 C 且栈顶是 A 就把 A 弹出，否则入栈，O(n) 时间 O(n) 空间。面试官追问数据结构说明他想听这个，而不是反复字符串替换（那样会退化成 O(n²)，且处理不了「删除后新形成的 AC」）。

搜索联想框的四连问是前端高频组合：输入防抖（等用户停手再发）、请求竞态（用自增序号或 AbortController 丢弃过期响应，而不是靠先发先回）、空结果与错误态、以及联想词的缓存与预取。防抖是「最后一次触发后等待 N 毫秒才执行」，节流是「N 毫秒内只执行一次」，二者解决的不是同一个问题。

Skill 与 MCP 的区别可以说清层次：MCP 是模型与外部工具/数据源之间的协议（解决「怎么接」），Skill 是把某类任务的做法、脚本与规范打包成可复用的能力（解决「怎么做这类事」）。能看到候选人的 skillhub，说明这家团队确实在积累这类资产。

二面是本场的技术核心。图片检索 Agent 那串问题层层递进：Embedding 模型选型要看模态（图片要不要和文本对齐）、维度与成本、领域适配（通用 CLIP 类模型对表情包这种排版文字多、风格化的内容效果一般），答不出具体模型名会显得是照抄教程。BERT 分词那几问要注意别混：中文 BERT 用的是字级或 WordPiece 子词，不是分词器；「识别关键词」可以走 TF-IDF/TextRank/BM25 或让模型抽取，清洗则是去停用词、去高频无信息词。

LangGraph 的选型理由要落到「需要循环与状态」：意图理解 → 检索 → 判断是否足够 → 再检索/生成回答，这条链路有分支和回退，用图建模比链式清晰，还能断点恢复。Electron 那两问是典型的「选型反思」：Electron 用 Chromium + Node 把 Web 应用打进桌面，跨平台来自 Chromium 的一致性，代价是体积和内存；如果只是查表情包，轻量方案是纯网页/Tauri/浏览器扩展——面试官在考你会不会为一个简单需求上重武器。

「直接做成 Markdown 让 LLM 读」是个好问题，诚实答更好：小规模、描述质量高的场景确实可行，靠长上下文一次读完省掉检索链路；但规模一大就撞上下文上限、成本和召回精度，而且更新维护困难。自己实现向量检索与用向量库的差别在工程性：索引结构（HNSW/IVF）、过滤、持久化、并发与增量更新，自己写通常准确率不会更高，但能学到东西。

Agent 指令合并与死循环是全场最硬的两问。新指令不该打断正在执行的动作，正确做法是把它作为「追加约束」写进会话状态，在当前步骤结束后由规划环节重新读取；如果用户补充的是方向性修正（重点关注内存），就把它提升为高优先级约束，让后续步骤先做内存相关检查，同时在输出里显式确认「已收到补充」。死循环的感知要靠可观测信号：同一工具同样参数的重复调用次数、步数或 token 预算上限、连续多步没有产生新的观察结果、目标未推进；退出策略是预算熔断 + 强制收敛（让模型基于已有信息给部分结论）+ 上报人工。写 Harness 就是把这些做成外置策略：循环检测器、预算计数器、超时与重试上限、可中断的状态机，而不是指望模型自觉。

前端手写递归树组件考的是基本功：节点递归渲染、展开状态存在一个 Set 或 map 里、key 用节点 id、点击切换时避免整棵树重渲染。模糊搜索那层提一句「支持错别字」就意味着要做编辑距离或前缀树 + 容错匹配，答不上细节至少给出思路。

HR 面问的都是稳定性：为什么考研、为什么没有更好的学校、为什么这段时间没实习、加班能不能接受。这类问题没有标准答案，但前后要一致、不要贬低过去的选择。作者最终的复盘是「一问小林的项目就不同频」，这句话本身值得记住——不是你做过的每个项目都能扛住深挖，面试里要主动把话题引到自己真正掌控的部分。
