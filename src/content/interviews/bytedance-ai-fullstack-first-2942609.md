### 《参考解析》

**35 分钟视频的处理链路**：不能整段塞给模型。链路是：上传到对象存储 → 抽取音轨 → ASR 转写（分段、带时间戳）→ 关键帧抽取（按镜头切换或固定间隔）→ 文本分块与向量化入库 → 检索或按时间线组织 → 模型基于转写与关键帧摘要生成结果。工程上要处理长任务：分片并行、断点续跑、进度回传、失败重试，以及 token 预算控制（只把相关片段送进模型）。

**为什么不直接交给多模态大模型**：一是上下文与时长限制，35 分钟视频的帧序列远超窗口；二是成本，逐帧送模型的开销比 ASR + 少量关键帧高一个量级；三是可控性，转写文本可检索、可引用时间戳、可人工校对，纯视觉理解难以定位依据。缓存的疑问要分清：模型侧的前缀缓存只在相同输入前缀时有效，视频内容各不相同，命中率极低；而自己的链路可以缓存转写结果与向量，重复提问不必重跑。

**100 个字段是否都加索引**：不需要。索引不是越多越好——每个索引占空间、拖慢写入、增加优化器选择成本。只给高频查询条件、连接字段、排序分组字段建索引；优先联合索引覆盖多个条件（注意最左前缀），区分度低的列（性别、状态）单独建索引收益很小。还要避免冗余索引（已有 (a,b) 就不必再建 (a)）。

**Pi agent 与长任务压缩**：Pi 这类 Agent 框架的核心是「模型 + 工具 + 循环」，理解其消息组织、工具调用协议与中断恢复机制。长任务压缩的运行时策略：保留系统提示与最近若干轮原文；把更早的轮次摘要成结构化记录（目标、已完成、关键结论、待办）；工具输出只留摘要与引用，原文落盘可回查；接近窗口阈值时触发压缩而不是等到报错；压缩后校验关键约束是否还在（否则模型会丢目标）。

**手撕 LeetCode 3**：滑动窗口 + 哈希表记录字符最近出现的位置。右指针扩张，遇到重复字符时把左指针移到 `max(left, lastIndex[c] + 1)`，每步更新最大长度，时间 O(n)、空间 O(字符集)。暴力解法是 O(n²) 枚举起点并逐字符判重，面试时要能说出两者的差距以及为什么滑动窗口不会漏解。

**岗位要求**：这个岗位培养 to B 与 to C 的全栈人才，需要前端与后端都了解，不止于调接口。回答时如实说明前端的边界（做过什么、没做过什么），并给出补齐计划。
