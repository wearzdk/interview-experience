### 《参考解析》

1. Spring Boot 通过启动类和自动配置导入候选配置，结合条件注解、环境属性和 Bean 后置处理器完成容器装配；MVC 请求依次经过 DispatcherServlet、映射器、适配器、控制器和消息转换器。
2. Undo log 支持回滚与一致性读，Redo log 保证崩溃恢复，Binlog 记录逻辑变更供复制和恢复使用。两阶段提交让 InnoDB 与 Binlog 对同一事务的提交状态保持一致。
3. B+ 树非叶节点只存键和指针，树高低且叶子有序，适合范围扫描；联合索引从最左列开始连续使用，遇到范围条件后后续列通常不能继续用于定位。
4. Redis 主线程执行命令，网络事件由 I/O 多路复用器批量就绪后处理，避免每个连接创建线程的切换成本。RDB 适合快速恢复，AOF 更接近实时，生产上可组合使用并明确 fsync 策略。
5. 热点 key 可用互斥重建、逻辑过期或请求合并；穿透用空值或布隆过滤器；雪崩通过随机 TTL、分批失效和限流降级缓解。Cluster 按 slot 将 key 分布到分片，扩容时迁移 slot 并更新拓扑。
6. 线程安全 LRU 通常以哈希表加双向链表实现 O(1) 访问和淘汰，再用锁或分段并发控制保护复合操作。接口幂等需要业务唯一键、状态机和唯一约束共同兜底。
7. 分布式事务可按业务选择 TCC、Saga 或可靠消息最终一致性；不能只依赖本地事务。OOM 先结合 GC 日志、堆转储和 MAT 找到大对象或泄漏引用，再从集合生命周期、缓存和线程数入手修复。
