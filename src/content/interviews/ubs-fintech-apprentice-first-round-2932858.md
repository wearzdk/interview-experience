### 《参考解析》

**四位面试官轮番问，考的是能否在不同提问风格下稳定表达**。同一个项目被两个部门从「质量控制」和「编排实现」各问一遍，答法必须一致——第一遍说 validation agent 用 LLM 打分、第二遍说成规则校验，会被判定为不熟。准备方式是把项目写成一张卡片：一句话定位、架构图、关键取舍、指标、失败案例，任何角度都能回到卡片。

**validation agent 的质量控制要分层答，别只说「用大模型判断」**。第一层是确定性校验：schema、必填字段、数值范围、引用是否存在，能拦掉大部分低级错误。第二层是证据校验：答案里的每个结论是否能在检索到的原文里找到支撑，找不到就拒答或降级。第三层才是 LLM-as-judge，必须给 rubric（正确性、完整性、是否臆造），judge 最好与被判模型不同源，避免自己给自己打分。外层再挂抽样人审和失败样本回流——人工纠正过的 case 都进回归集，改 prompt 或换模型前先跑一遍；指标看误判率、与人工标注的一致率、单次校验的成本与延迟。

**「量化指标怎么得来的」是分水岭**，因为大部分人只能报一个漂亮数字。答法是先说基线（人工处理要多久、准确率多少），再说测量方式（固定评测集上的离线指标 + 线上灰度或 A/B 的增量），最后区分绝对值和增量——指标变好可能只是流量结构变了，必须有对照组。说不清基线的指标，会被默认是编的。

**RAG 的流程要能一口气讲完离线与在线两段**。离线是解析（表格、双栏）→ 清洗去重 → chunk → 建父子索引 → embedding → 入库；在线是 query 改写（补全指代、拆子问题、生成多 query）→ 多路召回 → 融合 → rerank → 组装上下文 → 生成并给出引用。父子索引解决粒度矛盾：小子块检索保命中精度，命中后把父块整段喂给模型保上下文完整。常见追问是 chunk 多大，答案不该是数字，而是「按文档结构切，表格单独处理，再按评测集的 recall 调」。

**场景题（给量化团队做 AI 助手）按五段答最稳**：数据（行情、因子、研报、内部文档，先解决权限与合规）→ 输入（自然语言 + 结构化参数，要能识别「哪只票、什么区间」）→ 编排（意图路由到查数、算因子、画图、写报告等工具，工具只读优先，写操作要人确认）→ 评测（数值正确性优先于文采，用 gold set 逐条比对，涉及金额的一律人工复核）→ 客户（交付形态、审计留痕、响应延迟）。这一段能讲出「哪里必须人来兜底」，比堆名词更加分。

**LangGraph 要讲清它和 chain 的差别**：显式状态图，节点是函数、边可以是条件边，因此能循环、能回退；checkpoint 把每步状态落盘，支持断点续跑和 human-in-the-loop 中断，子图用来复用一段流程。**Agent 与 workflow 的区别**在控制权：路径预先定义死的是 workflow，由模型决定下一步的是 agent；生产系统多数是 workflow 包住若干 agent 节点。

**skill 与 MCP 不是同类东西**：skill 是把「怎么做一件事」打包（说明、脚本、规范），解决知识与流程复用；MCP 是工具接入协议，解决「模型怎么调到外部系统」。选哪个看能力边界在提示词还是在外部服务。「MCP 跑本地还是 website」则要能说清 transport 的区别（本地 stdio、远程 HTTP/SSE）以及对凭据、内网访问的影响。

**全英面真正的难点是听不懂，而不是不会**。作者两次没听清都主动追问，面试官反而补出关键词（fine-tuning）——沉默猜答案比问一句伤害大得多。准备时把讲稿压成英文关键词卡片，把 retrieval、rerank、orchestration、evaluation 这些词练到不用想。
