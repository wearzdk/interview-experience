### 《参考解析》

**先说清 G、M、P 各管什么**

G 是 goroutine，保存任务执行所需的状态；M 是操作系统线程；P 保存执行用户 Go 代码所需的调度和内存分配资源。M 执行用户 Go 代码时需要持有 P，P 的数量由 GOMAXPROCS 决定。它限制的是同时执行用户 Go 代码的并行度，不是整个进程能创建多少个线程。可以对照 [Go 运行时说明](https://go.dev/src/runtime/HACKING) 理解这几个对象的关系。

协程通信可以用 channel 传递数据，也可以共享内存并用锁或原子操作同步。面试时接着说明任务何时结束、取消信号如何传递，以及发送方是否可能一直阻塞，比只列出 channel 更完整。

**链路追踪要能定位慢在哪一步**

一次 Agent 请求往往包含多次模型调用和工具调用。trace 表示这次请求的整体执行链，span 描述其中的一步，通常记录起止时间、父子关系、状态与错误。回答时可以拿真实经历说明：总耗时增加，是模型响应变慢、某个工具卡住，还是重试次数增多。日志里的同一个 trace 标识能把这些片段关联起来。

**有序集合为什么适合排行榜**

有序集合的成员唯一，按分数排序，既能更新成员分数，也能查询排名和分数范围。Redis 源码介绍了跳表与哈希表配合的实现：前者支持有序遍历，后者便于按成员查找。具体编码还要结合版本与集合规模，不能只凭“使用了 ZSET”就推断所有实例的内部布局。参见 [Redis 有序集合实现](https://github.com/redis/redis/blob/unstable/src/t_zset.c)。

红黑树通过颜色约束和旋转维持平衡；跳表通过多层索引缩短查找路径。两者都能支持有序查询，但实现、内存布局和维护方式不同。范围扫描时，跳表找到起点后沿底层链向后走即可。

**容器题从内核机制讲起**

Linux 容器利用 namespace 隔离进程看到的部分系统资源，通过 cgroup 管理资源用量。容器与宿主机共享内核，不能把它解释成每个容器都启动一套完整的虚拟机。再接上实际用过的命令，例如用 `docker ps` 看运行状态、`docker logs` 读日志、`docker inspect` 查配置、`docker exec` 进入运行中的容器执行命令。

Kubernetes 则需要区分控制面和节点：API Server 提供集群接口，etcd 保存集群状态，调度器为 Pod 选择节点，控制器持续协调实际状态与期望状态；节点上的 kubelet 负责落实 Pod 的运行要求，并与容器运行时协作。
