### 《面试题目》

1. 请做一下自我介绍。
2. 介绍一下你做过的项目。
3. 讲一下你研究的问题背景、现有方法、你们的发现，以及你的具体贡献。
4. 从零写一个能用的 harness，至少需要哪些组件？
5. 为什么 2023 年 ReAct 就出现了，直到 2025 年才真正流行起来？
6. 简述一下手写一个 ReAct 怎么写。

### 《参考解析》

**harness 的最小组成**：一个能跑起来的 agent harness 至少要有五件东西。① 主循环：读模型输出、判断是工具调用还是最终答复、把工具结果拼回上下文、再发下一轮，带轮数上限和取消机制。② 工具层：工具注册表（名字、描述、JSON Schema）、参数校验、执行与超时、错误回填给模型。③ 上下文管理：历史消息的裁剪与压缩（摘要旧轮次、保留关键约束与已确认事实）、token 预算控制。④ 权限与安全：哪些工具需要确认、文件与命令的作用域、危险操作的白名单。⑤ 可观测与状态：会话持久化、todo/计划列表、日志与耗时统计，方便中断后恢复和事后复盘。往上再加评测与重试就是产品级。

**为什么 ReAct 到现在才流行**：ReAct 本身只是「思考—行动—观察」的循环范式，2023 年就能写出来，但当时基座模型的指令遵循和多步工具调用不稳定，长上下文也撑不住几十轮循环，跑几轮就漂。到 2025 年三个条件同时到位：模型能可靠地按 schema 出工具调用并在失败后自我纠正；上下文窗口与缓存成本下降到能承受长轨迹；真实需求出现——写代码、查资料、跑流程这类任务必须多步执行，单轮问答解决不了。此外工具生态（MCP 这类统一协议）把「接一个工具」的成本从写适配器降到配置，才让 Agent 从 demo 变成可交付。

**手写 ReAct**：核心就是一个 while 循环。system prompt 里写清可用工具清单和输出格式（thought / action / action_input），把用户任务作为第一条消息；每轮把模型输出解析出来，若是 action 就到工具注册表里查函数、校验参数、执行，把 observation 作为新消息追加；若给出的是最终答案或达到步数上限就退出。工程上要补三件事：解析失败要能把错误原文回给模型让它重来而不是直接崩；每轮记录 token 与时延，超预算就压缩历史；终止条件要显式（模型自报完成、命中最大步数、连续无进展）。

**研究与项目的答法**：面试官追问「背景—方法—发现—贡献」实际上是在验你有没有真的做过。讲研究按论文的四段式说：这个问题为什么重要、别人怎么做的、你的方法新在哪、你个人具体做了哪一块、结果是多少。讲项目则要能说出数据从哪来、指标怎么定、失败案例长什么样，别停在架构图上。
