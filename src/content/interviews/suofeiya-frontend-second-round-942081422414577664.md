### 《参考解析》

**SSE 断点续传**要在协议里带任务 ID、消息序号和结束标记，客户端记录最后收到的序号，重连时带 `Last-Event-ID` 或查询参数；服务端按任务缓存已发送内容，从断点继续。多任务并发时用任务 ID 区分事件流，前端按 ID 路由到对应消息列表，不能只靠全局连接。

**流式渲染卡顿**用批量更新和虚拟列表：把分片先放进缓冲区，按 `requestAnimationFrame` 或固定时间窗合并渲染，避免每个 token 都触发 React 重渲染；长列表只渲染可视区域。权限和 Token 用路由守卫 + 请求拦截器，刷新 Token 用单例锁防止并发，失败清理登录态。

**组件与布局**：弹窗 API 可以设计成 `title`、`content`、`footer` 插槽或 `actions` 数组、`visible`、`onCancel/onConfirm`，内部用 Portal 挂到 body，处理焦点锁定、ESC 关闭和滚动锁。响应式用 CSS Grid `repeat(auto-fit, minmax(...))` 或媒体查询。无限滚动用 IntersectionObserver 监听哨兵，加 `loading` 和 `hasMore` 状态防重入，用游标或页码判断结束。

**并行请求**用 `Promise.allSettled`，每个请求独立 `then` 渲染成功数据，失败显示局部错误；`Promise.all` 一失败全失败，`race` 取最先完成。页面越用越卡，查内存泄漏（未清理的定时器/监听器/闭包）、DOM 节点增长、事件监听重复绑定、缓存无上限和长任务，用 Performance 面板和内存快照定位。
