### 《面试题目》

1. MySQL 的 B+ 树索引怎样影响 SQL 优化？
2. 怎样求最大乘积连续子数组？
3. 数组与 List 怎样按访问模式选择？
4. 推送断线后怎样恢复？

### 《参考解析》

**B+ 树索引与 SQL 优化**：先看查询条件能不能用上索引的最左前缀——联合索引 `(a, b, c)` 上，`where a=? and b=?` 能用，`where b=?` 用不上；范围条件之后的列不再走索引定位。再看要不要回表：只查索引里已有的列就是覆盖索引，`explain` 的 `Extra` 会显示 `Using index`；否则要按主键再查一次聚簇索引。排序与分组也可能用索引避免 `filesort`。最后看优化器为什么没选索引：区分度太低（性别、状态）、统计信息过期、或者条件上套了函数导致索引失效。不要把「有索引」等同于「查得快」，数据分布和回表代价都会改变执行计划。

**最大乘积连续子数组**：和最大子数组和不同，负数会让最小值翻成最大值，所以每个位置要同时维护以当前元素结尾的最大乘积与最小乘积。转移是 `newMax = max(x, maxProd*x, minProd*x)`、`newMin = min(x, maxProd*x, minProd*x)`，答案取过程中的最大 `newMax`。实现上必须先用旧的 `maxProd/minProd` 把两个新值都算出来再一起更新，先改最大值会让最小值用错状态。边界要单独走：数组含 0（乘积归零，相当于重新开始）、只有一个元素、连续负数个数的奇偶。

**数组与 List 怎么选**：先确认语言和 `List` 的具体实现——Java 的 `List` 是接口，`ArrayList` 底层是数组、随机访问 O(1)、尾部追加摊还 O(1)、中间插入 O(n)；`LinkedList` 是双向链表，按下标访问 O(n)，头尾插入 O(1)，但每个节点多两个指针、缓存不友好。按访问模式选：以随机读和遍历为主用 `ArrayList`；只在两端进出用 `ArrayDeque`；确实需要频繁在中间插入删除且元素较大时才考虑链表。面试时先问清数据规模与操作比例，再给结论，不要一看到 `List` 就往链表上想。

**推送断线恢复**：这道题的关键是把「恢复」拆成四件事。识别断线：心跳超时、TCP 断开、或收到服务端的关闭帧，客户端要有重连状态机与指数退避加抖动的重试，避免雪崩。续传位置：客户端记住最后收到的消息序号或游标，重连时带上，服务端从该位置之后补发。去重与顺序：消息带单调递增的序号或消息 ID，客户端按序号去重、按序落位，缺失时主动拉取区间。幂等与状态一致：重连后先拉一次全量快照再增量同步，避免只靠增量补齐导致状态漂移。原帖提到的协议名写作「SEE」，尚未核实，具体帧格式与心跳参数要以对应协议文档为准。
