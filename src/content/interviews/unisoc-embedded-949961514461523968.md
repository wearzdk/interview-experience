### 《参考解析》

**编译与链接**：预处理展开宏、包含头文件、处理条件编译；编译把 C 转成汇编；汇编生成可重定位目标文件，此时外部符号地址还是占位；链接做符号解析与重定位，把多个目标文件与库拼成可执行文件，决定每个符号的最终地址。强符号是已初始化的全局变量和函数定义，弱符号是未初始化全局变量、或显式 `__attribute__((weak))` 的声明；多个强符号重名直接报重复定义，强符号与弱符号重名时链接器取强符号，多个弱符号取占用空间最大的那个，这也是「同名全局变量不报错却行为诡异」的常见来源。

**大小端与位域**：判断用 `union { uint32_t i; uint8_t c[4]; }` 看首字节，或者取地址强转成 `uint8_t*`。必须关心字节序的场合是跨机器传输、读写多字节硬件寄存器、解析文件格式与协议头，以及用位域映射寄存器——位域的分配顺序、跨字节如何拼接、是否允许跨存储单元，C 标准都没有规定，由编译器与目标 ABI 决定，所以寄存器映射宁可用移位与掩码，不要用位域。

**I2C 时序**：空闲时 SCL、SDA 都由上拉电阻保持高电平。起始条件是 SCL 高时 SDA 由高变低，停止条件是 SCL 高时 SDA 由低变高；数据传输时 SCL 低电平期间改变 SDA、高电平期间采样。每传 8 位后第 9 个时钟由接收方拉低 SDA 表示 ACK，不拉低就是 NACK——地址阶段 NACK 说明从机不在或地址错，数据阶段 NACK 可能是从机忙或写保护。因为总线是开漏结构，只能主动拉低、靠上拉拉高，所以必须有上拉电阻，也因此多设备可以线与共享。

**Cache 为什么能加速与三种映射**：加速来自时间局部性（刚访问的数据还会被访问）与空间局部性（相邻地址会被一起访问），把内存到 CPU 的慢路径换成片上 SRAM 的快路径。直接映射是「块号 mod 行数」定位唯一行，查找只需比较 tag，硬件最省但冲突多；全相联可放任意行，冲突最少但需要并行比较所有 tag，成本高；组相联是折中——先按组号定位一组，再在组内全相联比较，组数越多冲突越少、比较器越多。

**MESI 与一致性**：多核各有私有 Cache，同一地址可能在多个核里各有一份，写其中一份就与其他副本不一致。MESI 用四种状态描述行——Modified（本核独占且已改，与内存不同）、Exclusive（独占且与内存一致）、Shared（多核共享只读）、Invalid（失效）。写命中 Shared 行要先发 invalidate 让其他核置 I，收到确认后才改；写命中 Exclusive 可直接转为 M，不发总线事务；写未命中要先把行读进来（或整行写时用写分配/不分配策略）。本质是靠总线嗅探或目录协议维持「同一时刻最多一个可写副本」。

**写回与写通**：写通是每次写同时更新 Cache 与下一级内存，实现简单、一致性容易维护，但写带宽开销大；写回是只改 Cache 并置脏位，行被替换时才写回，写带宽省但需要脏位管理与替换时的额外延迟，且掉电时脏数据会丢。写未命中时还要配写分配（先把行读进来再改）或不分配（直接写穿透），常见组合是写回加写分配。

**Cache 与 MMU 的先后**：这个问题不能一句话答死，取决于 Cache 用虚拟地址还是物理地址索引与打 tag。VIPT 用虚拟地址的页内偏移并行查 Cache、同时查 TLB，tag 用物理地址，所以查找与地址转换可以重叠；PIPT 必须等 MMU 转换完拿到物理地址再查 Cache，延迟更高但不存在别名问题；VIVT 完全用虚拟地址，快但同一物理页映射到多个虚拟地址时会出现别名，需要靠页着色或硬件维护。现代处理器多是 VIPT 加 L1 尺寸不超过页大小的约束，从而在并行查找的同时避免别名。

**流水线与冒险**：把一条指令拆成取指、译码、执行、访存、写回，多级重叠以提高吞吐。数据冒险是后面的指令要用前面还没写回的结果，靠转发（旁路）解决，转发解决不了的用停顿或编译器插空指令；控制冒险是分支结果未定就取了后面的指令，靠分支预测加预测失败时的冲刷，或延迟槽；结构冒险是两条指令争同一硬件资源，靠增加端口或分离指令与数据 Cache。

**启动流程**：上电复位后 CPU 从固定复位向量取指，执行片内 BootROM——它初始化最基本的时钟与存储控制器，按引脚或熔丝决定的启动介质（SPI Flash、eMMC、SD）读取第一阶段 bootloader 到片内 SRAM 运行；SPL 再把完整的 U-Boot 搬到已初始化好的 DDR 并跳转；U-Boot 初始化串口、网络、DDR 参数，加载设备树与内核镜像到内存，设置启动参数后跳进内核；内核解压、建立页表、初始化内存管理与驱动模型、挂载根文件系统，最后启动第一个用户态进程。DDR 还没初始化时代码只能跑在片内 SRAM 或 XIP，这是 SPL 必须存在的原因。

**AMBA 与 AXI/AHB**：AHB 是单主控总线，流水线式地址与数据相位，适合低速外设；AXI 是面向高带宽的多通道协议，读地址、读数据、写地址、写数据、写响应各自独立通道，支持乱序完成、多笔未完成事务、burst 与 ID 标记，适合 CPU 与 DDR、DMA 这类高吞吐主设备。一次内存访问经过：CPU 发出虚拟地址 → TLB 查转换（缺失则查页表并可能触发缺页异常）→ 得到物理地址 → L1 Cache 查找（缺失则向 L2/LLC）→ 一致性检查与总线事务 → 内存控制器把物理地址译成 bank/row/column → DRAM 读出整行到行缓冲再取列 → 数据沿原路返回并填入各级 Cache 与寄存器。
