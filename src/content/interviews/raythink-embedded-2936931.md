### 《参考解析》

**进程与线程**：进程是资源分配单位，有独立地址空间与文件描述符；线程是调度单位，共享进程的地址空间、堆与全局变量，各自有栈与寄存器。进程切换要换页表、开销大；线程切换只换栈与寄存器、开销小。通信方式：进程间用管道、共享内存、消息队列、Socket；线程间用全局变量加锁、条件变量、信号量。嵌入式里还要提 RTOS 的任务本质是线程，共享同一地址空间。

**ADC 采集精度的影响因素**：参考电压的稳定性与精度（基准漂移直接变成测量误差）、分辨率（位数决定最小刻度）、采样率与信号带宽的匹配（采样不足会混叠）、输入阻抗与信号源阻抗的匹配（分压导致偏差）、前端运放的失调与噪声、电源与地线噪声、PCB 布局（模拟地与数字地、走线耦合）、温度漂移、校准（零点与满量程校准、多点拟合）。提升手段：用外部高精度基准、加 RC 滤波与跟随器、多次采样取平均或过采样、做工厂校准并保存系数、隔离数字噪声。

**死锁与避免**：四个必要条件见前述。嵌入式场景常见于两个任务各持一把锁再申请对方那把。避免手段：统一加锁顺序、用带超时的获取并在失败时释放已持有的锁、缩短临界区、用单一锁保护一组资源、必要时用无锁队列或消息传递替代共享内存。

**内存池原理**：预先向系统申请一大块内存，按固定大小切成块，用空闲链表管理。分配时从链表取一块，释放时归还链表。优点：分配释放时间确定（O(1)）、无外部碎片、不会因为长期运行而内存碎片化；缺点：块大小固定会造成内部浪费，需要按用途建多个不同粒度的池。实现要点：块头记录池信息或独立位图标记使用状态、加锁保证多任务安全、分配失败要有兜底策略（等待、丢弃或触发告警）、调试时加魔数与使用计数检测越界与重复释放。

**结构体对齐**：编译器为了让成员落在自然对齐的地址上，会在成员之间插入填充字节，结构体总大小也会补齐到最大成员对齐数的整数倍。规则：每个成员的偏移必须是其自身大小的整数倍（在默认对齐下），结构体大小是最大对齐数的整数倍。用 `#pragma pack(1)` 或 `__attribute__((packed))` 可以取消填充，适合协议帧与 Flash 存储；代价是可能产生非对齐访问，在部分架构上触发异常或性能下降，需要编译器支持非对齐访问或手动按字节拷贝。面试常问「改变成员顺序大小会不会变」——会，把大成员放前面通常能减少填充。

**大小端判断**：用联合体或指针取首字节。`union { uint32_t i; uint8_t c[4]; } u; u.i = 1;` 若 `u.c[0] == 1` 则为小端（低位字节在低地址），否则为大端。也可以用 `uint16_t x = 0x0102; *(uint8_t*)&x` 判断。网络字节序是大端，通信时要统一用 `htonl/ntohl` 转换。

**Git 常用指令**：`clone`、`status`、`add`、`commit`、`push`、`pull`、`fetch`、`branch`、`checkout`/`switch`、`merge`、`rebase`、`log`、`diff`、`reset`、`revert`、`stash`、`tag`、`cherry-pick`。要能说清 reset 与 revert 的区别：reset 改写历史（本地用），revert 生成反向提交（已推送的分支用）。
