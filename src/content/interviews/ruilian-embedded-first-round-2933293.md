### 《参考解析》

**`static` 是这场翻车的核心，它有三个完全不同的语义**：修饰局部变量 → 生命周期变成整个程序、只初始化一次，存在静态存储区（.data 或 .bss），函数返回后值还在；修饰全局变量 / 函数 → 链接属性变成内部链接（只在本编译单元可见），避免符号冲突；修饰类的成员变量 / 成员函数 → 属于类而不是对象，成员变量要在类外定义、全类共享一份，静态成员函数没有 `this` 指针、不能访问非静态成员。所以「static 初始化一次后不可变」是错的，「不可变」是 `const` 的语义，`static const` 才是两者叠加。这个区分必须能在面试里一句话说清。

**同步与互斥是两个维度**：互斥是「同一时刻只允许一个执行体进入临界区」（锁、信号量初值 1）；同步是「按约定的先后顺序协作」（条件变量、信号量控制执行次序）。同步与异步是调用模型：同步调用要等结果返回才继续，异步发起后立刻返回、结果通过回调 / 事件 / future 通知。这两组概念极易混，答的时候先定义清楚再举例。

**IO 多路复用**：一个线程用 `select/poll/epoll` 同时监视多个 fd，谁就绪处理谁，避免「一连接一线程」的资源浪费；`epoll` 用内核红黑树 + 就绪链表，没有 fd 上限、返回即就绪，LT 是没处理完会继续通知、ET 是只在状态变化时通知一次（必须循环读到 `EAGAIN`）。追问通常会往「ET 为什么要非阻塞 fd」「epoll 惊群怎么处理（EPOLLEXCLUSIVE / SO_REUSEPORT）」走。

**粘包拆包**：TCP 是字节流、没有消息边界，发送方的多次写可能被合并（Nagle 算法加剧），接收方一次读可能读到半个或一个半包。解决靠应用层定界：长度字段（最常用）、固定长度、分隔符（注意转义）、或自描述协议（如 protobuf 带长度前缀）。UDP 是数据报、保留边界，不存在粘包但要自己处理丢包与乱序。

**RAII** 是「资源获取即初始化」：把资源（内存、文件句柄、锁、socket）的生命周期绑定到对象生命周期，构造时获取、析构时释放，异常安全靠栈展开保证析构一定执行；`std::lock_guard`、`std::unique_ptr`、`std::fstream` 都是它的应用。

**多态与虚函数**：基类声明 `virtual`，每个含虚函数的类有一张虚函数表（vtable），对象里存 vptr 指向它；通过基类指针调用时按对象的实际类型查表（动态绑定），所以基类指针指向子类对象会调子类的重写版本。注意构造 / 析构函数里调用虚函数不会多态（构造期 vptr 还指向基类），以及基类析构必须是虚的。这个知识点作者答乱了，其实是 C++ 面试出现频率最高的一组题，把 vtable 的机制 + 虚析构 + 纯虚函数与抽象类串起来记最稳。
