### 《参考解析》

**先看这份题单的结构**：一面问「你做过什么」，二面问「你懂不懂原理」，两面的分界线非常清楚。准备时把项目拆成「动机—方案—结果—反思」四段，一面用前两段讲清楚，二面用后两段接住追问。

**SID 那一串问题其实是同一个答案的三个切面**。「为什么用大模型学 ID」讲的是信号来源：原生 ID 纯符号、无先验，长尾商品曝光少、梯度稀疏；用内容与行为序列压出来的语义码天然带相似性先验。「SID 相比 Embedding 的优势」讲的是表达形式：一串离散码的组合空间远大于单个向量，且长尾能被码本共享。「为什么原生 ID 难收敛」讲的是优化难度：高频商品把码本占满，低频商品几乎拿不到更新。三问答完要能落回自己的项目，说出具体提升了哪个指标。

**RQVAE 的两个必答点是残差量化与梯度直通**。残差量化：多层码本逐层编码上一层重建后的残差，小码本拼出大表达空间。梯度：`argmin` 不可导，前向取最近码字、反向用 straight-through 把梯度直接传给编码器输出，再加码本损失约束编码器输出别离选中码字太远；码本更新用 EMA 更稳。补一句码本塌缩的监控与死码重启，是明显的加分。

**Hinge loss 手写**：`relu(margin - (s_pos - s_neg))` 取均值。讲的时候点出「只有正样本没超过负样本 margin 时才有梯度」，以及 margin 的作用是让排序有余量、不是把分数拉得越开越好。

**排序范式的对照表要能背下来**：pointwise 用 logloss 或 MSE，简单但和排序指标不一致；pairwise 用 hinge 或 BPR，只关心相对序；listwise 用 ListNet 交叉熵或 LambdaRank 的 lambda 梯度，最贴近 NDCG，代价是列表构造与实现复杂。

**SFT 与 GRPO 的分野在监督信号**：SFT 逐 token 模仿标准答案，学得快但不会因为走错路径被惩罚；GRPO 用同一 prompt 的一组采样做组内相对优势，不训 critic，奖励函数承担全部监督职责。奖励设计要分「可验证的硬指标」（格式、答案正确）与「需要打分的软指标」（推理质量、简洁度），正负样本由组内归一化自然产生。

**两道手撕都是基本功**：快速选择平均 O(n)、最坏 O(n²)，讲清随机化 pivot 与只递归一侧；零钱兑换先确认是求最少硬币还是求方案数——前者取 min、后者累加，循环方向与初值都不同，先问再写能省掉返工。
