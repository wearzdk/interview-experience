### 《参考解析》

**为什么用互斥锁**：当多个任务访问同一份共享资源且至少有一个写操作时，需要互斥保证一致性。典型场景是串口或总线设备被多个任务共用、共享缓冲区读写、文件系统操作。互斥锁与二值信号量的区别在于所有权：互斥锁有持有者概念，支持优先级继承，只能在持有它的任务中释放；信号量可以跨任务释放，适合中断通知任务。选择依据是「是否需要所有权与优先级继承」。

**优先级反转与解决**：高优先级任务等待低优先级任务持有的锁，而中优先级任务抢占低优先级任务运行，导致高优先级任务被间接阻塞，这就是优先级反转。解决手段：优先级继承（低优先级任务持锁期间临时提升到等待者的优先级，FreeRTOS 的 mutex 支持）；优先级天花板（把锁的优先级设为可能使用它的最高任务优先级）；设计上缩短临界区、避免在持锁期间做耗时操作、把共享资源改为消息传递（队列）而不是共享内存。

**任务状态变化**：FreeRTOS 中任务有运行、就绪、阻塞、挂起、删除。更高优先级任务就绪会立即抢占当前任务，当前任务从运行转为就绪；同优先级任务按时间片轮转；当前任务调用阻塞 API（延时、等队列、等信号量）进入阻塞态并带超时；调用 `vTaskSuspend` 进入挂起态，只能由 `vTaskResume` 唤醒，不参与调度。

**I2C 错误排查**：先分类：无应答（NACK）、总线被拉低、时序错误、地址错误。排查顺序：用示波器或逻辑分析仪看 SCL/SDA 波形，确认起始信号、地址字节、ACK 位是否正常；确认从设备地址（7 位与 8 位写法差异是高频错误）；确认上拉电阻与总线电容（上拉过大导致上升沿慢）；确认速率模式与从设备支持的最高频率；总线被拉低时检查是否有从设备在传输中复位、需要发 9 个时钟脉冲解锁；用 `i2cdetect` 扫描地址。软件侧检查时钟延展处理、重试逻辑与错误码。

**CAN 与 CAN FD**：CAN 经典帧数据段最长 8 字节、速率最高 1 Mbps；CAN FD 数据段最长 64 字节，支持数据段变速（仲裁段保持低速保证兼容，数据段可提速到 5 Mbps 以上），帧格式增加 FDF 与 BRS 位，CRC 更强。两者可以在同一总线共存：FD 帧在仲裁段与传统帧兼容，传统控制器遇到 FD 帧会报错帧，所以需要控制器支持 FD 或做网关隔离。注意事项：收发器要支持 FD 速率、终端电阻与线束质量要满足高速率、混合组网时传统节点会破坏 FD 帧。

**CAN 仲裁机制**：基于 ID 的逐位仲裁，采用「显性位覆盖隐性位」的线与逻辑。多个节点同时发送时，逐位比较 ID，发送隐性位却检测到显性位的节点退出仲裁转为接收，ID 数值越小优先级越高。仲裁是非破坏性的，赢家继续发送且不损失时间。这也决定了 ID 分配要按实时性要求设计，紧急报文用小 ID。

**SPI 地址位宽与速率**：地址位宽由从设备寄存器地址空间决定（8 位、16 位、24 位），也受协议约定影响（有些器件用命令字节加地址字节）。速率由主设备分频、从设备最高时钟、PCB 走线与信号完整性共同决定；速率过高会出现采样错误，需要用逻辑分析仪确认建立保持时间。

**DMA 的作用**：直接内存访问，外设与内存之间搬运数据不经过 CPU，减少中断次数与 CPU 占用，适合串口、SPI、ADC 的批量数据传输。使用要点：缓冲区对齐与大小、传输完成与半传输中断、双缓冲避免处理期间被覆盖、cache 一致性（有 D-Cache 的 MCU 要在 DMA 前后做清理或无效化）、DMA 与 CPU 同时访问同一块内存的竞态。
