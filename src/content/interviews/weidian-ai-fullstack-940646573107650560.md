### 《面试题目》

1. 自我介绍
2. 讲一下 agent 项目的状态机是怎么具体流转的
3. 讲一下从 query 到输出的全流程
4. 如果 AI 涉及资金方面的操作会怎么办
5. 讲一下你负责的部分（意图识别）
6. 你做的东西如何量化的，给你分配任务的人对你的指标要求是什么，qps 多少
7. 你遇到了什么问题，如何去解决
8. 中间模型的选型是怎么选的
9. 是否用 AI 开发，AI 给出错误建议了怎么办，你如何有自己的业务判断
10. 上下文系统和记忆机制的实现，短期记忆和用户画像，什么信息填入 prefill 的窗口
11. 大模型微调，训练语料
12. 反问

### 《参考解析》

**状态机与全流程**：这类项目答的是「可控性」。典型状态机是：接收 query → 意图识别与参数抽取 → 路由到具体能力（知识库问答 / 工具调用 / 澄清追问）→ 执行 → 结果校验 → 生成回复 → 记录与埋点。每一步都有明确的进入条件、失败出口和超时策略，而不是让模型自由发挥。面试官会追问的是异常分支：意图识别不出来怎么办（追问澄清而不是硬猜）、工具调用失败怎么办（重试上限 + 降级为人工 / 静态答案）、模型输出不合规怎么办（校验层拦下重生成）。把这些讲清楚，才说明状态机真的落过地。

**涉及资金的操作怎么办**：这是 AI 全栈岗的必问题，实际考的是「权限与确认的设计」。原则是模型不直接执行不可逆的资金动作：模型只能生成结构化意图（比如「用户想退款，订单号 X，金额 Y」），真正执行交给后端服务，并且必须经过规则校验（金额上限、订单状态、风控名单）+ 用户显式确认 + 人工或二次审批，全链路留审计日志。模型侧再补一层防护：提示词约束、输出 schema 校验、敏感意图单独分类拦截（前面提到的「怎么保证模型不自主说好的我帮你退款」就是这一层）。一句话总结：大模型负责理解与生成，资金的判定与执行必须在确定性代码里。

**量化指标怎么写**：面试官问「qps 多少、指标要求是什么」是在验证你到底是不是核心参与者。可以量化的维度包括：离线指标（意图识别准确率、召回率、人工介入率、平均轮次）、在线指标（响应延迟 p95/p99、QPS、成功率、超时率）、业务指标（问题解决率、转人工率、用户满意度）、成本指标（单次对话 token 消耗、模型调用成本）。数据来源要说清（线上埋点、离线评测集、A/B 实验），没做过就明确说没测过，别编数字——追问细节时一定会穿。

**模型选型**：选型不是选「最强的」，而是按任务分层。意图识别、槽位抽取这类确定性任务用小模型或分类模型（0.6B / 1.5B / BERT 级），延迟低、成本低、可本地部署；开放问答和复杂规划才上大模型。评估维度包括：效果（在自己的评测集上比，不看榜单）、延迟、单 token 成本、上下文长度、是否支持 function call / 结构化输出、私有化与合规要求。常见做法是路由：简单 query 走小模型，置信度低或复杂 query 才升级到大模型，用仲裁阈值平衡成本与效果。中间可以插一层「模型能力对照实验」——同一个评测集跑多个候选，按准确率和成本画帕累托前沿再定。

**上下文与记忆**：短期记忆是当前会话的消息序列，长期记忆是跨会话的用户画像与事实。工程上的核心是「窗口里放什么」：系统提示（角色与约束，常驻）、用户画像摘要（常驻，压缩成一两段）、近期对话原文（保真，最近 N 轮）、更早的历史用滚动摘要替代、最后加上本轮检索到的知识片段。装配顺序也重要——把最关键的约束放在开头和结尾（中间容易丢），长文档用引用标注 + 按需展开而不是全塞进去。压缩要防「摘要漂移」：每次沿用旧摘要会累积误差，常见做法是定期用原始消息重建摘要，或者摘要 + 关键事实表（结构化槽位）双写。

**微调与 AI 辅助开发的判断力**：微调部分要能说清三件事：数据从哪来（业务日志清洗、人工标注、合成增强）、数据格式与规模（指令 / 偏好对，几千到几万条量级）、怎么验证（留出评测集对比基座，看目标指标而不是 loss）。如果只是风格对齐或领域术语，优先考虑 RAG + 提示词，微调的成本和迭代周期都不小。至于「AI 给的错误建议怎么办」，回答要落到可执行的方法：先用小样例验证再全量改、看官方文档和源码而不是只信模型、关键改动先写测试、不清楚的领域找同事确认，以及明确「模型是提效工具，业务正确性由我负责」。

**这一轮的落点**：全程无手撕，问题密集围绕项目，属于「能不能把一个 AI 应用系统讲明白」的面试。面试官最后那句「可以全 AI 开发，但是要有自己的判断力」其实点出了这类岗位的真实评价标准：会调模型不值钱，能把不确定性收敛成可上线的系统才值钱。
