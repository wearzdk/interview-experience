### 《参考解析》

**Framebuffer 与 DRM 不在同一个抽象层**：Framebuffer 是显存的线性映射抽象，内核通过 fbdev 暴露 `/dev/fb0`，应用 mmap 之后按像素格式直接写显存，驱动只负责把这块内存交给显示控制器扫描输出。它简单、开销小，适合固定分辨率的单图层场景，但没有原子提交、多图层合成、页面翻转与缓冲区同步机制，容易出现撕裂，多图层要靠硬件叠加器或应用自己合成。DRM/KMS 是完整的显示子系统，核心对象有五个：framebuffer 描述一块像素缓冲，plane 描述图层及其缩放、格式与位置，CRTC 描述扫描输出与时序，encoder 负责把像素流转换成 HDMI、DSI、LVDS 等信号，connector 描述物理接口与 EDID 探测到的显示能力；对象之间通过 property 配置，支持 atomic commit 与 page flip。至于「Framebuffer 与 ARM 的区别」，这两个概念不在一个维度：前者是显示内存的抽象，后者是处理器架构，遇到这种问法应先确认对方想问的是 fbdev 与 DRM 的差异，还是 Framebuffer 与 GPU 渲染的差异，再作答。

**设备树解决的是硬件描述与内核代码耦合**：ARM 平台早期把板级信息写成大量板级文件，每改一颗外设或一个引脚就要改内核源码并重新编译。设备树把硬件描述抽成独立数据（dts 编译为 dtb），由 bootloader 把 dtb 地址传给内核，内核解析成 device_node，再生成 platform_device 与驱动匹配，驱动只关心资源（寄存器地址、中断号、时钟、GPIO）而不关心具体板子。带来的好处是同一份内核镜像可以支持多块板卡，板级差异只改 dts；代价是多了一层匹配与解析，调试时要同时看 dts、驱动 compatible 与运行时生成的设备节点。

**probe 没有执行的原因要按链路排查**：先看匹配是否成功，compatible 字符串与驱动 of_match_table 是否一致，驱动是否编进内核或已 insmod；再看设备树节点是否被 status 置为 disabled，或者节点压根没被编译进 dtb；然后看依赖资源是否就绪，时钟、regulator、复位、pinctrl、GPIO 未准备好时驱动会返回 -EPROBE_DEFER 进入延迟探测队列，表现为「驱动加载了但 probe 没跑」；还要排除地址或中断冲突、驱动初始化顺序、以及模块依赖未加载。排查手段是 dmesg 里的 deferred probe 提示、`/sys/bus/platform/devices` 与 `/sys/bus/platform/drivers` 下的绑定关系、`/proc/device-tree` 的实际节点，必要时用 ftrace 跟踪 probe 调用。

**用户态与内核态通信按数据量与语义选型**：系统调用适合单次控制；ioctl 适合设备命令与寄存器读写；procfs、sysfs、debugfs 适合小量状态查看与配置；netlink 适合异步、多播的内核事件上报；mmap 适合大块数据零拷贝共享；此外还有信号、uevent、FUSE 与 socket。mmap 的典型场景是大文件随机读写、进程间共享内存、把设备寄存器或显存映射到用户态；好处是省掉内核到用户态的一次拷贝、按需缺页加载、多进程可共享同一份物理页。使用时要注意偏移必须页对齐、访问越界会触发 SIGSEGV、文件被截断后访问映射区会触发 SIGBUS、需要持久化时要 msync。

**物理内存与虚拟内存的分工**：物理内存是真实存在的存储颗粒，容量固定、地址连续但分配容易碎片化；虚拟内存给每个进程独立的地址空间，由 MMU 通过页表映射到物理页，带来三件事：进程间隔离与权限保护、按需分配与换出（可以申请超过物理容量的地址空间）、以及简化链接与内存管理（连续虚拟地址映射到离散物理页）。代价是地址翻译开销（靠 TLB 缓解）与页表本身的内存占用。DMA 场景还需要额外注意缓冲区的物理连续性，通常用预留内存、CMA 或 IOMMU/SMMU 解决。

**串口帧解析用状态机加环形缓冲**：接收中断只负责把字节写入环形缓冲并更新计数，解析放在任务上下文，避免在中断里做长逻辑。状态机按「等帧头—收长度—收载荷—校验—等帧尾」推进，每收到一个字节就驱动一次状态迁移；长度字段要设上限，防止畸形帧导致缓冲区溢出。半包靠状态机保留中间状态解决，粘包靠循环解析直到缓冲不足一帧；丢包后要能重同步，常见做法是超时复位状态机并向后搜索下一个帧头。错误检测用 CRC16 或校验和，校验失败计数并丢弃整帧，同时上报错误类型便于现场定位。若协议含转义字符（如 0x7E 转义），要在收载荷阶段做反转义，并且转义后的长度不能计入帧长判断。测试时要覆盖逐字节喂入、随机切片、插入噪声与超长帧，验证解析器不会越界也不会卡死。
