### 《面试题目》

1. 实习项目的难点是什么？技术架构是怎么考虑的？
2. 如果要推广给其他部门也用你开发的系统，需要考虑什么？
3. 第二段实习项目的技术架构是怎么考虑的？
4. MCP 服务和普通 Web 服务有什么区别吗？
5. 手撕：力扣 875 吃香蕉的速度（二分法）。

### 《参考解析》

**项目拷问怎么答**：这类岗位的面试官几乎不给八股，全程沿着简历上的一行字往下钻，所以准备的重点是「把项目讲成一条可追问的决策链」。安全的叙述结构是：业务背景与规模（谁在用、多少 QPS、多大数据量、服务几个部门）→ 你遇到的约束（时延、成本、人力、历史包袱）→ 候选方案与为什么淘汰其他方案 → 最终方案换来了什么、代价是什么 → 难点是怎么定位的（现象 → 排查手段 → 根因 → 修复 → 上线后的数据变化）。几个高频追问要提前想好：这套系统里**哪一部分是你写的**、为什么不用现成的开源方案、流量涨十倍哪里先崩、出过什么线上问题、如果重做会怎么改。答不出精确数字时宁可给量级和估算过程，也不要含糊过去——面试官会顺着「大概」继续往下挖。

**「推广给其他部门」考的是从工具到平台的差距**：自己团队内部能跑的系统，换成多租户多场景的平台，缺的是治理能力。要覆盖几层：① **解耦**——调度层不能吃业务语义，任务与流程模型要能描述任意业务，差异通过插件、配置或 DSL 表达，这就是原帖提到的调度层与业务层解耦；② **隔离**——数据、配置、执行环境、配额都要按租户切开，一个部门的慢任务不能拖垮别人，资源隔离最终落在并发配额、独立队列、超时与重试上；③ **权限**——接入统一身份源，按角色做 RBAC，区分谁能建、谁能执行、谁只能看，写操作留审计日志；④ **资源治理**——并发配额、限流、超时、重试（重试必须配退避与幂等，否则故障时会被重试放大）、优先级与排队；⑤ **可观测与 SLA**——按租户维度打点，出问题能定位到谁的哪次执行；⑥ **接入成本**——SDK、文档、自助接入，否则能力再强也推不动。答题时把「技术上要加什么」和「组织上谁会反对」都摆出来，会显得真做过推广。

**MCP 服务和普通 Web 服务的区别**：MCP（Model Context Protocol）是给大模型客户端接工具用的协议，规范底座是 JSON-RPC 2.0，不是给人写业务代码去调的 REST 接口。差别集中在四点：① **契约的消费者不同**——普通 Web 服务的调用方是开发时写死的程序，参数错了在联调期就暴露；MCP 的调用方是模型，服务必须**自描述**（工具名、描述文案、JSON Schema），模型只能靠这些文字判断要不要调、参数怎么填，所以描述质量直接决定调用成功率。② **能力模型不同**——server 对外给三类原语：`tools`（可执行动作）、`resources`（可读上下文）、`prompts`（预置提示模板），连接建立时先 `initialize` 协商协议版本与能力，还有会话概念。③ **传输不同**——本地走 stdio，远程走 Streamable HTTP 或 SSE，可能是长连接、有状态。④ **错误语义不同**——错误更多是给模型看的，要写成模型能理解并自我纠正的话（参数校验失败要指出哪个字段不对），只有不可恢复的错误才终止。相同的地方是：它依然是服务端，鉴权与权限最小化、限流、幂等、审计、可观测一样不能少；另外因为上游可能是被提示词注入的模型，写操作类工具要有确认环节或沙箱边界。

**手撕 875：答案空间上的二分**：这题考的是能不能想到「二分答案」，而不是二分查找本身。关键判据是**单调性**：吃香蕉的速度 `k` 越大，吃完所有堆所需的小时数单调不增；因此可以在 `k ∈ [1, max(piles)]` 上二分最小的可行解，判定条件是 `check(k) = Σ ceil(piles[i] / k) ≤ h`。实现要点：上取整别用浮点，写 `(pile + k - 1) / k`；`left = 1`、`right = max(piles)`，`while (left < right)` 取 `mid = (left + right) / 2`，`check(mid)` 成立就 `right = mid`，否则 `left = mid + 1`，最后返回 `left`；时间复杂度 `O(n · log max(piles))`。常见的追问点：为什么上界取 `max(piles)`（取更大只会更慢、不会更优）、`h` 小于堆数时无解（题目保证有解）、以及这道题和「在有序数组里二分」的区别——这里二分的不是下标而是答案空间，能不能二分完全取决于可行性关于 k 是否单调。最后可以补一句总结：凡是「求最小或最大的可行值」且「可行性与取值单调相关」的题，都可以先想二分答案。
