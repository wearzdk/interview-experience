### 《面试题目》

1. 选择题（20 道）：C++、Java、Go、Python、Linux 命令、数据库都会考，覆盖面很杂。
2. 编程题一：给定一个含正负数的数组，连续子序列和为 0 就可以合并删除，删除次数不限，问最多能删除多少次？要求 O(n)，否则超时。
3. 编程题二：给定大小相同的两个矩阵 A、B，以及两个空数组 1、2；从左上走到右下，每步可以把 A 的元素放进数组 1、B 放进数组 2（或反过来），到达终点时两个数组和的绝对差值最小是多少？A、B 中元素最大为 80，矩阵长宽不超过 80。
4. AI Coding：不给骨架，只给要求和数据样例，在自己的技术栈上设计并实现一个「报表模板管理 + 数据查询清理 + 可视化」系统，有 Token 预算限制（约 1500 万）。

### 《参考解析》

第一道编程题的模型是「前缀和相同的位置之间可以整段消掉」。设前缀和 `P[i]`，若 `P[j] == P[i]` 说明 `(i, j]` 这段的和为 0，可以删除一次。于是问题变成把数组按前缀和分组，每一组内相同值的出现次数能贡献多少次删除——用哈希表统计每个前缀和最后一次出现的位置，边走边累加，复杂度 O(n)。这题的关键是「删除后不影响前缀和相等关系」这个性质，想通这一点才不会去真的模拟删除。

第二道是沿着路径做状态 DP，难点在状态空间：每一步的决策只影响「数组 1 的和 - 数组 2 的和」这个差值，于是状态可以设计为 `(i, j, 当前差值)`，转移到右边或下边时差值加上/减去对应元素，最后取终点处 |差值| 最小的路径。差值范围有界（最长路径步数 × 单元素最大值），所以可以开一维偏移数组；帖子里提到的「用位运算把状态压进一个大整数」是省内存的优化手段，不是必须——先把可行性想清楚（状态数 ≈ 160 × 160 × 差值范围）再谈优化，考场上来就想位运算容易把时间烧光。

AI Coding 题反映的是新趋势：题目不给骨架，考的是你能否用 AI 快速搭出一个能跑的东西，并且管住 Token 预算。实战策略是先在纸上定最小可用范围（模板数据模型 + 查询接口 + 一个可视化页面），把需求拆成可独立验证的模块，一次只让 AI 做一块并立刻跑通；预算有限时优先保证主链路能演示，砍掉「高级功能」。帖子里作者 35 分钟烧完 1500 万 token 只做出 CLI 版，说明预算规划和范围控制是这题的真正考点。

选择题杂糅多语言与数据库，短期能做的就是按「语言共性 + Linux 常用命令 + SQL 基础」过一遍高频点，别指望覆盖全部。
