### 《面试题目》

1. 做一下自我介绍。
2. 大二专业课学得怎么样？408 内容过了一遍吗？计算机网络重点讲讲。
3. 你认为什么课是水课？
4. 你用了 Redis 和 MySQL，MySQL 表是怎么设计的？一共有几张表，每张表的内容是什么，为什么这么设计？
5. 好友表、好友申请表能不能放进 user 表？
6. AI Coding（40 分钟）：实现一个 HTTP Mock 服务平台。
7. 自测时状态码出现 1xx，你怎么理解？
8. 响应体输入测试发现了问题，时间不够了，你打算怎么处理？
9. 反问。

### 《参考解析》

**好友关系不要塞进 user 表。** 好友关系是用户与用户之间的多对多关系，放在 user 表只能用逗号分隔的 ID 列表或 JSON，违反第一范式，查询「谁是我的好友」「我们是不是好友」都要全表扫描或字符串匹配，也无法加唯一约束与索引。正确做法是独立的 `friend_relation(user_id, friend_id, status, created_at)`，用 `(user_id, friend_id)` 唯一索引防重复，必要时存双向两条或一条加双向查询；申请表单独一张 `friend_request(from_id, to_id, status, message, created_at)`，用 `(from_id, to_id)` 唯一约束防止重复申请。拆表的理由是关系有独立生命周期、状态与查询模式，和用户属性变更频率不同。

**AI Coding 的关键是过程可见。** 帖主的做法是让 AI 先读 `problem.md`，按 P0/P1/P2 分级并产出 `plan.md`，再按计划分阶段实现、每阶段测试、最后整体回归。这个流程值得借鉴的点：先定义范围与优先级，避免一上来生成一大堆不可控代码；每个阶段可运行、可验证；边做边向面试官讲思路，让面试官看到判断而不是只看结果。时间不够时优先保证 P0/P1 完整，P2 挑影响最大的做。

**HTTP Mock 服务平台的最小设计。** 规则模型：方法、路径（支持路径参数与通配）、查询参数匹配、请求头匹配、响应状态码、响应头、响应体、延迟；匹配按优先级从具体到通配；支持动态响应（模板变量、随机数据）；规则持久化到数据库或内存，提供管理接口；服务端用统一入口拦截请求、查规则、返回响应，未命中返回 404。工程上要考虑并发安全、规则热更新、请求日志与调试页面。

**1xx 是信息性状态码。** 100 Continue 表示服务器已收到请求头、客户端可以继续发送请求体；101 Switching Protocols 用于协议升级（WebSocket）；102 Processing、103 Early Hints 用于处理中与预加载提示。日常业务少见的 1xx 不代表实现错误，但如果 Mock 服务把 1xx 当作最终响应返回，客户端可能一直等待，需要确认状态码语义与响应体是否符合预期。

**自测发现问题后的处理。** 时间不够时先判断问题的影响面：是否阻断主流程、是否只影响边界输入；能快速修的当场修并补一条测试，不能修的记录在交付说明里，写清现象、复现方式与建议。面试官更在意你是否能识别风险并诚实说明，而不是假装一切正常。

**408 与专业课的答法。** 面试官问「学得怎么样」，不要只报课程名。挑一门你真正理解的课，讲一个具体问题：例如 TCP 三次握手为什么不是两次、拥塞控制从慢启动到快恢复的过程、进程与线程的地址空间差异。被问「哪些是水课」时可以诚实评价，但要有依据：课程内容、考核方式、你从中获得了什么。
