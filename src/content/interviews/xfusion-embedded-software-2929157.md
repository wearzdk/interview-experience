### 《面试题目》

1. 你是否是空白三方？
2. 你了解我们公司吗？知道我们是从华系分出来的吗？
3. 你的 DRL 课题和嵌入式有什么关系？
4. 你的项目代码有多少行？
5. Python 版本是多少？3.1 会不会因为版本太老出现兼容性问题？
6. 项目里有没有用一些外部库？具体用了哪些？
7. 你还有什么想问的？

### 《参考解析》

**面试体验与信号**：这场面试的槽点很多：HR 先问空白三方、面试官走错会议室、等待十几分钟、在工位面试、全程质疑代码量和 Python 版本。遇到这种场子，先别把自我价值绑定在面试官身上。面试是双向选择，对方不尊重候选人的时间、不按岗位提问，本身就是团队管理和招聘流程的信号，可以在反问环节确认团队的技术方向和培养方式，再决定要不要继续。

**代码量与版本**：被问代码量，不要报一个虚数。可以说「仓库总行数、我负责模块的行数、其中核心逻辑和测试各多少」，并补一句「行数不等于复杂度，关键模块的难点在协议解析/并发/实时性」。Python 3.11 被听成 3.1，是沟通问题，不是技术问题；可以平静重复「是 3.11，不是 3.1」，并用一个具体特性说明，比如 `tomllib`、异常组、 faster CPython。外部库要报得出名字、用途和替代方案，别只说「用了很多库」。

**DRL 与嵌入式**：如果岗位是嵌入式，面试官却一直问深度强化学习，可能说明团队实际做的是算法部署/边缘 AI，或者面试官没看简历。回答时把 DRL 课题往嵌入式的落点上拉：模型推理的资源约束、延迟、量化、算子支持、数据采集和在线更新。如果对方不接，也不必强行迎合，反问团队当前的技术栈和这个岗位的真实工作内容。

**公司调研**：被问「了解我们公司吗」，至少要知道超聚变的服务器、算力基础设施、x86/ARM 产品线和软件生态，以及它和华为的关系。不要只背「华系分出来」。这类问题考的是求职意愿，不是技术；答不上来会显得海投。
