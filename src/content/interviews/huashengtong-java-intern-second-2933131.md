### 《面试题目》

1. WebSocket 相关：长连接怎么建、连接与推送怎么管（面试官提到公司里用得很多）。
2. 加密解密算法相关：对称与非对称怎么选、链路上加密解在哪一层。
3. 缓存击穿怎么处理？（作者的回答是「先对请求做好校验」）

### 《参考解析》

**WebSocket 在 Java 后端通常怎么问**

握手是一次 HTTP Upgrade，之后升级成双向长连接，所以面试常从「为什么不用轮询」切入：轮询有延迟、大量请求是空的，长连接省资源但要自己管活。工程上要答出四块：连接管理（按用户或会话保存 Session，单机用 ConcurrentHashMap，集群要广播——Redis pub/sub 或网关按用户固定路由）；心跳与重连（应用层 ping/pong、指数退避、重连后补拉）；消息可靠（ack、重发、序号去重、离线消息落库）；并发与背压（单个 Session 写要串行，异步发送走队列）。实现层可以提 Spring 的 @ServerEndpoint 与 WebSocketHandler、Netty 的 ChannelHandler，以及 Nginx 要透传 Upgrade 头、调大 proxy_read_timeout。行情类业务里面试官真正想听的是「广播量怎么控、断线那几秒的数据怎么补」。

**加密解密：对称、非对称、摘要三层**

对称加密（AES）快，用于数据本身，关键是模式与 IV：选 GCM 这类带认证的模式，IV 随机且绝不复用，禁止 ECB。非对称（RSA、ECDH）慢，只用来做密钥交换和签名，不拿来加密大报文，还要交代填充方式与密钥长度。摘要（SHA-256、bcrypt）不可逆，存密码要加盐并选慢哈希，不能用 MD5。真实链路是组合：TLS 用非对称协商出会话密钥，再用对称加密传数据；JWT 只需防篡改就签名（HS256、RS256），需要保密才加密成 JWE。常见坑是密钥硬编码、日志打明文手机号与身份证、把加密当脱敏——这几条讲出来，比背算法名字更能证明做过东西。

**缓存击穿：先校验再回源，为什么对**

击穿指某个热点 key 失效的瞬间，大量并发请求同时穿到数据库。标准解法是互斥重建：用 setnx 或 Redisson 拿锁，只有拿到锁的请求回源并回填，其余请求短暂等待后重读缓存；锁要设超时、回填前做双重检查，避免死锁与重复重建。另一种是逻辑过期：value 里存过期时间、物理上不过期，发现过期就异步刷新，读请求先拿旧值，用一致性换稳定延迟。作者答「先对请求做好校验」被面试官认可，因为这属于更外层的判断：参数校验、防重放、限流把无效流量挡在缓存之前，能打到同一个 key 的并发就少了。工程上的顺序本就是先问「流量能不能不进这一层」，再问「进来之后怎么排队」。

**这类短帖怎么用：把提到的东西当权重表**

原文只留下一句「大多数问的都是很经典的问题」，信息量不大，但方向有用：一面筛基础，二面开始按团队真实技术栈挑重点。面试官主动说「公司里用得多」的 WebSocket 就是明牌——这家做行情推送，连接管理与广播是日常。遇到这类帖子，正确用法是把它当权重表：WebSocket、加解密、缓存三块各准备一个能和业务挂钩的例子（行情推送的断线补数据、传输加密与密钥轮换、开盘瞬间的热点 key），比再刷一遍八股有效。
