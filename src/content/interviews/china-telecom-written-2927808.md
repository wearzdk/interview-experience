### 《参考解析》

**这场笔试的结构与时间账。** 2 小时对应 25 道行测 + 25 道专业选择 + 3 道编程，平均下来选择题只有一分钟出头一道，编程题要留至少 50 分钟。很多人失手不是不会，而是前面行测的资料分析卡住、后面编程没时间写。合理的分配是：行测 35~40 分钟（资料分析放最后，能估就估、不能估就跳）、专业选择 25~30 分钟（不会的先标记，别死磕）、编程 50~55 分钟（先读三题，按把握排序，先把能 AC 的写完）。交卷前留 5 分钟检查边界与输入输出格式。

**专业选择题的复习范围。** 运营商笔试的计算机部分不考深度，考的是「学过没有」：计算机网络（OSI 七层与 TCP/IP、TCP/UDP、HTTP 状态码、DNS、子网划分）、数据结构（栈队列链表树图、遍历、常见排序的稳定性与复杂度）、操作系统（进程线程、死锁、页面置换、Linux 命令）、数据库（SQL、索引、事务、范式）、C 语言（指针、数组、字符串、位运算、宏）、以及少量算法复杂度分析。因为范围广，复习策略是「把本科学的教材目录过一遍 + 刷两套真题」，不要试图押题。

**编程题一：模拟题。** 原帖提到「要用 long 不然会超出限制，只能过 93%」——这是最典型的坑：题目给的中间结果会超过 32 位整数。C++ 用 `long long`，Java 用 `long`，Go 的 `int` 在 64 位平台是 64 位但仍建议显式用 `int64`，Python 无此问题。写完先算一下最大数据量级：如果 n 是 1e5、每个数是 1e9，求和就到 1e14，必须 64 位。另外注意取模题要在每一步取模，别等最后。

**编程题二：滑动窗口。** 原帖提到「求和的值也要用 long」，说明窗口内求和会溢出。滑动窗口的模板是：右指针扩张、更新窗口状态；当窗口不满足条件时，左指针收缩并回退状态；在每一步满足条件时更新答案。要分清「求最长」还是「求最短」：最长窗口在扩张后更新答案，最短窗口在收缩到满足条件时更新。边界是空数组、单元素、全相同元素；如果数组有负数，滑动窗口的单调性不成立，要换前缀和 + 哈希。

**编程题三：四向 BFS。** 原帖没时间写、直接 `return 0` 拿了 5%。四向 BFS 的标准写法：把起点入队并标记 visited，按层扩展（`for size := len(queue); size > 0; size--`），每个点向上下左右四个方向走，越界、障碍、已访问都跳过；需要最短步数就按层计数，需要路径就额外存 parent。常见变体是「多源 BFS」（把所有起点先入队，求每个点到最近源的距离）和「0-1 BFS」（边权只有 0/1 时用双端队列）。如果题目是网格里的连通块/岛屿数量，则用 DFS 或并查集更简单——读题时先判断是「最短路径」还是「连通性」，别上来就写 BFS。

**复盘：选择题是时间黑洞。** 这场笔试最大的问题是前面耗时太多，导致第三题没时间。改进办法：平时练习就计时，行测按「一分钟一道」训练跳题；专业选择遇到没见过的知识点，10 秒内决定蒙一个还是标记，不要试图现场推导；编程题先写暴力拿部分分，再优化，别一上来追求最优解。运营商笔试的编程题通常不难，AC 两道已经能过线，关键是别让第一题卡住整场。
