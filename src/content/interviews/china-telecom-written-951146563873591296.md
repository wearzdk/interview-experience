### 《参考解析》

**ARP 的处理流程**：主机 A 要发给同网段的主机 B，先查本地 ARP 缓存里有没有 B 的 IP→MAC 映射。没有就广播一个 ARP 请求（目标 MAC 全 F，内容为「谁是 B 的 IP，请告诉 A」），B 收到后单播回一个 ARP 应答带上自己的 MAC，A 把它写进缓存再发数据。若 B 不在同网段，A 查的是网关的 MAC，由网关逐跳转发；缓存有老化时间，过期要重新解析。回答时补一句「ARP 请求广播、应答单播，缓存有超时」，基本就完整了。

**怎么破坏死锁**：死锁的四个必要条件互斥、请求并保持、不可剥夺、循环等待，破坏其中任意一个即可。工程上最常用的是破坏循环等待——给所有锁定全局顺序，按同一顺序加锁；其次是破坏请求并保持——一次性申请全部资源，或申请不到就释放已持有的；破坏不可剥夺——申请不到时主动释放并重试（`tryLock` 超时放弃）；互斥本身通常无法破坏，只能减少锁的粒度或用无锁结构。答题时把「四个条件 + 对应一种工程做法」成对说，比只背定义得分高。

**页表与缺页中断**：虚拟地址经页表翻译成物理地址，页表项里有有效位、访问位、脏位等标志。访问的页不在内存（有效位为 0）时触发缺页中断，内核从磁盘换入页面、更新页表，若内存已满则按置换算法（LRU、Clock 等）选一页换出，脏页要先写回。优化手段是多级页表省空间、TLB 缓存热页表项、大页减少页表项数量。注意区分「缺页」与「越界访问」：前者是合法的按需调页，后者是非法地址，直接报错。

**召回率与准确率的算法**：准确率 = 预测正确的样本数 / 总样本数，或（在二分类里常指）预测为正且真正为正 / 预测为正；召回率 = 真正为正且被预测为正 / 所有真正为正。做题时先按题目给的混淆矩阵把 TP、FP、FN、TN 摆出来，再代公式，别用文字描述绕。只有正负样本总数和「预测正确数」时算不出召回率，必须知道正样本被抓到多少——题目条件不足时要敢于指出这一点。

**Transformer 注意力后续计算**：Q 与 K 点积后除以 √d_k 缩放，过 softmax 得到注意力权重，再用权重对 V 做加权求和，得到每个位置的输出；多头则是把多个头的输出拼接后过一层线性变换。回答时按「QK^T → scale → mask（decoder 的因果掩码）→ softmax → 乘 V → 拼接 → 线性」的顺序说完整。

**ReLU 的梯度**：ReLU(x) = max(0, x)，x > 0 时梯度为 1，x < 0 时梯度为 0，x = 0 处不可导，工程上一般取 0（或按框架实现取 0）。所以给输入输出求梯度，本质是看输入是否大于 0。顺带可以提它缓解梯度消失、计算便宜，但负半轴会「死亡 ReLU」，于是有了 LeakyReLU、GELU 等变体。

**这场笔试的时间账**：帖主的教训很典型——行测 25 题加计算机基础把时间吃掉，三道 ACM 编程题只剩很少时间，还卡在低级失误上。可操作的做法是先扫一遍三道编程题，按「读题 1 分钟内能想出思路」的标准排序，先做最有把握那道拿到分；行测里的资料分析、语句排序不要恋战，单题超过一分半就标记跳过；ACM 模式要提前练熟输入解析（多组数据、空行、EOF 结尾），这部分丢分最不值。
