### 《参考解析》

**BF16 与 FP16 都是 16 位，位宽分配不同，换来不同的范围与精度**。FP16 是 1 位符号、5 位指数、10 位尾数，范围约 6×10⁻⁵ 到 65504；BF16 是 8 位指数、7 位尾数，指数与 FP32 一致，范围等同 FP32，但精度只有约两位十进制。所以 BF16 不容易溢出，适合梯度与激活跨度大的训练，代价是舍入误差更明显；FP16 精度更好但需要 loss scaling 防下溢。

**在线 softmax 解决的是分块之后拿不到全局最大值**。每处理一个 K/V 块，先算该块分数与局部最大值 m_blk，用新的全局最大值 m_new 把已累积的输出 O 按 exp(m_old − m_new) 缩放，再乘本块的 exp(score − m_new) 累加，分母 l 同样缩放。这样不必保存完整分数矩阵、也不用两遍扫描，最终 O/l 就是精确结果。代价是每块多几次标量缩放与 exp 重算，用算力换掉 N×N 中间矩阵的 HBM 读写。

**「少读数据但多算几步仍然更快」要用算术强度算账**。GPU 算力增长远快于 HBM 带宽，多数推理 kernel 卡在访存；如果省下的字节数乘带宽单价，大于新增解码、反量化指令的时间，整体就是赚的。判断依据是 roofline：算 kernel 的 ops/byte 与机器拐点比，落在带宽侧就值得用计算换访存。加速比也不等于「减少的字节比例」，因为原 kernel 可能本来就没跑满带宽。

**ILP 与 TLP 是两种填满执行单元的思路**。ILP 指单线程内互不依赖的指令并行，靠循环展开、拆分累加器、软件流水让调度器在等延迟时仍有指令可发；TLP 指用更多 warp 隐藏延迟。SM 能驻留多少 warp 由几项资源取最小值：每 block 线程数上限、每 SM 的 warp 槽位、寄存器文件（每线程寄存器数乘线程数）、共享内存与 block 数上限。所以压低寄存器用量常比加大 block 更能提高占用率，但占用率高不等于快，还要看 stall 原因。

**量化的取舍不止省多少空间，还要看精度、硬件支持和工程成本**。FP8 有原生 Tensor Core 支持，矩阵乘能直接吃到算力；NF4 是 4 位正态浮点加分块量化常数，压缩率更高但需要反量化，只在 decode 阶段划算。PTQ 用校准数据统计激活分布、离线定 scale，成本低但离群值会拉低精度；QAT 在训练里插入伪量化节点让模型适应舍入误差，精度更好但要重新训练。该不该继续用高精度，要看业务指标是否真的受益。

**按端点拆分区间是一道扫描线**。把所有起点和终点收集起来排序，或利用两个序列各自有序做双指针归并；然后在相邻端点之间维护覆盖计数：起点加一、终点减一，计数大于零的那一段就是输出。例子中端点 1、3、4、5、7、9 把数轴切成五段，覆盖数分别是 1、2、3、2、1，于是得到 [1,3]、[3,4]、[4,5]、[5,7]、[7,9]。允许共享端点意味着把区间看成半开区间，边界只归属一侧。排序 O(n log n)，两端有序时归并加扫描是 O(n)。

**分割回文串是回溯加预处理**。从起点尝试每个切点，子串是回文就加入路径继续递归，到串尾收集方案；最坏情况有 2^(n−1) 种分割，回溯本身至少要输出这么多结果。优化点是把「判断回文」从 O(n) 降到 O(1)：先用中心扩展或区间 DP 预处理 pal[i][j]，整体从 O(n²·2^n) 降到 O(n·2^n)。用下标传递避免反复拷贝子串。
