### 《参考解析》

**渲染与事件循环**：HTML 解析成 DOM、CSS 解析成 CSSOM，合成渲染树，布局（layout）算几何，绘制（paint）出图层，合成（composite）上屏。事件循环是「一个宏任务 → 清空微任务队列 → 必要时渲染」，宏任务包括 script、setTimeout、I/O，微任务是 Promise 回调、MutationObserver、queueMicrotask。渲染发生在两次宏任务之间，所以同步长任务会阻塞渲染。

**闭包怎么被 GC**：闭包本身是函数 + 它捕获的词法环境，只要还有引用（挂在全局、事件监听、定时器、DOM 上的属性）就回收不了。要让它可回收，就得断开所有引用：把持有闭包的变量置 null、移除事件监听（`removeEventListener` 必须传同一个函数引用）、`clearInterval`、把 DOM 属性上的引用删掉。注意「没有执行余地」不等于「没有引用」——GC 看的是可达性，不是还会不会被调用。

**隐式转换**：`==` 在类型不同时按规则转换：一边是数字一边是字符串就把字符串转数字（`''` → 0，`'abc'` → NaN）；布尔先转数字；对象先用 `valueOf` 再用 `toString` 转原始值；`null == undefined` 为 true，但 `null == 0` 为 false。所以 `[] == false` 为 true（`[]` → `''` → 0，false → 0），这也是为什么工程里统一用 `===`。

**React 的优先级与打断**：React 18 的并发渲染把更新按优先级分车道（lane），高优先级更新（用户输入）可以打断低优先级（如大列表渲染）的进行中工作。实现靠 Fiber 架构把渲染拆成可中断的单元，配合 scheduler 在浏览器空闲时段（`MessageChannel`）执行任务，时间片用完就让出主线程；被丢弃的低优先级工作会在之后重新调度。要说明「打断只发生在 render 阶段，commit 阶段不可中断」。

**Vue vs React**：Vue 是响应式驱动（Proxy 追踪依赖，改数据自动精确更新），模板编译期做静态优化，上手快、约定多；React 是「UI = f(state)」，靠 setState 触发重渲染 + 虚拟 DOM diff，生态更大、灵活度高但需要自己做 memo 优化。Vue3 的组合式 API 与 React Hooks 在逻辑复用上思路接近。

**全链路监控**：错误采集用 `window.onerror` / `unhandledrejection` / `addEventListener('error', ..., true)` 捕获资源错误，React 用 ErrorBoundary；性能用 `PerformanceObserver` 采 LCP/INP/CLS 与资源时序；请求层拦截 fetch/XHR 记录耗时与失败；再补用户行为（点击、路由切换）作为上下文。上报用 `sendBeacon` 保证页面卸载时不丢，采样 + 聚合 + sourcemap 还原堆栈，最后接告警与看板。

**SKU 笛卡尔积优化**：属性组合爆炸时不要一次性生成全部 SKU。按需计算（用户选到哪一层就算哪一层）、用位图/集合运算判断某组合是否可选（把每个属性值对应到可选 SKU 的 bitset，选择时做 AND）、以及在后端预计算并缓存可用组合。前端渲染长列表用虚拟滚动。核心思路是「用集合运算代替嵌套循环」。

**AI 协作与约束**：说清你的工作流——给足上下文（相关文件、类型定义、约定），任务拆小，要求它输出可验证的结果（测试、diff），人做最终判断。约束偏移的办法是给它明确的接口与禁止项，并在提交前用类型检查、lint、单测兜底；关键逻辑自己写。
