### 《参考解析》

**static 的四种用法**：一是局部静态变量，生命周期延续到程序结束、只初始化一次，C++11 起首次进入的初始化是线程安全的（裸机 C 里不保证）；二是文件级/全局 static，把符号变成内部链接，其他编译单元不可见，用来避免多文件重名；三是类静态成员变量，属于类而非对象，需要在类外定义（C++17 起可 inline 直接在类内初始化）；四是类静态成员函数，没有 this 指针，不能访问非静态成员，常配单例使用。面试里容易只答「存在静态存储区」，其实链接属性才是关键考点。

**多态与虚表**：多态是基类指针或引用调用虚函数时按对象的动态类型分发。实现上对象头部有一个 vptr 指向该类的虚表，虚表按声明顺序存放虚函数地址；子类覆写时把对应槽位替换成自己的实现，多继承会持有多个 vptr 并需要 this 指针调整（thunk）。要补充一个高频追问：构造和析构期间 vptr 会指向当前正在构造/析构的类，所以在构造函数里调虚函数不会分发到子类。

**构造、析构能不能是虚函数**：构造函数不能是虚函数——对象还没构造完、vptr 尚未就位，虚调用无从谈起，需要多态创建就用工厂函数。析构函数在作为基类时必须是虚函数：否则用基类指针 delete 子类对象时只调用基类析构，子类资源泄漏；虚析构会生成 deleting destructor，先调子类析构再释放内存。

**map 与 unordered_map**：map 底层是红黑树，查找/插入 O(log n)，元素按 key 有序，支持 lower_bound、范围查询，迭代器在插入时稳定；unordered_map 底层是哈希表（通常链地址法），平均 O(1)、最坏退化到 O(n)，元素无序，rehash 会导致迭代器失效。选择依据是有没有序需求与范围查询：要遍历有序结果就用 map，只做点查就用 unordered_map，并注意自定义 key 要提供 hash 与相等比较。

**元素唯一与去重**：map 和 unordered_map 的 key 都唯一，重复 insert 不会覆盖（insert 返回 false），要覆盖用 `operator[]` 或 `insert_or_assign`；如果要存放重复元素就用 multimap。去重常见三种做法：遍历时判断 `insert().second`、先收集到 vector 再排序后 `unique` + erase、或直接放进 set/unordered_set。元素是自定义类型时要定义好相等与哈希规则。

**移动语义与转发引用**：移动构造/移动赋值接收右值引用，把资源（堆指针、文件描述符、缓冲区）直接搬走并把源对象置空，避免深拷贝。std::move 本身不移动任何东西，只是把左值 static_cast 成右值引用，真正干活的是随后匹配到的移动构造；被移动后的对象处于有效但未指定状态，别再用它的值。转发引用是形如 `T&&` 且 T 需要推导的场景（模板参数、auto&&），配合 std::forward 保持实参的值类别，是实现完美转发的基础；注意 `const T&&` 和具体类型 `int&&` 都不是转发引用。
