### 《参考解析》

**MCU 性能不只看主频。** 主频决定每秒钟能执行多少个时钟周期，但实际性能还取决于：总线与存储层次（Flash 是否有预取与缓存、等待周期是几个、指令与数据是否共用总线）、流水线深度与分支预测、外设与 DMA 的搬运能力（CPU 是否被数据搬运占住）、以及编译器优化与代码本身的数据局部性。主频提高通常同时提高功耗与发热，嵌入式里更常见的是「降频 + 用 DMA 卸载 + 提高 cache 命中」来换有效吞吐。回答时结合具体芯片说清 Flash 等待周期与 ART 加速器、SRAM 大小、外设时钟域，比只报一个主频数字更有说服力。

**DMA 与双缓冲。** DMA 让外设与内存之间直接搬运数据，CPU 只负责配置传输（源地址、目的地址、长度、触发源）并在完成中断里处理。单缓冲的问题是「搬运期间 CPU 不能碰这块内存」，否则会读到半新半旧的数据；双缓冲（ping-pong）把内存分成两块，DMA 写 A 时 CPU 读 B，DMA 写满 A 触发中断后切换，CPU 处理 A、DMA 接着写 B，从而把搬运与处理并行起来，代价是多一块内存与切换逻辑。串口、ADC、音频、以太网收包都常用这个模式。

**中断上下文为什么必须短。** 中断处理期间通常关中断或屏蔽同级中断，耗时过长会导致其他中断被延迟甚至丢失（尤其在高频采样、通信场景），也会让实时任务的响应抖动变大。原则是「中断里只做最小必要的动作」：清标志、把数据搬到缓冲区、置位信号量或把事件投递到队列，真正的处理放到任务里做。耗时操作、可能阻塞的调用（malloc、文件 IO、等锁）都不能放在 ISR 里。

**FreeRTOS 的调度与堆。** FreeRTOS 默认是抢占式优先级调度，同优先级任务按时间片轮转（可配置），每个任务有独立的栈（由 `xTaskCreate` 指定深度，从堆里分配），切换时保存/恢复上下文（寄存器组、栈指针）。堆管理有五种方案：heap_1 只分配不释放，heap_2 支持释放但不合并，heap_3 包装标准 malloc/free（加锁），heap_4 支持释放并合并相邻空闲块（首次适配 + 边界标记），heap_5 在 heap_4 基础上支持多块不连续内存。heap_4 的分配过程是：从空闲链表里找第一个足够大的块，切分后把剩余部分放回链表；释放时通过块头记录的大小找到相邻块，若空闲则合并，减少碎片。它不保证实时性，分配时间与碎片情况相关，所以高频路径上应避免动态分配。

**CAN 与 EtherCAT 的取舍。** CAN 是总线型、多主、基于报文 ID 仲裁，速率通常 1Mbps（CAN FD 数据段可到 5Mbps 以上、载荷从 8 字节扩到 64 字节），适合控制指令与状态上报，布线简单、成本低、抗干扰好。CANopen 在其上定义应用层：PDO 是过程数据对象，周期性、实时、无确认地传输；SDO 是服务数据对象，用于参数读写，有请求-响应确认，适合配置而不是实时控制。EtherCAT 是以太网物理层的工业总线，主站发一帧、从站边转发边读写（on-the-fly），拓扑可以是线型/环型，同步精度可达微秒级、周期可到百微秒，适合多轴同步运动控制——人形机器人关节多、控制周期短、需要严格同步，所以用 EtherCAT；CAN 的带宽与同步精度支撑不了几十个关节的高频闭环。

**PID 抗饱和与 FOC。** 积分饱和的成因是执行器达到限幅后误差仍在累积，退出饱和时积分项要很久才能释放，表现为超调与响应迟滞。两种常见处理：clamping（积分项一旦让输出超出限幅就停止累加，或把积分项钳在允许范围内）、back-calculation（把「实际输出与限幅后输出的差」乘一个系数反算回积分项，让积分快速回退）。快变场景（目标频繁跳变、执行器容易饱和）更适合 back-calculation，因为它能根据饱和深度动态回退；clamping 实现简单，在缓变场景够用。

FOC 的思想是把三相交流电机的定子电流变换到随转子旋转的 d-q 坐标系：Clarke 变换把三相电流 (ia, ib, ic) 变成两相静止坐标 (iα, iβ)，Park 变换再按转子电角度旋转到 (id, iq)。变换后，id 控制励磁分量、iq 控制转矩分量，原本随时间正弦变化的量变成近似直流量，用 PI 就能做到稳态无差，再反变换回三相、经 SVPWM 驱动逆变器。回答时补一句：角度估计不准会让 d-q 耦合，表现为效率下降、噪声增大、带载能力变差。

**优先级反转与同步原语。** 优先级反转指高优先级任务等待被低优先级任务持有的锁，而低优先级任务又被中优先级任务抢占，导致高优先级任务被间接阻塞。解决办法是优先级继承（持锁的低优先级任务临时提升到等待者的优先级，FreeRTOS 的 mutex 默认支持）和优先级天花板（把锁的优先级设成所有可能使用者的最高值）。mutex 有所有权、支持优先级继承，用于保护共享资源；semaphore 没有所有权，用于任务间同步或计数（生产者-消费者、中断通知任务），二值信号量不能替代 mutex 做互斥，因为它不解决优先级反转。
