### 《面试题目》

1. 为什么想要换工作，是因为目前公司发展不好吗？
2. 为什么想要更换城市？之前来上海实习过吗？目前是技术骨干还是什么位置？
3. 期望薪资是多少？是否有落户需求？
4. 在校期间是否有实习？
5. 网关产品和金融企业测试有什么区别？
6. 输入网址打开网页经历了哪些协议层？
7. TCP 协议三次握手、四次挥手的过程。
8. 自动化框架是什么？Selenium 怎么选型的？接口层面的自动化怎么搭建框架？
9. 简单介绍 Pytest 自动化框架，你的理解。
10. Pytest 怎么做数据驱动测试？
11. 印象最深刻的 BUG。
12. Selenium 找不到 Web 的某个组件，怎么办？
13. 系统时延比较大，开发觉得是网络问题，你怎么排查？

### 《参考解析》

**动机类问题要给「向前」的理由**：问「是不是目前公司发展不好」时，不要顺着贬低前东家，把重点放在目标岗位与自身的匹配（业务方向、技术栈、城市）。被问「是技术骨干还是什么位置」是在确认你的职级与话语权，如实说负责的范围与带人情况，夸大在背调环节会出问题。落户需求如实回答，这类信息影响 offer 方案的沟通。

**网关产品与金融企业测试的区别**：网关是流量入口，测试重点是协议兼容与转发正确性、限流熔断与灰度、长连接与超时、配置变更的生效与回滚、以及高并发下的稳定性；金融企业的系统更强调资金与数据的一致性、账务可对账、权限与审计、监管合规与变更窗口，测试要覆盖对账、冲正、幂等与异常分支的场景组合。答的时候各给一个具体例子，比罗列形容词有效。

**输入网址到页面呈现的协议链路**：浏览器解析 URL → DNS 解析（浏览器缓存、系统缓存、hosts、递归查询）→ 建立 TCP 连接（三次握手）→ TLS 握手（HTTPS）→ 发送 HTTP 请求 → 服务端处理并返回响应 → 浏览器解析 HTML、构建 DOM 与 CSSOM、布局与绘制、加载子资源。能把这条件链路讲到「DNS 走 UDP 53、大响应走 TCP」这种细节，面试官会继续追问。

**TCP 三次握手与四次挥手**：三次握手是 SYN、SYN+ACK、ACK，目的是双方确认收发能力并同步初始序列号，两次不够是因为服务端无法确认客户端收到了自己的 SYN。四次挥手是 FIN、ACK、FIN、ACK，因为 TCP 是全双工，两个方向要分别关闭；主动关闭方最后进入 TIME_WAIT，等待 2MSL 以保证最后的 ACK 能到达并让旧连接报文在网络中消失。

**自动化框架与数据驱动**：Selenium 的选型理由通常是跨浏览器、社区成熟、与语言栈匹配；接口自动化一般分四层——用例层（YAML/Excel 或代码）、数据层（测试数据与断言数据分离）、驱动层（requests 封装、鉴权、重试、日志）、报告与 CI 层。Pytest 的数据驱动用 `@pytest.mark.parametrize`，配合 fixture 管理前置与清理，`conftest.py` 放共享 fixture；复杂场景可以用 `pytest_generate_tests` 从外部文件动态生成参数。

**两个排查题**：Selenium 找不到元素，先确认是否在 iframe 或 shadow DOM 里、是否要切换窗口、元素是否在加载完成前就被查找（显式等待而非 sleep）、定位器是否唯一、页面是否因权限或环境差异没渲染出来。时延排查先分段：用 curl 或浏览器开发者工具看 DNS、连接、首字节、下载各阶段耗时，判断是网络、服务端处理还是前端渲染；再看服务端日志与链路追踪定位慢在下游哪个依赖、数据库慢查询还是锁等待；对比不同网络与不同地域的复现结果，拿数据说服开发，而不是各说各话。
