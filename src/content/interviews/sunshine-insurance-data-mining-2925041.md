### 《面试题目》

1. 自我介绍
2. 介绍梯度提升模型
3. 讲一件你遇到过的困难的事情
4. 业务题：给数据，在约束下如何建模做项目
5. 执行和组织怎么选择？

### 《参考解析》

**梯度提升（GBDT）要讲清「加法模型 + 前向分步 + 拟合负梯度」三件事。** 它是一个加法模型：`F_m(x) = F_{m-1}(x) + ν · h_m(x)`，每一轮训练一棵新的弱学习器（通常是回归树）去拟合当前模型损失的**负梯度**（对平方损失来说负梯度就是残差，对对数损失则是最优的梯度方向），然后以学习率 ν 缩步长加进模型。这样做的直觉是「每次只修正上一步犯的错」，所以用一堆高偏差低方差的浅树组合出低偏差的强模型。工程上要能说清关键超参及其作用：树的深度/叶子数（控制单棵树复杂度，越深越容易过拟合）、学习率与树的数量（两者此消彼长，小学习率 + 多棵树通常效果更好但更慢）、行/列采样（引入随机性、降方差、提速，这也是 XGBoost 相对 GBDT 的重要改进）、正则项（叶子权重 L2 + 树复杂度惩罚）、以及缺失值处理（XGBoost 会为缺失值学一个默认方向）。对比其他模型：比线性模型能自动捕捉非线性与交互特征、无需精细特征工程；比随机森林用的是「拟合残差」而不是「并行装袋」，通常精度更高但更容易过拟合、也更难并行（XGBoost/LightGBM 用直方图与预排序近似解决）。**LightGBM 的 Leaf-wise 生长与直方图算法**可以主动提，这是它的速度来源，但小数据下 Leaf-wise 容易过拟合，要限制叶子数或改用深度优先。

**「给数据、在约束下建模」这类业务题的答题框架是「目标 → 数据 → 约束 → 方案 → 验证 → 落地」。** 第一步先把**目标量化**：业务要的到底是分类（会不会赔付）、回归（赔多少）、还是排序（先审谁）。第二步看数据：样本量与标签质量、正负样本比例、特征可得性（**上线时能拿到的特征才算特征**，避免标签泄露与时间穿越）、以及时间维度（保险数据强时序，必须按时间切分训练/验证而不是随机切分）。第三步明确约束：可解释性（金融保险受监管，往往要求能解释拒保/加费理由）、实时性（审批是毫秒级还是离线批处理）、以及公平性/合规（不能使用歧视性特征）。第四步给方案：特征工程（分箱、WOE、交叉、时序聚合）、模型（可解释优先用逻辑回归 + 评分卡，效果优先用 GBDT，或 GBDT + LR 的融合）、评估（AUC/KS/PR-AUC、按时间回测、分群稳定性），并给出**代价敏感**的阈值选择（漏审的坏账损失与误拒的客户损失不对称，阈值要按业务成本定）。第五步验证与上线：离线回测 + 小流量 A/B + 监控特征漂移与效果衰减，并给出模型迭代与回滚机制。答题时把「你怎么知道它有效」讲清楚，比堆模型名更加分。

**「执行和组织怎么选择」这类问题考的是自我认知与协作取向。** 稳妥答法是从「当下阶段 + 个人优势 + 团队需要」三个维度说明：如果团队处于早期或自己经验不足，先做执行、把细节做扎实是更合理的积累；当对业务与技术链路有完整理解、能承担跨人协作与目标拆解时，再转向组织/推动角色。要给出具体依据（做过什么事、被人认可的能力是什么），避免空谈「我都可以」。保险/金融类岗位还会关心稳定性与合规意识，回答里可以带一句对数据与结论负责的态度。
