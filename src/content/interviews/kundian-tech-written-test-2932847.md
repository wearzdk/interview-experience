### 《面试题目》

1. 笔试的形式和时长是怎样的？（双机位监考，约一小时，四道题）
2. 三道算法题是什么难度？
3. SQL 题考什么？
4. 笔试链接的有效期是多久？

### 《参考解析》

**先把「双机位 + 限时 + 链接有效期」这三件事当成流程题准备。** 双机位要一台正面摄像头（答题屏幕）加一台侧后方手机（拍到手和桌面），考前半小时就该把第二机位架好、登录监考系统、确认电量与充电线、关掉手机通知，并把桌面清空——临时找支架、手机没电、侧机位角度不合格，都是最常见的开场翻车点。「收到链接三天内做完」意味着时间可以自己挑：挑自己状态最好的时段、确保网络稳定、别拖到最后一晚（当天系统的并发和监考排队都不由你控制）。

**一小时四道题，节奏比能力更重要。** 合理分配是 SQL 先做（最基础、一行能写，五到十分钟收掉，先把确定的分拿到），再三道算法。算法按「先扫一遍题面判断哪道最熟」的顺序做，别顺着编号做；每题先写暴力或最直观版本保证有分，再优化——很多笔试按通过用例给分，卡在一道题上死磕是最亏的。

**「接近 Hot100 中等」这个难度描述，对应的其实是几类固定套路**：哈希表与双指针（两数之和、三数之和、盛水容器、无重复最长子串）、滑动窗口（最小覆盖子串、长度最小的子数组）、链表（反转、合并、环、K 个一组）、二叉树（层序、路径和、最近公共祖先、构造）、DP（爬楼梯、打家劫舍、最长递增子序列、编辑距离）、堆与 TopK、图的 BFS/DFS（岛屿数量、拓扑排序）。这些题的价值不在「做过」，而在能在十分钟内写完且一次过边界：空数组、单元素、重复元素、整数溢出、负数。笔试里最常见的失分不是想不出解法，是思路对了但边界没处理、提交三次才对。

**「一行 SQL」这类题考的往往是聚合或去重**：求每组的最大值/第 N 名（`group by` + `having` 或窗口函数 `row_number()`）、去重计数（`count(distinct)`）、按条件统计占比、取每个用户最新一条记录（`row_number() over (partition by ... order by ...)` 或相关子查询）。既然题目说简单，那就要一次写对、注意 `null` 参与比较时用 `is null`、日期范围用左闭右开避免边界重复统计。写之前先想清楚「结果一行还是一列、要不要排序」，能省掉一次改题。

**被评价为「简单」的笔试，筛选点通常落在两处**：一是通过率（四题全过的人本来就少），二是代码质量与一次提交的正确率。所以别因为题简单就提前交卷，留十分钟把每题的边界用例自测一遍，比多刷一道题划算。
