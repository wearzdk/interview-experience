### 《面试题目》

1. RAG 的流程是怎样的？（整场唯一一道八股）
2. 介绍实习经历，并接受细节追问。
3. 介绍项目经历，并接受细节追问。
4. 介绍你的论文工作。
5. 算法题：实现一个 LRU 缓存。
6. 反问：部门业务是什么？

### 《参考解析》

**RAG 这道题答成「向量库 + 大模型」就废了。**面试官想听的是链路上每一段的选择和代价：文档解析（PDF 双栏、表格、页眉页脚怎么处理）→ 切分（固定长度还是按语义/标题切，chunk 大小与重叠的取舍）→ 向量化（选哪个 embedding 模型、维度、是否归一化、中英文是否同一模型）→ 索引（HNSW 与 IVF 的召回率/内存/构建时间差异，是否加元数据过滤）→ 召回（top-k 取多少、要不要混合检索 BM25 + 向量、多路召回怎么融合）→ 重排（cross-encoder 精排的延迟成本）→ 拼 prompt（上下文顺序、截断策略、引用编号）→ 生成（约束只依据上下文作答、答不了要说不知道）→ 评估（召回率 recall@k、答案忠实度、人工抽检集）。再补一句工程侧的东西——增量更新怎么触发重建索引、多租户怎么隔离、缓存放在哪一层——就能和只会背流程的人拉开距离。

**实习和项目的「拷打」通常沿三条线走**：你负责的那部分边界在哪（哪些是你写的、哪些是别人写的）、数据从哪来、指标怎么算的。回答时把「我做了什么 → 为什么这么做 → 效果用什么衡量 → 如果重做会改哪里」讲成闭环，比罗列技术栈有效。被问到自己没参与的部分，直接说清边界，硬撑会被下一层追问打穿。

**论文只要讲四件事**：解决什么问题、别人怎么做的、你的方法新在哪、实验证明了什么。面试官常追问的是 baseline 是否公平、消融实验有没有做、数据规模多大——这些答不上来，会被判定为「挂名」。

**LRU 是实习面试的常客，考的是边界而不是思路**。标准做法是哈希表 + 双向链表（带 head/tail 哨兵），`get` 命中后把节点摘下来挂到头部，`put` 时若 key 存在则更新值并前置、不存在则新建并在超容量时删掉尾节点，`get` 与 `put` 都要 O(1)。易错点有三个：容量为 0 或 1 的边界、更新已有 key 时不能重复计数、删尾节点后要同步删哈希表项。Java 里可以用 `LinkedHashMap(capacity, 0.75f, true)` 重写 `removeEldestEntry` 十行写完，但面试官多半会要求手写链表版，最好两版都能写。如果要加并发，就在外层加锁或用分段锁，并说明为什么不用 `ConcurrentHashMap` 直接凑。

**十分钟后 HR 来电**说明这条线的决策链很短：技术面过了就直接进 HR 沟通到岗时间。实习岗到这个阶段，真正决定成败的往往不是算法题，而是能实习多久、每周几天——被问到时要给确定的答案。
