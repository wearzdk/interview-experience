### 《参考解析》

**嵌入式岗的技术面考察结构**

嵌软岗的面试基本可以拆成四块：C 语言与内存、MCU 外设与通信协议、RTOS 与并发、Linux 系统与驱动，再叠一个贯穿全程的项目深挖。前两块决定能不能进二面，后两块决定能不能谈薪与定级。投递前值得先想清楚自己站哪一边：偏 MCU 的裸机与 RTOS 路线，还是偏 Linux 应用与驱动的路线，两条路线的八股重合度其实不高，混着准备容易两边都答不深。

**C 语言与内存：刷人最多的一关**

高频点集中在几个地方。`volatile` 要能说出三个场景——硬件寄存器、中断与主流程共享的变量、多线程可见性，并且说清它不做原子性和内存屏障。结构体对齐与 `#pragma pack` 要会算 sizeof，顺带把大小端、位域、柔性数组一起过一遍。手写代码常考 `memcpy` 的重叠处理、环形缓冲区、链表反转、位图统计、字符串处理，写的时候主动处理边界（空指针、长度为零、越界），比写得快更加分。指针与数组的区别要用 `sizeof`、退化和传参三个角度讲，别停在「数组名是指针常量」。

**RTOS 与并发**

任务状态与调度策略（抢占/时间片）、优先级反转与优先级继承、临界区的几种保护方式（关中断、调度器上锁、互斥量）各自的开销和适用场景，是这一块的骨架。要注意两个常见追问：为什么中断服务程序里不能阻塞、不能在中断里随手拿互斥量；任务栈怎么估算，栈溢出的现象是什么。共享资源用互斥量、任务间通知用信号量或事件标志、数据传递用消息队列，能按语义选对原语，比背 API 更重要。

**Linux 系统与驱动**

从 Linux 应用岗问下来，进程与线程、进程间通信、内存管理（虚拟内存、缺页、mmap）依然是主线；往驱动方向走则要补启动流程、设备树如何描述硬件、驱动 probe 的时机、字符设备的 file_operations、中断上下半部与并发控制（自旋锁与互斥锁的选择依据是「会不会睡眠」）。面试官往往用一个真实场景收尾：设备偶发丢数据，你怎么定位——这时把示波器、逻辑分析仪、内核日志、perf 说清楚，比背结论更有说服力。

**项目与多轮流程**

简历上的项目要经得起三层追问：你具体写了哪一部分、为什么这样设计、出了什么问题怎么定位。没亲手写过的模块不要写上去。多数大厂的嵌软岗流程里都有机试环节，C 语言题与基础算法题是主力，提前把输入输出边界和复杂度练熟。技术面之后的综合面更看稳定性与方向匹配，能不能讲清楚「为什么做嵌入式」，往往比多答对一道八股更影响结果。

**怎么用这类面经清单**

同一家公司的多轮面试往往会重复考察同一批知识点，只是深度不同。按公司纵向刷一遍（一面到三面），能看出追问是怎么一层层加深的；按知识点横向扫一遍，能快速找出自己的空洞。清单本身只是索引，真正要花时间的是把每个知识点讲到能应付二次追问。
