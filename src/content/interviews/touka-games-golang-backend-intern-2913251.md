### 《参考解析》

**秒杀系统的压测与缓存击穿**：QPS 只有一千多，通常不是「并发上不去」，而是瓶颈在别处：压测客户端自己先到极限（Goroutine 数不等于有效并发连接，压测机和被测服务抢同一台机器的 CPU 与网卡）、HTTP 连接没有复用导致握手开销占满、日志和 JSON 序列化这类同步开销、全局锁竞争、以及 Redis 单线程命令排队。排查顺序是先看压测机与被测机的 CPU/网卡/连接数，再用 pprof 看火焰图，最后才怀疑业务逻辑。缓存刷新有两条路：一是写 DB 后主动更新缓存（简单但并发下可能写入乱序），二是删缓存让读请求回源（更常用），配合逻辑过期避免热点 key 同时回源。缓存击穿（key 不存在或刚过期、100 个请求全部打到 MySQL）的正解是「只放一个请求过去」：用 Redis SETNX 加锁让单个请求重建、其余短暂自旋或返回旧值；或者逻辑过期 + 异步刷新，读请求先返回旧值；再用布隆过滤器拦住数据库里根本不存在的 key。100 条消息打给 MySQL 也不该是 100 次写：把请求合并成一条重建任务，消息带唯一业务键做幂等消费，消费端只让第一个成功、其余丢弃。

**Go 空接口与空结构体**：`interface{}`（Go 1.18 后可以写 `any`）用来承载任意类型，常见于 JSON 编解码的中间结构、日志字段、容器类库和反射场景；它的代价是装箱与类型断言的开销，能用泛型或具体类型就别用它。`struct{}` 是零大小类型，不占内存，典型用法是 `map[string]struct{}` 做集合（value 不占空间）、`chan struct{}` 做信号通知（只关心事件不关心数据）、以及没有状态的方法接收者。两者的区别是：空接口表达「什么类型都可能」，空结构体表达「没有数据」，面试时把使用场景和代价一起说清就够了。

**error 封装与判断**：封装用 `fmt.Errorf("查询订单失败: %w", err)`，`%w` 保留错误链。上层判断不要比字符串，用 `errors.Is(err, ErrNotFound)` 判断是不是某个哨兵错误，用 `errors.As(err, &target)` 提取具体错误类型再读它的字段（比如 code、httpStatus）。自定义错误实现 `Error() string` 接口，需要携带上下文就定义结构体错误类型，并在跨层传递时始终用 `%w` 包一层而不是新建一个错误，否则错误链就断了。业务码不要塞进错误字符串里靠前缀匹配，那是典型的事故来源。

**部署与交付**：本地 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags "-s -w" -o app` 交叉编译出静态可执行文件，`scp` 或发布系统推送到服务器，用 systemd 托管（`Restart=always`、限定运行用户、日志交给 journald），前面挂 Nginx 做反向代理与 TLS 终结，配域名而不是裸 IP 加端口。更规范的做法是多阶段 Docker 构建（构建阶段带 Go 工具链，运行阶段只留二进制和时区文件），配健康检查、优雅退出（监听 SIGTERM 后停收新请求并等待在途请求结束）、灰度与回滚。别用 root 直接 `nohup ./app &` 这种跑法。

**位运算求 1024 的余数**：1024 是 2 的 10 次方，对非负整数而言 `x % 1024` 完全等价于 `x & 1023`，位与比取模快，也是面试官想听的点。负数要先取绝对值或用补码语义处理，Go/Java 里负数取模结果符号跟被除数走，直接位与会得到不同的值。推广一下：任何 `% 2^k` 都能转成与 `2^k - 1` 的位与，反过来「判断能否被 2 的幂整除」也是同理。编译器对常量 2 的幂本来就会做这个优化，但面试里能主动指出来是加分项。

**短剧维护中台的 AI 使用场景**：分阶段说更清楚。需求阶段用 AI 把一句话需求拆成用户故事和字段清单（短剧名、封面、集数、状态、热度分、上传人），自己再核对业务口径；设计阶段用 AI 出表结构草稿、接口契约草稿和状态机图，热度排序的算分口径必须自己定（播放量、完播率、时间衰减怎么加权）；编码阶段用 AI 生成 CRUD、分页、热度排序的样板代码，上传下载改成对象存储的预签名 URL，AI 辅助写转码与截图预览的调用；测试阶段用 AI 造 Mock 数据和边界用例（超大文件、断点续传、并发上传同名文件）；上线后用 AI 读慢查询日志提优化建议。要明确说出 AI 不负责的部分：权限模型、与 APP 的接口契约、存储与转码选型、以及任何涉及数据口径的决定，这些都是人来拍板。反问环节可以问业务方向、团队是传统编程还是 AI coding 为主、公司是否提供 token、以及前三个月对新人的预期，这些问题能显示你在认真评估匹配度。
