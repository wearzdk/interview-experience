### 《面试题目》

1. 自我介绍，介绍项目。
2. 项目的一整个流程怎么走的？
3. 提到高并发，怎么实现？
4. SQLite 和 MySQL 有什么区别？
5. 怎么结构化输出？
6. 用户的问题怎么直接给到其他程序使用？
7. 用户可以查询指定的文档，这块怎么处理？

**反问**

8. Agent 是针对内部业务还是客户？——两者都有，侧重内部业务提效。

### 《参考解析》

**项目全流程怎么讲**：按「输入—处理—输出—运维」四段组织。输入层说清来源（用户自然语言、上传文档、外部系统事件）与预处理（清洗、切分、鉴权）；处理层说清编排（意图识别、检索、工具调用、模型生成）与状态管理（会话、重试、超时）；输出层说清结构化格式、引用与错误码；运维层说清部署、监控、评测与迭代。讲的时候给一条真实请求的完整链路，比罗列模块更有说服力。

**Agent 场景的高并发**：高并发在 Agent 系统里瓶颈通常不在业务代码，而在模型调用与检索。做法分为：入口限流（按用户与租户的令牌桶、队列排队）、请求编排（异步化，长任务立即返回任务 id、结果走轮询或推送）、模型调用侧（连接池、批量、流式、多渠道路由与降级、缓存相同请求）、检索侧（向量库分片与副本、结果缓存、预计算）、存储侧（会话与日志写多读少，用消息队列削峰、冷热分离）、以及降级策略（模型不可用时返回缓存或模板答案）。如果项目里只有一个 SQLite 单文件库，高并发就是伪命题——先说明当前量级与瓶颈，再讲清楚如果放大十倍会先改哪里。

**SQLite 与 MySQL 的区别**：SQLite 是嵌入式库，无独立进程、零配置、整个库是一个文件，读写走文件锁，同一时刻只允许一个写者，适合单机、小数据量、读多写少（桌面应用、边缘设备、测试）；MySQL 是客户端—服务端架构，支持多连接并发、行级锁、事务隔离级别、主从复制与分库分表，适合多用户、高并发、需要网络访问的服务端场景。SQLite 的优势是极简与可靠（单文件易备份、无运维），劣势是并发写与网络访问；MySQL 的优势是并发、生态与运维工具，劣势是需要部署与调优。

**结构化输出怎么做**：优先用模型的原生结构化能力（JSON Schema / function calling / response format），把 schema 写清楚字段类型、枚举与必填项；解析失败时做一次修复重试（把错误信息回给模型让它修正），仍失败则降级到规则解析或返回明确错误。工程上要对输出做校验（类型、范围、业务约束）、记录解析失败率，并对关键字段做二次确认。不要只靠提示词说「输出 JSON」而不做校验。

**把用户问题交给其他程序**：本质是把自然语言转成可执行的意图与参数（结构化指令），通过 API、消息队列或函数调用交给下游。设计上要有稳定的契约（意图名、参数 schema、版本）、幂等键、超时与重试、以及结果回传通道。若下游是内部系统，通常由 Agent 调用工具（tool calling）完成；若是异步任务，返回任务 id 由调用方轮询。

**指定文档查询**：先做文档入库（解析、切分、embedding、元数据），查询时按用户指定的文档 id 过滤检索范围，避免跨文档串味；权限要在检索前校验（用户是否有权读这份文档），而不是在生成后过滤。文档内定位可用页码、段落 id 或句子级索引，返回时附引用。文档更新要做增量索引与版本管理，删除要同步清理向量。
