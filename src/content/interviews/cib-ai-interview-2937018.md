### 《面试题目》

1. 选择一种编程语言（可选项有限）。
2. 协议相关问题。
3. 根据所选语言问技术问题与语言设计哲学：一个底层原理问题，再给一个较复杂场景问内部状态，最后问这门语言为什么要这么设计。
4. 计算机基础知识：SRP、OCP 是什么，结合实例讲解它们在软件设计中的重要性。
5. 追问：如何结合实际开发场景用它们解决实际问题？SRP 背后的核心原理是什么？它有没有不适用的场景或边界？
6. 宝洁八大问：最难的一次是什么、如何跨领域学习新知识、如何发现并解决问题等。
7. 每大题追问两到三次。

### 《参考解析》

**语言选择的影响**：AI 面让你先选语言，后面就围绕这门语言追问，所以不要选「听说过但没写过」的。选你最熟的那门，哪怕它不是岗位主语言——被追问底层原理时，熟悉度决定你能不能答到第二层。如果可选项里没有你熟的，选语法与内存模型最接近你熟语言的那门，并在回答时说明你的实际经验在哪门语言上。

**语言设计哲学的答法**：以 Java 为例，设计目标是「一次编写到处运行、强类型、面向对象、向后兼容」，所以有 JVM 字节码、垃圾回收、单继承加接口多实现、装箱与泛型擦除这些取舍。以 Go 为例，目标是「简单、并发友好、编译快」，所以有 goroutine 与 channel、没有继承只有组合、错误显式返回、GC 但可调。回答结构：设计目标 → 具体机制 → 这个机制带来的代价。追问「较复杂场景下内部是什么状态」时，要能讲到内存布局或运行时结构，例如 Java 的对象头与锁升级、Go 的 GMP 调度与逃逸分析。

**SRP 与 OCP**：单一职责原则指一个类只应有一个引起它变化的原因，核心是「变化的维度」而不是「代码行数少」；它的边界在于「职责」的划分依赖业务语境，过度拆分会导致类爆炸与调用链过长，所以实践中按变化频率与变更来源聚合。开闭原则指对扩展开放、对修改关闭，靠抽象与多态实现：新增类型时加实现而不是改分支。它的不适用场景是需求本身不稳定、抽象尚未成型时，过早抽象会固化错误的方向，此时先写具体实现、等变化出现再重构更合理。结合实际例子：支付渠道接入用策略模式加工厂满足 OCP；订单状态机把每个状态的流转封装成独立类满足 SRP。

**AI 面的应对**：兴业这场是「一半技术一半宝洁」，每题思考 16 秒、作答 5 到 10 分钟，追问两到三次，双机位全程录像。准备要点：技术题要能讲到第二层（原理与取舍），行为题用 STAR 但压缩背景，每段留一个可被追问的细节。数字人面试没有互动反馈，语速放慢、句子说完整、避免长时间沉默；作答时间足够，不要急着结束。

**宝洁八大问的通用结构**：情境（一句话）→ 任务（你要达成什么）→ 行动（你具体做了什么，用「我」而不是「我们」）→ 结果（可量化）→ 反思（如果重来怎么改）。跨领域学习那题要给路径：先建立框架再补细节、找权威资料、用小项目验证、找人校准。
