### 《参考解析》

**Agent 连续失败，先分类再决定重试，不能无脑循环。** 三次报错要拆成三类：瞬时错误（超时、限流、5xx）可以指数退避重试；参数/契约错误（缺字段、类型不对、枚举越界）重试同样的调用没有意义，要把校验器的报错原文回喂给模型，让它修正参数，并限制修正次数；逻辑错误（工具选错、目标本身不可达）要回到规划层，换工具或拆任务。工程上设全局步数/费用上限，连续失败达到阈值就降级：返回已知的部分结果、转人工、或明确告诉用户「这一步没做成，原因是什么」。同时把每次调用的入参、出参、错误码、trace_id 落日志，否则线上根本不知道为什么错。

**工具参数校验用 schema，上下文管理用「状态 + 摘要 + 检索」。** 工具定义里写 JSON Schema，调用前本地校验，失败时把「哪个字段、期望什么、实际是什么」结构化返回给模型；工具内部还要做业务校验（ID 是否存在、权限是否足够），两层不能省。上下文方面，短期保留最近若干轮原文，长期把「任务目标、已确认事实、用户偏好、待办」写进结构化 memory，需要时按相关性检索回来；摘要要有损但可控，定期用原始记录校正，避免多轮之后摘要漂移。工具返回也要截断：长列表只给前 N 条和总数，大文本给摘要加引用，避免一次调用把窗口打满。

**SFT 和 DPO 的区别在「学什么信号」。** SFT 是监督微调，用「输入 → 标准答案」的配对数据做最大似然，让模型学会任务格式、领域表达和基本行为，数据质量比数量重要，通常要先有 SFT 再做偏好优化。DPO 直接用「同一输入下 chosen / rejected 两条回答」的偏好对优化策略，跳过训练奖励模型和 RL 采样，目标函数里显式提高 chosen 相对 rejected 的概率，同时用参考模型约束住不要偏离太远。它的优点是稳定、便宜、易复现；局限是依赖偏好数据质量、对分布外问题约束弱，且没有在线探索。常见流程是 SFT 打底 → 构造偏好对 → DPO/ORPO 调风格与安全性 → 评测集回归。

**LoRA 是「冻结原权重，只学低秩增量」。** 对某个线性层 `W ∈ R^{d×k}`，不直接更新 W，而是加一个低秩分解 `ΔW = B·A`，其中 `A ∈ R^{r×k}`、`B ∈ R^{d×r}`，r 远小于 d、k；前向变成 `h = Wx + (α/r)·BAx`。训练只更新 A、B，参数量降到原来的百分之几，显存和存储都省，推理时可以把 `BA` 合并回 W，不增加延迟。初始化通常 A 随机、B 置零，保证起步时增量为零；r、α、dropout 和目标模块（q/k/v/o、MLP）是要调的，r 越大容量越强也越容易过拟合。

**实体对齐是知识图谱里最脏也最关键的活。** 同一疾病的中文名、英文名、缩写、俗称被抽成不同实体，单靠字符串匹配不够。可做的分层：① 归一化（全半角、大小写、去空白、繁简转换）；② 别名词典与规则（ICD/MeSH 等标准库、院内字典、括号里的英文名）；③ 向量相似 + 字面相似（编辑距离、Jaccard、字符 n-gram）做候选召回；④ 用上下文属性辅助判断（科室、症状、药品关系是否一致）；⑤ 人工审核高风险合并，保留合并理由和来源。图谱里用「规范实体 + 别名边」表达，不要直接把别名删掉，否则会丢检索入口。评测要单独看准确率与召回率：医疗场景宁可漏合并，也不能把两个不同疾病错并成一个。

**从数据里抽实体关系的 Agent，设计顺序是「schema 先行」。** 先和业务确认本体：实体类型、关系类型、属性、约束（哪些关系允许自环、基数是多少），落成机器可读的 schema；再做文档解析与分块，保留章节和表格结构；抽取阶段可以用「LLM 按 schema 输出 JSON + 规则/词典兜底 + 校验器」，长文档分块抽完后做跨块合并；然后实体对齐、去重、冲突消解，最后入图并建索引。质量上要有人工抽检集，按实体类型和关系类型分别算 P/R/F1；线上要能回溯每条三元组来自哪段原文，否则错了没法修。
