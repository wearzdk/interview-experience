### 《参考解析》

**跨设备跟踪与标识跳变**：单摄像头内的跟踪靠运动预测（卡尔曼滤波）与外观特征的匹配，跨设备则失去连续的帧间信息，必须依赖重识别（ReID）。难点有三：不同相机视角、光照、分辨率导致同一目标的外观特征分布不一致；目标从一个视野消失到进入下一个视野之间存在时间空窗；遮挡与并排行走会造成特征混淆。工程解法是「时空约束 + 外观特征」联合匹配：用相机标定与地理关系建立视野间的可达区域和迁移时间窗，只在合理时间窗内做候选匹配；外观特征用 ReID 模型提取 embedding，做余弦距离匹配并设阈值；对高置信匹配才更新全局 ID，低置信先挂起，等更多帧确认。标识跳变（ID switch）的评价指标是 MOTA、IDF1 与 ID switch 次数，优化时要在「少跳变」与「少漏跟」之间取舍。

**现场干扰与边缘部署**：单设备跟踪的干扰包括光照突变、逆光、雨雾、目标遮挡、相似着装、相机抖动。模型侧用数据增强覆盖这些场景，检测器与 ReID 分开训练，跟踪器加运动模型抑制抖动；部署侧做轻量化：剪枝、蒸馏、INT8 量化、算子融合，导出 ONNX 后编译为 TensorRT 引擎，按边缘设备的算力选择输入分辨率与批大小，用多流并行（解码、预处理、推理、后处理分线程）把各段流水起来。要给出可验证的数字：原始模型多少毫秒、量化后多少毫秒、精度掉了几个点、采取了什么补偿（量化感知训练、保留敏感层为 FP16）。

**全局数据结构**：一条目标记录通常包含全局 ID、当前与历史的位置（世界坐标或各相机坐标）、时间戳、外观特征向量、状态（活跃、丢失、已注销）、置信度、来源相机、轨迹片段。作用是支撑匹配（特征与时空）、生命周期管理（超时注销）、业务查询（轨迹回放、越界统计）与调试（回溯为何发生 ID 切换）。设计上要注意特征向量的更新策略（滑动平均还是保留多帧）、内存上限（长时间运行要淘汰旧轨迹）与并发访问（多路相机线程写入）。

**项目负责人怎么讲**：对内是拆任务、定接口、控进度、做 code review 与联调；对外是需求确认、验收标准、现场问题响应。回答要落到具体动作与结果，例如「把检测与跟踪拆成两个可独立验证的模块，约定数据格式，使两组人能并行开发，联调时间从两周降到三天」。被问冲突处理时讲一次真实的分歧：先对齐目标与验收标准，再把方案拆成可对比的实验，用数据决定，而不是靠职位压人。

**竞赛项目与企业落地项目的差别**：竞赛以指标为先，数据干净、周期短、允许反复试错；企业项目要交付、要可维护、要考虑现场环境、成本与售后，指标之外还有稳定性、可观测性与文档。回答时说明自己在两种模式下分别学到什么，以及落地项目里被迫做的取舍（例如为了实时性牺牲一点精度）。

**求职意向类问题**：地域、行业、岗位认知要给出有依据的选择，而不是「都可以」。谈嵌入式岗位时讲清它与你做过的事的连接：资源受限下的取舍、软硬结合、现场问题定位。B 站分享的收获落到「把做过的事讲清楚迫使自己补全原理、也从评论里发现问题」，比说「提升了表达能力」具体。
