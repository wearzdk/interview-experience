### 《参考解析》

**Ontology 平台怎么建**：Ontology 是给业务世界建模的一套概念体系：对象类型（业务实体，如订单、门店）、属性（字段与类型）、关系（实体之间的关联）、Action（对实体可执行的操作，含入参 Schema、权限、副作用与审批）。平台的职责是把这些定义集中注册、版本化、发布，并让消费方（Agent、前端、后端服务）按统一语义发现与调用。管理上通常用元数据服务 + 注册中心：定义存库（对象、属性、关系、Action 各一张表，带版本与状态），发布时生成快照并推送变更事件；消费方通过 SDK 或 OpenAPI 拉取元数据，Agent 侧把它转成工具描述（tool schema）注入模型。效果衡量的指标要能落到业务：接入的业务域与 Action 数、Agent 调用成功率与人工兜底率、接口收敛前后新增一个业务接入的工时、以及业务侧可观测的收益（如客服自助解决率、工单流转时长）。

**柔性调用链**：业务系统里同一个语义可能落在不同协议上——新服务是 HTTP/JSON，老系统是 JSF（Dubbo 系的 RPC）。柔性调用链指在 Action 层做协议适配与容错编排：根据元数据里声明的后端实现选择协议，统一做参数校验、超时、重试、降级与熔断，失败时回退到备用实现或转人工，而不是让模型直接面对多种协议与错误码。所谓「柔性」是相对「硬编码调用」而言：调用路径由元数据驱动，可配置、可灰度、可在不改代码的情况下切换后端。

**Ontology 为什么重新受关注**：大模型能理解自然语言，但不知道企业内部的实体、关系与可执行操作，直接给接口会乱调、给文档会编造。把业务语义显式建模成对象与 Action，等于给模型一份受约束的世界模型与工具集：它知道有哪些实体、能做什么、参数边界在哪，从而把「自然语言意图」稳定映射到「合法操作」。这与 MCP 解决「工具如何被发现与调用」是互补关系——MCP 管协议，Ontology 管语义与治理。

**确定性规则与 LLM 分工**：原则是「能用代码判定的不交给模型」。前置用 JSON Schema 约束输出结构（字段、类型、枚举、必填），模型输出后先解析校验，不合格直接重试或走兜底；后置用规则断言校验业务不变量（金额不能为负、时间不能倒挂、引用 ID 必须存在、权限必须匹配），命中即拦截并记录。LLM 负责语义理解、意图识别、生成候选与解释；确定性规则负责边界、权限与最终裁决。这样幻觉被限制在「候选生成」阶段，不会直接落到执行。

**延迟任务系统设计（每秒一万提交、可取消）**：核心是把「时间」变成可索引的键。方案一：时间轮（timing wheel）——按秒/毫秒分槽，任务按到期时间放入槽内，指针推进时取出到期槽执行，插入与删除 O(1)，适合大量短延迟任务；分层时间轮（Kafka 的做法）解决跨度大的问题。方案二：按到期时间分桶存 Redis ZSET（score = 执行时间戳），消费者用 `ZRANGEBYSCORE` 取到期任务，配合 `ZREM` 的返回值保证只有一个实例抢到（原子操作即分布式锁）；取消就是从 ZSET 删除并置状态为 cancelled。方案三：数据库按时间分片 + 状态机，适合需要强持久化与可查询的场景。

「是否需要外部数据库」取决于三件事：任务丢失能否容忍（能重放就不需要强持久化）、取消与查询是否要跨实例可见、以及审计与重试要求。金融、订单类必须落库；纯提醒类可以只放内存 + 定期快照。

轮询参数：批量大小按「单批处理耗时 < 轮询间隔」倒推，例如每批 500 条、单条 2ms 则一批约 1 秒，轮询间隔取 200~500ms 并用长轮询或阻塞队列降低空转；高频短延迟任务用时间轮 + Netty 的 `HashedWheelTimer` 思路，避免每秒全表扫描。多实例防重复：ZSET 的 `ZREM` 原子抢占、或数据库 `UPDATE ... WHERE status='pending' AND execute_at<=now LIMIT n` 加行锁、或按任务 ID 哈希固定到某个实例（一致性哈希）配合故障转移。取消的实现要注意竞态：任务已进入执行中时取消要能中断（检查取消标记、协作式取消），已执行的取消请求记录为「取消失败」并返回明确状态，而不是静默丢弃。

**多头的含义**：单头注意力只做一次 Q/K/V 投影，得到一个注意力分布；多头把 Q/K/V 投影到 h 组低维子空间，各自独立算 scaled dot-product attention，再拼接后过输出投影。作用是让模型在不同子空间里并行关注不同类型的关系（语法、指代、位置、语义角色），类似卷积的多通道；每头维度 d_model/h 使总计算量与单头相当。亮点还包括：完全基于注意力的并行化（取代 RNN 的时序依赖）、位置编码、残差与 LayerNorm 支撑深堆叠、以及 scaled dot-product 里除以 √d_k 稳定梯度。

**组合总和**：给定候选数组（元素可重复使用）与目标值，求所有和为目标的组合，解集不能重复。做法是回溯：排序后递归，参数带 `start` 保证组合内非递减从而去重，`target` 递减，等于 0 时收集，小于 0 或当前数大于剩余目标时剪枝。时间复杂度上界 O(N^(T/M))（N 为候选数、T 为目标、M 为最小候选值），也可以表述为解的个数乘以每个解的长度；空间是递归深度 O(T/M)。要能现场写出可运行代码并跑几个用例（如 candidates=[2,3,6,7], target=7 → [[2,2,3],[7]]）。
