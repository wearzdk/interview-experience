### 《面试题目》

1. 你对 Java 的理解是什么？Java 的优势是什么？
2. 什么是 Agent，和调用 API 有什么区别？
3. Redis 缓存穿透和缓存击穿有什么区别？
4. JVM 的内存分区是怎样的？
5. B+ 树为什么比 B 树更适合做索引？
6. 你简历上这个项目解决什么问题？
7. 这个功能为什么这么设计？当时考虑过别的方案没有？
8. 上线后遇到过什么问题？
9. 这个功能在源码里大概落在哪个模块？
10. 当时那个参数是怎么调的？调大了会怎么样？
11. 这个项目你自己跑起来过吗？
12. 为什么你会设置三次后介入？具体的流程逻辑是什么，介入方式是什么？
13. 这段实习里你具体负责什么？为什么这块是组长定的、那块是同事做的？
14. 你平时怎么用 AI 写代码？AI 生成的代码你会逐行看吗？

### 《参考解析》

**淘汰率最高的不是算法**：面试官明确说手撕没写出来、算法超时占比不高，真正的问题是问答。原因很实在：一场常规技术面只有四十分钟，面试官只能按这四十分钟里看到的东西打分。表达不清、项目讲不透、被追问就崩，都会被记成「拿不到真实水平」。

**紧张与没有结构是两件事**：紧张到眼神躲闪、一句话组织不完整，面试官通常会给两三轮缓冲，换个更开放的问题；如果越给缓冲越紧，基本就判定了。另一类是紧张但话多，一个问题讲三分钟还没到重点——技术也许不差，但表达没练过。改善方式很具体：对着手机录几遍自我介绍和一个项目讲解，自己回放听，两三次就能明显收敛。

**热身题与简历必须对得上**：简历写 Redis 就问穿透与击穿，写 JVM 就问内存分区，写索引就问 B+ 树。这里出问题往往不是答得浅，而是答错或者明显背模板。最典型的是把「B+ 树为什么更适合索引」答成「因为它是 B 树的优化版本」——这是正确的废话，面试官要的是机制：B+ 树非叶子节点只存键、扇出更大、树更矮，叶子节点用链表串起来，范围查询只扫叶子、顺序 IO 更省。另一个雷是「精通」：写了精通就按精通的标准问，两层就能挖到底，写熟练或了解反而不会被为难。

**项目追问怎么撑住**：面试官会沿着「解决什么问题 → 为什么这么设计 → 考虑过别的方案吗 → 上线后遇到什么问题 → 源码落在哪个模块 → 参数调大调小会怎样」一路往下。答不上来时反复说「这是组长定的」「这块是同事做的」「需求就是这样」，本身不扣分，但继续问这部分怎么实现还是答不上来，就只能认为这段经历的深度不够。开源项目和教程项目更容易露：真跑过的人有肌肉记忆，能说出具体的坑；只看过视频的人用词正确但没有落点。

**被点破后的态度决定诚信分**：承认「这个项目我是跟着教程做的，源码看过但没完全跑通」，面试官大概率会换个方向继续问，这段经历不至于成为扣分点。硬撑——问做没做过说做过、问细节说记不清、再问说时间太久——消耗的是可信度，而可信度在四十分钟里补不回来。AI 时代这一点更微妙：用 AI 写代码完全没问题，但把 AI 生成的代码当成自己逐行写的来讲，第二层追问就会露馅。

**态度也是评分项**：全程「嗯、对、还行」不给展开，或者被质疑方案时反问「那你们线上是怎么做的」，都属于把技术讨论变成了对抗。正确顺序是先答完对方的问题，再提出自己的疑问；真正强的人反而平实，问什么答什么，不懂就说不懂并讲清自己的理解边界。
