### 《参考解析》

**roofline 与算术强度**：横轴是算术强度（FLOP/Byte），纵轴是可达性能，屋顶由两条线拼成——左侧斜线是带宽上限（峰值带宽乘算术强度），右侧平台是算力上限，交点对应的算术强度就是机器的拐点。算子落在斜线区是带宽瓶颈，落在平台区是计算瓶颈。判断别凭感觉，看 profiler 的 memory 与 compute throughput 占比。

**stall 分类与定位**：常见的有 long scoreboard（等全局内存）、short scoreboard（等共享内存）、barrier（等同步）、MIO throttle（共享内存或特殊功能单元排队）、math pipe throttle（计算单元打满）、not selected。Nsight Compute 的 Warp State 页直接给占比，先看最高的一类，再回源码找对应的访存模式、bank conflict 或同步点。

**SpMV 与 GEMM**：GEMM 计算密集、数据可复用，靠分块提高片上复用率，shared memory 加 register tiling；SpMV 访存不规整、每行非零元个数不定，算术强度极低，几乎必然带宽受限，方向是换压缩格式（CSR、ELL）、按行分组降低 warp 内负载不均、向量化访存。

**CPU 侧与 launch 开销**：跨 NUMA 掉性能通常是内存分到了远端节点，用 numactl 同时绑核绑内存，OpenMP 还要注意线程亲和性与 false sharing。CPU 调度跟不上 GPU 时问题多在提交路径：每次 launch 要走驱动做参数拷贝、上下文检查、命令入队，小 kernel 多了固定开销超过计算本身，解法是 CUDA Graph、批量提交或算子融合。
