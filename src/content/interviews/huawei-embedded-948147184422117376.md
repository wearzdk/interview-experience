### 《参考解析》

**互斥锁在内核里的实现与阻塞线程的去向。** Linux 上用户态的 `pthread_mutex_lock` 最终走 futex（fast userspace mutex）：无竞争时只在用户态做一次原子 CAS，把锁字从 0 改成 1，不进入内核；有竞争时才通过 `futex(FUTEX_WAIT)` 系统调用陷入内核，把当前线程挂到该锁地址对应的等待队列上并置为睡眠态（TASK_INTERRUPTIBLE / UNINTERRUPTIBLE），由调度器切走。解锁时 `futex(FUTEX_WAKE)` 唤醒等待队列里的一个线程，被唤醒的线程重新竞争锁。所以「加锁失败的线程去哪了」的答案是：先自旋一小段（adaptive spinning），失败后进入内核等待队列睡眠，不再占用 CPU。自旋锁则不睡眠，原地循环检查锁标志，适合临界区极短、且不能睡眠的场景（中断上下文），多核上有效，单核上纯属浪费。

**原子操作与内存屏障。** 原子操作靠 CPU 提供的原子指令实现（x86 的 `LOCK` 前缀、ARM 的 LDXR/STXR 或 LSE 的 LDADD），`LOCK` 会锁总线或锁缓存行，保证读改写不可分割；无锁编程里的 CAS 循环就是基于它。和加锁相比，原子操作没有系统调用与调度开销，但高竞争下 CAS 失败重试会空转、缓存行来回失效（伪共享），吞吐反而不如锁。`volatile` 只保证「每次都从内存读、不被编译器优化掉」，不保证原子性、不保证顺序（CPU 与编译器都可能重排）、也不保证缓存一致性层面的可见性，所以不能用它做线程同步。内存屏障（`smp_mb`、`smp_rmb`、`smp_wmb` 或 C11 的 `atomic_thread_fence`）用于约束重排：在「先写数据、再置标志位」这类发布-订阅模式里，必须在两者之间插入写屏障，读者在读到标志位后插入读屏障，才能保证看到完整的数据。

**TCP 可靠传输与流量控制。** 可靠性由四件事共同保证：序号与确认（每个字节有序号，接收方 cumulative ACK）、超时重传与快速重传（收到三个重复 ACK 立即重传）、校验和、以及接收端的去重与排序。流量控制靠滑动窗口：接收方在 ACK 里通告自己的接收窗口（rwnd），发送方据此限制在途数据量，避免压垮接收端。拥塞控制是发送方对网络的估计：慢启动（cwnd 从初始窗口指数增长到阈值）、拥塞避免（线性增长）、快速重传与快速恢复（收到三个重复 ACK 时减半并重传），以及超时后的重传与窗口收缩。两者配合的方式是「实际可发送量 = min(rwnd, cwnd)」，慢启动的作用是在不知道网络容量时快速试探，避免一开始就大流量造成拥塞崩溃。现代内核还用 BBR 这类基于带宽与 RTT 建模的算法替代丢包驱动。

**TIME_WAIT 与 2MSL。** TIME_WAIT 由主动关闭方进入，作用是两件事：其一，保证最后一个 ACK 能到达对端——如果 ACK 丢失，对端会重传 FIN，处于 TIME_WAIT 的一方还能重发 ACK，否则会回 RST 导致对端异常；其二，让本次连接的旧报文在网络中消散，避免它们被随后复用同一四元组的新连接误收。等待 2MSL 是因为报文最长存活时间为 MSL，一来一回正好覆盖。服务器出现大量 TIME_WAIT 通常是因为服务端主动关闭了大量短连接（例如 HTTP 短连接、反向代理到上游没开 keep-alive）。处理手段：开启长连接与连接复用、由客户端主动关闭、调整 `tcp_tw_reuse`（谨慎）、扩大本地端口范围、减少不必要的短连接。`tcp_tw_recycle` 在现代内核已移除，不要再提。

**epoll 为什么高效。** select/poll 每次调用都要把整个 fd 集合从用户态拷贝到内核态并线性扫描，复杂度 O(n)，且有 FD_SETSIZE 限制。epoll 用三件事解决：`epoll_create` 在内核建一棵红黑树保存关注的 fd（增删改 O(log n)，不用每次重传）；`epoll_ctl` 注册时给每个 fd 挂上回调，数据到达时由中断/软中断把就绪的 fd 挂到就绪链表；`epoll_wait` 只返回就绪链表里的 fd，复杂度与就绪数成正比而不是与总数成正比。触发模式有水平触发（LT，只要还有数据就一直通知）与边缘触发（ET，状态变化时通知一次，必须一次读到 EAGAIN），ET 配合非阻塞 IO 可以减少系统调用次数，但写错容易丢数据。

**内存泄漏的定位流程。** 先确认现象：是 RSS 持续上涨还是仅虚拟内存增长（后者可能是 mmap 或线程栈预留，不一定是泄漏）。再看趋势：稳定复现的操作路径下观察增长斜率，判断是泄漏还是缓存膨胀。工具上，用户态用 Valgrind（memcheck / massif）、AddressSanitizer 的 LeakSanitizer、`mtrace`，或在代码里重载 `malloc/free` 记录分配点；内核态看 `/proc/<pid>/smaps`、slabinfo、kmemleak。定位方法是「分配点归因」：抓两次快照做差分，按调用栈聚合，重点看只增不减的分配点。修复后要加回归：长时间压测观察 RSS 是否收敛，并在 CI 里跑一次泄漏检测。

**C 语言细节。** 数组名在大多数表达式里退化为指向首元素的指针，所以函数传参传的是指针，函数内 `sizeof` 得到的是指针宽度；要传长度必须显式带 `len`。二级指针用于「需要修改指针本身」的场景：在函数内分配内存并回写给调用方（`void alloc(char **p)`）、修改指针数组的元素、以及作为二维数组的行指针。`malloc` 后 `free` 再访问是未定义行为，可能读到脏数据、可能触发堆破坏、也可能看起来正常（这正是它危险的地方），调试器与 ASan 能抓到 use-after-free。`strcpy` 按 `\0` 截断且不检查目标容量，是缓冲区溢出的经典来源，应改用 `strncpy`/`snprintf` 并显式补 `\0`；`memcpy` 按字节数拷贝、不关心内容，适合二进制数据，但源与目标重叠时行为未定义，重叠要用 `memmove`。结构体对齐的优化原则是把成员按对齐要求从大到小排列，减少填充；也可以用 `__attribute__((packed))` 但会带来非对齐访问的性能损失甚至总线错误。

**手撕题的要点。** 反转链表用三指针迭代（prev、cur、next），注意保存 next 再改指针、最后返回 prev；递归写法要说明栈深度 O(n)。回文判断不申请额外空间就用双指针从两端向中间收，注意跳过非字母数字、统一大小写，以及空串与单字符的边界。
