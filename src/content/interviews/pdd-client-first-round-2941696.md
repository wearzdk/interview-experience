### 《面试题目》

1. 让你去实现一个线程池，怎么实现？
2. 缓冲队列具体怎么实现？
3. 有很多数字，要去查找其中一个数，链表快还是数组快？
4. 哈希冲突了，为什么拉链法用链表不用数组？
5. 前后端信息互传怎么保证安全？
6. HTTPS 为什么能保证安全？
7. 手撕：LeetCode 27 移除元素（Remove Element）。

### 《参考解析》

**手写线程池的五个部件**：任务队列（缓冲队列）、工作线程集合、互斥锁与条件变量、状态标志（running / shutdown）、提交接口。核心循环是「加锁 → 队列空则 wait 在条件变量上 → 否则取任务 → 解锁 → 执行」；提交时入队后 `notify_one`。要讲到的细节：用 `std::condition_variable` 配合 `unique_lock` 避免忙等；关闭时要先置停止标志再 `notify_all`，让线程退出而不是永久阻塞；任务用 `std::function<void()>` 擦除类型；拒绝策略（队列满时阻塞、丢弃、抛异常或由调用方执行）要显式选择；线程数按 CPU 核数与任务类型（CPU 密集 vs IO 密集）决定，不要固定写死。加分项是提到「异常不能让线程 terminate」，任务执行要 try/catch 兜住。

**缓冲队列的三档实现**：无界 `std::deque` + 互斥锁最简单但可能撑爆内存；有界队列要在满时阻塞生产者或走拒绝策略；性能要求高时用环形缓冲区（固定容量、读写指针、原子操作）实现单生产者单消费者无锁队列，或用条件变量做双缓冲切换减少锁竞争。结构性回答是「容量策略 + 同步方式 + 溢出的处理」，这三件事决定队列能不能用在生产里。

**链表还是数组查找**：如果只是「查某个值在不在」，两者都是 O(n) 线性扫描，但数组有连续内存与 cache line 预取，实际更快（同样的 n，数组通常快数倍）；如果数据有序，数组可以二分 O(log n)，链表不行；如果是按索引访问，数组 O(1)、链表 O(n)。如果「很多数字」且反复查询，正确回答是先建哈希表或排序，而不是在链表和数组之间选。

**拉链法为什么用链表**：冲突桶里的元素个数不可预知，链表可以 O(1) 插入、按需增长，不需要预估桶的容量；用数组则要么定长（冲突多时装不下）要么每次冲突扩容搬移。代价是链表节点分散、缓存不友好，所以现代实现在桶内元素超过阈值时转成红黑树（Java 8 的 HashMap 阈值是 8），或者用开放寻址 + 连续存储（如 SwissTable、Robin Hood 哈希）换取局部性。回答到这里才完整。

**前后端传输安全要分层**：传输层用 HTTPS（TLS）保证机密性、完整性与服务端身份；身份层用短期 token（JWT 或 session + HttpOnly Cookie），配合刷新机制与登出失效；请求层防 CSRF（SameSite Cookie、CSRF Token、校验 Origin）与重放（时间戳 + nonce + 签名）；输入层做校验与转义防 XSS / SQL 注入，服务端永远不信任前端校验；敏感字段额外加密或脱敏，密钥不进前端代码；接口做鉴权（越权校验要按资源归属判断，不能只判断是否登录）与限流。要强调「HTTPS 只解决传输，不解决越权、重放与前端密钥泄露」。

**HTTPS 为什么安全**：TLS 握手用非对称加密（ECDHE 密钥交换 + 证书签名）协商出一个会话密钥并验证服务端身份（证书链 + 主机名校验），之后的数据用对称加密（AES-GCM 或 ChaCha20-Poly1305）传输——非对称解决「密钥怎么安全地商定」，对称解决「大量数据怎么加密才不慢」，AEAD 同时提供完整性校验（防篡改）。ECDHE 提供前向保密（私钥泄露也解不开历史流量）。要说清它**不保证**什么：不防服务端本身作恶、不防客户端被劫持（中间人装了根证书就能解密）、不防业务逻辑漏洞，所以还需要 HSTS、证书固定（pinning）与业务侧鉴权配合。

**移除元素**：双指针，`slow` 指向待写入位置，`fast` 遍历，遇到不等于 `val` 的元素就写到 `slow` 并前进，最后返回 `slow`。时间 O(n)、空间 O(1)，元素顺序可以改变时还可以用「与末尾元素交换」的写法减少写入次数。
