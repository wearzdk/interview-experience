### 《参考解析》

**面试官在验证什么**：整场的主线不是八股，而是「简历上的数字能不能撑住追问」。被问到模型选型、测试集、错误率时，回答必须能落到具体口径：测试集多少条、从哪来、标注几个人、指标怎么算、错误分类的边界是什么。如果数字是估算的，被追问两层就会崩。准备这类项目时，把「数据来源 → 标注规则 → 指标定义 → 迭代记录」写成一张表，比背结论有用。

**测试集与防过拟合**：测试集要按真实分布构建，从线上抽样并用人工标注，覆盖高频意图与长尾异常；规模不必大，几百条且标注一致比几万条噪声数据有用。防过拟合的手段是：训练/验证/测试严格分开、测试集不参与提示词调优（调优只用验证集）、定期用新采样的数据替换一部分测试集（滚动测试集）、以及在线上用真实流量做影子评估。要能说清「指标提升了但线上没变」的可能原因：测试集与线上分布不一致、指标口径只覆盖了容易的部分、或者收益被其他环节吃掉。

**错误归因**：先把错误分类再统计——检索未召回、检索召回了但排序靠后、上下文超长被截断、模型理解错误、生成格式不符合要求、工具调用参数错误、以及业务规则本身不允许。每类占比不同，优化手段完全不同。统计口径要固定（同一批测试集、同一套判定脚本），否则前后对比没有意义。面试官追问「数据补全之后单项错误率下降多少」就是在查你是否真的做过逐项归因。

**本体化的价值**：本体是对业务概念及其关系的显式建模（实体、属性、关系、约束），它的作用不是「让模型更聪明」，而是提供可复用的结构：让检索能按概念扩展、让规则校验有依据、让不同系统对同一概念的理解一致。抽取方式通常是「模型初抽 + 人工审核 + 规则校验」三步，质量指标包括覆盖率（业务文档中的关键概念是否被覆盖）、准确率（抽样人工判定）、一致性（同一概念在不同文档中是否归一到同一实体）、以及下游可用性（用本体做检索或校验后，任务指标是否提升）。只讲「我们用大模型抽了本体」而不讲质量校验，会被判定为没有落地。

**登录注册与密码存储**：JWT 方案下，登录成功签发 access token（短期，15～30 分钟）与 refresh token（长期，存服务端可吊销），access token 放内存或 HttpOnly Cookie，不要放 localStorage（易被 XSS 读取）；签名用 HS256 时密钥要足够长且不落前端，用 RS256 时注意不要把私钥泄漏。密码必须加盐哈希，用 bcrypt、scrypt 或 Argon2，不要用 MD5/SHA1，也不要用可逆加密；盐每人独立随机，cost 参数按机器性能调。

**AI 生成登录代码的常见问题**：硬编码密钥或数据库口令、字符串拼接 SQL 导致注入、密码明文或弱哈希存储、JWT 未校验过期与签名算法、把用户输入直接放进日志（泄漏密码）、缺少登录失败限流与账号锁定、`catch` 后静默返回成功、以及把 `userId` 从请求参数里取而不是从 token 解析（越权）。SQL 注入的根治是参数化查询（PreparedStatement 或 ORM 绑定参数），辅以最小权限数据库账号与输入校验。

**用户名防重**：最可靠的是数据库唯一索引，插入冲突时捕获唯一键异常并返回明确提示；不要用「先查再插」，因为并发下两个请求会同时查到不存在。Redis 可以做前置拦截（`SETNX` 占用用户名，设置合理过期），但只能降低数据库压力，最终一致性仍靠唯一索引兜底。其他方案包括分布式锁（按用户名加锁，串行化注册）、以及把用户名归一化（大小写、全半角、空白）后再比较。Redis 与 MySQL 的一致性用「先落库成功再写 Redis、失败则删除缓存」加补偿任务处理。

**三线程循环打印 ABC**：三种写法。① `synchronized` + `wait/notifyAll`：共享一个状态变量表示该谁打印，每个线程循环里 `while (state % 3 != id) wait();`，打印后 `state++`、`notifyAll()`。② `ReentrantLock` + 三个 `Condition`：线程 A 等 `condA`，打印后 `condB.signal()`，形成 A→B→C→A 的唤醒链。③ `Semaphore`：A、B、C 各一个信号量，A 初始为 1、其余为 0，每个线程 `acquire` 自己的信号量、打印、`release` 下一个的。要写可运行代码，注意三点：`wait` 必须放在 `while` 里防虚假唤醒、共享状态要用 `volatile` 或锁保护、输出后要 `flush` 或统一由锁保护避免交错。常见编译/逻辑错误是 `wait()` 用在没有持有锁的地方（抛 `IllegalMonitorStateException`）、条件判断写成 `if`、以及 `notifyAll` 写成 `notify` 导致唤醒错线程。
