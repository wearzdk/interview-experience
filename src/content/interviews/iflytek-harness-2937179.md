### 《参考解析》

**哪些指令进沙箱**：不是按命令文本判断，而是按执行路径判断——模型发起的工具调用中所有会产生副作用的动作都进沙箱，包括 shell 命令、文件读写、网络请求、包安装与子进程。准入层先做命令解析（拆分管道与重定向，识别解释器嵌套），再按路径、域名、可执行文件三类白名单过滤，未命中的直接拒绝并回传结构化原因，而不是交给模型猜。

**Linux 与 macOS 的权限语义**：能对齐的是「能力」层面：文件读写范围、网络出站、子进程创建、资源上限。无法完全抹平的是机制层面：Linux 用 namespace 做视图隔离、seccomp 做系统调用过滤、cgroup 做资源限额；macOS 用 Seatbelt 的 profile 描述操作级策略，没有 cgroup 的对应物，系统调用过滤粒度也不同。因此框架的策略模型应建立在能力抽象上，两端的实现各自适配，而不是试图让两端行为逐字节一致。

**拒绝日志关联到工具调用**：每次工具调用生成唯一标识，通过环境变量、进程组或 cgroup 名注入到被执行进程，同时在调用开始时记录 pid 与时间窗；沙箱日志按时间与 pid 采集后，用标识回填到调用记录。macOS 上 Seatbelt 的拒绝日志可由 log stream 实时读取，解析出进程与路径后按 pid 与时间窗匹配；Linux 上则从审计子系统或 eBPF 事件取 pid。

**eBPF 关联上层标识**：在 sys_enter 或相关 tracepoint 上取 pid/tgid，再沿进程树向上找到工具调用创建的那个根进程，映射到调用标识；更稳的做法是把标识写入进程环境变量或 cgroup 路径，eBPF 侧读取 cgroup id 即可直接关联，不依赖进程树推断。跨容器时用 cgroup id 比 pid 可靠。

**避免影响宿主与状态恢复**：工作区用写时复制或 overlay 挂载，命令只在挂载层写入，结束后丢弃；资源侧限制 CPU、内存、进程数与磁盘配额，超限即杀；网络侧强制走代理。需要保留产物时只把白名单目录同步出来。快照适合「执行前可回滚」的场景，但成本高，通常只对高风险操作或长任务开启。

**同时表达读目录与访问网络**：策略要能按「资源 × 动作」组合，文件规则写成路径前缀加读写位，网络规则写成域名或 CIDR 加方法，两条规则同时生效取交集而非覆盖；实现上可以把策略编译成沙箱 profile，文件部分交给挂载与权限位，网络部分交给代理白名单，两者独立生效。

**AI 编程时代语言基础**：仍然重要，但重心从默写 API 转向判断力——能读懂生成代码的复杂度、内存与并发语义，能在编译错误与运行时异常里定位根因。语言基础差的人无法审查 AI 产出，也无法在模型给出错误方案时识别出来。

**隐性知识**：写进仓库里模型能读到的地方：项目说明、目录级规则文件、示例代码、类型定义与测试。一次性的口头约定要落成文档或检查项，否则下一轮对话又会丢。对无法文档化的部分，用「先让模型复述约束再动手」的方式校验它是否理解。

**是否全部审查**：按风险分级。核心链路、并发与资源管理、鉴权与数据边界必须逐行看；样板代码与纯展示层可以靠类型检查、测试与静态分析兜底。责任不因代码由 AI 生成而转移，提交者仍是责任人。

**线上问题定位**：先看指标与日志确定影响面与时间点，再看链路追踪定位到具体环节，最后用最小复现验证假设。AI 适合做日志检索、假设生成与脚本编写，但结论必须由数据验证，不能把模型的推测当成根因。

**Agent 运行链路的安全风险**：提示注入导致越权工具调用、工具参数被构造为命令注入、凭据被读取后外带、沙箱逃逸、资源耗尽、以及多 Agent 之间传递不可信内容。实际限制手段是工具最小权限、路径与域名白名单、危险操作二次确认、输出脱敏与完整审计。

**外部 Skill 的供应链风险**：Skill 本质是可执行的提示与脚本组合，来源不可信时等同于引入任意代码。需要来源审核与签名、声明所需权限、在沙箱内运行、限制其可访问的工具与数据，并在升级时重新审核，而不是一次信任长期有效。
