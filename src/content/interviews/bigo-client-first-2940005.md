### 《参考解析》

**AIGC 任务的客户端链路**：素材上传（分片 + 断点续传 + 秒传）→ 创建生成任务（带幂等键）→ 轮询或长连接接收进度 → 完成后拉取结果并缓存。客户端要处理：上传中断重试、任务超时、重复提交、App 被杀后的恢复（把任务 ID 持久化，下次进入页面继续查）。服务端边界：素材校验与转码、任务调度、模型推理、结果存储由服务端负责；客户端负责采集、压缩、上传、状态展示与本地缓存。

**怎么确认完成**：上传侧用分片 + 服务端返回已接收的分片位图，全部到齐后调「合并」接口；生成侧用任务状态机（排队/生成中/成功/失败），客户端轮询带退避（避免打爆），或用 WebSocket/SSE 推送。关键是要有「任务 ID + 版本号」，避免用户重复点生成产生多个任务。

**JVM 运行时内存区域**：程序计数器（当前字节码行号，线程私有）、虚拟机栈（栈帧：局部变量表、操作数栈、动态链接、返回地址，线程私有）、本地方法栈（native 方法）、堆（对象实例与数组，线程共享，GC 主战场）、方法区（类元信息、常量池、静态变量，JDK 8 后是元空间，用本地内存）。另有直接内存（NIO 的 `DirectByteBuffer`），不受堆大小限制但受物理内存限制。

**StackOverflowError 与 OOM**：栈溢出发生在栈深度超过限制，通常是无限递归或方法调用链过深，栈帧太大也会（大数组作为局部变量）。堆 OOM 是对象持续增长且 GC 回收不掉（内存泄漏、一次加载过大文件、缓存无上限），报 `Java heap space`；元空间 OOM 是类加载过多（动态生成类、热部署），报 `Metaspace`；还有 `GC overhead limit exceeded`（GC 花大量时间却回收很少）。

**HashMap 与 TreeMap**：HashMap 基于哈希表，无序，平均 O(1)，允许一个 null key；TreeMap 基于红黑树，按 key 自然序或 Comparator 排序，O(log n)，支持 `firstKey`、`floorKey`、范围查询 `subMap` 等有序操作，不允许 null key（要比较）。需要排序或范围查询用 TreeMap，否则用 HashMap。哈希冲突：HashMap 用链地址法，链表长度到 8 且容量 ≥ 64 转红黑树，退化到 6 转回链表；好的哈希函数（扰动函数让高位参与运算）能减少冲突。

**进程与线程**：进程是资源分配的单位（独立地址空间、文件描述符），线程是 CPU 调度的单位，同进程内线程共享堆与方法区、各自有栈与程序计数器。线程切换开销小于进程，但共享状态带来同步问题。共享计数器加一保证原子性：`AtomicInteger`（CAS）、`synchronized` 或 `ReentrantLock`、`LongAdder`（高并发下分段累加，吞吐更高）。

**线程池与 1000 并发请求**：核心参数七个（核心线程数、最大线程数、空闲存活、时间单位、队列、线程工厂、拒绝策略）。1000 个并发网络请求要看是「同时到达」还是「持续 QPS」：IO 密集型可以适当放大线程数（但不能无限，受内存与下游承载限制），更好的做法是异步非阻塞（NIO/协程）+ 有界队列 + 限流；队列满时用 CallerRuns 或降级，不能默默丢弃。还要注意每个请求的超时、重试与熔断，避免线程池被慢请求占满。

**HTTPS 请求的完整过程**：DNS 解析 → TCP 三次握手 → TLS 握手（ClientHello 带支持的版本与套件、ServerHello 与证书、客户端校验证书链与域名、密钥交换、生成会话密钥）→ 发送加密的 HTTP 请求 → 服务端处理并返回 → 连接复用或关闭。中间还有可能经过 CDN、负载均衡、网关。客户端要能说出证书校验（CA、有效期、域名匹配）与 TLS 1.3 的简化（1-RTT、0-RTT）。

**列表头像错位**：RecyclerView 复用 ViewHolder，异步加载图片回调回来时，ViewHolder 已经被绑定到另一个 item，旧请求把图片设置到了新位置上。解决：给每个 ViewHolder 或请求打上 tag（图片 URL 或 item id），回调时比对当前绑定的 tag，不一致就丢弃；用图片库（Glide/Coil）自带的 `into(imageView)` 与生命周期绑定，它会自动取消；在 `onViewRecycled` 里取消请求；占位图与淡入避免闪烁。

**AI Coding 怎么验证**：生成后先编译、跑单测、跑 lint；对业务逻辑写针对性的用例（边界、异常、并发）；用 `git diff` 人工审关键路径；对不熟悉的 API 查官方文档；在测试环境跑一遍真实流程。Agent 产出的多文件改动要分步提交，保证可回滚。

**链表有环与环长**：快慢指针判断有环（相遇即有环），求环长时从相遇点继续走，再次回到相遇点所走的步数就是环长；求入环点则把一个指针放回头节点，两指针同速前进，相遇处即入口。空间 O(1)、时间 O(n)。

**合并有序区间**：先按起点排序（题目已保证有序），遍历时维护当前区间，若下一个区间的起点 ≤ 当前区间的终点则合并（终点取两者最大），否则把当前区间加入结果并换新。注意边界：空数组、完全包含、相邻但不重叠（`[1,2]` 与 `[3,4]` 不合并）、起点相同。
