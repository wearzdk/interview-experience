### 《面试题目》

1. 请做一下自我介绍。
2. 讲一讲你的实习和项目，在其中具体担任了哪些工作？
3. 项目中遇到过哪些问题？你是怎么解决的？

---

### 《参考解析》

**自我介绍按五段组织，控制在 1 到 2 分钟**

顺序是：**个人背景**（学校、专业、学历、研究方向）→ **项目经历**（参与过哪些相关项目、主要研究什么问题）→ **核心成果**（论文、专利、竞赛、项目指标或其他可验证的结果）→ **个人工作**（自己具体负责哪些模块、解决了什么问题）→ **岗位匹配**（为什么希望做嵌入式软件这类岗位）。

嵌入式方向要落在具体坐标上：用过的 MCU 或 SoC 型号、RTOS 或裸机方案、接触过的总线与协议（UART、SPI、I2C、CAN、以太网）、工具链与调试手段（Keil、IAR、GCC、JTAG/仿真器、逻辑分析仪）、项目规模与周期。时间有限，突出与岗位最相关的那一段，其余一句带过就好，不要照着简历念。

**讲项目：先分清「团队完成了什么」和「我做了什么」**

顺序建议：项目要解决什么实际问题 → 研究或交付目标 → 自己的具体任务 → 技术路线（工具、方法、实验手段）→ 最终结果与指标。面试官在这一题上追得最紧的就是归属：**哪一部分是你亲手做的、做到什么程度、别人做了什么**。稳妥的表述方式是「整体方案是团队定的，我负责其中的驱动层与通信协议部分，具体做了 A 和 B，指标从 X 提到 Y」，把自己那一段讲到接口、数据结构、异常分支的粒度；同时准备好每一项指标的测法（在什么条件下测、样本多少、对比基线是什么），说不清测法的数字反而会减分。

**讲问题解决：闭环比结论重要**

推荐的结构是**问题现象 → 原因分析（先给假设）→ 验证方法 → 解决方案 → 结果对比**。最容易失分的是「我查阅资料后修改了参数，最后解决了问题」这种只有结论的说法——面试官要的是你有没有建立假设、设计实验、用数据把假设验掉或证实。嵌入式岗位可以按故障类型准备几个真实案例：

- **通信异常、数据丢失**：先看物理层（示波器或逻辑分析仪看电平与时序、波特率与时钟配置是否匹配），再看协议层（帧格式、CRC 校验、NACK 与重传），最后查软件层——中断里做了耗时操作、环形缓冲区溢出、DMA 与 CPU 同时访问、任务优先级导致的处理不及时，都是常见根因。
- **传感器读数不稳定**：先排除硬件（供电与参考电压、走线干扰、接地），再上滤波（硬件 RC、软件滑动平均或卡尔曼），同时核对初始化配置、采样时序与标定参数是否与被测物理量匹配。
- **任务调度或资源竞争**：检查 RTOS 任务优先级与栈大小、临界区保护、互斥量与信号量的使用方式，留意优先级反转与死锁，以及高优先级任务长期占住 CPU 造成低优先级任务饥饿。
- **控制效果不符合预期**：采样周期的稳定性往往是第一嫌疑（抖动会直接毁掉控制效果），其次才是参数整定与模型误差，用阶跃响应或开环实验把执行机构与算法两部分的问题分开。
- **偶发故障**：重点在留证与复现——加结构化日志与看门狗计数、长时间压测、做温度与电压的边界条件测试，按「减少变量 → 稳定复现 → 收敛范围」的顺序推进，而不是靠猜。

**三面通常在考什么**

技术面走到第三轮，专业知识已经验过一遍，这一轮更多看匹配度、稳定性和表达：能不能把复杂项目讲清楚、被追问到不会的地方怎么反应（诚实说出边界再给相邻思路，比硬答好）、为什么选这家公司这个岗位、能不能接受工作地点与节奏。准备时把项目里每一个数字与结论复盘到能自证，再想清楚两三句「为什么来」的说法，基本就够用了。
