### 《面试题目》

1. 简要自我介绍，重点介绍 AI Agent 相关项目经历与落地成果
2. 介绍个人 Agent 项目中的真实代码产出比例，以及 AI 辅助编码的实际使用占比
3. 说明项目中 Agent 运行基座（Harness）的技术选型，是自研架构还是基于开源框架改造
4. 完整阐述从用户需求输入，到 Agent 生成代码、自测、最终合入 PR 的全链路工作流程
5. 项目中需求拆解、任务规划、内容审查模块为自研实现还是依托现有技能组件调度
6. 如何系统性校验 Agent 输出代码的可用性、合规性与需求匹配度，有哪些自动化验收手段
7. 若给定 UI 设计稿与需求文档，如何设计自动化方案，让 Agent 自主校验页面还原度与交互正确性
8. 讲解 RAG 体系中如何量化判断召回内容相关性；多路检索结果如何做融合、重排与择优输出
9. 手撕：二叉树路径总和题型，判断是否存在根到叶子的路径满足目标和条件
10. 手撕：最长递增子序列，要求输出序列长度 + 完整具体序列，并说明从 O(n²) 优化至 O(n log n) 的核心思路
11. 讲解 Computer Use 技术的底层实现原理、页面元素定位逻辑，并对比其与 Playwright 自动化方案的差异
12. 结合业务场景，设计一套 AI 提效方案，用于团队加速需求开发、自动查错与 bug 修复，说明整体架构与落地思路

### 《参考解析》

**「真实代码产出比例」怎么答**：这类问题在测你是否诚实以及是否理解 AI 编程的边界。合理的答法是给分层数据：脚手架与样板代码（接口定义、CRUD、配置）AI 占比很高，业务核心逻辑与边界处理以人为主，测试用例由 AI 起草再人工补断言。同时说明衡量方式（比如按 diff 行数、按文件数、按功能点），并主动指出「行数占比不衡量价值」——真正省下的是检索与样板时间，风险在于引入看似合理但边界错误的实现。

**校验 Agent 输出的自动化手段**：按成本从低到高排序——静态检查（lint、typecheck、格式化）；单元与集成测试（含针对 AI 常犯错位置的定向用例）；接口契约与 schema 校验；端到端脚本（关键链路可复现）；diff 范围校验（超出预定文件即中断）；以及必要的回归评测集。合规性校验要单独一层：敏感信息与密钥检测、依赖白名单、许可证扫描、以及权限与数据访问边界的静态审查。

**UI 还原度自动校验怎么做**：可行方案是「截图比对 + 结构断言」双轨。先用 Playwright 在固定视口与设备像素比下截取目标页面，与设计稿对齐尺寸后做像素级 / 结构相似度比较（SSIM 或分块差异阈值），差异区域高亮出来；同时对关键元素做 DOM 断言（位置、尺寸、间距、颜色、字体）与交互断言（点击、hover、键盘可达性、加载与错误态）。要注意设计稿与实现的差异往往在字体渲染、间距单位、响应式断点上，所以阈值要按区块设定并保留人工复核环节，不能让「像素差异为 0」成为目标。

**RAG 召回相关性的量化与融合**：召回相关性可量化的方式有：人工标注的 query-doc 相关性分级算 nDCG / MAP / MRR；无标注时用「答案是否被引用」「生成答案与检索片段的语义一致度」做代理指标；线上用点击、停留、追问率与转人工率做反馈。多路检索的融合常见 RRF（按名次倒数求和，不需要分数归一化）或加权求和；重排用交叉编码器（query 与文档一起编码，精度高、成本高，所以只对 top-N 做）；择优输出要带上引用与置信度，低置信度时拒答或追问。答到这里可以补一句工程现实：融合权重与 top-N 都要用评测集调，不是拍脑袋。

**Computer Use 与 Playwright 的差异**：Computer Use 让模型看截图（或多模态输入）并输出坐标级鼠标键盘动作，底层是把屏幕作为观测、把动作作为输出，靠视觉理解定位元素——不依赖 DOM，所以能操作任意界面（含 Canvas、远程桌面、老系统），但慢、贵、且不确定性高。Playwright 依赖选择器与结构化 DOM，可编程、可断言、可并行、可复现，适合回归测试；一旦页面结构变化或元素在 Canvas 里就失效。实践结论是：需要确定性与速度的用 Playwright，需要应对未知界面或视觉判断的用 Computer Use，两者可以组合（脚本负责主链路，视觉模型负责校验还原度）。

**手撕两题的要点**：二叉树路径总和用递归（自顶向下减目标和，到叶子时判断是否为 0）或回溯（维护当前路径与累加和），注意「叶子」的定义必须是左右孩子都为空，空树与负值也要覆盖，如果要返回所有路径则需要回溯并在加入结果时做深拷贝。最长递增子序列的 O(n log n) 做法是维护一个「长度为 i 的递增子序列的最小结尾值」数组 `tails`（严格递增，用二分找第一个大于等于当前值的位置替换，等于就跳过以处理严格递增），长度即为答案；要输出完整序列需要额外记录每个元素的前驱下标（`prev[i]`），最后从取得最大长度的位置回溯构造。面试时先说 O(n²) 的 DP 定义 `dp[i]` = 以 i 结尾的 LIS 长度，再说明如何用二分把状态压缩到 O(n log n)，最后补前后驱数组的细节。

**这一轮的特点**：这是一场「AI Agent 岗位的实战面」——题目几乎都是「你怎么保证 AI 产出的东西是对的」，考察的是工程约束能力而不是模型知识。准备方法很直接：真的用 AI 完整做过一个从需求到合并的项目，把每一步的失败与补救记下来。
