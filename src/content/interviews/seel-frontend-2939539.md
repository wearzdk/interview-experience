### 《参考解析》

**两个 Effect 的时序**：React 的提交流程是 render 阶段（可中断，计算变更）→ commit 阶段（同步应用 DOM 变更）→ 执行 `useLayoutEffect` 的清理与回调（同步，在浏览器绘制之前）→ 浏览器绘制 → 执行 `useEffect` 的回调（异步，通常在下一帧之后）。因此 `useLayoutEffect` 先于 `useEffect`，也先于用户看到新画面。需要读取布局（`getBoundingClientRect`、`scrollHeight`）并同步修正视觉的逻辑放 `useLayoutEffect`，避免用户看到中间态闪烁；数据请求、订阅、日志上报放 `useEffect`。

**为什么会卡**：`useLayoutEffect` 在绘制前同步执行，回调里做重计算、强制同步布局（读布局后写样式再读）或大量 DOM 操作，会推迟绘制，表现为掉帧或白屏。定位方式是用 Performance 面板录制交互，看 commit 之后、paint 之前的长任务，火焰图里会直接显示组件的 layout effect 回调；也可以用 `PerformanceObserver` 观察长任务。它是同步执行的，不是异步。

**宏任务与微任务**：一次事件循环取一个宏任务执行，结束后清空微任务队列，再进入渲染与下一个宏任务。宏任务包括整段脚本、`setTimeout` / `setInterval`、`MessageChannel`、I/O 与 UI 事件；微任务包括 `Promise.then`、`queueMicrotask`、`MutationObserver` 与 `await` 之后的续体。`Promise.then` 先于定时器，因为微任务在当前宏任务结束时立即清空，而定时器要等下一轮且受最小延迟约束。「运行」一段代码指的是同步执行其中的语句并注册回调，回调和微任务要等当前同步代码执行完才会被处理。

**AI 工具的使用**：编辑器层面 Cursor 的优势是行内补全与代码库上下文，Claude Code 一类终端代理适合跨文件改造与批量重构，VS Code 加插件更贴近原始环境。模型选择按任务分：补全与改写用小而快的模型，跨文件设计与疑难排查用推理更强的模型。关注 token 成本是必要的，长上下文会显著抬高单价，做法是缩小上下文范围、复用缓存、把重复任务脚本化。需求描述要给出背景、约束、验收标准与不能改动的边界，必要时附上现有代码与报错原文；「skill」这类自定义能力要有自测用例、目录与权限边界、禁止改动的文件清单，并用脚本或钩子强制。

**行为题的回答**：先确认紧急程度与验收标准（是否当天必须上线、谁验收、能否拆成两步），再读老代码与调用方评估影响面，选择最小改动并保留回滚路径；没有 PRD 就把字段、校验、交互、异常态与埋点列成清单找需求方确认，交付后补文档。这个题考的是在信息不全时如何收敛范围，而不是埋头写完。

**HR 类问题**：频繁换实习要给出选择逻辑与收获，而不是抱怨前公司；用户视角与产品视角的冲突本质是短期体验与长期目标的取舍，给一个具体例子说明如何平衡；从大数据转前端要讲清触发点（某次做可视化或工具的经历）与自学的证据（博客、项目）；对业务的理解要具体到产品解决的问题与用户是谁；成长预期分「公司能给的条件」（导师、代码评审、真实项目、技术分享）与「自己要付出的努力」（系统补基础、复盘、主动承担），两边各给一条可执行的计划。
