### 《核心观点》

1. 被裁两次、每次 gap 都要四五个月，问题往往不在能力差，而在于把时间放到了错误的地方——工作年限涨了，对候选人的要求也跟着涨，面试才是职业发展的主线。
2. 给面试准备留出固定位置：把「记住更多面试题」当成一件长期要做的事，像收藏古董一样一点点攒起来。
3. 建议每个人都建一份自己的 GitHub 项目，专门用来收集自己的面试题，并定时复习，复习节奏可以借用遗忘曲线。
4. 工作中遇到任何东西，都要顺手想一下它能不能变成一道面试题；做一个项目时，也要想象它会不会被拿来出题。
5. 只在八股里背过、没真做过的题，要在公司主动创造实践机会，把它做一遍，答案才立得住。
6. 面试题的深度（一道题能答多深）和广度（会几道题）本身就是一种复利，薪资的提升也来自这里。

### 《参考解析》

**为什么说面试是职业发展的主线**：随着工作年限增加，公司对候选人的期望会从「会写业务」升级为「能讲清原理、能做方案取舍、能扛住深度追问」。日常业务交付很少主动锻炼这三样东西，如果完全不准备，gap 期就变成纯粹的时间消耗，面试连续失败又进一步拉长空窗。把面试准备常态化，等于把职业发展的主动权握在自己手里，跳槽涨薪的空间也来自这里。

**建一份自己的面试题库仓库**：在 GitHub 上开一个仓库，按技术域分目录（例如 JavaScript、浏览器与性能、工程化、网络、算法），每道题记三部分：题目原文、自己当时的回答、补完之后的标准答案与追问。用 Markdown 写，方便全文搜索；有新理解就改自己写的那部分，别只收藏别人的文章链接——收藏夹不会在面试里替你回忆，能自己复述出来的版本才会。

**用遗忘曲线安排复习**：新录入的题在第 1 天、第 2 天、第 4 天、第 7 天、第 15 天各复习一次，重点是「不看答案先讲一遍」。复习时只标三档：讲得清楚、提醒后能讲清、完全讲不出。第三档单独拉一个清单，下次面试前优先过。每周固定一个时间段集中复习，比碎片时间随机翻看有效得多。

**在工作中主动取材**：做 Webpack 配置时，就把 Webpack 场景题收集起来，顺带看关键插件的源码原理，再对比 Webpack 与 Vite 在开发态、构建产物、HMR、依赖预构建上的差别；做性能优化时，把 FCP、LCP、CLS、INP、TTFB 这些指标的定义、采集方式、优化手段各记一道题，最好能给出优化前后的真实数据。做完一件事就沉淀一道题，比事后集中背要牢固。

**背过但没做过的题要创造实践机会**：有些题只在八股里见过，答起来心虚。解决办法是在公司主动找机会把它做一遍，比如把构建耗时统计接入 CI、给页面加一套性能埋点、把接口缓存策略改成可配置。实践过之后再答，细节和边界条件都是自己的。深度和广度一起攒，时间长了就是别人跨不过去的差距。
