### 《参考解析》

**volatile 只保证「每次都去内存读」，不保证原子性**。它抑制编译器把变量缓存进寄存器、或删掉看起来没用的读写，适合中断与任务共享的标志、DMA 更新的状态、寄存器映射。但 `cnt++` 是读-改-写三步，中断插在中间就会丢更新；要原子得关中断、关调度，或用 LDREX/STREX 与 `__atomic` 内建。volatile 也不带内存屏障，编译器和 CPU 仍可重排，跨核共享必须自己补 barrier，否则「读到了标志、数据还是旧的」这类问题会在优化等级变化后突然出现。

**结构体内存对齐是填空而不是压缩**。每个成员的偏移必须是其对齐值的整数倍，结构体总大小按最大成员对齐向上取整。char、int、char 在四字节对齐下是 1+3 填充+4+1+3 填充 = 12，改成 char、char、int 就是 1+1+2+4 = 8。面试官让现场重排，是看你知道填充从哪来、能不能靠调序省内存。嵌入式里还要留意 `#pragma pack` 的代价：省了空间，却可能换来非对齐访问，在 Cortex-M0 这类核上直接 HardFault。

**环形缓冲区的判空判满有两套写法**。留一格空位时，`head == tail` 为空、`(head+1) % N == tail` 为满，代价是浪费一个槽；用单调递增的读写计数、靠差值判断，则能吃完容量，但要处理计数回绕。单写单读场景不需要锁：写者只动 head、读者只动 tail，各自对另一个位置只读，配 acquire/release 语义即可；多写者才需要临界区或原子 CAS。DMA 写入时还要把「有效长度」放在最后更新，并保证 cache 已清，否则读者可能看到半条数据。

**容量要按最坏情况算，不能按「没出过事」算**。公式是生产速率乘消费者最长阻塞时间，再加一次突发量：10 kHz 采样、每次 4 字节、消费者可能被压 20 ms，就需要 800 字节，然后留余量。溢出策略必须显式选：丢新保旧适合状态量，覆盖最旧适合实时流；同时加溢出计数与水位告警。没有计数，「从来没丢过」通常只是没测过，而不是真的没丢。

**延迟要看分布，验证修复也不能靠「几天没复现」**。在采集完成和处理完成各打一个时间戳（DWT 周期计数器或硬件定时器），统计 P99 与最大值，长尾才对应丢数据的时刻，平均值会把问题掩盖掉。验证有效性要么构造能稳定复现的压力场景——拉高采样率、注入高优先级负载、缩小缓冲，要么给出统计口径：跑了多少帧、按当前速率还有多大概率复现。只跑几天属于采样不足，不构成结论。
