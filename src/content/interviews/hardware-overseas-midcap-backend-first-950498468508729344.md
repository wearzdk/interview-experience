### 《面试题目》

1. 自我介绍。
2. 用英文自我介绍，然后用英文介绍你的项目。
3. 简历上写的第一个需求，核心是要解决了什么问题？
4. 你在字节的实习中，研发加测试是在同一套平台用 AI 一键开发吗？还是说只是代码在 git 上用 AI 一键开发？是怎样的协作模式？
5. 组内有没有用 workflow 和 skills，还是 vibecoding？
6. 你平常是怎么开发代码的？
7. 简历上写的第二个需求，核心是要解决了什么问题？
8. 简历上写的第三个需求，核心是要解决了什么问题？
9. 你觉得做完这些需求，你的相关技术有没有得到沉淀？
10. 如果给你一个老项目，这个项目他做得很差，需要你重新把它重构，怎么去梳理它的模块划分？你觉得你需要做些什么，该如何入手？

### 《参考解析》

**英文自我介绍与项目介绍**：不用追求口音，追求「结构清晰、术语准确」。准备一个 60 秒版本：姓名与背景 → 做过的方向 → 一个项目的「问题—方案—结果」→ 为什么这家公司。项目里提前查好专有名词（throughput、latency、idempotency、message queue、CI/CD），卡住时用简单句绕过去，不要中途切回中文。帖主遇到的面试官说「研发大部分都是这个水平，学一下专有名词没啥大问题」，说明这类岗位的英文要求是「能沟通」而不是「流利」。

**三个需求各解决了什么问题**：面试官连问三遍同一句式，是在检查你是否理解「需求背后的业务目标」，而不是只会写代码。每个需求用一句话说清「谁的问题、不解决会怎样、你的方案带来什么变化」，再补一句你的具体贡献。三个需求最好能体现能力递进（从执行到设计、从单点到链路）。

**AI 协作模式**：区分三种东西——「AI 辅助编码」（IDE 补全、对话生成）、「AI 参与研发流程」（生成用例、review、写文档、分析日志）、「AI 原生的工作流」（workflow/skills 编排，模型按固定流程执行多步任务）。回答时讲清楚你们团队实际是哪一种，以及质量怎么保证（谁 review、有没有测试门禁、灰度怎么做）。不要为了显得先进而夸大，面试官会追问细节。

**平常怎么开发**：给一个真实的工作流：读需求与现有代码 → 写设计或伪代码 → 小步实现 → 自测（单测/本地跑）→ 提交 review → 联调 → 灰度 → 监控。AI 在哪些环节介入、你如何验证它的输出。这题没有标准答案，要的是「有章法」。

**技术沉淀**：不要说「学到了很多」。给具体的沉淀物：抽出的公共组件、写的文档/规范、沉淀的排查手册、可复用的脚手架、以及在团队内的分享。能说出「后来别人也在用」最好。

**老项目重构怎么入手**：先「摸清现状」而不是先改代码：读 README 与文档、跑起来、看依赖关系与调用链、看监控与日志找热点与故障、看测试覆盖率、访谈维护者与用户；然后「划定边界」：按业务能力或数据边界划分模块，找出耦合点与共享状态；再「定策略」：绞杀者模式（新功能新写法、旧功能逐步替换）、先加测试再重构、小步提交、灰度与回滚方案；最后「排序」：先做风险低收益高的（补测试、拆依赖、统一日志），再做核心模块。要强调「重构不是重写」，以及「没有测试就不重构」。

**硬件出海 + 金融支付的特殊性**：这类公司通常有海外合规、多币种、支付通道对接、设备与云端的协同。面试前了解目标市场的支付习惯（东南亚的电子钱包、欧美的卡组织）、合规要求（PCI DSS、数据本地化），反问时能问出深度。
