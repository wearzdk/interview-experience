### 《参考解析》

**堆和栈的区别，static 有什么用**

栈由编译器自动管理：函数调用时压栈帧、返回即回收，x86 上自高地址向低地址生长，空间很小（STM32F4 的启动文件里 `_Min_Stack_Size` 常见 0x400~0x2000），分配只是移动 SP 指针，速度极快，但递归太深或在大数组放栈上会栈溢出直接进 HardFault。堆由 `malloc` 管理，从 `_end` 到栈顶之间的空闲区（`_Min_Heap_Size`）按需分配，速度慢、会产生碎片，裸机项目里一般不推荐随意 malloc。C 语言里 static 有三个作用：修饰局部变量时改变存储期（放到 `.data`/`.bss`，函数退出不销毁）；修饰全局变量或函数时改变链接属性为内部链接，仅本文件可见，避免多文件重名冲突；在 C++ 里修饰类成员表示属于类而非对象。两个常被追问的点：未初始化的全局/静态变量由启动代码清零，而局部变量不初始化就是栈上的残留值；中断和多任务共享的全局变量必须加 `volatile`（防编译器把它优化进寄存器）并用临界区保护，否则会出现「读到的值永远不变」这类玄学 bug。

**野指针与 malloc/free 的防法**

野指针有三个来源：定义时未初始化、free/delete 之后没置 NULL 的悬垂指针、返回了指向栈上局部变量的地址。防法是定义即初始化（`int *p = NULL;`）、free 后立刻置 NULL、不返回局部数组地址、使用前判空。malloc/free 场景的坑更集中：free 后继续用、重复 free（会破坏堆块链表头，往往是延迟很久才崩）、malloc 不判 NULL、错误分支提前 return 造成泄漏、越界写踩坏相邻堆块的头部。嵌入式里的实践是优先静态分配或内存池（固定块大小，O(1) 分配且天然无碎片）；必须动态分配时坚持「谁分配谁释放」并集中管理，另外可以开 MPU 让越界访问立即触发 HardFault，而不是静默改写别的变量。

**STM32F4 资源与 SPI/I2C/MQTT 组网**

STM32F4 系列（以 F407 为例）主频 168 MHz，SRAM 是 192 KB（112 KB + 16 KB + 64 KB CCM），Flash 512 KB~1 MB，带 FPU 和 DSP 指令；CCM RAM 不能给 DMA 用，这是分配缓冲区时的常见坑。SPI 四线（SCK/MOSI/MISO/CS）全双工、无地址靠片选，速率可达 fPCLK/2（约 42 MHz），适合 Flash、屏幕、高速 ADC，注意 CPOL/CPHA 四种模式和片选时序。I2C 两线（SCL/SDA）开漏加外部上拉，7 位地址支持多主多从，标准 100 kHz / 快速 400 kHz / 快速+ 1 MHz，适合传感器和 EEPROM；坑是从机拉低 SDA 不放会导致总线死锁，需要手动发 9 个时钟脉冲恢复。MQTT 是应用层发布订阅协议、基于 TCP，靠 broker 转发，QoS 0/1/2 三档，带遗嘱消息和 keepalive。多组数据上网的设计思路：按数据种类拆 topic（状态 / 遥测 / 告警），上报走「本地环形缓冲 + 定时或阈值触发打包」，断网时缓存补传并用序号去重，报文太大就换 CBOR 或自定义二进制；网络栈用 lwIP 加 4G 模组（AT 指令或 PPP），重连做指数退避，绝不在中断里做网络发送。

**进程线程、锁与 FreeRTOS 优先级反转**

进程有独立地址空间，切换要换页表，通信走管道 / 共享内存 / 消息队列 / socket；线程共享地址空间、只独立栈和寄存器，切换便宜，但共享数据必须加锁。常用锁有互斥量、计数信号量（可用于中断与任务同步）、自旋锁（短临界区、多核）、读写锁。生产者-消费者用「计数信号量 + 互斥量」组合：一个信号量计空位、一个计满位，mutex 只保护缓冲区本身的读写，不要用一把锁把整个 push/pop 串起来。FreeRTOS 里 `xTaskCreate` 的 `usStackDepth` 单位是字而不是字节（32 位机要 ×4），给太小就是随机 HardFault，用 `uxTaskGetStackHighWaterMark()` 看水位来定尺寸。优先级反转指高优先级任务等低优先级任务持有的锁，而低优先级又被中优先级任务抢占，导致高优先级被间接阻塞很久；解法是让互斥量支持优先级继承（FreeRTOS 里必须用 `xSemaphoreCreateMutex` 创建互斥量，二值信号量没有继承机制，不要拿它当锁），或者用优先级天花板协议。状态机的实时性靠「事件驱动 + 每个状态执行时间有上界」来保证，别在状态函数里做阻塞式等待。

**项目介绍与「为什么选我们」**

项目介绍按「目标指标 → 难点 → 突破方式 → 收获」四段讲，先把量化指标摆出来（采样周期、控制精度、通信成功率、成本下降幅度），再讲你个人负责的那一块，避免把团队成果说成自己的。回答「你对我们了解多少」时不要背公司简介，挑一个和自己项目能接上的点讲：阳光电源主业是光伏逆变器与储能系统，嵌入式岗位的核心诉求是电力电子控制、实时性与可靠性（并网标准、故障保护、长期无人值守运行），把自己的 RTOS、通信、驱动经验和这些诉求对齐，再说明为什么选合肥或南京（家在附近、有产业配套、愿意长期发展）。这类问题的评分点是「匹配度真实」而不是「夸得多」。
