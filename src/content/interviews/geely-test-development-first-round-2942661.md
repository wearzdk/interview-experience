### 《参考解析》

**「Linux 命令怎么执行」要答到 fork / exec 这一层**：shell 先读取命令行、做词法拆分与变量展开、处理管道与重定向；如果是内建命令（cd、echo、export）就在 shell 进程内直接执行，否则按 PATH 逐个目录查找可执行文件。找到后 shell 调用 fork 创建子进程，子进程调用 execve 把可执行文件加载进自己的地址空间——内核解析 ELF 头、映射代码段与数据段、设置栈与入口地址，然后开始执行；父进程用 wait 等待子进程结束并取回退出码。管道则是先 pipe 建管道，再 fork 两次把标准输入输出接上。可以用 strace 观察 execve 这一跳来验证。

**Python 与 C 的区别按「执行方式、类型系统、内存、并发、适用场景」五点讲**：C 是编译成机器码后直接执行，静态类型、手动管理内存、无运行时 GC，性能接近硬件，适合操作系统、嵌入式、驱动与对时延敏感的场景；Python 是解释执行（先编译成字节码再由解释器执行），动态类型、引用计数加循环 GC，开发效率高、生态丰富，适合脚本、测试框架、数据处理与胶水层。并发上 C 可以直接用线程与多进程，Python 有 GIL，CPU 密集型任务要靠多进程或把热点下沉到 C 扩展。测试岗常见组合是 Python 写框架与用例、C 写被测模块或性能工具。

**为什么选汽车行业测试，别答成「互联网卷不过」**：给正向理由——车载测试是软硬结合，涉及域控制器、CAN / 以太网通信、HIL 台架与实车路试，测试对象从纯软件扩展到整车功能安全与实时性，经验可积累；再说清个人匹配点（做过嵌入式或通信相关项目、对车辆功能感兴趣）。同时要能说出汽车测试与互联网测试的差别：迭代节奏、验证手段、问题定位链路、对安全和确定性的要求，否则会显得只是随便投的。

**「为什么没留实习公司」与「冲突怎么解决」是一类题**：前者给客观原因（岗位方向、城市、业务调整），不贬低前东家；后者按「先确认事实、再对齐标准、最后留记录」回答——先复现问题，确认是需求歧义还是实现缺陷，用日志、用例、需求文档把分歧变成可讨论的证据，必要时拉产品与开发三方评审，结论写进缺陷单或评审记录。测试的价值在于把主观争论转成可验证的判断。

**「想做哪个细分类别」要提前选一个并说理由**：车身与座舱功能测试、三电与热管理、智能驾驶与感知、底盘与整车集成、测试平台与自动化工具链，各自的技术栈差别很大。选一个与实习经历或项目最接近的，讲清它测什么、用什么手段、难在哪，再补一句愿意从基础功能测试做起。反问环节可以问团队目前自动化覆盖率、台架资源怎么分配、新人前三个月的培养路径。
