### 《面试题目》

1. 这场笔试的整体流程和题型分布是怎样的？
2. 选择题主要考哪些范围？
3. 代码阅读题考的是什么？
4. 编程题一：一道与「AB 门」有关的问题，题干要求是什么？
5. 编程题二：一道以「小红的……」开头的长题干题，考的是什么？
6. 笔试挂了之后，你怎么复盘？
7. 零实习的简历怎么过初筛？过了之后为什么还是挂？

### 《参考解析》

**这类笔试的结构是固定的五段**：基础选择题（计算机基础、语言特性、框架、数据库、操作系统与网络）、代码阅读（给一段代码问输出或找 bug，考语法细节与边界）、算法题（中等难度，考数据结构选型）、后端开发题（接口设计、表设计、SQL 编写或场景分析）、编程题（ACM 模式，自己处理输入输出）。帖主遇到的「AB 门」与「小红……」两道题都属于最后一段，题干长、需要先把业务描述翻译成模型——这类题失分往往不是算法不会，而是没耐心把题意抽象出来。

**选择题的复习要有边界**：Java 方向的高频点是集合（`HashMap` 的扩容与树化、`ArrayList` 与 `LinkedList` 的取舍）、并发（线程状态、`synchronized` 与 `volatile`、线程池参数与拒绝策略）、JVM（内存区域、GC 算法与常见收集器、类加载）、Spring（IoC 与 DI、Bean 生命周期与作用域、AOP 的代理方式、事务传播行为与失效场景）、MySQL（索引结构与最左前缀、事务隔离级别、锁、慢查询）、Linux（`ps`、`top`、`grep`、`awk`、`tail -f`、`df`、`netstat`/`ss`、`lsof`、权限位）与网络（TCP 三次握手、HTTP 状态码、DNS）。复习方法不是通读教材，而是按「这个知识点会怎么出选择题」整理易错项，比如 `HashMap` 的初始容量与负载因子、`String` 的不可变与常量池、事务在同类内部调用时为什么会失效。

**代码阅读与编程题的应试顺序**：代码阅读先看有没有边界问题（整数除法、短路求值、`finally` 与 `return` 的先后、`i++` 与 `++i`、字符串比较用 `==`），再代入两组数据验算。编程题先写读入与暴力解保证有分，再优化；题干长的时候把输入输出样例抄下来，用样例反推数据规模，规模决定复杂度上限（n ≤ 1000 可以 O(n²)，n ≤ 10⁵ 必须 O(n log n)）。帖主交白卷的两道题，事后复盘的正确做法是：考后按记忆把题干复原，限时重做一遍，再找同类型的题连做五道——笔试的题感只能靠限时训练建立。

**「AB 门」这类命名不必纠结字面**：题干没记全时不要凭名字猜题意。这类题的通用解法是先形式化——把条件写成真值表或状态机，明确「输入是什么、每一步能做什么、问的是什么」，再判断是模拟、搜索还是贪心。考场上遇到读不懂的题，先花两分钟把已知条件列成表，往往就能看出结构；实在没有思路就写出暴力搜索拿到部分分，比空着强。

**零实习简历的投递策略**：帖主的两个反思都成立。一是简历与 JD 的匹配度决定初筛通过率，后端岗放一个前端项目或与岗位无关的二创项目，通过率会明显下降；正确做法是把项目按目标岗位重写（突出接口设计、数据库、并发、部署），关键词对齐 JD。二是官网海投的效率极低——字段不统一、职位重复、大量无效岗位，行测类笔试还消耗时间，所以渠道要分层：官网投最想去的少数几家，BOSS 等平台做批量触达，内推优先。至于「要不要先刷力扣」，答案是要，但刷法要对：按题型分类刷、每类十到二十道、限时手写，而不是从简单到难无脑刷数量。

**笔试挂了不等于简历有问题**：这场笔试的反馈只说明「当前算法与工程基础没达到该岗位的笔试线」，与简历质量是两件事。可执行的下一步是把笔试暴露的缺口列成清单（本题里是算法与 Python 数据处理、后端基础题库），给每项排一个两周计划，同时继续投递——投递与补短板并行，不要等「准备好」再投。
