### 《面试题目》

1. 这场笔试考哪些题型？
2. SQL 部分考到什么难度、重点是什么？
3. 统计概率部分考哪些内容？
4. 业务 case 题怎么考？
5. 性格测评要注意什么？

### 《参考解析》

**四块题型分别对应什么能力**

SQL 考的是取数基本功，题主给出的判断是「中等偏上，join 和窗口函数是重点」——这两个恰好是校招笔试最稳定的高频点。统计概率考假设检验、贝叶斯这类基础加场景题，重点不是公式推导，而是「这个业务问题该用哪种检验、结论怎么解释」。业务 case 是给一个场景让你拆解指标，明确写了「考思路不考背诵」。最后是性格测评，按第一反应答即可。

**SQL 的复习要落到具体题型**

「join 与窗口函数是重点」这句话可以拆成两类题。连接类要能分清 inner join、left join 在「查没有下单的用户」「查每个用户最近一单」这类题里的差别，以及 `where` 与 `on` 写法的语义区别（左连接时把条件写在 `where` 里会把外连接退化成内连接，这是最高频的错）。窗口函数重点在 `row_number`/`rank`/`dense_rank` 的区别（并列时排名是否跳号）、`lag`/`lead`（算相邻事件间隔、求连续登录）、以及 `sum() over (partition by ... order by ...)` 做累计与占比。练习方式用题主那套就够：每天两三道保持手感，做完回头把「换一种写法会不会错」想一遍。

**指标口径要提前串起来**

笔试和面试都会考指标的拆解，而拆解的前提是口径清楚。题主把 GMV、转化率、留存这几个指标的定义和相互关系串了一遍，这是性价比最高的一步：GMV 是下单金额还是成交金额、是否含退款、是否含运费；转化率的分母是 UV 还是会话数、从哪一步算到哪一步；留存的基准日、次日/7 日/30 日怎么定义、是按自然日还是按滚动窗口。口径不清楚时，同一个「转化率下降」的问题会得出完全相反的结论。

**业务 case 的答法：先澄清再拆**

数分 case 题的失分大多发生在开头——拿到题就直接给原因。可用的顺序是：先 clarify（这个指标的定义、统计周期、对比基准），再拆解（按公式拆：GMV = 用户数 × 下单率 × 客单价；或按维度拆：新老客、渠道、地区、端），然后给验证方案（需要哪些数据、看哪个字段、怎么排除季节性）。原帖作者在一面复盘里也提到同样的方法：先分层定位再找原因，别急着下结论。

**时间与心态**

笔试做不完是常态，题主的经验是「先保住会做的，别在一道题上死磕」。具体执行上：开考先扫一遍题量与分值，SQL 题优先（确定性高、拿分稳），统计概率的场景题写清思路即可，业务 case 至少把框架和关键指标写出来。性格测评题量大但不计对错，别反复修改，把时间留给客观题。
