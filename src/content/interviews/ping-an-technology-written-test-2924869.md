2. 3 道多选：Agent 与 AI 基础
3. RAG 的检索阶段和生成阶段分别存在哪些问题？
4. 怎么理解幻觉的概念？
5. 工具调用的底层实现是什么？
6. 编程题一：字符串反转
7. 编程题二：给定数组与其中两个数字，判断这两个数字是否相邻
8. 填空题：控制模型输出多样性的参数是什么？强化学习属于哪个训练阶段？把模型参数变小称为什么？

### 《参考解析》

**RAG 的检索阶段问题，可以按「切片、召回、融合」三处拆。** 切片阶段：切得太碎会丢上下文、切得太粗会稀释语义，跨段落/跨表格的信息被切开后无法召回；解析阶段的 PDF 表格、图片、公式丢失也会直接导致内容缺失。召回阶段：向量检索对专有名词、型号、错误码这类精确匹配不敏感，纯关键词检索又缺语义泛化，所以常见问题是**该召回的没召回（漏召）**与**召回了不相关的（误召）**；查询本身口语化、含指代（「它」「这个」）时，不做查询改写就会偏题；多跳问题需要多轮检索，单轮召回不到。工程上还有元数据过滤缺失导致越权/串库、以及 TopK 定得过大把噪声灌进上下文。

**生成阶段的问题主要是「有材料也不用」和「没有材料也硬编」。** 典型表现：上下文里明明有答案却因为片段顺序、长度或提示词约束不足而答错；多个文档冲突时不说明依据只挑一个；超过上下文窗口后关键信息被截断；以及幻觉——检索没命中证据时模型靠先验知识编出看似合理的答案。缓解手段：提示词里明确「只依据给定材料作答、无依据就说不知道」、要求引用片段编号、把最相关的片段放首尾（缓解中间遗忘）、结构化输出便于校验、生成后做引用核对与事实性检查、必要时二次检索。**幻觉的定义**可以答成「模型生成了流畅但不忠于输入证据或事实的内容」，分为与上下文矛盾、与事实矛盾、以及无依据但无法证伪三类；RAG 场景下最要关注的是第一类。

**工具调用的底层实现，一句话是「把工具描述成结构化函数签名，让模型输出调用参数，由运行时执行并回灌结果」。** 具体链路：把工具的 name、description、参数 JSON Schema 一起作为可用函数列表传给模型（function calling / tool use 字段）→ 模型在需要时输出一个结构化的调用请求（函数名 + 参数 JSON）而不是自然语言 → 宿主程序解析并校验参数、执行真实函数（本地函数、HTTP 接口或 MCP 服务）→ 把返回值作为一条 tool/observation 消息追加进上下文 → 模型基于结果继续推理，循环直到给出最终答案。工程要点：参数校验和权限检查必须在宿主侧做（模型输出不可信）、工具结果要限长并做错误结构化（避免把超长报错灌爆上下文）、调用要有超时与重试上限、以及要防死循环。

**编程题与填空题。** 字符串反转直接切片或用双指针原地交换，注意处理 Unicode 字符时按码点而不是字节反转；「判断两个数字是否相邻」的常规解法是先定位两个数的下标再比较差的绝对值是否为 1（O(n)），如果只关心值不相邻可以先把值映射成下标哈希再 O(1) 查询。填空题：控制输出多样性的参数是 temperature（采样温度，与之配套的还有 top_p / top_k）；强化学习在 LLM 训练中通常是最后一个阶段 **RLHF/RLAIF（对齐阶段）**，前面依次是预训练与指令微调；把模型参数精度变小以降低显存与加速推理称为**量化**（INT8/INT4，对应的还有剪枝、蒸馏、低秩分解等模型压缩手段）。
