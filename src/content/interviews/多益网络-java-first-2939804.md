### 《面试题目》

3. 你工作中 AI 的使用情况如何？AI 时代怎么提高自己的竞争力？
4. 你怎么用 AI 去排查问题？又怎么识别 AI 给出的答案是错的？
5. 索引相关：索引是什么？加索引会带来什么问题？
6. Redis 缓存击穿是怎么回事？
7. 怎么做一个像百度地图那样、能够判断路况和红绿灯时间的产品？
8. 算法题：数组循环排序，把 12345 变成 45123。
9. 附加题：怎么用 Java 做一个拷贝，但又不能有同一个引用地址？

### 《参考解析》

**索引的代价**：索引本质是把某一列（或几列）的值按顺序组织成额外的数据结构（MySQL InnoDB 是 B+ 树），用空间换查询时间。代价有四块：写入变慢——每次 insert/update/delete 都要维护索引页，随机写放大；占用磁盘与内存——索引本身要存储，还会挤占 buffer pool；优化器可能选错索引——区分度低或统计信息过期时反而更慢；过多索引让 DDL 与数据迁移变重。所以索引要按真实查询建，联合索引遵守最左前缀，定期用 `EXPLAIN` 与慢查询日志复核。

**缓存击穿**：某个热点 key 过期的一瞬间，大量并发请求同时打到数据库。解决方式有三类：互斥锁（只让一个请求回源，其余等待或返回旧值）、逻辑过期（value 里存过期时间，后台异步重建，读到的始终是旧值不阻塞）、热点永不过期加主动更新。还要配合空值缓存防穿透、随机过期时间防雪崩。

**地图路况与红绿灯怎么设计**：先拆数据源——路况来自浮动车轨迹（司机/乘客手机的定位上报）、交管部门数据、路口摄像头与地磁线圈；红绿灯相位来自交管信号机接口或路口设备。再拆链路：端侧定时上报定位（匿名化、按 30 秒~1 分钟采样）→ 消息队列削峰 → 实时计算（按路段聚合速度，用滑动窗口算拥堵指数）→ 写入时空索引（GeoHash/路格）→ 查询侧按瓦片返回。红绿灯时间用历史相位 + 实时排队长度做预测，不确定时给区间而不是精确秒数。最后是工程约束：上报频率与电量、数据合规与脱敏、弱网重传、以及「预测错误」的兜底文案。

**数组循环排序**：若指把 `12345` 循环右移两位得到 `45123`，做法是三次反转——整体反转得 `54321`，前 k 位反转得 `45321`，后 n-k 位反转得 `45123`，时间 O(n)、空间 O(1)；`k` 要先对 `n` 取模。若指按某个基准循环移位，也可用临时数组或 `System.arraycopy` 分两段拷贝。面试时先确认题意与 `k` 的方向，再写。

**Java 深拷贝**：要让副本与原对象不共享引用，常用三种方式：手动实现拷贝构造或 `clone()` 并逐层复制引用字段；序列化反序列化（Java 原生序列化、JSON、Kryo），要求对象可序列化且性能可接受；用拷贝工具（如 MapStruct、Dozer、Spring `BeanUtils` 只做浅拷贝，深拷贝要配转换器）。注意 `Object.clone()` 默认是浅拷贝，集合里的对象仍指向同一份；不可变对象（String、包装类）不需要复制。
