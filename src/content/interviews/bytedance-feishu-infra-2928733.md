### 《参考解析》

**AST 最近公共祖先**：求一组节点的 LCA，最省事的是对整棵树做一次后序遍历：递归返回每个子树里命中的目标节点数，第一个累计数等于目标总数的节点就是答案，复杂度 O(n)、空间 O(h)。目标里若某个节点本身是其他目标的祖先，答案就是它，这种计数法天然覆盖。树上带 parent 指针时也可换个思路：从一个目标节点向上把祖先打上标记，再从其余目标节点向上爬，第一个被标记的祖先即 LCA；节点多时按 LCA(a,b,c)=LCA(LCA(a,b),c) 两两合并，配合倍增可把单次查询降到 O(log n)。渲染场景还要补一句边界：找到 LCA 后只重渲它的子树，前提是 LCA 到根路径上的 props/context 没变，否则得继续向上找。

**await 不能避免阻塞**：await 只是把后续代码挪进微任务，让出的是调用栈，不是主线程。把一段同步的 CPU 密集解析包成 Promise 再去 await，计算照样占满主线程，页面该卡还是卡。真正不阻塞只有两条路：一是把解析移出主线程，放 Web Worker（或 WASM）里跑，主线程只收结果做 patch；二是把任务切成小块，块与块之间用 `scheduler.yield()`、`setTimeout(0)` 或 `requestIdleCallback` 主动让出，配合每帧几毫秒的时间预算，把长任务拆成多个短任务，INP 才不会爆。流式解析也是同一思路：凑够一个完整块就先产出部分结果。

**流式渲染**：链路是模型按 token 返回 → fetch + ReadableStream 增量读取 → TextDecoder 解码 → 增量解析 → 增量挂载。核心在「增量」：不要每来一段就整段 innerHTML 重渲，会闪烁、丢焦点和滚动位置；应把已闭合的标签块 append 成 DOM，未闭合部分留在 buffer 等闭合，Markdown 按块级边界切分。模型输出不可信，插入前必须 sanitize、禁内联脚本。再用 rAF 合并高频 chunk，配骨架屏、自动滚底、停止生成与出错重试。

**白屏 oncall**：先定影响面（单用户还是全量、哪个版本/网络/地区），再判断是渲染异常、流式中断还是接口不可用。止血优先：回滚或关开关，给降级路径——展示缓存的上次报告、提示重试或转非流式。定位时重点看流式读取有没有吞异常、有没有 ErrorBoundary、超时重试是否生效，常见根因就是流读到一半抛错后容器仍为空。修复补上兜底 UI、try/catch/finally、指数退避重试和「首屏无内容」监控，最后留复盘与回归。
