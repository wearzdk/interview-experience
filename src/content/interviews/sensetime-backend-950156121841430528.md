### 《参考解析》

**ThreadLocal**：每个线程持有一个 `ThreadLocalMap`，以 ThreadLocal 对象为 key、业务值为 value；key 是弱引用、value 是强引用，ThreadLocal 对象被回收后 key 变为 null，但 value 仍被线程强引用，线程长期存活时形成泄漏。线程池中线程复用且未清理，会把上一次请求的上下文带给下一个任务，既是泄漏也是串数据。规范做法是在 `finally` 中 `remove()`。

**锁与可见性**：`synchronized` 是 JVM 内置的管程实现，支持锁升级（偏向锁 → 轻量级锁 → 重量级锁），不可中断、非公平；`ReentrantLock` 基于 AQS，支持公平锁、可中断、超时与多条件变量，需要手动释放。`volatile` 保证可见性与有序性（禁止指令重排），不保证复合操作的原子性，`i++` 仍需加锁或使用原子类。底层通过内存屏障与缓存一致性协议实现。

**线程池与 JVM**：核心参数是核心线程数、最大线程数、队列容量、空闲存活时间、线程工厂与拒绝策略。CPU 密集型按核数配置，IO 密集型按「核数 ×（1 + 等待时间/计算时间）」估算，但必须结合下游连接池容量，否则加线程只会把压力转嫁给数据库。拒绝策略按业务选：丢弃最旧适合时效性强的行情推送，调用方执行适合不能丢的写操作，自定义策略记录日志并降级。JVM 内存分为堆、虚拟机栈、本地方法栈、方法区（元空间）与程序计数器，堆与方法区会 OOM，栈会 StackOverflow。Full GC 频繁先看是否有内存泄漏（老年代增长、dump 分析）与晋升过快（新生代过小、大对象直接进老年代），再调堆比例与收集器；G1 关注停顿目标，ZGC 适合大堆低延迟，切换要以压测与 GC 日志为依据。

**Spring**：Bean 生命周期为实例化 → 属性填充 → Aware 回调 → BeanPostProcessor 前置 → 初始化方法（`@PostConstruct`、`afterPropertiesSet`、init-method）→ 后置处理 → 使用 → 销毁。循环依赖靠三级缓存：一级放成品 Bean，二级放已实例化未填充的早期引用，三级放对象工厂用于生成 AOP 代理，从而在填充属性时能取到引用并保证代理一致。`@Transactional` 失效常见于同类内部方法调用（不走代理）、方法非 public、异常被吞或抛出受检异常未配置 `rollbackFor`、多线程调用与数据库引擎不支持事务。

**MySQL 与 Redis**：B+ 树层级低、非叶子节点只存键，单页能容纳更多索引项，叶子节点用链表连接便于范围扫描与排序。隔离级别从读未提交到串行化，InnoDB 在可重复读下用 MVCC 加间隙锁减少幻读，但并非完全消除。慢 SQL 用慢查询日志与执行计划定位，关注是否走索引、扫描行数、回表与临时表。分库分表后的 ID 可用雪花算法（时间 + 机器 + 序列，注意时钟回拨）、号段模式（数据库批量发号，减少依赖）或 UUID（无序，不利于聚簇索引）。Redis 快在内存操作、单线程避免锁竞争、IO 多路复用与高效数据结构；RDB 是快照、恢复快但可能丢数据，AOF 记录写命令、可配置每秒刷盘，生产常用混合持久化。分布式锁用 `SET key value NX PX` 加唯一值，释放时用 Lua 校验值，续期用看门狗；问题是主从切换可能双持有，需要 Redlock 或接受最终一致。缓存穿透用空值缓存与布隆过滤器，击穿用互斥重建或逻辑过期，雪崩用过期时间打散与多级缓存；一致性用 Cache Aside 加删除重试与消息补偿。
