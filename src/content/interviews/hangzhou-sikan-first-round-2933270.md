### 《参考解析》

**操作系统四类资源的答案要各自落到机制**：CPU 用进程 / 线程调度（时间片轮转、优先级、CFS 的虚拟运行时间）与上下文切换；内存用虚拟内存 + 页表 + MMU + 缺页中断 + 页面置换（LRU / 时钟算法）与段页式管理；I/O 用设备驱动 + 中断 + DMA + 缓冲（内核缓冲、页缓存）+ 统一的文件描述符抽象；文件用 inode + 目录项 + VFS 抽象层 + 日志式文件系统。图灵机四部分是无限长纸带、读写头、状态寄存器、控制规则表，用来定义「可计算」的理论边界。

**中断处理流程**：外设发中断请求 → 中断控制器（APIC/GIC）仲裁并送 CPU → CPU 保存现场（CS/EIP/EFLAGS 或压栈）→ 查中断向量表跳到 ISR → ISR 上半部做最小必要工作（清标志、取数据）→ 下半部（软中断 / tasklet / workqueue）延迟处理 → 中断返回恢复现场。Linux 上还要提「中断上下文不能睡眠」「关中断会拉高延迟，所以要用线程化中断」。

**`shared_ptr` 的实现分两块**：对象指针 + 控制块（强引用计数、弱引用计数、删除器、分配器），`make_shared` 把对象和控制块一次分配（cache 友好），从 `shared_ptr` 构造则分两次；拷贝时强计数原子加，析构时减到 0 就删对象、强弱都到 0 才释放控制块。循环引用是「A 持有 shared_ptr<B>、B 持有 shared_ptr<A>」，两者计数都不为 0 永不释放；解法是把其中一条边改成 `weak_ptr`（不增计数，用 `lock()` 临时提升为强引用）。静态成员函数不能直接调用非静态成员函数，因为没有 `this` 指针——除非显式传入对象引用 / 指针，或者这个非静态成员其实不依赖实例状态（那就该改成静态）。

**左值 / 右值 / 将亡值**：左值有名字可取地址；纯右值是字面量与临时计算结果；将亡值是「有身份但资源可以被搬走」的对象（如 `std::move(x)` 的结果、返回右值引用的函数调用）。`std::move` 的实现就是 `static_cast<T&&>(t)`，它只做类型转换，真正搬资源的是随后匹配到的移动构造 / 移动赋值；所以对 const 对象 move 会退化成拷贝。

**`epoll_wait` 的阻塞 vs `read` 的阻塞**：`read` 阻塞是「这个 fd 没有数据就睡眠在这个 fd 的等待队列上」，一次只管一个 fd；`epoll_wait` 阻塞是「等就绪链表非空或超时」，它同时监视成千上万个 fd，返回的是「哪些 fd 就绪」的列表，本身不做数据传输；语义上 `read` 是数据搬运、`epoll_wait` 是事件通知（水平触发要你再 `read`，边缘触发必须一次读到 `EAGAIN`）。Hook 则是拦截函数调用或消息的机制：API Hook（inline hook / IAT hook）、消息钩子（Windows `SetWindowsHookEx`）、内核 hook（kprobe / ftrace）、以及框架层的生命周期 hook，常用于监控、兼容层与安全检测。
