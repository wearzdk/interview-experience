### 《参考解析》

**HashMap 扩容**：默认容量 16、负载因子 0.75，元素数超过 `容量 × 0.75` 时扩容为两倍。JDK 8 的扩容不是重新计算哈希，而是利用容量是 2 的幂这一性质，把每个桶的链表按 `hash & oldCap` 拆成「低位链」与「高位链」，低位留在原索引、高位移到 `原索引 + oldCap`，避免逐节点重算，也保持链表顺序。扩容时若链表长度 ≥ 8 且容量 ≥ 64 会转红黑树；扩容后树节点也可能退化回链表。多线程并发扩容在 JDK 8 下仍可能丢数据，并发场景用 `ConcurrentHashMap`。

**volatile 的作用**：保证可见性与有序性，不保证原子性。写操作会立刻刷回主内存并使其他线程的缓存行失效，读操作强制从主内存读；同时禁止指令重排（插入内存屏障），典型用途是状态标志位与双重检查锁定的单例（`instance` 声明为 volatile 防止「分配内存—赋值—初始化」重排导致拿到半初始化对象）。`i++` 这类复合操作仍需 `AtomicInteger` 或加锁。

**线程池满了怎么办**：按 `corePoolSize → 队列 → maximumPoolSize → 拒绝策略` 的顺序。拒绝策略有四种：`AbortPolicy` 抛异常、`CallerRunsPolicy` 由提交线程执行（天然反压）、`DiscardPolicy` 静默丢弃、`DiscardOldestPolicy` 丢最老的。生产上更常见的是自定义拒绝策略：落库或写消息队列稍后重试、返回明确的限流错误、上报监控。根本解法是评估队列容量与线程数、把慢任务隔离到独立线程池、加熔断降级，而不是无限加大队列（会掩盖问题并导致超时堆积）。

**Spring 事务失效**：① 方法不是 `public`（旧版本代理限制）；② 同类内部调用，`this.method()` 不走代理；③ 异常被 catch 吞掉，或抛的是受检异常而默认只回滚 `RuntimeException`；④ 传播行为设置不当（`REQUIRES_NEW`、`NOT_SUPPORTED`）；⑤ 数据库引擎不支持事务（MyISAM）；⑥ 多数据源未正确配置事务管理器；⑦ 事务方法被 `final` 或 `static` 修饰，代理无法覆写；⑧ 异步方法（`@Async`）里开事务，线程切换导致事务不生效。排查先确认代理是否生效（看注入的是代理对象还是原对象），再看异常与传播行为。

**MySQL 隔离级别**：读未提交（脏读）、读已提交（不可重复读）、可重复读（InnoDB 默认，配合间隙锁基本避免幻读）、串行化。实现靠 MVCC + 锁：快照读走 ReadView，当前读写记录锁与间隙锁。

**MQ 保证不丢失**：三段都要保——生产者用同步发送 + 确认机制（RabbitMQ 的 publisher confirm、Kafka 的 `acks=all` + 重试），Broker 持久化（队列与消息都持久化、多副本 `min.insync.replicas`），消费者手动 ACK 且处理成功后再确认（失败重回队列或进死信）。业务侧配合本地消息表或事务消息保证「业务落库」与「消息发出」一致，消费端做幂等，避免重复投递造成脏数据。

**重复请求处理**：入口用幂等键（客户端生成的 requestId、订单号、业务唯一键），服务端唯一索引兜底；分布式锁按幂等键加锁，处理完释放；状态机限制重复流转；支付回调按订单状态判重并直接返回成功。前端侧禁用按钮、防抖只能减少重复，不能替代服务端幂等。

**SSE 与 WebSocket**：SSE 是单向（服务端到客户端）、基于 HTTP、文本、自带断线重连（`Last-Event-ID`）、可穿过大多数代理，适合推送通知与大模型流式输出；WebSocket 是全双工、独立协议、需握手升级、支持二进制、延迟低，适合聊天、协同编辑、实时游戏。选型看是否需要客户端持续上行：只需要服务端推就用 SSE，简单且易运维；双向交互频繁才上 WebSocket。

**大模型调用失败怎么处理**：分错误类型——超时与限流做指数退避重试（带抖动、限制次数）；5xx 与网关错误切换备用渠道或模型；内容审核拒绝不重试，直接返回合规话术；上下文超长做截断或摘要；流式中断给客户端明确状态并支持续传。工程上要有超时、熔断、降级（返回缓存答案或模板回复）、以及完整的调用日志（请求 id、模型、token、耗时、错误码），并区分「用户可见失败」与「可重试失败」，不要把内部错误原样抛给用户。

**怎么检查 AI 生成的代码**：先看它是否理解需求（让它复述约束与边界），再逐段读——重点看异常处理、空值与边界、并发与事务、资源释放、SQL 注入与越权；跑单测与静态检查（lint、类型检查、SAST）；对核心链路做 code review 与灰度验证。把 AI 当成「写得快但需要审稿的同事」，提交粒度小、每次改动可回滚。

**合并区间**：按左端点排序，遍历时若当前区间左端点 ≤ 结果最后一个区间的右端点则合并（右端点取两者最大值），否则追加。时间复杂度 O(n log n) 来自排序，遍历 O(n)，空间 O(log n)（排序）或 O(n)（结果）。追问常考「区间已经有序」则降为 O(n)，以及「求交集而非并集」的变体。
