### 《参考解析》

1. **负向标签的价值**：正向标签解决「想要什么」，负向标签解决「绝对不能要什么」，对召回是硬过滤、对排序是强约束。提取上靠意图识别加槽位抽取，把「不想上夜班」「不接受出差」这类表述归一成结构化约束，再与岗位属性做匹配。

2. **标签权重与强弱限制**：必须有区分。「想做保姆」是职业方向，属于强约束；「不想上夜班」是排除条件，属于负向硬约束；「希望离家近」是软偏好。工程上把标签分成硬过滤、加权、仅展示三类，硬过滤放在召回前，软偏好进排序特征，避免把软偏好当硬条件导致召回为空。

3. **标签过多怎么处理**：做归一化和合并（同义标签映射到同一 ID）、按置信度和时效性截断、分层存储（长期画像放离线表，近期意图放实时特征），检索时只取与当前 query 相关的 TopN，而不是把所有标签都塞进模型。

4. **DCN-V2 的结构**：输入是 embedding 拼接，交叉网络逐层用 `x_{l+1} = x_0 ⊙ (W x_l + b) + x_l` 显式建模任意阶特征交叉，x0 是原始输入，所以每一层都能和原始特征交互；V2 用低秩分解（两个小矩阵相乘近似权重矩阵）降低参数量。它不是点积，点积是 FM 的二阶交叉；DCN-V2 是逐元素乘加，能表达更高阶。

5. **特征交叉模型对比**：FM 用隐向量内积做二阶交叉，参数量小但只到二阶；DeepFM 是 FM 加 DNN，浅层显式、深层隐式；DIN 用注意力根据候选物品对用户行为序列加权，适合序列兴趣建模。选型看特征稀疏度、是否需要高阶交叉、序列信息是否重要。

6. **分层预测 + Beam Search 与 32-32 束宽**：L1 到 L4 逐层预测，每层保留若干个候选（beam），下一层在上一层保留的候选中继续展开，最终取整条路径概率最高的组合。束宽是召回率与算力的折中：32 太窄容易漏掉正确路径，太宽算力翻倍，32-32 是实测下来的性价比点，并且要拿离线指标（整条路径准确率）验证，不能只看单层。

7. **Decision Model 的监督与损失**：本质是判别式分类（每个标签位置做多分类或二分类），监督信号来自人工标注和规则生成的弱标签，损失用交叉熵加层级约束（下层必须在上级成立的条件下才计损失）。要和生成式模型对比：判别式快、稳定、可控，但泛化到新标签需要重新训练；生成式灵活、能解释，但慢且不稳定。

8. **Top-K 热门 Query**：先归一化（`lower()`、`strip()`、正则把连续空白替换成一个空格），再用 `(query, user_id)` 集合去重保证 UV，然后按 query 聚合用户数，排序键是「用户数降序、query 字典序升序」，最后取前 K。边界要处理：归一化后为空串的丢弃、K 大于去重后数量时返回全部、同一用户大小写不同的查询算同一条。

9. **把协同内化到参数里**：工程层（Harness）解决的是「怎么调度」，能力内化解决的是「模型自己知道何时该退让、何时该交给别人」，省掉的是显式的规划提示和多轮往返的 token 与延迟。代价是训练成本高、可解释性下降。回答时要能说清「省了什么」：省的是每轮都要重新描述任务与能力的上下文，以及规划错误带来的返工。

10. **联合优化还是交替优化**：交替优化更常见——固定执行模型训规划模型（用执行结果作为奖励），再固定规划模型训执行模型，多轮迭代避免两边同时漂移导致训练不稳定。实验上要做单轮联合训练的对照，比较收敛速度和最终任务成功率。
