### 《参考解析》

**部署要讲到程序能接到请求**

可以按构建产物、配置、启动、检查四步回答。先生成可运行的包，确认运行时版本；再准备环境配置和外部服务连接；由进程管理工具或容器启动；最后检查日志、健康接口及关键请求。还要说明发布失败时怎样切回上一版本。只答一句 java -jar，往往接不住后面的追问。

**调优亮点要能复现**

选自己做过的一次慢查询、重复请求或批量操作优化。交代原来的耗时、定位依据、具体改法，以及在相同数据量和并发条件下的结果。没有测过的指标就不要补数字；能说清一次查询为什么多扫了数据，比泛泛列出缓存、异步、索引更有说服力。

**Linux 命令与场景配对**

查看进程和 CPU 可讲 ps、top，内存可讲 free，磁盘空间可讲 df，端口监听可讲 ss，日志检索可讲 tail 与 grep。面试官继续追问时，应能区分磁盘空间不足、内存不足和 CPU 忙，避免见到服务慢就直接重启。
