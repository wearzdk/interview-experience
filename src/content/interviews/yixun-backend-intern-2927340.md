### 《面试题目》

1. 自我介绍
2. 有没有实习经历？
3. 你看书吗？Java 的原理了解吗？
4. 项目是怎么做的？
5. JVM 虚拟机原理？
6. Java 的数据结构

### 《参考解析》

**短面试怎么应对**：十分钟的面试基本只能看「表达是否清楚、基础是否在线」。这种场合的通用策略是：自我介绍控制在 1 分钟内并且带一个可追问的钩子（做过什么系统、用什么技术、结果如何）；被问「看不看书」时给出具体的书名与收获（比如《深入理解 Java 虚拟机》里讲 GC 日志和内存模型的部分），比说「经常看」有效。

**JVM 原理的骨架**：内存区域分线程私有（程序计数器、虚拟机栈、本地方法栈）与共享（堆、方法区 / 元空间、直接内存）；对象分配走 TLAB 与 Eden，频繁存活的对象晋升老年代；回收算法有标记清除（碎片）、标记复制（新生代）、标记整理（老年代），回收器从 Serial、Parallel、CMS 到 G1、ZGC，演进主线是「更短停顿 + 更大堆」；类加载是加载、验证、准备、解析、初始化五步，用双亲委派保证核心类不被替换。能顺带说出一次真实的 GC 日志排查或 OOM 定位经验，比背概念强得多。

**Java 数据结构**：集合分 List（ArrayList 数组、查询快扩容要拷贝；LinkedList 双向链表、头尾操作快但随机访问慢）、Map（HashMap 数组 + 链表 + 红黑树、LinkedHashMap 保序、TreeMap 有序、ConcurrentHashMap 并发安全）、Set（基于 Map 实现，去重）与 Queue（ArrayDeque、PriorityQueue、BlockingQueue 用于生产者消费者）。回答时按「底层结构 — 时间复杂度 — 线程安全性 — 适用场景」四段说，比列举类名有价值。

**关于这类面试的提醒**：面试官提问跳跃、听不清、时间随意改动，本质上反映的是招聘流程不成熟，不必因此自我怀疑。把每一场都当成「挑出自己讲不清的点」的练习即可——作者自己总结的「完全不知道面试官想问什么」，也很可能是对方并没有明确的考察提纲。相比之下，把项目讲成「我解决了什么问题、怎么验证」的结构，在任何一个面试官面前都是有效的。
