### 《参考解析》

**多维打分要先讲清样本与口径。** 评测数据从哪来（真实日志、人工构造、模型生成）、每个维度由谁打分（规则、模型、人工）、分数如何合成、样本量多少、覆盖哪些场景与长尾、标注一致性怎么保证。面试官追问「数据是否过少、覆盖是否不全」，本质是在检验你是否知道小样本评测的置信区间与选择偏差。可以回答：先按业务场景分层抽样，给出每层的样本量与置信区间；对关键场景做全量回归，对长尾做定向补充；用人工抽检校准自动打分，并记录分歧率。

**GRPO 的核心是用组内相对优势替代价值网络。** 对同一个 prompt 采样一组回答，计算每个回答的奖励，用组内均值与标准差归一化得到优势，再按策略梯度更新；省掉 critic 模型，显存与训练复杂度更低。奖励设计要拆成可验证的信号：答案正确性、格式合规、工具调用是否正确、是否完成任务、效率与成本；权重与阈值要写明，并防止 reward hacking（模型学会迎合评分器而不是解决问题）。数据集要说明来源、难度分布、是否有多轮工具调用轨迹、如何构造难例。

**GRPO 与 DPO 的区别在数据与目标。** DPO 用成对的偏好数据（chosen / rejected）直接优化策略，不需要在线采样与奖励模型，训练稳定、成本低，适合有高质量偏好对、目标是对齐风格与偏好的场景；GRPO 是在线强化学习，需要可计算的奖励与采样环境，适合有明确正确性信号、需要探索多步决策的任务，例如工具调用、代码生成、数学推理。两者不是替代关系：常见路径是先 SFT 冷启动，再用 DPO 对齐，最后用 GRPO 在可验证任务上提升。

**SFT 与强化学习的边界。** SFT 教模型「怎么说、做什么」，适合有标准答案或示范轨迹、需要快速获得基本能力的阶段；强化学习优化「怎么做更好」，适合存在多个可行路径、可以用奖励区分优劣、且需要探索的场景。若任务没有可靠奖励，强行上 RL 只会放大评分器的偏差。

**多 Agent 的失败处理要落到工程机制。** 每个 worker 有超时、重试上限与幂等键；失败分为可重试（网络、限流）、可降级（换工具、换模型、缩小任务）与不可恢复（权限不足、输入非法）；编排层保存任务状态与中间结果，失败后从检查点恢复，而不是整条重跑；对关键写操作先落操作记录再执行，恢复时对账；最终向用户返回明确的失败原因与已完成部分。监控上要有成功率、重试率、平均耗时与失败类型分布。

**为什么选实体企业。** 回答要具体到岗位与业务：工业场景对稳定性、交付周期、软硬件协同的要求，Agent 在设备手册、售后、生产流程里的落地空间，以及你愿意接受的节奏与地点。避免说「互联网太卷」这类比较式理由，把重点放在你想做什么。
