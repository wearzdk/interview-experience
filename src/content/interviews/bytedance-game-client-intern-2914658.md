### 《面试题目》

1. 考察你最近的一个项目（围绕其中一个项目深挖了十多分钟）。
2. 看你参加了算法比赛，这是个什么比赛？
3. 算法题：一个方法接收两个参数（一个 vector2 类型的参数当圆心，另一个参数当半径），要求返回圆范围内的随机一个点。
4. 追问：你这样写的话，对圆内取点的概率不是均等的，能怎么优化？
5. 到岗时间是什么时候？
6. 自我介绍。

### 《参考解析》

**圆内均匀随机取点**：正确解法是「平方根半径 + 均匀角度」。极坐标下 `(r, θ)`，θ 取 `[0, 2π)` 均匀分布，半径不能直接取 `R * U`（U 为 [0,1) 均匀随机数），而要取 `R * sqrt(U)`：

```
θ = 2π * rand01()
r = R * sqrt(rand01())        // 关键：开平方
return center + (r * cos θ, r * sin θ)
```

原因是面积元：半径为 r 处的圆环面积是 `2πr·dr`，与 r 成正比，所以按半径看「落在 [r, r+dr] 的概率」随 r 线性增长。若 r 取均匀分布，随机点会明显向圆心聚集（圆心附近单位面积分到的点更多）。要修正这个概率密度，需要让 r 的分布函数满足 `P(r ≤ x) = x²/R²`，反变换采样即得 `r = R·sqrt(U)`；等价的说法是「r² 在 [0, R²] 上均匀」，所以直接对 `R² * U` 开方也得到同一结果。原帖作者的写法正是对半径取了 sqrt，所以当面试官质疑「概率不均等」时，很可能没细看或者是在考察他能不能讲清推导——这也是面试里常见的压力点：如果他当时能当场解释面积元与反变换采样，这个质疑反而会变成加分项。

**其他常见解法与坑**：① 拒绝采样，在边长 2R 的正方形内均匀取点，落在圆外就重取，期望迭代次数是 `4/π ≈ 1.27` 次，实现最简单也最不容易出错，实机上代价可以接受；② 均匀取角度 + 按 `sqrt` 取半径（如上），一次成型但依赖 `sqrt` 与三角函数；③ 想用球面均匀采样的类比（`z` 均匀取）会在二维下取错，二维是 sqrt 而三维是立方根——面试时能把二维/三维的区别讲出来很加分。另外要处理工程细节：`rand01()` 的精度与是否包含 1.0（包含 1.0 时 cos/sin 恰好落在边界，需要确认返回值是否允许在圆周上）；随机源是否线程安全、是否可复现（用带种子的 PRNG 便于回放和单测）；浮点下 `r` 可能因舍入略微超过 R，必要时 clamp。

**项目深挖怎么顶住**：这场面试的特点是全程只盯一个项目问，没有八股，所以项目的准备深度直接决定结果。可以按「四层」自查：① 动机层——为什么做这个项目、解决谁的什么问题、有没有更简单的替代方案；② 架构层——模块怎么划分、数据怎么流动、关键数据结构为什么这么选、并发模型是什么；③ 实现层——哪一段是你写的、最难的十行代码是什么、性能瓶颈在哪、怎么测的（帧率、内存、GC 峰值这类可量化指标）；④ 反思层——如果重做会改什么、踩过什么坑、哪些地方是妥协。游戏客户端方向还会额外关心帧同步/状态同步、渲染与逻辑的分离、对象池与内存管理、以及跨平台（不同机型）的兼容处理，简历上写了就一定要能展开。遇到答不上来的问题，给出「我会怎么查、怎么验证」的思路，比硬编一个答案安全。

**算法比赛与到岗时间**：面试官问比赛是什么级别，通常是在给简历上的加分项校准含金量，回答要如实说清规模与赛制（校级/省级/区域赛/线上赛、个人还是三人队、你负责哪一部分）以及名次，别含糊。到岗时间则直接影响实习 offer 的发放——日常实习通常要求一周到岗 4 天以上、连续 3 个月以上，回答时给出明确可到岗日期和每周可实习天数，比「随时都可以」更可信。原帖作者提到当时算法题写得磕磕绊绊、被提示「还有三分钟」时思路卡住，事后才反应过来自己原来的写法是对的——这类情况的教训是：面试中先讲思路再写代码，边写边说「半径为什么要开平方」，面试官就不会把正确的实现当成漏洞来质疑；时间压力下也要先说出结论再补充细节。
