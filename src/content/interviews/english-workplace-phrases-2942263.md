### 《面试题目》

1. 英文面试被问懵、需要缓冲几秒时，怎么说？
2. 晨会上要说明自己被上游接口卡住，怎么说？
3. 手头已经排满，想婉拒临时加的需求，怎么说？
4. Code Review 时想温和地提一个改进建议，怎么说？
5. 没听清面试官的问题，想请对方换个说法，怎么说？

### 《参考解析》

**缓冲几秒**。`Wait a minute, let me think` 的问题在于它像在打断流程，听着是被问住了。换成 "That's a great question—let me take a moment to structure my thoughts."：先认可问题，再说明你在组织思路，`structure my thoughts` 传达的是「我在整理」，而不是「我不会」。同类说法还有 "Let me think through the trade-offs for a second."，把停顿变成分析的一部分。

**说明被卡住**。`I cannot continue because API is not ready` 只陈述了事实，没有推进。地道说法是 "I'm currently blocked by the staging API. Could we loop in the backend team after standup?"：`blocked by` 说清阻塞源，`loop in` 是拉相关同事进来，一句话把状态、影响和下一步都讲了。晨会要的就是这三点。

**婉拒加塞**。"I am too busy to take this task" 听起来像态度问题。换成 "I'm at full capacity with the release this week, so I won't be able to take this on."：`at full capacity` 是满负荷（客观状态），`take on` 是承接任务，拒绝的是这件事而不是这个人。要留余地就补一句 "Happy to pick it up next week if it can wait."。

**Code Review 提建议**。"Your code here is wrong" 是判断人。换成 "Nitpick here—would it be cleaner to extract this into a helper function?"：`Nitpick` 明说这是小建议、不是阻塞项，`would it be cleaner` 用疑问句把决定权留给作者，后面接具体改法而不是评价。英文 CR 里 `nit` / `nitpick` / `non-blocking` 这几个词就是用来降冲突的。

**请对方换个说法**。"Sorry, say again please" 太随意，也没说明你缺什么。换成 "Could you rephrase that slightly? I want to make sure I'm addressing what you're looking for."：`rephrase` 是换种说法，后半句说明目的是「确保回答到点上」，对方不会觉得是自己的表达有问题。若只是没听清某个词，可以说 "Sorry, I missed the last part—could you repeat the question about X?"，把不确定的范围缩小。

**共同规律**。这五句都遵循同一个结构：先认可或说明客观状态，再给具体动作或请求。中式直译往往只保留了「我不行 / 你错了」这一层，缺少让对方可以接着走的那一步，所以听起来生硬。
