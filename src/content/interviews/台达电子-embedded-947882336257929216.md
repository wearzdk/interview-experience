### 《面试题目》

1. 用中英文各做一次自我介绍，突出和嵌入式相关的经历。
2. 讲一个你最熟的嵌入式项目，你独立交付的边界在哪里？
3. 如果让你重新选型主控，你会从哪些维度评估，而不只看主频？
4. 请按「应用 / 中间件 / BSP / 驱动」画分层，并说明层间依赖规则。
5. 从传感器采样到执行器输出，把一条完整数据通路讲清楚。
6. Cortex-M 上电复位后，到执行 main 之前内核和启动代码做了什么？
7. 解释 const 和 volatile 同时出现在指针上时，各自约束什么。
8. 链接时的内部链接、外部链接，和 static 全局变量有什么关系？
9.（原帖在此处中断）

### 《参考解析》

**中英自我介绍各一分钟**：中文讲学校与年限、主芯片与 RTOS、独立负责的模块、可量化的结果（稳定性、功耗、量产批次）；英文用同一结构，专有名词用标准说法（MCU、ISR、DMA、CAN），不要逐字翻译中文稿。少讲课程清单，多讲一个你解决过的具体问题，结尾留一个可展开的点，方便面试官顺着追问。

**独立交付边界要说得清「我做了哪一层、接口是什么、验收标准是什么」**：先说产品目标与硬件平台（主控、关键外设、是否上 RTOS），再说自己负责的模块（传感器采集、通信协议、板级驱动或控制环），然后说明与别人的接口（消息格式、调用约定、联调方式），最后用可量化结果收尾。准备一个自己排过的典型故障，讲定位过程而不是结论。

**主控选型的维度**：外设是否够（定时器数量、ADC 精度与通道、CAN/USB、DMA 通路）、Flash 与 RAM 余量（是否要 OTA、日志、双 Bank）、生态（库、调试器、量产烧录、长期供货）、功耗与工作温区、封装与 PCB 约束、团队熟悉度与迁移成本。只追主频的选型在量产阶段会因为供货或功耗返工，这是面试官想听到的判断。

**分层与数据通路**：驱动层放厂商库、启动文件、寄存器封装，与具体板子无关；BSP 负责引脚、板载器件初始化与板级 API；中间件是 RTOS、文件系统、协议栈、GUI，通过移植层对接 BSP；应用层是业务状态机、算法与人机交互，不直接碰寄存器。规则是上层只调下层稳定接口，换芯片优先替换驱动与 BSP，保住应用层。数据通路按「采样（定时触发 ADC 或 DMA 循环缓冲）→ 预处理（滤波、标定、有效性判断、异常值隔离）→ 决策（控制算法或状态机）→ 输出（PWM/DAC/通信命令，带限幅与安全联锁）→ 闭环（超时、看门狗、故障降级）」讲。

**Cortex-M 启动流程**：从向量表取 MSP 初值与复位处理函数入口；启动文件拷贝 .data 段、清零 .bss 段，必要时初始化堆；调用 SystemInit 配置时钟、Flash 等待周期与总线分频；执行 C 运行时初始化（构造函数等，视工具链而定）；跳转 main。有 Bootloader 时还包含跳转前的镜像校验与向量表重定位。

**const、volatile 与链接属性**：const 约束「不通过该路径修改对象」，是编译期语义；volatile 约束「每次访问都真正读写」，防止被优化掉；两者同时出现常见于只读状态寄存器——软件不该写，但值会变。中断标志、DMA 可见缓冲、MMIO 寄存器是典型场景。链接属性上，普通全局符号默认外部链接，其他编译单元可以引用；加 static 变成内部链接，作用域限制在本文件，避免命名冲突；static 函数同理；static 局部变量放在数据区，生命周期跨调用，初始化只做一次。头文件里不要放非 static、非 inline 的定义，否则容易多重定义。
