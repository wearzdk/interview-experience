### 《面试题目》

1. 做一下自我介绍。

4. 现场用 pytest 实现它的具体功能，比如参数化、前后置，或任意你了解的功能；不知道的话就当场实现一个差不多的。
5. 介绍项目，问到一个具体问题，你会怎么去解决？

### 《参考解析》

**pytest 参数化的实现机制。** `@pytest.mark.parametrize("a,b,expected", [(1,2,3), ...])` 把参数名与数据挂在函数的 mark 上；pytest 收集用例时，`pytest_generate_tests` 钩子读取这些 mark，调用 `metafunc.parametrize()` 把一组数据展开成多个测试项，每个测试项带独立的 id。实现一个简化版：写一个装饰器把参数列表存到函数属性上，收集阶段遍历模块里的函数，发现属性就为每组参数生成一个闭包并注册为独立用例；执行时把参数传给原函数。要点是「收集与执行分离」、用例 id 可读、参数组合（笛卡尔积）与单参数化能共存。

**前后置用 fixture 表达。** `@pytest.fixture` 装饰的函数在测试前执行，`yield` 之前是 setup、之后是 teardown；`scope` 控制生命周期（function、class、module、session），`autouse=True` 自动应用，`conftest.py` 让 fixture 在目录范围内共享。依赖注入靠参数名匹配：测试函数声明 `def test_x(db):`，pytest 就去找名为 `db` 的 fixture。简化实现：维护一个 fixture 注册表，执行测试前按参数名解析依赖、递归执行 setup，测试结束后逆序执行 teardown；用生成器的 `next` / `close` 模拟 yield。

**现场写代码先讲结构再写。** 10 分钟不足以写完整框架，面试官看的是你是否理解机制。可以先说「我实现一个最小版本：装饰器收集参数 → 收集器展开用例 → 执行器注入参数」，然后写 30 行左右的核心代码，最后说明真实 pytest 还做了 id 生成、跳过标记、fixture 作用域缓存、插件钩子。卡住时不要沉默，把已知的 API 与设计讲出来。

**项目问题按「定位—验证—修复—回归」回答。** 先描述现象与影响面，再说如何缩小范围（日志、复现、二分、对比），提出假设并设计验证，修复后补用例防止回归。自动化测试岗尤其看这一点：你能否把一次偶发问题变成稳定的测试用例。

**实习内容要能说出「你写的测试测什么」。** 覆盖了哪些模块、用什么框架、用例数量与维护成本、发现了哪些有效缺陷、CI 怎么集成、失败怎么归因。没有量化数据时，讲清流程与一个具体案例，比罗列工具名有效。
