### 《面试题目》

1. 请做一下自我介绍。
2. 简历深挖：项目和实习经历里的细节。
3. 围绕项目连环追问「为什么这么做」。
4. 业务题：某个指标出现异动，你怎么分析？
5. 手写一道中等难度的 SQL。
6. 反问环节。

### 《参考解析》

**45 分钟的流程结构说明了考察权重**

自我介绍加简历深挖、项目追问、一道业务 case、一道 SQL、反问——四块时间大致均分，说明这个岗位对「业务分析能力」和「取数基本功」的要求是对等的，不是纯 SQL 岗也不是纯业务岗。准备时两块都不能偏。

**项目追问「为什么这么做」该怎么答**

连环追问的目的不是难住你，而是确认这个方案是你想的、还是照抄的。答法上每讲一个决策，主动补齐四件事：当时的约束（数据量、时限、人力）、考虑过的备选方案、为什么淘汰它们、以及事后的效果验证。比如「为什么用这个指标衡量」→ 当时的替代指标是什么、口径有什么差异、上线后指标有没有真的动。被问到答不上来的地方，坦白说「这块是同事负责的，我了解的是接口约定」，比现编一个理由安全得多。

**指标异动分析：先分层，再找原因**

这是数分面试最标准的题，答成一个固定框架就能稳定得分：第一步确认口径与真实性——指标定义有没有变、埋点有没有改、数据链路有没有延迟或重复上报，很多「异动」其实是口径问题；第二步做维度拆解——按时间（趋势、季节性、节假日）、按用户（新老客、渠道、地区、端）、按漏斗（曝光、点击、下单、支付各环节转化率），定位是哪一层、哪一群人出了问题；第三步区分内外部原因——内部看版本发布、活动结束、策略调整，外部看竞品动作、行业大盘、舆情；第四步给验证方案——需要什么数据、怎么排除混杂因素（比如同期对照、分群对比）。原帖作者总结的「先分层定位再找原因」正是这个顺序里最关键的一条：不定位到具体维度就直接猜原因，答案一定是散的。

**MECE 拆解与 clarify**

case 题别急着答，先问清楚三件事：指标的定义、时间范围与对比基准、以及这次分析的目的是什么（找原因还是给方案）。然后用 MECE 的原则拆：公式拆解（GMV = 用户数 × 下单率 × 客单价）、流程拆解（漏斗各环节）、维度拆解（人、货、场）。拆完挑一个分支深入，并说明「如果这一支没问题，我再看下一支」——面试官要的是可执行的排查路径，不是一次给出所有可能。

**手写 SQL：中等难度通常考三件事**

一道「中等难度」的 SQL 一般会在三个地方设卡：多表连接加过滤条件的位置（`where` 与 `on` 的区别，左连接别写错）、分组聚合后的筛选（`having` 与窗口函数的区别）、以及「每组取 Top N」「求连续 N 天」这类需要窗口函数的题（`row_number()` 配子查询过滤，或 `lag` 判断连续性）。写的时候边写边说思路，把边界条件（空值、重复记录、时间区间开闭）交代清楚，比闷头写完更有分。

**反问环节别空着**

可以问三类问题：这个岗位日常的分析产出主要服务哪些业务方、团队现在最想解决的指标问题是什么、新人前三个月通常接什么类型的需求。这些问题既体现你对业务的关注，也能帮你判断这个岗位是不是「取数岗」。原帖作者提到的「面完当天就有结果」属于流程特点，不代表每家公司都这样，别拿它当预期。
