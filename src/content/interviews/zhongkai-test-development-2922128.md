### 《面试题目》

1. 说说你的实习经历，包括你提到的那部分测试过程？
2. 功能测试流程是怎样的？（答完后追问）你还知道哪些功能测试？
3. 说说你对 Python 的理解，包括版本、框架这一块。
4. 你是后端实习，为什么来做测试？

### 《参考解析》

**功能测试流程怎么答**：按需求评审 → 测试计划 → 用例设计 → 用例评审 → 执行与缺陷跟踪 → 回归 → 测试报告与上线确认这条主线走，但不要只报步骤名。落到一个具体功能上过一遍，面试官才信你真做过：以登录为例，先用等价类划分出手机号合法、格式非法、位数边界几类输入，密码覆盖最小长度、最大长度、含特殊字符几档，再补验证码过期、连续错误锁定、并发登录这些分支，最后说明哪些用例进冒烟、哪些进回归。能被追问的细节是「这条用例为什么这么设计」，而不是步骤背得多熟。

**「还知道哪些功能测试」是把测试类型铺开**：按阶段分有单元、集成、系统、验收；按目的分有冒烟（快速判断版本能不能测）、回归（确认改动没伤到旧功能）、探索式测试（不写用例，按 charter 边测边设计）；按特性分有兼容性（机型、系统版本、浏览器）、界面、易用性、安装升级；性能与安全通常单列，严格说不属于功能测试。答的时候点一句「我实习里做得最多的是冒烟加回归加兼容性」，比单纯罗列名词更可信。

**对 Python 的理解分三层说**：语言层——解释型、动态类型、缩进即语法，GIL 决定了多线程跑 CPU 密集任务并不划算，要多进程或换实现；版本层——2 与 3 在 print 和字符串上是两套东西，3.6 起有 f-string、3.8 有海象运算符、3.10 有 match-case，实际项目以目标环境的解释器版本为准，不追新；工程层是测试岗真正被看的——pytest 的 fixture 与参数化、requests 造接口用例、selenium 或 appium 做 UI、allure 出报告，依赖用 venv 或 poetry 管，配置收在 pytest.ini 里。能说清 fixture 的作用域（function / class / module / session）基本就过关了。

**后端实习为什么转测试**：别说「后端太难」或「没拿到后端 offer」，这是自己给自己减分。给正向理由：实习里实际做过测试相关工作，发现自己对质量把关和问题定位更有兴趣；测试开发是用工程手段解决测试问题，后端经验正好用得上——写自动化框架、造数据、做压测、从日志和链路里定位线上问题，都是后端的基本功。再补一句对岗位的理解：测开不是点点点，而是把重复的验证沉淀成可维护的代码和平台。

**原帖里最值得借鉴的一条**：作者复盘时提到，面试中用豆包搜答案、结果声音没关被面试官听见。远程面试前的自检清单值得固定下来——麦克风与系统声音、共享屏幕的范围、浏览器标签与消息通知、备用网络。技术之外，这些细节最容易让本来能过的一场面试直接结束。
