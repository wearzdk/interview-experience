### 《参考解析》

**事件循环、闭包、this 这类题，答「机制 + 一个真实踩坑」才区分得开人。** 事件循环要讲清一次宏任务结束后清空整个微任务队列（微任务里产生的微任务也在同一轮清完），之后才可能渲染，所以微任务里写长循环会饿死渲染；`setTimeout` 的延迟只是「最早可执行时间」。闭包导致泄漏的典型场景是长生命周期对象持有闭包（全局事件监听、定时器、缓存），排查靠 Chrome Memory 面板的堆快照对比与 Allocation Timeline，看 Detached DOM 与持续增长的闭包数量。`this` 的四种绑定（默认、隐式、显式 call/apply/bind、new）里，箭头函数没有自己的 `this` 是因为它不绑定，取的是词法作用域的 `this`，也因此不能做构造函数。`new` 做四件事：创建空对象并设原型、把 `this` 绑上去执行构造函数、若返回对象则用返回值、否则返回该对象。

**Vue2 到 Vue3 的响应式替换，核心是「能不能拦截新增/删除属性与数组索引」。** `Object.defineProperty` 只能劫持已存在的属性，所以 Vue2 要靠 `Vue.set`/`Vue.delete` 补，数组则重写了七个方法；`Proxy` 代理整个对象，`get/set/deleteProperty/has` 都能拦，还支持 Map/Set 与懒代理（访问到才递归），初始化开销更小。追问通常会到 `v-if` 与 `v-for` 的优先级：Vue2 里 `v-for` 先执行，`v-if` 每轮都判断，浪费性能；Vue3 里 `v-if` 优先级更高，直接报错提示拆开写。`key` 的作用是帮 diff 复用节点，用 index 当 key 在列表插入/删除时会错位复用，导致状态串行（输入框内容跑到下一行）与多余的重渲染。

**性能优化被追问数字，是这场面试最值得记住的一课。** 面试官问的不是「你有没有优化」，而是「你怎么证明」。可用的口径有三层：实验室数据（Lighthouse 的 LCP/FCP/TBT，固定机型与网络限速）、真实用户数据（web-vitals 上报的 p75 LCP）、以及拆分后的归因（首屏 JS 体积从多少 KB 降到多少、首屏请求数、TTFB）。优化手段与指标要能对上：拆包 + 路由懒加载降的是首屏 JS 执行时间，图片懒加载与 `srcset` 降的是 LCP，preconnect/preload 降的是请求排队，SSR/SSG 降的是首屏渲染依赖 JS 的问题。「明显下降」这种表述在简历上等于没写，至少要有「LCP 从 4.2s 降到 2.1s（p75，移动端 4G）」这样的句式。

**只写过一个框架不致命，讲不清差别才致命。** 面对「进来要写 React」这类问题，正确的姿态是承认差异并说明迁移成本在哪里：Vue 是响应式追踪 + 模板编译，React 是不可变数据 + 状态驱动重渲染，两者在「状态怎么组织、副作用放哪、如何避免重渲染」上的心智不同，但把需求拆成组件、管理状态流转的能力是通用的。能说出自己已经补到哪一步（hooks 与组合式 API 的思路接近、`useMemo`/`memo` 对应 `computed` 的差别），比空喊「我学得快」有效。

**手写三件套的评分点在边界。** 防抖要区分立即执行与延迟执行、要能取消防抖、要透传 `this` 与参数；深拷贝要处理循环引用（`WeakMap`）、`Date`/`RegExp`/`Map`/`Set`、以及不可枚举属性与原型；`Promise.all` 要按索引保序、任一 reject 就整体 reject、空数组立即 resolve。现场写的时候先把边界条件念出来，面试官往往会顺着边界继续追问，这比一次写对更能体现工程素养。
