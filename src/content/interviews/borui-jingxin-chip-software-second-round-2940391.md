### 《参考解析》

**32 位与 64 位描述的是通用寄存器和指针宽度，不等于地址总线宽度。** 32 位处理器一次能处理 32 位整数、指针占 4 字节，虚拟地址空间理论上限为 2³² 即 4GB；64 位处理器寄存器与指针为 64 位，但实际虚拟地址往往只用 48 位或 52 位（ARMv8-A 常见 48 位），物理地址宽度又是另一组参数，ARMv7-A 的 LPAE 可到 40 位，ARMv8 可到 48 位以上。ABI 也随之不同：LP64 下 long 与指针为 8 字节，ILP32 下为 4 字节，移植时结构体布局、对齐、打印格式符都会变。32 位系统的 4GB 虚拟空间通常划分为用户空间与内核空间（Linux 常见 3G/1G 或 2G/2G），内核空间里再放 vmalloc、直接映射区、外设 MMIO 映射区与保留区；物理地址空间则包含 DRAM、Boot ROM、Flash、片上 SRAM、外设寄存器、中断控制器与保留空洞。

**超过 4GB 的工程处理，本质是把「必须常驻映射」和「可按需映射」的资源分开。** 可选手段有几类：启用 LPAE 或 PAE 扩展物理地址宽度，让 32 位虚拟地址能够映射到 4GB 以上的物理页；把大块 DRAM 放到高端，用 highmem 或按需 `ioremap`/`mmap` 临时映射；把外设 MMIO 窗口通过地址重映射搬到高物理地址，仅在访问时映射进内核虚拟空间；关闭或合并未使用的外设窗口，缩小 MMIO 占用；在多核或 AMP 场景下按核划分地址窗口。优先动外设而不是压缩内存，原因在于外设窗口的地址往往由 SoC 的地址译码与重映射寄存器决定、可以搬移或按需映射，而 DRAM 需要连续大块、压缩会直接损失容量并影响性能；此外大量外设窗口是稀疏的、并不需要同时驻留在虚拟地址空间，搬移的工程代价小于削减内存带来的系统性影响。相反，若外设地址在硅片里固定死、无法重映射，就只能调整内存布局或启用 PAE。

**SMP 靠硬件一致性加软件同步，AMP 靠分区与显式维护。** SMP 下所有核共享同一地址空间，CPU 通过 CCI/CCN 与 ACE 维护缓存一致性，但一致性只保证「最终能看到正确值」，不保证访问顺序与原子性。软件层要用原子指令（LDXR/STXR、LSE 原子操作）做计数器与标志位，用自旋锁保护临界区，用 DMB/DSB/ISB 约束内存访问顺序；每个核的栈、per-CPU 变量、中断状态必须独立，频繁写的共享变量要按 cache line 对齐，避免伪共享导致总线流量飙升。关中断只能挡住本核，挡不住其他核，所以自旋锁必须配关抢占或关中断使用。AMP 下每个核跑独立 OS 或裸机，通常没有硬件缓存一致性：共享内存要么映射为 non-cacheable，要么在写后 clean、读前 invalidate，并且按物理地址或统一虚拟地址维护；核间通信靠 mailbox、IPI、硬件信号量或共享环形缓冲区，数据所有权按核划分，避免两个核同时写同一块内存；跨核访存同样需要内存屏障，编译器的重排与 CPU 的重排都要考虑。

**APB3 是两相握手的低速外设总线。** 主要信号包括 `PCLK`、`PRESETn`、`PSEL`、`PENABLE`、`PADDR`、`PWRITE`、`PWDATA`、`PRDATA`、`PREADY`、`PSLVERR`。一次传输分 setup 与 access 两个阶段：setup 阶段 `PSEL` 拉高、`PENABLE` 为低，主设备给出地址与控制信号；下一个时钟进入 access 阶段，`PENABLE` 拉高，从设备通过 `PREADY` 插入等待周期，读数据 `PRDATA` 或写完成在 `PREADY` 有效的最后一拍采样，`PSLVERR` 同样在此时有效表示错误。APB 不支持流水线、没有 burst，最小传输为两个周期，因此带宽低、时序简单，适合寄存器访问、UART/I2C/GPIO 这类慢速外设；高速数据通路用 AXI 或 AHB，中间通过 AXI-to-APB 桥转换。调试时要重点看 `PREADY` 长期为低导致的挂死、`PSLVERR` 未处理、以及桥的地址窗口配置错误。

**Normal 与 Device 的区别在缓存、推测与访问顺序。** Normal Memory 允许缓存（write-back/write-allocate、write-through、non-cacheable 等属性）、允许推测读与预取、允许非对齐访问与访问合并，按 shareability 决定是否跨核一致，适合 DRAM、代码段、栈和普通数据。Device Memory 不允许缓存、不允许推测访问，具有强顺序约束（ARMv8 细分为 Device-nGnRnE、Device-nGnRE、Device-GRE，约束依次放宽），要求自然对齐、访问宽度与寄存器定义一致，通常不支持独占访问，适合 MMIO 寄存器、FIFO、中断清除、门铃寄存器这类有副作用的地址。把设备寄存器配成 Normal 且可缓存，会出现读到旧值、写被合并或重排、状态位读一次就被清掉等问题；反过来把普通内存配成 Device，会损失大部分性能。实际 BSP 里还要注意页表项属性、MAIR 配置、以及映射粒度（块映射与页映射）是否与外设窗口对齐。

**嵌入式设计模式要落到资源受限与中断上下文。** 状态机适合协议解析、设备控制、业务流程这类有明显状态迁移的场景：用表驱动把「当前状态 + 事件」映射到「下一状态 + 动作」，比层层 `if/else` 更易审查与测试，也方便画状态迁移图做覆盖。观察者模式适合传感器数据分发、事件通知、UI 刷新：被观察者维护回调列表，状态变化时通知订阅者，解耦生产者与消费者；嵌入式中要注意回调在中断里执行时的可重入与耗时，通常把中断里的通知降级为投递事件到队列，由任务上下文处理。其他常用模式包括用函数指针表实现策略切换、用命令队列串行化硬件操作、用单例管理唯一的硬件资源、用 RAII 管理 C++ 中的锁与文件句柄。判断标准不是模式名字，而是它是否减少了耦合、是否能在无堆、无异常、可静态分析的前提下工作。
