### 《参考解析》

**volatile 与寄存器操作。** `volatile` 告诉编译器这个变量可能被程序之外改变，禁止把它缓存到寄存器、禁止删除「看似无用」的读写、禁止重排相对顺序。必须加的场景：ISR 与主循环共享的标志/缓冲区、映射到硬件的寄存器地址、多核间通过内存共享的标志（这里还要配内存屏障）。中断里改的标志如果不加 volatile，主循环可能一直用寄存器里的旧值，循环永远退不出去。注意它不是原子性保证，计数器仍要关中断或原子操作。

**static 与 const。** `static` 修饰局部变量：存到静态区，生命周期贯穿程序、只初始化一次，函数重入时不再初始化；修饰全局变量/函数：链接属性变为内部链接，只在本编译单元可见，避免命名冲突。`const` 修饰谁取决于 `*` 的位置：`const char *p` 是指向常量的指针（内容不可改，指针可改），`char *const p` 是常量指针（指针不可改，内容可改），`const char *const p` 两者都不可改。

**定点与浮点。** 定点用整数表示，隐含一个缩放因子（如 Q15 表示 1 位符号 + 15 位小数），运算全是整数加减乘移位，没有浮点单元也能跑、延迟确定、无舍入抖动；浮点表示范围大、精度按有效位算、代码可读性好，但在无 FPU 的 MCU 上软件浮点很慢且耗时随数值变化，破坏实时性。云台控制环路要求在固定周期内完成、且需要可预测的延迟，所以常用定点；同时浮点累加的舍入误差在长时间积分时也会积累，定点反而可控（配合饱和与舍入处理）。

**位操作。** 置位 `reg |= (1u << n)`；清零 `reg &= ~(1u << n)`；翻转 `reg ^= (1u << n)`；多位用掩码 `reg = (reg & ~MASK) | (val << SHIFT)`。对硬件寄存器要读-改-写，注意有些寄存器读清、写一清零，且中间不能被中断打断（关中断或用位带操作）。

**中断流程。** 外设触发 → 中断控制器（NVIC/GIC）记录挂起位、比较优先级 → 若优先级高于当前执行且未被屏蔽，CPU 完成当前指令、保存现场（部分寄存器压栈）→ 查向量表跳到 ISR → 执行 → 清除中断标志（漏清会反复进中断）→ 恢复现场返回。ISR 里要短：只做取数据、置标志、清中断，重活丢给任务或 DMA 完成回调。

**DMA 与冲突。** DMA 由独立控制器搬数据，CPU 不参与逐字节拷贝，省下 CPU 周期、能配合外设做连续采集。冲突来自总线与缓存一致性：如果 CPU 和 DMA 访问同一块内存且该内存被 cache 缓存，DMA 写内存后 CPU 可能读到 cache 里的旧数据（或 CPU 写的数据还在 cache 未落内存）。处理办法：把 DMA 缓冲区放到 non-cacheable 区域、或用 `SCB_CleanInvalidateDCache_by_Addr` 做 clean/invalidate、或用双缓冲（乒乓）让 CPU 处理 A 区时 DMA 写 B 区，处理完再交换。

**I2C 与 SPI。** I2C 两根线（SCL/SDA）、支持多主多从、有地址寻址和 ACK、速率常见 100k/400k/1M，适合低速多传感器的板级总线；SPI 四根线（SCK/MOSI/MISO/CS）、全双工、无寻址靠片选、速率可到几十 MHz，适合高速短距离。云台上的 IMU 常用 SPI（采样率高、延迟低、时序简单），磁力计/温度等低速器件走 I2C，实际按器件手册与总线负载决定。SPI 四种模式由 CPOL（空闲电平）和 CPHA（采样沿）组合：模式 0 空闲低、上升沿采样；模式 3 空闲高、上升沿采样；模式 1/2 是下降沿采样，必须和从机手册一致。

**滑动窗口均值与大窗口优化。** 定长环形缓冲区 + 维护累加和：加入新样本时 `sum += new - old`，输出 `sum / N`，复杂度 O(1)，不用动态内存。大窗口时可以用两级滤波（先做小窗口均值再做二级均值）、或指数滑动平均（`y = y + (x - y) / N`，内存 O(1) 且等效长窗口），代价是对突变响应变慢。浮点长期累加会有舍入误差累积，改进是用整数累加（定点采样）、定期用 Kahan 求和校正、或每隔一段时间用窗口内数据重算一次。

**云台增稳。** 核心是「测量姿态 → 计算补偿 → 驱动电机抵消扰动」。陀螺仪测角速度，积分得到角度变化；加速度计测重力方向，提供长期无漂移的倾角参考；两者用互补滤波或卡尔曼/ Mahony 融合出姿态。控制器把目标姿态与实际姿态的误差送入 PID（外环角度、内环角速度），输出力矩/电流给电机，同时前馈补偿手抖的高频分量。增稳的关键在于带宽与延迟：滤波器延迟太大会导致相位滞后，补偿反而震荡。

**陀螺仪漂移与加速度计噪声。** 陀螺仪积分误差来自零偏（bias）随温度和时间变化、以及量化噪声，积分后变成角度漂移，长时间必然发散，所以需要加速度计或磁力计提供绝对参考做校正。加速度计测的是比力，运动时的线性加速度会混进重力方向，振动和抖动会让倾角估计剧烈跳动，所以它只适合低频参考，需要低通滤波；单用陀螺仪会漂、单用加速度计会抖且怕振动，融合才能兼顾动态与长期稳定。

**图像链路与 MIPI。** sensor 感光 → 内部 ISP 或 SoC 的 MIPI CSI 接收 → DMA 写入帧缓冲 → 图像处理（去马赛克、降噪、AWB/AE、缩放、格式转换）→ 编码或送显示/算法。MIPI CSI-2 是差分串行、带时钟通道和多条数据 lane，速率高、线少、抗干扰好、支持长距离排线；并口是并行多位 + 像素时钟，线多、速率受限于时序 skew，适合短距离低速。图像传输爱用 YUV 是因为人眼对亮度敏感、对色度不敏感，YUV 可以色度下采样（4:2:0 只保留 1/4 色度数据）在同等主观质量下大幅降低带宽，而且亮度分量可直接用于很多算法。

**零拷贝。** 让数据在模块间传递时不做多次内存拷贝：用 DMA 直接把外设数据写进共享缓冲区、指针传递而非值传递、用内存池预分配避免频繁申请、用 `mmap` 让用户态直接访问驱动缓冲区、或硬件提供 CSC/scaler 直接在原地转换。多模块间用环形容器 + 引用计数，谁用完谁释放，避免一份数据在 pipeline 里被复制三四次。

**实时性与优先级。** 硬实时是错过截止时间就产生不可接受后果（飞控、电机控制），软实时是偶尔超时只影响体验（音视频播放）。云台控制环路属于硬实时（或至少是强实时），控制周期抖动会直接反映为抖动和异响。保证不超时：控制任务放最高优先级、周期由硬件定时器驱动、任务内只做必要计算（三角函数查表、定点运算）、避免在控制任务里做内存分配和阻塞 IO、用 DMA 卸载数据搬运、测算最坏执行时间（WCET）并留余量。中断延迟由「中断屏蔽时间 + 当前指令执行完 + 现场保存 + 向量跳转 + 高优先级抢占」组成，降低手段是缩短临界区关中断时间、提高控制中断优先级、把耗时 ISR 拆成上半部/下半部。中断嵌套按优先级抢占，优先级高的 ISR 必须更短，否则会拖住所有低优先级中断的响应。

**多任务优先级与定时器。** 一般控制环路最高（硬实时、周期最短），数据采集次之（要被控制消费），图像处理最低（可丢帧、可用空闲算力）。用固定优先级抢占式调度并做优先级反转防护（互斥量优先级继承）。精确采样周期用硬件定时器触发 ADC/DMA 或直接触发控制中断，不要用软件延时或普通 task delay；时钟源不准（晶振误差、温漂）会导致采样率偏移，积分出的角度和滤波器系数都会偏，长期还会与外部时间不同步，必要时用外部高精度时钟或周期性校准。
