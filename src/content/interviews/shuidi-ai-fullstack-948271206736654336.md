### 《参考解析》

**LangGraph 与 DAG**：LangGraph 把流程建模成状态图，节点是函数或模型调用，边定义流转，支持条件边、循环、并行与中断；核心是一个可持久化的状态对象，节点读取状态并返回更新，checkpointer 保存每一步，支持恢复与人工介入。DAG 只允许无环，适合一次性的任务编排；Agent 需要根据观察结果回到前面的步骤，所以必须有环，这是两者的本质区别。底层执行是调度器按边推进节点、合并状态、在中断点持久化，循环要有最大步数与终止条件。

**MCP Server 开发**：MCP 是模型与外部能力之间的协议，Server 暴露 tools、resources、prompts 三类能力。用 Python 或 TypeScript 的官方 SDK 定义工具名、描述与 JSON Schema 参数，实现处理函数，通过 stdio 或 HTTP/SSE 传输；资源用于只读数据，工具用于动作，要区分权限与幂等。实现机制是客户端把工具清单与 schema 注入模型上下文，模型返回工具调用，客户端执行后把结果回传。Java 生态可用 Spring AI 或手写 JSON-RPC。

**视频理解**：先做预处理——抽帧、抽音频、场景切分、语音转写、OCR，得到带时间戳的文本与关键帧；再建立索引，把转写段落与帧描述向量化，保留时间戳与来源；用户提问时先检索相关片段，把文本、关键帧与时间范围一起交给多模态模型回答，并附上时间点引用。长视频要分层摘要，避免把整段视频塞进上下文；需要精确到画面时按时间范围回取帧。

**微服务与限流**：常见组件包括网关、注册中心与配置中心（Nacos）、RPC（Dubbo/OpenFeign）、消息队列、缓存、数据库、链路追踪与日志。限流可以放在网关做全局限流，也可以在服务内用 Sentinel/Resilience4j 做接口级限流，算法有令牌桶、漏桶、滑动窗口、并发数限制；限流要配合降级与熔断，返回明确的错误码与重试建议。OpenFeign 常与 Nacos 服务发现、Spring Cloud LoadBalancer、Sentinel、Micrometer/Tracing 一起使用。

**MQ 与 RPC 的选型**：RPC 适合同步请求-响应、低延迟、强依赖的调用，调用方需要立刻拿到结果；MQ 适合异步解耦、削峰填谷、广播与最终一致，生产方不关心何时被消费。判断标准是「是否需要立即得到结果」「是否能接受最终一致」「流量是否突发」「是否多方消费」。两者可以组合，比如下单走 RPC 校验库存，后续通知走 MQ。

**给 AI 编程工具加约束**：明确技术栈与版本、目录与分层、接口与数据模型、错误处理与日志规范、测试要求、禁止改动的文件、依赖引入规则、代码风格与提交前检查；要求先给方案再写代码，改动尽量小，涉及数据库与配置的变更要单独说明。验证靠编译、类型检查、单测与 review，不靠模型自述。

**职业方向**：结合做过的事情给一条主线，比如「AI 应用工程，偏 Agent 与 RAG 的落地」，并说明下一阶段想补的能力（系统工程、评测、模型原理）。不要只说「想做 AI」，要给具体场景与理由。
