### 《面试题目》

1. 自我介绍（按准备的 PPT 讲，十几分钟）。
2. 介绍 OpenVINS 的全部流程。
3. IMU 初始化的具体细节是什么？
4. 滤波和视觉前端具体是怎么实现的？
5. FEJ（First-Estimate Jacobian）的细节是什么？
6. OpenVINS 和 VINS-Fusion 有什么区别？
7. 两者滑窗 marginalization 的细节分别是什么？
8. 使用开源框架时，你自己做了哪些改动？（会继续追问细节）

### 《参考解析》

**OpenVINS 的完整流程。** 它是一个基于滤波的视觉惯性里程计（MSCKF 系的 EKF-SLAM 变体），主线可以按「初始化 → 传播 → 观测 → 更新 → 状态管理」讲。启动阶段先做静态初始化：用一段静止窗口估计 IMU 的陀螺零偏与重力方向，据此把首帧相机位姿对齐到重力坐标系，并给出初始速度与协方差；随后进入运行循环——IMU 每个测量到来时按运动学做状态传播并推进协方差（误差状态形式），相机帧到达后由视觉前端提取并跟踪特征，新特征按是否加入状态向量分成 MSCKF 特征（只用作观测约束，三角化后投影）与 SLAM 特征（进入状态向量、可长期复用），最后统一做量测更新并用卡方检验拒掉外点（含 RANSAC 与门控）。状态向量典型包含 IMU 状态（位姿、速度、零偏）加一个位姿克隆滑窗（历史相机位姿），所以「克隆 + 边缘化旧克隆」就是它控制规模的方式。要能讲清这个设计带来的一增一减：加了历史位姿让延迟观测（多个时刻同时看到同一特征）能被正确利用，代价是状态维度随滑窗增长、计算量上升。

**IMU 初始化的细节。** 静态初始化的核心是三件事：重力方向、陀螺零偏、以及初始速度/位姿与协方差。常用做法是采集一段静止数据，陀螺均值作为零偏初值（注意静止检测要可靠，人体手持或平台上有人走动都会污染均值），加速度计均值方向作为重力方向，并据此构造世界系与 IMU 系的旋转；由于加速度计此时只能观测到重力方向而无法观测偏航，偏航通常规定为与首帧相机朝向一致，而这一项的初始协方差要设得比较大以反映其不可观测性。速度初值一般设为零，位置设为零并给一个合理的协方差。初始化期间要冻结状态或者用特殊的传播模型（不能一边估计零偏一边按未标定的零偏积分），同时把初始化阶段的协方差设好，否则后续滤波器会过度自信。动态初始化（边走边初始化）更实用也更难：需要联合估计速度、重力方向与尺度，常见做法是视觉-惯性对齐（VINS 系列的做法），在几秒的滑动窗口内解一个最小二乘。面试被追问时最好能说明「哪些量可观、哪些不可观」——绝对位置与偏航不可观，尺度需要足够激励（足够的加速度变化）才能恢复。

**滤波与视觉前端的实现细节。** 视觉前端负责「从图像到可用的量测」：特征提取（FAST/Shi-Tomasi + 金字塔）、跟踪（KLT 光流是最常见的选择，因为快且稳定）、特征管理（网格化分布保证空间均匀、按跟踪长度与视差决定保留或丢弃、控制总量在计算预算内）、以及外点剔除（前后向光流一致性检查、RANSAC、与惯导预测做投影匹配的门控）。前端的输出是特征轨迹，量与频率要与后端解耦——前端慢不能让滤波器停等，所以要做时间戳对齐与延迟补偿：把观测按其曝光时刻对应到 IMU 传播出的位姿（或保留一段位姿历史做插值），否则快速运动时会出现系统性残差。滤波器侧的实现要点是误差状态（用 3 维最小参数表示旋转误差，避免四元数过参数化导致协方差奇异）、数值上保持协方差的对称性与正定性（做 Joseph 形式更新与周期性对称化）、以及量测雅可比里对特征位置的处理（三维点还是逆深度参数化各有取舍）。这些细节是压力面里最容易被问到哑口的地方，答不出来时给出「我知道这里要处理，但项目里用的是框架默认实现」也比硬编更安全。

**FEJ 与可观性：为什么需要它。** EKF 的一致性问题是：理论上系统有不可观方向（整体平移、偏航），这些方向上的不确定性不应被虚假地降低，但标准 EKF 在每次更新时都按当前估计值重新线性化，等于在不可观方向上引入了不存在的信息，结果是协方差越来越小、滤波器过度自信、估计在后期出现漂移而置信区间仍很窄。FEJ 的做法是：状态传播与所有量测雅可比都固定在同一个线性化点（通常是该状态第一次被估计时的值，即 first estimate），使不同时刻的雅可比对同一状态保持一致，从而保留可观性矩阵的正确零空间。OpenVINS 里可以直接配置是否启用（FEJ 与 OC-EKF 这类可观性约束方法），实测结论是长轨迹、大尺度下能明显改善一致性，代价是实现复杂、需要为每个状态保存线性化点，且如果线性化点与真值偏差大，收敛后的线性化误差也会带进来。回答时要讲清「一致性」这个词的含义——不是精度更高，而是协方差与真实误差匹配，这对下游融合（与 GPS/激光/地图对齐）非常关键。

**OpenVINS 与 VINS-Fusion 的架构差异。** 最本质的差异是后端机制：OpenVINS 是滤波（MSCKF/EKF-SLAM，状态含 IMU + 相机位姿克隆，特征大多不进状态），VINS-Fusion 是滑动窗口优化（把滑窗内的 IMU 状态、特征参数一起做非线性最小二乘，用边缘化把出窗的信息转成先验）。由此派生的差别：滤波是增量式、每步的代价固定且低（实时性好、对 CPU 友好），但没有迭代重线性化，对线性化点敏感、需要 FEJ 这类技巧维持一致性；优化能做多次迭代、精度通常更高、更容易融入闭环与全局优化，但计算量随窗口增长、需要严格管理边缘化与先验。工程表现上，OpenVINS 更容易在低算力平台跑，代码结构对状态与协方差的管理非常显式，适合作为研究基线；VINS-Fusion 的精度与鲁棒性在常见场景更好，但参数与先验处理更容易踩坑（先验一致性、数值退化）。另外两者的特征处理方式也不同：OpenVINS 明确区分 MSCKF 与 SLAM 特征，VINS-Fusion 广泛使用逆深度参数化并在滑窗内统一优化；标定处理上，VINS-Fusion 支持在线外参与时延标定，OpenVINS 对相机-IMU 外参与时延的在线估计也在持续完善。

**滑窗 marginalization 的细节。** 优化的滑窗必须把要移出的状态的信息保留下来，否则等于丢弃历史观测、估计会跳变。标准做法是 Schur 补：把要边缘化的状态与被保留的状态分块，对信息矩阵做消元，得到一个只含保留下状态的条件概率，作为下一轮优化中的先验因子（在 g2o/Ceres 里通常实现为一个自定义的「先验/边缘化」约束）。几个关键工程点：第一，先验的线性化点必须固定在边缘化发生的那一刻，之后不能随优化重线性化，否则会引入虚假信息（这正是优化版里的一致性来源，与滤波里的 FEJ 是同一类问题的两条解法）；第二，边缘化会带来 fill-in，原本稀疏的矩阵被填满，所以要先做变量排序或用稀疏结构管理来限制复杂度；第三，被边缘化的特征如果只被滑窗内少数帧观测，可以只保留其约束而不保留参数（Schur 补掉特征更常见，通常先把特征边缘化掉再处理帧），顺序不同计算量差别很大；第四，边缘化只应移除「足够老且信息已充分」的状态，并且要配合关键帧选择策略（视差、时间间隔、信息量）避免频繁边缘化带来的信息丢失与漂移。理解到这个层次，才能回答「为什么先验不能重线性化」「为什么特征要先消掉」这类追问。

**被追问「你改了什么」时怎么答，以及压力面的复盘。** 改开源框架的动机要落在具体问题上，而不是「为了学习」：例如前端在纹理弱或强光场景跟踪丢失，改成网格化特征管理 + 更严的外点门控；初始化在运动剧烈时失败，改成加静止检测与重试的状态机；时延未标定导致高速运动下残差偏大，加入相机-IMU 时延的在线估计；或者为了在低算力平台上跑，把协方差更新的热点改成稀疏/分块计算。回答结构建议固定为「基线表现 → 失败现象 → 定位到代码里的哪一段 → 改法与依据 → 指标变化（ATE/RPE、跟踪成功率、耗时）」，有对照实验和数据才能顶住追问。至于这类压力面，作者自己的复盘其实很准：题目没有超纲，问题在于知识是「知道但讲不成体系」。可操作的准备方法是对每个核心模块写一份「三层讲稿」——三十秒的结论、两分钟的原理、以及一份能画出来的数据流图；把 OpenVINS/VINS-Fusion 的初始化、传播、量测、边缘化四段的顺序与依赖关系背成固定的叙事，遇到追问就先定位到「这是四步里的哪一步」，逻辑就不容易散。项目 PPT 讲十几分钟也要压缩，把时间留给「难点与取舍」，面试官真正想听的是你的判断而不是流程复述。
