### 《面试题目》

1. 实习里做了什么？（问得比较浅，没有追问）
2. 为什么用 RabbitMQ 而不是 RocketMQ？
3. RocketMQ 的事务消息是怎么实现的？
4. DDD 的分层是怎么划的？
5. 贫血模型和充血模型有什么区别？
6. MySQL 优化有哪些手段？
7. 分库分表怎么做的？
8. AOP 是怎么用的、在哪注入？

### 《参考解析》

**「为什么用 RabbitMQ 而不是 RocketMQ」这题答「公司本来就用」是下策**，要能给出可比较的维度：RabbitMQ 基于 AMQP、路由灵活（exchange 的 direct/topic/fanout 能满足复杂的多播与条件路由）、单机吞吐量级在万级、Erlang 生态运维门槛偏高但延迟低且稳定；RocketMQ 是阿里系、天然支持事务消息、延迟消息、消息回溯和堆积（百万级堆积不影响性能），适合订单、支付这类需要「发出去一定不丢、还能查」的场景。真实的选型理由通常是「业务量与团队栈」：日均消息量不大、路由规则复杂就选 RabbitMQ；要做削峰、事务消息、海量堆积就选 RocketMQ。补一句「Kafka 适合日志与流式，不适合单条消息的可靠投递与延迟消息」，把三家摆在一起说，比单点比较更像做过决策。

**RocketMQ 事务消息的关键是「半消息 + 回查」**：生产者先发一条对消费者不可见的半消息，Broker 落盘成功后返回 OK，生产者在本地事务里执行业务（比如扣库存、写订单），提交则把半消息转为可投递，回滚则删除；如果提交/回滚那一步丢了（进程挂了、网络断了），Broker 会定时回查生产者的本地事务状态接口，根据结果决定投递还是丢弃。它解决的是「本地事务与消息发送的原子性」，但消费端仍可能重复消费，所以消费侧必须幂等——这两句话要一起说，缺一句就会被追问「重复消费怎么办」。

**DDD 分层的核心是依赖方向**：接口层（interfaces，controller/consumer 负责协议转换）→ 应用层（application，编排用例、事务边界、不发业务规则）→ 领域层（domain，实体、值对象、聚合、领域服务、仓储接口）→ 基础设施层（infrastructure，仓储实现、MQ、缓存、外部接口）。依赖只能向内，领域层不依赖 Spring 和数据库，靠依赖倒置把仓储接口定义在领域层、实现放在基础设施层。答的时候最好结合自己项目说清「哪几个聚合、聚合根是谁、跨聚合怎么协作（领域事件）」，只背分层名字很容易被追问「那你的 Service 里放了什么」。

**贫血模型 vs 充血模型**：贫血是实体只有 getter/setter，业务逻辑全堆在 Service，好处是简单、和 ORM 贴合，坏处是逻辑散落、难以保证不变量；充血是实体带行为（`order.pay()` 内部校验状态流转），Service 只做编排，好处是不变量收敛在聚合内、可测试，坏处是对设计能力要求高、和 CRUD 框架不契合。面试里答「按场景选」并给出理由最稳：核心域（订单、支付、库存）用充血，边缘的配置、字典表用贫血。

**MySQL 优化按「SQL → 索引 → 表结构 → 架构」四层说**：先看慢查询日志定位，`explain` 看 type、key、rows、Extra（出现 filesort、temporary 要警惕）；索引上做覆盖索引、联合索引最左前缀、避免函数与隐式转换、控制索引数量；表结构上收敛字段宽度、大字段拆表、用合适的数据类型；再往上才是读写分离、缓存、分区、分库分表。分库分表要讲清三件事：切分键怎么选（尽量让高频查询带分片键，否则要读扩散）、路由与聚合怎么做（ShardingSphere 中间件或客户端分片，跨库 join 与分页要改写）、扩容与数据迁移怎么不停机（成倍扩容 + 双写 + 校验 + 切流）。这题最容易翻车的是只答「按用户 ID 取模分 16 库」，一问「那按订单号查怎么办」「扩容怎么办」就空了。

**AOP 那半句「在哪注入」问的是代理时机**：Spring 在 Bean 初始化后置处理阶段（`BeanPostProcessor.postProcessAfterInitialization`）判断是否需要代理，需要就生成 JDK 动态代理（有接口）或 CGLIB 子类代理，把切面织进去。所以能拦到的只有「经过代理对象的方法调用」——同类内部 `this.method()` 自调用不走代理、`private`/`final` 方法不被 CGLIB 覆盖、对象不是 Spring 管理的（自己 new 的）也没有切面。日常用法是 `@Aspect` + `@Around` 做日志、耗时统计、权限校验、分布式锁，事务 `@Transactional` 本身也是 AOP。这题如果只答「用注解加个切面」，追问一句自调用失效就答不上来了。

**最后提醒节奏**：25 分钟问完 8 个问题，平均三分钟一个，说明面试官在快速扫你的知识面宽度而不是深挖某一项。这种场次里，每个问题给出「结论 + 一个理由 + 一个项目例子」的三段式，比在一个问题上讲十分钟更加分。
