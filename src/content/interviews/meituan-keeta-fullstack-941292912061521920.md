### 《参考解析》

**选 React Native Web 通常是为了复用业务逻辑和组件，但它的边界要讲清楚。** 优势是一套 React 代码同时跑 Native 和 Web，团队可以共享状态管理、接口层和大部分 UI 逻辑；代价是 Web 端的 DOM、CSS、SEO、首屏和可访问性与原生不同，某些原生能力需要降级或写平台分支。回答“为什么不用纯 H5”时，可以从多端一致性、原生体验和长期维护成本讲；回答“为什么不用原生双端”时，则要承认人力成本和迭代速度的约束。适配问题要举具体例子，比如滚动容器、安全区、字体、图片加载、路由、手势冲突和样式单位，别只说“做了兼容”。

**端外拉起要区分 Universal Link、App Link 和自定义 scheme。** 理想链路是：页面先判断是否在端内，端外点击时尝试打开通用链接，系统没有安装或未匹配时回落到下载页/网页版；不能直接依赖自定义 scheme，因为浏览器和微信等容器会拦截，且失败时没有可靠回调。要处理唤起超时、用户取消、已安装但版本过低、以及 iOS/Android 的差异。设计还原则不能只靠肉眼，最好有设计 token、组件库约束、截图对比和关键页面的视觉回归；图层问题要理解合成层、z-index、transform、opacity 和滚动容器如何产生新的 stacking context，很多“还原不了”其实是层叠上下文或字体度量差异。

**AI coding 题考的是协作方式，不是让 AI 替你写完。** 拿到题目先拆需求和边界，再让 AI 生成骨架或测试，自己负责关键逻辑、异常处理和最终审查。平时用 AI 可以覆盖样板代码、单测、类型定义、重构建议和报错定位，但必须能解释每一行，关键路径要自己写并跑测试。被问生成率时，不要报一个虚高的比例，可以说“简单 CRUD 和样式大概一半左右，核心逻辑和并发/错误处理仍以手写为主”，再补你如何做 code review 和回归。

**快排要写对分区和递归边界。** 选基准后把小于基准的放左边、大于的放右边，递归处理左右区间；工程实现常用随机基准或三数取中避免有序数组退化，小区间可以切插入排序。边界要处理空数组、单元素、重复元素，递归终止条件是 `left >= right`。面试里现场没调通很常见，先保证逻辑正确，再检查比较符号、交换条件和递归参数。作者复盘“只差一个等号”，说明手写代码后要用小用例手动走一遍，别急着提交。
