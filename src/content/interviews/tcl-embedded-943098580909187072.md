3. 单核运行的情况下，memset 和 memcpy 的实现应该比较简单：给定指针和长度做设置或复制，你认为难点在哪里？

### 《参考解析》

**无标准库实现 memset/memcpy 的难点**：没有 libc 意味着不能依赖编译器把循环优化成库调用。真正的难点有四条：按机器字长搬而不是逐字节搬（头部对齐、按 `uint64_t` 批量、尾部收尾），否则性能差一个量级；源与目的重叠时要像 `memmove` 那样判方向（`dst < src` 从前向后，否则从后向前）；不能假设地址可随意读写，寄存器区、只读段、设备内存要分开处理；0 字节与非对齐长度的边界。BootLoader 里没有标准库，通常是因为 C 运行环境还没建立——栈、`.bss` 清零、重定位都没就绪。

**BootLoader 从单核到多核**：Boot ROM 只拉起一个核（BSP），它初始化 DRAM、把镜像搬到运行地址、建好栈之后，再用平台相关方式唤醒从核——ARM 上常见 spin-table（从核在固定地址轮询 release 标志，主核写入口与标志后 `sev`）或 PSCI 的 `CPU_ON`（走 SMC/HVC 进固件）。唤醒前要给每个核准备独立栈与入口参数，处理 cache 一致性与内存屏障，从核起来后各自初始化 MMU、GIC 与定时器。

**物理地址到虚拟地址的切换**：关键在于切换瞬间 PC 不能跳飞。先建页表（内核直接映射、外设区用设备内存属性），配置 `TTBR`/`MAIR`/`TCR`，`dsb` 后打开 MMU；打开时 PC 所在代码必须落在恒等映射区，等跳到高地址虚拟空间后再撤掉恒等映射并刷 TLB。链接地址与加载地址不一致时还要先做重定位。

**多核地址空间与内核共享映射**：每个核的 MMU 独立，但同一进程的线程共享一套页表，所以同进程在不同核上看到的虚拟地址是同一份；不同进程各自独立（ASID 区分）。内核空间在每个进程页表里都映射同一份，是为了系统调用与中断时不必切页表；代价是 Meltdown 这类侧信道能读到内核数据，缓解手段是 KPTI，每次陷入内核都要换页表，性能有损耗。

**栈指针与 Ring Buffer**：SP 指向当前栈帧（ARM 满递减栈，压栈先减 SP），返回地址存在 LR 或栈帧里，函数返回时弹回 PC、SP 加回帧大小；TP 指向 TLS 基址，切换线程要一起换。Ring Buffer 的线程安全取决于生产者消费者数量：单生产单消费可用读写索引加 acquire/release 做无锁，多生产者要 CAS 抢位或加锁；索引与数据分处不同 cache line 避免伪共享，容量取 2 的幂用位与代替取模。三级流水线把不同速率的环节解耦，慢的一级不会直接阻塞快的一级，吞吐由最慢一级决定；代价是延迟与内存占用，级数不是越多越好。
