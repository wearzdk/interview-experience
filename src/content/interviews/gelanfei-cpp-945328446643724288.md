### 《参考解析》

**内联函数与宏**：相同点都是「展开到调用处、避免函数调用开销」，区别在编译期能力。宏由预处理器做纯文本替换，没有类型检查、没有作用域、参数会被求值多次（`SQUARE(i++)` 会自增两次），调试时看不到栈帧；内联函数是真正的函数，有类型检查、有作用域、参数只求值一次，展开由编译器决定（`inline` 只是建议，递归函数、函数体过大、取地址时都不会展开）。现代 C++ 的结论是：常量用 `constexpr`，小函数用 `inline` 或直接交给编译器，宏只留给条件编译与字符串化这类预处理器专有能力。

**多态的实现**：编译期多态靠重载与模板，运行期多态靠虚函数。含虚函数的类会有一张虚函数表（vtable），每个对象头部有一个指向该表的虚表指针（vptr）；调用虚函数时通过 vptr 查到函数地址再间接跳转。派生类重写虚函数就是替换表里对应槽位的地址，多重继承时对象里会有多个 vptr、各自对应一张表。追问常考「构造函数能不能是虚函数」（不能，vptr 在构造期间还没准备好）、「析构函数为什么要虚」（通过基类指针 delete 派生对象时，非虚析构只会调基类析构，派生类资源泄漏）。

**指针数组与数组指针**：`int *a[10]` 是指针数组——十个元素，每个是 `int*`；`int (*a)[10]` 是数组指针——一个指针，指向「十个 int 的数组」。判读规则是先看括号与结合性：`[]` 优先级高于 `*`，所以没有括号时先成数组。工程上数组指针常见于二维数组传参（`void f(int (*p)[10])`）和按行遍历。

**虚拟内存**：每个进程看到的是独立的连续地址空间，由页表映射到物理页，MMU 在访问时完成翻译（TLB 缓存最近的映射）。作用有四条：隔离（一个进程踩坏内存不会波及别人）、按需分配与超额分配（物理内存比地址空间小得多也能跑）、共享（同一份动态库或文件页在多进程间只占一份物理内存）、方便实现 mmap 与换页。虚拟地址到物理地址的翻译过程、缺页中断的处理流程是高频追问。

**memcpy 与 memmove**：`memcpy` 不处理内存重叠，源与目标区域交叠时行为未定义（高效实现可能按块正序拷贝，重叠会自我覆盖）；`memmove` 检测到重叠时改成从尾部倒序拷贝，保证结果正确，代价是多一次方向判断。手写时要注意 `void*` 转 `char*`、`size_t` 计数、返回目标指针以支持链式调用。

**段错误调试**：先看是空指针、野指针、越界写还是栈溢出。手段依次是：编译加 `-g` 用 gdb 跑出 core 或 `bt` 看栈；`ulimit -c unlimited` 让崩溃落 core 文件；用 AddressSanitizer（`-fsanitize=address`）在越界发生的那一刻就报出具体位置；用 `valgrind` 查未初始化读与内存泄漏；怀疑栈溢出就调大栈或改成堆分配。生产环境上还要看 dmesg 里的 segfault 记录（出错地址与指令指针）。

**epoll 与 select**：`select` 把 fd 集合整体拷进内核、返回后遍历所有 fd 找就绪的，复杂度 O(n)，且有 1024 的 fd 上限；`epoll` 用红黑树管理注册的 fd、用就绪链表返回事件，只拷贝就绪的那些，O(1) 拿到结果。触发方式分水平触发（LT，只要还有数据就一直通知，写起来简单）与边缘触发（ET，只在状态变化时通知一次，必须一次读到 `EAGAIN`，配合非阻塞 fd）。epoll 的适用前提是「大量连接、少量活跃」，连接数少或都是活跃短连接时它不比 select/poll 快。

**mmap 与热更新**：`mmap` 把文件映射进进程地址空间，读写内存即读写文件，省掉一次用户态到内核态的拷贝，也让多个进程共享同一份页。整流器热更新的做法是把固件或参数文件映射进来，更新时写新文件再原子替换（rename），运行中的进程重新映射即拿到新内容，不用停机重启；配合 `msync` 控制回写时机。追问会问「mmap 写和 write 的差别」「映射区修改什么时候真正落盘」「进程崩溃时未 msync 的数据会不会丢」。

**NV12 与编解码**：NV12 是 YUV 4:2:0 的一种排布，共两个 plane——Y plane 存整幅亮度，UV plane 交错存 U 和 V（每四个 Y 共享一组 UV，所以 UV plane 高度是 Y 的一半）。与之对比 I420 是三个 plane（Y、U、V 各自连续），NV21 只是 UV 顺序反过来。H.264 的核心概念是 I/P/B 帧、GOP、宏块与运动补偿、熵编码（CABAC/CAVLC）；H.265 引入 CTU 与四叉树划分、更多帧内预测方向，同画质下码率大约省三到五成，代价是算力更高、专利池更复杂。
