### 《面试题目》

1. 简要自我介绍，重点介绍 AI Agent 相关项目经历与落地成果
2. 个人 Agent 项目中的真实代码产出比例，以及 AI 辅助编码的实际使用占比
3. Agent 运行基座（Harness）的技术选型：自研架构还是基于开源框架改造
4. 从用户需求输入，到 Agent 生成代码、自测、最终合入 PR 的全链路工作流程
5. 需求拆解、任务规划、内容审查模块是自研实现还是依托现有技能组件调度
6. 如何系统性校验 Agent 输出代码的可用性、合规性与需求匹配度，有哪些自动化验收手段
7. 给定 UI 设计稿与需求文档，如何设计自动化方案让 Agent 自主校验页面还原度与交互正确性
8. RAG 体系中如何量化判断召回内容相关性；多路检索结果如何融合、重排与择优输出
9. 手撕：二叉树路径总和（是否存在根到叶子路径满足目标和）
10. 手撕：最长递增子序列，输出长度与完整序列，并说明 O(n log n) 优化思路
11. Computer Use 技术的底层实现原理、页面元素定位逻辑，与其和 Playwright 的差异
12. 设计一套 AI 提效方案，用于团队加速需求开发、自动查错与 bug 修复

### 《参考解析》

**Harness 选型怎么讲**：Harness（Agent 运行基座）要回答的是「模型之外的那一层怎么搭」：模型调用与重试、工具注册与权限、上下文装配与压缩、状态与记忆、日志与回放、以及并发与限流。自研的理由通常是可控与可调试——链路能看清、出问题能定位、不需要迁就框架的抽象；基于开源框架的理由是起步快、生态与工具现成。面试里更好的答法是给出判断依据：如果团队核心诉求是「稳定跑通一条既有链路」，自研薄薄一层往往更省事；如果要快速试多种编排模式，用框架更划算。别忘了提可观测性——没有轨迹日志的 Agent 系统在生产里无法排障。

**合规与需求匹配怎么校验**：合规性不能只靠模型判断，要靠规则与工具链：敏感信息检测（密钥、手机号、内部域名）、许可证与依赖扫描、访问边界检查（有没有越权读写内部数据）、以及输出内容的规则过滤。需求匹配度则要靠「可验收的规格」：把需求写成带验收条件的条目（Given-When-Then），让 Agent 逐条自测并给出证据（哪个测试用例覆盖哪一条），人审时只核对证据是否成立。这种「规格驱动 + 证据留痕」是 AI 开发流程里最关键的工程实践。

**面试中的两个提醒**：一是这场面试与同一天另一份记录（内容完全一致）说明同一场面试会被多人写成面经，看面经时要交叉验证、抓住重复出现的考点——这里反复出现的就是 Harness 选型、全链路流程、校验手段、RAG 融合重排。二是手撕题（路径总和、LIS）属于中等难度的经典题，要求「输出完整序列」的版本比只求长度更容易写错，练习时要用前驱数组把回溯路径也实现一遍。
