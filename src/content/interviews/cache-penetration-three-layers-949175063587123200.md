### 《面试题目》

1. 缓存穿透你怎么处理？
2. 你线上用的是哪个方案？
3. 如果攻击者每次换一个随机 ID，空值缓存不就变成一堆垃圾 key？内存会不会被撑爆？
4. 空值缓存的过期时间应该设多长？
5. 布隆过滤器呢，你为什么没用？用了会踩什么坑？
6. 布隆过滤器不支持删除，数据被删了怎么办？
7. 穿透、击穿、雪崩三者怎么区分，各自的对策是什么？
8. 面试时你会怎么组织这道题的回答？

### 《参考解析》

**空值缓存的真实边界**：它能挡住「同一个不存在的 ID 被反复查」，挡不住「每次换一个新 ID」——后者的 key 是分散的，缓存一百万个空值等于帮攻击者存了一百万条垃圾，内存成本反而由自己承担。因此空值缓存要配三条限制：空值 TTL 压短（一分钟级别，不要与正常数据同周期）、入口做格式与权限校验（长度、字符集、负数 ID 直接拒）、空值用特殊标记而不是真正的 `null`，避免反序列化时与「无此键」混淆。

**布隆过滤器的上线事故**：帖主在上一个项目用客户端内存版布隆，启动时预热几百万用户 ID。上线两周后新注册用户查不到——过滤器里的数据是启动时加载的，新用户写库后没有同步进去，判断结果就是「不存在」，请求在入口被拦掉。修法是写库成功后异步把 ID 加进过滤器，但消息丢失仍会出问题，最终加了一层兜底：过滤器说「不存在」时放一小部分流量（例如百分之一）穿透到缓存，用于对账与纠偏。

**不支持删除的代价**：用户注销或数据删除后，位数组里的位置还在，会一直误判为「可能存在」。要支持删除就得上计数布隆或布谷鸟过滤器，复杂度和内存都会上升。因此布隆适合「ID 空间明确、新增不频繁、能接受一定误判」的场景；数据频繁增删时，维护成本很难看。

**三者的区分**：穿透是查的数据根本不存在，缓存永远不会命中；击穿是单个热点 key 过期瞬间大量请求打库；雪崩是大量 key 同时过期或缓存整体挂掉。触发条件不同，对策也不同：穿透靠参数校验、空值缓存、布隆过滤器；击穿靠互斥锁重建、逻辑过期、热点不过期；雪崩靠过期时间打散、多级缓存、限流降级。

**分层答法**：先说清穿透的本质是「查询不存在的数据」，主动与击穿、雪崩划清界限；再讲方案分层——入口参数校验、空值缓存、布隆过滤器前置、限流与风控兜底；然后主动说出每种方案的副作用（空值缓存怕随机 key，布隆怕删除与同步延迟）；最后给自己的取舍：数据量不大、能接受一分钟脏读就用空值缓存，ID 空间收敛、读多写少再考虑布隆。

**加分点**：能讲出「我在真实流量下被哪个方案坑过」比背名词有效。面试官追问的往往不是方案本身，而是方案的失效边界。
