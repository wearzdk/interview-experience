### 《参考解析》

**指针与内存三题要说得准**：空指针是值为 `NULL` / `nullptr` 的指针，野指针是指向已释放或未初始化内存的指针（`free` 后不置空、返回局部变量地址、越界后继续用都会产生）；悬垂指针与野指针常常一起问。内存泄漏是申请后未释放、程序生命周期内不可达，C 里靠配对的 malloc/free、C++ 靠 RAII 与智能指针规避，定位用 Valgrind、ASan 或跟踪分配计数。堆与栈的区别按四点答：管理方式（手动 vs 编译器自动）、分配效率（栈是移动栈指针，堆要走分配器且可能系统调用）、空间大小（栈 MB 级、堆可达内存上限）、碎片（堆有外部碎片）。除了栈更快这一条，还要补「栈上对象生命周期随作用域结束、堆上对象要显式管理」这个语义差异。

**`volatile` 与 `static` 的常见误区**：`volatile` 告诉编译器该变量可能被外部修改，禁止缓存到寄存器、禁止优化掉读写，用于寄存器映射、中断与主循环共享的标志位、DMA 缓冲区；它**不保证原子性也不提供内存屏障**，多核场景要靠原子操作与 `__DMB` 之类的屏障。`static` 在函数内是静态存储期（只初始化一次、跨调用保留），在文件作用域是内部链接，在类内是类级成员。`inline` 是建议而非命令，现代编译器自行决定是否内联，它的实际主要用途是允许头文件中定义函数而不违反 ODR。

**大小端通信问题**：小端是低位字节放低地址（x86、多数 ARM 默认），大端相反（网络字节序）。两端不一致时按结构体直接收发会解析错位，甚至把 `0x1234` 读成 `0x3412`。解决方式是协议里显式规定字节序并用 `htonl` / `ntohl` 转换，或逐字节序列化（TLV 协议），浮点与多字节字段都要处理；串口与 CAN 场景还要约定位序与字段对齐，不要直接 memcpy 结构体发出去。

**中断与上线流程**：MCU 上电后从复位向量取初始 SP 与 PC，执行启动文件里的复位处理（初始化 .data / .bss、调用 SystemInit 配置时钟、跳到 `main`）。中断向量表是「中断号 → 处理函数地址」的数组，放在 Flash 起始处，IAP 或 Bootloader 场景要重定位（`SCB->VTOR`）。中断流程是硬件保存部分现场 → 跳转向量 → 通用入口保存剩余寄存器 → 调用 C 处理函数 → 清中断标志 → 恢复现场返回。注意事项：处理函数要短、不能阻塞或调用不可重入函数、共享变量用 `volatile` 或临界区保护、注意中断优先级与抢占关系、清标志要及时否则会反复进入。

**优先级反转与解决**：低优先级任务持有互斥锁、高优先级任务等锁而阻塞，中优先级任务又抢占了低优先级任务，导致高优先级被间接拖住。解法是优先级继承（持锁任务临时提升到等待者的优先级，FreeRTOS 的 mutex 支持）或优先级天花板（持锁即提升到该锁可能被访问的最高优先级）；另外要避免在临界区里调用阻塞接口。

**I2C、SPI、UART、CAN 的对比**：I2C 两线（SDA 数据、SCL 时钟）、开漏加外部上拉、支持多主多从、靠 7 位地址寻址、速率 100k/400k/1M/3.4M，适合板内低速器件（传感器、EEPROM）；开漏是为了线与（多个设备同时拉低不短路）并能做时钟同步与仲裁，上拉电阻决定上升沿速度与功耗。SPI 四线（SCK、MOSI、MISO、CS）、推挽全双工、速率可达几十 MHz、每个从机一根片选，四种模式由 CPOL / CPHA 组合决定采样沿，适合高速器件（Flash、屏幕）。UART 两线（TX、RX）异步、无时钟、靠约定波特率、帧格式为起始位 + 数据位 + 校验位 + 停止位，双方时钟误差累积要控制在半个位宽内（常用 8 倍过采样容忍约 2%~3%）。CAN 差分总线、两端 120Ω 终端电阻、基于 ID 的逐位仲裁（ID 越小优先级越高）、有 CRC 与错误帧机制，适合车载与工业多节点，CAN FD 把数据段提速到 2~8 Mbps 并支持 64 字节负载。

**I2C 出错怎么排查**（这题是「调试方法论」的考点）：先用示波器 / 逻辑分析仪看 SCL 是否有时钟、SDA 是否被拉死（从机在传输中途复位会一直拉低 SDA，需要发 9 个时钟解锁或断电重连）；确认地址是否 7 位 / 8 位搞混、上拉电阻是否合适（阻值过大上升沿太慢、过小功耗高）、总线电容是否超标；用扫描程序逐个地址探测设备是否存在；检查时序参数（建立保持时间、时钟频率是否超过从机上限）；多主或中断场景确认是否有其他任务并发访问同一总线（要加互斥）；软件侧确认 ACK / NACK 处理与超时重试是否实现，避免一次失败就死等。

**准备顺序的建议**：作者自己的体会是项目与实习优先，八股是项目的延伸。落到执行上是：先把一个项目讲到能回答任意深度的追问（架构、选型理由、难点、调试过程），再按「语言 → MCU → RTOS → 总线」补八股，每一类都准备一两个能落到代码或波形上的具体例子，比背结论有效。
