### 《参考解析》

**Cache 映射方式：三种结构的本质是「冲突」与「比较次数」的权衡。** 直接映射是 `index = 地址 % 行数`，一行只放一个内存块，硬件只需比较一个标签，最快最省，但地址相距为 cache 容量的两个块会反复互相踢出（冲突缺失），真实程序里这种规律性访问并不少见。全相联允许任意块放进任意行，冲突缺失为零，代价是每次查找要并行比较所有行的标签，硬件开销大，只适合行数很少的场合（典型是 TLB 和很小的 L1）。组相联是折中：先按 index 定位到一组，再在组内（2 路、4 路、8 路）比较若干标签，冲突缺失随路数增加迅速下降而比较器只线性增长，所以现代 L1/L2 基本都是 4 到 16 路组相联；路数继续加大收益递减，还拖慢命中时间。面试时最好把三种替换策略（随机、LRU、伪 LRU）和「组相联下 LRU 的实现代价」一起提一句，能显示你理解的是设计取舍而不是背定义。

**MESI 与写回写通：一致性的源头是「同一份数据有多个副本」。** 多核各自有私有 Cache，某核改写自己缓存里的数据后，别的核手里的副本就过期了，这就是一致性问题；DMA 直接改内存、而 CPU 缓存不知道更是另一类（硬件不 snoop DMA 时的显式维护）。MESI 给每个缓存行四个状态：Modified（本核改过、内存是旧的）、Exclusive（干净且只有本核有）、Shared（干净且多核共有）、Invalid（失效）。核要写一个 Shared 行，先发总线请求让其他核把它置为 Invalid 并拿到确认，再升级为 Modified；要写一个别人持有的 Modified 行，则先把那份数据拿过来（写回或转发）再改。写回与写通的差别在于「什么时候把数据写回内存」：写回只在脏行被替换时写内存，写操作在缓存命中时完全不碰总线，省带宽但要维护脏位；写通每次写都同时写缓存和内存，状态机简单、一致性容易做，但写带宽压力大得多，实际还会配写缓冲。再补一句写分配与不写分配（写未命中时是否先把行拉进缓存），写通配不写分配、写回配写分配是常见组合。

**Cache 与 MMU 谁先谁后：现代处理器让它们并行，而不是串行。** CPU 发出的是虚拟地址，必须先经 MMU（查 TLB，缺失再走页表）翻译成物理地址；如果 Cache 等翻译完再访问，就多了一拍延迟，所以主流 L1 用 VIPT（虚拟索引、物理标签）：用虚拟地址里落在页内偏移范围内的低位做组索引，同时并行送 MMU 翻译，等物理地址回来再用它比较标签。这样做的约束是索引位宽不能超过页内偏移，否则同一物理页的不同虚拟映射（别名）会落到不同组里造成数据不一致——4KB 页、32KB 8 路的 L1 正好每路 4KB，就是这个约束的直接体现（也叫「页着色」问题的来源）。L2 通常在 L1 之后，拿到的已经是物理地址，用 PIPT，结构更简单。被追问「为什么这样设计、有什么好处」时，答案就是拿「省掉串行的翻译延迟」换「索引位宽受页大小限制」，能说出别名问题和 VIPT/PIPT 这两个词基本就到位了。

**流水线冒险要分三类讲清楚现象与解法。** 结构冒险是硬件资源冲突，比如单端口存储器同时要取指和访存，解法是指令与数据分离的哈佛结构、多端口寄存器堆、或者插入停顿。数据冒险最典型的是 RAW：后一条指令要用前一条还没写回的结果，绝大多数算术指令可以用前递（旁路）把结果从流水线后段直接送到前段，只有「load 之后立刻使用该寄存器」传不了（数据要到访存阶段末尾才拿到），必须停一拍或由编译器调度一条无关指令填空。控制冒险出在分支跳转上：取到跳转指令时后面的指令已经进流水线了，靠分支预测（静态预测、BHT/BTB 动态预测）先猜一个方向继续取指，猜错就冲刷流水线重取，代价是若干拍的浪费——分支越深、流水级越多，惩罚越大。回答时把「前递解决大多数、load-use 必须停顿、预测失败要冲刷」这三条因果说清，比罗列名词有效。

**上电启动流程：每一级都在「让下一级能跑起来」。** 复位后 CPU 从固定复位向量跳到片内固化的 BootROM，这段代码最小、只做最基础的事：初始化时钟与最简启动介质接口，按启动引脚或熔丝选择从哪里引导（SPI Flash、eMMC、SD、串口），做安全启动的签名校验，然后把第一阶段 bootloader 搬到片内 SRAM 执行。第一阶段（SPL/MLO 之类）体量受 SRAM 限制，核心任务是初始化 DDR 控制器——因为完整 bootloader 装不进 SRAM，必须先让内存在容量上可用；随后完整 bootloader（U-Boot 等）从 Flash 把内核镜像、设备树和可能的 ramdisk 搬到 DDR 并校验，设置好启动参数后跳转到内核入口。内核再完成自解压、建立页表开启 MMU、初始化各子系统与驱动、挂载根文件系统，最后启动 init/systemd。这条链被追问时最常见的卡点是「为什么需要两段 bootloader」（SRAM 太小、DDR 还没初始化）和「每一级如何保证可靠性」（校验和、A/B 备份、失败回滚），主动补上这两点就是加分项。
