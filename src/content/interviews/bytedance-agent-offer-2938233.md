### 《面试题目》

1. 一面：Agent 相关理论深挖，手写「多个有序数组取最大的 K 个数」。
2. 二面：设计链表，支持按下标查找、插入、删除。
3. 三面：最长公共子序列，要求输出具体序列。
4. （复盘）一面 Top K 当时按每组取一个比较来写，复杂度是多少？更好的做法是什么？
5. （复盘）设计链表容易漏掉哪些边界？
6. （复盘）只写出 LCS 长度算不算完成？怎么从 DP 表回溯出序列？

### 《参考解析》

**Top K 这题的失分点几乎都在复杂度上**。每组取当前最大值逐一比较，是 O(Km)（m 为数组个数、K 为要取的个数）；正确做法是用堆维护每组当前的候选，弹出堆顶后从该组补下一个，O(m + K log m)。面试时先把「每轮只有一个候选被消耗」这句话说出来，让面试官看到你意识到可以增量维护，再写代码。用 Python 时 `heapq` 是最小堆，取负值压入；用 Java 时 `PriorityQueue` 配自定义比较器，注意存「值 + 所属数组下标」两个字段，否则弹出后不知道该从哪个数组补数。手写前先确认 K 与总元素数的关系，K 大于总数时直接返回全部。

**设计链表的边界清单比代码本身更重要**。写之前把六种情况列出来：空链表插入、在头部插入、在尾部插入（`index == size`）、删除唯一节点、删除头节点、`index` 越界。用头尾哨兵可以消掉前四种里的特判，删除时先定位前驱、改指针再释放。常见错误是插入时先改了 `pred.next` 再去读 `pred.next.prev`，此时读到的已经是新节点，指针链断掉；正确顺序是先接后继再改前驱。写完用「空 → 插一个 → 插三个 → 删中间 → 删头 → 删尾」这条路径手推一遍，比口头声称正确有效。

**LCS 只写长度是半成品**。长度 DP 与回溯是两段独立的能力：`dp[i][j]` 相同则左上移并记录字符，不同则往 `dp` 值更大的一侧走，相等时任选一侧。容易漏的是字符收集顺序（回溯得到的是逆序，要反转）和「子序列不要求连续」这个前提要主动说明。如果面试官追问空间，答「求长度可以滚动数组，求具体序列必须保留整张表或额外记录每一步的选择」。三面通常还会追问一个变体，比如输出所有 LCS 或求最短公共超序列，思路都从这张表出发。

**这份时间线的价值在于「面完立刻复盘」**。帖主在等 offer 期间把一面的 Top K 重新写了一遍，才发现当时的最优解没答出来；这种复盘比再刷十道新题有用，因为面试现场的压力会让人退回到最直觉的写法。可操作的做法是：每轮结束当天写下「题目、我当时的答案、卡住的地方、正确思路、下次怎么开口」，一周后只看「卡住的地方」这一列。二面、三面的手写题都属于「知道思路但容易写错」的类型，练法是在纸上限时写完整代码并自己走边界，不是在编辑器里靠补全和调试通过。

**Agent 岗的理论面与算法面权重相当**。一面理论问得深，说明岗位要的是能讲清记忆、工具调用、流程约束的人，而不只是会写模型调用的人；准备时把做过的 Agent 项目按「目标 → 拆解 → 工具设计 → 失败处理 → 效果度量」讲一遍，每个环节准备一个具体数字。三轮的算法题难度中等偏上，但都不是偏题，属于「写对边界就能过」的类型，把常见数据结构题的边界清单背熟，收益比追新题高。

**拿到 offer 之后**：帖主提到终于能睡个好觉，这是秋招后期的真实状态，但签约前仍要确认岗位方向、组的具体业务、转正与考核口径。面试中反问环节问到的信息，往往比 offer letter 上的职级更能决定入职后的体验。
