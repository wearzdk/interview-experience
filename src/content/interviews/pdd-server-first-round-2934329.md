### 《参考解析》

**SSE 与 Content-Type**：SSE 走普通 HTTP 长连接，响应头 `Content-Type: text/event-stream`，body 是一行行 `data: {...}

` 的事件流，浏览器侧用 `EventSource` 或 fetch + ReadableStream 消费。选它的理由：单向推送足够（模型只往下吐 token）、天然支持断线重连（`Last-Event-ID`）、能穿过大多数网关与代理、实现比 WebSocket 简单。它的坑也要说：中间层（Nginx/CDN）的空闲超时要配心跳注释行（`: ping`），HTTP/1.1 下单域名并发连接数有限制所以要走 HTTP/2。

**动态 Token 与多实例鉴权**：Token 里应带「用户标识 + 会话/任务标识 + 过期时间 + 签发实例无关的签名」，用非对称签名（RS256）或共享密钥 HMAC，验签不需要查库，任意实例都能独立校验——这是多实例一致性的正解。如果需要「一次一密」或撤销能力，就把 Token 的 jti 与状态放 Redis（带 TTL），所有实例读同一份。最不该做的是把状态放本地内存，那样负载均衡一转就失效。

**双链路降级**：主链路（自建网关 + 主力模型）超时或错误率超阈值时，切到备用链路（另一家供应商 / 更小更快的模型 / 缓存答案 / 模板兜底）。触发条件要具体：首 token 超时（比如 3s）、整体超时、5xx 比例、以及配额耗尽。重试要区分幂等性——流式生成重试会产生重复内容，所以重试应发生在「还没有吐出任何 token」之前，一旦开始输出就只能截断并提示，不能重发。

**Agent 越权**：核心是「用户身份贯穿到底」。模型不能自己决定「以谁的权限访问」，工具执行时必须携带终端用户的身份凭证（而不是 Agent 的服务账号），由被调服务做真实的权限校验；Agent 只做意图解析与参数拼装，参数涉及资源 ID 时要做归属校验（这个订单是不是这个用户的）。再加三层：工具级白名单（每个工具声明它需要的最小 scope）、敏感工具强制人工确认、全链路审计。扩展到 C 端的关键是把授权从「逐人配置」变成「角色 + 属性（RBAC/ABAC）+ 资源归属」，权限判定收敛到一个统一服务，Agent 与前端共用同一套判定。

**单例找错**：常见错误是双重检查锁没加 `volatile`（指令重排导致拿到未初始化完成的对象）、把 `getInstance` 写成非静态、构造器没私有化、以及用 `static` 变量在类加载时初始化但依赖了外部可变状态。正确写法是静态内部类（延迟加载 + 线程安全）或枚举单例（防反射与序列化破坏）。

**数组右侧最大值**：从右往左遍历，维护 `maxRight`（初始 -1），对每个位置先保存 `arr[i]` 再写 `arr[i] = maxRight`，然后 `maxRight = max(maxRight, old)`。O(n)/O(1)。

**I/D 构造数组**：贪心 + 栈。遇到 `I` 就把当前数字入栈并弹出，遇到 `D` 就只入栈，最后把剩余数字全部弹出——这样递减段被逆序输出，天然满足 `D`。也可以用「先按 D 段长度分配大数」的贪心：从左扫，遇到 D 连续段长 k，就给这段分配当前最大的一段降序。

**字符串数组等价判断**：先判长度相同，再排序后逐个比较（O(n log n)），或用字符计数向量（每个字符串的字符频次数组）作为哈希键放进 map。等价定义要先跟面试官确认（是否考虑重复、顺序是否敏感），这是这类题的关键。
