### 《参考解析》

**三面真正在考的三件事**：从帖主的记录看，面试官反复回到「项目的复杂性具体在哪里、方案是否真的对应这些困难」「效果指标怎么产生、能不能代表真实业务价值」「你个人到底承担了什么，哪些属于团队建设与未来愿景」。这三问是同一个问题的三个切面：三面不再验证你会不会写代码，而是判断这段经历是不是你的、你对它的理解有没有到决策层。回答时把项目拆成「输入是什么、约束是什么、我做了什么判断、结果用什么口径衡量」，主动交代哪些部分不是你做的，比把整个项目说成自己主导更可信。

**本体化建模与 CLI+Skill 的路线对比**：本体化是先定义领域里的实体、关系与属性（岗位、技能、公司、招聘流程），再把可执行动作绑定成 Action，模型在语义层里选择动作、填参数；CLI 加 Skill 是把能力封装成命令行工具，配合一份技能说明交给模型组合调用。前者的优势是语义统一、可解释、可审计、跨系统可复用，模型面对的是业务概念而不是接口细节，约束能落在本体上；代价是建模与维护成本高、存量系统改造面大、新能力上线要先进模型再落地，扩展速度慢。后者的优势是接入快、复用现有工程能力、组合灵活，适合长尾与探索期能力；代价是缺语义层，模型靠说明文档理解边界，权限、错误处理与一致性分散在工具里，规模上来后难以保证同义不同名、参数口径一致。实际工程里常见的折中是分层：本体负责核心实体与动作契约，执行落到 CLI，Skill 作为对外说明，这样语义层稳定、实现可以逐步替换。存量系统重构成本高时，先做「读侧本体」——把数据映射成统一概念用于检索与推理，写侧仍走原有接口，避免一次性改造。

**Action 的粒度与业务概念为什么不能直接映射数据库表**：Action 应按「用户能理解的一次业务动作」切，例如「发起一场面试」「把候选人推进到下一轮」，而不是按接口或表切。粒度太细，模型要串很多步才能完成一件事，中间任何一步失败都要重新规划；粒度太粗，参数爆炸、可选分支多，模型容易填错。判断标准是：一个 Action 的参数里出现的都是业务语义字段（岗位、轮次、时间），并且它的成功与否可以用一句业务语言描述。数据库表直接暴露给模型的问题在于，表结构是存储的实现细节——字段名是缩写、状态是枚举码、一次业务操作要改多张表，模型无法从中理解业务约束，也没有事务边界可言；业务概念则要额外承载不变量（例如「已结束的面试不能改评分」），这些规则在表结构里根本不存在。

**指标口径怎么讲才站得住**：面试官会连问三层——指标是什么、怎么算出来、和谁比。回答时先给基线（旧方案 / 无方案时的表现），再给本次的数字，最后给样本量与评估方式（人工抽检多少条、抽检的一致性怎么保证、是否双人标注）。「纠正前的数据」这类追问是在确认你有没有把基线搞混：如果纠正前是旧方案的表现，那说明的是替换收益；如果是自己初版的测试结果，说明的只是迭代收益，两者不能混着说。指标讲不清时，宁可说「这一项目前只有人工抽检的定性结论，没有可比的量化基线」，也不要编一个看起来漂亮的百分比。

**进程与线程、JVM 内存结构、TCP 与 UDP**：进程是资源分配的基本单位，拥有独立的地址空间、文件描述符表与页表，进程间通信要走管道、共享内存、socket；线程是调度的基本单位，同一进程内的线程共享堆与方法区，各自有独立的栈、程序计数器与寄存器，切换开销远小于进程，代价是共享状态需要同步。JVM 运行时数据区按线程私有与共享划分：私有的有程序计数器、虚拟机栈、本地方法栈；共享的是堆与方法区（JDK 8 起为元空间，使用本地内存），另外有直接内存与运行时常量池。堆按分代划分新生代（Eden 与两个 Survivor）与老年代，对象优先在 Eden 分配，经历若干次 Minor GC 后晋升。TCP 面向连接、提供可靠有序的字节流，有握手挥手、重传、拥塞控制与流量控制，适合对完整性有要求的场景；UDP 无连接、不保证顺序与可达，头部只有 8 字节、没有拥塞控制，适合实时音视频、DNS 这类能容忍丢包但要求低时延的场景。往深一层可以说 TCP 是字节流没有消息边界，所以应用层要自己做长度前缀或分隔符来拆包。

**个人项目与评测怎么答**：把「练手」和「有业务效果」分开讲清楚，是这类问题的关键。练手项目讲清楚目标、架构取舍、踩过的坑与现在的局限；有业务效果的项目给指标、给对照、给样本。评测方式要具体：用什么公开数据集或自建集、指标是准确率还是人工偏好、与哪个基线比、评测脚本可不可复现。面试官问到工具或平台，说明他关心的是你有没有做过可复现的评估，而不是随口说「效果不错」。

**职责与分工怎么提炼**：用「我负责的边界 + 我做的关键判断 + 结果」三段式。边界要具体到模块与阶段（例如「我负责抽取层的 schema 设计与对齐策略，下游的模板与前端由另外两位同学负责」）；关键判断要说明当时有哪些选项、你为什么选这个、代价是什么；结果给可核验的事实。把团队成果与个人贡献分开陈述不会减分，反而会让面试官相信你后面说的数字。
