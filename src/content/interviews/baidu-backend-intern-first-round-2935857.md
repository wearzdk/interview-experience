### 《参考解析》

**回表与避免回表。** InnoDB 的二级索引叶子节点只存索引列和主键，按二级索引查到主键后还要再走一次聚簇索引取出整行，这就是回表。避免手段：把查询需要的列都放进索引做成覆盖索引（`EXPLAIN` 的 Extra 出现 `Using index` 即命中）、只 select 必要列而不是 `SELECT *`、用索引下推减少回表次数、必要时调整查询走主键。代价是索引变宽、写放大，所以覆盖索引要挑高频查询做。

**联合索引 (A,C,B) 与是否加 D。** 联合索引遵循最左前缀：能命中 A、A+C、A+C+B 的等值条件，以及 A 的范围 + 后续等值（范围列之后的列无法用于精确定位）。列序的一般原则是等值条件在前、区分度高的在前、范围列尽量靠后、排序列与最左前缀对齐。把 D 加进去只有当查询确实需要 D 且能形成覆盖索引时才划算——判断依据是这条 SQL 的调用频率、D 的列宽和更新频率；如果 D 是大字段或频繁更新，加进去会让索引变大、每次写都要维护，收益不抵成本。

**缓存三问。** 穿透是查一个数据库里也不存在的 key，请求全部打到 DB，解法是缓存空值（短 TTL）、布隆过滤器前置拦截、参数校验；击穿是某个热点 key 过期瞬间大量并发回源，解法是互斥锁/单飞（只放一个请求回源，其他等待）、逻辑过期 + 异步刷新；雪崩是大量 key 同时过期或缓存集群整体不可用，解法是 TTL 加随机抖动、多级缓存、熔断降级与限流、Redis 高可用部署。

**setNX 与分布式锁。** `SET key value NX PX ttl` 只在 key 不存在时写入并带过期时间，返回 OK 表示抢锁成功。落地要注意：value 存持有者标识（实例 + 线程），解锁必须用 Lua 比对 value 再删除，避免误删别人的锁；过期时间要覆盖业务耗时并配续期；业务失败要主动释放；Redis 主从切换可能丢锁，关键场景要配 Redlock 或用数据库唯一约束兜底。

**URL 到 Go 服务。** 浏览器解析域名 → DNS 递归查询得到 IP → TCP 三次握手（HTTPS 还要 TLS 握手）→ 请求到达机房入口（SLB/反向代理/网关）→ 按 Host、路径、Header 做七层路由 → 转发到对应机器的端口 → Go 的 `net/http` 监听该端口，`ServeMux` 或框架路由匹配到 handler。同一台机器跑多个 Go 服务时，通常让每个服务监听不同端口，由 Nginx/网关按域名或路径前缀反代；也可以用 `SO_REUSEPORT` 让多个进程共享同一端口由内核分流，或直接上容器编排按 Service 做负载。

**5xx 常见码。** 500 服务器内部错误；501 未实现；502 网关从上游收到无效响应（后端挂了或返回非法内容）；503 服务暂不可用（过载、限流、维护）；504 网关等待上游超时。排查 502/504 时先看网关日志里的 upstream 地址与耗时，再对后端进程和依赖做检查。

**幂等与防篡改。** 幂等：客户端带幂等键（业务单号或请求 ID），服务端用唯一索引或 Redis `SETNX` 抢占，第一次执行并把结果落库，重复请求直接返回同一结果；状态机只允许单向迁移，失败要清理幂等记录避免把失败固化。防篡改：对参数按字典序拼接后加时间戳和随机 nonce 做 HMAC 签名，服务端验签并校验时间窗与 nonce 是否用过；再加 HTTPS 防传输层窃听。

**红包随机分配。** 经典做法是二倍均值法：每次在 `[1, 剩余金额/剩余人数 × 2]` 区间内随机一个金额（以分为单位取整，且保证给后面每人至少留 1 分），最后一个人拿走剩余全部。这样每人的期望相等，且不会出现有人拿到 0 或最后一人独吞的情况；要更均匀可以用线段切割法（在总额上随机切 n-1 刀）。

**AI 辅助开发的方法论。** 先把需求和验收标准写清楚（输入输出、边界、错误码），让 AI 产出后自己逐行审；用类型系统和静态检查兜住低层错误；关键路径必须有测试或可复现的验证脚本；把项目约定（分层、命名、日志、错误处理）写进上下文而不是每次口头描述；生成代码先小范围落地，跑通再扩大；对涉及并发、事务、权限的部分默认不信，自己重写或重点复核。
