### 《参考解析》

**项目深挖的标准答法**：每个项目先给一句定位（解决什么问题、什么形态的产品），再讲清「我负责哪一层」，然后按数据流讲链路（采集 → 处理 → 上送 → 展示 / 存储），最后给结果与指标。被问「为什么是你承担这个角色」时，答案要落在可验证的差异上（你之前做过类似模块、你熟悉这套工具链），不要说「因为我想锻炼」。

**多进程与多线程的划分依据**：按「故障隔离」与「共享需求」划分——不同硬件或不同可靠性等级的功能放不同进程（摄像头采集崩了不能带崩主控），需要高频共享状态、切换开销敏感的逻辑放同一进程内的多线程；进程间用共享内存 + 信号量、消息队列或 Socket，进程内用互斥锁、条件变量、无锁队列。回答时要补一句线程数不是越多越好：受 CPU 核数、内存与下游承载限制，线程池要设上限并监控队列积压。

**协议选型按场景给结论**：设备与云端控制面用 MQTT（轻量、支持 QoS、断线重连与遗嘱消息），局域网内高频小包用 UDP 并自己做重传与序号，需要可靠有序的配置下发与文件传输用 TCP，浏览器与后端做长连接用 HTTP/SSE 或 WebSocket，实时音视频用 RTP/WebRTC（UDP + 拥塞控制 + FEC），工业现场用 Modbus / CAN。每个都要说出「为什么不用另一个」。

**Linux 移植与工具链**：移植的本质是把内核、设备树、根文件系统三件套适配到目标板。工具链来源有三类：芯片厂商提供的 SDK 预编译工具链、Buildroot / Yocto 自行构建、发行版交叉包（如 `gcc-aarch64-linux-gnu`）；要确认 libc（glibc / musl / uClibc）、浮点 ABI（hard / soft float）、内核头文件版本三者匹配，否则会出现「编译通过但运行时报 illegal instruction 或符号找不到」。

**存储配置**：eMMC 分区（Boot、Env、Kernel、RootFS、Data）、NAND 要处理坏块与 ECC、NOR 可直接 XIP；软件侧在设备树里描述控制器节点与分区表（`fixed-partitions`），启动参数里指定 rootfs 位置与只读挂载（`ro`）保护根文件系统，数据分区单独挂载并定期检查。

**引导程序与串口无输出**：Bootloader 阶段通常是 ROM → 一级引导（SPL / 片内 ROM 加载）→ U-Boot → 内核。需要改引导程序的场景：换 DDR 参数与时钟、改启动介质顺序、加 A/B 分区与回滚、加安全启动校验、改环境变量默认值。串口无输出的排查顺序是先硬件后软件：量供电与复位电平、确认串口线序（TX/RX 是否交叉）与电平（TTL vs RS232）、量晶振是否起振、确认波特率与校验位、看 Bootloader 是否真的在跑（用示波器看是否有周期性输出或点灯）、读芯片启动模式引脚是否选对了介质、最后才是代码（早期串口初始化、时钟配置、DDR 初始化失败会死在 SPL）。

**设备树与内核调试**：设备树把板级硬件信息（地址、中断、时钟、GPIO、引脚复用）从内核代码里剥离，内核启动时解析 DTB 生成 `device_node`，再与驱动里的 `compatible` 匹配（`of_match_table`）触发 probe。修改外设通常只改 dts（新增节点、改 pinctrl、改 status），不用重编内核。内核调试的手段有 `printk` / `dynamic_debug`、`ftrace`、`perf`、`kdump` + crash 分析 oops、`/proc` 与 debugfs、以及 JTAG。定位崩溃先看 oops 里的 PC 与调用栈，再对照 `System.map` 找函数。

**RTOS 调度与上下文切换**：核心功能是任务管理、调度、同步与通信（信号量、队列、事件组）、时间管理与内存管理。抢占式优先级调度是「就绪态里最高优先级的任务运行」，同优先级时间片轮转；SysTick 定时器中断里做调度决策（`xTaskIncrementTick`），需要切换时触发 PendSV 异常，在 PendSV 里保存 R4-R11 与 PSP、切换栈指针、恢复新任务的寄存器（硬件自动保存 R0-R3、R12、LR、PC、xPSR）。优先级反转用优先级继承（互斥量）解决，中断里不能调用会阻塞的 API，要用 `FromISR` 版本。

**Socket 通信流程**：TCP 服务端 `socket → bind → listen → accept → recv/send → close`，客户端 `socket → connect → send/recv`；UDP 无连接，直接 `sendto / recvfrom`。常见问题：粘包（TCP 是字节流，要自定义长度字段或分隔符）、半包与超时（设置 `SO_RCVTIMEO` 或用 `select/poll`）、连接泄漏（`accept` 后要关闭 fd、处理 EINTR）、大量短连接导致 TIME_WAIT 堆积（连接复用或调 `SO_REUSEADDR`）、心跳与断线重连。
