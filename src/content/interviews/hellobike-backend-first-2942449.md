### 《参考解析》

**回表与覆盖索引**。InnoDB 的二级索引叶子节点只存索引列和主键，不存整行数据。用二级索引查询时，如果 `SELECT` 的列不全在索引里，就要拿主键回聚簇索引再取一次行，这就是回表。不需要回表的条件是「查询涉及的列全部在同一个索引里」——也就是覆盖索引，`EXPLAIN` 的 `Extra` 会显示 `Using index`。优化手段是把高频查询需要的列放进联合索引，或者用 `SELECT` 只取索引列。

**四种锁**。记录锁（Record Lock）锁住索引记录本身，命中唯一索引等值查询时使用；间隙锁（Gap Lock）锁住两条记录之间的开区间，用来防止幻读；临键锁（Next-Key Lock）是记录锁加前面的间隙，是 RR 隔离级别下的默认加锁单位；插入意向锁（Insert Intention Lock）是插入前在间隙上加的一种特殊间隙锁，多个事务插入同一间隙的不同位置互不冲突。要能说清：唯一索引等值命中时退化为记录锁，范围查询或非唯一索引会加临键锁；间隙锁之间不互斥，但会和插入意向锁冲突。

**死锁**。典型成因是两个事务以相反顺序加锁，或者间隙锁与插入意向锁互相等待。处置：先看 `SHOW ENGINE INNODB STATUS` 的 `LATEST DETECTED DEADLOCK` 段，定位两条 SQL 与持有 / 等待的锁；再把访问顺序统一（比如按主键排序批量更新）、缩短事务、降低隔离级别或改用乐观锁。回答时要给出一个真实例子，说明怎么复现与修复。

**EXPLAIN 怎么看**。重点字段：`type`（从好到差 system > const > eq_ref > ref > range > index > ALL）、`key`（实际用了哪个索引）、`rows`（预估扫描行数）、`filtered`（过滤比例）、`Extra`（`Using index` 覆盖索引、`Using where` 回表后过滤、`Using filesort` 额外排序、`Using temporary` 临时表）。判断效率的核心是「扫描行数是否接近返回行数」，差距大就要改索引或改 SQL。必要时用 `EXPLAIN ANALYZE` 看真实耗时。

**索引失效的典型场景**。对索引列做函数或运算（`WHERE DATE(create_time) = ...`）、隐式类型转换（字符串列传数字）、前导模糊匹配（`LIKE '%x'`）、联合索引不满足最左前缀、`OR` 连接的条件有一侧没索引、`!=` / `NOT IN` 导致优化器放弃索引、区分度太低的列、以及优化器估算后认为全表扫描更便宜。要补一句：`ORDER BY` 与 `GROUP BY` 的列不在索引顺序里也会导致 filesort。

**Redis 五种类型的底层实现**。String 用 SDS（带长度与预分配，二进制安全）；List 用 quicklist（双向链表 + 每个节点是 listpack）；Hash 小数据用 listpack、大了转哈希表；Set 整数集合用 intset、其余用哈希表或 listpack；ZSet 小数据用 listpack、大了用跳表 + 哈希表（哈希表存 member 到 score，跳表按 score 排序）。此外还有 bitmap、HyperLogLog、GEO、Stream 这些扩展类型。答这题要说明「小对象用紧凑编码省内存，超过阈值自动转成大结构」这一设计取舍。

**为什么引入 Redis**。不是为了替代 MySQL，而是补三件事：读性能（内存访问、抗高并发读）、特殊数据结构（排行榜、计数器、去重、限流）、以及跨进程共享状态（分布式锁、会话）。引入的代价是一致性问题（缓存与库不一致、过期与淘汰）、运维复杂度与内存成本。回答时要给出具体场景，并说明一致性方案（先更新库再删缓存、延迟双删、订阅 binlog）。

**过期策略**。Redis 用「惰性删除 + 定期删除」组合：访问时检查是否过期并删除（惰性），后台周期性随机抽样检查并删除（定期）。内存达到 `maxmemory` 时触发淘汰策略：`noeviction`（拒绝写）、`allkeys-lru`、`volatile-lru`、`allkeys-lfu`、`volatile-lfu`、`allkeys-random`、`volatile-random`、`volatile-ttl`。要说明 LRU 是近似实现（采样）、LFU 适合热点差异大的场景，以及为什么不能只靠过期删除（过期键可能长期不被访问）。

**设计一个 Redis 的数据结构层**。这题考抽象能力：先定义统一的对象模型（类型 + 编码 + 引用计数 + 过期时间），再按数据规模设计双编码（小对象用连续内存的紧凑结构减少指针与分配开销，超阈值转哈希表 / 跳表）；字符串用带长度的二进制安全结构；有序集合要同时支持按成员查分（哈希）与按分排序（跳表）；内存管理用固定大小的分配器减少碎片；并发模型用单线程处理命令、IO 多路复用，避免锁。说完这些，再补一句取舍：紧凑编码省内存但插入可能触发转换，跳表实现简单但比平衡树占内存。
