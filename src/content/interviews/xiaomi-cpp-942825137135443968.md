### 《参考解析》

**epoll 相比 poll 的优势是「不随连接数线性变慢」**。poll 每次调用要把整个 fd 数组从用户态拷到内核态并线性扫描；epoll 用红黑树管理注册的 fd、用就绪链表返回事件，`epoll_wait` 只取就绪的，所以连接多但活跃少时效率高。实现上是 `epoll_create` 建实例、`epoll_ctl` 增删改、`epoll_wait` 等待；支持水平触发和边缘触发，边缘触发必须配合非阻塞 IO 一次读到 EAGAIN。

**套接字 API 按顺序记**：服务端 socket → bind → listen → accept → read/write → close；客户端 socket → connect → read/write → close。注意字节序转换、部分读写、EINTR 重试和关闭时的 TIME_WAIT。

**线程池数量看任务类型**：CPU 密集型约等于核数（+1 防抖），IO 密集型可以远大于核数，按「核数 × (1 + 等待时间/计算时间)」估算；最终要靠压测调，并配上有界队列和拒绝策略，避免无限堆积。

**有虚函数的类会多一个虚表指针**（64 位下 8 字节），用于运行时多态；多继承可能有多份。空类 sizeof 为 1 是为了保证不同对象地址不同。

**智能指针**：unique_ptr 独占所有权、不可拷贝只可移动、零额外开销；shared_ptr 共享所有权、控制块里放强引用计数和弱引用计数、计数原子但对象访问仍需同步；weak_ptr 打破循环引用。优先 unique_ptr，确实共享再用 shared_ptr。

**反转字符串的健壮性**：处理空串、单字符、UTF-8 多字节（按字符而不是字节反转会复杂）、以及入参是 const 时要不要返回新串。双指针原地交换是最常见的写法。
