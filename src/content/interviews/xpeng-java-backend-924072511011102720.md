### 《面试题目》

1. 能否介绍在公司大模型应用项目中承担的技术工作？
2. 如何处理长上下文和模型幻觉问题？
3. Dify 二次开发中做过哪些工具或 MCP 能力？
4. Claude Code 与 Dify 的定位和适用场景有什么区别？
5. JVM 内存区域和垃圾回收机制是怎样的？
6. MySQL 索引和事务在项目中如何使用？
7. 平时如何使用 AI 编程助手，怎样验证生成代码？
8. MyRPC 项目的核心链路和技术难点是什么？
9. 未来更希望深耕哪个技术方向？

### 《参考解析》

1. **上下文治理**：按任务阶段保留必要事实，对历史对话做结构化摘要，并把稳定资料放入可检索知识库。摘要必须保留约束、未决项和证据来源，不能只压缩自然语言长度。
2. **幻觉控制**：限制模型只能基于检索证据和工具结果作答，对关键字段做结构化校验；低置信度或证据冲突时明确拒答或进入人工确认。
3. **工具边界**：Dify 更偏应用编排与快速搭建，编程助手面向代码库理解和修改。MCP 提供标准化工具接口，工具粒度应围绕稳定业务能力而非简单复刻每个底层接口。
4. **AI 代码验证**：先审查需求覆盖和边界，再运行静态检查、构建和真实链路验证。回答时应说明自己如何发现并修正过生成代码的问题，而不是只描述使用频率。
