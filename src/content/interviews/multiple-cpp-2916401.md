### 《参考解析》

**静态多态与动态多态**：静态多态在编译期就确定调用哪个函数——函数重载靠名字修饰区分参数列表，模板靠实例化生成不同的函数体，CRTP 靠把派生类当模板参数传进去，共同点是零运行时开销、但不能对"运行期才知道的类型"编程。动态多态在运行期靠 vptr 加虚表分发，代价是一次间接跳转和无法内联（除非编译器能去虚拟化），换来的是面向接口编程的能力。面试官顺着这题往下问多继承和菱形继承时要答出因果链：多继承下同一个基类子对象可能出现两份，数据冗余且访问有二义性；虚继承让被虚继承的基类只保留一份共享子对象，代价是对象布局里多出虚基类偏移信息、访问基类成员要间接寻址，而且初始化的责任落到最派生类身上。

**虚函数表里存什么、多态怎么实现**：虚表在编译期为每个多态类生成一张，按声明顺序存放虚函数地址，另外还带 RTTI 指针和 offset-to-top 等信息；对象里第一个（或多个）指针位置放 vptr。基类指针调用虚函数时通过 vptr 定位到表、再按固定槽位跳转，子类覆写就是把该槽位替换成自己的实现，多继承下对象持有多个 vptr，跨基类指针调用还需要 this 指针调整。两个高频追问：构造和析构期间 vptr 会被设置成当前正在构造/析构的类，所以在构造函数里调虚函数不会分发到子类；纯虚函数的槽位是一个会终止程序的占位实现，纯虚析构函数也必须给出定义。

**map 为什么用红黑树而不是完全平衡二叉树**：map 需要的是"有序 + 对数查找"，红黑树只保证近似平衡（最长路径不超过最短路径的两倍），树高仍是 O(log n) 量级，但换来的是插入删除时极少的旋转——红黑树插入最多两次旋转、删除最多三次，而 AVL 这类严格平衡树为了维持平衡因子在最坏情况下要沿路径旋转 O(log n) 次。map 的实际负载是读和写混合的，为每次写入付出严格平衡的代价不划算。加上红黑树实现里只需维护颜色这一位信息、比较函数只要求严格弱序，工程上更简单可靠，迭代器在插入时也不会失效——这些共同决定了 STL 的选择。

**C++ 从源码到可执行文件经过哪几步**：预处理、编译、汇编、链接。预处理阶段展开 `#include` 和宏、处理条件编译，产出纯 C++ 源码；编译阶段做词法语法语义分析和优化，生成汇编代码（模板在这一步真正实例化，这也是模板要实现到头文件里的原因）；汇编阶段把汇编翻成机器码，产出带符号表和重定位信息的目标文件；链接阶段做符号解析与重定位，把多个目标文件和库拼成一个可执行文件，静态库直接拷入、动态库只记依赖，符号在装载时才解析。常见的追问点：为什么模板报错在编译期、为什么会有未定义符号、inline 与 ODR 规则、以及编译优化级别对调试体验的影响。

**粘包与解决方式**：TCP 是面向字节流的协议，没有消息边界的概念，应用层一次 send 的数据可能被拆成多个报文、也可能和下一次的粘在一起，所以粘包是应用层缺少分帧协议的表现，不是 TCP 的缺陷。解决方案四类：定长消息（实现简单、浪费带宽，适合固定结构的协议头）、分隔符（要处理转义，文本协议常用）、长度字段加负载（最通用，先读 4 字节长度再读 body）、以及自描述格式（protobuf、HTTP chunked）。工程上还要处理"半包"——读到的数据不足一条完整消息时要缓存起来等下次可读，并且必须给长度字段设上限，否则对端报一个超大长度就能让服务端按声明分配内存直接 OOM。

**`*p++` 与 `(*p)++`、编译链接之外的笔试小题**：`*p++` 因为后缀 ++ 优先级更高，等价于 `*(p++)`，取的是当前 p 指向的值、然后 p 自增，表达式类型是指向对象的类型；`(*p)++` 是先解引用再自增那个对象的值，指针不动。区别落到笔试题上就是"指针有没有移动、被指向的值有没有变"。不用第三个变量交换两个数有三种常用写法：加减法 `a=a+b; b=a-b; a=a-b`（可能溢出）、异或法 `a^=b; b^=a; a^=b`（要求两个变量不同地址，自己和自己换会清零）、以及 C++ 用 `std::swap`。至于 `&&`、`||` 与 `%`、`/` 的区别，要讲清短路求值：`&&` 和 `||` 返回布尔语义并且可能不计算右侧，`%`、`/` 是算术运算且除数为 0 是未定义行为，负数取模的符号规则也常被拿来出题。
