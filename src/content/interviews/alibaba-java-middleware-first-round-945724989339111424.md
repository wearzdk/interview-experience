### 《面试题目》

1. ZGC 的颜色指针为什么只用 42 位？剩下的 22 位用来做什么？
2. 多视图映射（Multi-Mapping）和 42 位指针是什么关系？
3. 如果堆内存超过 4TB，42 位不够用了怎么办？

### 《参考解析》

**颜色指针的本质是「把 GC 状态编码进指针本身」**。64 位指针里，低 42 位是对象的真实虚拟地址，2^42 = 4TB，这是 ZGC 设计之初覆盖的最大堆容量；第 42 到 45 位这 4 位存放 Marked0、Marked1、Remapped、Finalizable 四个标记位；再往上的 18 位（46 到 63）保留未用。为什么不是「42 位刚好够用所以选它」，而是「把高位留给元数据」——这样堆内对象不需要额外的 mark word 位来记录 GC 状态，读屏障在拦截引用时只看指针就能判断对象处于哪个阶段，不必访问对象头，也不必暂停应用线程。

**多视图映射是让「颜色」在地址翻译阶段生效的机制**。ZGC 在虚拟地址空间里把同一份物理内存映射到多个视图，每个视图对应一组颜色位组合；应用线程拿着一个「旧颜色」的指针去访问对象时，MMU 按指针高位选到对应视图，在地址翻译时自动完成引用修正，落到正确的物理地址。所以颜色指针负责「标记状态」，多视图映射负责「翻译地址」，两者配合才能在并发重定位（对象搬家）时让应用线程几乎无感知——这也是 ZGC 不需要软件写屏障、停顿能压到毫秒级以下的原因。

**堆超过 4TB 时，位宽是可调的**。ZGC 的地址位宽不是写死的常量，后续版本支持按最大堆动态选择 42 到 44 位（对应 4TB 到 16TB），地址位变多就意味着可用于颜色的位变少，需要更精细的编码来复用状态位。这背后是一个三方权衡：地址空间（能支持多大的堆）、元数据能力（能编码多少 GC 状态）、以及实现复杂度（读屏障与映射表的维护成本）。回答时能把「为什么是低位做地址、高位做元数据」讲清，比记住 42 这个数字重要得多。

**延伸考点**：ZGC 的并发标记与并发重定位分别靠什么保证正确性（读屏障 + 转发表）、染色指针与分代 ZGC 的差别（分代后需要额外的 remembered set 与屏障组合）、以及它和 G1/Shenandoah 在停顿与吞吐上的取舍。社招面到中间件团队，通常还会顺着问「你线上用什么收集器、为什么、调过哪些参数、遇到过什么 GC 问题」，准备时要能落到自己负责过的服务上。
