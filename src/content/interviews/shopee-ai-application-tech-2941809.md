### 《面试题目》

1. ReAct 核心思想是什么？与 CoT 有什么区别？ReAct 的短板是什么？
2. MCP 协议是什么？在 Agent 工具生态中起什么作用？Function Calling 与 MCP 有什么异同？
3. 长上下文工程常用哪些手段？超长上下文在位置编码、注意力开销、信息遗忘上的挑战与解决方案是什么？
4. RAG 的完整链路是什么？检索阶段、生成阶段各自的幻觉类型与缓解办法是什么？
5. Function Calling 的底层原理是什么？什么时候会出现格式错误？提升调用准确率的方案有哪些？
6. Agent 的多层记忆如何划分？会话记忆、个人记忆、团队记忆在存储载体、生命周期、检索方式上有什么差异？
7. 长时记忆如何做选择性遗忘？如何防止记忆库无限膨胀？
8. 多用户共用 Agent 时，记忆归属会冲突，如何设计权限隔离？

### 《参考解析》

**这类题的共同骨架**：先一句话给定义或结论，再讲清机制（为什么这样工作），最后落到工程取舍（代价是什么、线上怎么防）。只背名词、不回答「代价与边界」是这类面试最常见的失分点。

**第 1 题，ReAct 与 CoT**。结论：CoT 是「想」，ReAct 是「想—做—看」的循环。机制：Thought 产出下一步动作，Action 调工具，Observation 回写上下文，循环直到给出答案。区别在于信息来自模型内部还是外部环境。短板要具体：轨迹变长后上下文膨胀、错误沿轨迹传播、重复调用与死循环、延迟成本线性增长、对工具返回格式敏感。工程对策：最大步数、观察结果压缩、失败重试与终止条件、全链路轨迹记录。易错点：把 ReAct 说成「更高级的 CoT」，或只讲优点不讲失效模式。

**第 2 题，MCP 与 Function Calling**。结论：Function Calling 是模型能力，MCP 是连接协议。机制：工具 Schema 进上下文，模型输出结构化调用意图，宿主执行后回传；MCP 把工具的发现、描述、调用与传输标准化，让客户端接入多个服务端。关系：MCP 工具最终仍以 Function Calling 形式被模型调用。易错点：把两者说成竞争关系，或忽略 MCP 带来的权限与信任边界问题（第三方 Server 的工具描述本身就是不可信输入）。

**第 3 题，长上下文**。按三层答：位置编码（RoPE 外推、NTK / YaRN、ALiBi）、注意力开销（FlashAttention、稀疏与滑窗、GQA / MQA、KV Cache 量化与分页、前缀缓存）、信息利用（分段摘要、结构化改写、检索替代全塞、关键约束放头尾）。要主动提「lost in the middle」：上下文变长不等于有效利用变强，中间位置的信息召回会下降。易错点：只列技术名词，不说明各自解决的是「能不能表示位置」「算不算得动」「记不记得住」中的哪一个问题。

**第 4 题，RAG 幻觉**。链路：解析与切分 → 索引（向量 / 关键词 / 混合）→ 查询改写 → 召回 → rerank → 组装上下文 → 生成 → 引用与校验。检索段幻觉是漏召回与错召回，指标看 recall@k、MRR，手段是混合检索、结构化切分、多查询、元数据过滤、rerank、证据阈值。生成段幻觉是「有证据但答错」，表现为忽略证据、跨来源拼接、数字错配、引用不支持结论；手段是限定证据范围、逐句引用、证据不足时拒答、程序化校验数字与实体、生成后做支持性检查。易错点：把两类幻觉混成一句「模型会胡说」，或只谈生成不谈检索。

**第 5 题，Function Calling**。结论：本质是「按 Schema 生成结构化输出」，现在多由受约束解码保证格式。格式错误的高发场景：Schema 嵌套过深、联合类型与大量可选参数、工具过多且描述重叠、要求同时输出自然语言与 JSON、流式被截断。提升准确率：收敛工具集、写清使用与不使用条件、参数用枚举与示例、减少必填项、给正反例、结构化错误回传让模型重试、关键调用做校验与确认。易错点：把「提示词里写请输出 JSON」当主要方案。

**第 6 题，多层记忆**。用一张表答最清楚：会话记忆存在上下文与短期缓存，生命周期为一次会话，按时间与摘要检索；个人记忆存在结构化库加向量索引，按用户命名空间，生命周期数月，支持导出与删除；团队记忆存在知识库 / 文档库，按组织或项目命名空间，生命周期最长，要求版本与来源可追溯。补充三者的写入权限与一致性差异。易错点：只讲存储介质，不讲谁写、谁能读、怎么删。

**第 7 题，选择性遗忘**。四层机制：重要性打分、时间衰减、合并抽象、容量配额；配套去重与冲突覆盖（保留版本），以及用户要求忘记时的硬删除。指标看「关键事实召回是否保持」与「存储增长是否收敛」。易错点：答成「定期删最旧的」，那会把低频但关键的事实删掉。

**第 8 题，多用户隔离**。原则：写入带归属、检索带过滤、越权不可见、跨范围可审计。做法：租户 / 用户命名空间、可见范围字段、查询层强制权限过滤（不能先召回再在应用层筛）、团队共享走显式授权、缓存键含租户与权限版本、工具调用做用户级鉴权。易错点：只在提示词里写「不要泄露其他用户信息」，那不是隔离。
