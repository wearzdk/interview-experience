### 《面试题目》

1. InnoDB 在主键、唯一键和普通非索引字段条件下执行 UPDATE 时如何加锁？
2. RC 隔离级别下使用唯一键条件更新时，加锁范围是什么？
3. Java 垃圾回收为什么需要分代算法？
4. 如何设计支持提前一年预订和代他人购票的重复订单拦截？
5. 如何分享一次主动学习并落地 AI 技术的经历？

### 《参考解析》

InnoDB 的加锁范围取决于访问路径、隔离级别和是否命中唯一索引，分析时要区分记录锁、间隙锁与临键锁，不能只背结论。重复订单拦截应定义业务唯一键，先用数据库唯一约束保证最终一致，再配合幂等令牌和过期策略处理重试。AI 项目复盘应说明目标、方案、评测数据和失败边界。
