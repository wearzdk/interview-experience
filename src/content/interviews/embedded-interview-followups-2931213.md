### 《面试题目》

1. 这个变量为什么放在这里？它落在哪个段？
2. 中断里为什么不能这么写？
3. 这个锁到底保护了什么？
4. DMA 传完之后，缓冲区什么时候可以复用？
5. 链接脚本一改，程序为什么起不来？
6. 复位之后到 main 之前，中间发生了什么？
7. 队列和信号量怎么选？阻塞、唤醒和超时分别怎么定？
8. UART、SPI、I2C 的时序、错误处理和 DMA 传输分别怎么设计？
9. 项目里写了「实时」，最坏执行路径和任务优先级是怎么设计的？
10. 需求一改就出问题，你会从内存、时序还是并发入手排查？
11. 这个指针为什么不能返回？
12. 这个结构体为什么解析错位？
13. 中断和任务之间共享的数据，谁写谁读？临界区该包住哪几行？
14. 中断上下文为什么不能阻塞？
15. 总线的主从关系、时钟来源和错误恢复怎么讲？阻塞轮询、中断和 DMA 各适合什么场景？
16. 向量表、段初始化、栈布局和 HardFault 现场分别怎么看？

### 《参考解析》

**这类追问在判断什么**：面试官往下压两层，确认的是三件事——写的代码底层机制是不是真的理解；出了问题能不能按内存、时序、并发、启动链路的顺序定位；简历上的 MCU、RTOS、驱动是不是只停留在调过例程。所以答法不是背名词，而是走一条链：这个机制解决什么问题 → 不用它会怎样 → 用错了会出现什么现象 → 出了 bug 从哪查 → 项目里哪段代码对应得上。能说出名词只算听过，能解释取舍和排错路径才算接得住。

**变量放在哪，为什么**：局部变量在栈上，函数返回就失效；函数内 static 和全局变量在 .data（有初值）或 .bss（零初始化），生命周期是整个程序；字符串常量和 const 数据可能在 .rodata；malloc 出来的在堆上，要自己管释放。答「为什么放这里」必须落到生命周期和可见性，再补一句放错会怎样：把局部数组的地址返回出去就是悬空指针，把大缓冲区放栈上会栈溢出，把频繁改的标志放只读段直接编译不过。

**结构体解析错位**：这是协议类项目最常翻的车。原因无非对齐、字节序和位域：结构体被插入 padding，收到的字节流长度和 sizeof 不一致；多字节字段大小端没转换；位域的排布依赖编译器和架构。正确做法是按字段显式解析（固定偏移读、显式转字节序），或者用 packed 加明确的平台代价说明，绝不把收到的字节流直接 memcpy 成结构体。

**中断、DMA 与任务的并发**：中断上下文不能阻塞，因为它没有可以睡眠的上下文，睡眠就意味着中断无法返回、系统卡死；也不能长循环、不能调 printf 或 malloc。所以共享数据用最小临界区加原子操作或无锁结构：单生产者单消费者用环形缓冲配读写指针，注意编译器和 CPU 的重排（volatile 不够，需要屏障）；多写者才上锁。DMA 缓冲区能不能复用取决于「完成」的语义，驱动的完成回调或中断里确认传输结束后才能复用，同时要处理 cache 一致性——DMA 前 clean、DMA 后 invalidate，或者直接用非缓存内存，否则 CPU 读到旧数据。任务优先级要能讲出最坏路径：谁会被谁抢占、优先级反转怎么防、中断到任务的最坏延迟是多少。

**总线为什么通**：能收发只是起点，要讲主从关系（谁产生时钟、谁发起传输）、时钟来源与分频、错误恢复（NACK 怎么处理、超时怎么退、总线锁死怎么救）。三种传输方式的选择也要说得具体：小数据低频用阻塞轮询，简单但占 CPU；数据零散、要求及时响应用中断；大批量高吞吐用 DMA，代价是复杂度和一致性处理。

**启动、链接与 HardFault**：复位后先从向量表取初始 SP 和 Reset_Handler，启动代码关中断、初始化时钟与内存、把 .data 从 Flash 拷到 RAM、把 .bss 清零，再调 SystemInit 和 main。链接脚本决定这些段的地址和大小，改错了会出现向量表没对齐、栈被放到不可写区域、.data 超出 RAM 这类问题，现象就是启动阶段直接 HardFault 或跑飞。查 HardFault 要看压栈的 PC 和 LR 定位出错指令，再读 CFSR、HFSR 判断是总线错误、用法错误还是内存管理错误，配合栈回溯和 map 文件找到具体函数。
