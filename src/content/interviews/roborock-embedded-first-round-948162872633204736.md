### 《面试题目》

3. 嵌入式工程里 boot、驱动、中间件、应用通常怎么划分职责？
4. 解释一下 C 里的 restrict 关键字，实际项目里你会怎么用？

6. sizeof 是运算符还是函数？对数组名和指针分别有什么结果？

### 《参考解析》

**扫地机的软件链路。** 从下往上可以分成五段：传感采集（激光雷达、视觉、IMU、碰撞与悬崖传感器、尘盒与电量检测，进驱动层做时间戳对齐与滤波）、感知与定位（建图、定位、障碍识别，输出环境地图与位姿）、规划决策（清扫路径、避障策略、回充、分区与禁区）、运动控制（速度与姿态闭环，驱动轮、风机、滚刷、水泵等执行器）、以及贯穿各层的通信、电源管理、故障诊断与 OTA。回答时补一句实时性分层：感知与规划可以跑在应用处理器上、周期几十毫秒；电机闭环必须在 MCU 上、周期百微秒级，两者通过 CAN 或串口交换指令与状态。

**分层职责。** Boot 负责时钟与引脚初始化、启动跳转、必要的升级与版本校验（A/B 分区、回滚）；驱动负责寄存器操作、中断与 DMA，对上提供稳定接口，屏蔽芯片差异；中间件提供协议栈、文件系统、日志、参数管理、RTOS 封装；应用只做业务状态机、策略与人机交互，不直接碰寄存器。边界清晰的价值是移植成本低、问题好定位——换一颗 MCU 只改驱动层，换一个业务策略不动驱动。

**restrict 的语义与风险。** `restrict` 是给编译器的承诺：在它的作用域内，该指针是访问目标对象的唯一方式（不存在别名）。编译器据此可以省掉「每次写完都重新从内存读」的保守行为，做更激进的优化。它常用于性能敏感的拷贝、滤波、矩阵运算接口参数。风险在于这是契约而不是检查：如果实际存在别名却标了 `restrict`，编译器优化后可能读到旧值，结果是未定义行为且很难排查。嵌入式里不是必须用，只有在热点循环里、且能证明无别名时才值得加。

**inline 与宏。** 宏是预处理阶段的文本替换，没有类型检查、参数可能被多次求值（`MAX(a++, b)` 的经典坑）、调试时看不到符号；inline 是编译器层面的建议，有类型检查、可调试、可被内联也可能不被内联（取决于优化等级与函数大小）。选择原则：小函数、需要类型安全用 `static inline`；需要跨编译单元强制展开、或需要字符串化/拼接等预处理能力时才用宏。常量用 `const` 或 `enum` 而不是宏，能获得类型与作用域。

**sizeof 与 2 的幂。** `sizeof` 是编译期运算符（少数变长数组场景推迟到运行期），不是函数。对数组名得到整个数组的字节数；对指针得到指针本身的大小（32 位系统 4 字节、64 位 8 字节）。数组作为函数参数会退化为指针，所以函数内 `sizeof(arr)` 得到的是指针宽度——这也是必须显式传长度的原因。判断 32 位无符号数是否为 2 的幂：`n && ((n & (n - 1)) == 0)`。原理是 2 的幂的二进制只有一个 1，减 1 后该位变 0、低位全变 1，按位与结果为 0；`n == 0` 要单独排除，因为 0 也满足 `n & (n-1) == 0` 但不是 2 的幂。

**DMA 与 Cache 一致性。** 多数平台允许 CPU 与 DMA 同时访问同一块内存，但要注意三件事：其一，Cache 一致性——DMA 直接写内存，CPU 可能从 Cache 读到旧数据（DMA 写）或 DMA 读到 CPU 尚未写回的数据（CPU 写），需要按方向做 cache invalidate / clean，或把缓冲区放在非 cache 区；其二，总线竞争——DMA 占用总线会拖慢 CPU 访问同一块内存，高带宽场景要评估总线矩阵与优先级；其三，缓冲区的对齐与长度要满足外设要求（例如 4 字节对齐、长度是 burst 的整数倍），传输期间应用层不能改写同一缓冲，用双缓冲或完成回调切换。没有 Cache 的小 MCU 上主要考虑后两点。
