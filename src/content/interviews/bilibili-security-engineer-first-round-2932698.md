### 《面试题目》

1. 详细介绍你的项目。（会问得非常细致，用来确认这件事确实是你做的）
2. HTTP 的原理是什么？
3. HTTP 请求报文和响应报文分别包含哪些部分？常见的响应状态码有哪些？
4. WAF 是什么？

### 《参考解析》

**「确认项目是不是你做的」是安全岗一面最常见的开场**，因为安全方向的简历水分最大，且候选人常常只是跟着靶场刷过题。它通常沿四条线往里钻：这个系统原来有什么问题、你是怎么发现的（手工还是工具、扫的哪个面）、你具体改了什么（是加了过滤还是改了架构）、改完之后怎么验证有效（有没有复现、有没有回归）。只要在「谁写的这段代码」和「数据从哪来」上含糊一次，后面的问题就会变成审问。准备时给项目画一张数据流图，标出每个信任边界和你动过的位置，基本就稳。

**HTTP 的「原理」要答到分层和连接上**，不是背方法名。应用层协议、靠 TCP 提供可靠传输、请求-响应模型、无状态（状态靠 Cookie/Session/Token 承载），HTTP/1.1 默认 keep-alive 复用连接但有队头阻塞；HTTP/2 用二进制分帧和多路复用解决应用层队头阻塞，头部用 HPACK 压缩；HTTP/3 换到 QUIC 解决 TCP 层的队头阻塞。再补一句 HTTPS 是在 HTTP 与 TCP 之间加 TLS 做认证与加密，就够完整。

**报文结构是硬知识点**。请求报文是请求行（方法、URI、协议版本）+ 请求头 + 空行 + 请求体，响应报文是状态行 + 响应头 + 空行 + 响应体。请求头常被问的有 `Host`（HTTP/1.1 必填，虚拟主机靠它路由）、`Content-Type`、`Content-Length` 与 `Transfer-Encoding: chunked`、`Cookie`、`Authorization`、`X-Forwarded-For`（代理链上真实 IP 的来源，也是绕 WAF 的常见入口）。状态码要能说语义而不只是名字：301 永久重定向（会被缓存）、302/307 临时重定向（307 保留方法）、304 命中协商缓存、400 请求本身有问题、401 未认证、403 已认证但无权限、405 方法不允许、429 限流、500 服务端异常、502 网关拿到无效响应、503 服务不可用、504 网关超时。顺着 502/504 追问「线上出现过吗、怎么定位的」是很常见的下一步。

**WAF 要答出部署形态和局限**。Web 应用防火墙工作在应用层，按规则/语义/机器学习识别 SQL 注入、XSS、命令执行、路径穿越、恶意爬虫与 CC 攻击，形态有云 WAF（DNS 或 CNAME 接入）、反向代理型、插件型（ModSecurity + OWASP CRS）。与 IPS/IDS 的区别在：WAF 串在链路上能阻断，IDS 只旁路告警。最容易追问的是「WAF 能不能全信」——不能：编码变形、分块传输、注释与大小写混淆、超长参数、JSON 嵌套都能绕过规则匹配，真正的防线还是参数化查询、输出编码、最小权限，WAF 只做兜底和争取修复时间。误报也要提：正常请求被拦时靠白名单和观察模式（只记录不阻断）过渡。

**面试官态度好不代表要求松**。B 站这类内容平台的安全岗还会关心风控与业务安全的交界（撞库、薅羊毛、内容安全），反问时问团队更偏基础安全还是业务安全，是个能加分的问题。
