### 《参考解析》

**三次握手与两次为什么不够**：客户端发送 SYN 与初始序列号，服务端回复 SYN+ACK（自己的序列号与对客户端序列号的确认），客户端再发 ACK。第三次的作用是让服务端确认「客户端能收到我的报文」，从而确认双方收发能力都正常。只用两次时，服务端无法区分「客户端真实发起的新连接」与「网络中滞留的旧 SYN」，后者会让服务端建立一条客户端并不存在的连接，浪费资源并被用于 SYN 泛洪放大。三次握手同时完成序列号同步，为后续可靠传输提供起点。

**子网与 CIDR**：把掩码写成二进制，数其中连续 1 的个数即前缀长度。例如 `255.255.255.0` 是 `/24`，可用主机数为 `2^(32-24) - 2 = 254`（去掉网络地址与广播地址）；`255.255.254.0` 是 `/23`，可用 510 台。CIDR 地址块长度即前缀位数，块内地址数为 `2^(32-前缀)`；划分子网时用「借位」，每借一位子网数翻倍、每个子网可用主机数减半。点分十进制与二进制互转要熟练，考试里常常给出一个 IP 与掩码让判断网络地址与广播地址。

**常见端口**：HTTP 80、HTTPS 443、DNS 53（TCP 与 UDP 都用，区域传送走 TCP）、SMTP 25（提交常用 587）、FTP 控制 21、数据 20、SSH 22、Telnet 23、MySQL 3306、Redis 6379。

**HTTPS 的安全机制**：TLS 在 TCP 之上提供三件事——握手阶段用非对称加密（或 ECDHE 密钥交换）协商出会话密钥并验证证书链，确认服务端身份；记录层用对称加密保护传输内容的机密性；用 MAC 或 AEAD 保证完整性，防篡改。证书由受信任的 CA 签发，客户端校验证书链、域名与有效期，避免中间人攻击。

**路由转发**：路由器收到报文后查目的 IP，按最长前缀匹配在路由表中找到下一跳与出接口，重写二层帧头（源 MAC 改为出接口、目的 MAC 改为下一跳），同时递减 TTL，TTL 归零则丢弃并回 ICMP 超时。默认路由用于兜底，ARP 负责把下一跳 IP 解析为 MAC。NAT 场景下还要改写源地址与端口并维护会话表。

**防火墙与 Web 漏洞**：防火墙的核心功能是按五元组与状态做访问控制、NAT、应用层过滤与日志审计，分为包过滤、状态检测与应用层代理三类。常见 Web 漏洞包括 SQL 注入、XSS、CSRF、SSRF、文件上传与路径穿越、越权（水平与垂直）、反序列化、命令注入、XXE 与开放重定向；防护要靠参数化查询、输出编码、CSP、CSRF Token、上传白名单与内容校验、最小权限与服务端逐次鉴权。

**Linux 权限**：三位数字分别对应属主、属组、其他人的 `rwx` 权值（r=4、w=2、x=1）。744 表示属主可读写执行、属组只读、其他人只读；755 是属主全权、其他人可读可执行，常用于目录与可执行文件；644 是属主读写、其他人只读，常用于普通文件。目录的执行位代表可进入与可遍历，缺少 x 时即便有 r 也无法访问目录内的文件。

**文本查找命令**：`grep` 按内容匹配并支持正则，`-r` 递归、`-n` 行号、`-A/-B/-C` 上下文；`find` 按名称、大小、时间、权限找文件并可配合 `-exec`；`locate` 查预建索引，速度快但可能过期；`which` / `whereis` 找可执行文件位置；`awk`、`sed` 做按列提取与流编辑。

**3-2-1 原则与加密**：至少保留 3 份数据、存放在 2 种不同介质上、其中 1 份异地保存；目的是同时防硬件故障、误删与区域性灾难，并定期做恢复演练。对称加密用同一密钥加解密，速度快，适合大数据量，难点在密钥分发；非对称加密用公钥加密、私钥解密（或反向签名），解决密钥分发与身份认证，但速度慢，通常只用于密钥交换与签名，实际传输采用「非对称协商 + 对称加密数据」的混合模式。

**OSI 七层与虚拟化**：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。虚拟化分为全虚拟化（如 KVM，客户机无需修改）、半虚拟化（客户机配合修改，如早期 Xen）、硬件辅助虚拟化（VT-x/AMD-V）、操作系统级虚拟化（容器）以及网络与存储虚拟化。虚拟机虚拟的是硬件，每台有独立内核，隔离性强但启动慢、开销大；容器共享宿主机内核，靠 namespace 做隔离、cgroups 做资源限制，启动快、密度高，但隔离边界弱于虚拟机。

**TCP 与 UDP**：TCP 面向连接、可靠、有序、有流量控制与拥塞控制，头部 20 字节起，适合文件传输与 Web；UDP 无连接、不保证可靠与顺序、头部仅 8 字节、开销小、时延低，适合音视频、DNS 查询与游戏。需要可靠性的 UDP 场景通常在应用层自行实现重传与拥塞控制（如 QUIC）。

**敏感信息服务器的加固**：账号侧禁用 root 远程登录、用密钥认证并关闭密码登录、按角色分配最小权限、开启 sudo 审计与登录失败锁定；网络侧只开放必要端口、用防火墙限制来源、管理口走跳板机或 VPN、关闭不必要的服务；数据侧对敏感字段加密存储、传输走 TLS、密钥与配置分离并由密钥管理服务托管、日志脱敏；系统侧及时打补丁、开启 SELinux 或 AppArmor、用文件完整性监控与集中日志审计；运维侧做定期备份与恢复演练、变更留痕、异常登录与提权告警。
