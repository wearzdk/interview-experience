### 《面试题目》

1. 面向对象的三大特性是什么？
2. MySQL 和 Redis 有什么区别？
3. 了解拆箱和装箱吗？
4. RabbitMQ 的作用是什么？
5. 如果客户购买商品后要求退款，商家怎么实时处理？

### 《参考解析》

**三大特性**：封装是把状态和操作绑定、只暴露必要接口；继承是复用与扩展，注意组合优于继承；多态是同一接口不同实现，Java 靠「编译期看声明类型、运行期看实际类型」的方法分派实现，重载是编译期静态分派、重写是运行期动态分派。

**MySQL vs Redis**：定位不同。MySQL 是关系型、磁盘持久化、支持事务与复杂查询、强一致；Redis 是内存 KV、单线程处理命令（6.0 起 IO 多线程）、毫秒级、支持丰富数据结构，但持久化是异步的（RDB/AOF），可能丢少量数据。生产中 Redis 常做缓存、分布式锁、计数器、排行榜，MySQL 是真源。答的时候补一句「缓存与数据库的一致性问题怎么处理」通常能加分：先更新库再删缓存 + 延迟双删 + 过期兜底。

**装箱拆箱**：基本类型与包装类型的自动转换，`Integer i = 1` 是 `Integer.valueOf(1)`。考点在缓存：`Integer` 默认缓存 -128~127，所以 `Integer a=127,b=127` 时 `a==b` 为 true，128 则为 false，比较必须用 `equals`。拆箱时对象为 null 会 NPE，这是最常见的线上事故来源。

**RabbitMQ 的作用**：解耦（生产者不用知道消费者）、异步（把非核心链路如发短信、写日志移出主流程）、削峰（突发流量进队列按能力消费）、可靠投递（confirm + 持久化 + 手动 ack + 死信队列）。要说清「怎么保证不丢、不重复」：生产者 confirm、队列与消息持久化、消费端手动 ack、消费幂等靠业务唯一键。

**退款实时处理**：一条典型链路是——退款请求落库生成退款单（幂等键为订单号 + 退款批次），发消息到 MQ，支付网关异步回调更新状态，库存与优惠券按策略回补，最后通知用户。实时性靠「消息 + 回调」而不是轮询；一致性用状态机 + 定时对账兜底，异常单进人工队列。回答时把「幂等」「状态机」「对账」三个词说出来，比画架构图更有说服力。
