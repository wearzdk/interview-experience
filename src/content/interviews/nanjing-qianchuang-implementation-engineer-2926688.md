### 《参考解析》

**Linux 服务的排查是一条固定链路，从「进程有没有起来」倒着往回查。** 先看进程和服务状态（`systemctl status`、`ps -ef | grep`）、再看端口有没有监听（`ss -lntp`）——进程活着但端口不监听，通常是配置加载失败或绑定到了错误的地址；接着看日志，这是最关键的一步，MySQL 是 `error.log`（`/var/log/mysql/error.log` 或数据目录下），systemd 托管的服务还会把启动期的报错吞进 `journalctl -u mysql -n 200`。日志之外按概率排：磁盘满（`df -h`）、数据目录或 socket 文件权限不对（`ls -l`、SELinux 或 AppArmor 拦截也会留痕）、配置文件语法错（`mysqld --validate-config`）、端口被占、上次非正常关闭导致 InnoDB 需要恢复。答这题时要把「先确认现象、再收窄范围、最后动手改」的顺序讲出来，而不是背命令清单——面试官考的是排障习惯。

**401 和 500 的区别不在数字，而在「责任方」。** 401 是未认证，请求根本没通过身份校验——没带 token、token 过期或签名不对，客户端要做的是重新登录或刷新凭据，服务端不该在这里报 5xx。顺带区分两个常被混的：403 是已认证但没权限，404 是资源不存在。500 是服务端内部错误，说明请求进来了但处理过程中抛了异常，要看服务端日志和堆栈定位。做接口回归（或接口自动化）时，这套状态码语义直接决定了断言怎么写：401/403 应该是稳定的预期值，一旦回归里出现 500 就是必须拦下来的缺陷，而不是「通过」。回归流程的标准动作是：确认环境与数据基线 → 用测试用例集按优先级跑通主链路 → 校验响应状态码、业务码、关键字段与库里的落库结果 → 失败的用例单独记录并复现 → 输出报告与缺陷单，修复后重跑受影响的部分而不是全量重来。

**Docker 和反向代理在实施岗里考的是「你会不会交付」，不是「你会不会写 Dockerfile」。** 能说清容器化的收益和常见坑就够了：环境一致性免掉「我这里能跑」，但要注意数据卷必须外挂（容器一删数据就没了）、时区与编码要在镜像里固定、`restart: always` 这类重启策略要配、日志要落到宿主机方便排查。反向代理（Nginx 为主）要能说出它在实施场景里的四个作用：把内网多个服务收敛到一个端口对外、做 HTTPS 卸载（证书只装一处）、做负载均衡与简单的健康检查、以及通过 header 透传真实客户端 IP 和转发协议（不然后端拿到的全是代理的地址）。常用的就是 `proxy_pass`、`proxy_set_header Host/X-Real-IP/X-Forwarded-For`、`location` 前缀与正则匹配优先级，以及改完配置 `nginx -t` 校验再 reload。数据库连接工具（Navicat、DBeaver、DataGrip、命令行 client）答的时候顺带说一句你会做什么——看表结构与索引、跑只读 SQL 核对数据、导出导入，以及生产库上只做查询不做结构变更。

**「现场不具备实施条件」是考你的判断和沟通顺序，正确动作是先止损、再对齐、最后留痕。** 第一步确认到底缺什么、缺到影响哪一步：是网络不通、没有机位电源、客户侧对接人不在、还是前置系统还没验收。能自己解决的小问题（需要一根网线、需要开个策略）当场解决；解决不了的，不要在现场硬试也不要擅自改客户的网络与安全策略，而是立刻把影响面报给己方项目经理和客户的对接人，给出两个可选方案（今天先做哪部分、剩下的约什么时间）让对方确认。所有变更与等待都要落在实施记录里（时间、原因、对接人、结论），这既是交付凭证也是免责依据。核心原则：不承诺做不到的工期，也不把问题带回去自己扛——现场实施最忌讳的是「先不说，回去再想办法」。

**客户情绪激动的场景，处理逻辑是「先接情绪、再谈事实、最后给时间表」。** 第一步不要在对方激动的时候解释技术细节或辩解责任归属，那只会升级；先复述他关心的问题，确认你听懂了（「您担心的是这次上线影响了正常业务，对吗」），让他知道有人接住了。第二步把话题从「谁的错」拉回「怎么解决」，明确说清你现在能做什么、需要谁配合、大概多久有结果，给一个具体的下一次同步时间。第三步才是回到事实与责任划分，而且尽量在书面上做，避免口头扯皮。还有一个前提是别把情绪当成针对自己——实施岗遇到的多半是业务压力转移，专业的态度是把事推着走。答这题时如果只答「耐心沟通、安抚情绪」是拿不到分的，要给到可执行的步骤。

**最后三个问题（应届、出差、薪资）是硬条件确认，答得含糊会被直接筛掉。** 能否全国出差是实施岗的准入项，如果有真实限制（家庭、健康、考证计划），要诚实说清限制的范围和频率，而不是先答应再做不下去——实施岗的差旅强度通常很高，入职后反悔的代价比现场被拒大得多。期望薪资要给区间而不是一个点，并且按「当地同岗位校招水平 + 差旅补贴是否包含在内」说明依据，同时反问一下薪资结构和补贴标准（出差补贴、住宿标准、报销周期这些对实施岗的实际收入影响很大）。这一段尽量问清楚，它比技术问题更决定你入职后的体验。
