### 《面试题目》

1. 自我介绍，讲一下你的知识储备、编程技能和项目经验。
2. 这两个 Agent 项目是实习产出还是在校学习做的？
3. Agent 项目调用的是内网私有模型还是公网模型？模型版本是什么？
4. 第一个 Agent 项目里四个智能体分别负责什么工作？
5. Agent 项目是你独立完成的吗？
6. 项目是手写代码还是 AI 辅助编码？部署在哪里、怎么和用户交互？
7. Java 项目是什么背景下做的？实现了哪两套系统、核心功能是什么？
8. Java 项目用什么 IDE、哪个 Java 版本、MySQL 什么版本？
9. 单体外卖项目设计了多少张数据库表？
10. Redis 在项目里的使用场景是什么？
11. Java 项目的前端怎么处理？后端接口怎么验证？Vue 掌握到什么程度？
12. 工作分配上，你更偏向 Java 后端还是 Agent 智能体开发？
13. 在校课程偏向模型训练微调，还是大模型上层智能体应用？
14. 听完岗位和业务介绍，你有什么想问的？

### 《参考解析》

**这场面试的由来，本身就是一条经验**。HR 大概是看到候选人在本地才主动联系，原本约的是 Java 开发实习；电话里听说做过 Agent，就让改简历，于是校内做的两个「简易小项目」被推到了主位。结果 20 分钟里十几个问题几乎都在核验同一件事：简历上写的东西是不是你亲手做的。这类被 HR 临时改方向的面试很常见，准备时的原则是——简历上任何一行都要能撑住「环境、模型、调用方式、部署形态、交互入口」这五个具体名词，说不出名词的部分宁可删掉。

**真实性追问链该怎么接**。问「内网还是公网、什么版本」不是好奇，而是最快的验伪手段：真跑过的人记得模型名和版本、记得怎么配 key、记得限流和超时踩过什么；只是看过教程的人答不上具体版本。问「四个智能体分别负责什么」是在验你把多智能体当概念还是当代码——分工要能说出输入输出和交接条件（谁产出计划、谁调工具、谁校验、谁汇总，失败了回到哪个节点）。问「是否独立完成」时，团队项目就说清边界：哪几个模块是你写的、接口是谁定的、你改了别人哪部分。把别人的活说成自己的，一追细节就露。

**「手写还是 AI 辅助」这题别否认**。现在的面试官默认你会用 AI 编码，否认反而可疑。得体的答法是承认用了，然后说清三件事：哪些部分是生成的、你怎么验证它跑通（测试用例、日志、边界输入）、你改写了什么（换了实现、修了并发问题、补了错误处理）。对方真正担心的是这份代码你维护不了，所以重点落在「我能解释并改动每一行」上。

**版本类和数量类问题是防包装的标准题**。IDE、Java 版本、MySQL 版本、表数量、Redis 场景，这四个问题连在一起问，是判断你有没有真的建过库、跑过项目。表数量要能立刻报出来，并说清核心表之间的关系（订单、用户、商品、地址怎么关联，哪些字段建了索引）；Redis 要落到具体场景和失效策略——缓存什么数据、用的什么结构、过期时间怎么定、缓存和库不一致时怎么处理，只说「用过 Redis 做缓存」等于没答。

**前端与接口验证别夸大**。被问 Vue 掌握程度时，按真实水平说：能搭页面、能调接口、能改组件就够了，别声称精通。接口验证要给具体工具和动作（Postman / Apifox 建集合、覆盖正常与异常入参、跨域怎么配、登录态怎么带），这比背 Vue 的生命周期有用。

**两个意向类问题决定岗位匹配**。「更偏 Java 后端还是 Agent 开发」不要答「都可以」，给一个有理由的偏好，再说清另一条为什么也能接受——理由要落在做过的事上（比如「Agent 那边我完整跑通过工具调用链路，Java 那边我做过完整的订单流程，两边我都能上手，但更想继续做 Agent 的编排」）。「课程偏训练微调还是上层应用」是在确认你能干哪种活：公司做的是应用层，就老实讲你做过 prompt、工具调用、流程编排，别硬吹微调，否则下一个问题就会问你要 GPU 和数据集。
