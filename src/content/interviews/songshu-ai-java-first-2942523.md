### 《参考解析》

**Spring 循环依赖与三级缓存**：单例 Bean 的字段注入/Setter 注入循环依赖靠三级缓存解决。一级 `singletonObjects` 存成品；二级 `earlySingletonObjects` 存提前暴露的半成品；三级 `singletonFactories` 存对象工厂，用于在需要时生成早期引用（有 AOP 时生成代理）。创建 A 时先放工厂到三级缓存，填充属性发现依赖 B，创建 B 时又依赖 A，就从三级缓存拿到 A 的早期引用（或经工厂生成代理后放入二级），B 完成后 A 继续填充。

**构造器注入为什么不行**：构造器注入要求在实例化阶段就拿到依赖对象，此时对象还没被创建，无法提前暴露引用，三级缓存没有介入的时机，因此直接抛 `BeanCurrentlyInCreationException`。解决办法是改用字段/Setter 注入、加 `@Lazy` 延迟代理，或重构掉循环依赖——后者才是根因修复。

**回表与覆盖索引**：二级索引的叶子节点存的是索引列与主键值，按二级索引查到主键后还要回聚簇索引取整行，这一步就是回表。若查询需要的列全部包含在索引里（联合索引覆盖查询列），就无需回表，称为覆盖索引；`EXPLAIN` 的 Extra 显示 `Using index`。减少回表的办法是建合适的联合索引、只查必要列、避免 `SELECT *`。

**ReadView 判断可见性**：ReadView 记录生成时刻活跃的读写事务 ID 列表（`m_ids`）、最小活跃事务 ID（`min_trx_id`）、下一个将分配的事务 ID（`max_trx_id`）与创建者事务 ID。判断行记录的 `DB_TRX_ID`：小于 `min_trx_id` 可见；大于等于 `max_trx_id` 不可见；落在区间内则看是否在 `m_ids` 中，在则不可见。不可见时沿 undo log 找上一个版本。RC 每次查询生成新 ReadView，RR 在事务首次快照读时生成并复用。

**缓存雪崩**：大量 key 同一时刻过期，或缓存层整体不可用，请求全部打到数据库。对策：过期时间加随机抖动打散；热点数据逻辑过期 + 后台异步刷新；多级缓存（本地 + Redis）；缓存层做高可用（哨兵/集群）；对数据库入口做限流与降级，并用互斥锁保证同一 key 只有一个请求回源。

**手撕 SQL 与 DP**：SQL 中等题建议优先选窗口函数、`GROUP BY + HAVING` 或自连接类，先花一分钟读清口径（去重、并列、空值），再动手；DP 中等题先写状态定义与转移方程，用样例手推一遍再编码，卡住时先写暴力递归再记忆化，避免上来就写循环。选自己练过的题型，不要临场赌运气。
