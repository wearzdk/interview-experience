### 《面试题目》

1. 请做一下自我介绍。
2. 谈谈制造与运维的智能化该如何发展？
3. 机械设计方面有哪些经验？
4. 做过哪些机器人运动学仿真？
5. 用 Python 做过哪些数据分析？
6. 深度学习用过哪些框架？

### 《参考解析》

**这是典型的「岗位方向匹配」面试，不是八股面试**

从帖子看，面试官问得很泛，唯一被深挖的是论文。这种结构说明这一轮的真正目的不是考知识点，而是确认你的经历和岗位方向对不对得上：智能制造精密装备开发与自动化这个方向要的是「机械本体 + 运动控制 + 数据与算法」的交叉背景，所以每个问题背后都在找同一件事——你过去做过的东西里，哪一块能直接接到岗位上。答题策略因此要变：不要试图把一个方向讲得特别深，而要把几段经历按「我做过什么 → 用到什么方法 → 结果如何 → 和装备/自动化有什么关系」快速过一遍，让面试官自己挑一块追问。每段控制在 90 秒，主动留线索（「这里的运动学我用的是 DH 参数建模」），把追问的主动权交出去。

**制造与运维的智能化：要讲出层次，别停在名词**

这题几乎必问，答得好坏差别很大。建议分三层展开。第一层是设备与产线现场：给设备加传感（振动、温度、电流、视觉）、把 PLC/CNC 的数据采集上来，先解决「看得见」——OEE、稼动率、节拍、不良率能实时上看板。第二层是分析与决策：时序数据的趋势与突变检测做预测性维护，视觉做外观缺陷与装配防错，工艺参数的回归/寻优替代老师傅试参数，排产用运筹或仿真做优化。第三层是闭环：分析结果要能回到执行侧——自动下发参数、触发工单、联动 AGV 与机器人，否则再好的模型也只是报表。讲的时候最好挂一个自己做过的具体场景（例如「实验室里做过电机振动数据的异常识别」），并说清难点在哪：现场数据脏、标注成本高、样本不均衡、工况漂移导致模型上线后衰减。能主动提运维侧（备件预测、远程诊断、故障知识库）会比只谈制造更完整。

**机械设计与机器人运动学仿真：用「参数—验证—误差」三件套回答**

机械设计经验不要只报项目名字，按「需求与约束 → 方案选型 → 关键件计算 → 出图与加工 → 装调验证」讲一条完整的链，重点提你亲手做过计算或选型的部分（电机选型与扭矩校核、传动比与背隙、导轨与联轴器、公差与装配工艺性），并给出量化结果（重复定位精度、节拍、成本）。运动学仿真可以讲清你用的工具与方法：串联机械臂用 DH/改进 DH 建模，正解用齐次变换，逆解用解析法或数值迭代（雅可比伪逆、阻尼最小二乘），轨迹规划做关节空间与笛卡尔空间的插补、梯形/S 曲线速度规划，避奇异点与关节限位；工具上 MATLAB Robotics Toolbox、Adams、MuJoCo、Gazebo、ROS/MoveIt 都能提，但每提一个都要能说清「用它验证了哪个具体结论」。如果仿真和实物有偏差，讲清误差来源——建模忽略的柔性、间隙与摩擦、标定误差、控制周期——这类复盘比多报几个软件名加分得多。

**Python 数据分析与深度学习框架：诚实划边界，给出可迁移的部分**

数据分析这题的重点通常不是 pandas 语法，而是你有没有把数据用起来的完整经验：数据从哪来（实验采集、日志、公开数据集）、怎么清洗（缺失、异常、时间对齐）、怎么做探索性分析并得出结论、结论有没有落回决策。哪怕只是处理过实验数据、做过批量绘图与统计检验，也比空谈「会 numpy/pandas」强；能补一句可视化或报表自动化的例子更好。深度学习框架问题（PyTorch、TensorFlow、Keras、paddle 等）同样是「用过 + 做过什么」的格式：讲一个具体任务、数据规模、网络结构与训练技巧（学习率调度、数据增强、迁移学习）、最终指标，以及部署时的取舍（延迟、算力、量化）。如果只是跟着课程跑过 demo，就明说是课程/自学项目并讲清你理解的原理（反向传播、卷积、损失函数），把「我能多快补上」说实——面试官对校招生的期待本来就是基础扎实 + 可培养，硬吹深度会在后续追问里立刻露馅。

**论文与反问**

被深挖论文是这个方向面试里最正常的走向：面试官想确认这段工作是不是你主导的、有没有工程含量。准备时把论文压成「要解决什么问题 → 别人怎么做的、差在哪 → 我的方法核心是什么 → 实验怎么设计的、指标多少 → 有什么局限」，并准备好被问「如果换一批数据/换一个工况还成立吗」。帖子没有记录反问环节，但这类岗位值得问的是：团队当前做的装备方向、校招生入职后的项目节奏、需要补的技能栈（机械、电气、控制、算法哪块为主），以及入职前建议先学什么——这既是获取信息，也是在展示你会为岗位提前做准备。
