### 《面试题目》

1. 看你有使用过 AI，平常是怎么使用 AI 的？开发简历上那个项目时，有进行过 AI 辅助开发吗？有没有什么场景是 AI 辅助也不好完成、必须人工完成的？
2. 你开发的那个项目对接 SDK，你是怎么和客户经理交流需求、和前端对接的？有没有什么技术沉淀？
3. 看到你做过离线消息的拉取，如果拉取时某个接口超时或者耗时很长，你会怎么排查、加索引、优化？
4. 看你有运维部署的经历、修改过 Nginx 配置，说说你遇到过要修改 Nginx 配置的情况，当时怎么发现、怎么处理的？
5. 你是计算机专业的，简历上貌似只有一个项目，课程项目介绍一下？

### 《参考解析》

**「怎么用 AI」要答出工具链和边界，不能只说「用来查资料」。** 可以分三层：日常开发用 AI 做代码补全、单元测试草稿、报错解释；复杂任务用 harness 接模型 API（如 Claude Code、IDE 插件）做多文件修改和重构；学习时用 AI 做计划、出题、模拟追问。关键是给出一个「AI 帮不上」的具体场景：企业自研引擎、老旧框架、内部协议这类文档稀缺且充满隐式约定的代码，AI 容易按通用范式产生幻觉，必须人工读文档、确认状态机语义、再决定改哪里。这个回答既证明你真的用过，也证明你知道 AI 的边界——面试官反感的是「什么都让 AI 写」和「完全不用 AI」两个极端。

**SDK 对接的答案是「契约先行 + 文档沉淀」。** 和客户经理对齐的是业务目标、使用场景、交付时间，不是技术细节；和技术方对齐的是接口清单、字段含义、错误码、鉴权方式、版本兼容策略。落地时先写接口文档和示例代码，再做联调环境，最后把常见问题整理成 FAQ。技术沉淀不是写一篇总结，而是留下可复用的东西：接口契约（OpenAPI/Protobuf）、初始化与错误处理模板、联调 checklist、版本变更记录。面试官追问「前端怎么对接」时，要能说清数据格式、字段类型、空值约定、分页方式、跨域和鉴权，而不是「前端自己看文档」。

**慢 SQL 排查要按「定位 → 解释 → 改写 → 验证」走。** 先看接口耗时分布和日志，确认是数据库慢还是下游慢；打开慢查询日志，拿到具体 SQL 和参数；用 `EXPLAIN` 看访问类型、命中索引、扫描行数、是否临时表/文件排序。常见问题是联合索引顺序不对、范围查询后面的列失效、函数包裹索引列、`LIKE '%x%'` 前导通配、隐式类型转换。优化手段：补联合索引（把等值条件放前、范围放后）、覆盖索引减少回表、分页改写（深分页用「上次最大 id」或延迟关联）、大查询拆成子查询先缩小主键范围、必要时加缓存或异步化。改完要用真实参数对比执行计划和耗时，并在压测环境验证，不能只看「explain 里出现 index 了」。

**Nginx 大文件上传的问题，通常是三个配置一起撞。** 先是 `client_max_body_size` 默认 1M，超过直接 413；再是 `proxy_read_timeout` / `proxy_send_timeout` 默认 60s，大文件传久了被断开；还有 `proxy_request_buffering on` 会把整个请求先缓冲到磁盘，占空间也拖慢首字节。处理方式是按业务调整 body 限制、延长超时、必要时关闭请求缓冲让后端流式接收，同时在后端和网关层都做大小限制，避免「Nginx 放开了、应用又炸」。排查路径是看 Nginx error log（413/499/504）、看后端是否收到请求、用浏览器 Network 看请求卡在哪个阶段。原帖里候选人漏了「先看线上日志」这一步，面试官追问的正是这个顺序。

**课程项目是「简历只有一个项目」的补救，不是减分项。** 准备两段就够：一段讲技术栈与你的角色（SpringBoot + Vue 的绩效管理系统，你负责后端接口、权限、文档），一段讲一个具体难点（库存预减的原子性、消息队列削峰、并发下的超卖）。不要泛泛说「做了增删改查」，要讲清数据模型、关键接口、怎么测、上线后遇到什么问题。面试官问课程项目，本质是在确认你的基础是不是只有简历上那一个项目撑门面；能讲出取舍和踩坑，比项目数量更重要。
