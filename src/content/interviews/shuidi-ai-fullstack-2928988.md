### 《参考解析》

**Go 的 GMP 与 Work Stealing**：G 是 goroutine，M 是内核线程，P 是持有本地队列的调度上下文，数量等于 `GOMAXPROCS`。M 绑定 P 才能执行 G，并发度与线程数解耦，G 在用户态切换、栈很小，开销远低于线程。P 的本地队列空时先取全局队列，再随机偷另一个 P 一半的 G，CAS 保证只有一个窃取者；M 阻塞在系统调用时会把 P 交出。

**SSE 断线重连与消息续传**：SSE 是服务端到客户端的单向 HTTP 流，实现比 WebSocket 简单，而这里只需推 token。连接断开不影响任务：任务作为独立协程运行，产出按会话写入 Redis Stream 并分配递增序号；重连时带 `Last-Event-ID`，服务端从该位置重放，客户端按序号去重。

**缓存穿透、击穿、雪崩**：穿透是查不存在的 key，用布隆过滤器或空值缓存挡在库前；它用多个哈希映射比特数组，判「不存在」一定准、判「存在」有误判。击穿是热点 key 失效瞬间流量回源，用互斥锁只放一个请求回源，或逻辑过期先返回旧值、后台刷新。雪崩是大批 key 同时过期，过期时间加随机抖动并限流降级。

**Kafka 重复消费与幂等**：默认语义是至少一次，重复来自三处：生产者没收到 ACK 而重试、消费者处理完但 Offset 提交失败或提交前宕机、Rebalance 后分区重放。解法是消费端幂等：用业务唯一 ID 建去重表加唯一索引，让数据库约束挡掉并发重复。生产者开 `enable.idempotence=true` 配 `acks=all` 消除重试重复。

**Function Calling、MCP 与 Agent Loop**：Function Calling 是模型侧能力，给模型工具名、描述和参数 Schema，模型输出结构化调用意图，宿主执行后回填结果。MCP 是协议层，规定工具与资源如何被发现和调用：Host 发起，Client 维护与 Server 的会话，Server 暴露能力；MCP 工具最终也通过一次工具调用被选中。Agent Loop 是「推理、调工具、回填观察、再推理」的循环，直到给出答案或触达步数上限；ReAct 边想边做，Plan-and-Execute 先规划再执行。
