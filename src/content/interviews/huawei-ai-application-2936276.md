### 《参考解析》

**Swap 的实现。** Linux 把长时间不访问的匿名页换出到 swap 分区/swap 文件（或者压缩后放进 zram），同时把页表项改成「不在内存」的标记。进程再次访问时触发缺页异常，内核从 swap 读回页面并重新建立映射。回收动作由 kswapd 在内存低于低水位时后台触发，实在不够就同步直接回收。挑哪些页换出靠 LRU 双链表（active/inactive，配第二次机会），换出前要用反向映射 rmap 找到所有映射该页的页表项逐个改。`vm.swappiness` 决定匿名页和文件页的回收倾向，配成 0 也不是禁用 swap，只是尽量不换匿名页。工程上的坑：swap 在机械盘上会导致整机抖动到不可用；透明大页（2MB）换出要拆成 4K 页，写放大明显；容器里通常直接关 swap，用 cgroup 的 `memory.swap.max` 兜住，宁可 OOM 也不要不可预测的延迟。回答时把「换出 → 缺页 → 换入」的完整路径讲清，再补一句回收触发时机，比背概念有说服力。

**硬中断与软中断。** 硬中断由外设（网卡、时钟、磁盘）拉起，打断当前执行流，跑在中断上下文里：不能睡眠、不能拿可能睡眠的锁、要尽可能短。所以内核把它拆成上半部和下半部——上半部只做应答硬件、把关键数据搬到内存这类不能延后的事。软中断（softirq）就是下半部的一种，在中断返回路径或 `ksoftirqd` 线程里延迟执行，目前有网络收发、定时器、RCU、块设备等十来个类型；同一个软中断类型可以在多个 CPU 上并行，所以处理函数必须自己保证重入安全，而且仍然不能睡眠。需要睡眠的活（可能阻塞的 IO、要拿 mutex）只能丢给 workqueue，它跑在内核线程里、有进程上下文。一个具体例子是 NAPI 收包：硬中断只负责关中断并把设备挂到轮询队列，真正的收包由 `NET_RX` 软中断批量处理，这样高包量下不会每包一次中断。线上判断瓶颈可以看 `/proc/softirqs` 的增速和 `top` 里 `si` 的占比。

**矩阵最大路径积。** 和「最小路径和」的区别在于负号会翻转大小，所以每个格子必须同时维护最大值和最小值。转移时把三个来源（上方、左方，以及题面允许的其他方向）的 `max*val` 与 `min*val` 一起参与比较：

```python
mx = [[None] * n for _ in range(m)]
mn = [[None] * n for _ in range(m)]
for i in range(m):
    for j in range(n):
        v = grid[i][j]
        if i == 0 and j == 0:
            mx[i][j] = mn[i][j] = v
            continue
        prev = []
        if i > 0:
            prev += [mx[i - 1][j], mn[i - 1][j]]
        if j > 0:
            prev += [mx[i][j - 1], mn[i][j - 1]]
        cands = [p * v for p in prev]
        mx[i][j], mn[i][j] = max(cands), min(cands)
print(mx[m - 1][n - 1])
```

两个容易翻车的点：一是初始值不能填 0——元素含 0 时 0 会把状态「洗白」，应该用哨兵（Python 用 `None`、C++ 用 `LLONG_MIN`）表示不可达；二是乘积要开 `long long`，几个 1e9 连乘就溢出了，若数值更大就得改成比较对数或大数。如果题面给的是可上下左右四个方向移动，那就有环，不再是 DP，需要先确认方向约束再动手——这一步问清楚比写错再改便宜得多。

**论文追问怎么接。** 面试官通常只追三层：你的问题定义是什么、为什么这个方法有效、实验是否能支撑结论。准备时把 baseline、数据规模、指标提升的归因各写一句话，并预判两个挑战（对比是否公平、消融是否充分、方法落地代价多大）。被问到记不清的细节，直接说「这部分我没做，是合作者负责的」，比现编更安全。
