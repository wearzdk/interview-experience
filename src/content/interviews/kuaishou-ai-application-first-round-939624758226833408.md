### 《参考解析》

**Agent 记忆要分短长期，上下文膨胀靠分层治理**：工作记忆（当前会话）放最近若干轮原文加工具调用摘要，情景记忆存历史任务与结论，语义记忆存用户稳定偏好（语言、地点、习惯），三者存取路径不同。治理膨胀的手段包括：按优先级裁剪（系统提示与工具契约不裁，早期历史先压缩）、滚动摘要（每 N 轮把旧对话压成结构化要点）、工具结果外置（大返回落对象存储只留引用与摘要）、检索式回忆（需要时按向量检索取回而不是全塞进 prompt）。偏好类数据用结构化 KV 或带 TTL 的表存，不要指望模型「记住」，否则既费 Token 又容易串味。

**工具调用缓存与成功率优化是两件配套的事**：可缓存的前提是「无副作用 + 参数足以决定结果 + 结果时效可接受」——查询类适合缓存，写操作绝不能缓存；缓存键用工具名加规范化参数哈希，TTL 按数据变化频率定（汇率分钟级、订单状态秒级、知识库条目按版本号失效），并给缓存加灰度和命中率指标。调用失败常见原因分四类：参数不合 schema（模型编造字段）、鉴权与限流、下游超时或 5xx、同名工具选错。对应手段是：用 JSON Schema 严格校验并把错误信息回灌给模型自我修正、给工具写清一句话描述与正反例、收敛工具数量、加超时与重试（只重试幂等操作）、连续失败降级到确定性兜底。衡量就看调用成功率、平均步数与无效调用占比。

**RAG 全流程要说成一条可调优的流水线**：解析清洗 → 切分（按结构语义切，重叠窗口兜住跨段语义）→ 向量化（选与检索语言匹配的 embedding，注意对称／非对称）→ 索引存储（向量库加元数据过滤）→ 查询处理（Query Rewrite、多查询扩展、意图路由）→ 检索（向量召回 + 关键词 BM25 混合，RRF 或加权融合）→ 重排（cross-encoder 精排）→ 生成（带引用、约束只能依据片段作答）→ 评估与回流（召回率、忠实度、答案相关性）。抑制幻觉的抓手是：召回质量（宁缺毋滥、加相似度阈值）、强制引用与拒答（检索为空或分数过低就说不知道）、生成后一致性校验、把坏例沉淀成评测集。至于为什么没上 Knowledge Graph，可以老实答：收益集中在多跳关系推理，而当前业务问题多属单跳事实检索，图谱的构建维护成本远高于增量收益——讲清取舍比硬上更好。

**AI Coding 工作流要有明确的人机分工**：拿到需求先自己写清边界与验收标准（Spec 先行），再让 AI 起草方案与骨架，人审查接口与数据流；实现阶段小步提交，每步都保持可运行；验证靠类型检查、lint、单测与端到端跑通，AI 可以生成测试骨架但断言由人把关。连续三次修不好同一个 Bug 就该停下——说明前置假设错了，正确动作是回到最小复现、缩小范围、必要时换实现路径或求人 review，而不是继续换 Prompt 硬试。判断「能跑但逻辑烂」的信号包括：吞异常、重复实现、隐藏的并发假设、硬编码、边界缺失、无意义抽象，发现手段是 review 清单加静态扫描加针对性单测。被问到 AI 工具瓶颈或校招生能力时，答题要落到可验证的证据：AI Coding 的短板在于缺乏项目级长期记忆与真实运行反馈，人的价值前移到定义问题、设定约束、验收结果。

**系统设计题按「输入—决策—执行—输出—兜底」五段答**：智能文档审阅 Agent 的输入是文档（先解析结构分块），决策层做风险识别（分类模型或规则库打标）与修改建议生成，执行层调用检索（法规、模板库）、比对工具、批注写入接口，输出要带定位（第几段第几行）、置信度与依据引用，兜底是低置信度转人工、批量任务限流与审计日志。行程规划 Agent 则要设计工具集（天气、地图、票务、支付）、约束求解（预算、时间窗、偏好）、异常处理（天气变化触发重规划）、多轮澄清（缺预算或日期主动问）与用户确认点（下单类动作必须确认）。两者共同的采分点是：工具契约清晰、幂等与超时、失败可恢复，以及人在关键节点有否决权。

**手撕反转链表的追问考的是边界与规模**：基础版本用三指针迭代或递归，注意头结点、单节点与递归栈深度。链表有环要先判环——快慢指针找到相遇点后直接反转会死循环，正确做法是定位入环点、断环再反转，或者先判环直接返回错误。每 k 个一组反转要在反转前数够 k 个，不足 k 个保持原序，注意组间前后指针的接续。长度 10 亿、内存放不下时，思路要换成外部存储或流式处理：把链表分片落盘（或放分布式存储），片内先反转，再通过指针文件拼接，或者用「多次遍历 + 固定大小缓冲」把驻留内存压在常数级。这类追问的采分点不是写出代码，而是你能说出「内存放不下时算法变成 IO 密集型，瓶颈在磁盘与网络而不是指针操作」。
