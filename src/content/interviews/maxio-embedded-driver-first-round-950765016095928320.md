### 《面试题目》

1. 简历的项目展开讲讲：团队分工？你的角色？主要业务？
2. 上位机与下位机的交互是谁主导的？
3. Linux 系统的调度是谁负责？
4. 以当时参与的角度来说，觉得哪些地方是欠缺的？
5. 项目的开发语言是 C 还是 C++，平常用什么语言多？
6. 实习项目详细讲解。
7. 如何去评估仿真的实现有没有问题？指标谁来定？
8. 项目中总共有几个线程？
9. 怎么保证两个线程之间的数据交互？
10. FPGA 中出现问题，怎么去 debug？
11. 对现在应聘的这个岗位了解吗？
12. 个人的职业规划？
13. 对加班的看法？

### 《参考解析》

**「你的角色」这题要能划清贡献边界。** 面试官问团队分工，是在确认简历上的东西有多少是你做的。答法是把项目拆成模块，说明自己负责哪几块、与谁对接、交付物是什么（驱动、协议、测试脚本、文档），再补一句别人做的那部分你了解到什么程度。含糊其辞会被连续追问细节，直到露馅。

**上下位机交互谁主导，取决于协议定义权。** 通常由下位机（设备侧）主导时序与帧格式：它决定何时上报、如何应答、超时怎么处理；上位机按协议发命令并处理重传。但「主导」还有另一层意思——需求与接口规范往往由系统侧或客户定义，软件只是实现。回答时说清三件事：协议由谁定、主从关系是谁发起谁应答、异常时谁负责重试与恢复。

**Linux 的调度由内核的调度器负责，用户态只能影响不能接管。** 内核里有多个调度类，按优先级从高到低是 stop、deadline、realtime（SCHED_FIFO / SCHED_RR）、fair（CFS/EEVDF，普通进程）、idle。CFS 用虚拟运行时间 `vruntime` 选下一个任务，保证公平；实时类按固定优先级抢占。用户态能做的三件事：设调度策略与优先级（`sched_setscheduler`、`nice`、`chrt`）、绑核（`sched_setaffinity`）、以及用 `mlockall` 避免缺页。嵌入式里常追问「实时性怎么保证」，答案通常是实时调度策略 + 关抢占区间控制 + 中断线程化（PREEMPT_RT）。

**「哪些地方欠缺」是反思题，要给具体的技术债。** 有效的答法是承认一处真实的不足并说明后来怎么补：比如当时没有做压力测试、错误处理只覆盖了正常路径、协议没有版本号导致升级兼容困难、日志不足以定位线上问题。空泛地说「经验不足」没有信息量。

**C 与 C++ 的选择要落到场景。** 驱动与内核态只能用 C（内核不支持 C++ 运行时）；应用层用 C++ 可以拿到 RAII、容器与模板的好处，代价是二进制体积、异常与 RTTI 的开销、以及和 C 接口的边界处理。回答时说明自己项目里哪部分用哪种、为什么。

**仿真结果的评估，先定「和谁比」。** 通常要有一个 golden model（参考模型、MATLAB 定点模型、或实测数据），逐点比较误差并给出容差；指标包括功能覆盖率、误差的均值与最大值、边界与异常输入的通过率、以及资源与时序是否满足约束。指标由谁定要分清：功能正确性的判据一般由系统或算法团队给，性能指标由产品需求给，验证覆盖率由验证计划定。回答里要体现「我先和算法同学对齐了判据，再写脚本自动比对」这样的协作细节。

**线程数量与数据交互。** 线程数按职责划分（采集、处理、通信、日志），说明每个线程的周期与优先级。两个线程交换数据的方式按场景选：共享缓冲区加互斥量（简单、通用，注意锁粒度与优先级反转）、条件变量加队列（生产者-消费者，能阻塞等待）、环形缓冲加读写指针（单生产者单消费者可以做到无锁，靠原子操作与内存屏障）、双缓冲（读写分离，适合周期性整块替换）。要补的关键点是：无锁方案必须说清内存序与 ABA 问题，有锁方案必须说清临界区里不能做阻塞调用。

**FPGA 调试的常规路径。** 先分是逻辑问题还是时序问题：逻辑问题用 ILA / SignalTap 抓内部信号，看状态机卡在哪个状态、握手信号是否配对；时序问题看静态时序分析报告（建立/保持裕量、跨时钟域路径），跨时钟域要用同步器（两级触发器、异步 FIFO、握手），不能直接打拍。常见坑是复位不同步、时钟使能漏接、以及仿真通过但上板失败（因为仿真没有延迟与亚稳态模型）。

**岗位认知与职业规划。** 嵌入式驱动开发岗的日常是板级 bring-up、外设驱动、性能与稳定性调优、以及与硬件和固件联调；回答时把「我做过什么、和这个岗位的重合点在哪」讲清楚。职业规划给三年内的具体目标（独立负责一个模块、掌握一类总线或存储栈），比「成为技术专家」有说服力。

**加班那题如实说。** 说明自己能接受的强度、项目关键期可以投入、以及长期靠流程和工具减少无效加班，比单纯表态「完全接受」更可信。
