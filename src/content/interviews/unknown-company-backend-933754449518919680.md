### 《面试题目》

1. 考察维度：项目经历、Java 基础、数据库能力、沟通表达能力、AI 编程工具使用、自驱力。
2. 项目里说做过 SQL 优化，是基于什么做的？分表怎么分，实际场景下怎么分表？
3. 实际项目中会遇到的问题：Redis 大 key、热点 key、SQL 优化分别怎么处理？
4. 平时用 AI 编程工具吗？实际怎么用 CC 建 skill 提效？
5. 围绕项目发散提问，让候选人讲自己的看法。

### 《参考解析》

1. **面试官怎么形成判断**：让人挂很容易，让人过要综合评估——挂掉只需要换下一份简历，放水让不合适的人过了，到二面领导那里会露馅。所以第一轮面试官的目标不是找最强的人，而是确认这个人能不能胜任、我敢不敢推荐给下一轮；准备充分度和表达清晰度在其中的权重比很多人想的高。
2. **八股答得浅是否致命**：帖中通过的候选人 Java 基础只能很浅地回答，但项目表述熟悉、发散追问能接住、数据库有准备，依然通过。八股的作用是筛掉完全没准备的人，不是评分主体；反过来说，它是唯一能低成本准备的环节，完全不准备等于主动递给面试官一个否决理由。
3. **数据库为什么被重点问**：因为它能从"项目里说过的一句话"立刻往下钻——你说做过 SQL 优化，面试官接着问分表以及真实场景怎么分，答不出来就说明优化是别人做的或只是照着做。大 key、热点 key 同理，属于只有真在线上踩过才知道痛点的知识，背概念很容易被一句追问戳穿。
4. **AI 编程工具怎么答**：面试官问这个不在工具名录，而在你怎么把它变成效率——用 CC 建 skill、沉淀团队规则、明确哪些代码必须人 review。回答"没用到"或者"只用过某工具、也不关注行业动态"，在这个时间点会被读成自驱力不足，而这恰好是他考察维度里的一项。
