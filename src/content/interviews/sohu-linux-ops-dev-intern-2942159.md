### 《参考解析》

**POSIX 线程怎么管理**：核心是「生命周期 + 同步 + 资源」三件事。创建用 `pthread_create`，回收用 `pthread_join`（可拿返回值）或 `pthread_detach`（分离，退出自动回收，适合常驻工作线程）；线程数要按 CPU 核数与任务类型定，IO 密集可以多于核数，CPU 密集接近核数；共享数据用 `pthread_mutex` 保护、条件变量 `pthread_cond` 做通知、读写锁 `pthread_rwlock` 提升读多写少场景；线程局部存储用 `pthread_key` 或 `__thread`；退出要统一：设停止标志 + 唤醒条件变量，避免 `pthread_cancel` 的异步取消带来的资源泄漏。工程上还会配线程池、无锁队列、以及 `pthread_setname_np` 便于排查。

**在线升级脚本的逻辑怎么讲**：按「检查—下载—校验—切换—回滚」讲：检查当前版本与磁盘空间、下载新包（断点续传、超时重试）、校验（sha256 或签名，防篡改与半包）、解压到版本目录（`releases/v1.2.3`）、切换软链（`current -> releases/v1.2.3`，原子操作）、重启或热加载服务、健康检查（端口、接口探活），失败则切回上一个软链并重启。要点是幂等（重复执行不产生副作用）、可回滚（保留上一版）、可观测（日志与退出码）、以及不在业务高峰执行。如果脚本还管多台机器，要说明并发控制与分批灰度。

**Agent、Skills 与 MCP**：MCP 是模型与外部工具/数据源之间的标准化协议（工具发现、调用、资源与提示模板），解决「怎么接」；Skills 是把一类任务的做法固化成可加载的单元（提示词 + 脚本 + 资源 + 触发条件），解决「怎么做」。运维场景里的结合点是：把「查日志、看监控、重启服务、扩容」包装成 MCP 工具，把「排障流程」写成 Skill，让 Agent 按步骤调用并留痕。要强调安全边界：工具要最小权限、危险操作要二次确认或走审批、所有调用要审计，不能让模型直接拿到生产 root。

**Linux 与 shell 的常见考点**：进程与信号（`kill -15` 与 `-9` 的区别、僵尸进程与孤儿进程）、文件描述符与 `ulimit`、`/proc` 下的关键文件、内存与负载（`free`、`vmstat`、`iostat`、`top` 的 `load average` 含义）、网络排查（`ss`、`tcpdump`、`curl -v`、DNS 解析顺序）、权限（`rwx`、`umask`、SUID）、systemd 的 unit 与日志（`journalctl`）。shell 脚本考的是「会不会写健壮的脚本」：`set -euo pipefail`、引号包裹变量、`trap` 清理临时文件、判断命令是否存在、处理空格与通配符、用 `getopts` 解析参数、日志与退出码规范。

**408 八股怎么准备**：数据结构（复杂度、树与图的遍历、排序稳定性）、操作系统（进程调度、内存管理、文件系统、死锁）、计算机网络（TCP 三次握手四次挥手、拥塞控制、HTTP 与 DNS）、组成原理（Cache、流水线、存储层次）。运维岗更看重操作系统与网络，回答时尽量往「线上排查」上靠：比如 TCP 的 `TIME_WAIT` 过多怎么处理、`CLOSE_WAIT` 多说明什么。

**职业规划与反问**：规划要贴合岗位——短期把 Linux 与自动化做扎实，中期能独立负责一套监控/发布/容灾体系，长期往 SRE 或平台工程走。反问「您对我的评价」是加分动作，能拿到即时反馈；再问「入职后主要负责哪块、团队怎么分工」，既判断岗位真实内容，也表达你已经在想怎么上手。帖主 All In 之后当场接 offer，这类「面试官明确说会带你」的团队，反问工作内容时可以顺势表达自己的偏好。
