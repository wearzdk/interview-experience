### 《参考解析》

**合并 K 个升序链表**：用最小堆存每个链表的头节点，每次弹出最小节点接到结果尾部，再把该节点的 next 入堆；堆大小 K，总时间 O(N log K)，空间 O(K)。也可以用分治两两合并，O(N log K)。ACM 模式注意自己定义节点、读输入。

**戳气球**：区间 DP。在数组两端补 1，`dp[i][j]` 表示开区间 (i,j) 内全部戳破的最大得分，枚举最后戳破的 k：`dp[i][j] = max(dp[i][k] + dp[k][j] + nums[i]*nums[k]*nums[j])`，按区间长度从小到大算，答案 `dp[0][n+1]`。时间 O(n³)。

**Workflow vs Harness + Skill**：Workflow 是确定性编排，路径固定、可预测、成本低，适合步骤明确的业务；Harness + Skill 把「执行框架」和「任务知识」分开，模型在边界内动态选工具、调整顺序，适合分支多、需要判断的任务，代价是成本、延迟和不确定性。回答时给判断标准：流程能否穷举、失败是否可接受、是否需要模型做决策。

**推荐冷启动与信息茧房**：冷启动用热门 + 内容属性 + 少量探索（bandit），先给多样性再收敛；有画像后做召回（向量/协同/规则）→ 排序（CTR 预估）→ 重排（多样性、去重、业务规则）；反馈回流做实时特征和负样本；信息茧房用探索比例、内容多样性约束、跨域推荐缓解。

**Go Context**：用于跨 API 边界传递取消信号、超时和请求级元数据。超时通过 `WithTimeout` 生成带 deadline 的子 context，子 goroutine 通过 `Done()` 感知；父 context 取消会级联到子。不建议存进结构体，是因为它应该随一次请求显式传递、生命周期短，存进长生命周期对象会导致取消信号错乱和泄漏；标准做法是作为函数第一个参数。

**离线评测集**：按「能力维度 × 场景 × 难度」分层抽样，覆盖正常、边界、对抗、长尾；每条有输入、期望要点、评分规则；与知识库做去重和泄漏检查（评测题不能直接出现在检索库里）；用人工标注校准 LLM judge；每次改动跑同一套并记录版本。可参考 RAGAS、BEIR、MT-Bench、AgentBench 等公开基准的设计思路。

**性能瓶颈**：模型调用（并发、限流、token 成本）、向量检索（索引规模、延迟）、会话状态存储（读写放大）、工具调用（外部依赖 RT）、编排层的串行等待。优化方向是缓存、批处理、异步化、分级模型、连接池与超时控制。
