### 《面试题目》

1. 自我介绍。
2. 你是保研的吗？硕士排名这个总人数是多少？英语水平怎么样？介绍一下你的主攻方向。
3. 你的个人项目有开源到 GitHub 上吗？可以手机打开你的 GitHub 主页给我看看吗？这些都是什么软件？
4. 你们这些项目都有用 AI coding 吗？报销吗？主要用哪些模型？
5. 你觉得这些项目里最感兴趣的是哪个？
6. 这个项目你有持续去维护吗？你觉得还有哪些可以优化的地方？
7. 这个平台有什么 baseline benchmark 吗？怎么去定位和优化？
8. 你觉得你这个功能能直接让 Codex 实现出来吗？这个项目最终最好的呈现，你觉得应该是怎样的？

### 《参考解析》

**当场打开 GitHub 主页**：这比简历硬。面试官看三件事：有没有真能跑起来的东西（README 写清启动方式、依赖、截图或 demo 地址）、提交是否持续（commit 时间线、issue 与 PR）、代码是不是自己写的（提交粒度、注释风格）。项目不用多，一两个讲得透的胜过十个 fork；把 README 当作品集写，比堆技术名词有效。提前把主页整理干净，仓库置顶、删掉跟岗位无关的练手代码。

**AI coding 怎么答**：面试官想确认你是真的在用，以及有没有成本意识。说清日常用什么模型、哪些场景用（样板代码、测试、重构、查文档）、哪些场景不用（核心逻辑、安全相关），团队有没有统一报销和规范。用 AI 生成的代码同样要自己 review、跑测试，能讲清哪部分是自己的判断，比强调效率更加分。

**baseline 与定位优化**：被问「有什么 benchmark、怎么定位」时，正确顺序是先建可重复的基线：固定数据集、固定环境、记录 P50 与 P95 和吞吐，再每次只改一个变量做对比。定位靠 profiling 而不是猜：火焰图看热点，慢日志看单次请求，压测看瓶颈在 CPU、IO 还是锁。答不出基线数据，等于承认优化是凭感觉做的。

**让 Codex 直接实现怎么接**：这题在考对任务边界的判断。模型擅长有明确输入输出的局部功能，不擅长需要业务上下文、跨系统集成和隐性约束的部分。可以答：核心算法和接口骨架能让模型生成，但数据结构设计、异常路径、权限与一致性要人来定，同时说明自己会怎么验证生成结果——写测试、构造边界输入、对比旧实现。

**双选会的节奏**：展位式面试人多，每人十几分钟，自我介绍压到一分钟以内，把最强的项目放最前面。反问可以问团队规模、技术栈，以及新人上手的第一件事，这类问题面试官答得快也更真实。
