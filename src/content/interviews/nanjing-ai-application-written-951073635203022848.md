### 《面试题目》

1. 笔试一共考哪些部分？题型是怎么分布的？
2. 第一部分的选择题：在具体场景下怎么选择应用 AI，考的是什么？
3. 编程题一：对 list 里的数据做处理，要求是什么？
4. 编程题二：给一段 Python 数据处理代码，要求修改并自己重写一份。
5. 业务题一：以智能客服为例，客户得到的回答出错了，整条链路哪里可能出错？怎么分析？
6. 业务题二：重新设计这个智能客服的链路，哪些要优先设计，哪些要注意边界？
7. 平时只练算法题、不写 Python 数据处理，考场上怎么办？

### 《参考解析》

**这类笔试考的是「工程判断」而不是背诵**：选择题给的是业务场景（这个需求该用规则、检索还是大模型；这个环节要不要加人工审核；这个指标掉了先查哪一层），选项之间往往没有绝对对错，考的是能不能说清代价。做题方法是对每个选项问三句：它解决了什么问题、引入什么新风险、成本落在谁身上。编程题考的是把业务数据揉成目标结构的能力——分组、去重、排序、聚合、字段清洗，这在日常写脚本时天天用，但在力扣里练不到。

**Python 数据处理该练到什么程度**：列表与字典的基本操作要熟到不用想——推导式（含条件过滤与嵌套展开）、`sorted(key=...)` 与多级排序、`dict.get` / `setdefault` / `collections.defaultdict` 与 `Counter`、`groupby` 前先排序、`zip` 与 `enumerate`、`json.loads` 后按路径取字段、异常数据的 `try/except` 与 `None` 判断。数据量上来之后换成 pandas：`read_csv` / `read_json`、`groupby().agg()`、`merge`、`fillna`、`astype`、`apply` 与向量化操作的取舍。考场上最实用的习惯是先把输入读成统一结构（一行一条记录、字段名固定），再写一个纯函数做转换，最后统一输出——这样即使读入格式看错，也能快速改一处。

**智能客服答错了，链路要分层排查**：从用户输入到最终回复，至少六层——接入与限流（超时、重试、并发被打满导致返回兜底话术）、语音识别或文本预处理（同音错字、口语省略、多语言混杂）、意图识别与路由（该走售后却路由到售前，置信度低于阈值没有转人工）、知识检索（知识库没有这条、切分粒度不对、召回了过期文档、向量检索与关键词检索各自的短板）、生成（上下文超长被截断、把检索内容当成指令、编造不存在的政策、引用错订单）、后处理与合规（敏感词过滤误杀、格式化失败、链接失效）。定位方法是拿具体 case 逐层看中间结果：ASR 转写对不对、意图标签与置信度、召回的前 K 条是什么、prompt 里塞了什么、模型原始输出是什么，一层层缩小范围，而不是笼统地说「模型不行」。

**重设链路的优先级与边界**：优先级按「错一次的代价」排——先做意图路由的置信度阈值与兜底（宁可转人工，也别让模型硬答），再做知识库的入库审核与过期机制（错误知识的杀伤面最大），然后是生成侧的约束（只允许基于检索内容作答、必须给出来源、不确定就说不确定），最后才是体验优化（多轮记忆、语气、多渠道适配）。边界要写清楚：能查什么不能查什么（越权查询别人的订单）、哪些操作必须二次确认（退款、改地址）、什么情况下必须转人工、超时与降级策略、隐私数据的脱敏与留存、以及成本上限（单次会话的 token 与工具调用次数）。工程上还要配套可观测性（每层的日志与指标）、离线评测集（一批标注过的历史会话）与灰度发布，否则改一版 prompt 都不知道是变好还是变差。

**没准备过怎么办**：帖主的复盘是对的——把「力扣刷得熟」当成「笔试没问题」是常见误判。缺口要按岗位补：投 AI 应用岗就把数据处理脚本、SQL、Prompt 与检索链路的基本概念补齐；投后端就补并发、数据库与系统设计。考场上遇到完全没准备的题型，先写能拿分的部分（编程题先保证读入输出与暴力解跑通），业务题按「分层—每层可能的问题—怎么验证」的框架写，哪怕细节不全，结构分也能拿到。
