### 《参考解析》

**这份索引怎么用**

作者把 70 多场面试按「客户端 / 服务端」拆成两栏，每栏再按公司分篇，最值得用的地方不是题目本身，而是**投递前的范围校准**：投一家之前先看同一栏里同类公司问了什么，就知道这家大概率会落在哪个知识块，而不是把整本八股从头背一遍。

**两条线的公共底座其实是一样的**

不管投客户端还是服务端，作者列出的第二行都是「C++ 基础、操作系统、计算机网络」。这三块是共用的地基，差别只在往上盖的那一层：客户端往 Android / Java / Kotlin 与 UI 场景题上走，服务端往 MySQL、Redis、并发与项目架构上走。所以复习顺序应该是先把 OS 与网络打通，再按目标岗位补上层，而不是一开始就分成两套笔记——同一批知识在两条线里都会被问，分成两套等于把地基背两遍。

**按公司分篇比按题背更有效**

同一个公司同一批面试官的题是高度重合的：一轮问过的知识点，二轮、三轮大概率换个角度再问一次。作者把「轮次多的公司分成不同篇单独更新」，实际等于给了一家公司内部的题目演进路径——先看一面问了什么，再看二面在同一个点上追到了哪一层，这比刷零散的高频题更接近真实面试的深度曲线。

**场景题是两条线共同的分水岭**

作者把「算法题、场景题」并列写在两个方向里，说明场景题不是某一侧的专属。客户端偏交互与状态，服务端偏并发与一致性，但共同点都是「给一个具体约束，问你怎么设计」。准备方式也一样：拿自己项目里一个真实做过的模块，把「如果流量翻十倍 / 如果中途失败 / 如果要回滚」三个追问先自己答一遍，面试里被追到第三层才不至于断。

后面作者还会继续补充高频问题与面试经验，这份索引本身也会变长，按公司名进来找比按时间翻更省事。
