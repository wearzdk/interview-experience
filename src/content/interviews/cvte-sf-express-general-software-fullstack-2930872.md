### 《参考解析》

**双令牌是 access token + refresh token 的分工**。access token 有效期短（分钟级）、随请求携带、泄露窗口小；refresh token 有效期长、只用来换新的 access token，通常存在 HttpOnly Cookie 或服务端，并支持吊销。这样既不用每次请求都查库校验会话，又能在 access token 过期后无感续期。

**防重放要靠「一次性 + 时效」**。常见做法是请求带时间戳和 nonce，服务端在时间窗内校验 nonce 未使用过（Redis SETNX 加过期），超过窗口直接拒绝；更强的做法是对关键请求做签名（方法 + 路径 + body + 时间戳），签名密钥不出服务端。只靠 HTTPS 不够，因为抓到的合法请求仍然可以重发。

**用户文件与物理文件双视图**是指「用户看到的是目录树，底层存的是对象/块」**。用户视图维护逻辑路径、权限、共享关系；物理视图负责实际存储位置、分片、去重和副本。两层之间用元数据表映射，改名和移动只改逻辑层，删除走标记删除 + 异步回收，避免大目录操作把请求卡住。

**删除文件夹会不会阻塞，取决于实现**。同步递归删除大目录会占住请求线程和磁盘 IO，表现出来就是接口超时；工程上一般做成异步任务：先标记删除、写任务表，由后台线程分批删，前端立即返回。同时要考虑权限校验、软删除保留期和失败重试。

**延时队列的典型场景**：订单超时未支付自动取消、定时发布、退款到账延迟通知、优惠券到期提醒、消息重试退避。实现上小规模用 Redis ZSet（score 存到期时间）轮询，大规模用 RocketMQ 延时消息或时间轮，关键是保证「到点只消费一次」和失败可补偿。
