### 《参考解析》

**Agent 项目与范式**：讲项目先定边界：用户是谁、输入输出是什么、哪些步骤由模型决策、哪些由代码保证、失败怎么恢复。ReAct 是「推理—行动—观察」循环，适合边查边改、工具反馈能指导下一步的任务；Plan-Execute-Replan 先出计划再执行，适合步骤多、依赖清晰、需要人工审核计划的任务，缺点是计划可能过时。企业可用标准不是「能跑」，而是权限可控、结果可评估、失败可恢复、成本可预算、行为可审计。

**RAG 与 Skill**：RAG 适合知识量大、更新频繁、需要引用的场景；Skill 适合流程固定、需要模型按步骤执行的方法论。两者可以组合：Skill 规定「怎么查、怎么验」，RAG 提供「查什么」。切块要按文档结构、语义完整性和检索粒度定，不能只按固定字数；一个 chunk 混入大量无关内容时，可以做父子块、句窗检索、重排或让模型先抽取再索引。多路召回后用 RRF、加权分数或 cross-encoder 重排融合，最终用标注集看 recall@k、MRR、答案正确率和引用准确率。

**记忆与压缩**：记忆可以分三层：工作记忆保留当前任务的状态和最近对话；情景记忆存历史交互和工具结果，按时间/重要性检索；语义记忆存稳定事实、用户偏好和领域知识。压缩前先保留系统约束、用户显式要求、未完成任务、关键实体和工具返回值；压缩后要能回查原文。不能丢的信息用结构化状态机或外部存储兜底，而不是指望摘要模型。Claude Code 的压缩本质也是保留近期消息、工具结果摘要和关键文件上下文，细节可以按「保留什么、丢弃什么、怎么恢复」讲。

**Computer Use 与 AI Coding**：云电脑链路是模型看截图/DOM/可访问性树，输出坐标或结构化动作，执行层在云主机上点击/输入，再把新状态回传，循环直到完成；要处理分辨率、延迟、弹窗、权限和失败重试。AI Coding 工作流可以按「需求澄清—方案—拆任务—生成—测试—review—提交」讲，重点是人在哪些节点把关。SDD 的价值是把需求和验收标准变成可执行契约。AI 最难的是跨文件上下文、隐式约束和验证闭环，改进方向是缩小任务、补测试、让模型先解释再改。
