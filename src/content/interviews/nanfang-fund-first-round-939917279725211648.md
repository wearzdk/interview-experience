### 《参考解析》

**生产治理类项目：把「发现 → 定位 → 处理 → 度量」讲完整**

面试官从「做了哪些生产治理」一直追问到「MAT 定位到什么原因」，是在核实你有没有真的动手定位过线上问题。答题时按一条完整的线走最好：先是发现（怎么注意到问题——监控告警、用户反馈、巡检指标，指标是什么，比如内存水位、GC 频率、接口 P99）；再是定位（怎么缩小范围——按时间点与发布记录对齐、按实例与接口维度切分、拿到堆快照用 MAT 看支配树与引用链，最终定位到是什么对象被谁持有）；然后是处理（改了什么，是减少对象创建、给缓存加淘汰、还是把批处理拆小）；最后是度量（优化后水位或 GC 次数怎么变、观察了多久）。

被追问「CSV 优化减少的内存占比是不是很小」时不要辩解，直接承认它只是症状之一并给出优先级判断：真正的大头是某类常驻对象或缓存无界增长，CSV 那类改动的价值在于降低了峰值分配速率（减少 GC 压力）而不是降低常驻内存。这种「哪种改动收益大、为什么」的判断力，比声称每一项都重要更能得分。

**业务量再大怎么办：从治标到治本的分层答法**

「老板让你解决、业务量太大」这类问题要给分层方案而不是一个招式。应用层：把同步处理改成异步（消息队列削峰、批量写入、串行改并行）、限制单次请求规模（分页、游标、导流）、把重查询改成预计算与物化视图。缓存层：本地缓存 + 分布式缓存分层，热点数据预热，缓存不命中要有降级而不是直接把压力打给数据库。数据层：加合适的索引、冷热分离与归档、读写分离、分库分表。架构层：把非核心能力（报表、导出的离线任务）迁到独立集群，避免拖垮在线链路。资源层：扩容要能配合限流保护，先保核心接口可用。每个方案都要配一句代价（一致性、成本、复杂度），面试官通常就是在听你会不会算这笔账。

**本地缓存与「请求落到同一台机器」**

这题问的是缓存一致性与路由。本地缓存（例如 Caffeine）读最快，但多实例之间不共享，更新时要靠广播失效（消息队列、Redis 发布订阅）或者容忍短暂的脏读；请求不保证落在同一台机器上，所以如果缓存只存在于某个实例，其他实例就是未命中。要保证「命中同一台」有两个层面：一是路由层面做会话粘性/一致性哈希（网关按用户 ID 或 key 哈希到固定实例），二是不依赖粘性而是把共享状态放到集中式缓存（Redis）。更常见的务实做法是「本地缓存做一级 + Redis 做二级 + 变更时广播失效」，把一致性窗口控制在可接受范围内，并对本地缓存设短 TTL 与容量上限，允许它自然过期。还要讲清代价：一致性哈希在节点扩缩容时会迁移一部分 key（虚拟节点可缓解倾斜）；粘性路由会让个别实例成为热点，且实例故障时用户会明显掉线。如果面试官继续问「怎么知道本地缓存脏了」，答案就是失效广播 + 版本号 + 短 TTL 三重兜底。

**GC Root、Java 内存结构与锁机制**

GC Root 的常见来源要报全：虚拟机栈中局部变量表引用的对象（含正在执行的方法的参数与局部变量）、方法区/元空间里类的静态属性引用的对象、常量引用的对象、本地方法栈中 JNI 引用的对象、活跃线程对象、以及 JVM 内部的系统类加载器、基本类型的 Class 对象、常驻异常对象、被同步锁（`synchronized`）持有的对象。补充一句可达性分析的边界（弱引用、软引用、虚引用与 `finalize`）会显得更完整。

Java 内存结构按运行时数据区讲：线程私有的程序计数器、虚拟机栈、本地方法栈；线程共享的堆（新生代 Eden/Survivor 与老年代）、方法区（JDK 8 之后由元空间实现，位于本地内存）；另有直接内存（NIO 的 `DirectByteBuffer`，不受堆上限约束但受进程内存限制）与运行时常量池。每一块要能说清「存什么」和「可能抛什么异常」——虚拟机栈会栈溢出、堆会 OOM、元空间会 OOM、直接内存会本地内存溢出。

锁机制按「能不能自动释放、能不能中断、是否区分读写」来梳理：`synchronized` 是 JVM 内置的监视器锁，JDK 6 之后有偏向锁、轻量级锁、重量级锁的升级路径，加锁解锁由字节码保证、异常时自动释放，但不可中断、不可超时。`ReentrantLock` 基于 AQS，支持公平/非公平、可中断加锁、超时、多个条件变量；`ReentrantReadWriteLock` 区分读写、适合读多写少；`StampedLock` 用乐观读进一步提升读性能，但不支持重入且不可中断。并发实现的答题线是「先讲无锁，再讲有锁」：用 CAS/原子类与不可变对象避免共享，其次用并发容器（`ConcurrentHashMap`、`CopyOnWriteArrayList`、阻塞队列）代替自己加锁，再上显式锁，最后才是长事务与悲观锁；同时别忘了线程池、`CompletableFuture` 与 `ForkJoin` 这类把并发组织起来的手段。面试里能主动说出「优先减少共享状态」的思路，通常比背锁的分类更受欢迎。

**实习经历与岗位认知**

实习时长、是否转正、为什么离开这类问题如实说清时间线与原因即可，不用编造。被问「最大的技术困难、是自己调研还是 mentor 告诉你的」，要如实区分两部分——哪些是别人指的方向、哪些是你自己查文档与做实验得出的结论，分开讲反而显得可信，也顺带证明你能独立推进。至于「了解平台研发工程师岗位吗」，可以给一个贴合金融行业的定义：平台研发负责的是支撑业务系统的公共底座——交易与行情的中台服务、发布与配置管理、监控与容量治理、以及稳定性保障，特点是要求对性能与一致性敏感、对线上严谨，可以在反问里确认这个团队具体维护哪一层平台、以及稳定性工作的占比。
