### 《参考解析》

**评测集与指标这一组是全场技术含量最高的部分，答题要落在「统计口径」上。** Recall@5 只衡量「前 5 条里有没有正确文档」，它**不关心顺序、不关心答案质量、也不关心拒答**：如果每道题的正确答案都能被检索到，Recall@5 就是 100%，但生成阶段照样可以答错，或者把不相关内容排在第一导致模型被带偏。所以 100% 的 Recall 必须搭配别的指标才有意义——MRR/NDCG 看排序质量、精确率或 Context Precision 看噪声、答案正确率与「有依据回答率」看端到端效果、拒答准确率看幻象治理。**评测抖动**（同一版本多次运行结果不同）的处理：固定随机种子与温度（尽量降到 0）、对同一题目多次采样取稳定统计而不是单次判定、用配对对比（同一批样本上新旧版本各跑一遍）而不是跨批次比较、以及给指标加置信区间，别把 1% 的波动当成改进。**数据泄露**要防的是评测题出现在训练/微调语料中，做法是从真实流量里切分并保留留出集、对微调数据与评测集做去重。

**「离线全绿、线上出错」这类题，根因分析有一条标准路径。** 先确认现象：线上错误 SQL 的样本、频率、是否集中在某些库表或某些问法。然后按「训练/评测分布 vs 线上分布」的差异查四件事：① **评测集覆盖不到**（题型、表结构复杂度、口语化程度、多轮上下文、时间相关问法）；② **数据漂移**（线上库表加了字段/改了枚举值，评测集还是旧 schema）；③ **上下文不同**（线上带历史对话与用户术语，评测是单轮干净输入）；④ **非确定性**（离线跑一次通过不代表稳定通过，要重复跑看方差）。改进方向：把线上失败样本回流进评测集并分层（按表数量、join 深度、聚合复杂度），加**结构断言**（SQL 是否只读、是否命中允许的表、是否带 limit）而不只比结果集，引入影子执行/双跑对比来提前发现问题，以及上线前用「留出集 + 对抗集」双门禁。

**RAG 系统的自动化测试套件可以按「数据、检索、生成、性能、安全」五层设计。** 数据层：多格式解析正确性、切片边界、元信息完整性、幂等重建；检索层：召回率/排序指标回归、权限过滤（越权用例必须有）、TopK 与阈值的敏感度；生成层：答案正确性与有依据率、引用可溯源、拒答行为、对冲突证据的处理；性能层：端到端 P50/P95、并发下的瓶颈定位（要能分辨是检索还是模型调用拖慢——按阶段埋点分段计时，再做压测分别施压）；安全与鲁棒层：提示词注入、超长输入、敏感信息泄露、脏向量（用错误 embedding 或未清洗文本注入，看系统是否给出无依据答案并建立脏数据检测任务——比如定期跑「答案与证据一致性」抽样审计）。**权限漏洞**这一问要主动补：仅靠知识库 ID 过滤不够，还要防「同一知识库内部的文档级权限」（部门/密级）、向量与原文的权限一致性（改了原文权限要同步重建索引）、以及检索接口的越权访问（用户可伪造 kb_id 参数）；正确做法是在检索前用服务端可信身份拼过滤条件，而不是信任客户端传参。

**AI 应用的评测平台核心模块**可以答成六块：① 数据集管理（版本化、分层、留出集）；② 被测系统接入（统一的调用适配层，支持模型/prompt/工具集切换）；③ 评测执行（批量跑、并发控制、重试与超时、成本统计）；④ 判定层（确定性断言 + 模型裁判 + 人工抽检三档，并记录判定置信度）；⑤ 指标与报表（按题型/业务线/版本对比，带置信区间与失败样本下钻）；⑥ 回归门禁与告警（接 CI，指标退化即阻断发布，线上灰度对比）。要强调的判据：**模型裁判必须抽查校准**（人评一致性低于阈值就不能当发布门），以及**评测要版本化**，否则「上次是多少」都说不清。Python 那几问的要点：装饰器是「接收函数返回函数」的高阶函数，带参数的装饰器多一层闭包（`def deco(arg): def wrapper(f): ...`），要配 `functools.wraps` 保留元信息；`__new__` 创建实例（在 `__init__` 之前，必须返回实例），`__init__` 初始化，`super()` 按 MRO 顺序查找下一个类，在 `__init__` 里用 `super()` 能保证父类只被初始化一次；生成器是「函数里带 yield」的惰性序列（用 `send`/`throw`/`close` 与调用方双向交互），迭代器是实现 `__iter__`/`__next__` 的对象，需要惰性求值、处理大文件或无限序列时优先用生成器，因为它是边算边产出、不占内存。
