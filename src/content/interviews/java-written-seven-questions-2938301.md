### 《面试题目》

1. 编程题一道（题面未记录，帖主正常完成）。
2. 问答题六道，覆盖 Java 基础知识，按文字描述作答（题面未记录）。

### 《参考解析》

**这类测评的题型结构值得提前知道**：不少公司在笔试里混入「文字问答题」，形式接近面试口述题的书面版本——给一个概念或场景，要求用几段话说明原理、区别与适用条件。它考察的仍然是八股范围（集合、并发、JVM、数据库、框架），但评分看的是表述是否成体系，而不是关键词是否出现。

**时间分配上，编程题优先做完再回头写问答**。编程题通常占分最多且便于自查（本地跑样例、检查边界），问答题的边际收益取决于你能否在有限字数内讲清结构。帖主的教训是「很多没答就是算了」——空白题与答得不完整的题在分数上没有区别，先把每道题写出一段有层次的回答，再回头补充细节。

**文字作答按「定义—原理—对比—场景」四段组织**：先用一句话给出准确定义，再讲实现原理或关键机制，然后与相邻概念做对比（例如 synchronized 与 ReentrantLock、ArrayList 与 LinkedList、== 与 equals），最后落到什么场景下选它。这样即使细节记得不牢，结构和判断仍在。

**刚离职的求职者要预留复习窗口**：八股不是背一遍就够，距离上一次系统复习超过一个月，常见追问（底层数据结构、锁升级、GC 分代与回收器、索引失效场景）就会答得含糊。投递前用两三天把高频题过一遍，比在测评里现编更划算。
