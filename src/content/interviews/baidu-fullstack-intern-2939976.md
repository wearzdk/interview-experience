### 《面试题目》

1. 自我介绍。
2. 项目介绍：怎么做的？用 AI 写代码时，你遇到过哪些问题？怎么解决的？怎么排查问题？
3. MySQL 的索引、MySQL 一共有哪几种隔离级别，在默认的可重复读隔离级别下，还会存在幻读现象吗？
4. 对比 B+ 树，如果索引改用红黑树或跳表来实现，它们各有什么优缺点？
5. 如果要做一个排行榜，可以用 Redis 来实现吗？你会选择哪个数据结构？
6. 当数据量级很大时，Redis 会出现「大 Key」的问题，你怎么优化解决？
7. 有了 AI 之后，你觉得前后端的分界还明显吗？你自己更愿意做哪一端？

### 《参考解析》

**用 AI 写代码遇到的问题**：真实的问题有几类：生成的代码引用了不存在的 API 或旧版本接口；看起来能跑但边界没处理（空值、并发、超时）；改一处带崩另一处（不了解上下文）；测试与文档的幻觉。排查方法：先跑编译与单测，把报错原文回灌；用断点或日志确认实际执行路径；用 `git diff` 逐行审；对不确定的库直接查官方文档。回答时带一个具体例子，比列问题类型有说服力。

**隔离级别与幻读**：四种隔离级别是读未提交、读已提交、可重复读、串行化。InnoDB 默认可重复读。幻读指同一事务内两次范围查询的行数不一致。InnoDB 在可重复读下用两种手段应对：快照读（普通 `select`）靠 MVCC 读一致性视图，看不到别的事务新插入的行，因此不会幻读；当前读（`select ... for update`、`update`、`delete`）靠 next-key lock（记录锁 + 间隙锁）锁住范围，阻止插入。所以严格说「可重复读下没有幻读」在绝大多数场景成立，但在「先快照读、再当前读」的混合场景，或间隙锁未覆盖到的边界，仍可能出现语义上的幻读——面试时把「快照读 vs 当前读」讲清楚，比回答「不会」更准确。

**B+ 树 vs 红黑树 vs 跳表**：B+ 树是多叉平衡树，一个节点存多个 key，扇出大、树高低（三到四层可存千万级），叶子节点用链表相连，适合范围查询与磁盘页读取——每次 IO 读一个 16KB 页，正好装一个节点。红黑树是二叉平衡树，树高约 2log₂n，同样数据量层数多得多，磁盘 IO 次数成倍增加，范围查询要中序遍历、缓存不友好；优点是实现简单、内存索引（如 `std::map`）够用。跳表用多级链表实现近似平衡，查找/插入 O(log n)，范围查询友好、实现比平衡树简单、并发插入容易（Redis 的 zset 就用跳表），缺点是空间开销（每层指针）与内存随机访问不如数组。选型取决于存储介质（磁盘 vs 内存）与是否需要范围查询。

**Redis 排行榜**：用 `ZSET`（有序集合），`ZADD` 更新分数、`ZREVRANGE` 取 Top N、`ZREVRANK` 查排名、`ZINCRBY` 加分，底层是跳表 + 哈希表，O(log n)。同分时按成员字典序排，若要「先到先得」可以把时间戳编码进分数（分数 = 成绩 × 10^k + (MAX_TS - 时间)）。超大排行榜要分片（按榜单维度或哈希分桶）或只保留 Top N。

**大 Key 优化**：大 Key 指单个 key 的 value 过大（字符串几 MB 以上）或集合元素过多（百万级）。问题是读写阻塞单线程、网络带宽打满、删除时卡顿、集群下数据倾斜。优化手段：拆分（把大 hash 按字段哈希拆成多个小 hash、大 list 分页拆成多个 key）；只存必要字段、压缩 value；用 `HSCAN`/`SSCAN` 分批读而不是 `HGETALL`；删除用 `UNLINK`（异步释放）而不是 `DEL`；设置合理的过期与淘汰策略；业务上把「全量排行榜」改成「分页 + 缓存 Top N」。治理上先用 `redis-cli --bigkeys` 或 `MEMORY USAGE` 找出大 Key，再按业务改。

**AI 之后前后端分界**：分界在「职责」上仍然存在，在「技能栈」上变模糊了。AI 让一个人能快速写出另一端的代码，但接口契约、数据模型、性能与安全边界仍需要有人负责。全栈的价值不是「什么都会写」，而是「能端到端判断一个需求怎么落地、瓶颈在哪一端」。自己更愿意做哪端要给出理由与证据（做过的项目、擅长的部分、想深入的方向），不要说「都可以」。

**摩尔投票法变体**：基础题是「找出出现次数超过一半的元素」——候选人计数，相同 +1、不同 -1，归零换人，最后剩下的候选再验一遍。变体常见有：找出现次数超过 n/3 的元素（最多两个，用两组候选人同时投票，最后各自验证）；找出现次数超过 n/k 的（维护 k-1 个候选人）；或要求返回所有满足条件的元素。核心思想是「不同元素相互抵消，剩下的才可能是多数」，但必须补一次计数验证，因为候选人不一定真的超过阈值。
