### 《面试题目》

原帖没有记录具体题目，只记下了这场笔试的实际形态，这里照实说明，不做补充：报考方向为嵌入式，使用的是北森一类的在线测评平台，考试需要开启摄像头监控；题型是选择题加后面几个填空题；题目内容与难度接近于大学机房里 C89 语言的期末考试，作者觉得与自己准备的 C++ 方向关系不大。

### 《参考解析》

**这场笔试透露出什么信息**。三道线索值得注意：平台是第三方在线测评（北森这类），意味着题目来自通用题库而不是嵌入式团队自己出的；需要开摄像头，说明会做防作弊监控，环境准备（网络、摄像头权限、浏览器、安静环境、提前做完身份核验）本身就是流程的一部分，别把时间浪费在调试设备上；题型是选择题加填空题，没有编程题，说明它主要筛的是语言基础与常识的准确性，而不是工程能力。对照作者「和我 C++ 有什么关系」的吐槽，可以推断这套卷子更偏传统 C 语言基础，嵌入式岗位用它做初筛是常见做法——单片机与驱动开发的底层是 C，标准库与语法细节直接决定代码是否正确，所以企业倾向用 C 语言基础题做快速分层。

**C89 风格的可能考点范围与复习方向**。语言基础部分：数据类型与长度（`char`、`short`、`int`、`long`、`long long` 的取值范围与是否带符号）、整型提升与隐式类型转换、各进制的字面量写法、`sizeof` 与 `strlen` 的区别、运算符优先级与自增自减的求值顺序、位运算（置位、清位、取反、判断奇偶、交换两数、掩码提取字段）。指针与内存部分：指针与数组名的关系、指针的算术运算、二级指针、函数指针与回调、`const` 与指针结合的三种含义、`malloc/free` 与内存泄漏、野指针与悬空指针、结构体内存对齐与 `sizeof` 计算、大小端判断。字符串与标准库部分：`strcpy`、`strncpy`、`memcpy`、`memmove` 的差异与重叠内存问题、`strcat` 的越界风险、`sprintf` 与 `snprintf` 的安全用法。控制流与函数部分：`switch` 的 fallthrough、`static` 修饰局部变量（生命周期）与全局变量（链接属性）、`extern` 的作用、宏与函数的区别（文本替换与副作用，如 `#define SQ(x) x*x` 的坑、带参数的宏要加括号）、条件编译 `#ifdef`。指针与结构体在嵌入式里的实际用法：寄存器映射与 `volatile`（编译器不能优化掉对硬件寄存器的读写）、位域、联合体用于协议解析、`union` 与 `struct` 的相互转换。填空题常考输出结果（`printf` 的格式串与返回值）、数组越界后的行为、循环次数计算以及字符串处理的边界。

**答题策略**。选择题量大时间紧，先易后难，遇到需要计算的 `sizeof` 与优先级题不要纠缠；填空题看清要求是「填值」还是「填表达式」，涉及类型的地方注意是否有符号与宽度（嵌入式里 `int` 宽度、`char` 的符号性都是常见陷阱）；不确定的题用排除与代入验证，不要空着。考完后如果通过，技术面基本会接着围绕 C 基础、指针、内存与单片机外设展开，复习重点应从「考试型语法」转到「能不能解释清楚自己写的驱动代码」，把 `volatile`、中断上下文、内存对齐、DMA 与指针操作这些串起来讲，比单纯刷题更有效。另外，这家公司做的是家电方向的嵌入式，面试里常见的问题还包括 RTOS 的使用经验、常见外设（UART、I2C、SPI、ADC、PWM）与调试手段（示波器、逻辑分析仪、串口日志、JTAG 单步），可以提前按这个清单准备自己讲得出的例子。
