### 《面试题目》

**笔试：选择与简答**

1. HTML、CSS、JavaScript 三大件的基本功，以及 React / Vue 相关的选择题与简答题。
2. CSS Flex 布局如何实现容器内左侧固定宽度、右侧自适应伸缩？
3. 虚拟 DOM 的定义是什么？它带来哪些好处？

**笔试：编程题**

4. 用 JavaScript 实现数组元素去重。
5. 用 React 或 Vue 实现一个简单的双向绑定。

**无领导小组讨论**

6. 场景题：面向物料 BOM 业务，协同输出一套可行的设计方案。制造行业的产品 BOM 中，一个成品由多级子件组成，子件可继续拆分为下级零件，是无限层级的树形结构（例如发动机总成 → 缸体组件 → 螺栓、垫片）。需要支持：输入成品物料编码向下查询完整 BOM 树并逐层展开；只统计叶子节点的底层原材料数量，中间组件不计；导出 BOM 汇总清单；BOM 层级可能达到十几层，且存在循环 BOM 风险（A 包含 B、B 又包含 A）；支持分页与懒加载，一次性加载全部层级会卡顿。
7. 后端需要给出：BOM 树形数据的数据库存储方案；查询方案（递归查询 / 预计算 / 路径字段等）；循环 BOM 如何识别与拦截；底层物料汇总逻辑；接口清单、入参、返回结构；大数据量与深层级下的性能优化思路。
8. 前端需要给出：BOM 树形页面的模块与交互（展开折叠、懒加载、勾选、汇总面板）；树形组件的数据结构设计；导出功能的交互、加载状态与报错提示；循环 BOM 告警、查询超时、物料不存在等异常场景的展示。
9. 必须产出七项内容：BOM 数据库表结构设计、查询与底层物料汇总的业务流程、循环 BOM 识别与拦截策略、深层级性能风险与优化方案、后端接口清单及返回示例、前端页面模块与交互逻辑、当前方案的风险点与未知问题的解决方式。
10. 前后端必须对齐：树形返回的 JSON 结构、错误码、异常提示文案。
11. 反问环节。

### 《参考解析》

**Flex 实现左右固定与自适应**：左侧写 `flex: 0 0 200px`（或固定 `width` 加 `flex-shrink: 0`），右侧写 `flex: 1 1 0` 并显式设置 `min-width: 0`。关键在 `min-width`：Flex 子项的 `min-width` 默认是 `auto`，右侧一旦放了长文本、表格或 `pre` 内容，就会按内容最小宽度撑开，表现为「自适应失效、整行溢出」。同时要把 `flex: 1`（等价 `1 1 0%`，基准为 0，按比例分剩余空间）与 `flex: auto`（`1 1 auto`，基准取内容宽度）区分开，内容宽度差异大时两者结果不同。文本超长还需要 `overflow: hidden` 加省略号，或允许换行时配 `overflow-wrap`。面试时补一句兼容方案：退化为 `width: 200px` 加 `width: calc(100% - 200px)`，代价是失去弹性。

**虚拟 DOM 的定义与收益**：虚拟 DOM 是用普通 JavaScript 对象描述真实 DOM 的结构（类型、属性、子节点），状态变化后生成新的对象树，与旧树做 diff 得到最小变更集合，再批量提交到真实 DOM。收益有四点：声明式编程把「怎么改」交给框架，开发者只描述「应该是什么」；跨平台渲染，同一套描述可以输出到 Web、原生端或字符串（SSR）；批量更新减少重复的布局与重排；组件化与可测试性更好。代价同样要说清：diff 本身消耗 CPU、内存里长期多一份树，大列表或高频局部更新的场景不如精准的手写 DOM 操作，需要 key、memo、虚拟滚动配合。因此「虚拟 DOM 一定更快」是常见误区，它换来的是可维护性与可预测性。

**数组去重**：最简写法是 `[...new Set(arr)]`，按 SameValueZero 判等，能去掉重复的 `NaN`，但内容相同的对象仍然各算一个；`filter((v, i) => arr.indexOf(v) === i)` 语义直观但复杂度 O(n²)，数据量大时不可用；按业务键去重（对象数组）用 `Map` 或 `reduce` 更合适，`Map` 保留首次出现、顺序稳定，复杂度 O(n)。若要求保留引用与顺序，用 `Map` 遍历原数组后取 `values()`。

**简单双向绑定**：Vue 的 `v-model` 是 `:value` 加 `@input` 的语法糖，自定义组件通过 `modelValue` 与 `update:modelValue` 实现；响应式在 Vue 2 用 `Object.defineProperty` 劫持 getter/setter，无法监听对象新增属性与数组下标赋值，Vue 3 改用 `Proxy` 拦截整个对象。React 的受控组件把 `value` 与 `onChange` 绑定到 state，本质是单向数据流加事件回写，并不是真正的双向绑定。回答时点明这一差别，比直接写一段 `v-model` 更能体现理解。

**无限层级 BOM 的存储与查询**：邻接表（`parent_id`）最直观，配 `parent_id` 与 `code` 索引；读多写少的场景加闭包表或物化路径（`path` 存 `/A/B/C`），把「查子树」变成前缀匹配，避免递归。MySQL 8 可用递归 CTE（`WITH RECURSIVE`）一次查出子树，但要注意 `cte_max_recursion_depth` 与语句超时；数据量不大时也可一次取全量子树在内存组树，减少往返。循环 BOM 的识别：递归时携带已访问路径，遇到重复编码即成环；写入阶段可用闭包表检测祖先链，或在物化路径上做包含判断；识别后要能指出具体环路（A → B → A）并拒绝保存，而不是只报「数据异常」。叶子汇总只对没有子件的节点累加，且多级用量要按层级连乘（每级用量相乘），简单相加是典型错误。性能上按层懒加载、虚拟滚动、导出走异步任务并回传下载链接，热点成品可预计算汇总结果。前后端最容易踩的坑是树节点结构没定死——`id`、`code`、`name`、`unit`、`qty`、`hasChildren` 与错误码必须先约定，否则联调反复。讨论结束后的汇报会被随机抽人提问，需要能说清自己负责的部分、判断依据与放弃的方案，而不是复述整组结论。
