### 《面试题目》

1. Coding Agent 项目的执行与任务编排平台是什么样的程序？
2. OpenAI 兼容 API 中 Completion 与 Responses 两类接口有什么区别？
3. Agent 调用模型时可以传哪些参数，参数如何固化？
4. 模型的 Thinking 开关会带来什么影响？
5. 长任务如何避免注意力漂移和初始指令被上下文冲淡？
6. 如何系统评测 Agent，并与其他编程 Agent 对比？
7. 事实层、聚合层和快照层有什么区别，分别如何实现？
8. 用户量较小时，如何验证点赞链路的实际效果？
9. 为什么项目同时使用 MySQL、PostgreSQL、Caffeine 和 Redis？
10. 两个开源项目中的贡献是否已通过 PR 合并？
11. 使用 AI 学习和开发时有哪些正面与负面案例？
12. 没有实习经历时，如何证明自己的核心优势？

### 《参考解析》

1. **长任务稳定性**：把目标、约束、计划和当前状态放在结构化工作区，阶段完成后压缩历史但保留决策依据；关键动作通过工具结果和检查点验证，避免只依赖模型记忆。
2. **Agent 评测**：使用固定任务集和隔离环境，记录成功率、修改正确性、耗时、成本、人工介入次数及回归情况。对比时统一模型、权限、超时和任务输入，避免只挑成功案例。
3. **数据分层**：事实层保存不可歧义的原始事件，聚合层提供可重算统计，快照层服务低延迟读取。聚合和快照都应能追溯到事实数据，并明确刷新时点。
4. **多存储选型**：每种组件必须对应不同的数据模型、访问模式或一致性要求；若职责重叠且规模很小，多套数据库和缓存只会增加同步与运维成本，应优先收敛。
5. **小流量验证**：通过端到端日志、数据库状态和可重复的真实操作证明链路正确，再用故障注入验证幂等和恢复；不能把缺少用户量等同于无需验证。
