### 《参考解析》

**微信翻译功能的测试设计**：按「输入—处理—输出—周边」四层拆。功能层覆盖语种（中英日韩及小语种）、输入形态（文本、语音、图片 OCR、聊天上下文）、长短文本、表情符号与特殊字符、方言与错别字；边界层覆盖空输入、超长文本、纯符号、混合语言；结果层校验翻译准确性（可用标准语料做回归）、术语一致性、格式保留（换行、@、链接）；交互层覆盖发送前编辑、长按翻译、撤回、转发后的展示；非功能层覆盖离线、弱网、超时、并发、耗电与隐私（翻译内容是否上传、是否留存）。最后补一句「准确性不能靠人眼逐条看，要建小规模双语对照集做回归」。

**需求文档不清时怎么推进**：先把模糊点列成问题清单，按「影响用例设计」和「影响排期」排序，找产品当面确认并留下书面结论；对暂时确认不了的，按最保守的假设设计用例并在用例里标注假设；同时用原型、竞品、历史版本反推预期行为；如果仍阻塞，先覆盖确定部分，把不确定项挂风险清单并在提测会上同步。

**SQL 与建表**：查询题先写清「筛选—聚合—排序—分页」的顺序，注意 WHERE 与 HAVING 的区别、NULL 的比较、索引列不要套函数。建表要点：字段类型够用即可（金额用 DECIMAL 不用 FLOAT）、主键与自增、NOT NULL 与默认值、字符集统一 utf8mb4、时间字段用 DATETIME/TIMESTAMP 并明确时区、必要的唯一索引与联合索引（注意最左前缀）、外键与级联策略、表注释与字段注释、预估数据量决定是否分区。

**AI 与自动化结合**：可以讲三条落地路径：用 LLM 把需求文档转成用例草稿再由人审；用 LLM 生成接口用例的参数组合与断言，跑完后把失败样本回流；用视觉模型做 UI 元素定位的兜底。要强调「AI 产出必须过 Review 和回归集」，否则会生成大量看似合理但不存在的业务规则。

**公司与岗位准备**：面试前至少记住公司主营（机器视觉检测设备）、典型产品形态（缺陷检测、尺寸测量、定位引导）、客户行业（3C、锂电、半导体等），并把「视觉检测」和「伺服电机」的基础概念补上：伺服电机是带编码器闭环反馈的电机，控制器给位置/速度指令，驱动器闭环调节。硬件不熟时，回答重点放在「如何用已有的测试方法论快速上手」而不是硬编经历。
