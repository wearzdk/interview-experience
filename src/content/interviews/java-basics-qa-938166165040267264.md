### 《参考解析》

**static 与流程控制语句**

static 成员属于类而不是实例，跟着 Class 对象走：静态变量在类加载的准备阶段先赋零值、到初始化阶段才赋真实值，静态块按书写顺序执行且只执行一次，所以静态块的顺序会影响结果。静态方法里没有 this，只能直接访问静态成员，要访问实例成员必须显式传入对象。真正要记住的是代价——静态可变状态是全局共享的，多线程下必须自己做同步；静态集合会随着类加载器一直被引用，很容易变成不会被回收的缓存，用完记得清理。static 适合常量、无状态工具方法和单例持有者，不适合放有生命周期的业务数据。

break 终止当前这一层循环或 switch，continue 只结束本次迭代、继续下一轮，两者都不影响方法本身，而且都不会让 finally 被跳过；return 直接结束整个方法，但方法级的 finally 仍然会执行。要跳出多重嵌套循环，标准写法是在外层循环前加标签（如 `outerLoop:`），再用 `break outerLoop;` 一次性跳出——标签可以带在任意语句前，`continue outerLoop` 则用于跳到外层的下一次迭代。工程上更常见的替代是把它抽成一个方法用 return 直接退出，或者用标志位控制外层条件，因为标签越多可读性越差；用抛异常来跳出循环属于拿异常做流程控制，线上不要这么写。

**面向对象基础与多态**

面向对象和面向过程不是对错之分，而是分解问题的粒度不同：面向过程按步骤和函数组织，数据与操作分离，链路短、写起来直接，适合简单线性的任务；面向对象以对象为基本单元，把数据和对数据的操作绑在一起，通过封装、继承、多态换取可扩展性和可维护性，代价是多一层抽象、设计和理解成本更高。大型系统需求会变，所以更偏向面向对象；但一个几百行的脚本硬套一堆类，反而是过度设计。

面向对象的特征通常说三条——封装、继承、多态，也有人把抽象并列进去。封装的重点不是「加 getter/setter」，而是控制可见性并把不变量收在类内部；继承是 is-a 的复用，但耦合很紧，所以有「组合优先于继承」的取向；抽象是用接口或抽象类把共同特征抽出来，让调用方依赖稳定的一侧。多态的价值在于调用方只认父类型或接口，新增实现时不用改调用代码。

Java 的多态分两种。编译期多态就是重载：同一个类里同名方法按参数类型和个数区分，编译期就定下调用哪个签名。运行期多态靠继承/实现、方法重写加上父类型引用指向子类对象：JVM 通过 invokevirtual 在运行时按对象的实际类型在方法表里选实现，所以 `Animal a = new Dog(); a.sound();` 走的是 Dog 的版本。几个容易踩的边界：字段访问和 static、private、final 方法以及构造器都不参与这种动态分派，按编译期类型或静态绑定处理，因此都不是运行期多态；另外在构造器里调用可被重写的方法，子类字段还没初始化完就会被调到，属于经典坑。

**抽象类与接口**

抽象类可以有实例字段、构造器和各种访问修饰符的具体方法，但只能被单继承，适合多个子类共享状态与实现；接口是能力契约，可以被一个类实现多个，字段隐式是 public static final，Java 8 起有 default 与 static 方法，Java 9 起还允许 private 方法。选型的判据是：需要复用实现和状态就抽抽象类，只需要约定行为、或者一个类要同时具备多种身份就用接口；现代写法常是定义接口再配 default 方法或组合。至于「抽象类表示 is-a、接口表示 has-a」这种说法不必照背，接口更准确的含义是 can-do 的能力约定，像 Comparable 就是典型的「具备可比能力」。

普通类和抽象类的关键差别只有能不能实例化，以及能不能声明抽象方法：抽象类不能被 new，必须被继承后由子类创建，可以有抽象方法也可以一个都没有（只要类上写了 abstract 就不能实例化），而普通类不能包含抽象方法。抽象类通常是当基类抽公共逻辑用的，普通类则直接拿来创建对象。

最后一题的常见错误答案要特别澄清：final 和 abstract 是互斥的，`abstract final class` 在任何情况下都编译不过（会报 illegal combination of modifiers），不存在「所有方法都是抽象时就可以加 final」这种例外——final 意味着不可被继承，而抽象类必须被继承、由子类补全实现才有意义，两个约束直接冲突；同理抽象方法也不能同时是 final、static 或 private。

**SOLID 原则怎么答才不像背书**

五条原则各配一句取舍就够了。单一职责说一个类只应有一个引起它变化的原因，落到代码上就是「改 A 需求不用动 B 的类」。开闭原则是目标而非手段：对扩展开放、对修改关闭，靠的是多态和抽象，不是到处加 if。里氏替换约束的是继承的正确性——子类替换父类后行为不能被破坏，不能加强前置条件、也不能削弱后置条件，正方形继承长方形是经典反例。接口隔离反对胖接口，宁可拆成多个小而专的接口，避免实现方被迫写一堆用不上的空方法。依赖反转说的是高层模块和低层模块都依赖抽象，细节依赖抽象，这也是 Spring 那套依赖注入的理论依据。答题时按「原则一句话 + 一个自己项目里的例子」组织，比逐条背定义更容易过关。
