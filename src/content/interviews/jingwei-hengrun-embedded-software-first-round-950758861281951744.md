### 《参考解析》

**内核数据传给用户空间的四条路。** 最常规的是在驱动的 read / write / ioctl 里用 `copy_to_user` 与 `copy_from_user`：用户态传进来的是虚拟地址，内核不能直接解引用（可能属于别的进程、也可能被换出），必须经这两个函数做地址校验与拷贝，返回值要检查——拷贝不完整时返回未拷贝的字节数，不能当成功。第二条是 `mmap`：把内核里用 `vmalloc` / `kmalloc` 分配的缓冲区映射到用户空间，适合视频帧、大块采样数据这类零拷贝场景，代价是要自己管好页表与缓存一致性。第三条是伪文件系统：procfs、sysfs、debugfs 里创建文件，用户态 `cat` 或 `echo` 就能读写，适合调试与少量控制参数，不适合高频数据。第四条是 netlink 或字符设备配合 poll / epoll，适合异步事件通知。回答时补一句「无论走哪条路，用户指针都必须先 `access_ok` 校验，且不能在持锁或中断上下文里做可能睡眠的拷贝」，这题就完整了。

**设备树的作用是把硬件描述从代码里搬出去。** 同一份内核镜像要跑在不同板子上，以前靠板级文件（board file）把地址、中断号、时钟写死在 C 代码里，一款板子一份代码；设备树用一份独立的文本（编译成 dtb）描述 CPU、内存、总线、外设的地址与中断、引脚复用、时钟树，内核启动时解析成 `device_node`，驱动通过 `compatible` 字符串匹配自己的节点，再用 `of_*` 系列接口取资源。带来的直接好处是驱动与板级硬件解耦、一款 SoC 的多块板子共用同一份内核、改硬件不用重编内核。面试常追问「驱动怎么拿到设备树里的资源」，答 `of_match_table` 匹配 + `platform_get_resource` / `devm_*` 取寄存器与中断。

**inline 是建议而不是命令。** 作用是消除函数调用的开销（压栈、跳转、返回），让编译器把函数体直接展开到调用点，对小而频繁调用的函数（getter、位操作封装）有意义；同时它保留了函数的类型检查与作用域，比宏安全。代价是代码体积膨胀、指令缓存命中率下降、调试时断点不好下；而且 `inline` 只是给编译器的提示，开 `-O0` 或函数体过大时不会展开。另外要区分两个概念：C99 的 `inline` 与 `static inline`（后者放头文件里最常用，每个编译单元一份，避免重复定义），以及 C++ 里类内定义的成员函数默认隐含 inline。

**堆与栈的区别可以按六点答。** 分配方式：栈由编译器自动分配释放，堆由 `malloc` / `free`（内核里是 `kmalloc` / `vmalloc`）手动管理；生长方向：栈通常向低地址生长，堆向高地址；生命周期：栈随函数返回销毁，堆由程序员控制；大小：栈空间小且固定（线程栈常见几 MB，嵌入式任务栈只有几 KB），堆可以大到接近可用内存；碎片：栈不产生碎片，堆反复分配释放会产生外部碎片；速度：栈只是移动栈指针，快；堆要走分配器查找空闲块，慢且时间不确定。嵌入式里还要补一句：任务栈溢出是常见故障，靠高水位线与哨兵检查，堆则要注意 `kmalloc` 在中断上下文里不能睡眠。

**根文件系统的「文件类型」有两层含义，先问清再答。** 如果问的是 Linux 的七种文件类型：普通文件、目录、字符设备、块设备、FIFO（命名管道）、socket、符号链接，用 `ls -l` 第一列区分。如果问的是根文件系统的目录结构，按 FHS：`/bin` 与 `/sbin` 放基础命令，`/etc` 放配置，`/dev` 是设备节点，`/proc` 与 `/sys` 是内核导出的伪文件系统，`/lib` 放共享库与内核模块，`/usr` 放用户程序与文档，`/var` 放可变数据（日志、锁），`/tmp` 临时文件，`/mnt` 与 `/media` 挂载点，`/root` 是 root 的家目录。嵌入式常见的形式是 BusyBox + 精简目录，或用只读的 squashfs 加一个可写的 overlay。

**Linux 是不是实时，取决于跑的是哪个内核。** 标准 Linux 内核是软实时：能保证吞吐和公平调度，但不保证最坏响应时间，关中断、自旋锁、优先级反转都会带来毫秒级抖动。硬实时有三条路：打 PREEMPT_RT 补丁（把自旋锁改成可睡眠的 rtmutex、中断线程化，最坏延迟降到几十微秒）、Xenomai 或 RTAI 双内核（实时任务跑在独立的小内核上，Linux 作为低优先级任务）、或者干脆实时部分用 RTOS、Linux 只做应用处理器。回答时要落到项目：如果项目里只是采集与显示，标准内核够用；如果要做电机控制、CAN 周期报文，就得说清用了哪种方案、实测延迟是多少。

**项目与综合素质题的答法。** STM32 项目按「外设→驱动→应用」讲：用了哪些外设（ADC、CAN、SPI、定时器）、驱动是自己写的还是用 HAL、遇到过什么问题（时钟配置、DMA 与缓存一致、中断优先级）。驱动开发经历要具体到字符设备还是平台设备、有没有写过 file_operations、怎么调试（printk、ftrace、逻辑分析仪）。「为什么投成都」和「三到五年规划」要落到可验证的事实：成都的汽车电子与嵌入式岗位密度、自己的技术方向（车载软件、AUTOSAR、域控制器）、希望在几年内独立负责一个模块。「对汽车行业怎么看」可以从电动化与智能化带来的软件占比上升、功能安全与 OTA 要求、以及车载软件迭代节奏切入，避免空泛的行业前景描述。「对加班怎么看」如实说明自己能接受的强度与边界，比表态「完全接受」更可信。
