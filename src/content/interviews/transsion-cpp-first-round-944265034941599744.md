### 《面试题目》

1. 一个局部对象、一个 new 出来的对象、一个全局对象，生命周期分别由谁管？
2. unique_ptr、shared_ptr、weak_ptr 你在项目里怎么选？shared_ptr 到底比裸指针贵在哪？
3. 虚函数的调用过程能讲到汇编级吗？为什么虚函数默认不能被内联？
4. 10 万条设备黑名单要频繁按前缀查，你选 map、unordered_map 还是别的？
5. vector push_back 到 100 万条扩容了几次？为什么 GCC 是 2 倍而 MSVC 是 1.5 倍？
6. std::move 到底做了什么？为什么返回局部变量时不要写 return std::move(x)？
7. 手撕：实现 strcpy，如果 src 和 dst 有重叠你怎么办？
8. memmove 和 memcpy 有什么区别？为什么 memcpy(dst, src, 4) 能被优化成一条指令？

### 《参考解析》

**三类对象的生命周期，本质是「谁负责那一行析构」**。局部对象归作用域：离开作用域按构造逆序析构，编译器在每个出口（含异常 unwind）都插了桩，栈对象天然异常安全；new 出来的对象归你，指针变量自己还在栈上，出作用域销毁的只是指针，堆上的对象没人替你 delete——所以裸 new 应该直接包进智能指针；全局/静态对象归运行时，main 之前构造、main 之后逆序析构，真正的坑是跨编译单元初始化顺序标准未定义，A 的构造函数用到还没构造的 B 就会读到空值，解法是改成函数内 static（Meyers 单例），C++11 保证首次调用时线程安全。

**选型口诀：默认 unique_ptr，共享才 shared_ptr，观察一律 weak_ptr**。unique_ptr 是 move-only、`sizeof` 与裸指针相同、析构是编译期展开的 delete，零额外开销；shared_ptr 是 16 字节（对象指针 + 控制块指针），贵在控制块的强弱计数是原子操作，一次拷贝就是一条 `lock xadd`，多线程高频拷贝同一份 shared_ptr 会让控制块所在 cacheline 在两个核之间来回弹，实测比传裸指针慢数倍——参数该传引用。`make_shared` 把对象和控制块一次分配、省一次 malloc，但只要还有 weak_ptr 活着，整块内存都回收不了。

**虚函数调用是「两次取址 + 一次间接跳转」**：vtable 按声明顺序排槽位放在只读段，对象头部放 vptr，调用编译成取 vptr、按固定偏移取出函数地址、再间接 call。目标编译期未知，所以默认不能内联，也挡住了常量传播，多态分发还要吃一次分支误预测。去虚化的抓手：加 `final`、放进匿名命名空间、CRTP 把多态搬到编译期、开 LTO 做投机去虚化；热路径把最贵的几个算子模板化，通常比换容器更值。

**前缀查询先否掉哈希表**：哈希把 key 打散，前缀在桶里没有任何聚集性，只能全表扫。正确方向是「有序 + 二分」：排好序的字符串 vector 上用 `lower_bound` 取前缀起点，再用「前缀拼一个 0xFF」取终点，得到一段连续区间。为前缀而生的结构是 trie / 压缩前缀树，代价只与 key 长度有关、与条目数无关，但每个节点一次指针追逐、内存放大明显。10 万条读多写少，排序 vector 最划算；要中序遍历才轮到 `map`（节点单独分配、cache 不友好）；纯点查用 `unordered_map` 并 `reserve` 到预估条数，避开 rehash 时迭代器失效。

**vector 扩容是「均摊 O(1)、单次最坏 O(n)」**：容量不够就申请新块、搬元素、释放旧块。按 2 倍增长从 1 涨到 100 万约 20 次扩容，累计搬移量约等于最终元素数（等比级数求和）。GCC 取 2 倍、MSVC 取 1.5 倍是两个目标的取舍：2 倍增长次数最少、摊还最好，但新块永远大于此前所有释放块之和，旧内存无法复用；1.5 倍几轮之后新块能塞进之前留下的空洞，对长期运行、碎片敏感更友好。两个细节：移动构造没标 `noexcept` 时 vector 会退回拷贝（`move_if_noexcept`）；能预估就 `reserve`，还能避开扩容瞬间新旧两块同时在场的内存峰值。

**std::move 不搬任何字节**，它只是一次到右值引用的 `static_cast`，真正的搬运发生在移动构造里；被 move 之后对象仍有效但值未指定。收益也有边界：vector、string 的移动是偷三个指针 O(1)，std::array、开了 SSO 的短 string 仍然逐元素搬。`return std::move(local)` 把返回值表达式变成右值引用，直接掐掉 NRVO、反而多一次移动构造；写 `return local`，让编译器在调用方空间原地构造，零拷贝。

**strcpy 要先澄清语义**：标准 strcpy 对重叠是未定义行为，面试官问「重叠怎么办」其实是在看你知不知道这一点。要点：先算长度 n（`strlen` 不含结尾零，实搬 n+1 字节）；dst 在 src 之前、或 dst 不小于 src+n+1 时前向拷，否则从尾部倒着拷，不然前面的写会污染后面还没读的字节；再判空、返回 dst 以支持链式调用。加分项：逐字节版在 -O2 下常被识别成 memmove 调用，手写可按 8 字节对齐后整字拷贝，但要处理尾部越界读。

**memcpy 与 memmove 只差一句**：前者要求两块内存不重叠、重叠即 UB，后者先判断方向再决定前向还是后向拷，永远正确、代价是多一次分支。glibc 的 memcpy 按长度分档（通用寄存器、SSE/AVX、rep movsb），所以「memcpy 四个字节被折叠成一条指令」是说长度是编译期常量且够小，编译器直接生成一次 32 位 load 加 store，连函数调用都没有；长度是变量时才真的进 libc。别名分析也建立在不重叠的前提上，重叠时别指望它碰巧对。
