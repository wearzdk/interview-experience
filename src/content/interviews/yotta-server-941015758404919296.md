### 《面试题目》

1. 请做一下自我介绍。
2. 介绍实习中遇到并解决的一个问题。
3. 游戏服务端采用 Reactor 模型时，如何设计网络线程和业务线程，避免锁竞争和延迟抖动？
4. MySQL 事务有哪些特点？
5. 百万级长连接服务中，CPU 不高但 P99 延迟升高，如何定位？
6. UDP 没有 TCP 的重传机制，可以采取哪些方案提高可靠性？
7. 游戏服务端采用 Redis + MySQL 架构，如何解决缓存与数据库一致性？
8. 介绍一下路由和网关的概念。
9. 游戏服务端如何实现断线重连，保证状态恢复并避免旧连接和重复消息？
10. 按自顶向下或自底向上的顺序，介绍客户端与服务端建立连接和数据交互的流程。

### 《参考解析》

Reactor 的核心是把网络 IO 和业务处理解耦。多 Reactor 模型中，主 Reactor 负责 accept，子 Reactor 负责读写，业务线程池处理逻辑；共享状态尽量按玩家或房间分片，减少跨线程锁。网络线程不能执行慢业务，否则会拖住整条 IO 链路。

百万长连接下 CPU 不高但 P99 高，常见原因是单线程阻塞、锁等待、队列排队、发送缓冲区反压或下游抖动。要看每连接发送队列、线程池队列、GC、锁竞争和 off-CPU 时间，不能只看总 CPU。

UDP 可靠性要在应用层做序列号、ACK、超时重传、滑动窗口和拥塞控制；坐标这类高频状态可以只保留最新值，交易类消息必须可靠且幂等。断线重连要区分连接和逻辑会话，用世代号拒绝旧连接消息，用快照加增量恢复状态，关键请求用业务唯一键防重。
