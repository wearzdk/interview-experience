### 《面试题目》

1. 自我介绍。
2. 项目拷打（被直接质疑 SLAM 项目的深度）。
3. 手撕代码：使用非线性优化求浮点数的平方根（非力扣题，说是看候选人有非线性优化的背景）。

### 《参考解析》

**「用非线性优化求平方根」考的是把数值方法落到代码上的能力。** 核心是把求解转成求根：要算 `sqrt(a)`，就解方程 `f(x) = x² − a = 0`。牛顿迭代的更新式是 `x ← (x + a / x) / 2`，本质是在当前点用一阶泰勒展开近似目标函数、令近似式为 0 得到下一步。要答的点有四层：一是初值，初值选不好会多迭代甚至不收敛，常见做法是把浮点数的二进制指数右移一位（`0x5f3759df` 那类位技巧的简化版）拿到同量级的估计，再迭代一到两次即可；二是收敛速度，牛顿法在单根附近是二次收敛，误差平方级下降，迭代三次左右就能到 double 精度，所以循环条件可以是「相对误差小于 1e-12」或固定迭代三次；三是边界，`a = 0`、负数、`NaN`、`Inf`、次正规数要单独判，`a` 极大或极小时初值策略要避免溢出；四是「非线性优化」这个说法本身，题目表述更像「求非线性方程」，如果面试官其实想听高斯-牛顿或 LM，就用统一框架答：目标函数 `min (x² − a)²`、雅可比 `J = 2x`、更新步 `Δ = −J⁺f`，迭代即退化成牛顿法——把两种表述串起来讲，比只写一段循环更能体现理解。想再加分可以提 Quake 里的平方根倒数近似（一次牛顿迭代）以及 `std::sqrt` 在现代 CPU 上通常有硬件指令、手写迭代在精度与性能上都不占优的工程事实。

**被质疑项目深度时，先分清是「深度不够」还是「你讲得不够深」。** 面试官一句「你这 SLAM 项目深度不太够」，下一步通常是往底层追：前端用什么特征或直接法、外点怎么剔、后端是滑窗还是全图、边缘化之后信息矩阵怎么保持一致性（FEJ）、IMU 预积分有没有考虑零偏与重力对齐、回环检测用什么描述子、位姿图怎么求解、时间同步和外参标定怎么做的、评测用的什么数据与口径（ATE／RPE）、实时性在什么平台上跑到多少毫秒。如果这些只能答到「调库跑通、指标还行」，被判定深度不足是合理的；补救办法是回到项目里挑一条主链路，把每一步的公式、参数与失败模式都推一遍，并准备一个「我做失败了什么、怎么定位」的例子。如果确实是团队框架的功劳、自己只做了外围，那要诚实地把叙述收缩到自己真正掌握的部分，再把可迁移能力（优化、几何、C++ 工程、评测方法论）单独摆出来。

**传感器融合／VIO 方向的高频追问要有一条完整叙事。** 从「为什么要融合」讲起：单目有尺度不可观、纯 IMU 会漂，视觉与惯性在可观性上互补；然后是状态量的选择（位姿、速度、零偏、外参是否纳入估计）、IMU 预积分把高频数据压成帧间约束、视觉重投影残差与 IMU 残差一起做非线性最小二乘、滑窗为了控制计算量做边缘化、边缘化会引入信息丢失所以要用 FEJ 与可观测性约束避免虚假信息。再往上走一层是产品约束：头显或机器人上的算力、功耗、端到端时延、快速运动与弱纹理场景的鲁棒性，这些决定了工程上选 VIO 还是加激光、加 UWB。

**半小时的面试同样有信息量。** 这场总时长半小时多、项目拷打不深就转手撕，说明面试官很早就形成了判断；对候选人来说，一旦察觉对方往「验证性提问」走，要么用一个具体细节把话题拉回自己准备充分的地方（「这块我用的是 X，当时对比过 Y 和 Z」），要么就坦然接受这场的结果、把精力留给下一场。凉经的价值在于把「项目深度」这件事量化成可补的清单，而不是归结为运气。
