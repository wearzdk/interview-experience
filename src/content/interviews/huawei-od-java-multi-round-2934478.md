### 《参考解析》

**HashMap 与 0.75**：数组 + 链表 + 红黑树（链表长度 ≥8 且容量 ≥64 时树化）。下标用 `(n-1) & hash`，容量取 2 的幂；扩容翻倍时按 `hash & oldCap` 把元素分到原位置或 `i + oldCap`。0.75 是空间与冲突的折中：太小浪费空间、太大冲突率上升，这个值在泊松分布下让链表长度达到 8 的概率极低。

**Callable 为什么有返回值**：`Runnable.run()` 返回 void，无法把结果或异常带回调用方；`Callable.call()` 声明返回 V 且可抛受检异常，配合 `FutureTask`/`Future` 能在任务完成后 `get()` 拿结果、并捕获执行期异常。

**AQS 与 CAS**：AQS 用一个 `volatile int state` 表示同步状态 + CLH 双向队列管理等待线程，`ReentrantLock`、`Semaphore`、`CountDownLatch` 都基于它；CAS 是「比较并交换」的原子指令，`AtomicInteger` 与 AQS 的入队都用它，代价是 ABA 问题（用版本号解决）与自旋开销。

**缓存三剑客**：穿透是查不存在的数据打到 DB（布隆过滤器或空值缓存）；击穿是热点 key 失效瞬间大量请求打 DB（互斥重建或逻辑过期）；雪崩是大量 key 同时失效或缓存宕机（过期时间加随机、多级缓存、熔断降级）。

**Integer 的 128**：`Integer.valueOf` 对 -128~127 使用 `IntegerCache`，同一数值返回同一对象，所以 `==` 为 true；超出范围每次 new，`==` 比较的是引用。正因如此，包装类比较值一律用 `equals`。

**锁的分类**：按是否阻塞分自旋锁与互斥锁；按特性分公平/非公平、可重入、读写锁、乐观锁（CAS）与悲观锁；`synchronized` 是 JVM 层面的管程实现（有偏向/轻量/重量级升级），`ReentrantLock` 是 AQS 实现、支持中断与超时。

**手撕的教训**比题目本身更重要：三数之和因为用 `==` 比较 `Integer` 出错，说明「语言细节在紧张时会要命」；二面被要求用 Java 写而不是平时刷题的 C++，磕磕绊绊。投放简历的岗位写什么语言，就用什么语言练手撕。

**二面的项目追问方式**值得记：不只问做了什么，还问「为什么这么实现」「有没有更好的方案」「加限制条件后怎么办」。准备项目时对每个关键决策都备一条替代方案与取舍，才接得住第三层。
