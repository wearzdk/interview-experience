### 《面试题目》

1. 当目标板资源有限而构建机资源充足时，如何设计宿主-目标分离的构建流程？一套可复现的编译器套件通常应覆盖哪些组件、产物和调试配套？
2. 在硬实时约束下，中断上下文、可抢占任务与受保护共享数据之间怎样划分职责，才能降低调度抖动并规避优先级反转？
3. 板级硬件信息从内核源码中剥离后，如何借助外部描述数据完成早期初始化与驱动匹配？这种机制对多板复用和产品派生有什么影响？
4. 面向无 MMU、小内存的 MCU 与面向带 MMU、丰富外设的 Linux 平台，在启动入口、内存管理、并发模型、故障恢复和调试可观测性上有哪些架构级差异？
5. 同一地址空间内的执行流与独立地址空间内的执行流，在创建成本、隔离能力、调度粒度和共享数据方式上应如何取舍？
6. 面向多服务嵌入式系统，除管道和共享内存外，如何选择消息队列、信号、套接字、文件锁或同步原语？各自会引入哪些阻塞与优先级风险？
7. 为降低驱动缺陷对业务服务的破坏，运行域之间的权限边界如何设计？系统调用、缺页异常和地址翻译在其中扮演什么角色？
8. 从上电复位到业务服务可用，引导固件、内核解压与初始化、根文件系统挂载和服务编排各阶段应承担哪些职责？在安全启动和 OTA 回滚场景下启动链应如何调整？

### 《参考解析》

**宿主-目标分离构建**：构建机上跑交叉编译工具链，产物通过 NFS / TFTP / 串口 / 调试器下发到目标板，目标板只负责运行。可复现的工具链要覆盖：编译器与链接器（同一版本，固定 libc：glibc 或 musl，固定浮点 ABI 与目标架构三元组）、binutils、调试器（gdb + gdbserver，或 OpenOCD / J-Link）、构建系统与配方（CMake / Buildroot / Yocto，锁住所有包版本与源）、以及产物（内核镜像、设备树 DTB、根文件系统镜像、SDK 库与头文件）。可复现有三个抓手：容器化构建环境、锁文件的依赖清单、以及构建产物带版本标识（git commit + 工具链版本 + 时间戳）。常见坑是「本地能编、CI 编不过」——多半是工具链版本、路径写死或主机架构相关依赖。

**硬实时下的职责划分**：中断上下文只做最短的必要工作（读硬件、清标志、把数据放进无锁队列或信号量唤醒任务），绝不做内存分配、日志、阻塞调用；耗时处理下沉到可抢占任务，按优先级从高到低排布，实时任务优先级要高于所有非实时任务；共享数据用优先级继承的互斥量保护（FreeRTOS 的 mutex、Linux 的 PI futex），或用无锁结构 + 单写者约束避免锁。降低抖动的手段包括：关闭中断的时间窗口要尽量短、把长临界区拆开、避免在实时任务里做动态内存分配、用静态分配与内存池、把缓存与总线竞争考虑进去。优先级反转靠优先级继承或优先级天花板，不能让高优先级任务无限等待低优先级任务持有的锁。

**板级信息剥离与驱动匹配**：设备树（或 ACPI、板级描述表）把地址、中断号、时钟、引脚复用、电源域等信息从内核代码里移出；内核启动早期解析 DTB 建立 `device_node` 树，驱动通过 `compatible` 字符串与 `of_match_table` 匹配，`probe` 时用 `of_*` 接口取资源。收益是同一份内核镜像可支持多种板型（multi-platform），派生型号只改 dts；代价是调试时问题分散到「dts + 驱动 + 硬件」三处，且 dts 的语法错误往往只在启动日志里体现。Bootloader 需要把正确的 DTB 传给内核（`bootargs` + `fdt` 地址），双 DTB 时要注意选择逻辑。

**MCU 与 Linux 平台的架构差异**：启动入口上，MCU 直接从复位向量执行、无引导阶段，Linux 要经 BootROM → SPL → U-Boot → 内核解压与初始化；内存管理上，MCU 通常无 MMU、静态分配或简单堆，Linux 有虚拟内存、页表、按需分页与保护；并发模型上，MCU 是中断 + 前后台或 RTOS 任务（协作或抢占、无进程概念），Linux 有进程 / 线程、调度器、多核 SMP 与各种同步原语；故障恢复上，MCU 通常靠看门狗复位、无隔离，Linux 有进程隔离、oops 可只杀进程、有 kdump 可分析；可观测性上，MCU 靠串口日志与调试器，Linux 有 dmesg、ftrace、perf、/proc、core dump 与动态调试。

**同一地址空间 vs 独立地址空间**：线程共享地址空间，创建与切换成本低（只保存寄存器与栈、不换页表）、共享数据直接读写（但要自己同步）、隔离能力差（一个线程越界写会毁掉整个进程）；进程有独立页表，切换要换 CR3 / TTBR 与刷新 TLB，创建要复制或共享页表，隔离好、崩溃不互相影响，共享数据需 IPC。选择依据是「隔离需求」与「共享频率」：需要强隔离（第三方代码、不可信插件）用进程，高频共享大块数据用线程。

**多服务 IPC 选型**：管道（匿名 / 命名）适合父子或本机流式、简单但有拷贝与阻塞风险；共享内存最快但必须自己配信号量做同步，否则数据竞争；消息队列有边界与优先级、可实现异步与解耦，但队列满时会阻塞或丢消息，需要定容量与丢弃策略；信号只适合事件通知、不携带数据，且会打断系统调用；Unix Socket 通用、支持双向与传递文件描述符，适合本机服务间通信但比共享内存慢；文件锁适合跨进程互斥，但要注意 NFS 语义与死锁。风险点统一说：任何阻塞型 IPC 在实时任务里都可能引入优先级反转与不可控延迟，需要设超时、非阻塞模式或把阻塞转移到低优先级线程。

**运行域权限边界**：把不可信或高风险代码（驱动、第三方解析器）放进独立进程或沙箱，通过系统调用进入内核、由内核做参数校验与权限检查；MMU 用页表划分读写执行权限与用户 / 内核态，缺页异常是内核介入的入口（可用于按需分页、写时复制、以及检测非法访问并终止进程）；地址翻译保证一个域无法直接触碰另一个域的内存。工程的落点是「最小权限 + 故障隔离 + 可恢复」：驱动崩溃只影响其宿主进程，服务可重启；关键资源用能力（capability）或句柄而非全局名字访问；对共享内存做边界与生命周期约定。

**启动链与安全启动、OTA 回滚**：BootROM 校验一级引导的签名 → SPL / U-Boot 初始化 DDR 与存储、加载内核与 DTB → 内核解压、初始化驱动与挂载根文件系统（initramfs 或分区）→ init 系统启动服务（systemd / BusyBox init / 自研 supervisor）直到业务可用。安全启动要求每一跳都验签（RSA / ECDSA + 哈希，公私钥烧在 OTP 或 eFuse 中），失败则停止或进入恢复模式。OTA 回滚靠 A/B 双分区：新镜像写入非活动分区、校验通过后切换启动标志，启动失败由 Bootloader 计数回退到旧分区；同时要有防降级（版本号与签名策略）、断电安全（写入原子性与标志位）与回滚后的数据迁移兼容。要把「升级中掉电」与「新版本启动不了」两种失败都覆盖到。
