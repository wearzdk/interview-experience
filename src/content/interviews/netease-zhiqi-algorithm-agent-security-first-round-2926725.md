### 《面试题目》

1. 自我介绍。
2. 详细介绍一下实习期间做的项目。
3. 在项目开发过程中主要遇到了哪些问题？都是如何解决的？
4. 项目细节：你这个 GenAI 七层语义分析是干嘛用的？
5. 反问环节。

### 《参考解析》

**自我介绍要在一分钟里把「我和这个岗位的关系」说清楚。** 算法岗的自我介绍不是履历朗读，面试官想听的是两件事：你的技术栈与 Agent 安全方向的交集在哪里，以及哪段经历值得他接着往下问。安全方向的岗位特别看重可控性，所以开场最好就抛出与风险识别、越权防护、内容或工具调用管控相关的线索，把追问引到自己准备最充分的区域，别把时间花在课程成绩这类不产生追问价值的信息上。

**讲实习项目要按链路讲，而不是按功能列表讲。** 推荐的结构是：业务背景与目标（原来怎么做、痛点是什么）→ 整体架构与数据流（入口、处理、存储、输出各是什么）→ 我负责的边界（和上下游的接口契约）→ 关键决策与取舍（为什么选这个方案、代价是什么）→ 结果（量化指标）→ 复盘。安全方向的岗位几乎一定会追问失败路径：模型判错时怎么办、工具会不会越权、输入里被塞了恶意内容系统表现如何。这些要在讲述里主动留出接口，而不是等面试官问出来才现想。

**「遇到了哪些问题、怎么解决的」是这类面试真正拉开差距的地方。** 有效的答法是「现象—定位—根因—方案—验证」五步，并且一次只讲两三个真实难点，讲透比讲多好。比如效果不稳定，就要说清怎么用 badcase 聚类把问题收敛到某一类输入，改成什么策略之后、用哪个固定集合回归、指标从多少到多少。只说「查了很多资料最后解决了」，面试官既无法判断这件事是不是你做的，也看不出方法论。

**GenAI 七层语义分析这类问题，考的是你能不能把「模型能力」翻译成「工程可控的环节」。** 分层的通常做法是把一次生成拆成若干可独立校验的语义层：先做意图与任务识别，再做实体与约束抽取，中间层做上下文与知识对齐，然后在风险层面做意图合规与敏感度判定，最后是输出结构校验与可解释性标注。它解决的是「模型输出只有一个黑盒结果、出问题既无法定位也无法拦截」的问题——每一层都能单独评测、单独设阈值、单独打日志，线上出问题能直接定位到是哪一层的判断偏了。回答时要点出三件事：每层判什么、每层用什么数据评测、层与层之间冲突时以谁为准。这三点答得出来，比背一遍架构图有说服力得多；被追问「能不能减到三层」时，也要能说清哪些层是为了可解释性、哪些层是为了拦截动作而必须存在的。

**Agent 安全方向常被顺带考察的知识面，最好提前想清楚。** 常见的有：提示注入与间接注入（恶意指令藏在被检索的文档或工具返回值里）、工具调用的权限与参数校验（最小权限、参数白名单、危险动作用户二次确认）、数据外泄路径（日志、缓存、上下文里被带出的敏感字段）、模型与规则的分工（确定性策略用代码拦，模糊的语义判断交给模型兜底）、以及评测与红队（固定攻击集回归、上线前对抗测试）。这些不需要在主项目里全都做过，但被问到时能说出「我会怎么设计」，和完全没想过是两种评价。

**反问环节挑与岗位真实工作相关的问题。** 比如团队现在主要防的是哪一类风险、安全策略落在模型层还是网关层、有没有红队或对抗评测的固定节奏、新人入职第一个项目大概是什么。这类问题既能帮你判断岗位是不是真的在做安全（有些名义上是安全岗、实际在做内容审核），也会让面试官觉得你在认真考虑这份工作。反问里避开加班与转正这类话题，它们在技术面显得突兀。
