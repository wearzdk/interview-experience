### 《参考解析》

1. **SQL 到 AST**：词法分析把字符流切成 token（关键字、标识符、字面量、运算符），语法分析按 SQL 文法把 token 组织成树，每个节点表示一种语法结构（SelectStmt、FromClause、WhereExpr）。项目里一般直接用解析器库（如 JSqlParser）而不是自己手写，手写只在需要方言定制时才值得。

2. **AST 与设计模式**：结构上最像组合模式——节点与子节点同构、可以递归遍历；再叠加访问者模式做「不改节点、只加操作」，比如在 AST 上遍历检查是不是只读语句。答出这一层才算理解，而不只是背「组合模式」四个字。

3. **只读与权限控制**：解析 AST 判断语句类型，只放行 SELECT/SHOW 这类，拒绝 DDL/DML 和多语句；再按表名、字段做白名单，绑定数据库账号的只读权限做最后一道。返回行数在 SQL 层加 LIMIT，同时设查询超时，避免一条慢查询拖垮连接池。

4. **LIMIT 与分页兼容**：已有 LIMIT offset, size 时不要再套一层，按 AST 判断是否已有 LIMIT，没有才追加；有的话取两者最小值。子查询里已经带 LIMIT 的情况要递归判断，不能正则匹配了事。

5. **高频问题识别**：归一化后做计数，把参数替换成占位符再哈希，避免「同一个问题换个 ID」被当成新问题。热点会漂移，所以用带时间衰减的窗口（近 7 天加权）而不是全量累计，缓存设 TTL 并定期重算 TopN。

6. **语义归类**：轻量做法是分词加同义词表、编辑距离或 SimHash，重一点用向量相似度聚类。工程上通常两级：先精确命中和关键词召回，再用向量相似度判定是否同一类，阈值要拿真实样本校准。

7. **上下文保留轮数**：按任务类型定，闲聊几轮就够，排查类问题需要保留完整工具调用链。更稳的做法是不按轮数截断，而是按 token 预算裁剪：保留系统提示和最近若干轮，中间部分做摘要。

8. **结果换文件引用**：能显著降 token，但会让模型失去对明细的直接感知，容易出现「知道有文件但答不出具体行」的问题。合理做法是回传结构化的摘要加少量样本行，文件引用作为按需读取的入口，而不是把结果整体藏起来。

9. **验证 Token 优化效果**：固定一批真实问题做离线回放，对比优化前后的输入输出 token、首字延迟、答案正确率（人工或 LLM 打分）。只看 token 下降不看质量会得出错误结论。

10. **链路追踪**：每个请求一个 trace id，每轮模型调用和每次工具调用作为一个 span，记录入参、耗时、token 和结果摘要。开源可参考 OpenTelemetry 的 GenAI 语义约定、Langfuse、Phoenix 这类 LLM 可观测方案。

11. **死循环排查**：先看 trace 里每轮的工具入参有没有变化——参数不变而结果相似，说明模型没有吸收结果，通常是提示里缺少「已获得什么、还缺什么」的状态；也可能是结束条件没定义清楚。修法是给状态摘要、给明确的终止判据，再加最大轮次兜底。

12. **最大轮次**：按任务复杂度设，检索类 5～8 轮足够，超过就强制收尾并返回已有信息加一句说明。轮次上限是兜底，不是主要手段。

13. **用结果判断是否结束**：可以让模型对「已有信息是否足以回答」做一次判断，或者用规则兜底（连续两轮结果相似度高、关键字段已齐）就终止。重排只能提高相关性，不能替代终止判断。

14. **关键词改写**：同义词扩展、上位词与下位词替换、去掉限定词做宽召回、按领域词典补全缩写。实现上可以维护同义词表加规则，也可以让模型生成多个查询并行检索再合并。

15. **线程安全 List**：`Collections.synchronizedList`（全表加锁）、`CopyOnWriteArrayList`（写时复制）、`Vector`（遗留类）、或用 `ConcurrentLinkedQueue` 之类的并发容器替代。选型看读写比例。

16. **CopyOnWriteArrayList**：写操作在锁内复制一份新数组、改完替换引用，读操作完全无锁直接读当前数组，所以读多写少时性能好，迭代也不会抛 ConcurrentModificationException。

17. **缺点**：每次写都全量复制，内存开销和写延迟都随元素数量线性增长；数据有延迟，写完立刻读另一线程可能读到旧值；只保证最终一致，不适合频繁写和大列表。

18. **优化复制开销**：减少写频率（批量合并写）、换数据结构（读写都多的场景用 `ConcurrentHashMap` 或分段结构）、只在配置类、监听器列表这类「几乎只读」的场景使用它。

19. **打家劫舍**：`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`，只需保留前两个状态，O(n) 时间 O(1) 空间。
