### 《面试题目》

1. 哪里人？
2. 执法记录仪项目的整个代码框架
3. 执法记录仪的屏幕开发流程
4. 音视频同步如何进行？网络延迟如何处理？
5. 锐明实习中的多路复用机制、线程模型是怎么样的？
6. 是否了解烽火？
7. 做的都是音视频互联网方向，职业规划如何？研究方向不一样怎么办？

### 《参考解析》

**讲项目框架要有层次，不要从某个函数开始讲**：嵌入式项目按「硬件抽象层 → 驱动层 → 中间件／系统服务 → 业务应用」分层说，落到执法记录仪这类设备上就是：采集（摄像头／麦克风驱动）、编码（H.264/H.265、AAC 硬编或软编）、封装与存储（MP4 分片、循环覆盖、断电保护）、传输（RTSP/RTP 或私有协议）、显示与外设（屏幕、按键、指示灯、GPS）。每一层点出关键技术选型与理由，再说清进程／线程如何划分、数据怎么在层间流动、共享缓冲区由谁管理。这样面试官才能顺着你的描述继续深挖，你也才掌控节奏。

**屏幕开发流程考的是驱动到 UI 的完整链路**：典型顺序是硬件接口确认（MIPI DSI／SPI／RGB，分辨率与时序）→ 设备树与驱动配置（panel 初始化序列、背光与 PWM、上电时序）→ 显示框架接入（Linux 下 DRM/Framebuffer，RTOS 下自绘或 LVGL 之类）→ UI 层（图层管理、刷新区域、双缓冲防撕裂）→ 业务状态映射（录制中、电量、存储告警）。要能答出刷新率与功耗的权衡、花屏／闪屏这类问题的排查思路（时序、时钟、DMA 带宽、缓存一致性），以及为什么 UI 刷新不能和编码抢同一个核。

**音视频同步与网络延迟是同一类实时性问题**：同步的基础是统一时基，采集端给每帧打上时间戳（同一时钟源，RTP 场景就是 RTCP 的 NTP 映射），播放端以音频为基准（人耳对音频抖动敏感）调整视频的显示时刻或丢帧。网络抖动靠缓冲区吸收，但缓冲区越大延迟越高，所以要在「流畅」与「实时」之间设目标水位，常用动态抖动缓冲加上丢包重传（RTX/NACK）或前向纠错（FEC），弱网下主动降码率、降分辨率。要能用具体数字说明你调过什么参数、效果如何。面试官接着问「多路复用与线程模型」时，答案就是 epoll/select 加非阻塞 IO、每路连接的状态机、线程池分配与锁粒度，以及为什么不一路一线程。

**研发方向不匹配是硬伤，要用「可迁移能力」正面回应**：这类岗位很看重方向对口，被问到「你做的都是音视频互联网」时不要回避。可以说清三层：一是底层能力可迁移（C/C++、数据结构、并发与内存管理、调试手段、协议栈理解）；二是具体经验可迁移（多路复用、线程模型、实时数据流，这些在通信设备里同样出现）；三是自己的补课动作（对通信／光网络的了解、愿意从哪切入）。同时准备好一个像样的反问：团队做的是接入、传输还是终端，新人前三个月的培养路径是什么——这既是了解岗位，也是在展示你认真评估过匹配度。

**「是否了解烽火」这类题别硬吹**：面试前花二十分钟看官网业务板块与最近新闻，能说出「光通信、光纤光缆、数据通信、智慧城市等方向，以及运营商客户为主」这种量级的信息就够，再结合自己的项目谈一个可能的结合点。答不上具体产品线不致命，但把公司业务张冠李戴会很扣分。整场下来，这类「方向不太相关」的面试结果多半取决于匹配度而非技术深度，所以时间要花在把可迁移的点讲透、把职业规划的连贯性讲圆。
