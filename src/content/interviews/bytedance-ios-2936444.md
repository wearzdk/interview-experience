### 《面试题目》

1. 自我介绍。
2. 讲一下 RunLoop。
3. 问项目（围绕简历上的项目展开追问）。
4. 问了一些 AI 相关的问题。
5. 手撕：最长无重复子串。
6. 反问。

全程约 45 分钟。

### 《参考解析》

**RunLoop 要讲到「它为什么存在」，而不是背模式名。** RunLoop 本质是一个事件循环：没有事件时让线程休眠，有事件时被唤醒处理，从而避免主线程空转耗 CPU。iOS 里主线程的 RunLoop 由 UIApplication 启动，子线程的 RunLoop 默认不创建，第一次调用 `[NSRunLoop currentRunLoop]` 时才懒加载。一个 RunLoop 有一到多个 Mode，同一时刻只能跑在一个 Mode 上，切换 Mode 会让当前 Mode 的 Source/Timer/Observer 暂停；`NSDefaultRunLoopMode` 处理常规输入源，`UITrackingRunLoopMode` 在滚动时接管，这就是「拖动 TableView 时 NSTimer 不触发」的经典现象，解法是把 Timer 加进 `NSRunLoopCommonModes`。回答时按「作用—组成（Source0/Source1、Timer、Observer）—与线程的关系—常见坑」这条线讲，再补两个实战点：用 `CFRunLoopObserver` 监听 beforeWaiting 做卡顿监控；主线程做耗时操作用 `performSelector:withObject:afterDelay:` 或把任务丢到后台线程，别在主 RunLoop 上堆同步任务。面试官常追问「RunLoop 和自动释放池的关系」——AutoreleasePool 的 push/pop 挂在 RunLoop 的 beforeWaiting 和退出时机上，所以一个 RunLoop 循环结束会释放一批临时对象。

**项目深挖是社招面的主战场，准备的是「决策链」不是「功能清单」。** 面试官通常从一句「介绍一下你做过最有挑战的项目」开始，然后顺着你的话往下钻：数据量多大、为什么选这个方案、这个方案有什么代价、如果重做会怎么改、当时踩过什么坑、你在其中具体负责哪一部分。稳妥的讲法是把每个项目压缩成「背景与目标—约束条件—候选方案与取舍—落地细节—结果与度量」五段，每段都有具体数字（QPS、包体积、启动耗时、崩溃率、人力与周期）。不要只讲「我用了 XX 框架」，要讲「为什么不是 YY」；也不要回避失败，讲清楚一次判断失误和后续修正，比全程完美更可信。被问到不熟悉的细节时直接说「这块是同事负责的，我了解的是接口约定」，比临场编造安全得多。

**AI 相关问题考的是「你真的用过」而不是「你了解概念」。** 社招 iOS 岗这两年被问得多的是：有没有用 AI 辅助编码、用的是什么工具、在哪些环节提效明显、生成的代码怎么保证质量；App 里有没有接过大模型能力，SSE 流式返回怎么处理、弱网和断流怎么重连、token 怎么计费和限流、内容安全怎么做。回答要落到具体场景和取舍：比如流式输出用 URLSession 的 delegate 逐段拼接，注意在后台线程解析、主线程增量刷新 UI，避免整段重排导致列表跳动；再比如把 AI 生成代码纳入 code review 和单测，不允许直接进主分支。没有真实经验就讲你验证过的实验和结论，别泛泛谈「AI 会改变开发方式」。

**手撕最长无重复子串：滑动窗口 + 哈希表记录最近位置，O(n)。** 维护左指针 `left` 和一个 `map[char] = 最近一次出现的下标`；右指针从左到右扫，遇到字符已存在且其下标 `>= left` 时，把 `left` 移到 `该下标 + 1`，然后更新 `map` 并把 `right - left + 1` 拿去更新答案。关键细节有三个：一是判断条件必须带 `>= left`，否则字符虽然出现过但已在窗口外，会错误收缩；二是空串返回 0，单字符返回 1；三是问「返回长度还是返回子串」——返回子串时要在每次更新答案时记录起点。复杂度 O(n) 时间、O(字符集大小) 空间。写之前先口述思路和样例，写完主动跑三个用例（`abcabcbb`、`bbbbb`、`pwwkew`），再说一句「如果是字节流或 Unicode，用数组/字典按码点存，不用假设只有 ASCII」。

**反问环节按「岗位真实信息」来问，别问能查到的。** 可以问团队当前的技术栈与最低支持版本、这个岗位入职后前三个月最重要的目标、客户端团队的发布节奏与灰度机制、面试流程还有几轮。这些问题既显示你在认真考虑这份工作，也能帮你判断团队是否匹配；避免一上来问薪资福利和加班强度，那类问题留到 HR 面。
