### 《参考解析》

**MQTT 如何保证报文可靠**：可靠性要分三层说。传输层是 TCP 的确认与重传，保证连接内的字节流不丢不乱序，但连接一断就没了。协议层靠 QoS：QoS 0 最多一次，发完即忘；QoS 1 至少一次，PUBLISH 带报文标识符，接收方回 PUBACK，发送方在超时或重连后带 DUP 标志重发，因此可能重复，业务必须幂等；QoS 2 恰好一次，走 PUBLISH、PUBREC、PUBREL、PUBCOMP 四次握手，收发双方各保存一份状态，代价是两倍往返与额外存储。会话层靠 Clean Session 与 Session Expiry：关闭 Clean Session 后 Broker 为客户端保存订阅关系与未确认消息，断线重连可以续上；配合遗嘱消息，Broker 在检测到异常断连时替设备发布离线通知。工程上还要补几点：Keep Alive 要小于 NAT 老化时间，否则连接会被中间设备静默丢弃；重连使用指数退避加抖动；设备本地要有持久化队列与补传，缓存满时按优先级丢弃；QoS 1 的去重要用业务序列号而不是 PacketId，因为 PacketId 在会话内会被复用。把传输、协议、会话三层分开讲，比只回答「MQTT 有三种 QoS」扎实得多。

**Linux 的任务调度方式**：Linux 的调度按调度类分层，优先级从高到低是 stop、deadline、realtime、fair、idle。实时类有 SCHED_FIFO 与 SCHED_RR：FIFO 没有时间片，同优先级按入队顺序运行，直到被更高优先级抢占或主动让出；RR 在同优先级之间轮转并带时间片。普通任务走 SCHED_OTHER，早期是 CFS，用 vruntime 红黑树按权重分配 CPU，`nice` 值影响权重；6.6 之后内核改用 EEVDF，思路仍是按虚拟时间做公平与延迟控制。SCHED_DEADLINE 基于 CBS 算法，给出运行时间、周期、截止期三个参数，适合有明确时限的周期任务。实际工程手段也要能说出来：用 `chrt` 修改策略与优先级、用 `taskset` 或 `sched_setaffinity` 绑核、用 `isolcpus` 与中断亲和把 CPU 隔离出来留给实时线程、用 SCHED_IDLE 跑后台任务；同时要知道实时任务长期占满 CPU 会饿死其它任务，内核有 RT throttling 兜底。被问「怎么保证一个线程的实时性」时，答案应落在策略选择、绑核隔离、中断收敛与优先级继承这几项的组合上，而不是只说提高优先级。

**端侧部署与算力评估**：能不能部署到手机上，要拆成算力、内存带宽、功耗与框架支持四件事回答。算力看模型的 FLOPs 与目标帧率，二者相乘得到所需算力，再与目标芯片 NPU、GPU 的峰值算力对比，并打上利用率折扣——实际能到峰值的比例通常只有三到五成。内存看权重与激活值的峰值占用，以及是否还留得下系统运行的空间。功耗与散热决定能否长时间跑满，手机上没有风扇，持续高负载必然降频。框架支持决定模型能否被 NPU 接管，不同厂商的算子覆盖差异很大。落地手段是量化（INT8，注意校准集选择与敏感层回退）、剪枝与蒸馏、算子融合、降低输入分辨率与跳帧、把预处理放到 GPU 或 DSP。手机端还有额外约束：Android 上要面对 NNAPI 与厂商 SDK 的兼容性、后台进程被系统限制、以及没有 CUDA 这类通用并行环境，原本用 TensorRT 的模型迁过去通常要重走一遍转换（TFLite、ONNX Runtime、NCNN）。回答这题的关键是把「模型多大、需要多少算力、目标平台峰值多少、实际利用率多少」四个数给出来，而不是笼统地说可以优化。

**项目最难的点怎么讲**：挑一个现象复杂、定位过程有方法、结果可量化的案例，按背景、现象、假设、验证、结论、复盘组织。技术类难点优先选并发与稳定性问题，例如偶发崩溃、数据错乱、内存持续增长、弱网重连，因为这类问题能展示定位能力：如何收集现场、如何把范围二分、根因是什么、改了什么、指标改善多少。要避免两种答法：一种是把「查了很久」当成难点，讲了很久没有结论；另一种是把业务复杂度当成技术难点。如果面试官追问「重做一次会怎么改」，要能给出架构层面的改进，例如增加断言与自检、把共享状态收敛到单线程、引入可观测性，这一问考的是复盘能力而非记忆力。

**HR 面：offer、薪资与团队分歧**：这几个问题考的是稳定性与自我认知，答法要有结构。offer 与薪资如实说明在流程中的公司与大致区间即可，不必报到具体数字，重点是把海能达放在方向匹配的位置上讲，说明这个岗位的技术栈与你想做的方向为什么一致；手上没有 offer 就直接说在推进的流程，不要编。成绩与四六级如实回答，排名一般可以补充专业核心课的表现或成绩趋势，不必辩解。团队分歧给一个具体案例：分歧的技术焦点是什么、你用什么依据（数据、实验、标准）推动收敛、最终是否采纳了对方方案，落点是「对事不对人且有结论」。竞赛与干部经历用「角色、具体动作、结果」三句话讲完，不要铺陈比赛规则。家庭与个人情况属于背景核实，简短如实回答，不必展开与岗位无关的细节。
