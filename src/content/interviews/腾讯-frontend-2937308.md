### 《面试题目》

1. XSS 是什么？
2. CSRF 是什么？
3. Vue 的响应式是怎么做的？
4. 为什么 Proxy 更好？

### 《参考解析》

**XSS 要分类型并给出防御**：存储型（恶意脚本入库，其他用户访问时执行）、反射型（脚本随请求参数回显）、DOM 型（前端直接把不可信数据写入 `innerHTML` 等）。防御的核心是「按上下文转义 + 可信来源校验」：输出到 HTML 用实体转义，输出到属性、JS、URL 用对应的编码；用 CSP 限制脚本来源；对富文本用白名单过滤；Cookie 加 HttpOnly 减少被读取的风险。答完定义要立刻接防御，否则会被追问「怎么防」。

**CSRF 的本质是「借用户的登录态发请求」**：攻击者诱导已登录用户访问恶意页面，向目标站点发起带 Cookie 的请求。防御手段是 SameSite Cookie、CSRF Token（服务端校验一次性或会话绑定的 token）、校验 Origin/Referer、对敏感操作二次确认。和 XSS 的区别要讲清：XSS 是脚本在站内执行、可以读取页面数据；CSRF 是脚本在站外、只能借用 Cookie 发请求，读不到响应。

**Vue 响应式的演进**：Vue 2 用 `Object.defineProperty` 递归把每个属性改写成 getter/setter，在 getter 里收集依赖、setter 里派发更新，数组通过重写七个变更方法拦截；局限是无法监听新增/删除属性（需要 `$set`/`$delete`）、无法监听数组下标赋值、初始化时递归遍历全量属性。Vue 3 用 `Proxy` 代理整个对象，能拦截 get/set/has/deleteProperty/ownKeys 等操作，天然支持新增与删除属性、数组索引与 length，配合 `Reflect` 保证默认行为；依赖收集用 `track`/`trigger` 加 `WeakMap` 存储，惰性代理嵌套对象（访问到才代理），内存与初始化性能更好。还能补一句 `Proxy` 的兼容性代价与 Vue 3 的编译期优化（静态提升、Patch Flag）。

**压力面的应对**：面试官从第一个问题就往下钻，说明他在测「知识的深度边界」而不是「知不知道」。被问到不会的，直接说「这一层我没深入过，我了解到的是……」，然后给出自己的推理路径；不要用模糊的术语糊过去，被追问一句就露。帖主提到的「被压麻了」是常见体感，实际上这类面试的评价标准往往是「能不能在压力下保持结构」，回答语速放慢、先给结论再展开，比抢答有效。
