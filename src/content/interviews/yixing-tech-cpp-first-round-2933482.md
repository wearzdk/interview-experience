### 《参考解析》

**右值与移动语义是一条线，别答成两个孤立概念**。左值是有名字、可取地址的表达式，右值是没有名字的临时量（纯右值）或即将消亡的对象（将亡值）。拷贝构造要重新分配并复制资源，移动构造只是把指针「偷」过来并把源对象置空，复杂度从 O(n) 降到 O(1)。`std::move` 本身不移动任何东西，它只是一个把左值强制转换成右值引用的 cast，真正干活的是随后选中的移动构造 / 移动赋值；所以「move 之后源对象处于有效但未指定的状态」，别对着它读值。

**三种智能指针**：`unique_ptr` 独占所有权、不可拷贝只可移动、零运行时开销，是最优先的选择；`shared_ptr` 引用计数共享所有权、计数是原子操作有开销、并用强引用 + 弱引用两份计数防循环引用；`weak_ptr` 不增计数，用来观察 `shared_ptr` 管理的对象、`lock()` 拿到临时强引用，专门解决循环引用和「对象是否还活着」的判断。虚析构的原因是 `Base* p = new Derived` 后 `delete p` 时，若基类析构不是虚的，只调基类析构、派生类成员不释放——未定义行为级别的泄漏。

**迭代器失效按容器讲才准**：`vector` 扩容后全部失效（`push_back` 后旧迭代器不能用，`reserve` 能规避）、只造成尾部插入而不扩容时 `end()` 仍失效；`deque` 中间插入全部失效、首尾插入只失效对应端；`list` / `map` / `set` 只有被删元素的迭代器失效；关联容器 `erase` 时要用 `it = m.erase(it)` 这种写法。面试里最好补一句「用索引代替迭代器」或「先收集再删」这两种实用规避法。

**内存对齐**的两个理由：硬件访问对齐地址更快（跨越 cache line / 需要多次总线事务），以及某些平台根本不允许非对齐访问（ARM 上可能触发 fault）。结构体大小计算规则：每个成员相对起始地址的偏移必须是该成员对齐值（通常是自身大小，`#pragma pack` / `alignas` 可改）的整数倍，结构体总大小是最大对齐值的整数倍；所以 `char + int` 会占 8 字节而不是 5 字节，把大的成员放前面能减少 padding。

**select 与 epoll 的差别**：`select` 用固定大小的位图（`FD_SETSIZE` 常为 1024），每次调用都要把整个集合从用户态拷进内核，返回后还要自己遍历找出就绪的 fd，复杂度 O(n)；`epoll` 用内核里的红黑树 + 就绪链表，`epoll_ctl` 只注册一次，`epoll_wait` 返回的就绪列表直接可用，O(1) 取事件，且没有 fd 数量上限。另外 `select` 的水平触发、`epoll` 支持 ET（边缘触发，必须一次读到 `EAGAIN`）与 LT；大并发长连接用 epoll，少量 fd 或跨平台需求还能用 select / poll。
