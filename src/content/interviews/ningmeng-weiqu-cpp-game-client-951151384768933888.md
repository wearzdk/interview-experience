### 《面试题目》

1. 介绍一下 C++ 中各种内存分配方式，这些分配方式的区别是什么？
2. 堆和栈都是内存，为什么使用的开销不同？
3. 为什么操作系统中内存分为堆和栈，为什么不搞第三种内存？内存全都用堆行吗？请你设计一种新的内存架构，怎么设计？
4. 一直写内存、超出物理内存大小，这个时候会发生什么？如果内存都正在被使用、没法 swap，会发生什么？
5. 红黑树和哈希表的区别与使用场景。
6. 红黑树各个操作性能都不及哈希表，数据有序这种场景又比较有限，那红黑树的使用场景到底是什么？
7. 红黑树内部有序是不是自嗨？内部有序跟外部有什么关系？
8. 红黑树的性能为什么是 log n，为什么不是根号 n？请推导一下。

### 《参考解析》

**C++ 的内存分配方式**：按存储位置分五类——栈（函数内的自动变量，由编译器在函数入口/出口调整栈指针，分配即移动指针）、堆（`new` / `malloc` 手动申请，由分配器管理）、全局/静态存储区（`.data` / `.bss`，程序启动时分配、生命周期贯穿进程）、常量存储区（字符串字面量、`const` 全局量，只读）、以及线程局部存储（`thread_local`，每线程一份）。从分配机制再分：`malloc` / `free` 是 C 的分配器接口，按字节分配、不调用构造；`new` / `delete` 在分配之上调用构造与析构，类型安全；`new[]` / `delete[]` 还带数组长度信息；placement new 在已有内存上构造对象；C++11 起还有 `std::allocator` 与内存池（如 tcmalloc、jemalloc）在底层接管小块分配。区别的核心是「谁负责生命周期、是否调用构造析构、分配粒度与元数据开销」。这题答「生命周期不同」不够，要把五类存储期与两套分配接口分清楚。

**堆与栈的开销差异**：栈分配只做一次指针加减，地址连续、缓存友好、无元数据、无需加锁；释放是逆序自动完成，不可能泄漏。堆分配要走分配器的空闲链表/分级桶查找、写入块头元数据、可能加锁（多线程）、可能触发 `brk` / `mmap` 系统调用与缺页中断；释放要合并相邻空闲块、处理碎片。所以同样大小的对象，堆分配的耗时可以是栈的几十倍，且堆上对象地址分散，缓存命中率低。游戏客户端在每帧循环里避免频繁 `new`，就是这两个原因。

**为什么分堆和栈、能否统一**：栈满足「后进先出、生命周期与调用栈绑定、编译期可知大小」的需求，用一条寄存器就能管理，是函数调用模型的基础；堆满足「大小运行期决定、生命周期跨函数、需要共享」的需求。两者是两种访问模式，不是两种内存。全都用堆在理论上可行（早期某些语言实现就这么做），代价是每次函数调用都要分配与回收、失去栈的局部性与自动回收，性能与实现复杂度都不可接受；反过来全用栈则无法支持动态大小与跨函数生命周期。所谓「第三种内存」在硬件层面并不存在，能设计的是分配策略：例如区域分配（arena / 帧分配器，一帧结束整块丢弃）、对象池（固定大小对象复用）、分代/分级分配器（按大小分桶减少碎片）。面试里被要求「设计新架构」时，答这三类策略比空想硬件更得分。

**写满内存且无法 swap**：正常路径是物理页耗尽 → 触发页回收（回收 page cache、匿名页换出到 swap）→ 仍不足则触发 OOM killer，按 `oom_score` 杀掉进程；内核自身关键分配失败时可能 panic。如果所有匿名页都在使用、swap 也满，回收无从下手，最终就是 OOM killer 选一个进程杀掉，而不是「写入失败返回错误」——这是 Linux 的 overcommit 策略决定的：`malloc` 成功不代表有物理页，真正触碰时才缺页分配。C++ 程序里表现为某个进程被 SIGKILL，日志里常见 `Out of memory: Killed process`。要避免就只能限流、限制 cgroup 内存、或让程序自己处理分配失败（`new` 抛 `bad_alloc`、`malloc` 返回 null，且要关闭 overcommit 才可靠）。

**红黑树与哈希表**：哈希表平均 O(1) 查找，但无序、最坏 O(n)（哈希冲突）、扩容有抖动、不支持范围查询；红黑树所有操作稳定 O(log n)，中序遍历即有序，支持范围查询与按序取前 k。选型：只做点查且 key 分布可控用哈希表；需要有序遍历、范围查询、按序删除或要求最坏情况可预期时用红黑树。

**红黑树的场景与「内部有序」**：真实场景不是拿它当业务容器，而是作为「需要有序 + 稳定对数复杂度」的底层结构：`std::map` / `std::set` 的有序语义、`epoll` 里用红黑树管理待监听的 fd（按 fd 号有序，便于快速插入删除与遍历）、Linux 的 CFS 调度器用红黑树按虚拟运行时间排序取最左节点、内核的定时器与内存管理（vma 树）、数据库与文件系统的索引结构。内部有序对外部的价值是：中序遍历天然有序、范围查询 O(log n + k)、找前驱后继 O(log n)，这些哈希表都做不到。说「自嗨」是把「有序」当成了实现细节，其实它是接口能力——`std::map` 的 `lower_bound`、按序遍历、区间删除都依赖它。

**为什么是 log n 而不是根号 n**：红黑树是一棵近似平衡的二叉搜索树，树高被约束在 2·log₂(n+1) 以内（红黑性质保证最长路径不超过最短路径的两倍），每次比较排除一半子树，所以查找、插入、删除都是 O(log n)。根号 n 出现在「分块」类结构（如 sqrt decomposition：块内 O(√n)、块间 O(√n)），它的依据是把 n 个元素分成 √n 块、每块 √n 个，代价是两次线性扫描；树结构每层二分，不是分块，所以是 log。若问「为什么不是 O(1)」，答案是比较模型下基于比较的有序结构下界就是 Ω(log n)，要 O(1) 只能放弃有序（哈希）或放弃比较模型（基数排序、直接寻址）。
