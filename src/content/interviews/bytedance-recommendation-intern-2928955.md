### 《参考解析》

**多智能体任务分流**：常见分流是“意图识别 + 能力路由 + 结果校验”。入口用规则或小模型判断任务类型，orchestrator 再按能力标签、工具权限、成本与延迟预算选择 Agent；有依赖的子任务排 DAG，无依赖的并行。Codex、豆包这类产品本质是“通用模型 + 专用工具链路 + 兜底模型”。可优化的点包括用线上轨迹训练成本感知的路由器、把静态规则换成可学习阈值、给每个 Agent 定义输入输出契约、低置信度时回退到更强模型。面试中把创新点落在“路由依据”和“失败回退”上，比泛泛讲多 Agent 协作更具体。

**ASR 清洗的标签与收益**：一条样本是“转写片段 + 操作标签”，保留、删除、替换可做成 token 级三分类；替换还要给出目标词，通常由混淆集、领域词表加语言模型打分或轻量 seq2seq 生成，BiGRU 只负责判定操作。没有“插入”是因为清洗只处理已有转写，漏识别的内容不在 ASR 输出里，补不回来；这类问题要靠领域词表、重解码或二次转写。评估增量收益要固定下游 AC 自动机：离线对比清洗前后的匹配准确率、召回与任务成功率，并做“只去噪 / 只纠错”的消融；线上 AB 看下游命中率、误触发和时延。

**长序列建模**：主流是“先粗筛、再精算”。SIM 的 GSU 用类目、关键词或向量内积，从几千到几万条行为中召回与 target item 最相关的 Top-K；ESU 只对短序列做 target attention，把 O(L²) 降到 O(K·L)。其他路线有用 MIMN 等记忆网络把长序列压成固定容量兴趣槽、线性 Attention、状态空间模型、按时间分桶聚类，以及离线预计算 embedding。回答时点明“相关性检索”和“兴趣压缩”两条主线，并补充索引更新与召回损失的工程取舍。

**最大正方形**：用动态规划。dp[i][j] 表示以 (i,j) 为右下角的最大全 '1' 正方形边长；matrix[i][j]=='1' 时 dp[i][j]=min(上、左、左上)+1，否则为 0，答案是最大 dp 值的平方。时间 O(mn)，空间可滚动到 O(n)。ACM 模式要自己读入行列数与矩阵。

**和为 K 的子数组**：用前缀和加哈希表。遍历时维护 pre，累加哈希表中 pre-k 的出现次数，再把 pre 的计数加一，时间 O(n)。要主动澄清：数组含负数时滑动窗口不成立，只有元素全非负才能用双指针；先确认数据范围再选解法。
