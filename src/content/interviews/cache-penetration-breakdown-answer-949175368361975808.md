### 《面试题目》

1. 缓存穿透和击穿怎么答？
2. 布隆过滤器怎么删数据？
3. 空值缓存如果忘了设过期会怎样？
4. 穿透的三层防法分别挡什么？
5. 击穿的互斥锁重建方案有什么代价？
6. 逻辑过期方案适合什么场景？会读到脏数据吗？
7. 单机多线程要不要上分布式锁？
8. 面试官问这类题，真正想听的是什么？

### 《参考解析》

**先把三个概念分开**：穿透是查的数据压根不存在，缓存和 DB 都打不中，请求量大；击穿是单个热点 key 过期瞬间，短时间内大量请求打到同一行数据；雪崩是大批 key 同时失效或缓存整体挂掉，DB 整体被打爆。三者的内存层原因不同，混着讲会被认为只是背过八股。

**穿透的三层防法**：第一层是入口合法性校验，参数不符合格式的直接拒掉，不要走到查库那一步——帖主真实经历过下单查询接口被脚本刷随机参数，加上校验后 DB QPS 掉了一大半。第二层是空值缓存，查不到就写一个标记值，TTL 给几十秒到几分钟。第三层是布隆过滤器兜底，把全量存在的 key 预加载，查询前先过一遍。

**布隆过滤器的三个限制**：标准实现不支持删除，数据删了位数组里的位置还在，会一直误判为「可能存在」，要支持删除就得上计数布隆或定期重建；有假阳性——说不存在一定不存在，说存在可能不存在；需要预热与同步，新数据没进过滤器就会被误拦。因此被问「怎么删数据」时，正确回答是「标准布隆删不了，只能重建或换计数型」，而不是硬说可以。

**空值缓存忘设 TTL 的事故**：帖主上线时把空值写成 `"NULL"` 塞进 Redis，忘了设过期，用了默认永不过期，跑了两周后一批被爬虫刷出来的垃圾 key 把内存顶到告警线。修正做法是空值单独设短过期并加随机抖动，同时让空值标记与正常值用不同的序列化形态区分，避免反序列化抛异常。

**击穿的两种方案**：互斥锁重建是缓存 miss 的线程抢锁，抢到的查库回填，没抢到的短暂等待后重试；代价是未抢到锁的请求会阻塞，重建慢时线程池可能被打满——帖主就因重建 SQL 没索引、耗时过长导致接口超时率飙升，所以该方案只用于「重建成本可控」的场景。逻辑过期是 value 里带过期时间、Redis 本身不设 TTL，读到逻辑过期就异步重建、当前请求先返回旧值；代价是会读到脏数据，只适合一致性要求不高的展示类字段。

**部署形态先于方案**：单机多线程用本地 `synchronized` 或请求合并（singleflight）就够，不一定上分布式锁；分布式锁要设过期时间，并评估重建耗时，避免锁过期了重建还没完成。加一层本地缓存能挡住大部分击穿流量，代价是要处理多机不一致。

**面试的判断标准**：面试官不在乎方案多花哨，在乎你知不知道每个方案的失效边界。能说出「这个方案我线上踩过什么坑」，基本就稳了。
