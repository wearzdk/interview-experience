### 《面试题目》

1. 你平时怎么学习前端的？
2. 有没有欣赏的企业家？为什么？
3. Vue2 和 Vue3 的区别？
4. 手上有没有 offer？
5. 个人优点、缺点？
6. 在没有他人驱动下自己钻研的事？
7. 了解公司做什么吗？

### 《参考解析》

**Vue2 与 Vue3 的区别：按五个维度答**

这是前端面试的高频题，答全比答深更重要。响应式原理：Vue2 用 `Object.defineProperty` 递归劫持对象属性，新增/删除属性检测不到（要用 `Vue.set`），数组要重写七个方法才能监听；Vue3 用 `Proxy` 代理整个对象，天然支持新增属性、删除、数组索引与 `Map`/`Set`，且是惰性代理（用到才转换），初始化更快。API 组织方式：Vue2 用 Options API 按选项分块（data/methods/computed 分离），逻辑分散；Vue3 提供 Composition API，把同一功能的逻辑聚合在 `setup` 里，可抽成 `composable` 复用，类型推导也更友好。生命周期：Vue3 用 `onMounted` 等组合式函数替代 `beforeCreate`/`created`（`setup` 本身取代了这两个），新增 `onRenderTracked`/`onRenderTriggered` 便于调试。性能与体积：Vue3 的编译器做了静态提升、补丁标记（Patch Flags）与树结构打平，diff 更精准；支持 Tree-shaking，核心运行时更小；Fragment 支持多根节点，`Teleport`、`Suspense` 是新增能力。生态与工程：Vue3 默认 TypeScript 友好（`defineComponent`、泛型支持），`v-model` 支持多个、`v-if` 与 `v-for` 优先级调整（Vue3 里 `v-if` 优先级更高），全局 API 改为 `app.createApp()` 便于多实例隔离与测试。

**「平时怎么学习前端」要答出方法与证据**

不要答「看视频、看博客」，给出一条可验证的链路：信息源（官方文档优先、源码与 RFC、社区讨论）、动手（每学一个概念就写一个最小 demo 复现它的行为）、输出（笔记、组件库、博客、参与开源 issue），并落到一个具体案例上——比如「为了搞清响应式，我用 Proxy 手写了一个 200 行的响应式系统，实现了依赖收集与派发更新」。如果有持续性的证据更好：定期更新的笔记仓库、写给团队用的组件或工具、star 或者被采纳的 PR。这题通常在核实两件事：你的学习是否有自驱、方法是否高效（会不会只停留在教程层面）。

**「有没有欣赏的企业家」怎么答**

这题没有标准答案，考的是你有没有独立判断与表达偏好。可用的结构是「选谁 + 具体欣赏他做的哪一件事 + 对你的影响」：挑一个你真了解的人（技术型、产品型、或者把一家小公司做起来的创始人），说清一个具体决策或长期做法（比如坚持自研、对长期主义的取舍、组织方式的选择），再说它如何影响了你的行为（更愿意做长期积累的事、更重视用户反馈）。避免空洞的形容词、避免说「都很欣赏」，也避免踩在争议性话题上长篇输出——两三句话给出具体理由就够。

**Offer 情况、优缺点、自驱与公司了解**

「手上有没有 offer」如实回答即可，不用隐瞒也不用借它抬价，可以说清自己的时间线与选择标准。「优缺点」按岗位相关性选择：优点给能够被验证的（比如喜欢把问题追到根因、文档写得清楚、接手陌生代码上手快），缺点给一个真实但不致命的、并且带上你在怎么改善（比如「对细节容易钻太深导致节奏慢，现在会先定时限再决定深挖与否」）。「没有他人驱动下自己钻研的事」一定要有具体对象与产出：一个自己做的项目、一个为解决实际问题写的脚本、一次把某个库源码读通的经历。「了解公司做什么吗」要提前做功课，说清主营业务与产品、以及它与你岗位的关系，并顺势问一个更深入的问题（比如「前端在你们产品里主要承担什么，是 C 端页面还是内部工具」），这比背官网介绍有效。
