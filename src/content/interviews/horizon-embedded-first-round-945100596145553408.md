### 《面试题目》

1. Linux 启动过程中，BootLoader（U-Boot）主要负责哪些工作？典型启动流程是什么？U-Boot 如何加载内核和设备树并跳转到内核？
2. 什么是原子操作？它解决了什么问题？Linux 中常见的原子操作有哪些？原子操作适合保护一组复杂操作吗？如果不适合，应该用什么？
3. 在单核 CPU 上，如果当前正在执行低优先级任务，此时高优先级实时任务进入就绪态，CPU 会如何调度？如果当前处于禁止抢占、关中断或不可抢占临界区，会发生什么？
4. Tasklet 执行过程中如果需要访问共享数据，应该如何保证临界区安全？为什么不能简单使用互斥锁？应该使用自旋锁的哪种变体？
5. Linux 中的互斥锁主要解决什么问题？它与自旋锁相比有什么区别？

### 《参考解析》

**U-Boot 的职责与启动流程**：大致分两段。第一阶段（SPL 或上一级 boot）做最底层的初始化——设置异常向量、关中断、初始化时钟与 DDR、把完整的 U-Boot 搬到内存，然后在内存里跑第二阶段。第二阶段初始化串口、网口、MMC/Flash 等外设，读环境变量，按启动顺序（bootcmd）从 eMMC、SD、网络（TFTP）加载内核镜像（Image/zImage）和设备树（dtb）到内存，设置启动参数（bootargs，包含 console、rootfs、cmdline），最后关 MMU/Cache、把 CPU 寄存器按 ARM Linux 的 boot protocol 准备好（x0 传 dtb 地址等），跳转到内核入口。内核起来后再解压、建页表、初始化子系统、挂 rootfs、启动 init。回答时要点出"设备树是给内核描述硬件的，不是给 U-Boot 用的"，这是常见追问。

**原子操作的边界**：原子操作是不可被中断的读-改-写，解决的是多核/中断并发下的简单共享变量竞争，比如引用计数、标志位、统计量。Linux 里常见 `atomic_t`（atomic_inc/dec/read/set）、位操作（`set_bit`/`test_and_set_bit`）、`cmpxchg`、以及 `READ_ONCE`/`WRITE_ONCE` 配内存屏障。它只能保护单个变量的单个操作，**不适合保护一组需要整体一致的操作**（比如"检查队列非空 + 取出元素"这种复合逻辑），因为两条原子指令之间仍可能被插入。复合临界区要用锁：进程上下文用 mutex，中断/原子上下文用 spinlock，读写多写少用 rwlock 或 RCU。

**实时任务抢占**：Linux 的调度器在支持抢占的内核里，会在合适的抢占点（中断返回、系统调用返回、显式 `preempt_enable`）检查 `TIF_NEED_RESCHED`，如果高优先级任务就绪就切过去。但如果当前处在 `preempt_disable` 的临界区、关中断区间、或持有自旋锁，抢占会被推迟到临界区结束——所以实时性差往往不是调度器不认优先级，而是临界区太长或关中断太久。RT 内核用 `PREEMPT_RT` 把大部分自旋锁换成可睡眠的 rtmutex、把中断线程化，进一步缩短不可抢占窗口。这题的关键结论：优先级反转与延迟的根因多在临界区设计，而不是"调度策略选错了"。

**Tasklet 与临界区**：Tasklet 跑在软中断上下文（BH），属于原子上下文，不能睡眠。它可能被硬中断抢占，也可能在多核上与其他 CPU 上的同/不同软中断并发，所以共享数据要用自旋锁保护；而且因为硬中断也可能访问同一份数据，必须用 `spin_lock_bh()`（关本地软中断再拿锁），只关软中断不够防硬中断，只用 `spin_lock()` 又可能被软中断重入。**不能简单用互斥锁**的原因很直接：mutex 拿不到会睡眠，而软中断上下文不允许睡眠，睡了无法被调度回来，会直接死锁或触发 "scheduling while atomic"。同理也不能用可能睡眠的 `kmalloc(GFP_KERNEL)`、`copy_to_user` 等。

**互斥锁与自旋锁**：mutex 解决的是进程上下文里"临界区可能较长、允许睡眠"的互斥，拿不到锁时把当前任务挂到等待队列并让出 CPU，适合保护会做 IO 或可能阻塞的资源。spinlock 是忙等，临界区必须极短且绝不能睡眠，用在中断上下文和多核短临界区。区别可以按四点答：是否能睡眠（mutex 能、spinlock 不能）、适用上下文（mutex 只能进程上下文，spinlock 可用于中断）、开销（mutex 有上下文切换成本，spinlock 空转烧 CPU）、以及是否可递归（两者默认都不可递归，Linux 的 mutex 也不支持递归）。另外要提一句：单核非抢占内核里 spinlock 退化成关抢占，所以"自旋"的语义依赖 SMP 与抢占配置；实际选型先看上下文能不能睡，再看临界区长短。
