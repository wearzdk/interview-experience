### 《参考解析》

**source 透传的作用与不丢失保证**：source 是流量来源标识，贯穿「投放 → 分发 → 落地页 → 注册 / 下载」整条链路，用于归因与后续的渠道分析。要保证不丢失，关键在每一跳都要显式携带：跳转链接生成时拼参数、跨域跳转用白名单参数透传、应用内路由切换把参数写进路由 state 或全局 store 而不是只留在 URL、中间页与登录回调要回带原参数、短链展开与重定向里保留 query。校验手段是埋点上带 source 字段并在端到端链路上做一次抓包 / 日志核对，定期比对「投放侧点击数」与「落地页曝光数」的差值。

**新旧埋点数据一致性**：先对齐口径（同一行为的触发时机、去重规则、用户标识、时间窗），再用双写期做比对——同一批流量同时上报新旧两套，按 session 与事件名做 join，比对事件条数、用户去重数、关键属性分布；数据结构不同时写一层映射（新结构字段 → 老结构字段），把差异记录成映射表并做单测；灰度期间设阈值告警（差异超过 1% 阻断切换），全量后保留一段双写用于回查。

**幻觉与上下文丢失**：幻觉的根因是模型在信息不足时仍然生成，解法是检索侧保证召回质量（混合检索 + rerank + 相关性阈值）、生成侧要求引用来源并允许「不知道」、输出侧做事实校验（对照检索片段逐条核验）；上下文丢失多发生在长对话截断、多轮压缩、多 Agent 交接处，解法是把关键事实外置成结构化状态（用户画像、已确认约束、任务清单）而不是依赖对话历史，压缩时保留实体与决策、丢弃寒暄与重复内容，并在交接时传显式摘要。

**RAG 处理长文档与交叉论证**：提前入库的文档走离线管道——解析（表格与扫描件单独处理）、按结构分块（标题层级 + 语义边界 + 重叠窗口）、建索引（向量 + 关键词 + 元数据）。单次请求传入的超长文本无法走同一套索引，做法是「临时索引」：先对传入文本做分块与打分（BM25 或轻量向量化），再与已有知识库的召回结果合并做 rerank，只把最相关的片段拼进上下文；同时用 query 改写把用户问题拆成子问题分别检索，控制总 token。只拿摘要检索的问题在于摘要会丢掉具体数字、条件与例外，而这些恰恰是需要交叉论证的部分——正确做法是「摘要用于导航、原文片段用于作答」。

**超长文本的架构约束**：输入长度上限（拒绝或分段处理）、分块与并发解析的时长控制（超时与降级）、单次调用的 token 预算与截断策略、引用来源必须可回指到原文位置（页码 / 段落号）、敏感内容过滤、成本配额（按用户与租户限流）、失败重试与幂等、以及在提示词里明确「只依据给定材料作答」。

**CSS 居中与旋转**：不定宽高的居中——flex（`display:flex; align-items:center; justify-content:center`）最直接；grid（`place-items:center`）等价；绝对定位配 `top:50%; left:50%; transform:translate(-50%,-50%)`；或 `inset:0; margin:auto` 配合固定尺寸。旋转用 `transition: transform .2s` + `:hover { transform: rotate(90deg) }`，注意 `transform-origin` 默认是中心、内联元素要先 `display:inline-block`。

**Vue watch 监听不到数组内部对象新增 key**：Vue 2 用 `Object.defineProperty` 做响应式，无法拦截新增属性，所以给对象加新 key 不会触发更新（数组索引赋值与 `length` 修改同理）；解决方式是 `Vue.set` / `this.$set` 新增属性、或用整体替换（`arr[i] = {...arr[i], newKey: v}`）、或改用 `watch` 的 `deep: true` 加手动 `$forceUpdate`（不推荐）。Vue 3 用 Proxy 可以拦截新增属性，但 `watch` 默认仍然是浅层的——监听一个 reactive 对象时只有整体替换才触发，要深层需要 `deep: true`；监听 `ref` 对象则要注意 `.value` 的替换与内部修改的区别。

**URL 参数注入 XSS**：风险点是「把 URL 里的内容当 HTML 插入页面」——例如把参数拼进 `innerHTML`、`document.write`、`location.href`、`<a href>`、`<iframe src>`、`<img src>`（`javascript:` 伪协议）、`<style>` 的 `url()`。防护的核心是输出编码与上下文匹配（HTML 用实体编码、属性用引号包裹并转义、JS 里用 JSON 序列化、URL 用 `encodeURIComponent`），再加 CSP 阻断内联脚本，尽量避免 `innerHTML` / `eval` / `v-html`。`on` 类事件属性（如 `onerror`、`onclick`）的风险在于它们本身就是可执行代码，只要标签被插进 DOM 且带这类属性，浏览器就会执行——所以白名单化标签与属性比黑名单过滤可靠。

**自定义字体在 Webpack 的配置**：`webpack 5` 用 `asset/resource` 规则处理 `woff|woff2|ttf|eot`：`{ test: /\.(woff2?|ttf|eot|otf)$/i, type: 'asset/resource', generator: { filename: 'fonts/[name].[hash:8][ext]' } }`；老版本用 `file-loader`。字体文件大、加载阻塞文本渲染，实践上要 `font-display: swap`、只做子集化（`fontmin` / `subset-font`）、预加载关键字体（`<link rel="preload" as="font" crossorigin>`）。

**数组拍平（指定层级）**：递归版本在递归时把深度减一，深度为 0 就返回原数组；迭代版本用栈存 `{ item, depth }`，遇到数组且 `depth > 0` 就展开入栈，否则直接 push 结果。要处理 `reduce` 与 `concat` 的写法与稀疏数组、`Symbol.iterator` 的边界。

**并发请求队列控制器**：维护一个运行中的集合与一个等待队列，`add(task)` 返回 Promise；调度函数在 `running < limit` 时取出任务执行，`finally` 里删除并再次调度；要保证任务失败不阻塞队列（错误沿着它自己的 Promise 抛出），全部完成时 resolve。加分项是支持取消（AbortController）与优先级插队。

**从 URL 取参数**：`new URL(location.href).searchParams.get('fr')` 是最稳的写法（能处理编码、重复参数与 hash 路由）；hash 路由要用 `new URLSearchParams(location.hash.split('?')[1])`；手写正则时注意 `?`、`&`、`=`、`#` 与 URL 编码，且要做 `decodeURIComponent` 的 try/catch（非法编码会抛异常）。
