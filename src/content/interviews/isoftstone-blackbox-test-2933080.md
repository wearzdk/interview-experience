3. 你觉得 HTTP 和 HTTPS 有什么区别？

**数据库、Linux 与岗位**

6. SQL 你会吗？你用的什么工具连接数据库？

### 《参考解析》

**一条好用例的要素，答全比答多重要**：编号与所属模块、用例标题（一句话说清验证什么）、优先级、前置条件（账号、数据、环境、权限）、操作步骤、预期结果、测试数据、以及是否自动化。真正拉开差距的是两个细节：一条用例只验证一个点，出问题能立刻定位；预期结果要可判定，写「页面提示手机号格式不正确」而不是「提示正确」。能补一句用例的维护方式（需求变更时谁改、废弃怎么标记）就更完整。

**覆盖率不是把用例写多，而是让需求与用例能对账**：先建需求追踪矩阵，每个需求点至少挂一条用例，反向也能查到每条用例对应哪个需求，缺口一眼可见；设计时按方法补齐场景——等价类与边界值管输入域、判定表管条件组合、场景法管主流程与异常分支、正交试验压组合爆炸；再叠一层接口与代码覆盖率（JaCoCo 看行与分支、接口用例看路径覆盖）作为客观下限。最后一定要承认黑盒无法证明 100%，说明剩下的风险靠探索式测试和线上监控兜，这比硬答「能到 100%」可信。

**HTTPS 抓包的本质是中间人**：Fiddler 在本机起一个代理，客户端连它时它出示自己签的证书，再用真实证书去连服务端，两边各建一条 TLS，明文就落在中间。所以配置分三步：客户端把 Fiddler 的根证书装进受信任列表、Fiddler 打开 HTTPS 解密并勾选忽略服务端证书错误、客户端代理指向 Fiddler 端口。手机端最容易翻车：Android 7 以后应用默认不信任用户证书，需要改 network security config、装系统证书（要有 root）或用改包方式；再碰上证书固定（SSL Pinning）就得靠 Hook 或调试包。

**HTTP 与 HTTPS 的区别要落到工程后果**：HTTP 明文传输，中间任何一跳都能看能改；HTTPS 在 TCP 与 HTTP 之间加了 TLS，提供加密、完整性校验与身份认证，代价是握手往返和加解密开销，靠会话复用、TLS 1.3 的 1-RTT/0-RTT、证书与 CDN 卸载来摊平。测试视角要补一句：抓包、代理、 mock 在 HTTPS 下都要处理证书，这是日常最直接的差别。

**内连接与外连接：结果集形状不同**：内连接只保留两边都匹配的行；左/右外连接保留一侧全部行，另一侧没匹配上就补 NULL；全外连接两边都保留。实际写 SQL 时更常见的坑是把过滤条件写错位置——放在 WHERE 里会把外连接退化成内连接，要放在 ON 里才保留主表全量。连库工具答 Navicat、DataGrip、DBeaver、命令行 mysql 都行，说清哪个用得最熟。

**Linux 指令的使用场景要具体**：查日志（tail -f、grep、sed 截时间段）、看服务状态与端口（ps、netstat/ss、systemctl）、看资源（top、free、df、iostat）、定位文件与磁盘（find、du）、部署与起停脚本（nohup、kill）。说场景时最好带一次真实排查：接口 502 时先看端口在不在、再看日志有没有异常堆栈。

**「这个项目是不是之前面过」是个信号**：外包型公司同一项目会由不同团队反复招人，撞上重复面说明岗位在人力池里滚。被问到时如实说面过哪一轮、结果如何即可，同时问清这次的团队、驻场地点和客户，避免两次面的是同一个坑。
