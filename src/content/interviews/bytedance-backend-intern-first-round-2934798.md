### 《面试题目》

1. 从你的项目里挑一个精妙的设计来讲讲。
2. 你的 RAG 用了什么算法？（向量算法、向量召回）
3. 知识问答系统调用 LLM 时有哪些参数？输入输出分别大概有什么？
4. 给定一个整数和一个数组，输出用数组中的数字组成的、小于给定整数的最大数。
5. 给定一个数组，求出最小子数组和。
6. Redis 写超容量后会怎么样？
7. Redis 的淘汰机制是什么？
8. Redis 的持久化机制是什么？

### 《参考解析》

**「精妙的设计」要讲取舍，不要讲功能**：挑一个有约束条件的决策——为什么这样分片、为什么用这个数据结构、为什么把某段逻辑异步化，说清「当时的约束（数据量、延迟、成本）→ 备选方案 → 为什么选它 → 结果指标」。面试官不关心你做了多少功能，关心你能不能解释清楚设计背后的判断。

**RAG 的检索方案要能报出具体参数**：向量模型是什么、向量维度、切分策略（按标题层级还是固定长度、重叠多少）、索引类型（HNSW 的 M 与 efConstruction）、召回 top-k、有没有加关键词检索做混合、rerank 用什么。答「用了向量召回」等于没答，报出参数并说明为什么这么设才有信息量。

**调用 LLM 的参数与输入输出**：参数包括 model、messages（system/user/assistant）、temperature、top_p、max_tokens、stop、stream、以及工具相关的 tools 与 tool_choice；输入是消息数组（可能带图片或多模态内容），输出是 choices 里的 message（content 或 tool_calls）加 usage（prompt/completion tokens）。工程上要额外关注超时、重试、限流、以及流式下 usage 需要显式开启。

**算法一：用数组数字组成小于给定整数的最大数**。思路是构造长度为 k 的最大数并让它严格小于目标：可以用回溯/DFS 逐位构造，每位从 9 到 0 尝试，记录是否已经比目标前缀小（tight 标记），一旦小于前缀后续位可以全填最大数字；也可以从右往左找第一个可以减小的位置，把它减一（若该位已在数组里），右侧全部填数组最大值。边界要处理：结果不能有前导零（除非结果就是 0）、长度不足时可以补前导零但要去掉、无解返回空。

**算法二：最小子数组和**。如果允许空子数组，答案是 0（这也是很多题目的隐含约定，作答前要问清）。如果要求非空，就是经典的最大子段和取负：维护「以当前元素结尾的最小和」`cur = min(a[i], cur + a[i])`，全局取最小，O(n) 时间 O(1) 空间。如果题目其实是最小「长度」子数组达到某目标和，那就是滑动窗口/前缀和 + 单调队列，别混。

**Redis 写超容量**：受 `maxmemory` 约束，写入导致内存超限时按 `maxmemory-policy` 处理——`noeviction` 直接对写命令返回 OOM 错误（读仍可用），其他策略会先淘汰键再写入；如果淘汰后仍不够，同样报错。要注意主从与持久化场景下，从库的 maxmemory 检查行为、以及淘汰会触发 DEL 传播。

**淘汰策略分两大类**：只淘汰设置了过期时间的键（volatile-lru、volatile-lfu、volatile-random、volatile-ttl），和淘汰所有键（allkeys-lru、allkeys-lfu、allkeys-random）。LRU 在 Redis 里是近似实现（采样若干个键挑最久未用的），LFU 按访问频率并有衰减；选择依据是「缓存是不是可以全丢」——纯缓存用 allkeys-lru/lfu，Redis 里同时存了不能丢的数据就必须用 volatile 系列并且不能和持久化数据混部。

**持久化两种**：RDB 是某一时刻的全量快照（fork 子进程写，copy-on-write），文件小、恢复快，但会丢最后一次快照之后的写；AOF 追加写命令，`appendfsync` 有 always（每次刷盘，最安全最慢）、everysec（每秒，最多丢约 1 秒）、no（交给操作系统）。生产上常见组合是 RDB + AOF 混合（4.0 起的混合持久化），并从库做持久化、主库专注服务。
