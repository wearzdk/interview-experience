### 《面试题目》

1. 常考题型：字符串处理、数组操作、树遍历，以及动态规划、模型基础这类混合考点
2. 心法一：读题先圈关键词，把边界条件写在纸上
3. 心法二：刷题要按类吃透，别只凑数量
4. 心法三：拿到题先搭骨架，用伪代码理清思路
5. 心法四：环境不熟时，先写最简可运行版本
6. 心法五：调试先打印关键变量，别凭感觉改错
7. 心法六：模板提前备好，代码规范别丢分

### 《参考解析》

1. **边界条件有一份固定清单，照着核对就不用靠记性**：空输入与长度为 0、单元素、全部元素相同、已有序或完全逆序、含重复元素、负数与零、整型溢出（累加与乘法先想 long）、字符串的大小写与多字节、树只有一条链（递归深度会不会爆栈）。笔试里返工的最大成本不是想不出解法，而是写完一半发现漏了特殊情况推倒重来——把这些写在草稿纸上，每写完一个模块回头核一遍，是最省时间的习惯。

2. **「按类吃透」的正确姿势是固定四问**：拿动态规划说，每道题都问：状态定义是什么（`dp[i]` 或者 `dp[i][j]` 到底表示什么）、转移方程怎么写、初始化和遍历顺序怎么定、能不能做空间压缩。背包类连着做五道变式，比随机刷五十道更容易形成迁移。二叉树同理：递归、迭代（显式栈）、层序（队列）三种写法各手写一遍，顺便比较时间空间开销，面试官追问「不用递归怎么做」时才接得住。

3. **伪代码骨架是限时环境里最值钱的一步**：拿到题先用中文或简写把流程写进注释——判断空输入、构建哈希表、遍历、返回；把主要步骤和分支标出来，再逐段填成可运行代码。好处有两个：不至于写着写着忘了下一步；逻辑漏洞在骨架阶段就能看出来。写完骨架先写一个「最小可运行」版本确认输入输出框架通了（哪怕函数先返回空值），再填核心算法，避免在环境差异上浪费限时。

4. **调试要定位到「是数据错还是逻辑错」**：跑不通时盯着代码反复改条件判断，往往越改越乱。正确做法是在关键节点打印：循环开始前的数组长度、递归的入参、哈希表的键集合、中间变量的取值。先确认输入是不是你以为的那样，再看中间态有没有破坏不变量——多数 bug 都是数据形状或边界假设错了。平台支持断点就用断点，但打印最稳，不受环境限制。

5. **模板要能脱稿写出结构，规范是白送的加分**：常备的几类是快排（含随机基准或三路分区）、并查集（路径压缩 + 按秩合并）、LRU 缓存（哈希 + 双向链表）、BFS 与 DFS 框架、二分的边界写法。模板不必逐字默写，但要记住结构和易错点（边界开闭、更新顺序、死循环条件）。变量命名清楚、注释写在关键分支、缩进一致，会给阅卷人省力——AI 岗的笔试有时会额外看代码可读性，尤其是数据处理与模型调用部分，规范比炫技更稳妥。

6. **时间分配按「稳拿 / 搏一搏 / 放弃」三档**：AI 岗笔试的胜负往往不在压轴题会不会，而在基础题能不能一次写对。开考先花两三分钟扫一遍题目分档，把稳拿的先做完并检查边界，再回头攻需要推导的；实在卡住的题先写暴力解法拿部分分，别让一道题吃掉全部时间。刷题量带来的安全感，替代不了这种临场分配。
