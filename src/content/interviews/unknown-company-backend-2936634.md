### 《面试题目》

1. 请你大致做个自我介绍。
2. 为什么第一段实习时间只有两三个月？
3. 你的实习项目里数字人这块能具体展开讲讲吗？什么背景下的项目？
4. 请你大概介绍一下自己项目经历中的项目。
5. 代码审核工作流是怎么搭建的？
6. 安全和规范是怎么检测的？
7. 能否给一下 GitHub 的链接看一下？
8. 身边最近常用的 AI 工具、模型是什么？
9. 怎么看待最新的 AI？
10. 你最近的代码是怎么写的，手写还是用 AI，比例大概多少？
11. 能提前来实习吗？一周几天？

### 《参考解析》

**这场面试的信号很明确：不考八股，考「你真的做过什么」和「你怎么用工具」。** 这类中小厂的面试官通常就是未来的直属上级，问项目的目的是判断你能不能立刻上手、有没有独立把一个东西从零做到能用的经历。准备重点 therefore 不是背题，而是把两三个项目讲成「背景—目标—你的动作—结果—复盘」的完整故事，并且准备好被追问细节到实现层面。

**「实习只有两三个月」这类问题不是挑刺，是在确认稳定性和离职原因。** 回答要正面给原因（学业安排、项目周期结束、方向不匹配），不要贬低前东家，也不要含糊其辞。更好的答法是把它转成收获：「时间不长，但我独立负责了 X，交付了 Y，这段经历让我确定了要做这个方向」。如果确实是被裁或团队调整，如实说、一句话带过，然后把话题拉回自己做成的事。

**数字人项目要按「技术链路」讲，而不是按「我做了什么功能」讲。** 一条完整的数字人链路通常包含：形象资产（建模或 2D 驱动）、语音合成（TTS，注意音色与韵律）、口型对齐（viseme 或音频驱动的 lip sync）、表情与动作驱动、渲染与推流、以及实时交互的对话编排（ASR → LLM → TTS）。要讲清你负责哪一段、用了什么方案（自研还是接的开源/商用 SDK）、遇到的坑（比如音画不同步、延迟高、口型对不上中文音素）、怎么量化效果（首字延迟、端到端延迟、口型准确率）。

**代码审核工作流的搭建，答「触发—检查—门禁—反馈」四段。** 触发是 PR/MR 事件 webhook；检查项通常包括格式化与 lint、静态分析（类型检查、空指针、越界）、单测与覆盖率、依赖漏洞扫描（SCA）、密钥泄露扫描、以及人工 review 规则（必须几人 approve、必须解决所有 comment）；门禁是把这些检查设为合并前必须通过；反馈是把结果以评论或检查项的形式贴回 PR，失败时给出可操作的修复建议。再补一句「分级：主干严格、实验分支宽松，避免门禁太严导致大家绕过」，会显得你真配过而不是只会开开关。

**「安全和规范怎么检测」要区分确定性的规则与需要语义判断的部分。** 确定性的事交给工具：SAST 扫注入、反序列化、路径穿越；SCA 扫依赖 CVE；secret scanning 扫 AK/SK 与私钥；license 合规扫描；镜像扫描。语义类的事（这段逻辑有没有并发问题、这个接口有没有越权）目前更多靠 AI 辅助 review 加人工复核，AI 负责给候选问题、人负责判定，避免误报把人练成「无脑点忽略」。要能说出误报率和漏报率这两个指标，以及怎么用历史 bug 回归验证规则有效性。

**「给 GitHub 链接」是这场面试的实际考察点，要提前准备好。** 面试官会点进去看 commit 频率、commit message 质量、README 是否写清怎么跑、有没有测试、issue/PR 流程是否规范。如果主力项目是公司代码不能公开，就准备一个能公开的替代品：一个自己写的小工具、一个开源贡献记录、或者一份脱敏后的架构文档 + 代码片段。空仓库比没有仓库更糟。

**AI 工具与「手写还是 AI 写」的比例，回答要体现判断力而不是立场。** 合理的答法是把任务分类：样板代码、测试、文档、正则与脚本可以大量交给 AI；涉及核心业务逻辑、并发与事务、安全边界、线上热点的代码自己写或至少逐行审。比例给一个真实区间（比如日常 60-70% 由 AI 起草、自己重写与审查），并说清你怎么验证 AI 产出：跑测试、看 diff、构造边界用例。被问「怎么看待最新 AI」时，落到对自己工作方式的具体改变（学会了怎么描述需求、怎么拆任务、怎么审查），比空谈「AI 是工具」更有信息量。

**最后关于实习时间的问题要提前想清楚。** 一周能到几天、能不能全职、最早什么时候入职，给确定的答案；如果还在等其他 offer，不要明说「我在等」，可以说「我这边可以按贵司的时间安排入职」。这类岗位很多是「实习转正」，态度上的确定性本身就是加分项。
