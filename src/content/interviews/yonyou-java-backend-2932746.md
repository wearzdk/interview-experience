### 《参考解析》

**HashMap 的 put 流程**是这组题里最容易被追到细节的一道。先对 key 的 `hashCode` 做扰动（`h ^ (h >>> 16)`，让高位参与寻址），再用 `(n-1) & hash` 定位桶；桶空直接放入，桶里是链表就尾插并逐个 `equals`，命中则覆盖 value；链表到 8 且数组长度 ≥ 64 才转红黑树（不到 64 先扩容）；插入后 `size` 超过 `capacity * 0.75` 就扩容为两倍，1.8 用高低位拆分重新分布，不再逐个重算 hash。追问一般接三个：容量为什么是 2 的幂（位运算等价取模且更快）、负载因子为什么 0.75（空间与冲突的折中）、1.8 为什么改尾插（1.7 头插在并发扩容时会成环）。

**SpringBean 生命周期**按序说：实例化 → 属性填充 → `Aware` 回调 → `BeanPostProcessor` 前置 → `@PostConstruct` / `afterPropertiesSet` / `init-method` → 后置（AOP 代理多在这一步生成）→ 使用 → 销毁回调。实例化方式有构造器、静态工厂、实例工厂、`FactoryBean`，注解时代再加 `@Bean`。被追问循环依赖就答三级缓存，正好顺着这条链推出来。

**重载与重写**：重载在编译期按静态类型定（参数不同，返回值不同不算重载），重写在运行期按实际类型动态分派（签名相同、权限不能更严、异常不能更宽）。`==` 比值或引用地址，`equals` 默认也是地址比较，被 `String`、包装类重写成内容比较——自定义类重写 `equals` 必须同时重写 `hashCode`，否则放进 `HashMap` 会找不到。

**集合要能画出一张图**：`List` 有序可重复，`ArrayList` 查快、`LinkedList` 增删快但实际很少用；`Set` 不可重复，`HashSet` 靠哈希、`TreeSet` 有序、`LinkedHashSet` 保插入序；`Map` 独立一支，`HashMap` 无序、`LinkedHashMap` 保插入序或访问序（可做 LRU）、`TreeMap` 按 key 排序、`ConcurrentHashMap` 线程安全。被问「HashMap 有序吗」就答无序，顺势带出后两者的差别。

**抽象类与接口**：抽象类表达 is-a、可有状态和构造器、单继承；接口表达 can-do、可多实现、1.8 后有 default 方法但仍无实例字段。**IOC** 别只背「控制反转」，要说清它解决什么：依赖由容器启动时装配，换实现只改配置、单测能注入 mock、生命周期统一管理；DI 是实现手段，AOP 建在它之上。

**SQL 优化**答执行计划优先：`explain` 看 type/key/rows/Extra，避免 `select *`、避免索引列上做函数或隐式转换、联合索引守最左前缀、注意回表与覆盖索引、深分页用游标或延迟关联。补一句「先看慢日志定位再谈改写」会显得有实战感。

**最后两道题和反问才是信息量所在**。面试官主动承认岗位是运维 + SQL + 低代码，说明 JD 写 Java 开发、实际是实施/运维型岗位。碰到这种落差，反问就该问清：代码自研比例、有没有独立后端团队、低代码是配置还是写插件。作者面了四家分公司才确认这点——同名的「Java 开发」在不同分公司可能完全不是一份工作。
