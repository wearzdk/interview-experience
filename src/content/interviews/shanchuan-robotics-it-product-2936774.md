### 《参考解析》

**TimescaleDB 的选型**：它是基于 PostgreSQL 的时序扩展，把大表按时间切成 chunk，提供 hypertable、连续聚合与压缩。选它的理由通常是：团队已经熟悉 SQL 与 Postgres 生态，需要时序写入能力又不想引入独立的时序数据库；数据要能和业务表 join；需要保留原始数据做回溯。对比 InfluxDB 是专用时序库、写入与聚合更强但 SQL 生态弱、与业务数据关联麻烦；对比 ClickHouse 分析性能强但不适合高频单条写入与事务更新。回答时要说明你评估过的维度：写入吞吐、查询模式（按时间范围聚合还是按设备点查）、保留策略、运维成本、团队熟悉度。

**50ms 入库与崩溃丢数据**：如果实现是「内存缓冲 50ms 批量落库」，那么进程崩溃会丢这 50ms 的数据。要能说清取舍：这类采集数据通常允许少量丢失，所以用批量换吞吐是合理的；如果业务不允许丢，就要在采集端做本地持久化（写 WAL 或本地队列），落库成功后再确认，重启后重放。另一个方向是降采样：原始点全量写入成本高，可以按秒或分钟聚合后存长期，原始数据只保留短周期。面试官追问这点是看你有没有想过可靠性边界，答「接受丢失但要记录丢失量并监控」也是一种负责的回答。

**线程池拒绝策略**：四种内置策略——AbortPolicy 抛异常（默认，让调用方感知）、CallerRunsPolicy 由提交线程自己执行（形成反压，适合不能丢的任务）、DiscardPolicy 静默丢弃、DiscardOldestPolicy 丢最老的腾位置。选择依据是任务能否丢、能否延迟、调用方能否承受阻塞。生产上通常自定义：记录丢弃并打点，或写入重试队列。

**十倍流量怎么办**：先判断瓶颈在哪，不能只调线程数。步骤是：确认任务是 CPU 密集还是 IO 密集（IO 密集才能靠加线程提升，CPU 密集加线程只会加剧上下文切换）；把队列从无界改成有界，避免内存被撑爆；做背压与限流，把超出处理能力的请求挡在入口；把可异步的任务拆出去走消息队列削峰；做降级（非核心功能先关）；水平扩容实例而不是无限加线程。回答里要出现「有界队列 + 背压 + 削峰 + 降级」这几个关键词，并说明监控什么指标（队列长度、拒绝数、处理耗时）。

**CAS 与 ABA**：CAS 比较并交换，是无锁编程的基础，靠 CPU 的原子指令实现。ABA 问题是一个值从 A 改成 B 又改回 A，CAS 检查时认为没变过，从而误判。解决办法是加版本号（AtomicStampedReference）或加时间戳，比较时同时比较版本。Java 里也可以用 AtomicMarkableReference 只关心是否被改过。

**ConcurrentHashMap**：JDK 8 取消了分段锁，改为 Node 数组加链表加红黑树：写入空桶用 CAS，桶内有冲突时用 synchronized 锁住桶的头节点，锁粒度细化到一个桶；链表长度超过 8 且容量达到 64 时转红黑树；扩容支持多线程协同迁移，用 ForwardingNode 标记已迁移的桶；size 统计用 baseCount 加 CounterCell 分散热点。要能解释为什么读操作基本无锁：Node 的 val 与 next 用 volatile 保证可见性。

**InnoDB 为什么用 B+ 树**：磁盘按页读取，索引结构要尽量减少 IO 次数。B+ 树矮胖，非叶节点只存键不存数据，一个 16KB 页能放几百个键，三层即可覆盖千万级数据；叶子节点用双向链表连接，范围查询与排序只需顺序扫描；所有查询都走到叶子，路径长度一致，性能稳定。对比 B 树每个节点都存数据、单页键少、树更高；对比哈希索引只支持等值查询、不支持范围与排序；对比跳表内存友好但磁盘随机 IO 多。

**聚簇索引与二级索引**：聚簇索引的叶子节点存整行数据，一张表只有一个，通常是主键；没有主键时选唯一非空索引，再没有就生成隐藏的 row_id。二级索引的叶子存索引列加主键值，查非索引列要回表（先查二级索引拿主键，再回聚簇索引取整行）。覆盖索引是指查询的列都在二级索引里，可以避免回表。

**索引下推**：MySQL 5.6 引入，把 where 中能用索引列判断的条件下推到存储引擎层，在回表之前就过滤掉不匹配的记录，减少回表次数。例如联合索引 (a,b)，查询 `a = 1 and b like 'x%'`，没有 ICP 时要先按 a 回表再在 server 层过滤 b，有 ICP 时直接在索引上判断 b。

**主键不宜随机**：InnoDB 按主键顺序组织数据，随机主键（如 UUID）会导致插入位置分散，频繁页分裂与碎片，写放大明显；顺序主键（自增）总是追加到最右页，写入局部性好、缓存命中高。分布式场景需要全局唯一时，可以用雪花号这类「时间有序 + 机器位」的方案，兼顾唯一与顺序。

**前缀索引**：对长字符串列只索引前 N 个字符，能显著减小索引体积、提升写入与缓存效率。缺点是区分度下降，可能扫到更多候选行再回表过滤；也无法用于覆盖索引与排序。选择 N 的方法是统计前缀的选择性，取到接近全列区分度的最小长度。
