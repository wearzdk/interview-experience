### 《面试题目》

1. 自我介绍。
2. 产品介绍：一键开发游戏 Mod 的产品，你会怎么理解它？
3. 关于不同的 Skill（一类是固定输入输出，另一类是不稳定输入输出），你会怎么测试？
4. 产品第一阶段与用户交互的目的是让用户挑选模板和方案，再交给编码 Agent 编码，主要四个阶段：需求澄清、模板挑选、供用户审核、调用下游 Agent。这样一个长流程，你会怎么测试？
5. Web 自动化怎么做？Codex 的 computer use 你怎么使用？
6. 关于 computer use 你有优化方案吗？
7. OpenCV 的自动化与 computer use 的自动化差异是什么？你的选择以及为什么？
8. 测试用例生成的 Agent 你是怎么设计的？
9. 反问。

### 《参考解析》

**两类 Skill 的测试**：固定输入输出的 Skill 可以按契约测——参数校验（必填、类型、边界、非法值）、返回值结构与取值、错误码、幂等与超时，用表驱动覆盖；不稳定输入输出的（依赖模型或外部服务）不能逐字比对，改为断言可判定的性质：结构合法性、关键字段存在与范围、语义正确性（用规则或评审模型打分）、多次运行的一致性分布，并统计失败率而不是单次成败。

**长流程的测试**：四阶段是一条有状态的链路，测试重点是状态迁移与异常分支。做法：为每个阶段定义输入、输出与验收条件；构造主流程用例（正常走完）、分支用例（用户改需求、换模板、驳回）、异常用例（下游 Agent 超时、返回不合规、用户中途退出）；用可重放的会话记录做回归；对跨阶段的上下文传递单独验证（需求澄清的结果是否真的进了编码阶段的提示）。

**Web 自动化与 computer use**：Web 自动化走 DOM 层——Playwright/Selenium 定位元素、等待条件、断言页面状态，稳定、快、可并行，但只适用于自己能控制的页面。computer use 是看截图、移动鼠标键盘，能操作任意界面（包括桌面应用与第三方站点），代价是慢、贵、易受分辨率与遮挡影响。优化方向：缩小操作区域、缓存稳定的界面坐标、用可访问性树辅助定位、把确定性步骤换回 DOM/接口调用、失败时重试并保存截图。

**OpenCV 与 computer use 的选型**：OpenCV 模板匹配/特征识别适合界面稳定、元素外观固定的场景，毫秒级、离线、成本低，但界面一改就失效，且无法理解语义；computer use 由模型理解界面语义，适应变化，但对模糊控件容易点错。工程上常组合：用 OpenCV 做快速定位与校验，模型只在需要理解与决策时介入。

**测试用例生成 Agent**：输入是需求文档与接口/页面信息，输出是结构化的用例（前置条件、步骤、预期）。设计要点：先做需求解析抽取功能点与约束，再按测试类型（正向、边界、异常、权限）生成模板化用例，最后用规则校验格式与覆盖度、用历史缺陷库补充场景。生成结果必须人工评审后入库，避免把模型臆想的场景当成需求。
