### 《面试题目》

1. 介绍一下实习的需求，这部分会问得比较细。
2. 怎么保障 AI 生成的代码是正确的？
3. 虚拟地址和物理地址的区别是什么？
4. 进程之间可以有一样的虚拟地址吗？
5. IP 地址是怎么寻址的？
6. TCP 的可靠性靠什么保障？
7. 反问环节。

### 《参考解析》

**「怎么保障 AI 代码是正确」这题，答「验证手段分层」而不是「我会仔细看」。** 可用的层次从便宜到贵：静态层——类型检查、lint、编译期告警，把低级错误挡在提交前；测试层——先让模型按现有风格补单测，人再审查断言是否真的在验行为（很多 AI 写的测试是同义反复）；契约层——接口 schema、错误码与边界用例（空值、超长、并发）显式列出来；运行层——灰度、feature flag、可观测指标，让问题在小流量里暴露。真正关键的是「AI 改动必须可回滚、可归因」：一个小 PR 只做一件事，commit 信息说清意图，出问题能一键回退。面试官追问时最好举一个真实例子：比如模型给了一个看似正确的 SQL 优化，但在 `NULL` 排序上与 MySQL 方言不一致，是靠回归用例发现的。

**虚拟地址与物理地址，要讲到「MMU + 页表 + 缺页」这条链。** 虚拟地址是进程看到的地址空间，每个进程独立；物理地址是内存条上的实际位置，由 MMU 通过多级页表把虚拟页映射到物理页帧，页表项里有权限位（读写/执行/用户态）和 present 位。访问未映射的页会触发缺页异常，内核决定是分配新页（匿名页）、从磁盘换入（文件页），还是报段错误。因为映射是进程私有的，**不同进程完全可以拥有相同的虚拟地址**，它们指向不同物理页——这正是进程隔离的基础；相反，同一块物理内存也可以被多个进程用不同虚拟地址映射（共享内存）。加分点：`fork` 之后父子进程的虚拟地址相同但物理页靠写时复制共享。

**IP 寻址要分清「路由寻址」和「ARP 解析」两件事。** 发送方先用自己的子网掩码判断目的 IP 是否同网段：同网段就用 ARP 广播问「这个 IP 对应的 MAC 是谁」，拿到 MAC 后直接二层封装发送；不同网段则查路由表找到下一跳网关，把包发给网关的 MAC，由路由器逐跳转发，每经过一跳 TTL 减一，直到目的网络。过程中还涉及 NAT（私网地址转换）、分片（MTU 超限时按 MTU 切分并在目的地重组）。答到「同网段走 ARP、跨网段走网关 + 逐跳路由表」这层，基本就完整了。

**TCP 可靠性是一组机制的合集，别只答「三次握手」。** 核心是：序号与确认（累积确认，接收方告诉发送方「我期待的下一个字节」）、超时重传（RTO 基于 RTT 动态估算）、快速重传（收到三个重复 ACK 立刻重发，不等超时）、滑动窗口做流量控制（接收方通过窗口字段告诉发送方还能收多少，避免压垮接收端）、拥塞控制（慢启动、拥塞避免、快恢复，避免压垮网络）、以及校验和丢弃损坏报文。面试官常追问「UDP 想可靠怎么办」——那就要在应用层自己实现序号、确认、重传与窗口，QUIC 就是这么做的。
