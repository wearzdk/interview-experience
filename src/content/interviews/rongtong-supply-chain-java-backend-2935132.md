### 《参考解析》

**这场面试的形态是「一个 AI 项目吃满全场」，Java 只是配菜。** 原帖的判断很准：团队想要一个「会 Java 又会 Agent」的人。所以准备这类岗位时，RAG 项目必须能讲到实现细节——数据从哪来、怎么切、怎么召回、怎么排、怎么评、怎么部署，任何一环只答概念都会被打回。

**知识与向量来源要分层说清。** 第一层是原始语料：内部文档（制度、产品手册、工单、合同）、网页、以及 PPT/Word/PDF 这类办公文件，来源决定了权限与更新频率。第二层是加工：解析 → 清洗（去页眉页脚、去水印、纠正 OCR 错字）→ 结构化（标题层级、表格、图片说明）→ 分块（按语义或标题切，块与块之间保留父子关系做「小块检索、大块喂模型」）→ 向量化（选定 embedding 模型后固定版本，换模型必须全量重建）→ 入库（向量库 + 元数据：来源、页码、版本、权限标签）。元数据比很多人想的重要，因为召回之后的引用、权限过滤、时效过滤全靠它。

**PPT 解析的关键是「它其实是个 zip」。** `.pptx` 是 OOXML 包，解压后 `ppt/slides/slideN.xml` 里是文本，按 `a:p` 段落与 `a:t` 文本节点抽取即可，图片在 `ppt/media/`，备注在 `notesSlides`。难点不在抽文本，而在顺序与语义：要按 slide → shape 的 `a:off`（坐标）推断阅读顺序，表格要按行列还原，文本框之间的关联要靠位置而不是 XML 顺序。批量导入的做法是「目录扫描 + 任务队列 + 幂等键（文件 hash + 更新时间）」，单文件导入则同步返回解析结果；两条路都要做失败重试与坏文件隔离，并且解析结果要落库存版本，否则重建向量时无法复现。

**recall 提升要分环节归因，不要笼统说「换了更好的模型」。** 常见手段按收益排序：① 分块策略（语义切分 + 重叠窗口 + 父子块召回，最影响召回上限）；② 混合检索（向量 + BM25 关键词并行召回再融合，用 RRF 或加权，专有名词与型号靠关键词，近义表达靠向量）；③ query 处理（改写、扩展、多查询、意图拆解）；④ embedding 模型与领域微调；⑤ 元数据过滤（时间、来源、权限）；⑥ 引入 rerank 做精排。评测要靠固定标注集算 Recall@K、MRR、NDCG，并且对负样本集（应该召回不到的）做回归，否则一调参就「看起来变好」。

**交叉编码（cross-encoder）与双塔（bi-encoder）的区别是「是否把 query 和文档放在一起算」。** 双塔分别编码再算向量相似度，可以离线建索引、检索快，但交互信息丢失；交叉编码把 `[query, doc]` 拼在一起进模型输出相关性分数，交互充分、精度高，但没法预先建索引，只能对召回的 Top-K（几十到几百条）逐条打分，属于精排阶段。工程上的标准组合就是「双塔召回 + 交叉编码精排」，精排模型常用 BERT 类微调（如 bge-reranker），代价是延迟随 K 线性增长，所以要控制 K、做批量推理、必要时蒸馏成小模型。

**团队分工这类题要答「我负责哪一块 + 怎么和别人对齐」。** 好的答法是把项目拆成数据、检索、模型、工程、评测五块，说清自己主责哪块、和谁接口、接口约定是什么（数据格式、更新频率、SLA），再讲一次跨角色的冲突怎么解决。只说「大家一起做」会被判成没有真实参与。

**「Redis 信号量不想让它失效」要先确认问的是什么。** 如果指的是 Redisson 的 `RSemaphore`，它本身没有过期时间，失效往往是因为用 `tryAcquire(timeout)` 拿到许可后业务没释放、或者节点重启丢了许可；如果指的是 `RPermitExpirableSemaphore`（带租期的许可），那就有过期问题，正解是「续期」——后台定时用 `updateLeaseTime` 延长租期，或者业务结束时显式 `release`，并配合幂等与超时兜底。如果要自己实现，常见做法是 `INCR/DECR` 计数器加一个「持有者集合」（zset 存 permitId 与到期时间），用 Lua 保证原子，定期清理过期持有者把许可还回去。答题时先反问「你说的失效是哪一种失败」，比硬给一个方案更得分。

**JDK 8 的默认收集器是 Parallel Scavenge（年轻代）+ Parallel Old（老年代）。** 判断依据是「没有显式指定时，Server 级机器默认 Parallel」，可用 `java -XX:+PrintCommandLineFlags -version` 验证。执行流程按分代讲：新对象在 Eden 分配，Eden 满触发 Minor GC，存活对象复制到 Survivor（默认 8:1:1，年龄到 15 晋升老年代，大对象直接进老年代或触发分配担保）；老年代满触发 Full GC，Parallel Old 用标记-整理。JDK 9 之后默认换成 G1，这点要能说清，避免把「JDK 默认」当成永恒事实。

**MyBatis 解决的是「SQL 与 Java 对象的映射」，为什么引入它要挂到痛点。** JDBC 的痛点是模板代码多（连接、PreparedStatement、结果集映射、异常处理）、SQL 散落难维护；MyBatis 把 SQL 放到 XML 或注解里、参数与结果自动映射、动态 SQL 用标签拼装、一级缓存（SqlSession）与二级缓存（Mapper）减少重复查询，还便于 DBA 直接 review SQL。和 JPA/Hibernate 相比它是「半自动」：不替你生成 SQL，复杂查询更可控，但也意味着更依赖手写与人工优化。

**Spring MVC 与 Spring Boot 不是同一层的东西。** Spring MVC 是 Web 层的框架（DispatcherServlet、HandlerMapping、参数绑定、视图解析），解决「怎么处理 HTTP 请求」；Spring Boot 是「约定优于配置 + 自动装配 + 内嵌容器 + starter 依赖」的脚手架，解决「怎么把包括 Spring MVC 在内的一堆组件快速装配起来」。一句话：Spring MVC 是能力，Spring Boot 是交付方式。

**反转二叉树是递归三行题，重点在讲清边界。** `TreeNode invert(TreeNode root)`：空返回空；交换左右子节点；递归处理左右子树。复杂度 O(n)/O(h)。写完补一句：递归深度等于树高，极端链状树会栈溢出，工程上可以改显式栈做迭代；以及「交换与递归的顺序无关」这个常见追问。
