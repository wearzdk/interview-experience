### 《参考解析》

**扩频与频谱扩展的本质**：扩频是把窄带待传信号乘以一个速率远高于信息速率的伪随机序列，使信号能量摊开到远大于信息带宽的频带上；接收端用同步的同一序列做相关运算，把有用信号重新压缩回窄带，其余干扰与噪声因不相关而被摊开。处理增益约为 `10log10(B_rf / B_info)`，带宽扩展比越大抗窄带干扰能力越强。所谓「频谱扩展的本质」，在信息论上是用带宽换信噪比：香农公式 `C = B·log2(1+S/N)` 说明带宽与信噪比可以互换，扩频正是把信号功率降到噪声之下、靠带宽与相关处理恢复信息；实现层面则依赖伪随机序列良好的自相关与互相关特性，以及收发两端的严格同步。工程上还要回答直接序列扩频（DSSS）、跳频（FHSS）、 chirp 扩频的差别，以及同步捕获与跟踪为什么是难点。

**MSK 与 FSK 的差异**：MSK 是连续相位频移键控，调制指数固定为 0.5，两个频率间隔为 `1/(2T)`，因此一个码元周期内相位连续变化 ±π/2。它的包络恒定（可用非线性功放）、相位连续，频谱旁瓣衰减快（约按 f⁻⁴ 衰减），邻道干扰小、频带利用率高；普通 2FSK 在码元切换处相位跳变，频谱旁瓣衰减慢（约 f⁻²），带外泄漏明显。若继续追问，可提 GMSK 在高斯低通滤波后进一步压缩旁瓣，被 GSM 与蓝牙采用，代价是引入码间干扰。

**Linux 内存管理**：物理内存由伙伴系统按 2 的幂次管理页框，解决外碎片；内核小对象分配走 slab/slub 分配器，对常用结构做缓存；`kmalloc` 分配物理连续内存，`vmalloc` 分配虚拟连续但物理可不连续的内存，后者需要额外页表映射、效率略低。用户态通过多级页表把虚拟地址翻译到物理地址，采用按需调页与缺页异常，配合页缓存加速文件访问；内存紧张时用 LRU 回收、swap 换出，OOM killer 作为最后手段。回答时把「虚拟地址空间布局」也带一句：用户空间从低地址到高地址依次是代码段、数据段、BSS、堆（向上增长）、mmap 映射区（向下增长）、栈（向下增长），再往上是内核空间。

**`mmap` 与 `malloc`**：`malloc` 是 C 库函数，管理进程堆，小块内存通过 `brk` 扩展堆顶，超过阈值（glibc 默认约 128KB）改用匿名 `mmap`，并维护空闲链表以减少系统调用；它返回的是可读写的匿名内存，不与文件关联。`mmap` 是系统调用，把文件或匿名内存映射进进程地址空间，访问时通过缺页把文件页装入页缓存，因此读写大文件可以省掉「内核缓冲区到用户缓冲区」的一次拷贝，也天然支持多进程共享同一份页。区别可以归纳为：抽象层次不同（库函数对系统调用）、内存来源不同（堆与文件或匿名映射）、是否共享、以及释放方式（`free` 与 `munmap`）。使用 `mmap` 时要注意映射长度按页对齐、文件截断后访问越界会触发 `SIGBUS`、写回时机由 `msync` 控制。

**Linux 系统移植与驱动**：移植通常分三段——bootloader 适配（板级初始化、DDR 参数、启动介质、环境变量）、内核适配（设备树描述硬件、配置项裁剪、驱动使能、控制台与根文件系统挂载）、根文件系统搭建（BusyBox、Buildroot 或 Yocto，库与固件、init 脚本）。驱动部分要能说清自己写过哪一类：字符设备（`file_operations`、`cdev`、设备号）、平台设备（设备树 `compatible` 匹配、`probe` 中获取 reg、中断、GPIO、时钟）、还是 I2C/SPI 子系统下的从设备驱动。面试官更在意你是否理解「设备树如何描述资源、驱动如何匹配、probe 何时被调用」这条链路，而不是罗列驱动名。

**相机 Sensor 调试**：通常通过 I2C 配置寄存器，按数据手册的上电时序（复位、时钟、电源轨）初始化，再配置 MIPI CSI 的 lane 数、速率与数据格式；调试时用示波器或逻辑分析仪确认 MIPI 时钟与数据，抓 RAW 图看黑电平、坏点与色彩偏差，再调曝光、增益与镜头阴影校正。若没做过，如实说明并讲清自己理解的链路，比含糊其辞更安全。
