### 《面试题目》

1. 自我介绍。
2. 问项目。
3. synchronized 锁升级的具体流程是什么？
4. AQS 的原理介绍一下。
5. Spring 里面怎么实现 AOP 的？
6. 动态代理有几种实现方式？
7. zset 的底层数据结构是什么？
8. Agent 中的 ReAct 模式的工作原理是什么样的？
9. 反问：工作内容和结果什么时候出。

### 《参考解析》

**synchronized 锁升级**：对象头 Mark Word 记录锁状态。无锁时是对象哈希与分代年龄；第一个线程进入时若开启偏向锁，用 CAS 把线程 ID 写入 Mark Word，进入偏向锁，之后同一线程进入只需比对 ID，不再 CAS；出现另一个线程竞争时，在安全点撤销偏向锁，升级为轻量级锁——线程在栈帧里建 Lock Record，用 CAS 把 Mark Word 指向它，失败则自旋；自旋失败或竞争加剧，膨胀为重量级锁，依赖操作系统互斥量与等待队列，未获取锁的线程阻塞。JDK 15 起偏向锁默认关闭并标记废弃，回答时提一句版本差异能加分。

**AQS 的核心是 state 加等待队列**。`volatile int state` 表示同步状态，通过 CAS 修改；获取失败的线程包装成 Node 进入 CLH 变体的双向队列，用 `LockSupport.park/unpark` 阻塞与唤醒。它区分独占与共享两种模式，ReentrantLock、Semaphore、CountDownLatch、ReentrantReadWriteLock 都基于它实现。ReentrantLock 的公平锁在获取时先检查队列里有没有前驱，非公平锁直接先 CAS 抢一次，抢不到再入队，所以非公平锁吞吐更高但可能饥饿。

**Spring AOP 靠动态代理在运行时织入**。容器创建 Bean 时，`AnnotationAwareAspectJAutoProxyCreator` 找到切面与切点，匹配到目标 Bean 后生成代理对象，把通知（前置、后置、环绕、异常、最终）织入方法调用链。目标类实现了接口且配置为 JDK 代理时用 `java.lang.reflect.Proxy`，否则用 CGLIB 生成子类。常见坑是同类内部方法自调用不走代理，事务与切面失效，解决方式是拆到另一个 Bean、注入自身代理或用 AopContext。

**动态代理的实现**：JDK 动态代理基于接口，运行时生成实现类，调用转发到 `InvocationHandler`；CGLIB 基于 ASM 生成目标类的子类，重写方法并插入回调，不能代理 final 类与 final 方法；ByteBuddy 更灵活，Spring Boot 与 Mockito 都有使用；编译期还有 AspectJ 的织入。选择上，有接口用 JDK，无接口用 CGLIB，性能差异在现代 JVM 上已不明显。

**zset 是跳表加字典**。字典（hash）保存 member 到 score 的映射，支持 O(1) 查分数；跳表按 score 排序并支持范围查询，插入、删除、按排名查询都是 O(logN)。元素较少时用 listpack（旧版本 ziplist）压缩存储，超过阈值转为跳表加字典。跳表相比平衡树实现简单、范围遍历友好，这是 Redis 选它的原因。

**ReAct 是「推理—行动—观察」的循环**：模型先输出对当前状态的分析（Thought），再选择一个行动（Action，通常是调用某个工具及参数），运行时执行后把结果作为观察（Observation）送回模型，模型据此继续推理，直到给出最终答案（Final Answer）。它的价值是把推理过程显式化，让模型能根据工具返回修正计划；工程上要加最大步数、循环检测、工具错误分类与中断机制，避免原地打转。
