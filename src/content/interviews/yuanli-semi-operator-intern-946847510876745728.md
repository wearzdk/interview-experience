### 《面试题目》

1. 项目拷打：你做过什么真实的优化？profiling 数据是什么？瓶颈在访存还是计算？用什么工具看的？换个 shape 优化策略还成立吗？
2. 说一下对 SIMD 的理解，以及常见 CPU 的 SIMD 指令集有哪些。
3. 循环展开为什么会对性能有提升？
4. 不同相加顺序的 Reduce 会不会影响结果？为什么？
5. IEEE754 标准有哪些内容？
6. 空间换时间的思想在算子开发中有哪些典型场景？
7. PingPong 操作有了解吗？

### 《参考解析》

1. **项目怎么讲**：按「背景 → 瓶颈 → 你做的优化 → 量化结果」讲，并准备好被追问细节：优化前的 profiling 数据、为什么这个算子慢（访存密集还是计算密集）、用什么工具（perf、VTune、ncu、火焰图）、换 batch size 或 shape 后策略是否还成立、开启 fast math 后数值误差变化多少。高分表达是「我把访存模式从 gather 改成连续读，L2 miss 率下降 30%」这种带指标的具体动作。

2. **SIMD**：单指令多数据，一条指令同时对多个数据执行相同运算，属于数据级并行。它不靠多核，靠寄存器宽度换吞吐：128bit 一次 4 个 float，256bit 一次 8 个，512bit 一次 16 个。常见指令集：x86 的 SSE/AVX/AVX2/AVX-512，ARM 的 NEON 和可伸缩的 SVE/SVE2，RISC-V 的 V 扩展。工程上说清「编译器自动向量化失败时用手写 intrinsics，或者通过内存对齐和消除循环依赖帮助它向量化」。

3. **循环展开为什么快**：减少循环控制开销（自增、比较、跳转），提高指令级并行让多条独立指令同时进流水线，给编译器更大的基本块做调度和寄存器分配，也更容易触发向量化。代价是代码体积变大、寄存器压力上升、指令 Cache 可能变差，所以不是展开越多越好，要先看反汇编确认编译器是否已经展开。

4. **Reduce 顺序影响结果**：浮点加法不满足结合律，每一步都有舍入误差，不同顺序的误差累积路径不同，所以分块、树形结构、线程数不同都会得到不同结果。进一步的回答是树形归约（两两相加，误差上界更小、并行度更高）、Kahan 补偿求和（用补偿变量记录舍入误差）、以及可复现性问题（需要固定归约顺序或使用确定性算法）。

5. **IEEE754**：定义浮点的二进制布局、取值范围、舍入规则和特殊值。FP32 是 1 位符号、8 位指数（偏移 127）、23 位尾数，范围约 ±1.18e-38 到 ±3.4e38，有效十进制位约 6～9 位；FP16 是 1-5-10；FP64 是 1-11-52。特殊值有 ±Inf、NaN、±0；还有非规格化数（指数全 0、尾数非 0），表示接近 0 的极小值，部分硬件上计算会显著变慢，所以有些实现会 flush to zero。舍入默认是就近取偶。

6. **空间换时间**：查表法（激活函数、三角函数的预计算表）、预分配 buffer 避免循环内 malloc、数据重排（NCHW 转 NHWC 提升访存连续性）、im2col 把卷积转成 GEMM、缓存中间结果。要强调权衡：im2col 空间膨胀数倍可能反而增加 cache miss，所以有时用隐式 im2col 或间接索引；空间换时间要考虑 cache 容量和内存带宽。

7. **PingPong**：即双缓冲。两块缓冲区交替使用，一块在计算时另一块在搬数据，处理完交换角色，从而把数据搬移时间隐藏在计算之下。典型场景是 DMA 与外设、音视频解码与播放、网络收发包、GPU 上 `cudaMemcpyAsync` 与 kernel 计算重叠。技术要点是切换时机的同步（标志位、事件、fence）、多设备下的内存一致性、以及缓冲区大小（太小会卡顿，太大浪费内存）。三缓冲可以进一步减少抖动，算子场景双缓冲通常够用。
