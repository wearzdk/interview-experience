### 《面试题目》

1. 机考里有哪些常见的输入格式？分别该怎么读？
2. 「一行一个数，读到文件结束」这类输入，循环条件怎么写？
3. 先给组数 T、再跟 T 组数据，为什么每组都要重新初始化状态？
4. 读到「0 0」这类哨兵就停，和读到 EOF 有什么区别？
5. 先给 n 再给 n 个数，n 与数据不在同一行时怎么读？
6. 一整行字符串中间带空格，为什么不能按空格 split 成单词？
7. Python 里数据量大时循环 `input()` 为什么慢？怎么改？
8. C++ 里 `cin` 与 `scanf` 差在哪？`cin` 之后接 `getline` 为什么会读到空行？
9. 输出时行尾多一个空格会怎样？
10. 本地样例通过、提交却 WA 或 TLE，应该先怀疑什么？

### 《参考解析》

**五种格式对应五套模板，先把模板背熟再谈算法**：

```python
import sys

data = sys.stdin.read().split()   # 一次读完，后续按下标取，最快也最不容易错

# 1) 读到 EOF：一行一个数
for line in sys.stdin:
    x = int(line)
    ...

# 2) 先给组数 T
it = iter(data); T = int(next(it))
for _ in range(T):
    n = int(next(it))
    arr = [int(next(it)) for _ in range(n)]

# 3) 哨兵结束（读到 0 0 停）
while True:
    a, b = int(next(it)), int(next(it))
    if a == 0 and b == 0:
        break

# 4) 先给 n 再给 n 个数（可能跨行）
n = int(next(it)); arr = [int(next(it)) for _ in range(n)]

# 5) 一整行字符串（保留空格，不能 split）
line = sys.stdin.readline().rstrip('\n')
```

C++ 对应写法：`scanf` 或关掉同步的 `cin`（`ios::sync_with_stdio(false); cin.tie(nullptr);`）；读到 EOF 用 `while (cin >> x)`；先给 T 就 `cin >> T` 再循环；哨兵在循环里判断后 `break`；整行字符串用 `getline(cin, s)`，但前面用过 `cin >>` 时要先 `cin.ignore(numeric_limits<streamsize>::max(), '\n')` 把残留换行吃掉，否则 `getline` 读到空行——这是最经典的一个坑。

**Python 读入的性能差距是数量级的**：`input()` 每次都走一次缓冲与解码，几十万行时能慢出好几秒，`sys.stdin.readline` 快一些，`sys.stdin.buffer.read().split()` 最快（直接读字节再切分）。注意 `split()` 默认按任意空白切分，会把一行里的多个空格与换行都吃掉，所以「整行字符串」这种必须保留空格的场景不能用它，要单独 `readline`。输出侧同理：循环里 `print` 会频繁 flush，改成收集到列表再 `'\n'.join` 一次写出，能省掉大量系统调用。

**「本地对、提交错」的三条判据**：样例对不上先怀疑读入，再怀疑算法——尤其当题目有多组数据时，八成是上一组的状态没清（全局数组、计数器、并查集的父节点数组）。提交 WA 但本地对，优先查多组数据之间的残留、行尾多余空格与换行（有的判题系统逐字节比对，多一个空格就 WA）、整数溢出与浮点精度。提交 TLE 但本地跑得快，先看读入是不是太慢（Python 的 `input()`、C++ 没关同步）、再看算法复杂度是否在最大数据量下退化，最后看有没有在循环里做不必要的对象创建。

**边界用例要自己造**：空输入、只有一个元素、T = 1、n = 0、数据刚好读到 EOF 而末尾没有换行、数值取到上下界、以及「多组数据规模差异极大」的情况。上机前把样例复制到本地跑一遍，再跑自己构造的边界，比在考场上凭感觉调试省时间。

**为什么这件事值得单独练**：核心代码模式把读入藏起来了，平时的算法训练只覆盖「给定函数签名」这一种形态；机考的第一道门槛恰恰是「把输入变成内存里的结构」。帖主给的三步练法是可执行的：先刷完输入输出专项（半小时能过一轮），再挑十来道输入格式别扭的题专门练读入，最后在上机前把样例与边界在本地跑通。另外一句提醒值得记住——每道题都要能讲清思路，面试官常会拿笔试的题回头追问。
