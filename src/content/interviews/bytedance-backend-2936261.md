### 《面试题目》

1. Redis 和 MySQL 有什么区别？
2. 讲一下简历上的项目（面试官主要围绕项目提问）。
3. 第一道算法题：看完题开始写，十来分钟后发现题目理解错了。
4. 第二道算法题：换一题后手写实现。
5. 算法题里能不能用 HashSet 这类现成的数据结构？

### 《参考解析》

**题意没吃透就先别敲键盘。** 这道场面的典型路径是：扫一眼题、凭题型记忆直接写，写到一半发现输入输出和自己想的不一样。省时间的做法是开口复述——「我理解是给一个长度为 n 的数组，要求返回……，n 大概多大，有负数吗，需不需要考虑空输入？」三句话就能问出题型、数据规模与边界，也顺便让面试官看到你在建模而不是背题。数据规模还决定复杂度上限：n 是 10^5 就别写 O(n²)。

**「能不能用现成数据结构」要当场确认，别默认。** 力扣上 `HashSet` 随便用，但有些面试官把「手写」理解为「只允许数组和基本类型」，考的是你能不能自己实现哈希或双指针。进门先问一句「可以用标准库的集合类吗」，一句话省掉后面十分钟的拉扯。如果对方要求不用，就退回最朴素的写法：数组 + 手写哈希（取模 + 链地址）、或排序后双指针，把空间换时间的取舍讲出来。

**IDE 标红不等于你写错。** 面试间的在线编辑器常常没有完整 JDK、没有 import 自动补全，`HashSet` 这种要 `import java.util.*` 的类型会直接标红，甚至连 `main` 签名都校验得很怪。应对是提前把代码写成「零依赖」风格：只用数组和基本类型、自己写 `swap`、不调 `Arrays.sort`；必须用集合时把 import 写全并主动说「这里需要 import，编辑器可能没配」。真的跑不起来时，改成在纸上/注释里走一遍样例，把每一步的中间状态念出来——面试官要的是过程，不是一个绿色的 Run。

**面试官不懂 Java 时，把答案翻译成语言无关的话。** 他判断不了语法，就让他判断逻辑：先说思路（用什么结构、为什么）、再报复杂度（时间 O(n)、空间 O(k)）、最后给两三个手算样例走一遍。避免说「这里用 stream 一行就出来了」这类依赖语言特性的表达。

**项目被拷打却「没问出个所以然」，问题通常在讲法。** 先给 30 秒版本：项目解决什么问题、你负责哪块、最硬的一个技术点是什么；再留钩子等对方深挖。全程按时间线复述「我做了 A 又做了 B」，面试官接不上话，只能换题。

**Redis 与 MySQL 的区别别只答「一个内存一个磁盘」**：数据模型（KV 与富结构 vs 关系表与 SQL）、一致性（Redis 单线程命令原子、持久化 RDB/AOF 有丢失窗口；MySQL 有事务与隔离级别）、用途（缓存、计数、排行榜、分布式锁 vs 事务型主存储）、扩展（Redis Cluster 分片 vs 主从 + 分库分表）。落到一句：缓存扛读、数据库保正确性，中间隔着更新顺序与失效策略。

**另外两个细节**：面试官开着双机位往往是在录屏留档或按公司规范监考，不必解读成压力信号；面试环境不熟（编辑器、语言版本、有没有提示）是可以在开始前花一分钟确认的，问一句不扣分。
