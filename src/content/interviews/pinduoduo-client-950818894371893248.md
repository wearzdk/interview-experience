### 《参考解析》

**转岗动机要讲成主动选择**：面试官反复确认岗位与轮次，说明这次面试本身存在匹配问题。回答时先承认背景差异，再给出转向客户端的理由：对端上体验与性能有长期兴趣、做过与服务端联调的协议与网络层工作、希望补足客户端能力；同时说明可迁移的部分（网络编程、数据结构、并发、调试能力）与需要补的部分（UI 框架、生命周期、渲染与内存管理）。不要贬低服务端方向，也不要把客户端说成退路。

**自定义 IM 协议的字段设计**：一个可用的二进制协议至少包含魔数、版本、消息类型、序列号、时间戳、载荷长度与载荷，尾部加 CRC32 校验。魔数与版本用于快速识别与兼容升级，消息类型区分登录、心跳、消息、ACK、撤回，序列号用于请求响应配对与去重，长度字段解决 TCP 粘包与半包，CRC 用于发现传输或内存错误。粘包与半包的处理方式是在接收侧维护环形缓冲，先读固定头部长度的字段，再按长度字段判断整帧是否到齐，到齐才交给业务层，剩余字节留在缓冲等待下一帧。工程上还要补心跳与超时重连（指数退避）、消息去重与顺序保证（按会话序号）、发送窗口与 ACK、以及断线后的增量同步。若协议要跨版本演进，需要预留字段并约定未知类型的忽略规则。

**HTTPS 相比 HTTP 增加的内容**：HTTP 明文传输，内容可被窃听与篡改，也无法验证服务端身份。HTTPS 在 HTTP 与 TCP 之间加了 TLS：握手阶段用证书链验证服务端身份，用 ECDHE 协商出会话密钥（具备前向安全），之后用对称加密传输数据，并用 AEAD 或 MAC 保证完整性，防止篡改与重放。TLS 1.3 把握手压缩到 1-RTT，会话恢复可做到 0-RTT；ALPN 协商 HTTP/2 或 HTTP/3，SNI 指示目标域名，HSTS 强制后续走 HTTPS。代价是握手延迟与加解密开销，通常用会话复用、TLS 卸载到网关、以及 HTTP/2 多路复用来抵消。

**vLLM 的追问要落到机制**：vLLM 的核心是 PagedAttention，把 KV cache 切成固定大小的块并按需分配，用块表映射逻辑位置与物理块，解决传统实现按最大长度预分配导致的显存碎片与浪费；配合 continuous batching，在请求级别动态进出批次，而不是等整批结束，显著提升吞吐。此外还有 prefix caching 复用相同前缀的 KV、张量并行支持多卡、以及量化方案降低显存占用。落地时要能说清显存估算（权重加 KV cache）、吞吐与延迟的取舍（批大小越大吞吐越高、单请求延迟越差）、以及业务侧如何接入（网关、限流、超时、失败重试）。

**Agent 框架与效果优化**：LangChain 侧重把模型、工具、检索、记忆串成链路，LangGraph 用图结构表达带环的状态机，适合多步骤、可回退、需要人工介入的流程，节点是步骤、边是条件跳转，状态在节点间传递。运维助手这类 Agent 的核心工作流通常是：接收告警或自然语言请求，检索知识库与历史工单，规划排查步骤，调用监控与日志工具，汇总证据给出结论，必要时请求人工确认后执行变更。优化任务成功率的方向包括工具描述与参数设计、失败结果的可读反馈、上下文裁剪与状态管理、把复杂任务拆成可验证的子步骤、建立评测集做回归、以及全链路 trace 定位失败环节。

**两道手撕题的要点**：迭代求二叉树最大深度用显式栈做 DFS，栈里存节点与当前深度，或做层序遍历计数层数，时间与空间都是 O(n)；注意空树返回 0、栈的压入顺序不影响结果。三线程交替打印的关键是共享状态加同步原语：C++ 用 mutex 加 condition_variable，三个条件变量分别对应三个线程的轮次，等待时用谓词防止虚假唤醒；Java 用 synchronized 加 wait/notifyAll，或 ReentrantLock 加三个 Condition，也可以用 Semaphore 依次释放许可。要处理退出条件（打印到上限后唤醒所有线程结束），并避免忙等与死锁。面试官追问换语言实现，本质是考察是否理解同步原语的语义，而不是背 API。
