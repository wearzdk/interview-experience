### 《参考解析》

**SSE 流式闪屏的处理**：流式输出的闪屏通常来自「每收到一段就整体替换 DOM」或「占位高度跳变」。做法是按增量追加而不是整体重渲染、给容器预留最小高度、对代码块做增量高亮而不是每次全量解析、用 `requestAnimationFrame` 合并高频更新、滚动位置只在用户未手动滚动时自动跟随。SSE 本身还要处理断线重连、`Last-Event-ID` 续传与心跳。

**首页优化的答法要带指标**：先给指标（LCP、FCP、TTI、CLS），再说手段：资源体积（代码分割、按需加载、图片压缩与响应式尺寸、字体子集化）、网络（CDN、HTTP/2、预连接与预加载、缓存策略）、渲染（关键 CSS 内联、减少阻塞脚本、骨架屏、懒加载）。浏览器 Performance 面板的快照要看瀑布图里的长任务、主线程阻塞、资源加载顺序与优先级；重复请求通常是同一资源被不同模块各自加载、缓存头配置错误或预加载与实际请求重复，处理方式是统一资源入口、加缓存与去重、检查 `Cache-Control` 与 `ETag`。

**闭包与防抖节流**：防抖与节流都用闭包保存定时器或上次执行时间，所以「闭包让状态在函数调用之间保留」是它们的实现基础；反过来，闭包也是内存泄漏的常见来源（被外部引用无法回收），组件卸载时要清除定时器与事件监听。

**说服 React 开发者用 Vue3 的角度**：不从「哪个更好」争，而从迁移成本与收益讲：Vue3 的组合式 API 与 React Hooks 心智接近、模板编译带来运行时优化（静态提升、Patch Flag）、`<script setup>` 减少样板、官方生态（Router、Pinia、Vite）一体、渐进式接入可以按页面迁移。承认 React 在生态与跨端上的优势，给出具体场景下的取舍。

**响应式与构建工具**：Vue3 用 Proxy 代理对象，get 时 `track` 收集依赖、set 时 `trigger` 派发更新，依赖存在 `WeakMap` 里，嵌套对象惰性代理；对比 Vue2 的 `defineProperty` 能监听新增删除与数组索引。Webpack 是打包式构建，先分析依赖图再打包，开发时全量构建后走 HMR；Vite 开发态用原生 ESM 按需编译、依赖预构建，生产态用 Rollup 打包。CSS 方面 Webpack 通过 loader 把 CSS 抽成单独文件或注入 style，Vite 开发态用 ESM 直接加载 CSS 并支持 HMR，生产态同样抽离。AI Coding 部分按实际讲：用它生成样板与单测、改重构、查报错，说明成本（订阅费或按量）与边界（关键逻辑人工复核）。
