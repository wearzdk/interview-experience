### 《面试题目》

1. 为什么要从现在的公司离开？
2. 在实习过程中有什么样的感悟？
3. 想找一个什么样的实习工作，有什么规划吗？
4. 在 AI 时代，你对自己的职业规划有什么考虑？
5. 你对网络安全有没有想法，愿意从事这个行业吗？

### 《参考解析》

**离职原因这类问题，规则是对事不对人。** 面试官问「为什么离开」其实在听两件事：你的判断是否理性、以及你会不会同样评价他们。答法固定成「我在上一段得到了什么 + 新机会能补上什么」：先说清上一段真实收获（完整参与过一个模块、熟悉了从需求到上线的流程），再说客观差异（想接触更完整的技术链路、技术栈与目标方向不匹配、业务方向调整），最后收到这个岗位上。要避开的雷区：不评价前雇主、前同事、前领导；不把原因落在「钱少、加班多、太累」这类既无法验证又暴露风险的说法上；也不要把原因编成一个和简历对不上的故事，因为面试官很可能顺着追问上一段做的具体内容。

**「实习感悟」要落到一件具体的事上。** 「学到了很多、成长很快」等于没答。可用的模板是：挑一件自己主导或深度参与的事，交代背景 → 你当时做的判断 → 结果与数据 → 事后复盘会怎么改。比如「发现联调反复返工，我把接口文档和字段约束整理成清单，联调轮次从三轮降到一轮」。这类回答同时完成了三件事：证明你真的在做事、展示反思能力、给面试官递了一个他能接着问的钩子。感悟里回避抱怨和甩锅，把责任落在自己身上更好挖。

**职业规划分近中长期讲，且要能接得上简历。** 近期可以说具体一点：把 Java 基础、并发与 JVM、数据库与工程规范打扎实，同时熟悉团队在用的框架与研发流程；中期落在「能独立负责一个模块，从设计评审到上线与线上问题定位」；长期给一个方向性的纵深（后端架构、或安全研发）。规划不必宏大，但要和你已经做过的事连得上——简历上写的是后端开发，长期却说想转算法，面试官一定会追问中间怎么过渡。被问到「AI 时代」时，把定位讲清楚：它是提效工具，用它读陌生代码、写测试、查文档、加快排查，但变量是设计取舍、边界判断和线上问题的定位，这部分仍然依赖人的经验积累；不要讲成「AI 会取代初级开发所以我慌」，也不要讲「全靠 AI 就行」。

**「愿不愿意做网络安全」这类跨方向提问，先给结论再给理由。** 面试官问这个通常说明岗位内容和你投递的方向有出入，他想知道你能不能接受、以及有没有基础。答法上先明确表态，再补迁移路径：如果愿意，就说清已有的相关底子（网络协议、操作系统、Web 漏洞的原理，自己动手复现过哪些类型）以及打算怎么补（把 Java 代码审计和安全开发当切入点，安全研发本身也大量依赖后端能力，这个迁移是成立的）；如果确实不确定，就直说想先了解岗位日常做什么、团队怎么分工，把它当成一次双向沟通。最差的是含糊地答「都可以」——既没有信息量，也让对方无法判断你的稳定性。
