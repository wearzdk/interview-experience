### 《参考解析》

**5 天渗透项目第一天**：先对齐范围与授权（目标资产清单、测试时间窗、禁止动作、应急联系人），再做信息收集与资产梳理（子域、端口、指纹、历史漏洞），据此排出优先级与人力分工，输出一份当天可交付的计划与风险清单。第一天不急着打点，重点是确认边界、建立沟通机制、把「能做什么、不能做什么、出了问题找谁」写清楚。回答要体现交付意识：每天有产出、有记录、有同步。

**团队与沟通场景题**：组员不愿值班但想成长——先了解原因（值班与成长是否真的冲突），把值班与学习设计成可交换的（值班产出复盘、轮换机制、把交付任务拆成可积累的技能），并用明确的规则而不是人情推动。资深同事总把活交给你——先接住一次并记录工作量，再与对方对齐优先级（哪些是你的职责、哪些需要他确认），必要时把排期与冲突摆到台面上由负责人裁决，避免私下积累怨气。

**Token 安全**：Token 解决的是「无状态的身份凭证」问题，但本身不等于安全。要搭配：HTTPS 传输、短期有效期 + 刷新机制、签名算法与密钥管理、绑定受众与签发者、存储安全（HttpOnly Cookie 或安全的内存存储，避免 localStorage 被 XSS 读取）、撤销机制（黑名单或短过期）、防重放（nonce、时间戳）。JWT 常见误区是把敏感信息放进 payload（可被解码）和只依赖前端校验。

**盲注**：布尔盲注通过构造条件为真/假的 payload，观察页面返回差异逐位推断；时间盲注在条件为真时触发 `SLEEP()` 等延时，通过响应时间判断，适合页面无差异回显的场景；报错盲注利用数据库报错信息带出数据。验证时要控制变量（同一请求、同一参数、固定延时阈值），并注意不同数据库的语法差异（MySQL 的 `SLEEP`、`IF`，SQL Server 的 `WAITFOR DELAY`）。防御是参数化查询、最小权限、错误信息不外泄。

**MySQL 版本差异**：5.7 与 8.0 的差异包括默认字符集（latin1 → utf8mb4）、认证插件（mysql_native_password → caching_sha2_password）、窗口函数与 CTE 的支持、JSON 能力增强、`information_schema` 的部分表结构变化、以及 performance_schema 的默认开启。渗透语境下常关注 `information_schema` 的可用性、`secure_file_priv` 的默认值、以及 `LOAD_FILE`/`INTO OUTFILE` 的权限限制。

**提权**：Linux 下常见路径是内核漏洞、SUID/SGID 文件、sudo 配置错误、定时任务可写、环境变量劫持、服务配置错误、凭据泄漏；Windows 下是服务权限配置错误、未打补丁的本地提权漏洞、AlwaysInstallElevated、计划任务、令牌窃取。回答要强调「先做信息收集与枚举，再匹配利用」，并说明提权后的最小动作原则。

**异常文件排查**：先看文件属性（时间、权限、属主、大小、是否隐藏）、内容特征（脚本、二进制、编码）、位置（临时目录、Web 目录、启动项）、关联进程与网络连接（`lsof`、`netstat`、`ps`）。再到持久化位置排查（crontab、systemd、rc.local、计划任务、注册表启动项），结合日志回溯写入时间与来源。处置是隔离样本、保留证据、清除持久化、修补入口。

**半虚拟化与全虚拟化**：全虚拟化由 Hypervisor 模拟完整硬件，客户机操作系统无需修改，兼容性好但性能开销大（早期靠二进制翻译，现在靠 CPU 硬件辅助如 VT-x/AMD-V）；半虚拟化要求客户机感知虚拟化环境并做修改（如 paravirt 驱动、hypercall），性能更好但需要 Guest OS 配合。容器不是虚拟化，是命名空间与 cgroup 的隔离。

**客户交互最重要的事**：把技术问题翻译成客户能决策的信息：影响范围、风险、处理方案与时间、需要客户配合什么。及时同步进展，坏消息早说，承诺要留余量。回答时用一个具体例子支撑（例如现场发现高危漏洞时如何沟通处置优先级）。

**HR 面**：优缺点、协作冲突、择业逻辑要与前面技术面一致，不要出现前后矛盾的动机。缺点选真实的、可改进的，并给出正在采取的行动；被问「为什么现在选安服而不是目标方向」时，说明安服能提供的能力积累（客户现场、交付流程、攻防实战）与长期方向的连接。
