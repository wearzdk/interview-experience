### 《参考解析》

**内存管理：引用计数为主，标记-清除与分代回收为辅。** CPython 里每个对象有一个引用计数，赋值、传参、放入容器都会加一，重新赋值、离开作用域、从容器删除会减一，减到零立即释放。引用计数解决不了循环引用，所以有垃圾回收器：用标记-清除找出不可达的循环引用对象，再用分代回收降低扫描成本——新对象在第 0 代，活得越久被扫描的频率越低。面试时可以补一句实践含义：大量创建小对象会带来计数开销，循环引用多、对象生命周期长的场景要关注 GC 阈值和 `gc.freeze()` 之类的调优手段。

**拷贝三兄弟的区别在「嵌套对象是否共享」。** 赋值只是给同一个对象再起一个名字，两个变量指向同一块内存；浅拷贝创建一个新的外层容器，但内部元素仍是原来的引用，`list.copy()`、切片、`copy.copy()` 都是浅拷贝；深拷贝递归复制所有层级，`copy.deepcopy()` 会维护一个 memo 字典处理循环引用和重复引用。常见坑：浅拷贝后修改嵌套列表会同时影响原对象；深拷贝大对象代价高，且对不可变对象、文件句柄、锁这类对象不能盲目深拷贝。

**正则题要讲清锚点与贪婪性。** `re.match` 只从字符串开头尝试匹配，开头不匹配立即返回 None；`re.search` 扫描整个字符串找第一个匹配；`re.fullmatch` 要求整个字符串完全匹配。`<.*>` 是贪婪匹配，会尽可能吃到最后一个 `>`；`<.*?>` 是非贪婪匹配，遇到第一个 `>` 就停。抓网页标签时贪婪模式会把多个标签连成一段，非贪婪才是正确写法；但更稳的做法是用 HTML 解析器，正则只做简单提取。

**GIL 决定了 CPython 多线程的适用边界。** CPython 用全局解释器锁保证同一时刻只有一个线程执行字节码，所以多线程在 CPU 密集型任务上无法利用多核，频繁切换还会更慢；但线程在发起 IO、陷入系统调用时会释放 GIL，因此 IO 密集型任务用多线程仍然有效。选型上：CPU 密集型用 `multiprocessing`（进程间内存独立，靠序列化通信）或 C/C++ 扩展；IO 密集型用多线程或 `asyncio`；混合型把 CPU 部分丢进进程池、IO 部分用协程。可以补一句版本进展：Python 3.13 起有实验性的 free-threaded 构建，但生态兼容和性能还需要观察。

**其余小题按「一句话结论 + 一个例子」答。** lambda 是匿名函数表达式，适合作为 `key`、回调等短逻辑，复杂逻辑不要用；tuple 转 list 可以用 `list(t)`、`[*t]`、列表推导式；去重保序用 `dict.fromkeys(nums)`（或集合 + 推导式），只去重不保序用 `set`；按最后一个元素排序是 `sorted(data, key=lambda x: x[-1])`；`range` 返回不可变的整数序列，支持步长与负数；`pass` 是语法占位符；函数内用 `global` 声明后修改模块级变量（更推荐用返回值或类封装）；`except` 捕获异常，要指定异常类型、记录日志，避免裸 `except` 吞错。调试与静态检查可以提 `pdb`/`breakpoint()`、`logging`、`pytest`、`ruff`（集成 lint 与格式化）、`mypy`/`pyright`（类型检查）。
