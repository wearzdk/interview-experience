### 《面试题目》

1. TCP 与 UDP 有哪些相似点？
2. 二分查找的适用条件是什么，边界怎么处理？
3. 代码补全：用链表实现归并排序。
4. 代码补全：动态规划题（题干较长，帖主未完整记录）。
5. 编程题：给定长度为 n 的整数数组 nums，其中 nums[i] 在 [1, n] 之间，找出所有在 [1, n] 范围内但没有出现在 nums 中的数字。

### 《参考解析》

**TCP 与 UDP 的相似点**：两者同属传输层，都封装在 IP 之上，用 16 位端口号区分同一台主机上的不同进程，都提供校验和（TCP 必选、UDP 可选），都可用于请求—响应式的应用通信，也都可以在同一台主机上并发多个连接或数据报。面试里问「相似点」通常是给后面的「差异」做铺垫，答完相同之处要主动接上区别：连接与状态、可靠性与重传、有序性、报文边界、拥塞与流量控制、首部开销。差异的根源是设计目标不同——TCP 提供字节流抽象，UDP 保留报文边界、把可靠性留给应用层，因此实时音视频、DNS、QUIC 的基础传输都选 UDP。

**二分查找**：前提是序列有序且支持随机访问（数组可以，链表不行）。写法的关键在于固定一个循环不变量，通常取左闭右开区间 `[lo, hi)`：`while (lo < hi)`，`mid = lo + (hi - lo) / 2`（这样写不会在 `lo + hi` 上溢出），命中返回，`nums[mid] < target` 时 `lo = mid + 1`，否则 `hi = mid`。要能说清三种常见变体：查找第一个等于目标的位置、最后一个等于目标的位置、第一个大于目标的位置，它们的差别只在命中之后是收缩左边界还是右边界。边界错误高发在 `hi` 取 `n` 还是 `n - 1`、循环条件用 `<` 还是 `<=`，两者必须配套。

**链表归并排序**：三步——快慢指针找中点、断开链表、递归排序两半后合并。找中点时用 `slow` 每次走一步、`fast` 每次走两步，循环条件写成 `fast && fast->next`，结束时 `slow` 落在后半段的第一个节点；用 `prev` 记录 `slow` 的前驱并在递归前把 `prev->next` 置空，否则两半仍然相连会无限递归。递归终止条件是空链表或单节点。合并阶段用哨兵节点简化头插逻辑，比较两个头节点的值，取小者接到结果尾部。时间复杂度 O(n log n)，空间是递归栈的 O(log n)，若要求原地稳定排序，链表归并比数组归并更有优势，因为合并只需改指针、不需要额外数组。

**找出缺失的数字**：最优解是原地标记，时间 O(n)、额外空间 O(1)。做法是遍历数组，把 `nums[i]` 的绝对值减一作为下标，将该位置上的元素取负；第二遍遍历，仍为正数的下标加一即为缺失值。注意两个坑：一是元素可能已经被前面的步骤取负，取下标前必须取绝对值；二是原数组里可能有重复值，同一位置被取负两次会变回正数，所以取负前要判断 `nums[idx] > 0`。另一种写法是交换归位（把每个数换到它该在的位置），最后扫描位置与值不匹配的下标，逻辑更直观但交换次数更多。

**笔试备考的取舍**：这套卷子的结构（选择 + 代码补全 + 编程）说明它考的是 C 语言基本功与算法熟练度，而不是八股深度。选择题里的 TCP/UDP、二分查找属于必须秒答的题；代码补全考的是「能不能读懂别人的骨架并补上正确的循环与边界」，比从零手写更接近真实工作；编程题难度不高，卡人的往往是读题和边界。备考时按「基础语法与指针 → 常用数据结构手写 → 高频算法题」的顺序过一遍，比刷偏题有效。
