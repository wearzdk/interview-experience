### 《面试题目》

1. 缓存击穿是什么，如何防范？
2. Redis 实例只有一个，为什么需要分布式锁？分布式锁锁的是什么？
3. 查某个日志文件中包含 error 的行数，写出命令。
4. 了解 Java 中的内存泄漏吗？

### 《参考解析》

**缓存击穿要先和穿透、雪崩分开**。击穿是「单个热点 key 过期的一瞬间，大量并发请求同时发现缓存没有，一起回源查库」；穿透是「查一个数据库里根本不存在的 key，每次都打穿」；雪崩是「大批 key 在同一时刻集中过期」。三者常被混着问，先把定义分清就已经拿了一半分。击穿的防范有三类做法：互斥重建，用 `SET NX` 或进程内的 singleflight 只放一个请求回源，其余请求短暂等待或直接返回旧值；逻辑过期，value 里存业务过期时间而不是依赖 Redis 的 TTL，读到时发现过期就异步重建、同步返回旧值，保证不阻塞；热点数据永不过期加后台定时刷新。工程上还要补三件事：等待要有超时上限，不能无限阻塞；回源失败要能降级返回旧值并打点；重建完成后做一次双检，避免锁释放瞬间又被并发打穿。防穿透用空值缓存或布隆过滤器，防雪崩用随机 TTL 加多级缓存。

**「只有一个 Redis 实例，为什么还要分布式锁」考的是锁的边界**。锁保护的从来不是 Redis，而是多个业务进程对同一份业务资源的操作，比如多个实例同时修改同一条订单的状态。在单个 JVM 里用 `synchronized` 或 `ReentrantLock` 只能管住本进程的线程，管不到另一台机器上的进程；Redis 只有一台，但访问它的业务进程可以有很多个，它们各自的进程内锁互相看不见。另一半考点是「Redis 单条命令原子，不等于一串操作原子」：`GET` 判断状态再 `SET` 修改，这中间可能被其他进程插入，所以需要把「读—判断—写」整段串行化。实现上标准的写法是 `SET key uniqueValue NX PX 30000` 抢锁，value 用 UUID 或「实例 id + 线程 id」保证只有持锁者能释放，释放用 Lua 脚本比对 value 后删除，避免误删别人的锁；业务执行时间不确定时要有看门狗续期。再往深一层可以谈两个坑：主从切换时锁可能丢失，需要 fencing token 或接受「锁只是降低冲突概率，最终靠幂等与唯一约束兜底」；以及 Redlock 在时钟漂移与网络分区下的争议。面试时把这句说出来基本就到位了：分布式锁保证的是「大多数情况下只有一个执行者」，真正的正确性要靠数据库唯一索引、状态机与幂等来兜底。

**统计日志中含 error 的行数**：最直接的写法是 `grep -Fc -- 'error' app.log`。`-F` 表示按普通字符串匹配而不是正则（日志里出现 `[`、`.` 这类字符时不会被当成元字符），`--` 表示后面的参数不再当选项解析，`-c` 统计匹配的行数而不是出现次数。这里有两个容易错的点必须主动说明：同一行出现两次 error 仍然只算一行，如果要统计出现次数得用 `grep -Fo -- 'error' app.log | wc -l`；`grep` 默认区分大小写，大写 `ERROR` 匹配不到，要一起统计就加 `-i`。再补两个实际场景的变体：日志是压缩文件用 `zgrep -c`，要多文件汇总用 `grep -rc` 或 `grep -rhc ... | awk -F: '{s+=$2} END {print s}'`，只统计某个时间段的日志可以先 `awk` 过滤时间范围再交给 grep。能把这些边界讲清楚，比背下一条命令更能体现熟练度。

**Java 内存泄漏的本质是「对象已经没用了，但仍然被 GC Root 可达」**。Java 有垃圾回收，所以泄漏不是忘记 free，而是引用没有及时断开。常见场景有五类：静态集合只增不减（缓存、注册表、全局 Map）；ThreadLocal 用完不 `remove`，在线程池里线程长期存活，value 跟着线程一起活着；监听器与回调注册后没有反注册；连接、流、游标没有在 finally 或 try-with-resources 里关闭；内部类或匿名类隐式持有外部类引用。排查路径是：先用 `jstat -gcutil` 看老年代是否持续上涨、Full GC 后仍不回落；再用 `jmap -histo:live` 看哪类对象数量异常；然后 `jmap -dump` 导出堆转储，用 MAT 或 VisualVM 看支配树与 GC Root 引用链，找到「谁还拽着它」。线上可以在启动参数里加 `-XX:+HeapDumpOnOutOfMemoryError` 保留现场。预防手段是对缓存设上限与过期（Caffeine、Guava Cache 的 maximumSize 与 expireAfterWrite）、ThreadLocal 用 try-finally 清理、资源用 try-with-resources、对外提供的注册接口配套反注册。回答时给出一个你真实处理过的例子（哪个对象、被谁持有、怎么定位、怎么修），比罗列八种场景更有说服力。
