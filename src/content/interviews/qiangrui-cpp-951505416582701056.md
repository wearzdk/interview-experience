### 《参考解析》

**多进程通信的选型**：管道（匿名管道只能用于亲缘进程，命名管道可跨进程但仍是单向字节流）、消息队列（有消息边界，内核维护，适合小消息）、共享内存（最快的进程间数据传输方式，省去两次拷贝，但必须自己做同步）、信号量（不传数据，只做同步与互斥）、信号（只能传一个编号，用于事件通知）、Socket（可跨主机，Unix domain socket 在本机性能好且支持传递文件描述符）。结合项目说明时，要讲清为什么选它：需要传大块图像或帧数据就用共享内存加信号量；需要跨机器或统一编址就用 socket；只需要事件通知就用信号。优缺点要落到「拷贝次数、是否有消息边界、是否需要自己同步、能否跨主机」这四个维度，比背名词有说服力。

**线程池各阶段**：创建阶段确定核心线程数、最大线程数、任务队列容量与拒绝策略，线程数按任务类型取——CPU 密集接近核数，IO 密集按等待比例放大，不能一律取核数两倍。运行阶段要保证任务异常不会静默吃掉线程，工作线程的循环里捕获异常并记录；任务要可取消，长任务要检查停止标志。高并发下重点是队列与背压：无界队列会把内存打满，有界队列要配拒绝策略（丢弃、调用方执行、丢弃最旧），并暴露队列长度、活跃线程数、任务耗时等指标。销毁阶段先停止接收新任务，再等待在途任务完成（设超时），最后唤醒并 join 所有线程；不要在析构里无限等待，否则进程退出会挂住。

**STL 组件与 map/set**：容器（序列容器 vector、list、deque，关联容器 map、set，无序容器 unordered_map、unordered_set）、迭代器（容器与算法的胶水，分输入、输出、前向、双向、随机访问五类）、算法（sort、find、transform 等，通过迭代器与容器解耦）、仿函数（可被算法调用的对象，用于定制比较与运算）、适配器（stack、queue、priority_queue 与反向迭代器）、分配器（把内存管理从容器中抽出来）。map/set 的查找效率来自底层红黑树：它是有序平衡二叉搜索树，查找、插入、删除都是 O(log n)，且中序遍历天然有序，所以支持范围查询与按序输出。

**自定义排序与 Lambda**：`std::map` 的第三个模板参数是比较器类型，可以传一个定义了 `operator()` 的仿函数，或传函数指针；C++11 之后也可以传 lambda，但 lambda 的类型是编译器生成的匿名闭包类型，必须用 `decltype` 取类型再作为模板参数，或者用 `std::function` 包一层（后者有类型擦除开销）。更常见的做法是把排序规则放在元素类型里，或对 vector 用 `std::sort` 传 lambda。lambda 与仿函数的区别：lambda 是语法糖，编译器生成一个带 `operator()` 的类，捕获列表成为它的成员；仿函数是手写的类，可以有多个重载、可以有状态和继承，也能显式写出类型名。lambda 的优势是就地定义、可捕获外部变量；仿函数的优势是可复用、可命名、可重载，模板里更好用。

**四种类型转换**：`static_cast` 用于相关类型之间的编译期转换（数值转换、向上转型、void* 与其他指针互转），不做运行期检查；`dynamic_cast` 用于多态类型的向下转型与交叉转型，依赖 RTTI，失败时指针返回空、引用抛 `bad_cast`，有运行期开销；`const_cast` 只增删 const/volatile 限定，用于对接不接受 const 的旧接口，前提是对象本身不是 const；`reinterpret_cast` 是底层的位模式重解释，用于指针与整数、无关指针类型之间的转换，结果依赖平台，除底层协议解析外应避免。C 风格转换会把上面几种混在一起，难以看出意图，C++ 代码应显式使用对应的一种。

**auto 的实现**：auto 不是运行期类型推断，而是编译期的占位符。编译器在语义分析阶段根据初始化表达式推导出类型，规则与模板实参推导一致（会丢弃顶层 const 与引用，除非写 `auto&`、`const auto&`），推导结果在编译期就固定，生成的代码与手写具体类型完全一致，没有运行期开销。IDE 的「悬浮显示类型」则是另一件事：它靠 Clangd、语言服务等前端解析同一套语义得到类型，再展示出来，与编译器共享推导规则但不是同一个实现。

**实习意向类问题**：到岗时间、答辩安排、能否接受实习合同都如实回答，给出明确日期比含糊的「随时可以」可信。被问实习薪资时给一个区间并说明依据（同城同岗位的普遍水平、自己的可投入时间），不要反问「你们给多少」。被问是否愿意长期留下时，把判断落到具体的事上：这个岗位做什么、自己能学到什么、转正后的路径是什么，比空泛表忠心有效。
