### 《参考解析》

**SSE 是服务端单向推送，重连要自己补三件事**。它基于一条长 HTTP 响应，`Content-Type: text/event-stream`，服务端按 `data:`、`event:`、`id:` 格式持续写，浏览器用 `EventSource` 接收，断线后会自动重连并带上 `Last-Event-ID`。工程上要补的是：服务端按 id 续传、避免重连丢消息；心跳注释行防止中间代理按空闲超时掐断；客户端自己限制重连次数并退避，因为 `EventSource` 默认的固定间隔在服务端故障时会变成重连风暴。若需要双向通信或二进制，才考虑 WebSocket。

**同步计算卡住的是渲染时机，不是请求**。JS 在主线程上执行，点击事件里那段长同步计算没跑完，浏览器就没有机会做样式计算与绘制，所以「发布中」写进 state 也上不了屏；把重活挪进 Promise 的回调、点击处理函数先返回，浏览器就有机会先把「发布中」画出来，再执行那段计算。边界在于：`Promise.resolve().then` 只是微任务，仍在本次渲染之前跑完，中间态照样画不出来；真正让出渲染的是跨到下一个宏任务或等待真实异步（定时器、网络、rAF）。更稳的做法是先 setState，再用 `requestAnimationFrame` 让出一帧，或把重计算交给 Web Worker。

**input file 不是随便选的，是浏览器安全模型的产物**。网页不能凭路径读本地文件，否则任何站点都能扫你的磁盘；`<input type="file">` 是用户主动授权的最小入口，拿到的 `File` 对象只能读内容、拿不到真实路径（只有 `name` 和 `size`）。替代方案是拖拽 `drop`、粘贴、或 File System Access API 的 `showOpenFilePicker`，但后者兼容性有限、同样必须由用户手势触发。想「直接打开文件夹填路径」在 Web 上做不到。

**左右布局至少有四种写法，面试要讲清代价**。Flex 最常用：左 `flex: 0 0 200px`，右 `flex: 1`，并给右侧加 `min-width: 0`，否则内部长文本或 `pre` 会把容器撑破。Grid 是 `grid-template-columns: 200px 1fr`，语义更直接。传统写法是左 `float: left` 加右 `margin-left: 200px`，要清浮动。固定定位则给右栏 `left: 200px`。移动端还要考虑窄屏降级为上下堆叠，用媒体查询切换。

**Hooks 的规则来自它的存储方式**。React 按调用顺序把 state 挂在 fiber 的链表上，条件分支里调用会让顺序错位，第二次渲染取到别人的 state，所以只能在顶层调用。`key` 则是 diff 时判断「这个节点还是不是原来那个」的依据，稳定唯一的 key 能让组件复用、保住内部状态；用数组下标当 key，在插入或排序时会造成状态错位和多余挂载。所谓 Hooks 的「副作用」，指 `useEffect` 在渲染提交后执行、依赖数组决定重跑时机，清理函数没写就会泄漏订阅与定时器。

**tool calling 是把模型输出约束成一次结构化调用**。应用把可用工具的名称、用途和参数的 JSON Schema 一起发给模型，模型返回工具名与参数对象，由宿主程序校验后真正执行，再把结果回灌给模型继续推理。入参定义必须是机器可校验的 schema（类型、枚举、必填、嵌套结构），出参同样要约定，否则模型没法根据返回值决定下一步。只在提示词里写「请按这个格式」属于软约束，解析失败率会随复杂度上升；要稳定就用厂商的 function calling 或约束解码。执行侧还要做参数合法性校验与超时，不能信任模型给的路径和 ID。
