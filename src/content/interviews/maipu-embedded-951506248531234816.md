### 《参考解析》

**select 与 epoll**：select 用位图传递 fd 集合，每次调用都要把集合从用户态拷到内核态、返回后再遍历全部 fd 找就绪项，且有 `FD_SETSIZE`（通常 1024）上限；poll 用数组去掉了数量上限，但仍需全量拷贝与遍历。epoll 把「注册」与「等待」分开：`epoll_ctl` 把 fd 挂到内核的红黑树上，`epoll_wait` 只返回就绪链表里的项，复杂度与就绪数相关而不是与总 fd 数相关，且没有数量上限。epoll 的水平触发（LT）与边缘触发（ET）要讲清：LT 只要缓冲区还有数据就会持续通知，编程简单；ET 只在状态变化时通知一次，必须配非阻塞 fd 并循环读到 `EAGAIN`，否则会丢事件。缺点是 epoll 是 Linux 专有，跨平台要用 kqueue、IOCP 或封装。

**Reactor 模型**：主线程（acceptor）负责 `epoll_wait` 与 accept，把新连接分发给从线程（sub reactor），每个从线程各自持有一个 epoll 实例与事件循环，连接固定绑定到某个从线程，避免多线程竞争同一 fd。one loop per thread 的好处是无锁化、缓存友好、单个连接的事件顺序确定；代价是跨线程投递任务需要队列与唤醒机制（eventfd 或 pipe）。要能说清「为什么不在回调里做耗时操作」——会阻塞整个事件循环，长任务必须投递到业务线程池。

**Qt 对象树**：`QObject` 构造时指定 parent 后会被加入父对象的子对象列表，父对象析构时会遍历并 delete 所有子对象，所以删除父节点时子节点会一并被销毁，不需要手动 delete。这也意味着栈上创建的子对象不能再指定 parent（否则会二次释放），以及 `deleteLater()` 与直接 `delete` 的区别：前者把删除排到事件循环，适合在信号槽回调中安全地删除自己。跨线程的对象要注意线程亲和性，GUI 对象只能在主线程操作。

**多线程申请内存**：glibc 的 malloc 为每个线程维护 arena（默认 arena 数量与核数相关），小内存从线程自己的 arena 分配以减少锁竞争，但多个线程仍可能落到同一个 arena，此时要加锁；大块内存走 mmap，直接向内核申请，代价是系统调用与页表开销。频繁申请释放小块内存会造成碎片与性能下降，常见对策是内存池（按固定大小分级，一次向系统申请大块再切分）、对象池、以及 `tcmalloc`/`jemalloc` 这类替换分配器。线程的内存是否共享：虚拟地址空间是进程级共享的，一个线程能访问另一个线程的堆对象，所以「独享」只是分配器的缓存归属，不是地址空间隔离；栈是每个线程独享的。

**I²C 与 SPI**：I²C 两根线（SCL、SDA），支持多主多从、靠地址寻址、有应答机制，速率通常 100k/400k/1M，适合传感器、EEPROM 这类低速外设；SPI 四根线（SCLK、MOSI、MISO、CS），全双工、无地址靠片选、速率可到几十 MHz，适合屏幕、Flash、高速 ADC。Linux 下用户态可通过 `/dev/i2c-*` 与 spidev 操作，内核态则实现 i2c_driver/spi_driver 并注册到总线。回答时结合自己实际接过的器件说时序与调试手段（示波器看波形、上拉电阻、地址冲突）。
