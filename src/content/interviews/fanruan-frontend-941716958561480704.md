### 《参考解析》

**埋点弱网与可靠上报**：弱网判断可以综合 `navigator.connection` 的 `effectiveType`、`rtt`，再结合请求超时率与心跳探测，不能只依赖单一信号。采集到的事件先写入 IndexedDB 队列，带上事件 id、时间戳、重试次数和 sessionId；发送以服务端返回 2xx 和确认 id 为成功，失败按指数退避重试，超过上限就留在本地，等下次启动或网络恢复补发，服务端按事件 id 做幂等去重。页面卸载时在 `pagehide` 或 `visibilitychange` 里用 `navigator.sendBeacon` 或 `fetch(..., { keepalive: true })` 发送小包，keepalive 的请求体通常限制在 64KB 以内，不能塞大 payload。

**左侧固定、右侧自适应**：flex 最直接，容器设 `display:flex`，左侧 `flex:0 0 240px`，右侧 `flex:1`，并且右侧一定要加 `min-width:0`，否则内部长内容会把右栏撑破；也可以用 grid，写成 `grid-template-columns:240px 1fr`。右侧需要独立滚动时再补 `overflow:auto`。

**Vue 响应式与 computed/watch**：Vue2 用 `Object.defineProperty` 递归劫持属性的 getter/setter，数组靠重写变更方法监听，新增或删除属性得用 `Vue.set/delete`；Vue3 改用 `Proxy` 代理整个对象，能直接监听新增、删除和数组索引，配合 `effect` 完成依赖收集与触发。`computed` 有缓存，依赖不变就不重新求值，适合派生状态；`watch` 不缓存，依赖变化就执行副作用，适合发请求、写缓存这类异步或昂贵操作，可配置 `deep`、`immediate`、`flush`。

**协同编辑冲突**：两人同时编辑的核心是并发操作如何合并。OT 把操作转换后按服务端定序应用，需要中心节点；CRDT 让操作满足交换律，靠逻辑时钟和数据结构实现最终一致，适合离线与去中心化，代价是元数据和内存开销更大。实际还要处理插入位置偏移、插入与删除交叉、离线期间操作积压，以及断线重连后的版本对齐，通常用版本号或操作序号做增量同步。

**transform: scale 为何让 fixed 失效**：`transform` 会为元素创建新的包含块，子元素的 `position:fixed` 不再相对视口，而是相对这个被缩放的元素定位，坐标和宽高都按缩放后的盒子计算，于是出现偏移。解决方式是把 fixed 层通过 Portal 挂到 `body`，或避免在祖先上使用 transform，改用 `position:absolute` 加视口尺寸自行计算。
