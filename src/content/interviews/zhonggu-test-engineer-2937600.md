### 《面试题目》

1. 说一下你这几段经历的工作内容、离职原因与薪资。
2. 你这几份工作有纯软件相关的测试吗？我们这边是外包做游戏的。
3. 你会哪些工具？讲讲你了解的。
4. 假如给你一个登录功能，输入账号密码点击登录，你觉得应该测哪些？
5. 这个登录功能的性能应该怎么测试，用哪些工具？
6. Fiddler 你知道怎么用吗？说一下你是怎么用的。
7. Fiddler 怎么测试弱网，你测的是几 G 的？
8. JMeter 你知道怎么用吗？说一下它是怎么测试性能的。
9. Linux、MySQL、pytest 这些工具你工作中有用到吗？是怎么用的？
10. 你不是计算机专业的，那你这些课是怎么学的，报班吗？

### 《参考解析》

**登录功能的测试点要分维度列，而不是随手想。** 功能维度：正常登录、账号不存在、密码错误、账号为空/密码为空、超长输入、特殊字符与 SQL 注入尝试、大小写与空格处理、记住密码与自动登录、退出后再登录、多端同时登录（互踢策略）。安全维度：密码是否明文传输、是否有限流与锁定（连续错误 N 次锁定）、验证码是否可绕过、会话 token 是否可伪造、越权访问。兼容维度：不同浏览器与分辨率、移动端键盘遮挡、不同网络。体验维度：错误提示是否明确、加载状态、回车提交、密码可见切换。异常维度：服务不可用、超时、网络断开重连、并发重复提交（防重复下单/重复登录）。

**登录的性能测试。** 指标先定清楚：响应时间（P95/P99）、吞吐（TPS/QPS）、错误率、资源占用（CPU、内存、连接数）。场景分基准（单用户）、并发（逐步加压找拐点）、稳定性（长时间运行看内存泄漏）、峰值（突发流量）。工具用 JMeter 或 Locust 写脚本，参数化账号（CSV 数据集），加断言与集合点，配合监控（服务端 CPU、数据库连接数、Redis 命中率）。要注意登录通常涉及密码哈希与写会话，属于重操作，压测时要区分缓存命中与未命中，避免用同一账号压出假数据。

**Fiddler 的用法。** 核心是代理抓包：设置解密 HTTPS、按域名或进程过滤、查看请求与响应、用 Composer 重放与改造请求、用 AutoResponder 模拟返回、用断点（FiddlerScript 或工具栏）在请求前后修改参数。安全测试里常用它改请求参数（越权、改价、改数量）验证服务端校验。弱网测试用它设置上下行带宽与延迟（Rules → Performance → Simulate Modem Speeds，或自定义 FiddlerScript），模拟 2G/3G/4G 的带宽与丢包，观察加载、超时、重试与提示。面试官问「几 G」是在确认真实操作过，回答要能说出具体参数（例如 2G 上下行几十 kbps、延迟几百毫秒）与观察到的现象。

**JMeter 的流程。** 建线程组（并发数、循环次数、ramp-up）→ 加 HTTP 请求默认值与采样器 → 加参数化（CSV Data Set Config）与关联（正则或 JSON 提取器取 token）→ 加断言（响应码、响应体）→ 加定时器（模拟思考时间）→ 加监听器（聚合报告、察看结果树，正式压测时关掉避免自身开销）→ 分布式压测（多台 slave）→ 分析报告。要注意的是压测机自身可能成为瓶颈，以及被测服务的限流与缓存会让结果偏离真实。

**工具链与学习路径。** Linux 用于看日志、查进程与端口、定位资源问题；MySQL 用于造数据、核对落库、写查询验证；pytest 用于接口自动化（fixture、参数化、断言、报告）。非科班转测试的合理路径是「先补计算机基础（网络、操作系统、数据库）→ 学一门语言 → 做接口自动化项目 → 学性能与安全基础」。回答时给出具体的学习来源与产出（做过的项目、写过的脚本），比「报了个班」更有说服力。
