### 《参考解析》

**I2C 完整时序**：起始条件是 SCL 高电平时 SDA 由高变低；停止条件是 SCL 高电平时 SDA 由低变高；数据在 SCL 低电平时改变、高电平时稳定采样；每传输 8 位后第 9 个时钟由接收方拉低 SDA 表示 ACK，保持高电平表示 NACK。地址帧是 7 位地址加 1 位读写方向，部分器件用 10 位地址。重复起始条件（Sr）用于在不释放总线的情况下切换读写方向或切换寄存器地址。上拉电阻是因为 I2C 是开漏输出，只能拉低不能拉高，高电平靠上拉产生，也实现线与（多设备同时拉低不会短路）；容性负载决定上升沿速度，上拉过大上升沿变慢、过小功耗增加。

**NACK 与总线锁死的排查**：NACK 分几种：地址 NACK（从设备不在或地址写错，注意 7 位与 8 位写法）、数据 NACK（从设备忙、寄存器不可写、超出范围）、时序问题（速率过高、上拉不足）。排查顺序：确认地址与读写位、用 i2cdetect 扫地址、看波形确认 ACK 位、降低速率重试、检查电源与地。总线被拉低锁死常见于主设备在从设备传输中途复位，从设备仍在等待时钟把 SDA 拉低；处理办法是手动发送 9 个 SCL 时钟让从设备释放，再发停止条件，或在驱动里做总线恢复（GPIO 模拟时钟）；根本上要在复位流程里先复位 I2C 外设与从设备。

**SPI 四种模式**：CPOL 决定空闲时时钟极性（0 为低、1 为高），CPHA 决定在第一个还是第二个边沿采样（0 为第一个边沿、1 为第二个）。组合出 Mode 0 到 Mode 3，主从必须一致。常见器件是 Mode 0 或 Mode 3。调试时用逻辑分析仪看 CS 拉低后第一个时钟边沿数据是否稳定，采样点错位会读到移位的数据。

**platform 总线与设备树**：platform 总线是内核里的一条虚拟总线，用于挂接不依赖具体物理总线枚举的片上设备。设备（platform_device）描述资源（寄存器地址、中断号、时钟、GPIO），驱动（platform_driver）实现操作，二者通过 name 或设备树的 compatible 属性匹配，匹配成功后调用驱动的 probe。设备树把硬件描述从代码里抽出来，同一份内核镜像可以适配不同板子，改硬件只改 dtb；DTS 是板级描述，DTSI 是被 include 的公共部分，节点同名时后包含的会覆盖先前的属性，可以用 `/delete-node/` 删除。新接入 I2C 传感器的流程：查原理图确认总线号与地址 → 在设备树的总线节点下加子节点（compatible、reg、中断、供电 GPIO）→ 编译 dtb 并确认 `/proc/device-tree` 里有节点 → 驱动里用 `of_match_table` 匹配 → probe 里申请资源、注册字符设备或 input 设备 → 用 i2cdetect 与 i2cget 验证通信。

**字符设备驱动框架**：分配设备号（静态或动态）→ 定义 file_operations → 用 cdev_init/cdev_add 注册 → 用 class_create/device_create 在 /dev 下创建设备节点 → 实现 open/read/write/ioctl/release。用户态 open 时通过 VFS 找到 inode 对应的 cdev，取出 file_operations 并填充 file 结构，之后 read/write 就是调用驱动里注册的函数。用户态不能直接操作寄存器，是因为需要内核做地址映射、权限检查、并发与资源管理，直接访问会破坏隔离并可能让系统崩溃。

**中断上下半部**：上半部在中断上下文执行，要求快、不能睡眠，只做清中断标志、保存必要数据、唤醒下半部；下半部做耗时处理。tasklet 运行在软中断上下文，不能睡眠，同一 tasklet 不会并发执行；workqueue 运行在内核线程上下文，可以睡眠，适合需要调用可能阻塞的接口（I2C 读写、内存分配）的场景。自旋锁在持有期间不能睡眠，所以中断上下文只能用自旋锁；互斥锁会睡眠，只能用于进程上下文。

**启动优化到 5 秒**：先测量再优化，用 `initcall_debug`、`bootgraph`、`systemd-analyze`（或 buildroot 的启动脚本计时）找出各阶段耗时。优化方向：U-Boot 阶段裁剪无关驱动与命令、关闭调试输出、跳过不必要的自检；内核阶段裁剪配置、减少内置驱动、延迟初始化非关键模块、用 initramfs 或直接挂载；用户态阶段精简 init 脚本、并行启动服务、延迟非关键服务、用静态链接减少动态加载。要区分「必须提前初始化」的（存储、显示、关键外设）与「可以后置」的（网络服务、日志、UI 动画），并把可后置的改成按需加载。

**内存异常与性能排查**：段错误先用 core dump 加 gdb 看栈，或用 strace 看最后一个系统调用与信号；内存泄漏用 valgrind 或 kmemleak（内核态）；性能用 top 看进程、perf top 看热点函数、perf record/replay 做采样分析、iostat 与 vmstat 看 IO 与内存压力。网络问题用 tcpdump 抓包加 Wireshark 分析重传、乱序、窗口；MTU 是链路层最大传输单元，超过会分片，路径 MTU 不一致会导致大包丢失。
