### 《参考解析》

**LangChain 多节点实践要讲成数据契约，而不是组件清单。** 面试官问「三个节点分别实现了什么能力」，实质在确认你知不知道自己那条链路的输入输出。建议按「输入解析 → 节点 A → 节点 B → 节点 C → 输出」画一遍，每个节点说清四件事：输入什么、输出什么（字段与类型）、依赖了什么外部能力（模型、工具、检索、数据库）、失败时怎么处理。链路上的共享状态要指明（LangChain 里是 state／上下文字典在节点间传递），并说明节点为什么这么切——是按职责边界切（识别、检索、生成）、按可测试性切（每段能单独跑评测）、还是按可缓存性切。要主动交代取舍：链路越长上下文越容易丢，节点间要传递结构化的中间结果而不是整段自然语言；串联的节点越多累计时延越大，能并行就并行。

**意图识别加工具挑选，工程上的答案是「收敛候选 + 阈值兜底」。** 第一层用轻量手段（关键词、正则、向量召回、分类小模型）把几十个工具收敛到三五个候选，再让模型在候选里做选择——搜索空间小了，准确率立刻上去，成本也降；第二层把工具描述写清楚，重点不是「这个工具做什么」而是「什么时候该用它、什么参数必填、什么情况不要用」，让模型有条件判断；第三层设置信度与校验门，低置信度不进业务链路而走澄清追问，参数不符合 schema 直接拒掉重问；第四层允许一次请求多意图，拆成多个子任务分别执行再合并，或者按优先级追问先做哪个。评测口径要能说出来：意图分类准确率与混淆矩阵、工具选择准确率、澄清率、以及澄清之后的转正率。

**让 AI 稳定吐 JSON，靠的是约束加校验，不是反复叮嘱。** 优先用接口级的结构化输出能力（function calling、JSON schema、`response_format`），把 schema 直接作为参数传给模型；schema 里字段尽量扁平、必填项明确、枚举值穷举，避免自由文本嵌套。提示里给一两个输入输出示例比写一堆「请严格输出 JSON」有效。拿到输出后必须有程序侧校验（zod／pydantic），解析失败就走重试并且把错误信息回喂——重试要有上限（两三次），超限就降级成明确报错而不是硬造内容。还要把两类失败分开统计：格式失败（解析不了）和语义失败（解析得了但字段不合业务约束），前者靠约束与重试，后者靠后置校验与业务规则兜底。温度调低、减少无关上下文、把长输出拆成多次小输出，都能进一步降低抖动。

**虚拟滚动的原理是「只渲染可视区」，关键是高度与位置要能算准。** 基本结构是：容器设固定高度并允许滚动，内部放一个撑满总高度的占位元素（`total = itemHeight * count`），真正渲染的只有可视区上下各加若干条缓冲的项，用绝对定位或 `translateY` 把列表整体偏移到正确位置；滚动时按 `scrollTop / itemHeight` 算出起始索引，回收离开缓冲区的 DOM。真正的难点在不定高：要么先给预估高度、渲染后测量并回写缓存、再修正总高度与偏移（否则滚动条会跳），要么用 `IntersectionObserver`／`ResizeObserver` 做动态测量。要能说出取舍：定高实现简单、性能最好，不定高体验更自然但要做高度缓存与锚点修正。

**「为什么不用 sleep 等渲染」是同一类思路的延伸——等待要用事件而不是时间。** 固定 sleep 的毛病是两头不讨好：网络慢时等不够、快时白等，而且测试会变慢、不稳定。正确做法是等可观测的事件：等待目标元素出现或可见（轮询加超时上限，或用框架提供的等待条件）、等请求完成的生命周期钩子（等待某个 XHR／fetch 结束或网络空闲）、等 DOM 变化（`MutationObserver`／`ResizeObserver`）、等框架的渲染完成信号（`nextTick`、状态变为就绪）。核心原则是「条件满足即继续，超时报错并留下现场（截图、DOM 快照、日志）」，这样失败时能复现而不是靠猜。

**用 AI 按 spec 开发的流程，面试官其实在问「你怎么保证它不乱写」。** 步骤是：先把需求写成可执行的 spec（接口签名、数据结构、边界与错误语义、验收标准），明确改动范围与不允许碰的文件；让 AI 先给方案与影响面再动手；用可执行的验证做门禁——类型检查、lint、单元测试、必要的运行验证，并且要求 AI 自己跑通再说完成；人工只审关键决策与安全敏感处。关于 token 获取要有实际经验：走官方 API key 或企业订阅授权，注意密钥不要进仓库、按环境注入、设置用量上限与审计。这类团队还会关心你的自动化测试背景（恰好是「让 AI 的产出可被验证」的基础），把「我怎么为 AI 写的代码搭验证」讲成一套方法，比单说会用工具更有说服力。

**开放与背景类问题要答得稳。** 医药平台这类业务题，答题角度是「合规优先 + 数据敏感 + 供应链与院端场景」：药品流通有资质与追溯要求，数据不允许随意外发，所以 Agent 的价值更多落在内部效率（资料检索、单据核对、客服辅助）而不是对外的自由生成；能说出这类边界比堆业务名词得分高。至于专业、绩点、前端岗位前景这类问题，按事实讲自己的判断就好——前端岗位在收缩的是重复的页面搭建，增长的是工程化、性能与 AI 应用方向，把「我在往哪走、已经做了什么准备」讲清楚；被问「这个岗位是秋招还是实习转正」直接如实回答，并顺势问清入职时间与培养路径，正好接上反问环节。
