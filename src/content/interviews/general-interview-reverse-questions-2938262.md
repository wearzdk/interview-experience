### 《面试题目》

1. 这个组最近在做什么？
2. 团队的协作方式和 code review 怎么走？
3. 我进组前三个月可能先接哪一类活？
4. 我之前在某个项目里按业务域拆过服务，想对一下你们的新服务是按业务拆，还是按稳定性拆？（把「考一下」改成「对一下」的示例问法）

不宜在反问环节问的：贵公司未来五年规划、我能转正吗、加班多吗、JD 里已经写明的信息（例如 JD 写了双周迭代，就不必再问迭代周期）。

### 《参考解析》

**反问是面试流程里唯一由候选人主导的环节，说「暂时没有」等于主动放弃一次表达机会**。帖主的做法是把它当作固定准备项：每次面试前先定三个问题，而不是现场想。

**第一步自己列，不让模型凭空编**。打开备忘录写三类：这个组最近在做什么、协作与 code review 怎么走、进组前三个月会先接哪类活。这一步的目的是诚实——模型最容易给出「贵公司未来五年规划」这类问了等于没问的问题，因为它不知道你真的关心什么。

**第二步用 JD 与公开信息约束模型，并强制每条问题带依据**。提示词要点是：只基于给出的 JD 与公开材料提问；每条问题引用材料里的原句作依据；不问 JD 已经写明的答案；只问对方具体做事方式，不问展望与愿景；禁止编造对方没写过的产品名、团队名与技术栈；材料不足时标注「不要问」。把 JD 全文连同摘录的五到八行公开信息一起贴进去，输出才有可核对的基础。

**第三步把问法从「考一下」改成「对一下」**：先补一句自己做过的相关事，再问对方怎么做。区别在于前者让面试官觉得被审视，后者是同行之间的技术对齐，也顺带把你的经验讲出来了。模型常常把「参与」写成「负责」，改回真实职级，不要让反问环节变成夸大经历的场合。

**第四步按公司类型删到三个，出声过一遍**。技术岗优先保留：业务当下在推进什么、协作与评审节奏、这个岗位三个月内会接手的活；薪资福利留到后续沟通。三个问题读出声，卡住的换成更短的句子；同一家公司换面试官可以调整顺序，但不要在几轮里复读同一句。

**三个坑**：模型会发明对方没有的业务线，开口前必须能指回你贴进去的原句；不要问让对方难答的封闭题（能不能转正、加班多不多），换成对方愿意讲的具体做法；JD 已经写明的内容不要再问，暴露的是没读材料。
