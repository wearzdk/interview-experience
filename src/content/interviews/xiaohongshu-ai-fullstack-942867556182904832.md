### 《面试题目》

1. 自我介绍。
2. 主要在问项目。
3. 发送一次网页请求的具体过程是怎样的？
4. 网页的短链接、长链接是怎么回事？对 WebSocket 有了解吗？
5. 客户端请求一个网页，为什么第一次很慢、第二次很快？分析这个现象。
6. 进程和线程的区别？
7. 你怎么和 AI 协作？
8. 编程题：实现 LRU 缓存。

### 《参考解析》

**一次网页请求的完整链路**：浏览器解析 URL → DNS 解析（浏览器缓存、系统缓存、递归解析）→ 建立 TCP 连接（三次握手，HTTPS 再加 TLS 握手）→ 发送 HTTP 请求 → 经过 CDN/负载均衡/网关到应用服务 → 服务查缓存和数据库 → 返回响应 → 浏览器解析 HTML、构建 DOM 和 CSSOM、布局、绘制，过程中继续请求 JS/CSS/图片。

**第一次慢、第二次快，主要是缓存和连接复用**。DNS 有缓存、TCP/TLS 握手可以复用（keep-alive、HTTP/2 多路复用）、静态资源命中浏览器缓存或 CDN、服务端也有页面缓存和 JIT 预热。第一次要付握手、建连、冷启动、编译和回源的代价，第二次这些都被省掉了。分析现象时按「网络层 → 传输层 → 应用层 → 渲染层」逐层排查。

**短连接是每次请求新建 TCP、用完关闭；长连接是复用同一条连接发多个请求**。HTTP/1.1 默认 keep-alive 但同一连接上请求串行，HTTP/2 用多路复用解决队头阻塞。WebSocket 是在 HTTP 上升级出来的全双工协议，握手一次后双方可以随时推送，适合聊天、协同编辑、实时行情这类双向高频场景。

**LRU 的标准实现是哈希表 + 双向链表**。哈希表存 key 到链表节点的映射做到 O(1) 查找，双向链表维护访问顺序：get 命中就把节点移到头部，put 时如果容量满了就删尾节点。Java 里可以用 `LinkedHashMap` 的 accessOrder 模式，但面试一般要求手写，注意哨兵节点和容量为 0 的边界。

**「怎么和 AI 协作」要答出流程而不是态度**：需求先自己拆清楚、定接口和验收标准，再让 AI 在明确边界内实现；生成后自己 review、跑类型检查和测试、在真实页面上验证；复杂改动拆小步，避免一次给它太大上下文。
