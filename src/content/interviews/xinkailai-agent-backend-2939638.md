### 《面试题目》

1. 说一下你的项目。在 OPPO 平常都怎么干活？
2. 说一下整个 Agent 流程。
3. 说一下怎么评估 Agent。
4. 说一下 MySQL 底层。
5. 说一下线程池的参数和执行流程。

### 《参考解析》

**「Agent 的完整流程」要讲成分层的闭环，而不是一句「调模型」**：接收输入与上下文 → 规划（任务拆解，决定直接回答还是调工具）→ 工具选择与参数生成 → 执行工具并回填结果 → 观察结果、判断是否完成，未完成则继续下一轮 → 输出与落库。每一轮都要处理上下文增长、工具失败与超时、最大步数限制。工程上还要有 trace（每步的输入、模型输出、工具结果、耗时）与可回放，否则线上出问题没法定位。

**Agent 评估分三层**：结果层看任务成功率（端到端完成率）、正确性与副作用（有没有多调、误调工具）；过程层看步数、工具调用次数、无效循环率、首字与总耗时、token 成本；能力层用固定样例集覆盖典型任务、边界任务与历史失败案例，必要时人工标注一小批做基准。要注意评估集不能只放「问答题」——Agent 的价值在长链路任务，样例必须包含需要多步、需要调工具、需要处理失败重试的题目。评审用模型打分时要先用人工标注校准一致性，否则分数好看但不可信。

**MySQL 底层**：按「存储引擎—索引—事务—日志」四条线讲。InnoDB 用 B+ 树聚簇索引，叶子存整行，二级索引叶子存主键需要回表；事务靠 undo log 做回滚与 MVCC，redo log 做崩溃恢复（WAL，先写日志再刷脏页），binlog 做复制与归档，两阶段提交保证 redo 与 binlog 一致；锁有行锁、间隙锁、临键锁，隔离级别默认可重复读。

**线程池的参数**：核心线程数、最大线程数、空闲存活时间与单位、任务队列、线程工厂、拒绝策略。执行流程是——核心线程未满则新建核心线程执行；核心线程已满则入队；队列满则新建非核心线程直到最大线程数；仍满则触发拒绝策略（AbortPolicy 抛异常、CallerRunsPolicy 由提交线程执行、DiscardPolicy 静默丢弃、DiscardOldestPolicy 丢最老的）。参数怎么定要结合任务类型：CPU 密集型取核数附近，IO 密集型可以更大，且必须用有界队列，否则队列无限增长会把内存吃满。

**技术面「简单、聊天多」不等于稳过**：技术面通过只说明硬技能达标，HR 面考的是稳定性、动机与薪资匹配。这个案例里第二天 HR 面挂掉，常见原因是离职动机表达不清、对岗位与公司的预期不一致、或薪资区间对不上。准备时把「为什么离开上一家」「为什么选这家」「期望薪资与底线」三个问题写成一句话答案，前后口径一致，比临场发挥可靠。
