### 《面试题目》

1. 自我介绍。
2. 问 4 月份机考的情况。
3. 计算机组成原理了解多少？
4. CPU 由哪些部分组成？
5. 进程间通信方式有哪些？平时后端是怎么做的？
6. WebSocket 是基于什么协议的？
7. 项目追问：技术难点是什么、为什么这样选型、优化时怎么想的？
8. 手撕：共享屏幕 IDE，题目从聊天框发过来，不是 Hot100 的 hard 题。

### 《参考解析》

**CPU 的组成。** 从功能上分五块：运算器（ALU，做算术与逻辑运算、移位）、控制器（取指、译码、发控制信号，含 PC、IR、指令译码器）、寄存器组（通用寄存器、PC、状态寄存器）、高速缓存（L1 分指令与数据、L2 每核、L3 多核共享，解决 CPU 与内存的速度差）、总线接口与 MMU（取指取数、地址翻译、权限检查）。再往深一层要能提到现代 CPU 的几个机制：流水线（取指/译码/执行/访存/写回，靠分支预测和乱序执行填满流水）、超标量、SIMD，以及缓存一致性协议（MESI）和内存屏障——这些是「为什么多线程程序会看到乱序」的根源。如果面试官继续问「程序和内存的关系」，答冯·诺依曼的存储程序思想：指令和数据同在内存、按地址访问，瓶颈是 CPU 与内存的带宽差，所以才有 cache 与预取。

**进程间通信。** 按「有无内核参与、是否拷贝数据」来组织比罗列更清楚：管道与 FIFO（字节流、半双工、有亲缘关系或命名管道，适合简单流式数据）、消息队列（有消息边界、可按类型取）、共享内存（最快，零拷贝，但必须配信号量或文件锁做同步）、信号（异步通知，能带的信息极少）、socket（跨机，TCP/UDP，本机可用 Unix domain socket，比 TCP 回环少一层协议栈）、mmap 文件映射（大文件或共享内存另一种形态）。后端实际场景要具体：服务间用 HTTP/RPC（gRPC 走 HTTP/2）、异步解耦用消息队列（Kafka/RocketMQ）、同机多进程用 Unix domain socket（Nginx 与上游、Docker 与 containerd 都这么干）、需要极低延迟的大块数据用共享内存加信号量、缓存与分布式锁用 Redis 走网络。能补一句取舍：共享内存最快但同步最麻烦，socket 最通用但有序列化和拷贝开销，选型看的是延迟要求与耦合度。

**WebSocket 其实走 TCP。** 握手阶段是一个带 `Upgrade: websocket`、`Connection: Upgrade`、`Sec-WebSocket-Key` 的 HTTP/1.1 请求，服务端回 `101 Switching Protocols` 并给出 `Sec-WebSocket-Accept`（key 拼上固定 GUID 做 SHA-1 再 base64），之后这条 TCP 连接就不再是 HTTP 了，改用 WebSocket 自己的帧协议：FIN 位、opcode（文本/二进制/关闭/ping/pong）、MASK 位（客户端发往服务端必须掩码）、可变长度 payload。它和 UDP 半点关系没有——答成 UDP 是硬伤，因为 WebSocket 的所有特性（有序、可靠、面向连接）都来自 TCP。要能对比：轮询浪费请求、长轮询占连接且服务端要挂住请求、SSE 只能服务端单向推且是文本、WebSocket 全双工但需要自己维护心跳和重连。生产上的坑：中间代理要支持 Upgrade 并把读超时调大（Nginx 配 `proxy_set_header Upgrade/Connection`、`proxy_read_timeout`），否则连接被静默掐断；客户端要做 ping/pong 心跳、指数退避重连，重连后按消息序号补拉，不然会丢消息。

**项目追问的答法。** 面试官明说「不在意做了什么，只问技术难点」，所以别按时间线讲功能。用「难点是什么 → 为什么难（约束在哪）→ 你试过什么、为什么放弃 → 最后怎么解 → 效果怎么验证」的结构，一段话讲完一个点，最多两个点。技术选型要给出被否掉的备选和否掉的理由（数据量、延迟、团队熟悉度、运维成本），优化要给出前后对比的数字（P99、QPS、内存占用），没有数字就说出你是怎么量的。如果面试官明显不感兴趣，就压缩到一两句结论，把时间留给手撕——原帖这场项目聊了 20 分钟、对方没接住背景，说明讲得太细反而失分。

**手撕遇到没见过的题、语言还不合。** 先复述题意并确认输入输出与边界（有没有重复、是否要求原地、数据规模多大），这一步能避免写错方向；然后给暴力解并报复杂度，再讲优化路径，最后落代码。用 JavaScript 写而面试官看不懂时，主动把关键几行翻译成伪代码或口述语义（`Map` 是有序哈希、`sort` 默认按字符串比较要传比较器），别指望对方读语法。平时准备一门面试官大概率熟悉的语言（Java/C++）做备用，比临场解释语言特性稳。
