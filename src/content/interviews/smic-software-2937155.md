### 《面试题目》

1. 五分钟 PPT 展示：教育经历、项目经历、科研经历、实习经历。
2. 实习中最难的需求，怎么做的？
3. 实习中最大的收获是什么？
4. 在学校怎么做到科研和学生工作并行的？
5. 自己最大的缺点是什么？
6. 怎么看待 AI 迅速发展下，软件开发的工作？
7. 项目里的 Agent 设计讲一下。
8. 熟悉的技术栈有哪些，用 Java 开发过什么具体的项目？

### 《参考解析》

**五分钟 PPT 的结构**：一页个人概览（学校、专业、方向、求职意向），一页科研（课题、方法、成果），一页项目（最相关的一个，讲清你的角色与技术点），一页实习（做了什么、结果），一页技能与总结。每页只讲一个重点，控制在五十秒内；把最想让面试官追问的内容放在显眼位置，因为后续问题多半从 PPT 里挑。

**实习最难的需求**：选一个技术上有取舍、或跨团队协调成本高的需求。结构是：背景与约束（时间、依赖、数据量）→ 你考虑的方案与取舍 → 最终实现 → 结果指标。要说明「难在哪」而不只是「做了什么」，例如难在历史数据迁移不能停机、难在下游接口不稳定需要兜底。

**最大收获**：避免说「学到了很多」。给一个具体的能力变化：从只会写功能到会评估影响面、从被动接需求到会主动拆解、从单打独斗到会推动跨团队对齐，并用一件事佐证。

**科研与学生工作并行**：讲时间管理方法而不是「我很努力」：固定块时间、优先级排序、把学生工作流程化交给团队、关键节点提前排期。可以提一次冲突以及你怎么取舍的。

**最大缺点**：选真实的、不影响岗位核心能力的缺点，并说明正在怎么改。例如「早期过于追求一次做完美，导致交付节奏慢，现在会先交付可用版本再迭代」。避免「我太追求完美」这类伪装。

**AI 对软件开发的影响**：分三层答：编码环节效率提升（生成样板代码、单测、文档）、质量环节风险增加（需要更强的评审与测试）、角色变化（从写代码转向定义问题、设计架构、验证结果）。结论是「会用 AI 的人替代不会用的人，但判断力与工程能力仍是门槛」。可以补一句自己的实践：用 AI 做了什么、怎么验证生成结果。

**Agent 设计**：讲清目标、架构与评测。目标是什么任务、为什么需要 Agent 而不是固定流程；架构包括模型、工具、记忆、编排与兜底；评测包括用例集、成功率、成本与延迟。要能说出一个失败案例以及怎么修的。

**技术栈与 Java 项目**：按「语言、框架、中间件、数据库、工具」列，每个只说一句你用它做过什么。Java 项目选一个有真实数据量或并发要求的，讲清分层、接口设计、事务与异常处理。
