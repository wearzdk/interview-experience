### 《参考解析》

**指标归因是策略产品面试的主线**。被问「你的策略给指标贡献了多少」，不能只报涨幅。先拆指标：北极星指标是什么、由哪几个因子相乘或相加得到，你的策略作用在哪个因子上；再排除干扰：同期有没有其他策略上线、有没有大盘趋势与季节性、实验组与对照组是否可比。常见算法是 AB 实验的差值、灰度对照、双重差分（DID）与倾向得分匹配（PSM）；没有实验条件时，至少做分城市 / 分人群的对照与时间上的断点分析。回答「指标是业务算还是产品定」时，合理的分工是：业务与数据团队共建口径，产品提出要影响的因子与假设，最终口径由数据团队固化，避免产品自己挑一个好看的数。

**商业化与广告指标**：要能顺着链路说——曝光、点击、CTR、转化、CVR、CPA / CPX、ROI，平台侧还有 eCPM、填充率、广告收入、ARPU；电商广告还会看 GMV、客单价、复购。理解竞价：广告主按目标出价，平台在流量上做排序（eCPM = 出价 × 预估点击率 × 预估转化率，再叠加用户体验与生态约束），计费方式有 CPM / CPC / CPA / oCPX。答「对商业化产品的理解」时，落到「在用户体验、广告主 ROI 与平台收入之间做平衡」，并举一个具体机制（如频控、相关性门槛、冷启动探索）。

**策略产品与功能产品**：功能产品交付确定的交互与流程，需求边界清晰、验收靠可用性；策略产品交付的是「在不确定输入下持续给出较好决策」的系统，核心工作是定义目标与约束、设计信号与反馈、做实验与评估，交付物里包含模型 / 规则、评估集与监控。偏好哪一类要结合经历说，不要为了迎合岗位硬答。

**和研发的沟通**：面试官问「温和还是 push」，不是让你二选一，而是看你有没有方法。有效的方式是：需求先对齐目标与约束（为什么做、做到什么程度、什么时候要），把方案取舍和代价摆出来让研发参与决策，遇到分歧用数据或小成本验证解决；push 用在关键路径与明确承诺的节点上，而不是日常施压。需求 delay 的处理同理：尽早识别风险、拆里程碑、砍范围保核心、同步相关方预期，事后复盘根因。

**SQL 题**：

```sql
SELECT a.name,
       a.score + COALESCE(b.score, 0) AS total
FROM chinese_scores a
LEFT JOIN math_scores b ON a.student_id = b.student_id
ORDER BY total DESC;
```

要点：按学生 id 关联而不是姓名（重名）、用 LEFT JOIN 保留只有语文成绩的学生、`COALESCE` 处理缺失的数学成绩、按总分降序。若要求同分排序稳定，再加第二排序键。

**AI Agent 怎么搭建**：按「目标与边界 → 工具与数据 → 编排（单 Agent / 多 Agent、ReAct 或工作流）→ 记忆与上下文 → 评测与监控」讲。产品经理要能说清为什么用 Agent 而不是规则或普通模型调用、失败时怎么兜底、用什么指标判断它做得好（任务完成率、人工接管率、单次成本、时延）。

**卡片下发策略**：本质是推荐系统的一环——召回（候选卡片从哪来）、排序（用什么样的目标与特征）、约束（频控、多样性、疲劳度、冷启动探索）、评估（离线指标 + 在线 AB）。被问「你做了什么」，要区分「定目标与规则」和「实现模型」，别把算法团队的工作全揽到自己身上。

**AB 实验设计**：先给假设与要改变的指标，再定实验单元（用户 / 设备 / 城市）、分流比例与样本量，设置北极星指标、过程指标与护栏指标（时长、投诉、卸载），明确实验周期（覆盖完整周期，避免新奇效应），最后说怎么判断显著、怎么处理多个指标同时看带来的假阳性。上线决策不只看均值，还要看分群与长尾。

**产品体验评价与迁移**：用「用户—场景—任务—路径—反馈」拆：这个功能服务谁、在什么场景下用、要完成什么任务、路径有几步、每步的反馈是否清楚、失败时能否恢复。评价好坏要落到可验证的点（步骤数、成功率、等待时长、错误提示），再谈迁移到快手业务时目标用户与场景是否成立——不能因为一个功能在电商里好用，就假设它在内容社区同样成立。

**电商概念与动机题**：「为什么做产品」「成就感来自哪里」这类题不要背模板，用一个真实的选择说明你的判断标准（比如你更喜欢把模糊问题拆成可验证的假设，而不是只做交互）。电商概念准备 GMV、客单价、转化率、复购率、履约时效、退货率这几个，并能说清它们之间的关系。
