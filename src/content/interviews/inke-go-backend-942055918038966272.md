### 《参考解析》

**B+ 树与联合索引**：索引加快查询的本质是把无序扫描变成有序查找，减少磁盘 I/O。InnoDB 的 B+ 树只在叶子节点存数据，非叶子节点只存键和页号，因此同样大小的页能放下更多键，树高更低；叶子节点之间用双向链表连接，范围查询和排序可以直接沿着链表走。二叉树在数据量大时树高过高，且容易退化成链表，磁盘访问次数不可控。联合索引 (a, b, c) 遵循最左前缀：a 和 c 都是等值条件时，能用 a 定位，c 不能继续用来缩小范围，但可以走索引下推在引擎层过滤；a > 1、b = 2 时只能用 a 做范围扫描，b 的有序性在 a 的范围里不再全局成立。

**事务与 HTTP**：ACID 是原子性、一致性、隔离性、持久性。业务里只要有多条写操作必须同生共死，或者要保证「扣库存 + 写订单」这类组合的原子性，就该上事务；纯查询和单条幂等写入不需要为了用而用。GET 和 POST 的规范差异是语义、幂等性和缓存行为，不是简单的「参数在 URL 还是 body」；实际排障还要看网关、浏览器和服务端对长度、重试、缓存的实现。URL 到页面渲染可以按 DNS、TCP/TLS、HTTP 请求、服务端处理、浏览器解析 HTML/CSS/JS、构建 DOM/CSSOM、布局绘制这条链路讲，每一段补一个可观测点。

**Redis 与缓存三兄弟**：常用结构是 String、Hash、List、Set、ZSet，另外有 Bitmap、HyperLogLog、Stream 等。持久化有 RDB 和 AOF，生产上常混合使用。过期策略是惰性删除加定期抽样删除，内存满时再按 maxmemory-policy 淘汰。缓存穿透是查不存在的数据，解法是空值缓存、布隆过滤器、参数校验；缓存雪崩是大量 key 同时失效或 Redis 整体不可用，解法是过期时间加随机、热点 key 永不过期加后台更新、集群与限流降级；缓存击穿是单个热点 key 失效，解法是互斥重建或逻辑过期。

**分布式锁与一致性**：`SET key value NX EX` 的 NX 表示 key 不存在才设置，EX 是过期时间，二者必须原子地一起设置，避免加锁后进程崩溃导致死锁。释放锁要用 Lua 比较 value 再删除，防止误删别人的锁；续期可以用看门狗。缓存与数据库的一致性没有银弹：常用 Cache Aside，更新数据库后删除缓存，配合延迟双删、binlog 订阅或版本号；强一致场景不要靠缓存硬扛，应该让读请求回源或加分布式锁。

**签到系统**：表可以按用户和日期建唯一索引，字段包括用户 ID、签到日期、补签标记、奖励领取状态。补签要校验可补签的日期范围和次数，写入时靠唯一索引保证同一天不会重复。连签天数可以实时从最近记录往前数，也可以维护一张用户签到统计表，记录当前连续天数、上次签到日期和可领取档位。发奖励时把「领取」做成一条带唯一约束的流水，状态更新和流水写入放在同一事务里，重复请求只会命中唯一键，不会多发。高并发下可以用 Redis Bitmap 做每日签到标记，异步落库，但奖励发放仍要回到数据库做幂等。
