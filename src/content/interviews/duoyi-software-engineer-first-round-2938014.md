5. 入职以后你会怎样做来快速成长、融入团队？

8. 递归的思想，以及它的优缺点。

10. 代码题：给整数 n，输出 1 到 n 的全排列，并讲思路。

### 《参考解析》

**代码质量与安全插件要按作用分层回答。** 格式与风格层：Prettier、ESLint、Checkstyle、Spotless；静态分析层：SonarQube/SonarLint、SpotBugs、Semgrep（可自定义规则）；依赖安全层：`npm audit`、Dependabot、OWASP Dependency-Check；提交前拦截：Husky 加 lint-staged、pre-commit hook；密钥防泄漏：gitleaks、detect-secrets。回答时说明「哪一层拦住了哪类问题」比列名字有用，例如依赖扫描拦的是已知 CVE，静态分析拦的是空指针与资源未关闭，两者不能互相替代。

**线程安全按「共享可变状态」这一根源展开。** 线程安全问题来自多个线程并发读写同一份可变状态且缺乏同步，表现为竞态、可见性、有序性问题。解法分四类：不改共享（线程封闭、不可变对象、每个线程一份副本）；加了锁（synchronized、ReentrantLock，注意锁粒度与死锁）；无锁（CAS、原子类、并发容器）；以及用消息传递替代共享内存（队列、Actor）。回答时补一句「先判断这份状态是否真的需要共享」，往往比讨论用哪种锁更有效。

**递归的优点是表达力，代价是栈与重复计算。** 优点是能把问题分解成同构的子问题，代码接近数学定义，树的遍历、回溯、分治都天然适合；缺点是每次调用占用栈帧，深度过大会栈溢出，且朴素递归常有指数级重复子问题。工程上要么改成显式栈的迭代，要么加记忆化，要么用尾递归（取决于语言是否优化）。

**跨域的本质是浏览器的同源策略。** 协议、域名、端口任一不同即为跨域。常见方案：CORS（服务端返回 `Access-Control-Allow-Origin` 等响应头，预检请求处理 `OPTIONS`，带凭证时不能用通配符）；同源代理（开发环境 devServer proxy、生产环境 Nginx 反向代理）；JSONP（只支持 GET，历史方案）；`postMessage`（iframe 与窗口间通信）；以及同站部署下的 `document.domain`（已废弃趋势）。回答时说明各自适用场景——前后端分离项目首选 CORS 加凭证配置，跨团队或不便改服务端时用网关代理。

**全排列用回溯，关键在「选择—递归—撤销」三步与剪枝。** 维护一个已选路径和一个使用标记数组，每层从未使用的元素里选一个加入路径，递归到底层输出，返回后撤销选择。复杂度 O(n × n!)，因为共有 n! 个排列、每个排列输出需 O(n)。若输入含重复元素，需要先排序并在同层跳过相同值（`i > 0 && nums[i] == nums[i-1] && !used[i-1]`），否则会产生重复排列。面试时先口述复杂度与剪枝条件，再写代码，最后用一个 n=3 的例子人肉跑一遍，能避免边界写错。
