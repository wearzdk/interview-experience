### 《参考解析》

**「第三大的数」有两类解法，要按数据形态选。** 如果数组是一次性给定、允许排序，最直接是排序后去重取第三大（O(n log n)），或者用 `TreeSet` 维护有序集合；如果要求 O(n) 且只能遍历一次，就**用三个变量维护最大、次大、第三大**：遍历时依次比较并「挤出」当前值，注意严格大于（要去重）与不足三个不同值的边界（返回最大值或按题意返回 -1）。被指出「复杂度太高」通常就是因为先排序，这时改成一次遍历的三个变量维护即可降到 O(n) O(1)。如果数据是**流式**不断到来的，就用大小为 3 的小顶堆（`PriorityQueue`）维护最大的三个，或用有序结构；再进一步如果问「第 K 大」且数据量大，就用快速选择（QuickSelect，平均 O(n)）或堆（O(n log k)）。答题时把「数据是否能一次装进内存、是否要求去重、是否流式」这几个前提先问清，再给方案，比直接写代码更稳。

**垃圾回收这块，答题框架是「怎么判断垃圾 → 有哪些算法 → 有哪些收集器 → 什么时候触发」。** 判断存活用可达性分析（从 GC Roots 出发，GC Roots 包括栈上引用、静态变量、常量、JNI 引用、活跃线程），不用引用计数（解决不了循环引用）。回收算法：标记-清除（有碎片）、标记-复制（新生代 eden/survivor，浪费空间但快）、标记-整理（老年代，无碎片但慢）；分代假设是「大部分对象朝生夕死」，所以新生代用复制、老年代用标记-整理/清除。收集器演进：Serial/Parallel（吞吐优先）→ CMS（并发、低停顿但碎片与浮动垃圾）→ G1（分 region、可预测停顿、按收益回收）→ ZGC/Shenandoah（着色指针 + 读屏障，停顿与堆大小基本无关）。触发时机：Eden 满触发 Minor GC，对象经多次 Minor GC 存活后晋升老年代（`MaxTenuringThreshold`），老年代占用到阈值触发 Full GC；要能讲清 `Stop-The-World` 与「GC 日志怎么看」（`-Xlog:gc*`）。

**String/StringBuilder/StringBuffer 的区别是「可变性与线程安全」。** String 不可变（`final` 字符数组，任何「修改」都产生新对象），所以循环里 `s += x` 会创建大量临时对象；StringBuilder 可变、非线程安全、性能最好，单线程拼接首选；StringBuffer 可变、方法加了 synchronized、线程安全但更慢，只在多线程共享同一缓冲区时用。补充两点常被追问：字符串常量池与 `intern()`（编译期字面量入池，`new String("a")` 会创建两个对象或一个取决于池中是否已存在）；以及 Java 9 之后 String 底层从 `char[]` 改成 `byte[] + coder`（Latin-1 时省一半内存）。

**堆与栈，以及 IoC 与 Spring Boot/Spring MVC 的区别。** 堆是线程共享的运行时内存，存对象实例与数组，由 GC 管理，溢出抛 OutOfMemoryError；栈是线程私有的，存方法调用的栈帧（局部变量表、操作数栈、返回地址），递归过深抛 StackOverflowError。**IoC** 是「控制反转」：对象不再自己 `new` 依赖，而是把创建与装配交给容器，实现方式就是依赖注入（构造器/Setter/字段），好处是解耦、便于替换实现与测试；与之相伴的 AOP 用代理把日志、事务、权限这类横切关注点抽出来。**Spring Boot 与 Spring MVC 不是替代关系**：Spring MVC 是 Web 层框架（前端控制器 DispatcherServlet + 注解路由 + 参数绑定 + 视图解析），Spring Boot 是「约定优于配置」的工程脚手架——自动配置、起步依赖、内嵌容器、Actuator，把之前繁琐的 XML 配置收敛掉；Spring Boot 里默认就集成了 Spring MVC。

**索引相关两问。** 索引的作用是把「全表扫描」变成「按序定位」，提升查询效率，同时能支撑排序与分组、并通过唯一索引保证约束；代价是占空间、拖慢写入（每次写入要维护所有索引）、以及优化器选错索引的可能。**适合建索引的字段**：区分度高（性别、状态这类只有几个取值的列不值得单独建）、经常出现在 `WHERE`/`JOIN`/`ORDER BY`/`GROUP BY` 中的列、以及需要唯一约束的列；联合索引要按「等值条件在前、区分度高的在前、范围条件在后」设计并注意最左前缀，尽量让高频查询走覆盖索引（不回表）。不适合的：很少被查询的列、更新极频繁的列、区分度极低的列、以及大文本字段（可考虑前缀索引或全文索引）。面试里把「为什么快 + 代价是什么」都说清，比只背结论更完整。
