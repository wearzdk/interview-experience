### 《面试题目》

1. 你说你熟悉 C++ 对象模型，那一个带虚函数的类，它的对象在内存里到底长什么样？
2. 为什么基类析构一定要写成 virtual，不写会怎样，什么情况下可以不写？
3. shared_ptr、unique_ptr、weak_ptr 这三者，你分别在什么场景下用？
4. 父子节点互相持有 shared_ptr 造成循环引用，你怎么查、怎么改？
5. 让你给一个每帧要遍历十万次、插入删除很少的集合选容器，你选哪个，迭代器失效又怎么保证？
6. vector 的扩容倍数为什么是 1.5 或 2，reserve 你一般在什么时候调？
7. 右值引用和移动语义解决的是什么问题，移动构造为什么一定要加 noexcept？
8. 手撕：实现一个简化版 vector，支持 push_back 和自动扩容，你能当场写出来吗？

### 《参考解析》

**带虚函数的对象布局**。64 位下对象头部多出 8 字节的虚表指针 vptr，指向该类的虚表；一个类一张表，所有对象共享，表里按声明顺序存放虚函数地址（含析构的槽位）。布局顺序通常是 vptr、基类成员、派生类成员，按各自对齐要求填充。多继承时每个含虚函数的基类子对象各带一个 vptr，派生类新增的虚函数塞进第一个虚表末尾，用基类指针调用时还要做 this 指针偏移（thunk）。可以给具体数字验证：空类 sizeof 为 1，加一个虚函数变 8，再加一个 int 变 16（8 字节对齐）。踩坑点：用 memcpy 拷贝含 vptr 的对象，跨模块或跨进程时 vptr 指向的是原进程的虚表地址，行为未定义；所以含虚函数的类不能按字节拷贝。

**虚析构的必要性**。`Base* p = new Derived; delete p;` 若析构非虚，只调用 `Base::~Base`，派生类持有的资源（纹理句柄、顶点缓冲、文件描述符）不会释放，堆内存泄漏且行为未定义。实现上，虚析构让析构函数进虚表，delete 时经 vptr 找到实际类型的析构，再由编译器生成的 deleting destructor 先调派生析构、再调 `operator delete`。可以不写的场景：类标记为 final（不会被继承）、或从不用基类指针删除（例如纯接口用 protected 非虚析构，派生类自己 delete），这样可以省掉 vptr 的 8 字节与一次间接调用——在每帧创建上百万个小对象的引擎里，这个取舍是真实的。

**三种智能指针的选型**。默认用 `unique_ptr`：只有一个指针大小、零额外开销，所有权明确、可移动不可拷贝，适合「一个 Mesh 只属于一个 RenderEntity」这类独占场景。需要共享所有权时才用 `shared_ptr`：它带一个控制块（强引用计数、弱引用计数、删除器、分配器），拷贝会原子地增减计数，有缓存不友好的开销；`make_shared` 一次分配把对象与控制块放在一起，比 `shared_ptr(new T)` 少一次 malloc，局部性也更好。`weak_ptr` 不增计数，用于打破环、做观察者、缓存索引、以及父子互指中子指向父；使用时必须 `lock()` 提升为 shared_ptr 并判空，说明对象还活着。

**循环引用的排查与修复**。现象：对象该销毁时析构断点不触发，`use_count()` 稳定在 2 不掉，内存曲线只涨不降。定位手段：用 VS 的 Diagnostic Tools 或 heaptrack 抓两次快照对比，两个地址互相引用即成环；也可以在关键类里加静态计数器（构造 +1、析构 −1），退出时打印不为 0 的类名，比事后翻 dump 快。修法有优先级：父持 `shared_ptr`、子持 `weak_ptr`（标准解法）；或明确一方为独占（`unique_ptr` + 裸指针/引用）；或在双方都该退出时显式 `reset()` 打断环。设计上更根本的一条是：先想清楚「谁拥有谁」，把所有权画成树，环通常意味着模型本身有问题。

**每帧十万次遍历的容器选择**。只读遍历选 `vector`：十万个元素连续内存，缓存友好，遍历通常比 `list` 快 5~10 倍（差一个数量级很常见）；`list` 只在「中间频繁插入删除且元素很大、移动成本高于节点分配」时才考虑。若遍历中还要按 key 查找，用 `unordered_map` 或排序后的 `vector` 做二分。迭代器失效规则要背准：`vector` 扩容让所有迭代器、指针、引用失效，`erase` 让删除点及其之后全部失效（`push_back` 在未扩容时只失效 `end()`）；`map`/`unordered_map` 只有被删元素失效，其余稳定（`unordered_map` 的 rehash 会让迭代器失效但引用与指针仍有效）。工程约束：遍历中删除用 `it = c.erase(it)` 接续，或先标记后统一删；跨帧只持有下标或 ID，绝不持有迭代器或指针。

**扩容倍数与 reserve**。按 k 倍扩容，n 次 push_back 的总拷贝量是等比级数，均摊到每次是常数，所以 1.5 与 2 都满足均摊 O(1)。差别在内存复用与峰值：k=2 时新块大小等于此前所有块之和，永远装不下旧块腾出的空洞；k=1.5 时新块小于此前总和，有机会复用前面释放的空间，长期运行的程序碎片更少。代价是 1.5 倍扩容次数更多、拷贝总量略高。`reserve` 的时机：已知规模时必调（例如每帧收集可见物体先 `clear` 再 `reserve(1024)`），避免反复扩容；但 reserve 过大反而浪费——一个长期驻留的 4 MB 临时缓冲会把纹理缓存挤出去。经验数字：一千万个 int 从 0 涨到满，2 倍扩容累计搬运约两千万次、峰值内存约 1.5 倍；提前 reserve 则搬运为 0。

**右值引用、移动语义与 noexcept**。移动语义解决的是「临时对象与所有权的转移也要付深拷贝代价」：把一块 64 MB 的顶点缓冲从一个 vector 移到另一个，移动只搬三个指针，耗时从毫秒级降到纳秒级。转发引用（模板里的 `T&&`）配合 `std::forward` 保留值类别，让 `emplace_back` 能原地构造，少一次临时对象与一次析构。移动构造必须 `noexcept` 的原因是 `vector` 扩容要求强异常安全：扩容时若用移动构造，中途抛异常会导致旧块里的元素已被移走、新块又不完整，无法回滚；因此标准库用 `std::move_if_noexcept` 判断——移动构造没标 `noexcept` 就退回拷贝。漏写 `noexcept` 是线上性能腰斩的常见原因，且很难从代码上看出来。

**手写简化版 vector**。要点是把「三指针 + 扩容 + 异常安全」讲清楚：用 `begin_`、`end_`、`cap_` 三个 `T*` 表示区间，`size()` 与 `capacity()` 直接相减；`push_back` 先判 `end_ == cap_`，满时按 2 倍申请新块，用 `std::move_if_noexcept` 逐个搬到新块（或用 `std::uninitialized_move`），再 `delete[]` 旧块、更新三个指针；空 vector 首次分配给小容量（如 4），避免第一次插入就分配。析构里对 `[begin_, end_)` 逐个调用析构函数，再 `delete[]` 原始内存（注意 `new T[]` 与 `::operator new` 的区别：前者会默认构造，用 allocator 或 `::operator new` 才能构造未初始化内存）。拷贝构造要做深拷贝，移动构造直接窃取指针并把源置空；`clear()` 只析构元素、不释放内存。手撕时先写接口骨架并说明异常安全（扩容时若搬移抛异常要保证旧数据仍有效），比背代码更能拿分。
