### 《参考解析》

**数组的连续性与结构体对齐**：数组是顺序存储，逻辑相邻的元素物理地址也相邻，中间插入元素要把后面的元素整体后移，插入后依然连续，代价是 O(n) 的搬移；链表插入只改指针，但遍历失去随机访问。结构体对齐的规则有三条：每个成员的偏移必须是 `min(成员自身对齐, 指定 pack 值)` 的整数倍；结构体总大小必须是最大成员对齐的整数倍（末尾补 padding）；位域和空结构体在 C 与 C++ 里规则不同。优化空间的常规做法是按成员大小从大到小排列（把 `char`、`short` 往后放），必要时用 `#pragma pack(1)` 或 `__attribute__((packed))` 压紧，但代价是非对齐访问——在 ARM 上可能触发 alignment fault，或退化成逐字节访问而变慢，跨平台协议结构体用它、频繁访问的内存结构别用。

**结构体怎么「带上函数」**：C 的结构体没有成员函数，两条路。一是函数指针成员，把操作表挂在结构体上（`struct ops { int (*init)(struct dev *); ... }`），Linux 内核的 `file_operations`、`net_device_ops` 就是这个模式，换来运行时可替换、便于做多态；二是把结构体指针作为第一个参数传给普通函数，模拟 `this`，这也是内核里 `container_of` 能反查宿主结构体的基础。C++ 里成员函数本质也是隐式传 `this`，虚函数则是 vtable 加一层间接调用。

**FreeRTOS 的同步原语要能说清选型**：任务间传数据用消息队列（`xQueueCreate` / `xQueueSend` / `xQueueReceive`，可传值也可传指针，队列长度决定背压），ISR 里必须用 `FromISR` 变体并处理 `xHigherPriorityTaskWoken`。二值信号量用于事件通知（中断里 `xSemaphoreGiveFromISR` 唤醒任务），计数信号量用于资源计数，互斥锁（`xSemaphoreCreateMutex`）带优先级继承，能缓解优先级翻转——二值信号量没有这个能力，用在临界区保护上就可能出问题。串口收发的常见结构是「DMA 收 + 空闲中断 + 环形缓冲区 + 队列通知任务」，中断里只搬数据不做解析。递归锁、事件组、任务通知（更轻量的替代）也各提一句，能体现不是只背了三个 API。

**异常排查的路径**：先分级——HardFault / 总线错误这类硬件异常看栈帧里的 PC、LR、xPSR 与故障状态寄存器（CFSR、HFSR、BFAR、MMFAR），定位到出错指令与访问地址；再往下是野指针、栈溢出、中断里调用阻塞 API、DMA 越界、时钟或供电不稳。工程手段是加看门狗、把关键状态与调用栈写进不掉的备份寄存器或 Flash、开 MPU 把栈和只读区保护起来。帖主说「异常处理排查」被问到，回答时给出「复现—缩小范围—定位到寄存器/指令」的顺序，比罗列工具更有说服力。

**Linux 上电到 rootfs**：以 ARM64 为例，上电后 CPU 从 BootROM 取指（BL0，固化在芯片里，按拨码或 eFuse 决定从 eMMC / SD / USB / 串口加载），BootROM 把 SPL 或直接是 U-Boot 的 BL1 搬进 SRAM；随后是 TF-A（ATF）的 BL2/BL31 建立安全监控与 PSCI，再把 BL33（U-Boot proper）加载到 DRAM；U-Boot 初始化 DDR、外设，读取环境变量，从存储或网络（TFTP/NFS）取 kernel Image、dtb 与 initrd，跳转到内核；内核解压、建页表、初始化子系统，解析设备树匹配驱动，挂载 rootfs 后执行 `/sbin/init`（systemd / busybox init），再启动用户态服务。能画清「BootROM → SPL → U-Boot → kernel → init」这条链，并说清 SRAM 与 DRAM 的分界、设备树在各阶段怎么传递（U-Boot 把 dtb 地址放进 x0/x1 交给内核），这道题就稳了。

**烧录与编译环境**：烧录方式按场景分——研发阶段用 JTAG/SWD 配合 OpenOCD 直接写 Flash 或 DDR 里跑，USB 下载模式（fastboot、DFU、瑞芯微的 maskrom）适合量产与救砖，SD 卡启动镜像适合板子第一次点亮，U-Boot 里用 TFTP/USB 下载再 `sf`/`mmc write` 落到 SPI Flash 或 eMMC，产品出货后走 recovery 或 A/B 分区 OTA。编译环境的核心是交叉工具链与 sysroot：`aarch64-linux-gnu-gcc` 加目标板的 libc，内核走 Kbuild（`make ARCH=arm64 CROSS_COMPILE=... defconfig`、`menuconfig`、`dtbs`），用户态用 Buildroot 或 Yocto 出 rootfs，设备树用 `dtc` 反编译核对，最后统一进 CI 保证可复现。

**环形缓冲区**：一块定长内存加读写下标，写指针追上读指针为满、两者相等为空（或留一个空槽、或用计数器区分满空）。单生产者单消费者场景可以不关中断地无锁操作，但读写指针要用 `volatile` 加内存屏障（`__DMB()` 或 C11 的 acquire/release）防止编译器与 CPU 乱序；多生产者要加锁或用原子 CAS。它能避免数据搬移，天然适合串口 / DMA / 日志 / 音频流，关键指标是「最长不覆盖时间」与溢出策略（覆盖最旧还是丢最新）。面试官问这一题，通常接着问「中断里写、任务里读，临界区怎么处理」。

**视觉检测直线**：经典路线是灰度化 → 高斯滤波 → Sobel 求梯度 → Canny 边缘 → Hough 变换，在 (ρ, θ) 参数空间里累积投票，取峰值即为直线，优点是抗噪、能处理断裂，缺点是参数多、计算量大、对短线段不敏感；概率 Hough 只对随机采样的边缘点投票，速度快很多。另一条是 LSD / EDLines 这类基于梯度区域生长的线段检测，直接给端点，适合工业检测。工程上更常见的是先做 ROI 与二值化，再用 RANSAC 拟合直线（随机取两点建模、统计内点、迭代取最优），最后用最小二乘对内点精修，鲁棒性比 Hough 好且能给出拟合误差。若目标是测量（如引脚共线性、PCB 走线角度），还要做亚像素边缘与相机标定。

**外设与 UART 的定位**：外设指 SoC 内部除 CPU 与内存之外的控制器模块——GPIO、UART、SPI、I2C、CAN、ADC/DAC、PWM、定时器、USB、以太网 MAC、DMA 都算。UART 是异步串行通信控制器，属于典型外设；它不提供时钟线，靠双方约定的波特率采样，所以对时钟误差敏感（一般要求 2% 以内），帧格式是起始位 + 数据位 + 可选校验 + 停止位。面试官追问「UART 是不是外设」，实际在确认你是否分得清「外设」与「总线协议」——I2C、SPI 既是协议也是控制器外设，而 RS-232/RS-485 是电气层标准，和 UART 不是一回事。
