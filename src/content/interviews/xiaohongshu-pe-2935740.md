### 《面试题目》

1. 深挖实习做的东西，深入到原理（约 30 分钟）。
2. 讲一下 Agent 相关的设计模式。
3. Harness 都包含哪些方面？
4. 讲一下 Redisson 分布式锁的背景和原理。
5. 看门狗机制的不足是什么？
6. 谈一下 Agent 接入真实业务的优缺点。
7. 手撕：K 个一组反转链表。

### 《参考解析》

1. **Agent 设计模式**：常见的有 ReAct（思考—行动—观察循环）、Plan-and-Execute（先规划再执行，适合长任务）、Reflection（自我批判后重试）、Router（按意图分派到不同子 Agent 或工具链）、Orchestrator-Worker（一个编排者拆任务、多个执行者并行）、Human-in-the-loop（关键步骤等确认）。讲的时候要落到「什么场景用哪种」，比如步骤不确定用 ReAct，步骤多且可预规划用 Plan-and-Execute，需要并行检索用 Orchestrator-Worker。

2. **Harness 包含哪些方面**：把「模型之外、让它能持续干活的那一整套」讲全——提示与上下文组装、工具注册与执行、循环与终止条件、状态与记忆、权限与沙箱、错误重试与降级、可观测（trace、token、成本）、评测与回归。它是模型能力的放大器，模型的短板往往靠 harness 补。

3. **Redisson 分布式锁原理**：基于 Redis 的 `SET NX PX` 加锁，value 存「客户端 ID + 线程 ID」保证只有持有者能解锁；解锁用 Lua 脚本原子地判断并删除。可重入靠哈希结构记录重入次数。锁等待通过发布订阅实现，避免无意义轮询。

4. **看门狗的不足**：看门狗靠后台定时任务给锁续期，前提是持有锁的进程还活着且能连上 Redis。它的短板有几处：进程被 kill 或长时间 Full GC 时续期中断，锁会提前释放而业务还在跑；网络分区时客户端以为持有锁、Redis 已过期，出现双持有；续期是周期性的，极端情况下仍可能错过窗口；另外它只保证「锁在有效期内不失效」，不保证业务操作本身是幂等的。所以关键路径仍要靠数据库唯一约束、fencing token 或版本号兜底。

5. **Agent 接入真实业务的优点**：能处理非结构化的长尾请求、把多步操作串起来、用自然语言配置流程，开发和调整成本低于硬编码规则。缺点：结果不确定、延迟和成本高、错误难以复现和定位、权限边界难控（一旦能写数据就可能造成真实损失）、评测困难。落地的关键是把 Agent 放在「能回读、可回滚、有兜底」的位置上，写操作要确认和审计。

6. **K 个一组反转链表**：先数出总长度或逐组判断剩余是否够 k，够则反转这一组、接回前后指针，不够则保持原样。迭代写法用四个指针（组前驱、组首、组尾、组后继），O(n) 时间 O(1) 空间；递归写法更简洁但有栈深度风险。边界是 k=1、长度不足 k、正好整除。
