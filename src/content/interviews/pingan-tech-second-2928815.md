### 《参考解析》

**RAG 分块与表格跨页**：分块先按文档结构走——按标题层级切章节，再在章节内按语义或固定窗口细分，块大小按嵌入模型与检索粒度权衡（常见 300–800 token，重叠 10%–20%），并保留文档 id、章节路径、页码等元数据。表格跨页的根源在解析阶段：做版面还原，识别「续表」和重复表头，按列结构把两页的表拼回一张，再转成结构化 Markdown 或 HTML，整表作为一个 chunk；表太长就按行切，但每块都重复表头。再给表块生成「表名 + 列名 + 行标签」的自然语言摘要一起入库，向量检索才容易命中。

**AI 幻觉与高质量交付**：幻觉不能靠一句 prompt 消除。检索侧提高召回与重排质量；生成侧约束「只依据给定材料，无依据就说不知道」，并要求标注引用；输出侧校验结论是否有引用支撑、数字与单位是否与原文一致，关键场景加规则校验或第二个模型交叉核验；上线后靠评测集、badcase 库和链路 trace 持续回归。用 AI 快速高质量交付的关键是把任务拆小：先写清验收标准与测试，再让 AI 生成脚手架、单测和文档，人 review 设计与关键路径，小步提交，用 lint、类型检查和 CI 门禁兜住底线。

**对全栈的理解**：全栈不是「前端后端都会写」，而是能独立把一条业务链路从需求跑到上线：前端懂框架、状态管理、性能与可访问性；后端懂 API 设计、数据库建模、缓存与并发；再加 CI/CD、日志监控、线上排障这些运维能力。核心是边界感与取舍——知道问题该落在哪一层，出了问题能自己读日志定位，而不是等人接手。

**TDD 实践**：节奏是红—绿—重构：先写一个失败的测试把行为描述清楚，再写最小实现让它通过，最后在测试保护下重构。落地时优先覆盖核心业务逻辑和边界条件，比如金额计算、状态机流转、权限判断；IO 和 UI 层交给集成测试或少量端到端，保证测试快、独立、可重复并跑在 CI 里；探索型原型不必硬套。讲的时候结合真实写过的模块，说明先写测试带来了什么改变。

**行为题准备**：实习成就题用 STAR 讲，重点是你做的决策、遇到的阻力和可量化的结果；「为什么选成都」从业务匹配、长期发展和个人规划三条讲，别只说城市宜居。
