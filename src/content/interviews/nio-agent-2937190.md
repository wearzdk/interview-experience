### 《参考解析》

**Attachment 收包优化怎么讲**：按「原路径 → 瓶颈 → 改动 → 证据」四段讲。原路径上每个请求都要把 attachment 从协议帧里解析出来并复制到独立结构，短请求多时分配与拷贝占了大头；改动是把解析结果做成对原始缓冲的视图，配合池化减少分配，并明确生命周期由谁持有；证据是同一压测下的分配次数、拷贝字节、P99 延迟与 CPU 占用对比。只讲「用了池、少了拷贝」而不给数字，很难通过这类追问。

**Buffer Pool 的所有权与兼容性**：所有权必须在接口上写清楚——是调用方借出、框架借用，还是框架接管。借用要有归还协议与引用计数，接管则由框架负责最终释放。兼容性上，新接口不能改变旧调用方的语义，通常用新增可选参数、能力协商或适配层实现；默认路径保持旧行为，新路径灰度开启。

**消融实验**：把优化拆成可独立关闭的项，固定硬件、固定数据分布、固定并发，逐项开关跑同一基准，记录均值与分位数。要说明哪些指标是直接因果（分配次数）、哪些是间接收益（GC 减少带来的尾延迟改善）。面试官问「哪一项作用最大」，答案应来自数据而不是直觉。

**最少补多少个括号**：一遍扫描即可。维护当前未匹配的左括号数 open；遇到左括号 open 加一，遇到右括号时若 open 大于零则减一，否则说明这个右括号缺少左括号，答案加一并保持 open 不变；扫描结束后剩余 open 个左括号各需要一个右括号，答案再加 open。时间复杂度 O(n)，空间 O(1)。边界是空串与只有单侧括号的串。

**五种 Context 管理手段**：可以归纳为裁剪（按轮次或 token 丢弃）、摘要（把早期内容压缩成要点）、检索（把长期资料放到外部按需取回）、结构化（把任务状态写成字段而不是自然语言）、隔离（把子任务交给子 Agent，只回传结论）。实际系统通常组合使用：结构化状态保证不丢关键约束，摘要与检索控制窗口长度，隔离开支线任务。

**三类 Memory**：工作记忆是当前会话的临时状态；情节记忆是按时间存储的历史事件与对话片段，可按相似度与时间召回；语义记忆是从事件中归纳出的稳定事实与偏好。三者的写入策略不同：工作记忆随会话结束丢弃，情节记忆需要去重与衰减，语义记忆需要置信度与冲突消解。

**C++20 协程加 io_uring**：协程负责把异步回调写成顺序代码，awaiter 在发起操作时把 fd 与缓冲注册到 io_uring 的提交队列，挂起当前协程；完成事件从完成队列取出后恢复对应协程。要点是缓冲区生命周期必须覆盖到操作完成（用固定缓冲或引用计数），以及提交与收割的批量化以减少系统调用。对称转移与调度器决定恢复在哪个线程执行，跨线程恢复要考虑数据竞争。

**职业规划**：结合岗位讲可验证的方向，例如在 Agent 执行环境与可观测性上做深，能独立负责一个模块从设计到上线，并给出衡量标准。避免泛泛而谈「想成为技术专家」。
