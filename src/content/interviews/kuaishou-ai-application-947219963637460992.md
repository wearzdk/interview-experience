### 《面试题目》

1. 介绍一个 AI 应用项目，怎么说明它确实是 Agent？
2. 什么是意图澄清？用户没说清楚时怎么反问？
3. 意图识别树怎么设计？评测集和指标怎么选？
4. MCP 工具的参数、权限和错误怎么约束？
5. 调用失败后，怎么避免模型一直重试？
6. 手撕：反转单链表

### 《参考解析》

**怎么证明它是 Agent。** 判据不是「接了模型」，而是控制流由谁决定。固定的检索—生成—展示是 pipeline：中间结果如何，下一步都写死。Agent 的区别是模型看完工具返回再决定下一步——继续调、换工具、还是结束，并且循环有停止条件和外部约束。答的时候画一条请求路径：入口解析 → 模型决策 → 代码校验（参数、权限、是否需用户确认）→ 执行 → 结果回填 → 再决策，标出模型能决定的分支和代码强制拦住的点。

**意图澄清。** 一次只问一个分叉，不是把缺的信息列成问卷。「帮我更新报表」先判缺的是表、日期还是新值，只缺日期就问日期。第二是读写分离：查询可以带默认值先查再确认，写操作必须先确认范围和目标，不能猜一个区间就往库里写。第三是能从上下文推断的就别问，措辞给选项比开放提问收敛得快。

**评测集与指标。** 至少三类标签：应直接执行、需要再问一次、不该执行（越权、危险、明显无解）。只测总体准确率会掩盖最贵的错误——错误执行。指标分层看各意图的准确率与混淆矩阵、澄清后任务完成率、澄清轮次分布（超过两轮基本等于失败）、误执行的绝对条数，评测集从线上请求按意图分层采样。

**MCP 工具的参数、权限与错误。** 参数层用 JSON Schema 强约束：枚举代替自由文本、必填显式声明、数值给范围，能写进 schema 的不写进提示词。权限按最小可用：用户级凭据而不是服务账号通吃、跨租户隔离、危险动作二次确认。错误要结构化，并标出「可重试 / 不可重试 / 结果未知」。

**失败后怎么不陷入重试循环。** 先判能否安全重试：查询超时可退避重试；提交类超时属于结果未知，必须先查实际状态，否则就是重复下单；参数错误、无权限重试多少次都不会成功。工程上给硬约束：单轮最多 2–3 次、同一工具同一参数连续失败就换策略、总步数与时长设上限，超了强制收敛。

**反转单链表。** 三指针迭代：每步先用 `next` 存住后继，再改 `cur.next = prev`，两个指针前移，最后返回 `prev`；`while (cur != null)` 自然覆盖空链表和单节点。落笔前先画三个节点，能避免把后半段链表弄丢。
