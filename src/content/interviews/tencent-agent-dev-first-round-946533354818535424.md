### 《面试题目》

1. 自我介绍，挑一个项目展开：从上传文档到返回答案，整条链路怎么走？
2. 文档怎么解析、分块？为什么项目里只允许上传一个文件？
3. 向量召回耗时怎么测？Rerank 做了什么，怎么评估检索结果和问题是不是匹配？
4. Agent 有哪些核心模块？ReAct 是怎么跑起来的？
5. 一般几步能完成任务？到了最大步数还没做完怎么办，有没有设置 Plan？
6. MCP、Function Call、A2A 怎么区分？接过哪些 MCP 服务，自己手写的话要做哪些事？

### 《参考解析》

**上传到答案的链路**：文件上传后先做解析（pdf/docx 转文本，表格与图片单独抽出保留结构），再清洗、按语义或固定长度加重叠切块，每块生成 embedding 写入向量库并带上元数据（来源、页码、小节标题）。提问时先把问题改写或补全上下文，再向量化做近邻召回（常先粗召回几十条），过一遍 rerank 精排取前几条，拼进 prompt 让模型带上引用作答；命中不足就触发二次检索或要求用户澄清。

**解析与分块**：分块粒度直接影响召回质量——太小丢上下文、太大稀释语义。常见做法是按标题层级先切结构，再在段落边界上按 token 数切、相邻块留 10%～20% 重叠；表格单独序列化（行列转成文本或 markdown），图片走 OCR 或图文模型生成描述再挂到块上。只允许上传一个文件通常是产品与工程上的取舍：一是文档级隔离，检索范围明确、引用好回溯；二是省去跨文档去重与权限判断；三是成本与延迟可控。答的时候最好把「如果放开要多文件要补什么」一起说清。

**召回耗时与 Rerank 评估**：耗时要在服务端埋点分段测——查询向量化、向量库检索、rerank 各自的 p50/p95，别只报端到端。Rerank 是用交叉编码器对「问题—候选块」逐对打分重排，把语义相关但向量距离不近的块捞回来。评估要有标注集：对每个问题标出正确块，算 Recall@k（正确块有没有进前 k）、MRR 与 nDCG（正确块排得多靠前）；没有标注就用大模型做相关性打分再人工抽检。上线后看答案里的引用命中率和用户追问率。

**Agent 的核心模块与 ReAct**：规划（拆任务、出计划）、执行（工具调用）、记忆（短期上下文与长期存储）、观测与反思（判断结果是否达成）、终止控制。ReAct 就是把「想一步—做一步—看结果」交替进行：模型先输出思考，再输出一次工具调用，环境返回观察结果，循环直到能给出答案。

**最大步数与 Plan**：一般 3～8 步能完成多数任务，复杂任务十几步。设最大步数是防死循环与成本失控：到了上限要么把已有的中间结果整理成阶段性答复并说明还差什么，要么主动问用户要更多信息。Plan 值得加——先让模型给出步骤列表再逐步执行，既能让用户提前纠偏，也能在中断后从某一步继续。

**MCP、Function Call、A2A**：Function Call 是模型输出「我要调哪个函数、参数是什么」的能力，是单个模型与工具之间的协议；MCP 是把工具/资源/提示词标准化成服务端，任何客户端都能接同一套，解决的是「工具怎么复用、怎么跨应用共享」；A2A 是 agent 与 agent 之间的协作协议，解决的是「多个 agent 怎么分工、交接任务」。自己写一个 MCP 服务要做：定义 tools 的 name/description/输入 schema、实现调用逻辑、处理错误与超时、声明能力与鉴权，再接到客户端上跑通。
