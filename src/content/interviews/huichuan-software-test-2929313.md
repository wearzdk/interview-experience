### 《面试题目》

1. 介绍一下科研、实习和项目经历。
2. 你做的两个软著和一个专利具体是什么？
3. 听起来项目没有闭环，你做的事情怎么量化？
4. 大论文也是针对这个项目做的吗？难点是什么？
5. 个人项目是在学校做的吗？为什么要做这个项目？
6. 简历上第一段实习主要做了什么？两个模块怎么分工？测试流程是怎样的，用了哪些工具？
7. UI 自动化用的什么语言？
8. Web 登录界面有账号、密码、验证码三个输入框，从哪些维度设计测试？
9. Python 的基础知识掌握得怎么样？
10. 家是哪里的？意向工作地是哪里？

### 《参考解析》

**项目量化**：面试官说「没闭环」，通常不是嫌项目小，而是没听到「问题—方案—结果—验证」这条线。回答时先给一句结论，例如「把某类接口的回归时间从 40 分钟压到 8 分钟」，再补怎么做的：梳理重复用例、做参数化、把环境准备脚本化、接入 CI。数字可以是耗时、覆盖率、缺陷发现数、自动化比例，但必须能解释口径。如果没有线上数据，就退回到可验证的工程指标，别编业务收益。

**登录界面测试**：按维度展开比堆用例更加分。功能上测账号密码正确/错误、验证码正确/过期/错误、为空、超长、特殊字符、大小写、前后空格、回车提交、记住密码、多次失败锁定、找回密码入口。界面上测布局、提示文案、密码掩码、按钮禁用态、不同分辨率。兼容性测主流浏览器、移动端、不同系统。安全上测 SQL 注入、XSS、暴力破解、验证码复用、会话固定、敏感信息传输。性能上测并发登录、接口响应、验证码刷新频率。弱网和异常场景测超时、重复提交、服务端 5xx、验证码服务不可用。最后补一条：测试数据要能清理，避免污染环境。

**测试流程与工具**：一段实习可以按「需求评审—测试方案—用例设计—环境准备—执行—缺陷跟踪—回归—报告」讲，每步说自己具体产出什么。两个模块怎么分工，要讲清接口边界、联调方式、谁负责造数和兜底。UI 自动化说清语言、框架、元素定位策略、失败重试和报告，不要只报工具名。被问「为什么用这个工具」时，从团队技术栈、维护成本、稳定性三个角度答。

**反问**：可以问测试团队怎么分工、自动化在回归中的占比、新人培养方式、业务分布。面试官主动介绍了不同地点的团队职责，说明他对组织信息是开放的，顺势追问「这个岗位入职后前三个月最需要补齐的能力是什么」会比问薪资更有效。
