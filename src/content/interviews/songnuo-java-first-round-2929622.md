### 《参考解析》

**字符串拼接**：`s1 += "hello"` 在循环里会被编译成 `StringBuilder.append` 再 `toString`，每次循环创建新对象；如果是编译期常量拼接，javac 会直接折叠成常量。`String` 不可变，频繁拼接要用 `StringBuilder`，并发场景用 `StringBuffer` 或局部 builder。基本类型 `swap` 是值传递，函数内交换不影响外部；Java 没有 C++ 那样的引用传递，想交换要传数组/对象或返回新值。

**变量与内存**：局部变量在栈帧的局部变量表，成员变量随对象在堆，静态变量在方法区/元空间；静态变量能否被其他类访问取决于访问修饰符，`public static` 可以直接用类名访问。数组在堆上是连续内存，二维数组在 Java 里是“数组的数组”，各行可以不等长，所以不保证整体连续。

**并发容器**：ArrayList 线程不安全；ConcurrentHashMap 用 CAS + synchronized 锁桶头节点，JDK 8 后放弃分段锁；Hashtable 用整表 synchronized，粒度粗、并发差。库存防超发不能只靠分布式锁：锁能保证一致性但吞吐有限，万人抽百奖更适合“Redis 预扣 + Lua 原子脚本 + MQ 异步落库 + 数据库唯一约束/乐观锁兜底”，并处理预扣成功但落库失败的回滚。

**网络部分**：HTTP 报文分请求行/状态行、头部、空行、正文；跨域是浏览器同源策略限制，服务端用 CORS 响应头（`Access-Control-Allow-Origin` 等）放行，复杂请求先发 OPTIONS 预检；开发态也可用代理。HTTP 适合请求-响应，WebSocket 适合双向实时推送，MQTT 适合弱网、低功耗设备的长连接发布订阅；QoS 0 最多一次、QoS 1 至少一次、QoS 2 恰好一次，QoS 1 的 PUBACK 是接收端确认，重复消息靠业务幂等或消息 ID 去重。
