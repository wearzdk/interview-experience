### 《参考解析》

**内核态与用户态的数据交互**：内核态能直接访问全部内存和硬件、跑在特权级，用户态只能碰自己的地址空间；切换靠系统调用或中断/异常。数据交互的几条路：字符设备的 read/write、ioctl 传控制参数、procfs/sysfs 暴露状态、netlink 做双向消息、大块内存用 mmap 共享。关键铁律是不能直接解引用用户态指针——必须 `copy_to_user` / `copy_from_user`，它们会处理缺页和权限校验；大数据量走 mmap 加 DMA 零拷贝，别用 ioctl 一次搬几 MB。

**硬中断、软中断与下半部**：硬中断上下文不能被抢占语义上的睡眠（不能拿互斥锁、不能 kmalloc GFP_KERNEL、不能等 I/O），所以只做最紧急的清中断、取数据、挂起下半部。下半部有几种：softirq 在中断返回或 ksoftirqd 线程里跑，同一类型可在多核并行，适合网络收包这类高频场景；tasklet 基于 softirq、同类型串行，不会并发；workqueue 跑在进程上下文、可以睡眠、可以拿锁，适合耗时或需要阻塞的工作。选型口诀就是：越短的放上面，要睡眠的丢给 workqueue。

**自旋锁、互斥锁与信号量**：自旋锁忙等不睡眠，适合极短临界区，可在中断上下文用（中断里用 `spin_lock_irqsave` 关本地中断防止死锁）；互斥锁会睡眠、有优先级继承，适合较长临界区，但只能在进程上下文拿；信号量是计数型的，允许 N 个持有者，可睡眠、可跨上下文计数。代价要说清：自旋锁在单核上白烧 CPU，持锁期间绝不能睡眠；互斥锁在中断里用会直接崩。

**DMA 与 Cache 一致性**：DMA 让外设绕过 CPU 直接读写内存，省掉 CPU 搬运。问题出在 Cache：CPU 写的数据可能还在 Cache 里没回内存，DMA 读到的就是旧值；设备写进内存的新数据，CPU 读时可能命中 Cache 里的旧行。所以要按方向维护：CPU→设备先 clean（写回），设备→CPU 先 invalidate（作废）再读。非一致性架构用 `dma_map_single` + `dma_sync_single_for_cpu/device` 管理，一致性架构硬件保证但访问更慢。缓冲区要按 Cache 行对齐、长度补齐，别对大块未对齐区域做 invalidate，否则相邻脏数据会一起丢。

**内存优化与死机排查**：OOM killer 是在物理内存加 swap 耗尽时按 `oom_score` 杀进程，嵌入式里往往直接 panic 或杀掉关键进程，所以要在前面拦住：限制 slab/dentry cache、用 zram/zswap 压缩换出、把大缓冲改成按需分配或内存池、给关键进程调 `oom_score_adj`。定位泄漏看 `/proc/meminfo`、`slabtop`、kmemleak 和 kmalloc trace。死机排查优先级：先看串口日志和 dmesg，oops/panic 会带 PC、LR 和调用栈，信息量最大成本最低；能复现就上 gdb + JTAG/OpenOCD 打断点单步；锁死类问题开 lockdep 看锁序、看是否有中断风暴或 RCU stall；时序和电气问题才轮到示波器、逻辑分析仪看 I2C/SPI 波形。

**OTA 升级与系统选型**：OTA 的标准做法是 A/B 双分区加 Bootloader 校验启动，新固件先写入备用分区、校验（CRC/SHA + 签名）通过再切启动标志，失败自动回滚到旧分区，避免变砖；断点续传按固定块下发并逐块校验，重连后从上次成功的块继续；防刷靠固件签名和版本号单调递增，拒绝降级到有漏洞的旧版本。RTOS 还是 Linux 看四点：硬实时性要求（RTOS 微秒级确定性，Linux 走 PREEMPT_RT 也只是软实时）、内存与成本（Linux 要几十 MB 起）、生态与外设驱动（Linux 生态全、RTOS 更精简可控）、以及是否需要多进程、网络协议栈、文件系统这类复杂功能。
