### 《面试题目》

1. Agent 是跑在浏览器里，还是部署在后端服务器上？这题该怎么说？
2. 为什么选 SSE 来传模型的增量结果？
3. Tool 能访问敏感数据，但当前用户没权限，怎么防止越权？
4. 给一个整数数组，把每项替换成右侧所有元素的最大值，最后一项替换成 -1，怎么实现？

### 《参考解析》

**Agent 的部署位置**：实际系统通常是「前后端分工」，而不是二选一。模型调用与工具执行必须在后端——API 密钥不能下发到浏览器，工具要访问数据库、内网服务与文件系统，权限校验也只能在服务端做。浏览器侧承担交互与渲染：输入、流式展示、工具执行过程的可视化、以及需要用户确认的动作（例如「即将删除 3 个文件，是否继续」）。状态存放也要分清：会话历史与工具结果存服务端（可恢复、可审计），仅把当前界面状态留在前端。回答时先给结论「控制面在后端、表现层在前端」，再补一条判断依据：任何持有凭证或能产生副作用的操作都不能放在客户端。如果面试官追问「那前端能不能直接调模型」，答「可以用临时凭证做受限调用，但工具编排与权限仍应在服务端」。

**为什么选 SSE**：模型输出是「一次请求、持续返回」的单向流，SSE 正好匹配这个形态：基于普通 HTTP，服务端设置 `Content-Type: text/event-stream` 后持续写入 `data:` 事件，客户端用 `EventSource` 或 fetch 的流式读取消费；自带断线重连与事件 id，经过大多数代理与网关时兼容性好，实现比 WebSocket 简单。相比之下 WebSocket 是全双工、需要额外的连接管理与心跳，适合双向交互（如协同编辑、实时语音）；长轮询延迟高、连接开销大。选 SSE 的代价要说清：单向，若需要中途发送控制指令（停止生成、切换模型）得另开一个请求；HTTP/1.1 下同域并发连接数有限（HTTP/2 多路复用可缓解）；某些代理会缓冲响应导致「不流式」，需要关闭缓冲并设置 `X-Accel-Buffering: no`。

**工具越权的防护**：核心原则是「工具能查，不等于当前用户能查」。三层落实：① 身份来源——工具拿到的用户身份必须来自服务端会话（token 解析出的 uid），不能信任模型传来的 `user_id` 参数；② 授权判断——每次工具调用前，用「主体 + 资源 + 动作」做一次权限判定（RBAC 或 ABAC），查询语句本身也要带租户与权限过滤（`WHERE owner_id = ?`），而不是查出来再在应用层过滤；③ 最小权限——给工具的数据库账号只授予必要的表与操作，敏感字段做脱敏或不解码，写操作要求二次确认并留审计。还要防「间接越权」：模型可能被提示注入诱导去查别人的数据，所以参数校验要做白名单（例如只允许按当前用户的订单号查询），并对异常高频的跨资源访问告警。

**右侧最大值的原地替换**：从右往左扫描，维护 `maxRight` 表示当前位置右侧所有元素的最大值。对每个位置 `i`：先保存 `nums[i]` 的旧值，把 `nums[i]` 写成 `maxRight`，再用旧值更新 `maxRight = max(maxRight, old)`。初始时 `maxRight = -1`，这样最后一个元素自然被替换成 -1，同时避免了一个坑——如果数组全是负数，用 0 或 `Integer.MIN_VALUE` 之外的哨兵会算错，而 -1 只作为「右侧无元素」的初值，由于每步都用旧值更新最大值，负数场景仍然正确。时间 O(n)、空间 O(1)。要能口述边界：空数组直接返回、单元素数组返回 `[-1]`。如果要求不修改原数组，则从右往左填充新数组，逻辑相同。
