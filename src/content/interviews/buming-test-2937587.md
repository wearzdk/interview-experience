### 《参考解析》

**矩阵插列。** 二维列表插入一列的本质是「每行在指定位置插入一个元素」，注意越界与负索引的处理。Python 写法：

```python
def insert_col(mat, idx, values):
    if not (0 <= idx <= len(mat[0])):
        raise IndexError("列下标越界")
    for row, v in zip(mat, values):
        row.insert(idx, v)
    return mat
```

复杂度 O(n·m)（每行插入要搬移元素）。如果矩阵规模大且插入频繁，应改用列式存储或稀疏结构。读取时按 `mat[i][j]` 访问，注意行优先与列优先的缓存差异。

**requests 为什么能在没有消息边界的情况下收到 JSON。** TCP 是字节流协议，本身不保留消息边界，应用层必须自己定界。HTTP/1.1 用的是两种机制：带 `Content-Length` 时按长度读取；使用 chunked 编码时按块长度分块读取，最后以 0 长度块结束。`requests` 作为 HTTP 客户端解析响应头，据此知道 body 到哪里结束，再把完整 body 交给 JSON 解析器。所以「没有消息边界」其实是「TCP 没有，HTTP 有」。如果是自定义的裸 TCP 协议，就必须自己设计定界方式：长度前缀（最常用）、分隔符、固定长度、或关闭连接表示结束。回答时补一句粘包/半包的成因与处理（缓冲区 + 按长度切分），这是面试官真正想听的。

**进程与线程。** 进程是资源分配的基本单位，有独立地址空间，隔离性好、创建与切换开销大；线程是 CPU 调度的基本单位，共享进程的地址空间与文件描述符，切换开销小、通信方便，但需要同步机制保护共享数据，一个线程崩溃可能拖垮整个进程。进程间通信方式包括管道（匿名/命名）、消息队列、共享内存（最快，需同步）、信号量、信号、Socket（可跨机）。选择依据是隔离性与通信成本的权衡。

**MVC 与 MVVM。** MVC 分三层：Model 管数据与业务逻辑，View 负责展示，Controller 接收用户输入、协调 Model 与 View。它的痛点是 View 与 Controller 容易耦合、View 对 Model 的更新需要手动同步。MVVM 在 View 与 Model 之间加 ViewModel：ViewModel 暴露状态与命令，View 通过数据绑定自动同步，双向绑定让「改数据即改界面」；代价是绑定调试困难、复杂页面状态难追踪。前端框架（Vue/React）多采用 MVVM 或单向数据流的思想。

**静态语言的面向对象特性。** 封装（访问控制、隐藏实现）、继承（复用与扩展，注意组合优于继承）、多态（父类引用指向子类对象，运行时动态分派）、抽象（接口与抽象类定义契约）。父子类的调用关系：子类构造时先调用父类构造（Java 用 `super()`，C++ 用初始化列表），子类可重写父类方法，通过 `super` 调用父类实现；父类引用调用被子类重写的方法时执行子类版本（多态），但字段访问看声明类型。Python 的继承是动态的，支持多继承与 MRO（C3 线性化），方法解析按 MRO 顺序查找。

**AI 写代码的注意点。** 可以按「可信度分层」处理：样板代码、测试用例、文档、正则与转换脚本可以让 AI 多写；涉及资金、权限、数据一致性、并发与安全的代码必须逐行 review 并补测试。常见问题包括：编造不存在的 API、忽略边界与错误处理、依赖版本与项目不一致、把示例当成生产代码。防线是编译 + 单测 + 类型检查 + 关键路径手测，以及把「生成代码必须可追溯到需求与测试」写进团队规范。
