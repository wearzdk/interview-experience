### 《面试题目》

1. 队列管理出现数据不一致，怎么定位和修复？
2. 离线任务的调度流程怎么组织？
3. 高优先级任务来了，但集群没有空闲资源，怎么办？
4. 什么是缓存穿透，怎么处理？

### 《参考解析》

**队列数据不一致先画时间线**。把任务状态、消息投递、Worker 执行、结果提交四条线按时间排开，判断是消息重复、任务丢失，还是旧 Worker 覆盖了新状态。典型场景是结果已经写库、ACK 前连接断了，消息重投后如果直接从头执行，就会重复产生副作用；正确做法是重投后先读持久化的终态，已完成则只补确认、不重复执行。修复要落到机制：消息带业务唯一键、消费端幂等、状态机只允许合法迁移、ACK 放在持久化之后、加对账任务兜底。定位手段是查消息轨迹、消费日志、任务状态表与数据库写入记录，按同一任务 ID 串起来看。

**离线任务调度**：先保存任务定义与输入引用（对象存储路径、版本、参数），再可靠地发出通知；Worker 取得执行权后推进任务、记录检查点，结果与终态持久化后再确认消息；外部操作要有自己的幂等标识，因为消息确认不等于业务天然只执行一次。调度器负责依赖、重试、超时与并发控制，失败任务进死信队列并告警；长任务要能续跑，检查点要包含输入版本与中间结果位置。

**高优先级任务没有空闲资源**：优先级不会凭空增加容量。先看预留资源、弹性扩容能否赶上；再看低优先级任务能否在安全检查点暂停或抢占，暂停要能恢复、不能丢中间状态；没有可抢占任务也没有备用容量，就明确排队或拒绝，并告知预计等待时间与降级选项。不能只回答「提高优先级」，那只是改变排队顺序，不解决容量。

**缓存穿透**：查询的数据在缓存和数据库都不存在，却不断回源。方案是参数校验拦截非法请求、缓存空值并设短 TTL、布隆过滤器提前判断是否存在、对异常高频的 key 限流或拉黑。边界要讲清：空值缓存会占内存，随机 ID 攻击下会不断增长；布隆过滤器有误判、无漏判，新增数据要同步，删除困难；过滤器本身也可能成为瓶颈。更完整的方案是「入口限流 + 布隆过滤 + 空值缓存 + 回源保护」组合，并监控回源 QPS 与缓存命中率。

**备考方法**：这组题的价值在于把「正常完成」与「写库后断线」两种时间线各画一遍，逐项检查重投后读什么、哪些步骤能跳过、确认消息放在哪一步。能把失败路径讲清，比背消息队列的特性列表更能体现后端功底。
