### 《参考解析》

**Agent 与 LLM 的区别要一句话切开**：LLM 是「给定上下文，产出一段文本」的函数；Agent 是「给定目标，自主决定下一步做什么」的系统——它在循环里观察环境、选择工具、执行动作、根据结果修正，直到目标达成或触发终止条件。所以 Agent 的构成是：模型（决策）+ 工具（动作，带参数校验与权限）+ 状态与记忆（多轮上下文、任务进度、断点）+ 编排循环（规划、执行、观察、重试、终止）+ 评测与可观测（成功率的度量、每步的轨迹）。面试官说「你说的都是 LLM」时，要立刻从「模型能力」转到「循环与工程」：谁决定调用哪个工具、失败怎么重试、上下文怎么裁剪、什么时候停下、怎么判断做对了。

**MCP、Skills、Function Call 三者的层次**：Function Call 是模型侧的协议能力——你把一组函数的名称、描述、JSON Schema 参数给模型，模型输出一个结构化的调用请求，执行由你的程序完成，模型不接触真实环境。MCP（Model Context Protocol）是「工具与上下文的供给协议」——它标准化了客户端与服务器之间如何发现工具、资源和提示模板，让同一套工具能被不同宿主复用，解决的是「每家都要自己接一遍」的问题，它的粒度是「一个可调用的工具或一份资源」。Skills 更靠近「能力包 / 作业指导书」——把完成某类任务所需的说明、脚本、参考文件打包，模型按需加载，它解决的是「流程知识与长尾操作怎么组织」而不是单次函数签名。三者的关系可以概括为：MCP 负责把工具接进来，Function Call 负责在某一轮里选中并填参，Skills 负责把「做这类事的步骤与判据」交给模型。

**Python 异步**：`async def` 定义协程，`await` 在遇到 I/O 时把控制权交回事件循环，循环从就绪队列里取下一个任务继续跑。事件循环是单线程的调度器——它维护就绪回调、定时器与 I/O 多路复用（epoll/kqueue），本身不并行执行 Python 字节码。用异步做 I/O 的理由是 I/O 等待期间 CPU 本来空闲，用线程要付出线程切换与内存开销，协程切换在用户态、成本低，几万并发连接也能撑住。事件循环不能并行计算，CPU 密集型任务会阻塞整个循环（所有协程一起卡住），所以要用多进程（`multiprocessing`、`ProcessPoolExecutor`）绕开 GIL 真正利用多核；也可以在异步服务里把重计算丢进进程池，用 `run_in_executor` 或 `asyncio.to_thread` 桥接。异步代码的坑要能说：在协程里调用阻塞库、忘记 await、共享状态没有加锁、以及超时与取消的处理。

**离线惯导与在线导航的融合**：惯导（IMU + 轮速/里程计）靠积分推算位置，短期平滑、长期漂移；在线导航（GNSS、地图匹配、视觉/激光定位）绝对精度好但可能中断或跳变。工程上用误差状态卡尔曼滤波（ESKF）把两者融合：IMU 做预测，GNSS 与地图匹配做观测更新，估计位置、速度、姿态与 IMU 的零偏；GNSS 失锁时靠零速修正（ZUPT）、非完整性约束（车辆不能侧向滑动）和地图匹配维持，恢复后平滑回正。要讲清时间同步、外参标定、观测的协方差怎么设，以及隧道、地下车库这类长时失锁场景的退化处理。

**「接入部门业务的困难点」与反问**：这类问题的答法是先承认信息不足，再给出可执行的切入路径——先弄清部门的业务链路与现有系统边界，找到数据与接口的接入点，从一个小场景做端到端验证，再谈平台化。反问里关于「零代码平台是独立开发还是参与对方业务」的问题问得很好，它其实是在确认岗位是平台方还是乙方；回答时可以顺着说「两种模式的工程重点不同，平台方要抽象通用能力与权限模型，参与业务方要快速交付并沉淀可复用组件」，展示你理解组织分工。

**开源框架的理解**：不要只报名字。选一个真读过的讲：它解决什么问题、核心抽象是什么、扩展点在哪、有哪些设计取舍（性能 vs 灵活、约定 vs 配置）、你在项目里怎么用、遇到过什么坑、读过哪部分源码。被追问「有什么困难点」时给具体的排查过程，而不是「文档少」。
