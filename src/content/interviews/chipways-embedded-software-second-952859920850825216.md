### 《面试题目》

1. 先自我介绍，再挑一个能扛追问的项目，讲清你的职责边界和最终结果。
2. 这个项目的需求是怎么拆成软件模块的？模块之间怎么通信、怎么隔离故障？
3. 量产前你怎么证明实时性达标？除了「感觉挺快」，还有哪些可量化手段？
4. Flash 里同时有参数区和程序区，你怎么保证掉电不把参数写坏？
5. 如果升级包校验通过但新固件一启动就崩溃，系统如何还能回到可升级状态？
6. 厂商 SDK 驱动和自研驱动混用时，你怎么控制质量和联调成本？
7. Cortex-M 上怎么快速判断 HardFault 是「代码跑飞」还是「总线访问失败」？

### 《参考解析》

**项目陈述的边界要划清**。用 30 秒交代背景（学校、方向、主技术栈 C / MCU / RTOS 或裸机 / 总线），一句话说项目目标（控制节点、网关、采集或升级链路），然后明确边界：哪些模块是自己写的、哪些是合作或复用 SDK、接口怎么切。讲难点要落到具体约束——时序、内存、实时性、兼容性或量产问题——最后用可核对指标收尾：控制周期、CPU 占用、故障恢复时间、通过的测试项。

**模块拆分与故障隔离**。按数据流拆：采集 / 驱动、协议、业务状态机、存储与诊断。模块间用明确接口（函数表、消息队列、事件），禁止跨层直接碰寄存器；共享资源（Flash、总线、缓冲区）集中用互斥或单写多读约定。故障隔离靠三件事：单模块超时检测、分区喂狗（看门狗按模块复位而不是整机复位）、错误码逐层上抛，避免一处死循环拖死全系统；关键路径要有降级路径，通信失败进安全态或输出默认值，而不是空等。

**实时性怎么量化**。用 GPIO 翻转配合示波器或逻辑分析仪测两段：ISR 入口到出口、任务唤醒到开始执行，读脉宽要同时报典型值与最坏值。统计 WCET：关掉日志、拉满中断负载，看周期任务是否逾期。RTOS 侧看任务栈高水位、队列积压深度、空闲钩子统计的 CPU 空闲率。对周期任务设截止时间监控，逾期打点并进故障计数。报结论时必须带上测试条件：主频、编译优化等级、外设负载。

**Flash 掉电保护**。参数区独立分区、与代码区分开，擦除按扇区 / 页对齐。可靠性靠双备份或 A/B 副本：写新副本 → 校验 CRC → 再切换有效标志，写入顺序是「先写数据、最后写魔数 / CRC」，掉电最多丢掉一次未提交的更新。写过程关中断或加锁避免重入半写，必要时喂独立看门狗。上电加载时校验 CRC 与版本，失败回滚到旧副本或出厂默认值。还要考虑擦写寿命：参数频繁更新时做磨损均衡或写合并。

**升级后启动崩溃怎么回滚**。核心是任何时刻都保留至少一个可运行镜像：双槽（A/B）或 Boot + 双 App。Boot 记录「试运行」标志，新固件启动后在限定时间内报到「运行正常」才确认升级成功；没报到就回滚到旧槽，或停在 Boot 的通信能力里等待重新下载。崩溃现场尽量写进保留 RAM 或独立日志分区，下一轮上报。升级协议要有镜像签名、CRC 与断点续传，避免反复刷入同一个损坏包。回答时补一句：回滚路径本身也要被测过，否则量产时才发现回滚也起不来。

**SDK 与自研驱动混用**。稳定外设优先用 SDK / HAL，差异大或性能敏感路径才自研或裁剪；在 SDK 外再包一层板级接口，业务只依赖自有 API，降低换芯片的成本。改 SDK 要打补丁并记录版本，不要直接改原文件，否则无法合入官方更新。统一错误返回、超时与初始化顺序——混用最容易出问题的地方是时钟配置和中断优先级冲突。用同一套集成测试覆盖：初始化、边界速率、异常掉线、低功耗进出。

**HardFault 归因**。先读 CFSR：`IACCVIOL` / `DACCVIOL` 偏向 MPU 或访问违例，`IBUSERR` / `PRECISERR` 偏向总线错误；再看 BFAR / MMFAR 是否有效（`BFARVALID` / `MMFARVALID`），有效就说明是哪个地址出了问题。配合栈回溯（从 MSP / PSP 取栈帧里的 PC、LR）定位到具体函数。典型判据：PC 落在非法区域、SP 越界、访问了未使能时钟的外设寄存器或空指针偏移，是「代码跑飞」；地址合法但指向不存在的外设或越界内存，是总线访问失败。工程上要装 HardFault handler 并在里面保存现场，别让设备直接复位。
