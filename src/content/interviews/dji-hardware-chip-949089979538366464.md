### 《参考解析》

**SPI 的 CPOL 与 CPHA**：CPOL 决定空闲时钟电平（0 为低、1 为高），CPHA 决定在第一个还是第二个边沿采样（0 为第一个边沿、1 为第二个），两者组合成模式 0 到 3。配置必须与从设备手册一致，否则采到的位会整体错位。速率取决于从设备支持的最高时钟、走线长度与信号完整性，长线或高阻环境下要降频。

**DMA 启动配置**：外设地址（源或目的）、内存地址、传输长度、数据宽度、地址是否自增、传输方向、循环或单次模式、优先级、以及完成/半完成/错误中断的使能。要点是「外设地址固定、内存地址自增」，循环模式下长度寄存器会在回绕时自动重装。

**`volatile` 的边界**：它告诉编译器该变量可能被外部改变，禁止把读操作缓存到寄存器、禁止删除「看似无用」的读。适用场景是硬件寄存器、中断与主循环共享的标志、DMA 写入的缓冲区。它不保证原子性也不提供内存屏障，`count++` 依然是读改写三步，多核或中断并发下要用原子操作或关中断保护。

**`static` 的三种用法**：修饰局部变量时改变存储期（放在静态区，函数退出不销毁），作用域仍是函数内；修饰全局变量或函数时改变链接属性（内部链接，仅本编译单元可见）；修饰类成员时表示属于类而非实例（C++）。

**结构体内存对齐**：每个成员的偏移要是其对齐值的整数倍，结构体总大小要是最大对齐值的整数倍，因此成员顺序会影响 `sizeof`。把大对齐类型放前面、小类型集中放后面能减少填充。把字节流直接强转成结构体指针的问题有三：对齐不满足可能触发总线错误或性能下降、字节序与协议不一致、编译器可能插入填充导致字段错位；正确做法是按协议逐字段解析或使用 packed 结构并显式处理字节序。

**循环 DMA 与缓冲区覆盖**：用「写指针与读指针」或「半传输/传输完成中断」来划分可读区间。检测空闲只能说明总线上静默了一段时间，不能保证收到完整帧——两帧连发时中间可能没有空闲，粘包要靠长度字段或分隔符判断。若解析任务处理慢于 DMA 回绕，必须能检测覆盖：记录已处理位置与 DMA 当前写位置，若写位置越过了读位置就说明数据丢失，此时应丢弃该段并计数上报，而不是继续解析错位数据。

**双缓冲与队列传值还是传指针**：双缓冲（ping-pong）在任务处理时间可能超过一个周期时仍会失效，需要三缓冲或动态申请。队列传整份数据安全但拷贝开销大、占内存；传指针开销小，但缓冲区的生命周期必须由生产者与消费者约定清楚（通常用引用计数或「消费完成信号量」归还），否则生产者会提前复用正在被读的缓冲区。

**关中断不能阻止 DMA**：DMA 由硬件控制器独立搬运，不受 CPU 中断开关影响。要保证一致性只能从缓存维护（Clean/Invalidate）、内存屏障、或硬件一致性互联（如 AXI Coherency）入手。

**D-Cache 与 DMA 一致性**：CPU 写数据到缓冲区后要 Clean（把 cache 写回内存）再启动 DMA 发送；DMA 接收完成后要 Invalidate（丢弃 cache 中的旧副本）再让 CPU 读。缓冲区还要按 cache line 对齐，避免同一 cache line 内的其他数据被误刷。没有硬件一致性的平台上，这三件事缺一不可。

**FromISR 接口**：中断上下文不能调用可能阻塞的普通 API，`xQueueSendFromISR`、`xSemaphoreGiveFromISR` 这类接口不会阻塞，并通过 `pxHigherPriorityTaskWoken` 告知内核是否需要在退出中断时切换任务。通知失败通常是队列满，此时应计数丢弃并上报，而不是在中断里等待。

**多传感器时间对齐**：硬件上尽量用同一时钟源触发采样，或在采样瞬间读取统一的时间戳计数器；软件上为每个样本记录「采样时刻 + 序号」，按时间戳而非到达顺序对齐。丢帧要靠环形缓冲加序号检测，CPU 繁忙时用 DMA 把数据先搬进内存，任务只做解析。

**FreeRTOS 阶段优先级的改造动机**：标准 FreeRTOS 的优先级是静态的，任务创建后固定，抢占式调度下高优先级任务一旦就绪就会立即抢占。项目里若存在「同一任务在不同阶段需要不同优先级」的场景（例如采集阶段要实时、处理阶段可让出 CPU），应用层用状态变量只能让任务主动让出，无法改变被抢占的顺序，因此才考虑改内核让优先级随阶段变化。回答时要讲清改动的数据结构（就绪链表按优先级组织）、调度器在何时重新选择任务、以及副作用（优先级反转风险、调试难度、与原有 API 的兼容性）。

**UI 帧率优化**：先定位掉帧发生在哪一帧、是主线程阻塞还是渲染耗时，工具上用 systrace / Perfetto 或平台自带的帧统计；常见手段是减少主线程工作量（把解析、IO 移到子线程）、降低过度绘制、复用视图、减少布局层级、控制刷新频率。

**H.264 码流结构**：由 NAL Unit 组成，每个 NAL 有起始码与头字节，SPS/PPS 描述序列与图像参数，IDR 帧可独立解码，P 帧依赖前面的参考帧。FFmpeg 解码后通常输出 YUV420P（或 NV12），再转成渲染需要的格式。
