### 《核心观点》

1. 背景：硕士毕业两年，社招方向是后端加 Agent，手撕难度大约 LeetCode 100 题水平，意向与 OC 覆盖几家大厂和一些中小厂、初创公司。
2. 三个多月面了 50 多场，在职准备的辛苦程度容易被低估：工作日干到凌晨，周末很少休息，面试地点在会议室、食堂、楼梯间、花园都有，面完赶紧切回工位干活，晚上再加班复盘记题。
3. 当下社招有很大一部分隐性成本是信息差：很多公司面什么、什么风格、不同轮次考察什么重点，网上很难搜到最新最真实的内容，Agent 方向尤其零散。
4. 大厂根本不会只问 Agent——后端基础、算法手撕、项目深挖、场景设计一样不会少，和纯后端比只多不少。
5. 值得整理成自己的面试记录：从一面基础考察到二面项目深挖再到总监面的压力拷问，完整还原现场节奏和考察顺序。
6. 只有原题没有标准答案是好事：拿着真实问题结合自己的项目经历去梳理思路，比背带答案的题库更有用。
7. 失败的经验比成功的经验更值得复盘，把反思写下来才能形成自己的方法论。
8. 心态上，「再回首，轻舟已过万重山」——已读不回和横向对比是常态，坚持投递与复盘最终会换来 offer 和认可。

### 《参考解析》

**Agent 方向的社招到底考什么**：从这位候选人的面试记录看，考察是「纯后端 + Agent 增量」的组合。后端部分与普通后端岗完全一致：Java/Go 语言与并发、JVM 或 GC、MySQL 索引与事务、Redis 数据结构与持久化、消息队列与幂等、分布式一致性与限流熔断、网络与操作系统八股，加上一到两道手撕算法。Agent 增量部分集中在：大模型调用与流式输出、上下文窗口管理、记忆的存储与检索、RAG 的召回与评测、工具调用的设计与参数校验、多 Agent 编排与状态机、Prompt 与评测集建设、以及成本与延迟的权衡。准备策略是先把后端基础按面经清单过一遍保证不丢分，再把 Agent 相关的项目讲到能抗住三层追问。

**为什么 Agent 方向的信息差特别大**：这个方向技术栈新、术语还没统一，同一家公司不同团队的岗位描述可能完全不同（有的其实是后端加调 API，有的真的在做训练和推理优化）。求职者的应对办法有三条：一是明确区分「Agent 应用工程」和「模型算法」，投递前看清 JD 里的关键词（是否要求 PyTorch/分布式训练，还是要求服务端框架与中间件）；二是把面试当信息采集，每场结束记录被问到的题目和追问方向，几场之后就能看出这家公司真正的考察重心；三是主动向面试官反问团队的技术栈与业务场景，反问的回答往往比 JD 更真实。

**面试记录怎么整理才有用**：不要记成流水账。建议每场一页：公司、轮次、面试官角色、时长、题目原文（脱敏，去掉项目名和内部指标）、当时回答的要点、卡住的位置、以及下次改进项。按轮次分开看规律——一面偏基础与广度，二面偏项目深挖与方案取舍，总监面或交叉面偏业务理解、稳定性与压力测试。把题目按「答得好 / 答得一般 / 完全不会」三档标记，第三档直接进入复习队列。三个月 50 场下来，这份记录本身就是最有价值的资产。

**三轮次的应对重点**：一面（通常 40~60 分钟）保持节奏别超时，自我介绍控制在两分钟，项目介绍准备 30 秒、2 分钟、5 分钟三个版本；技术题边想边说，把思路讲出来比直接给答案重要。二面重点是项目深挖：面试官会顺着你的描述往下钻三层，所以要提前给自己的项目准备「为什么这么设计、替代方案是什么、有什么代价、数据是多少、如果重做会改什么」这套问答。总监面多在考判断力与稳定性：为什么离职、职业规划、遇到冲突怎么处理、对业务的理解，回答要具体、有事实支撑，避免情绪化和空话。

**在职准备的时间管理**：在职求职最难的是精力分配。可行的做法是固定几个时段：工作日的午休用来投递和约面，晚上固定一到两小时刷题或背八股，周末拿出半天做项目稿和模拟。面试尽量约在早上或午休，面完立刻写三行记录（被问了什么、哪里答得不好、下次补什么），不要拖到晚上——拖了就忘了。同时管理好预期：已读不回和面试后被横向比较都是常态，把结果拆成「投递量、约面率、进二面率」来看待，某一环偏低就针对性修，而不是靠情绪硬扛。
