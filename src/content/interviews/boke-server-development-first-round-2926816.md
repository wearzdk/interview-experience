### 《面试题目》

1. 实习经历介绍。
2. 针对简历上的项目逐条细致追问。
3. 基本没有八股。
4. 没有手撕。

### 《参考解析》

**纯项目深挖的面试，考的是「你到底做没做过」。** 面试官不是随机挑问题，而是心里先把你项目的数据流画一遍，再从入口到出口逐段下钻。所以准备方式不是背题，而是把项目写成一条链路：每一段都要能说出输入量级（QPS、并发连接数、单次批数据量）、用了什么数据结构或存储、失败与超时怎么处理、最后怎么验证。凡是答不出的地方，面试官会默认那段不是你做的——这比答错原理更致命。

**讲实习经历要先把「边界」讲清楚。** 业务目标是什么、需求是谁提的、你负责的模块到哪为止、和上下游的接口契约长什么样，然后才是你做的关键决策：为什么选这个方案而不是另一个，代价是什么。最后给量化结果，延迟、错误率、资源占用、人力成本任选能拿到的口径，并主动说一句复盘里的不足。团队成果与个人贡献必须分开说，把别人做的算成自己的，只要追问两层就会露。

**简历上写不细的点，是这场面试最大的风险。** 写「优化了接口性能」却答不出优化前后的 P99、慢在哪一段、怎么定位的，等于自己给面试官递刀。写技术栈时同理：列了 Redis / Kafka / K8s，就要准备好被问「具体用它的哪个特性、为什么不是别的」。反过来，项目里真踩过的坑、真做过的取舍，是最能拉开差距的素材，主动讲比等追问更占优。

**「没有八股」不等于不用准备原理，而是原理会被换成项目语境来问。** 服务器开发的常见追问面依旧绕不开：并发模型（线程池、协程、事件循环各自适合什么负载）、连接管理（长短连接、心跳、断线重连与消息补发）、一致性与幂等（重复请求怎么去重、顺序怎么保证）、存储（索引设计、缓存穿透与击穿、冷热数据分层）、以及限流降级与可观测性。区别在于面试官不会问「什么是 X」，而是问「你这个场景下 X 怎么做的」，答案必须落在自己的系统上。

**没有手撕代码时，主动创造可验证的信号。** 讲性能瓶颈时顺手写两行伪代码或推一次复杂度，讲并发时把加锁粒度与临界区画出来，都是低成本的加分项。反问环节建议问团队在做什么产品、线上稳定性用什么指标保障、值班与事故复盘机制怎么跑——这类问题能同时判断岗位含金量与面试官的水平。
