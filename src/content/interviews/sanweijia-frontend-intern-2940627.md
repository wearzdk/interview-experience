### 《参考解析》

**登录注册这道题考的是「有没有真的自己写过一遍」**：字段层面最小集合是账号标识（手机号或邮箱）、密码、确认密码、图形或短信验证码、协议勾选；工程上还要有加密方式（前端不明文落库，密码走 HTTPS 传后端再做慢哈希）、账号唯一性校验时机（失焦异步校验或提交时统一校验）、错误码到文案的映射。面试官继续追问验证码的作用，标准答案是区分人与机器、限制批量注册与撞库、顺带防短信轰炸和接口刷量，回答时补一句「验证码校验必须在服务端做、并且一次性消费」，就能把这道题从「表单有哪些格子」拉到「安全设计」。接口封装那一问要能说出 axios 实例化的几件事：`baseURL`、超时、请求拦截器加 token、响应拦截器统一拆业务码、错误统一提示、刷新 token 的重放机制。报错处理要分层：网络层（超时、断网、跨域、CORS 预检失败）与业务层（4xx 参数问题、401 未登录或 token 过期、403 无权限、409 冲突、5xx 服务端异常）分别怎么处理，哪些该重试、哪些重试会写脏数据。

**闭包与它的应用**：闭包是函数与其词法作用域的组合，内层函数持有外层变量，外层执行结束后这些变量仍被引用而不释放。应用场景举四个就够：防抖与节流（用闭包保存 timer 和上一次执行时间）、柯里化与偏函数、模块模式下的私有变量、一次性初始化的结果缓存。要主动说出代价——闭包引用的变量不会被回收，在 Vue 里定时器、事件监听、观察者忘记在 `beforeUnmount` 清理就是典型泄漏；也要说清解法（置 null、`clearInterval`、`removeEventListener`、用 `effectScope` 收拢）。

**Vue 生命周期与组件通信**：Vue 3 的顺序是 `setup` → `beforeMount` → `mounted` → `beforeUpdate` → `updated` → `beforeUnmount` → `unmounted`，被 `keep-alive` 包裹时多出 `activated` / `deactivated`，服务端渲染没有 `mounted`。选项式写法里 `beforeCreate` 与 `created` 在 `setup` 中被合并。通信方式按关系分：父子用 props 下行、emit 上行；跨层用 `provide` / `inject`；兄弟或任意组件用状态库（Pinia）；需要拿实例方法用模板 ref 加 `defineExpose`；透传属性与事件用 `$attrs`。`v-model` 是语法糖：Vue 3 展开成 `:modelValue` 加 `@update:modelValue`，Vue 2 是 `:value` 加 `@input`（可用 `model` 选项改名）；本质仍是单向数据流，子组件不能直接改 prop，只能发事件请父组件改。带参数的 `v-model:title` 只是把 `modelValue` 换成 `title`。

**逆推题的关键是把「剩多少」定义清楚**：设第 n 天开始时有 xₙ 个，吃掉一半多 3 个后剩 xₙ/2 − 3，所以 xₙ = (xₙ₊₁ + 3) × 2，从已知的「第五天吃完剩 2 个」倒推五次：2 → 10 → 26 → 58 → 122 → 250，第一天是 250 个。如果理解成「第五天开始时只剩 2 个」，那就只吃了四天，答案是 122。口述代码就是一次循环：

```js
let rest = 2;
for (let day = 5; day >= 1; day--) rest = (rest + 3) * 2;
console.log(rest); // 250
```

补一句「每一步都应是整数，出现小数说明假设错了」，比只报答案更能体现思路。

**判断点在多边形内用射线法**：从待判点向右引一条水平射线，统计与多边形各边的交点个数，奇数在内、偶数在外。实现时几个坑必须提：水平边要跳过（否则可能重复计数或除零）；顶点相交时用半开区间判断 `(yi > py) !== (yj > py)` 保证每个顶点只算一次；浮点比较留 epsilon；点在边上属于边界情况，先单独用叉积判共线再决定算内还是算外。复杂度 O(n)，点数很大时先做包围盒剔除，或把多边形切成网格 / 四叉树做索引。凹多边形射线法同样成立，自交多边形语义不清，改用环绕数（winding number）更合适。

**事件循环的输出是 1 → 3 → 2**：同步代码先执行完，输出 1；`await` 会把其后的代码挂起到微任务队列；定时器回调属于宏任务。当前宏任务（整段脚本）执行完后清空微任务队列，输出 3；再取下一个宏任务，输出 2。要能补两句：`await` 后面即使跟的是已 resolve 的值也会让出一次执行权；`Promise.then`、`queueMicrotask`、`MutationObserver` 都进微任务，`setTimeout`、`setInterval`、I/O 回调进宏任务，微任务里再产生微任务会在同一轮里被清空，所以死循环的微任务会饿死渲染。面试官问这一题，实际是在确认你是否理解「为什么有时先执行的代码反而慢」。

**Vue 那一问之后的 CSS**：不要只背属性名，按用途分组说：盒模型（`box-sizing`、`margin` 折叠）、布局（`display: flex` 的主轴交叉轴与 `flex-grow/shrink/basis`、`grid` 的 `grid-template-areas`、`position` 的 `fixed/sticky` 差异）、层叠（`z-index` 只在层叠上下文内比较）、响应式（媒体查询、`clamp()`、`vw/vh`、`container-query`）、动画（`transition` 与 `animation` 的区别、`transform` 不触发重排）。答的时候挑一个自己真正用过并踩过坑的（比如 `sticky` 需要父级没有 `overflow: hidden`），可信度远高于罗列。
