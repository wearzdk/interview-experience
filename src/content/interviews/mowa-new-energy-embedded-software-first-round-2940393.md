### 《参考解析》

**MQTT 用发布订阅和极简头部换取弱网适应性。** 它运行在 TCP 之上，客户端与 broker 建立长连接，按 topic 发布与订阅，topic 支持 `+` 单层与 `#` 多层通配符，发布者与订阅者互不知道对方，适合设备数量多、网络不稳定、上下行带宽都很小的场景。固定头部只有 2 字节，协议开销远小于 HTTP；`keepalive` 与遗嘱消息（LWT）让 broker 能及时发现掉线并通知业务方；`retained` 消息让新订阅者立刻拿到最新状态；QoS 0 最多一次、QoS 1 至少一次、QoS 2 恰好一次，分别对应可丢的遥测、需要确认的指令与不能重复的计费类消息。局限也要讲清楚：MQTT 不负责低延迟硬实时，QoS 2 的两次往返会放大延迟；大文件与高频视频不适合走 MQTT；broker 是单点，生产环境要做集群与持久化会话。嵌入式端常见做法是一机一密接入、按主题做 ACL、断线重连后补发离线消息。

**TCP 与 UDP 的选择取决于能否容忍延迟与丢失。** TCP 面向连接，三次握手建连，提供可靠、有序、去重的字节流，带流量控制与拥塞控制，代价是重传与队头阻塞；UDP 无连接，保留报文边界，不保证送达与顺序，头部只有 8 字节，延迟低但可靠性要应用层自己补。设备侧常见分工是：固件升级、配置下发、订单上报走 TCP 或 MQTT，实时控制环、传感器高频采样、音视频走 UDP，并在 UDP 上自建序列号、ACK、重传与 FEC。还要注意 TCP 的 Nagle 算法会合并小包增加延迟，交互式协议可开 `TCP_NODELAY`；UDP 要注意 MTU，超过路径 MTU 会分片，弱网下分片丢失会放大重传成本。

**RS485 与 CAN 都是差分总线，但解决的问题不同。** RS485 只定义物理层：两根差分线 A/B、半双工、多点总线，收发器通过 DE/RE 切换方向，两端需要 120Ω 终端电阻与偏置电阻，总线长度与速率成反比（低速率下可达千米级），节点数受收发器驱动能力限制。它本身没有仲裁、没有帧格式、没有错误恢复，可靠性依赖上层协议，工业上最常见的是 Modbus RTU。CAN 则把物理层与数据链路层一起定义：多主结构、按 ID 非破坏性仲裁、CRC 校验、应答与错误帧、自动重发，节点在总线忙时不会碰撞丢包；高速 CAN（ISO 11898-2）常见 125kbps 到 1Mbps，1Mbps 时总线长度约 40 米；低速容错 CAN（ISO 11898-3）速率不超过 125kbps，但支持更长总线与单线故障下的降级运行，常用于车身舒适系统。CAN FD 在数据段可提速到 2Mbps 以上，适合固件升级与大数据块传输。两者都要注意共地、隔离、浪涌防护与终端匹配，否则现场会出现随机误码。

**指针与引用的差异在语义而不只是语法。** 引用是已有对象的别名，定义时必须绑定，不能为空、不能重新绑定、不能做指针算术，`sizeof` 得到的是被引用类型的大小；指针是一个存地址的对象，可以为空、可以改指向、可以加减、可以有多级。编译器通常用指针实现引用，因此运行期成本相近，但引用给调用方的是「一定有效」的契约，适合参数传递与运算符重载；需要表达「可能没有」、需要遍历或管理生命周期时用指针。返回局部变量的引用、返回临时对象的引用、以及把引用成员存进生命周期更长的对象，都是常见悬空来源；常量引用可以延长临时对象生命周期，但只限绑定到该引用本身。结构体与联合体的区别在内存布局：结构体成员各自占空间，按最大对齐要求补齐，成员地址依次递增；联合体所有成员共享同一块存储，大小等于最大成员并按最大对齐取整，同一时刻只有一个成员有效。联合体常用于协议帧的多种视图、变体类型与节省 RAM，但读写非活动成员在 C++ 中属于未定义行为（C 中允许实现定义的类型双关），跨平台还要处理字节序与对齐。

**C++ 多态分编译期与运行期两条路。** 运行期多态靠虚函数：含虚函数的类有一张虚表，对象里放 vptr 指向所属类的虚表，调用时通过 vptr 间接跳转，因此无法内联、有一次间接寻址开销；基类析构必须是虚的，否则通过基类指针删除派生对象只析构基类部分；派生类用 `override` 让编译器检查签名，`final` 阻止继续派生；按值传递会发生对象切片，多态必须用指针或引用。编译期多态靠函数重载、模板与 CRTP，在编译期完成分派、可内联、无运行期开销，代价是代码膨胀与编译时间。嵌入式中数据面、逐字节处理通常避免虚函数，控制面用虚接口换取可扩展性；如果关闭 RTTI 与异常，`dynamic_cast` 与 `typeid` 就不能用，需要自己加类型标签。多态的价值在于让上层依赖抽象、下层可替换，而不是为了用而用。

**进程与线程的通信机制要按隔离级别选。** 进程间有管道与命名管道、消息队列、共享内存、信号量、信号、Unix domain socket 与网络 socket；共享内存最快但要自己配信号量做同步，管道简单但只能单向字节流，socket 可跨机器。线程间共享地址空间，主要靠互斥量、条件变量、读写锁、自旋锁、信号量与原子操作，配合线程局部存储隔离上下文；条件变量必须配谓词循环等待，防止虚假唤醒。嵌入式中还要考虑中断上下文不能睡眠、不能在 ISR 里拿可能阻塞的锁、锁的持有时间要短；跨核场景下自旋锁要配内存屏障，避免编译器与 CPU 重排导致的可见性问题。
