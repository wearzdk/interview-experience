### 《面试题目》

1. 自我介绍。
2. Agent 项目是自己做的吗？什么时候开始做的？是在实习公司做的吗？
3. 开源项目主要是参与贡献了 PR 吗？
4. Agent 项目用什么语言？对 Java 有了解吗？
5. 结合实习参与的模块，讲一下公司的产研协作流程。对传统软件工程过程有了解吗？
6. AI Native 的产研协作是否仍然遵循传统软件工程过程？AI 带来了哪些变化，可能有什么问题？
7. 权限中台的技术设计、登录、权限和第三方授权，是配合同事参与，还是自己负责？
8. 为什么离开上一段实习？更想做 Agent 开发，还是也接受业务系统开发？
9. 什么时候能到岗？可以实习多久？

### 《参考解析》

**项目归属要讲清楚**：初创公司面试官对「这是你自己做的还是公司的」很敏感。回答要明确三件事：项目来源（个人练手 / 实习任务 / 开源贡献）、你负责的部分（从需求到上线的哪几段）、可验证的产出（代码仓库、上线地址、用户量、PR 链接）。含糊其辞会被当成包装。

**传统软件工程过程**：需求分析 → 设计（架构、接口、数据模型）→ 开发 → 测试 → 发布 → 运维与迭代，配套的是评审、文档、版本管理、CI/CD。AI Native 的变化主要在「执行层」：生成代码、写测试、生成文档、分析日志的速度大幅提升，一个人能覆盖更多环节；但「决策层」没有变——需求是否真实、方案取舍、质量门禁、上线风险仍然要人负责。带来的问题：代码量膨胀但可维护性下降、review 负担集中、AI 生成的测试只测「实现」不测「需求」、团队对 AI 产出的质量预期不一致。

**权限中台**：讲清楚模型（用户-角色-权限-资源，RBAC/ABAC）、登录（账号密码/短信/第三方 OAuth2/OIDC，token 与 session）、鉴权（网关统一校验、服务内细粒度校验）、第三方授权（scope、授权码流程、token 刷新与撤销）。如果只是配合同事，就说明你负责的那一块（例如某个资源的权限校验、某个登录方式的接入），不要冒领整体设计。

**为什么离开上一段实习**：讲目标与现实的差距，不评价人。例如「想做偏 Agent 的应用开发，实际更多是业务系统的增删改查，所以想找一个更贴近方向的环境」。同时说明你从上一段带走了什么（工程规范、协作方式），避免给人「待不住」的印象。

**Agent 开发还是业务系统**：初创公司往往两者都要做，回答可以表达偏好但不要关门：「更想做 Agent 方向，也接受业务系统，因为业务系统能让我理解真实数据与流程，对做 Agent 有帮助。」这比「只想做 Agent」更容易拿到 offer。

**面试官的建议值得记下**：讲 Agent 项目时，技术之外要回答「用户是谁、解决什么问题、效果怎么衡量」。这三点恰好是很多学生项目缺的——有 demo 没有用户、有功能没有指标。补上这三个问题，项目叙述的完整度会明显不同。

**这类小厂面试的特点**：不问八股、重沟通与动机、决策快。要准备的是「你能来多久、能做什么、怎么和团队配合」，而不是算法题。反问可以问团队规模、实习生带教方式、业务当前最缺什么。
