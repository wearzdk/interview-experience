### 《参考解析》

**aicoding 环节考的不是「写出来」，是「改得对、说得清」**

这类现场改代码的题，面试官看的顺序是固定的：你先读懂代码在干什么 → 你怎么找到问题 → 你怎么验证改对了 → 你能不能顺着追问把设计拉开。所以拿到那段麻将判胡代码，别急着敲键盘。第一步先复述规则边界：胡牌是 4 组面子加 1 对将，还是也要支持七对、十三幺、杠之后补牌；字牌能不能做顺子。这一步问清楚，比闷头改十行更有分。然后跑两个最小样例（一个能胡、一个差一张），把 bug 定位到具体一类：常见的是牌数统计没校验 14 张、把将牌当面子重复用、回溯时状态没还原、数组下标越界、顺子判断跨了花色。改完主动交测试用例——标准胡、七对、单吊、字牌刻子，这比说「改好了」有说服力。

「动态配置模块」是这题真正的分水岭。硬编码 `if (isQiDui) return true` 一层层堆下去，换一个地区规则就要改一次代码。正确方向是把胡型写成**声明式规则**：一条规则 = 牌型模式（n 个面子 + m 个将）+ 匹配器，规则注册进表里按优先级跑，地区差异只是配置数据不同。能讲到「规则可组合、失败可解释（告诉用户差哪张牌）、后续加规则不改主流程」，这一问就到位了。

二面的限流器代码同理，先讲清它想实现什么（令牌桶还是滑动窗口），再逐条列问题：时间基准用 `System.currentTimeMillis` 但没考虑并发，`check-then-act` 在多线程下会超发；令牌补充后没有对桶容量封顶，长时间空闲后一次放出全部令牌；用 `sleep` 等待令牌会把线程堆在池子里；单机限流被当成分布式限流用；异常路径没归还许可。找准两三条讲透，比罗列十条更像干过活。

**缓存三件套：布隆过滤器挡在链路最前面，为的是不打到 DB**

这条链路的顺序是：请求进来先过布隆过滤器 → 存在的才查 Redis → 未命中再抢分布式锁回源 → 查库为空写空值缓存。三个组件各治一种病，答的时候要能把病名对上。

布隆过滤器治**穿透**（查一个数据库里根本不存在的 key，每次都打到 DB）。原理是一个位数组加 k 个哈希函数：写入时把 k 个位置置 1，查询时只要有任意一位是 0 就一定不存在，全是 1 则**可能存在**。特征是只会误判、不会漏判，且标准实现不支持删除（要删得用计数布隆或定期重建）。面试官追问「误判率怎么控」，答位数组长度 m 与元素个数 n 的比值、哈希个数 k 的取值，通常按 1% 误判率设计。

双重判定锁治**击穿**（热点 key 过期瞬间大量并发回源）。第一次判定在锁外查缓存，快速返回；未命中才去抢锁，拿到锁的线程**再查一次缓存**——因为等锁的这段时间里，前一个持锁线程很可能已经把数据回填了。第二次判定就是省掉重复回源的关键。注意锁要带超时、要有续期或看门狗，回填失败要释放锁，否则一个异常就把热点锁死。

空值缓存治**穿透之后的漏网之鱼**与布隆过滤器的误判：查库为空也写一个短 TTL 的占位值，避免同一个不存在的 key 反复穿透。TTL 要短（几十秒到几分钟），且要和正常数据用不同的标记区分开，否则「缓存里有值但值是 null」会骗过下游逻辑。

雪上加霜的第四种是**雪崩**（大批 key 同时过期或缓存整体不可用）：解法是 TTL 加随机抖动、热点 key 逻辑过期不设物理过期、多级缓存加限流降级。能主动把这四种病分清楚，比背「缓存穿透击穿雪崩」三个词强得多。

**消息重复消费：先承认它必然发生，再谈幂等**

答这题最容易翻车的一句是「我们保证消息不重复」。正确的前提是 MQ 基本只提供 at-least-once：生产者发送超时重试、broker 在 ack 丢失或消费超时后重投、消费者 rebalance 时分区被重新分配，三条路都会让同一条消息来两次。所以问题不是「怎么不重复」，而是「重复了怎么办」。

标准答法是分层做幂等。最硬的一层是数据库唯一约束：用业务唯一键（订单号 + 操作类型）建唯一索引，重复插入直接冲突，简单可靠。第二层是去重表或状态机：只允许「待支付 → 已支付」这样的一次跃迁，重复消息进来发现状态已变就丢弃，这比 setnx 更贴业务。第三层是 Redis 的 `SET NX` 前置去重，速度快但要注意它和业务写入不在同一个事务里，进程崩在中间仍会漏，只能当第一道筛子。再往上是版本号或乐观锁，处理并发更新。反过来，答「关掉重试」「加个 sleep」都是减分项。

顺手补一句顺序性会显得更完整：同一个业务键的消息要打到同一分区（按 key 哈希），否则幂等做对了、状态仍可能乱序。

**流程上的一点观察**

一面偏基础与现场编码，二面大部分时间在追问实习，两场都会给一段有 bug 的代码让你当场处理——这类岗位对「能不能上手改存量代码」的权重明显高于纯八股。这轮走的是内部转岗（活水）而不是外部秋招，时间线里因此出现过一个插曲：HR 换人之后流程被误判成不推进，重新对齐才恢复，最终在两周内走完二面、HR 面和审批。这类反复多半是内部交接问题而不是对你的评价，遇到流程突然停住，主动找对接人确认状态比干等有用。
