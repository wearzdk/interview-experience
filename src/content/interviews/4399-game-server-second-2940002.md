### 《参考解析》

**为什么做游戏服务器**：面试官在验动机的真实性。有效的答法是「具体体验 + 具体问题 + 具体选择」：玩过什么品类、注意到什么技术现象（延迟、外挂、匹配体验、同屏人数），因此想去做服务端。帖主的项目与游戏无关，被追问「为什么没写游戏 Demo 到简历」时，诚实说明取舍（简历篇幅留给更有产出的项目、Demo 规模不够）比硬编一个好。

**大学怎么积累、看过哪些开源代码**：这题考的是「有没有真的动手」。回答要给可验证的痕迹：读过哪个项目的哪部分源码（例如某框架的网络层、某引擎的序列化）、为什么读、读完之后改了什么。只说「看过 Redis 源码」会被追问「看了哪个模块、有什么设计你觉得好」，答不上来就是减分。

**下载开源模型/代码后做了什么优化**：必须有量化结果。例如「把开源 RAG 项目的 PDF 解析换成按标题层级切块，召回准确率从 x 提到 y」「给推理服务加了批处理，QPS 从 a 提到 b」。没有数字就说清楚怎么测的、测了哪些样本，也比「做了一些优化」强。

**技术文章是否原创**：CSDN/掘金这类博客在面试里是双刃剑——写得好是加分（说明有沉淀），洗稿或纯 AI 生成被识破是硬伤。如实说明写作方式（自己总结、配图自己画、代码自己跑过），并准备一篇能展开讲的文章。

**主动做过什么有价值的事**：用 STAR 讲一件小事即可：发现什么问题（监控缺失、重复劳动、文档过期）→ 你做了什么（写脚本、补监控、整理文档）→ 结果（节省多少时间、避免什么故障）→ 影响范围（团队几个人用）。面试官在意的是「不需要别人安排也会动手」。

**工具是否真被使用、提效多少**：这是二面最容易被问穿的一题。要能说出：谁在用（团队几个人、哪个角色）、用在哪一步（写用例、生成报告、查日志）、提效怎么算（原来人工多久、现在多久、样本多少）、还有什么不足（准确率、维护成本、边界场景）。只讲「做了个工具」没有落地数据，会被判定为自嗨。

**怎么平衡 AI 提效与独立思考**：给一条可执行的边界：机械性、可验证的工作交给 AI（样板代码、单测、文档、日志分析），需要判断的（架构取舍、根因定位、方案评审）自己主导；AI 的输出必须能解释、能验证，看不懂的代码不进主干。这样既表明拥抱工具，也表明不会把判断力外包。

**性格缺点**：选一个真实但不致命的，并说明正在怎么改。例如「早期做项目容易一头扎进细节，忽略排期，后来养成了先拆里程碑、每天对齐进度的习惯」。避免「我太追求完美」这类伪缺点，也不要把核心能力说成缺点。

**加班与作息**：如实回答能接受的节奏，同时给出可持续的理由（效率、稳定性）。游戏行业加班是常态，回避或过度承诺都不合适；可以问清楚团队的发布节奏与调休制度。

**期望薪资**：给一个区间，依据是「同岗位同城市的市场价 + 自己已有的 offer + 对公司的意愿」。不要报一个明显超出范围的数字又不解释，也不要说「都可以」。如果有竞品 offer，如实说岗位与城市，不要编造。

**家庭情况这类问题**：涉及隐私，可以简短回答与求职相关的部分（是否愿意来这个城市、家里是否支持），不必展开细节。面试官问这个通常是在评估稳定性与到岗意愿。

**反问**：认真看过 JD 的话，问具体的业务与技术：这个岗位负责哪款游戏/哪个模块、服务端的技术栈与自研程度、新人前半年怎么带、团队现在的发布节奏。避免问「公司文化怎么样」这种官网能查到的。
