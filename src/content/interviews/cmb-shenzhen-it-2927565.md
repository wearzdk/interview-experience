### 《面试题目》

1. 单选 45 题 ×1 分
2. 多选 5 题 ×2 分
3. 填空 10 题 ×2 分
4. 程序填空 2 题 ×5 分（含二叉树找第 k 小元素）
5. 应用题 5 题 ×7 分（含 SQL 题，其余为系统设计与 agent 相关的开放题）
6. 整体考点：大模型与 agent 基本概念、计算机网络、Java 基础

### 《参考解析》

**银行科技岗笔试的特点**：这次笔试没有行测，说明考察的完全是技术广度，且分值结构（应用题 35 分）决定了「开放题才是拿分重点」。复习优先级应该是：大模型与 Agent 的基本概念（这是近年银行笔试的新增必考项）、计算机网络、Java 基础、以及数据库 SQL。

**大模型与 Agent 概念题怎么准备**：高频考点包括：大模型的基本原理（Transformer、Token、上下文窗口、温度等采样参数）、提示工程（few-shot、CoT、结构化输出）、RAG 的流程与作用（解决知识时效与幻觉）、微调 vs RAG 的取舍、Agent 的组成（规划、工具调用、记忆）与常见模式（ReAct、Plan-and-Execute）、MCP 与 Function Calling 的关系、以及模型评估指标（准确率、幻觉率、延迟与成本）。概念题通常只要求辨析，但开放题会要求你写一段方案，所以每个概念都要能补一句「它解决什么问题」。

**程序填空与 SQL**：二叉树找第 k 小元素是「中序遍历 + 计数」的经典题（BST 中序有序，第 k 个访问到的就是答案；也可用左子树节点数剪枝）。程序填空类题目要特别注意边界条件与递归出口，先通读代码判断整体算法再填空。SQL 题常见的是分组统计、窗口函数（`row_number`/`rank` 取每组前 N）、多表关联与去重，写之前先把口径用一句话说清楚（统计什么、按什么分组、过滤条件是什么），再落到语法。

**系统设计开放题**：银行场景的系统设计题往往围绕「高可用 + 一致性 + 安全」：比如设计一个交易流水查询、对账系统或权限系统。答题框架是需求澄清（QPS、数据量、一致性要求）→ 存储设计（分库分表键、索引）→ 服务设计（接口、幂等、限流）→ 一致性方案（事务、消息、对账）→ 安全与审计（鉴权、脱敏、日志）。用这个顺序写，即使细节不全也能拿住结构分。
