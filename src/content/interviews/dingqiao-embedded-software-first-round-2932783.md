### 《参考解析》

**这场面试的骨架是「顺着一个项目往下钻到寄存器」**。80 分钟只围绕一个核心项目，从「你负责什么」问到「设备树改了哪几个属性」，中间不留换题的空隙。准备这类面试的正确姿势是把项目整理成一条纵深链：需求 → 方案 → 模块划分 → 关键实现 → 出过什么故障 → 怎么定位 → 最后怎么改。任何一层答不上来，面试官就会在原地继续追，而不是换话题。

**驱动加载失败的定位是有固定顺序的**，答题时把这个顺序说出来比背结论更加分：先看 `insmod` 的返回码（`-ENODEV` 是匹配不上、`-EINVAL` 是参数或寄存器配置错、`-EPROBE_DEFER` 是依赖没就绪），再 `dmesg` 看 probe 里打的日志停在哪一步，然后核 `of_match_table` 的 compatible 与设备树节点是否一致、节点 `status` 是否为 `okay`、`reg` 地址和中断号有没有和别的设备撞、clock / regulator / reset-gpio 是否已由别的驱动提供（这类依赖最容易表现为 defer），最后排除模块依赖顺序与内核版本不匹配（vermagic）。真机上还可以直接读 `/proc/device-tree` 确认设备树真的生效，而不是改了 dts 忘了重新编译 dtb。

**设备树的变更要说出「改哪一类属性、为什么」**：新增节点并写 `compatible` / `reg` / `interrupts` / `interrupt-parent`；引脚复用走 `pinctrl-0` 与 pinmux 节点；时钟与复位写 `clocks` / `clock-names` / `resets`；DMA 相关加 `dma-coherent` 或 `dmas`。工程纪律上，SoC 公共部分在 dtsi 里不动，改板级 dts 或 overlay，改完用 `dtc` 反编译核对。

**「内核主动推送用户态」是这场的分水岭题**。标准答案是 netlink：内核侧 `netlink_kernel_create` 建 socket，用户态用 `NETLINK_*` 协议族绑定后阻塞 `recv`，支持多播组，能做可靠、带边界的一对多推送。其他路径要能对比着说：uevent / kobject 适合设备热插拔通知，sysfs 与 procfs 是被动读、要轮询，字符设备的 `read` + `poll` 只能一对一且要自己定义消息格式。答「用共享内存 + 轮询」会被追问延迟和 CPU 占用。

**自旋锁、DMA、panic 三题考的是「知不知道边界」**。自旋锁只用于极短临界区且不能睡眠的上下文（中断处理），持有期间要 `spin_lock_irqsave` 关本地中断，临界区里不许 `kmalloc(GFP_KERNEL)`、不许 copy_to_user；能睡眠的场景一律用 mutex。DMA 要说清「设备直接读写内存、绕过 CPU」，项目里通常是收发包或大批量采样，配合同步接口（`dma_map_single` / `dma_sync_*`）和 cache 一致性。panic 定位则分两条路：现场看 Call Trace 里的 PC/LR 与栈回溯，用 `addr2line` 对 vmlinux 还原行号；事后靠 pstore/ramoops 把日志落到 flash，或者 kdump 抓 vmcore 用 crash 分析。内存问题接着答 kmemleak（泄漏）、KASAN（越界与 UAF）、slub_debug，配合 `slabtop` 看哪个 cache 在涨。

**C++ 侧几个问题都在考「知不知道语言规则背后的原因」**。引用必须初始化、不能重绑、没有空引用（编译器据此做优化），所以出参要能改指针本身时只能用二级指针，链表删除头节点、字符串数组遍历都是典型场景。「只能在堆上创建对象」的经典写法是把析构函数设为 private 或 protected，再提供 `destroy()`：栈对象离开作用域时无法调用析构，编译期就报错。虚函数那题一定要结合项目——比如用基类指针管理不同型号的传感器驱动，`override` 加虚析构，避免通过基类指针 delete 派生对象时漏析构。

**后半段的网络与流程题是「广度筛」**：TCP 可靠传输答序号确认、超时重传与快速重传、SACK、滑动窗口流控、拥塞控制四段；UDP 做可靠传输就是在上层自己实现序号、ACK、重传、去重和发送窗口（KCP、QUIC 都是这个思路）；HTTP 1.1 的队头阻塞、2 的多路复用与 HPACK、3 换到 QUIC over UDP 解决传输层队头阻塞并支持连接迁移。车载 V 模型则要能画出「需求 → 系统设计 → 软件设计 → 单元测试 → 集成测试 → 验收」的左右对应关系，说清 SDD 是把软件需求翻译成可实现的接口、状态机与数据结构，并且是测试用例追溯的依据——这题答得空，前面技术再熟也会被判「没做过量产项目」。
