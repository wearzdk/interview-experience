### 《面试题目》

1. 请做一下自我介绍。
2. 项目里遇到的难点是什么？
3. 进程和线程的区别是什么？
4. 线程间的通信方式有哪些？
5. 指针和引用的区别是什么？

### 《参考解析》

**进程与线程的区别**：从「资源」和「调度」两个维度讲最清楚。进程是资源分配的基本单位，拥有独立的虚拟地址空间、文件描述符表、信号处理表；线程是 CPU 调度的基本单位，同一进程内的线程共享地址空间和绝大部分资源，只独占栈、寄存器上下文和线程局部存储。由此推出四个差异：① 创建与切换开销——进程切换要换页表、刷 TLB，线程（同进程内）切换只换栈和寄存器，便宜得多；② 隔离性——一个线程野指针踩内存会带崩整个进程，进程之间互相隔离；③ 通信方式——线程直接读写共享变量（需加锁或原子），进程要靠管道、共享内存、socket 等 IPC；④ 崩溃影响范围。面试官几乎一定会追问两点：线程之间究竟共享了什么（堆、全局/静态变量、代码段、fd，不共享栈与寄存器），以及协程和线程的关系（协程是用户态调度、切换不进内核、适合 IO 密集，但要自己管调度与阻塞点）。做嵌入式的话还要能对上 RTOS 的说法：FreeRTOS 里的任务本质就是线程，每个任务独立栈 + TCB，调度器按优先级抢占，中断上下文里不能调用会阻塞的 API。

**线程间的通信方式**：严格说同一进程的线程共享地址空间，需要的不是「通信」而是**同步与互斥**，答题时最好先点明这一点。可用的原语按场景列：① 互斥量 + 条件变量——生产者/消费者模型的标准解，条件变量必须配一把互斥量、并且谓词判断要放在 `while` 里（防虚假唤醒和丢唤醒）；② 信号量——计数信号量做资源计数，二值信号量做事件通知（RTOS 里最常用，还能在中断里 `Give`）；③ 读写锁——读多写少时提升并发度；④ 自旋锁——临界区极短且不可睡眠的场景，中断上下文只能用它；⑤ 原子操作与内存序——无锁队列、CAS 更新状态；⑥ 消息队列/事件标志组——RTOS 里带拷贝和阻塞语义的现成机制；⑦ 屏障——多阶段并行计算的对齐点。最后补一句工程约束：加锁顺序统一避免死锁，锁粒度尽量小，绝不在持锁期间做 IO 或长计算，`std::mutex` / `std::condition_variable` / `std::atomic` 是 C++ 里的对应物。

**指针与引用的区别**：① 本质不同——指针是保存地址的变量，自身占内存、可重新赋值、可为空；引用是已存在对象的别名，必须初始化、绑定后不可改绑，底层通常用指针实现，但语义上不是对象。② 空值——指针可以是 `nullptr`，引用按语言约定不能为空，所以「用引用传参」本身是在向调用方承诺对象一定有效。③ 运算含义——指针 `++` 是地址偏移，`&p` 得到指针的指针；引用 `++` 是对被引用对象自增。④ 层级——可以有多级指针 `int**`，没有多级引用。⑤ 选型——表达「可能没有」用指针或 `std::optional`，表达「一定存在且不换绑」用引用（拷贝构造、赋值运算符的形参就是典型）。常被追问的是 `const` 的读法：`const int* p` 是不能改 `*p` 的指针，`int* const p` 是不能改 `p` 的常量指针，`const int* const p` 两者都锁死；以及「引用做返回值」时返回局部变量的引用会得到悬垂引用。
