### 《面试题目》

**项目与场景**

1. 削峰怎么做？后面请求积压或超时怎么处理？
2. 高并发分析：怎么判断是 IO 阻塞还是 CPU 高并发，分别怎么优化？
3. SKU / 库存表结构怎么设计、怎么快速查询？
4. 优惠券体系：满减、比例、可叠加怎么设计？美团式复杂优惠券的计算逻辑怎么设计算法？

**八股**

5. SSE 和完整的 HTTP 请求各有什么优缺点？
6. TCP 和 UDP 的区别？
7. 数组和链表的区别？队列有什么特点？

### 《参考解析》

**削峰与积压处理**：削峰的本质是把「瞬时写入压力」转成「可控的消费速率」。入口层限流（令牌桶/漏桶）挡住超量请求并快速失败，中间用消息队列缓冲（Kafka / RocketMQ），下游按自身能力消费；同步链路只做校验与落单，异步链路做履约与通知。积压出现后先看消费速率与生产速率、单条消息处理耗时、是否有慢调用或锁竞争，再决定扩容消费者、提高批量、降级非核心逻辑（如延迟发券、延迟发短信）。超时要有分层超时与重试：网关超时、服务超时、下游超时逐层收紧，重试必须带退避与幂等键，否则积压会变成雪崩。监控上盯队列 lag、P99 延迟、错误率与线程池队列长度。

**IO 阻塞还是 CPU 瓶颈**：看指标而不是猜。CPU 使用率高且 `us`（用户态）占比高、runqueue 长，是计算瓶颈；CPU 不高但请求延迟高、`wa`（IO 等待）高、线程池打满在等待，是 IO 阻塞。工具上：`top` / `pidstat` 看 CPU 与 iowait，`iostat` 看磁盘，`jstack` 看线程栈是否大量阻塞在 socket / 数据库连接，`arthas trace` 看单次调用耗时分布。优化方向不同：CPU 瓶颈做算法与序列化优化、减少重复计算、水平扩容；IO 瓶颈做批量、缓存、连接池、异步化（CompletableFuture / 响应式）、读写分离。还有一个常见第三类：锁竞争与线程池配置不当，表现为 CPU 不高、延迟高、线程都在等锁。

**SKU 与库存表设计**：SKU 表按「商品 → SPU → SKU」三层建模，SKU 存规格属性（颜色、容量）、价格、状态，属性用 JSON 或独立的属性值表；库存表按 `sku_id` 维度存可售、锁定、已售三个数量，加版本号或直接用 `UPDATE ... SET available = available - ? WHERE sku_id = ? AND available >= ?` 做乐观扣减。快速查询靠主键与唯一索引（`sku_id` 唯一）、热点库存放 Redis（预扣减 + 异步落库，注意缓存与数据库一致性）、分库分表时按 `sku_id` 哈希。库存的核心不是表结构，而是「不超卖」：单机用数据库行锁或乐观锁，多机用 Redis 原子脚本或分段库存（把 1000 件拆成 10 段，各段独立扣减，减少热点竞争）。

**优惠券体系设计**：券模板（类型：满减、折扣、立减；门槛：满 X 元；范围：全场/品类/单品；有效期；叠加规则；互斥组）+ 用户券实例（领取时间、状态、订单绑定）。计算逻辑分两步：先过滤（可用性：门槛、范围、时间、是否互斥），再求解最优组合。可叠加时这是一个组合优化问题，券数量少时可以按「互斥组内取最优、组间可叠加」降维——每组内枚举最优，组间做贪心或小规模 DP；券多时限定最多叠加 N 张，用带剪枝的搜索。工程上把「券计算」做成独立的计价服务，输入购物车与用户券包、输出优惠明细，保证下单、支付、退款三处口径一致；所有计算要可重放（记录用了哪些券、每张减多少），否则退款对不上账。

**SSE 与普通 HTTP**：普通 HTTP 请求是「一问一答」，服务端处理完返回完整响应，连接可复用但语义上是一次性；SSE（Server-Sent Events）在一条长连接上由服务端持续推送 `text/event-stream` 事件，浏览器原生 `EventSource` 支持自动重连与 `Last-Event-ID` 断点续传，适合通知、进度、流式输出这类单向推送。SSE 的优点是简单（纯 HTTP、无额外协议、穿透代理友好）、缺点也明显：单向（客户端要发消息得另开请求）、HTTP/1.1 下每域名连接数有限（HTTP/2 多路复用可缓解）、需要处理心跳与代理超时。与 WebSocket 相比，SSE 不做双向、不用升级协议，运维更简单；与轮询相比，实时性更好、无效请求更少。

**TCP / UDP、数组与链表、队列**：TCP 面向连接、可靠、有序、有流量控制与拥塞控制，代价是握手、重传与队头阻塞；UDP 无连接、不可靠、无序、开销小、时延低，适合实时音视频、游戏同步、DNS。数组内存连续、随机访问 O(1)、插入删除 O(n)、缓存友好；链表节点分散、随机访问 O(n)、已知位置插入删除 O(1)、有指针开销且缓存不友好。队列是先进先出，只允许尾部入队、头部出队，常用于缓冲与解耦；工程上要区分有界/无界（无界会吃内存）、阻塞/非阻塞、以及是否需要优先级。
