### 《参考解析》

**C++ 与数据结构：这一轮的八股都问在「取舍」上**

C 与 C++ 的区别不要只答「面向过程 vs 面向对象」，更值得说的是 C++ 多出来的那套工程手段：RAII 让资源跟着对象生命周期走、模板提供零成本抽象、异常与命名空间改变了大程序的错误处理和符号管理方式；而 C 的编译产物更小、和硬件更近，所以底层库、驱动仍然用它，C++ 代码也常靠 `extern "C"` 暴露接口给 C 调用。智能指针按所有权分：`unique_ptr` 独占、不可拷贝可移动，`shared_ptr` 用引用计数共享、控制块本身线程安全但指向的对象不是，`weak_ptr` 专门用来打断循环引用——被追问项目里用过没有时，讲一个「谁持有、什么时候释放」的真实场景比背 API 有效，比如网络层用 `shared_ptr` 管连接、定时器里只存 `weak_ptr` 防止连接被定时器吊住不释放。

多态这块要点出编译期与运行期两条路：重载与模板是静态多态，虚函数靠对象的 vptr 指向类的虚函数表在运行时派发，所以基类析构必须写成虚的，否则通过基类指针 delete 派生对象只会析构基类部分。多线程的追问标准答法是两边都覆盖——数据竞争靠锁、原子变量和无共享设计（线程本地、消息传递）解决，锁的粒度要小、别在持锁期间做 IO 或回调；死锁则从四个必要条件下手，工程上最有效的是全局固定的加锁顺序、一次用 `std::scoped_lock` 锁多个互斥量、以及给等待加超时兜底。

链表与树那几题是纯基本功，但都有「追问点」。数组和链表比的是随机访问 O(1) 对 O(n)、插入删除代价、以及数组的缓存局部性更好。O(1) 删除单链表节点只有在拿不到前驱时才用「把后继的值抄到当前节点、再删后继」这个取巧办法，限制很明确：节点不能是尾节点，而且真正被摘掉的是后继节点，如果别处还存着后继节点的指针就会悬空，所以它更适合内部临时链表。二叉树遍历说清前中后序的递归与显式栈写法、层序用队列即可，求高度是后序递归取左右子树最大值加一；「最短路径」要先分清场景——无权图用 BFS 逐层扩展，带权图就不是 BFS 能解决的，主动补这一句能显示你没有被题干带跑。红黑树的特性按四条记：节点非红即黑、根为黑、红节点的子节点必须为黑（不存在连续两个红）、任一节点到其所有叶子的黑节点数相同；由此保证最长路径不超过最短路径的两倍，插删时的旋转次数比 AVL 少，这正是 STL 的 map/set 选它的原因。

**网络：TCP/UDP 的区别最终要落到业务选型**

TCP 与 UDP 的区别可以按「连接、可靠性、有序性、传输形态、开销」五条对比，但面试官真正想听的是后半段。在 UDP 上做可靠传输，本质是自己在应用层重建 TCP 的那几件套：给报文编号并做确认、超时或收齐重复 ACK 后重传、用滑动窗口做流量控制与去重排序、再补一套拥塞控制避免把链路打爆；KCP 这类协议就是用更多带宽和 CPU 换更低延迟的典型。游戏里的选型标准是「这条消息丢了会怎样」：登录、充值、交易、聊天、背包变更这类必须到达且要求一致的操作走 TCP 或可靠通道；位置、朝向、技能表现这类高频状态可以走 UDP，允许丢包，因为下一帧的新状态会覆盖旧值，为此付出的代价只是瞬时表现不一致。实战里更常见的是混合通道，关键事件走可靠、状态同步走不可靠，弱网环境再叠一层基于 UDP 的可靠协议。

**业务设计题：匹配系统怎么同时照顾段位和等待时间**

这道题的答法是先给目标函数，再给机制。匹配的本质是在「对局质量」和「等待时长」之间做权衡：每个玩家维护一个 MMR（可由 Elo、Glicko、TrueSkill 之类的评分系统算出，段位只是它的展示分桶），撮合时在同一分桶内找分差最小的对手。等待时间一长就单调放宽搜索窗口——比如每等 5 秒把可接受的 MMR 差扩大一档，直到超过一个上限后接受跨段匹配，这就是「段位优先、等待兜底」的实现。工程上不要每人来一次就全局搜一遍，而是按 tick 定时从队列里撮合，用分桶加优先队列控制复杂度；同时要预留几个现实变量：多人组队时取队伍平均分并额外考虑队伍分差、跨区匹配受延迟限制、冷门分段或深夜可能长时间无解，得提前想好放宽策略或补位手段。能把这几个变量主动摆出来，比直接背一段伪代码更像做过系统。

**HR 面与产品面：这两轮筛的不是知识**

二三面几乎不考技术，问的是稳定性、动机和一致性。HR 面的高频内核是「你会不会来、能待多久、有没有更好的选择」——到岗时间、实习时长、导师是否知情、手上有哪些 Offer 和期望薪资、能不能接受加班节奏，都属于这一层；回答的原则是给确定的日期与范围而不是含糊的「可以」，一是一二是二，因为这些话后面会被拿去和技术面的说法对账。它还会用你简历上的细节做真伪校验：项目做了几个、文章是否原创、实习怎么拿到、工具到底被多少人用，凡是写得夸张的地方都会在这里被翻出来。产品面则看你对游戏是不是真有热情和理解——玩什么品类、怎么看行业、为什么是这家公司，靠临时背官网介绍很容易被问穿。原帖没有写最终结果。
