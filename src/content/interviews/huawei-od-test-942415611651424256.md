### 《面试题目》

#### HR 面

1. 自我介绍：毕业学校、专业、擅长技能，并简单介绍项目经历。
2. 为什么选择这个平台？
3. 为什么选择这个岗位？
4. 介绍一下你的项目。
5. 你的职业规划是怎样的？
6. 你对加班怎么看？
7. 你的期望薪资是多少？
8. 为什么考虑这个城市？
9. 你还有什么想问面试官的？

#### 技术面

1. 讲一下测试流程。
2. 你的项目是怎么进行测试的？
3. 你用过哪些测试方法，如何使用，举例说明。
4. Linux 常用命令有哪些？grep 命令有哪些参数？
5. 如何确保测试用例的覆盖率？
6. 项目中印象最深刻的难点是什么？
7. Python 有哪些数据类型，各自有什么特点？
8. 你如何和团队进行协作沟通？

#### 综面

技术面和 HR 面的结合，能把自己在项目里做的事流畅、专业地表达出来即可。

### 《参考解析》

**测试流程要答成一条闭环，而不是背阶段名称。** 需求评审阶段介入，确认可测性与验收标准；制定测试计划（范围、资源、排期、风险）；设计用例（等价类、边界值、场景法、状态迁移）；搭建环境与造数；执行（冒烟 → 功能 → 回归）；缺陷管理（提交、跟踪、复验、关闭）；上线前做验收与发布检查；上线后看监控与用户反馈，把线上问题回流成用例。每一段补一句「我在其中做什么」，比如「需求评审时我提了三个边界问题，避免后面返工」，比干列流程有说服力。

**测试方法要能落到例子。** 等价类：输入年龄 18–60，取 17、18、35、60、61；边界值：金额 0、0.01、上限、上限+0.01；场景法：登录 → 下单 → 支付 → 退款的主流程与异常分支；状态迁移：订单从待支付到已支付、已取消的合法/非法跳转；错误推测：断网、重复提交、并发点击、超时重试。覆盖率不只看「用例执行率」，要看需求覆盖率（每条验收标准有没有对应用例）、代码覆盖率（行/分支，作为参考不是目标）、场景覆盖率（正常、异常、边界、并发、权限）。确保覆盖率的方法是做需求-用例追踪矩阵，评审时逐条对照，缺口补用例；上线后用缺陷反查哪些场景没覆盖。

**Linux 与 grep 是测试岗的高频实操。** 常用命令按场景记：看日志 `tail -f`、`less`、`grep`、`awk`、`sed`；看进程 `ps -ef`、`top`、`lsof -i:端口`；看资源 `df -h`、`free -m`、`du -sh`；网络 `netstat -anp`、`ss -lntp`、`curl -v`、`ping`、`telnet`；权限 `chmod`、`chown`。grep 常问 `-i` 忽略大小写、`-v` 反向匹配、`-n` 行号、`-r` 递归、`-c` 计数、`-A/-B/-C` 上下文、`-E` 扩展正则、`-w` 全词匹配、`--include` 限定文件。会组合更重要：`grep -n "ERROR" app.log | tail -50`、`grep -c "Timeout" app.log`、`grep -A5 -B5 "Exception" app.log`。

**Python 数据类型按「可变/不可变、有序/无序、常用场景」回答。** 不可变：`int`、`float`、`bool`、`str`、`tuple`、`frozenset`，可哈希、能当字典键；可变：`list`、`dict`、`set`、`bytearray`。`list` 有序可重复，适合序列；`tuple` 有序不可变，适合固定结构；`dict` 键值映射、3.7 起保插入序、查找 O(1)；`set` 无序去重、集合运算。再补一句浅拷贝/深拷贝、`is` 与 `==` 的区别，基本就够。项目难点按「现象—定位—解决—结果」讲，别讲成流水账；协作沟通举一次跨端联调或需求冲突，说清你怎么对齐、怎么留痕、最后结果。
