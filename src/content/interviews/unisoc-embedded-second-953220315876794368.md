### 《参考解析》

**三种 Cache 映射**：直接映射把主存块按「块号 mod 行数」固定映射到唯一一行，硬件最简单、命中判断最快，但冲突严重——两个常用地址映射到同一行会互相踢出。全相联允许任意主存块放进任意一行，冲突最少，但需要比较所有 tag，硬件成本高、延迟大，通常只用于容量很小的 TLB 或 victim cache。组相联是折中：先按组号定位（类似直接映射），组内再全相联比较，常见 4 路、8 路、16 路。替换策略在组内用 LRU 或伪 LRU。

**MESI 与一致性问题的来源**：多核各有私有 L1，同一内存地址可能同时存在于多个核的 Cache 中，某个核写了自己的副本，其他核读到的就是旧值。MESI 给每行四个状态：Modified（本核独占且已修改，与内存不一致）、Exclusive（独占且干净）、Shared（多核共享且干净）、Invalid（无效）。写操作前要先拿到独占权（通过总线嗅探或目录协议让其他核的副本失效），因此写是「先失效再写」。写回与写通是另一个维度：写通每次写都同步到下一级，简单但带宽开销大；写回只在行被替换时写回，带宽省但需要脏位，且一致性与持久化更复杂。

**MMU、页表与 Cache 的先后**：CPU 发出的是虚拟地址，MMU 用页表基址寄存器加虚拟页号查多级页表，得到物理页框号，再与页内偏移拼成物理地址。为了加速，TLB 缓存最近的转换结果；页表项里带权限位与缓存属性。关于「谁先谁后」：现代处理器通常是 PIPT（物理索引物理 tagged）或 VIPT（虚拟索引物理 tagged），即用虚拟地址的低位做索引（因为页内偏移在虚实之间不变，所以不会产生别名问题）、用物理地址做 tag 比较，逻辑上 MMU 转换与 Cache 索引可以并行。ARM 上还要注意地址翻译前后的属性（可缓存、可缓冲、设备内存），驱动里 DMA 与 Cache 一致性的坑大多出在这里。

**流水线冒险**：数据冒险是后一条指令要用前一条的结果，解决靠转发（旁路）、插入气泡、编译器调度；控制冒险是分支导致取指方向不确定，解决靠分支预测、延迟槽、预测失败时冲刷流水线；结构冒险是硬件资源冲突（如取指与访存争同一端口），靠分离指令与数据 Cache、多端口解决。

**从上电到第一条指令**：上电复位后 CPU 从固定地址（如 ARM 的 0x0 或高地址向量表）取指，这段固化了 BootROM 代码。BootROM 做最基础的初始化（时钟、看门狗、串口），按启动介质（eMMC、SPI Flash、USB、SD）加载第一阶段 bootloader（如 SPL）到片内 SRAM 执行；SPL 初始化 DDR，再把完整的 bootloader（U-Boot）搬到 DDR；U-Boot 初始化外设、加载设备树与内核镜像到内存、跳转到内核入口；内核解压、建立页表、初始化子系统、挂载根文件系统，最后启动 init。每一级的存在都是因为下一级太大、放不进上一级的存储或内存。

**AXI 与 AHB**：两者都是 AMBA 总线。AHB 是较老的共享总线，单主机仲裁、流水线式传输、不支持乱序，适合低速外设；AXI 是点对点、多通道（读地址、读数据、写地址、写数据、写响应各自独立握手）、支持乱序与 outstanding 传输、突发长度更长，适合高带宽的 CPU、DMA、DDR 控制器。一次内存访问的完整链路大致是：CPU 发出虚拟地址 → TLB/MMU 转换 → L1 查询（命中直接返回）→ 未命中发到 L2 → 再未命中经总线接口（AXI）到内存控制器 → DRAM 行激活、列读取 → 数据沿原路回填各级 Cache 并返回寄存器。

**复盘：深度题怎么准备**：这类题的特点是「知道是什么」和「能讲清为什么这么设计」之间差距很大。准备方法不是多背题，而是对每个基础机制追问三层：它解决什么问题、怎么实现、代价是什么。比如 Cache 一线，从「为什么有 Cache」追到映射方式、替换策略、一致性协议、写策略、与 MMU/DMA 的交互，形成一条链，被追问时才能顺着讲下去。
