### 《参考解析》

1. **TCP 与 UDP**：TCP 面向连接、可靠、有序并提供流量和拥塞控制；UDP 无连接、开销小、只提供尽力而为的数据报传输。
2. **三次握手与四次挥手**：三次握手分别同步双方初始序列号并确认双向收发能力；挥手需要分别关闭两个方向的数据通道，通常由四个报文完成。
3. **集合与 ArrayList**：ArrayList 基于连续数组，尾部追加均摊 O(1)，扩容时复制数组；LinkedList 基于链表，按节点插入删除方便但随机访问慢。
4. **HashMap 与并发**：哈希冲突在桶内以链表或树组织，尾插可保持遍历顺序并避免头插在并发扩容时形成环。多线程场景应使用 ConcurrentHashMap 或外部同步，不能直接依赖 HashMap。
5. **volatile 与锁升级**：volatile 保证可见性和有序性，不保证复合操作的原子性；锁会根据竞争从偏向/轻量级逐步膨胀到重量级（具体版本实现可能不同）。
6. **线程池参数**：核心线程数、最大线程数、空闲存活时间、时间单位、工作队列、线程工厂和拒绝策略共同决定吞吐、延迟与过载行为，应结合任务类型和容量评估。
7. **ThreadLocal**：每个线程维护独立的 ThreadLocalMap，通常不会产生共享数据竞争；线程池中使用后应在 finally 里 remove，避免 value 长期残留。
8. **MySQL 事务与索引**：隔离级别从读未提交到串行化逐步提高隔离性；可重复读依赖 MVCC，但当前读、范围锁缺失等场景仍可能出现幻读。B+ 树多路、矮胖且叶子有序链表，适合磁盘范围查询。
9. **Redis 一致性**：常见做法是先提交数据库再删除缓存，并配合重试、消息订阅或延时双删。库存、余额等强一致数据应以数据库事务和版本校验为准。
10. **慢 SQL 与索引失效**：通过慢查询日志和 EXPLAIN 查看扫描行数、访问类型、候选/实际索引等；对索引列做函数或隐式类型转换、前缀模糊匹配、违反联合索引最左匹配等都可能导致失效。
11. **单例与算法**：单例可用枚举或静态内部类实现，验证时比较对象引用；三个线程可用 `Condition`/`Semaphore` 按状态轮转，链表反转用迭代指针，判断环用快慢指针。
