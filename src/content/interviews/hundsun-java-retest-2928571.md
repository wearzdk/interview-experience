### 《参考解析》

**Agent 项目收获**：不要只复述技术栈，讲“认知变化”。比如从“把模型接上就行”变成“要让流程可控、可评测、可回滚”；从“追求单次回答惊艳”变成“关注失败率和兜底”；从“堆 prompt”变成“做检索、工具、状态管理和观测”。再举一个具体坑：分块太大导致召回不准、工具参数没校验导致误调用、没有 trace 导致问题复现不了。最后说你现在会怎么设计得更好。

**入库与分块**：入库链路是“文档解析 → 清洗 → 切分 → 元数据标注 → 向量化 → 写向量库/全文索引 → 建别名”。分块按结构切，保留标题层级和来源；块大小与 overlap 用评测集调；表格、代码、问答对单独处理。入库要幂等（文档 ID + 内容哈希），更新用新版本 + 别名切换，删除要同时清向量和元数据。多路召回是向量 + 关键词（BM25）+ 结构化过滤，结果用 RRF 或加权融合，再重排取 top-k；每路召回的候选数、权重和过滤条件都要可配置、可评测。

**团队协作**：最重要的不是“沟通”两个字，而是“目标对齐 + 接口清晰 + 及时暴露风险”。可以讲一次具体协作：需求评审时把边界和验收标准写清，开发中用小步提交和接口 mock 并行，联调前先对日志和错误码，出现延期第一时间同步而不是最后一天说。沟通机制上，日常用站会/周会同步进展，重要决策留文档，跨团队用 issue 跟踪，避免口头承诺。

**对恒生的了解**：恒生电子是国内金融软件头部厂商，服务证券、基金、银行、期货等机构，核心产品包括交易、资管、财富管理、数据服务等；企业级项目多、客户现场实施多、对稳定性和合规要求高。回答时结合岗位说“想做金融业务的后端，能接触高并发/低延迟/强一致的场景”，不要只背公司简介。

**新技术学习**：选一个和岗位相关的，讲“为什么学、怎么学、怎么验证”。比如学 Agent 框架：先读官方文档和示例，再做一个最小 demo，然后读源码看状态管理和工具调用，最后在自己的项目里落地并用评测验证。不要列一堆课程名。

**base 与实习**：明确接受南京，说明可实习的时间段和每周天数；如果还有课，讲清学校安排和远程可能性。企业更看重到岗稳定性，含糊会减分。
