### 《参考解析》

**静态代码扫描报出来的隐患要按类别说**：空指针解引用与未判空的返回值、缓冲区溢出（`strcpy` / `sprintf` / 数组下标越界）、未初始化变量、资源泄漏（`malloc` 后未 `free`、文件描述符未关）、重复释放与 use-after-free、整数溢出与隐式截断、格式化字符串漏洞、有符号与无符号混比、`switch` 缺 `default`、在中断上下文里调用阻塞函数、共享变量未加保护导致竞态。说的时候点明「工具只能发现模式，真正的判断要落在数据流与调用上下文上」，比如同一个 `malloc` 在错误分支里漏了 `free`，扫描器能查出来；但锁的粒度是否合理、临界区里有没有阻塞调用，只能靠人看。

**malloc 失败时的阻塞等待**：标准 `malloc` 不阻塞，失败直接返回 `NULL`。要在 Linux 上「等内存」，可行手段有四类。一是应用层重试，`sleep` 后反复申请并设最大重试次数——最简单，但会掩盖问题。二是自建内存池加条件变量：池空时 `pthread_cond_wait` 阻塞，别的线程释放后 `pthread_cond_signal` 唤醒，可控但要把池的所有权理干净。三是依赖内核的回收行为：先 `madvise(MADV_DONTNEED)` 或主动 `malloc_trim` 逼出可用页，再重试；cgroup 限流下内存压力会触发直接回收。四是把分配前移到启动阶段，用 `mmap` 预留虚拟地址、靠缺页按需提交物理页。答这道题必须补一句前提：工业通信类软件不该长时间阻塞在分配上，正确做法是预留应急内存、上线前做资源校验、把分配失败当作可观测的告警而不是正常路径。

**浅拷贝与指针成员的释放时机**：浅拷贝只复制指针值，两个对象指向同一块堆内存，各自析构就会 double free；深拷贝重新申请内存并复制内容，两边独立。坚持浅拷贝还能安全释放，只有两条正统路线：引用计数（拷贝加一、析构减一、归零才释放，`shared_ptr` 就是这个模型，但要考虑循环引用与多线程下的原子性）与所有权转移（明确谁拥有、谁只借用，`unique_ptr` 加 `std::move`，C 里用「谁分配谁释放」的约定加文档约束）。工程上还可以退一步：把 buffer 改成定长数组或内存池句柄，从根上避开所有权问题。

**二值信号量链式驱动的问题**：任务 A 给信号量、任务 B 等它、B 干完再给下一个，看起来是流水线，实际把并行退化成串行——每一环都要等前一环，任何一环慢都拖住整条链；耦合极强，加一个环节要改上下游；二值信号量不带优先级继承，低优先级任务持有时高优先级任务会被中优先级任务插队（优先级翻转）；信号量只传「发生了」，不传数据，消费者还得去共享变量里取，又要额外加锁。优化方向是把「通知」换成「传数据」：用消息队列做生产者消费者解耦，队列长度提供背压；需要多事件汇合用事件组；只在一个任务和中断之间同步用任务通知（更轻、更快）；确实要保留链式语义时，用带优先级的互斥锁加超时，避免无限等待。

**缓存与局部性**：L1 离核最近、容量最小（几十 KB）、延迟一两个周期，分指令与数据（哈佛结构），每核私有；L2 稍大（几百 KB 到几 MB），通常每核私有或簇内共享；L3 最大（几 MB 到几十 MB）、延迟几十周期、多核共享，充当最后一级缓存。局部性分时间局部性（刚访问的数据还会被访问，所以有缓存）与空间局部性（相邻地址会被一起访问，所以按 cache line 64 字节整块加载）。工程含义很直接：顺序遍历数组比按列遍历二维数组快，结构体热字段放一起，避免伪共享（两个核改同一 cache line 的不同变量会来回失效）。DMA 场景必须做 cache 维护：发送前 clean（把脏数据写回内存），接收后 invalidate（丢弃旧缓存重新读），否则 CPU 读到的是 DMA 之前的旧值——这也是帖主提到的「注意 DMA 场景的 Cache 一致性」。

**三级流水线与冒险**：把指令拆成取指、译码、执行三级，多条指令重叠执行以提高吞吐，理想情况下每周期完成一条。冒险分三类：数据冒险（后一条要用前一条还没写回的结果，靠前递 / 转发或插入气泡解决）、控制冒险（分支跳转要等译码甚至执行完才知道下一条取哪，靠分支预测加预测失败时冲刷流水线）、结构冒险（两条指令同时要用同一个硬件资源，靠资源复制或停顿）。回答时可以把「分支预测失败要冲刷多少级」与「为什么嵌入式里更怕不可预测的分支」联系起来，体现对流水线深度的理解。

**IMU 的组成与工程处理**：IMU 由三轴加速度计与三轴陀螺仪组成（有的加磁力计成为九轴）。加速度计测比力，静态时能算倾角，但运动加速度会污染；陀螺仪测角速度，短期准、长期积分漂移，还有零偏与温漂；原始数据含高频噪声与量化误差。工程流程是：出厂或上电做零偏标定（静止取均值、温补查表）→ 低通或带通滤波去噪 → 姿态融合（互补滤波把陀螺的高频与加速度计的低频加权，或用 Mahony / Madgwick / 卡尔曼 / EKF）→ 输出四元数或欧拉角。真要评估噪声水平，用 Allan 方差看随机游走与零偏不稳定性。帖主给的是互补滤波与卡尔曼这条主线，面试时再补一句「剧烈运动时用加速度计修正姿态反而会引入误差，需要按运动状态动态调增益」会更完整。

**为什么 BSP 看重这几门课**：BSP 的活是把 SoC 的硬件能力交给上层——初始化时钟与电源、配置引脚复用、写外设驱动、适配设备树、处理中断与 DMA、跑通从 BootROM 到 rootfs 的启动链。这些工作全部落在 ARM 体系结构（异常等级、MMU、cache、内存序）、RTOS 调度（优先级、临界区、同步原语、优先级翻转）、中断（上下半部、中断嵌套、中断里不能阻塞）与缓存一致性上。底层基础决定的是排查效率：同样的「串口偶发丢数据」，懂 DMA 与 cache 的人会先查 clean/invalidate，不懂的人只能反复换波特率。
