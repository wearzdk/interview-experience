### 《面试题目》

1. 结合简历讲讲你的项目经历、用到的技术栈，以及你自认为的优势是什么。
2. 你是怎么把技术落地到具体项目里的？（面试官在 Agent 与前端两个方向上来回追问。）

### 《参考解析》

**这轮为什么「不像技术面」，它其实在考什么**

面试开始是签到加填表，随后大部分时间由面试官介绍公司现状与愿景；面试官单向输出时，候选人很容易听得发懵、插不上话。这类由业务负责人主导的面试，考察重心不是八股，而是匹配度与沟通：能不能听懂业务在讲什么、能不能接住话题、对公司与岗位有没有真实兴趣。前面签到填表、听公司介绍的环节本身也是观察的一部分。

准备策略因此不同：把公司做什么、这个岗位在他团队里承担什么搞清楚，准备两三个针对业务的问题（团队现在的技术栈、业务量级、这个岗位前三个月要交付什么），比再背一轮八股有效。当面试官长时间单向输出时，可以主动把话题拉回自己——承认理解、补充一段自己项目里的对应经验，而不是等对方问。

**讲技术栈与优势：先给结论，再给证据**

「没听出我的技术栈和优势」通常是表达问题，不是能力问题。结构化讲法分三层：一句话定位（我主要做全栈，前端用 Vue/React，后端用 Java 或 Node，独立交付过某类系统）；证据（做过什么、规模如何、你在其中的角色与产出）；与岗位的连接（这家公司需要的能力里哪几项我现成具备、哪一项要补）。

两个常见毛病要避免：把技术栈念成一串名词却不给场景（「我会 Spring Boot、Redis、Docker」），以及只讲我「了解」什么而不讲我「做过」什么。优势最好是一个面试官能复述的标签，例如「能独立把一个带模型能力的小系统从 0 做到可用」，而不是「学习能力强」。

**项目要按逻辑讲，不按时间讲**

「一会儿讲 Agent、一会儿讲前端」是典型的流水账讲法。改法是为每个项目准备一页结构：背景与目标（谁在用、解决什么问题）、我的职责与范围、技术方案与选型理由（为什么这么选、试过什么不行）、难点与解决过程、结果与量化、复盘（如果重做会怎么改）。全栈候选人尤其要讲清边界：哪些是独立完成的、哪些是协作的，前后端和模型侧各承担多少——面试官最担心的是「全栈」其实两边都浅。

项目里同时有 Agent 和前端时，用一条主线串起来讲，例如「用户在前端提问、请求怎么路由到 Agent、结果怎么回显」，比分开讲两块更容易让人记住。

**回去之后可以怎么补**

项目梳理是几天内就能补上的：把简历上每个项目按上面那页结构写成文字，一页一个，再对着手机录音讲一遍、回听，检查有没有结论先行、有没有量级、有没有把「团队做的」说成「我做的」。另外把技术栈按熟练、用过、了解分成三级，面试里主动区分（这块在项目里深度用过，那块只是了解），既显专业也能避免被追到坑里。面试前十分钟过一遍这份「我做过什么」的清单，现场散乱的概率会明显下降。
