### 《参考解析》

**1. 空类与 this 调整。** 空类大小是 1 而不是 0，原因是 C++ 要求同类型的两个不同对象地址必须不同——如果大小为 0，数组里所有元素的地址都会相同，取地址、比较、指针运算全都失效。一旦类里有虚函数，就会多一个虚表指针（64 位下 8 字节）；空基类优化（EBO）允许把空基类压到偏移 0 处不占空间，但**两个同类型的空基类不能都放在偏移 0**，所以第二个空基类至少要占 1 字节。

多继承下的 this 调整：派生类指针转成某个基类指针时，如果基类子对象在派生对象里有固定偏移，编译器直接加减一个常量（`this + offset`）；如果基类是虚继承的，偏移在编译期不确定，必须通过虚表的虚基类偏移项间接取。成员函数本身不占对象空间，非虚函数地址编译期就定了，`this` 一般通过第一个参数寄存器传入（x86-64 的 rdi、AArch64 的 x0），返回大对象时还要多传一个隐藏的返回缓冲区指针。

**2. 智能指针在车载代码里的坑。** 第一是**分配次数**：`shared_ptr<T>(new T)` 会做两次分配（对象一次、控制块一次），`make_shared` 合成一次，热路径上这点差别会被放大；第二是**引用计数本身是原子的，但被指向的对象不是线程安全的**，两个线程通过各自的 `shared_ptr` 副本改同一个对象照样有竞争；第三是**循环引用**，父子互相持有就永远释放不掉，必须有一端用 `weak_ptr`；第四是**同一个 shared_ptr 对象被两个线程同时赋值**属于数据竞争，C++20 才有 `atomic<shared_ptr>`，在那之前只能各自持有副本或加锁；第五是车载/功能安全场景通常限制动态分配（堆碎片、分配时间不确定、失败路径难处理），所以更多用 `unique_ptr` + 静态池、侵入式引用计数或对象池。

回答「引用计数是原子的吗」要补一句：计数操作是原子的，但 increment/decrement 用的是 relaxed/acquire-release 语义，保证的是控制块的正确释放，不保证你对 T 的读写顺序。

**3. STL 在实时系统里的问题。** 核心是**最坏情况不可控**，不是平均性能。`unordered_map` 的 rehash 要一次性搬所有节点，十万条时单次可能几十毫秒，直接把帧预算打爆；`map` 每次插入都有节点分配和树旋转，延迟抖动同样不可预测；`vector` 扩容要分配新块 + 搬移全部元素。再加上节点式容器每个元素单独 `new`，长期运行后堆碎片化，某次 1 KB 的分配可能失败。

替代表法要能说出来：固定容量的开放寻址哈希表（预分配连续内存、插入最坏 O(n) 但零分配）、侵入式容器（节点嵌在对象里，零额外分配）、排序数组 + 二分（万级数据内 cache 友好、比哈希还快）、环形缓冲做队列。可用的库是 `boost::intrusive`、`etl`（嵌入式模板库）、`flat_hash_map` 这类预分配实现。

**4. 模板膨胀与控制。** 每个模板实参组合都会生成一份独立代码，`vector<int>` 和 `vector<float>` 完全不共享，十个类型实例化一个大模板，二进制能涨几十 MB（车载 ECU 的 Flash 预算很紧，这点是硬伤）。控制手段：把与类型无关的逻辑抽到非模板基类（类型擦除），模板层只做薄封装；用 `extern template` 抑制在其他翻译单元重复实例化；对常用类型显式实例化一次；用 `if constexpr` 代替多份特化，减少重复实现。回答时补一句「内联是把双刃剑」——模板 + 内联让代码更快，但体积代价要算进固件预算。

**5. 手撕简化版 vector。** 三指针布局最干净：`begin`、`end`、`cap_end`，`size()` 返回 `end - begin`，`capacity()` 返回 `cap_end - begin`。`push_back` 先判 `end == cap_end`，满了按倍数扩容：`operator new` 拿原始字节 → 用 `std::move_if_noexcept` 逐个构造新元素（移动构造是 `noexcept` 才敢 move，否则退化成拷贝，保证强异常安全）→ 析构旧元素、`operator delete` 旧块 → 更新三个指针。析构里要显式对每个元素调 `~T()` 再释放整块内存。

面试官一定会看五个特殊成员：拷贝构造、移动构造、拷贝赋值、移动赋值、析构。手写资源管理类漏一个就是双重释放或泄漏，所以要点是「三/五法则」——写了析构就要想清楚另外四个。赋值建议用 copy-and-swap 保证自赋值安全和强异常安全。

**6. 为什么倍增，1.5 和 2 的差别。** 按 2 倍扩容，n 次 push_back 的总搬移次数是 1+2+4+…+n < 2n，均摊到每次是 O(1)；按固定长度扩容就是 O(n²)。1.5 与 2 的实质差别在**内存复用**：2 倍增长时，前面所有释放块的总和永远小于下一次要申请的大小，所以新块只能往新的地址要，任何时刻峰值内存接近 3 倍（旧块 + 新块）；1.5 倍增长时，前面释放的块加起来能容纳下一次申请，分配器有机会原地复用，峰值约 2.5 倍，长期运行的进程内存曲线更平。代价是 1.5 倍的摊还常数更大（总搬移接近 3n），大对象扩容会慢一些。所以「选哪个」取决于场景：内存紧张、对象大就用 1.5，追求吞吐就用 2。

**7. 位运算两连问。**

```cpp
// 2 的幂：正数且二进制里只有一个 1
bool is_pow2(unsigned x) { return x != 0 && (x & (x - 1)) == 0; }

// popcount：Kernighan 法，循环次数 = 1 的个数
int popcount_k(unsigned x) { int c = 0; while (x) { x &= x - 1; ++c; } return c; }

// 编译器内建，通常映射到单条 popcnt / cnt+addv 指令
int popcount_fast(unsigned x) { return __builtin_popcount(x); }
```

`x & (x-1)` 的作用是把最低位的 1 清掉，`x & (-x)` 是取最低位的 1（lowbit）。追问可能到「不用分支/查表怎么算」——SWAR 的并行位计数（先两两一组加、再四位一组加……）或查表法，说清思路就够。

**8. 大小端与跨平台传数据。** 判断方法：`union { uint32_t i; uint8_t c[4]; } u = {1};` 看 `c[0]` 是否为 1（也有用 `memcpy` 到 `char` 数组的，C++20 起 `std::endian` 直接给答案）。**不要用指针强转去读**（`*(char*)&i` 这类），那是严格别名违规，开优化后可能被优化掉。x86 与绝大多数 ARM 是小端，部分网络设备、DSP 和某些协议字段是大端。

跨平台踩坑清单：直接把结构体 `write` 到 socket 或落盘——对端按不同端序解析，`float` 能变成 1e-38 这种荒唐值；结构体对齐导致 sizeof 不一致（要显式打包或逐字段序列化）；`float`/`double` 的 IEEE754 位模式不能假定端序；协议里统一用网络序（`htonl`/`ntohl`，64 位用 `htobe64`）；协议版本升级时字段增删要有长度和版本号。回答时把「判断方法 + 转换手段 + 踩过的具体坑」三段给全，这题就稳了。
