### 《参考解析》

**进程与线程**：进程是资源分配与隔离的单位，拥有独立地址空间、文件描述符与权限；线程是 CPU 调度的单位，共享进程的地址空间与资源，有独立的栈、寄存器与线程局部存储。线程切换比进程轻，通信更方便，但一个线程崩溃可能拖垮整个进程。只有进程没有线程，隔离好但创建与通信成本高、无法利用多核共享内存；只有线程没有进程，共享方便但缺乏隔离，一个错误会影响全部任务，权限与资源也难以按任务划分。

**堆与栈**：栈由编译器自动管理，存局部变量、参数与返回地址，按线程独立，大小有限，分配释放快；堆由程序手动或 GC 管理，生命周期灵活，进程内线程共享，分配有碎片与同步开销。数组是连续内存，随机访问 O(1)、缓存友好，适合读多、长度稳定的场景；链表节点分散，插入删除 O(1)（已知位置），适合频繁增删、长度变化大的场景，但遍历与缓存不友好。

**虚拟内存**：给每个进程独立的地址空间，提供隔离与保护；按页映射到物理内存，支持按需调页、换出、共享库与 mmap；让程序不必关心物理布局，能运行比物理内存更大的地址空间，也方便内存整理与安全控制。直接操作物理地址会破坏隔离（一个进程可改另一个进程或内核的数据）、难以支持多道程序、产生外部碎片、带来安全漏洞，程序也无法在不同机器上稳定运行。

**URL 到渲染**：URL 解析与缓存检查 → DNS 解析（浏览器、系统、递归 DNS）→ 建立 TCP 连接（三次握手）→ 如果是 HTTPS 做 TLS 握手 → 发送 HTTP 请求 → 服务端处理并返回响应 → 浏览器解析 HTML、构建 DOM 与 CSSOM、执行 JS、布局与绘制。中间还涉及 CDN、负载均衡、HTTP 缓存、连接复用。

**TLS 与公私钥**：TCP 握手后，HTTPS 先做 TLS 握手：客户端发 ClientHello（支持的版本、套件、随机数），服务端回 ServerHello 与证书链，客户端验证证书（域名、有效期、签名链、吊销状态），双方用 ECDHE 交换参数生成会话密钥，之后用对称加密传输数据。非对称加密用于身份认证与密钥交换，对称加密用于数据，因为后者快。公钥可公开用于加密或验签，私钥保密用于解密或签名。客户端用自己的私钥加密，服务端没有对应私钥无法解密，只能用客户端公钥验签；客户端用服务端公钥加密，只有服务端私钥能解，中间人没有私钥解不开，但中间人可以替换公钥，所以需要证书与 CA。客户端信任操作系统或浏览器内置的根证书，用根公钥逐级验证证书链上的签名，确认公钥确实属于该域名。

**区块链**：分布式账本，区块按哈希链式相连，多节点按共识规则维护同一份状态，具有难以篡改与去中心化的特点；常见共识有 PoW、PoS。是否炒币是个人问题，如实回答即可，不必展开。

**无重复字符的最长子串**：用滑动窗口，右指针遍历，哈希表记录字符最近出现的位置；遇到重复且位置在左指针右侧时，把左指针移到该位置加一；每步更新最大长度。左指针收缩那一行的含义是「窗口内不能有重复字符，所以左边界必须跳过上一次出现的位置」，不是简单加一。时间 O(n)，空间 O(字符集大小)。

**合并区间**：按区间起点排序，遍历并维护当前区间；如果下一个区间的起点小于等于当前区间的终点，就合并（终点取两者较大值），否则把当前区间加入结果并更新。时间 O(n log n)，空间 O(n)。
