### 《参考解析》

**风控项目**要讲清数据流和决策链：处罚中心接收风险事件，做规则/模型判定，执行冻结、封禁、扣分等动作，再走申诉和复核；黑产识别分主动（设备指纹、行为序列、图关系）和被动（举报、客诉、资金异常）。冻结资金后申诉要对齐流水和状态机，避免重复退款或漏退；团伙模型从离线表迁到消息队列，是为了近实时更新关系图，数据量级要能说出日均事件和峰值。

**多 Agent**：主节点按场景路由任务，SubAgent 超时要把状态写回共享存储，由主节点决定重试、降级或跳过；关键是幂等、超时预算和状态机，避免一个子任务失败拖垮整条链路。大模型幻觉来自训练数据、上下文缺失和解码随机性，缓解手段包括 RAG、引用约束、结构化输出、工具校验、低温度和人工抽检。

**Java 与 MySQL**：HashMap 1.8 是数组 + 链表 + 红黑树，put 先算 hash、定位桶，空桶直接放，冲突则链表尾插，长度到 8 且容量到 64 转红黑树，超过阈值扩容并重新分布。synchronized 是 JVM 内置锁、自动释放，ReentrantLock 是 API 层锁、可中断/可超时/可公平；AQS 用 state 加 CLH 队列实现同步器。InnoDB 选 B+ 树是因为扇出大、树高低、叶子链表适合范围查询；跳表和红黑树要么磁盘局部性差，要么树高更高。默认 RR，互联网常用 RC 是为了减少间隙锁、提升并发。

**Redis 与网络**：缓存穿透用布隆过滤器/空值缓存，击穿用互斥锁/逻辑过期/预热，雪崩用过期时间打散、多级缓存和限流降级。分布式锁用 `SET NX PX` 加 Lua 释放，必要时看门狗续期。TCP 三次握手是 SYN、SYN+ACK、ACK；SYN 洪泛可以用 SYN Cookie、限速、代理和清洗。反转链表用三指针迭代或递归。
