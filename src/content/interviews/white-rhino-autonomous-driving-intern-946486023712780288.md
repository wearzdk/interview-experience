### 《面试题目》

1. 自我介绍与项目经历。
2. C++ 有哪些特性？
3. 智能指针有哪几种，各自解决什么问题？
4. 多线程、多进程分别怎么用？
5. 给一段代码，看它会打印什么（涉及构造、赋值、移动赋值）。
6. 给你三角形的三个点，怎么判断它是逆时针还是顺时针？
7. 给你一个 double 类型的数，如何算出它的三次方根？
8. 了解的最短路径算法说一下，展开讲讲 Dijkstra。
9. 还有别的最短路径算法吗？有学过 A* 算法吗？
10. 手撕：归并排序。

### 《参考解析》

**C++ 的核心特性**按「语言层 / 抽象层 / 运行期」分三组讲最清楚。语言层：静态类型、编译期多态（模板与重载）、零开销抽象、RAII 与确定性析构、移动语义与右值引用、`constexpr`、结构化绑定。抽象层：类与继承、虚函数与运行期多态、运算符重载、命名空间。运行期：手动内存管理（new/delete 与智能指针）、异常、STL 容器与算法。面试官问「特性」通常只是开场，紧接着就会挑一个深挖，所以每说一个都要准备好被追问一层——尤其是移动语义与 RAII。

**智能指针三种：`unique_ptr` 独占所有权**，不可拷贝只能移动，开销与裸指针基本一致，默认首选；**`shared_ptr` 共享所有权**，内部有引用计数（控制块里是强引用与弱引用两个计数），计数归零时析构对象，代价是一次原子操作与两份指针的内存开销，且要注意循环引用；**`weak_ptr` 不增加强引用计数**，用来观察 `shared_ptr` 管理的对象、打破循环引用、以及做缓存（用 `lock()` 提升为 `shared_ptr` 再判空）。还要说清 `shared_ptr` 的坑：两个独立地从同一个裸指针构造的 `shared_ptr` 会有两个控制块、导致二次释放，正确做法是用 `make_shared` 或 `enable_shared_from_this`。

**多线程与多进程的使用。** C++ 多线程用 `std::thread`、`std::mutex`/`lock_guard`/`unique_lock`、`condition_variable`、`std::atomic`、`std::future`/`promise`/`async`；线程共享同一地址空间，通信靠共享内存加同步，代价是数据竞争与调试困难。多进程用 `fork`/`exec`、`posix_spawn` 或跨平台的进程库，进程间靠管道、共享内存、Socket、消息队列通信；隔离性好（一个崩了不影响另一个），但创建与切换成本高、数据要序列化。自动驾驶场景里常见的是「感知、规划、控制各跑独立进程，通过共享内存或 DDS 传数据」，因为要隔离故障、也要让各模块用不同的调度策略。

**看代码说输出（构造 / 赋值 / 移动赋值）。** 这类题的判分点是「能不能分清对象被创建了几次、每次调的是哪个函数」。要记住的规则：`T a = b;` 与 `T a(b);` 是拷贝构造；`a = b;` 是拷贝赋值（要求对象已存在，先析构自己的资源再拷贝）；`T a = std::move(b);` 是移动构造（把 b 的资源指针偷过来、把 b 置空）；`a = std::move(b);` 是移动赋值。编译器会做返回值优化（RVO/NRVO）与复制消除，所以某些看起来该调拷贝构造的地方实际一次都没调——回答时要把「理论调用序列」和「实际输出」分开说，并说明这是 C++17 起的强制复制消除。另外别忘了临时对象与隐式转换（`explicit` 的作用）也会影响输出行数。

**三个点判断顺逆时针。** 用二维叉积判方向。设三点 `A(x1,y1)`、`B(x2,y2)`、`C(x3,y3)`，算 `cross = (B-A) × (C-A) = (x2-x1)(y3-y1) - (y2-y1)(x3-x1)`。`cross > 0` 时 A→B→C 是逆时针（在常见的右手坐标系、y 轴向上的约定下），`cross < 0` 是顺时针，`cross == 0` 三点共线。补充两点：屏幕坐标系 y 轴向下时结论会反过来，所以要跟面试官确认坐标系约定；浮点输入下不要直接判 `== 0`，要用一个与坐标量级相关的 epsilon 判「近似共线」。

**double 的三次方根。** 三种答法，按面试期望排序：① 牛顿迭代——求 `x³ = n` 即求 `f(x) = x³ - n` 的零点，迭代式 `x_{k+1} = x_k - (x_k³ - n) / (3x_k²) = (2x_k + n / x_k²) / 3`，初值取 `n` 或 `max(1, |n|)`，收敛是二阶的，十次以内就能到双精度极限；② 二分——在 `[0, max(1, n)]` 上二分，判断 `mid³` 与 `n` 的大小，稳定但要几十次迭代；③ 直接调 `std::cbrt`（工程上就这么干，但要能说出它内部也是多项式近似加牛顿修正）。必须处理的边界：负数（三次方根可以是负数，牛顿法对负数同样收敛，或先取绝对值再还原符号）、0、以及极大/极小值导致的溢出与下溢。

**最短路径算法要能横向对比。** Dijkstra 解决「非负权图的单源最短路」，贪心 + 优先队列，复杂度 O((V+E) log V)，不能处理负权边（负权要用 Bellman-Ford 或 SPFA，能检测负环）。A* 是 Dijkstra 的启发式版本，优先级从 `g(n)` 换成 `f(n) = g(n) + h(n)`，h 是到终点的估计距离；h 必须可采纳（不高估真实距离）才能保证最优，h 越接近真实值搜索越集中。此外还有 Floyd-Warshall（多源、O(V³)、能处理负权）、BFS（无权图）、以及自动驾驶里更常用的 Hybrid A*（考虑车辆运动学约束）与基于采样/优化的规划（RRT*、lattice planner）。被问到「没学过」时，这两分钟自学的答法是：先讲它解决什么问题、再讲与 Dijkstra 的唯一差别（优先级里多了 h）、最后说 h 的选择与可采纳性——把这三句话说清就已经过关了。

**手撕归并排序。** 分成两半递归排序再合并，核心是 `merge`：两个指针分别扫左右两段，取小的放进临时数组，某一段走完后把另一段剩下的整体拷过去，最后写回原数组。时间 O(n log n)、空间 O(n)（临时数组加递归栈 O(log n)），是稳定排序。要主动说的点：递归深度是 O(log n)，链表归并可以做到 O(1) 额外空间（只改指针），以及「为什么归并适合外部排序与外链表排序」——它只需要顺序访问，不需要随机写。

**这场的经验值得单独记一笔。** 二面面试官在候选人说「忘了 Dijkstra」之后，没有换题，而是让他共享桌面现场搜两分钟再讲——这说明面试考的是「遇到不会的东西怎么在短时间内学到能讲清楚」。可行的做法是：先抓这个概念解决什么问题，再抓它与已知方法的差别，最后抓一个关键约束（比如 A* 的启发函数必须可采纳）。这个套路比背实现细节更能救场。
