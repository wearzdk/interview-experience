### 《面试题目》

1. AD7606 驱动的技术细节（FMC + DMA）是怎么做的？
2. D-Cache 是什么？在采集链路里要注意什么？
3. 为什么要做零点 / 增益补偿？
4. 参考了 AUTOSAR 的哪些架构来实现项目？
5. 是否实际接触过 AUTOSAR？

### 《参考解析》

**AD7606 用 FMC 加 DMA 的驱动结构**：AD7606 是并行输出的 ADC，BUSY、CONVST、RESET、CS、RD 这些控制脚走 GPIO，数据总线挂在 FMC/FSMC 的地址空间上，CPU 或 DMA 按「读外部存储器」的方式取数。FMC 要配成异步 SRAM 时序，地址建立时间、数据保持时间、总线宽度（常见 16 位）按手册波形留余量，时序压得太紧会读到毛刺数据。采集流程是拉低 CONVST 启动转换、等 BUSY 变低、连续读各通道数据；高采样率下用外部中断或定时器触发，不要在主循环里裸轮询。DMA 把 FMC 映射地址当作源，一次搬完一帧多通道数据到 SRAM 环形缓冲，在半传输与全传输中断里做帧切换。

**缓冲与算法核的交接**：缓冲要对齐、长度固定，和算法之间用双缓冲或环形队列交接，避免边采边算踩同一块内存。调试顺序是先 GPIO 位带读写验证时序，再打开 DMA，用示波器看 CONVST、BUSY、RD 的相位关系，用逻辑分析仪核对实际采样率是否稳定。面试里能讲到「先验证时序再上 DMA」这一步，说明真的调过板子。

**D-Cache 的坑与处理**：Cortex-M7 的 D-Cache 让 CPU 读写先走缓存，不保证立刻与外设或 SRAM 的真实内容一致。DMA 往采集缓冲写数据时绕过 Cache，CPU 如果直接读旧缓存行就会拿到过期数据，所以处理前要对 DMA 缓冲做 Invalidate，按地址与 cache line 对齐；反过来 CPU 写完配置或描述符再让 DMA 读，要先 Clean 把缓存写回内存。工程上有两种策略：把采集缓冲放到非 Cache 区（用 MPU 配成 Device 或 Non-cacheable），或者强制 32 字节对齐并成对执行 Clean/Invalidate，选一种贯彻到底。双核共享内存（OpenAMP/IPC）同理，谁写谁 Clean、谁读谁 Invalidate，否则偶发错乱极难定位。

**零点与增益补偿**：ADC 前端的运放、AD7606 自身、基准电压、PCB 漏电都会引入失调（零点偏）与斜率误差（增益偏）。零点补偿是在输入短接或已知零基准时采一批点求平均，减掉固定偏置，否则小信号一直带着直流台；增益补偿是用已知满量程或两点校准算出比例系数，把原始码值映射到真实物理量。温度、供电与长期老化会让参数漂移，产线做两点校准、运行中可选温漂表，比只信出厂标称稳。补偿要放在标定之后、滤波与算法之前，并固化到 Flash，否则每块板的绝对值对不上，通道之间也无法对齐。

**AUTOSAR 部分要看得出「参考了什么」而不是「背了名词」**：分层上，MCAL（ADC/FMC/DMA/CAN 驱动）→ ECU 抽象 → 服务层（通信、诊断、存储）→ 应用层，上层不直接碰寄存器；通信栈借 PDU Router 与 COM 的思想做信号打包与路由；诊断参考 UDS/DCM 的会话、DID、例程划分，与 CAN TP 分段传输配合；调度上参考 BSW 的周期性任务加事件触发，把采集、通信、算法拆开；配置与代码分离，把通道、波特率、标定参数表项化。如果只是项目级简化实现，就明确说「参考了分层与配置化思路，不是完整 Vector 栈」，比含糊其辞更可信。
