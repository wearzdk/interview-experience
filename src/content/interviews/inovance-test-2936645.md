### 《面试题目》

1. 自我介绍（按照科研经历、项目来讲）。
2. 问的基本上都是简历里面的东西，并没有考其他的八股。
3. 如果某条用例的执行时间过长，你会怎么办？
4. 你怎么确保你的 Agent 助手抓取的东西是对的？
5. 问了一些项目里面的 UI 自动化相关的。
6. continue 和 break 区别？
7. 深拷贝和浅拷贝？
8. Web 登录界面，账号、密码、验证码三个输入框，从哪些维度设计测试？
9. 反问。

### 《参考解析》

**「用例执行时间过长」的答法要体现优先级判断，而不是一句「优化一下」。** 先定位时间花在哪：是前置环境准备（部署、造数）、用例本身的步骤太多、等待与同步（固定 sleep 而非条件等待）、还是依赖外部系统响应慢。对应手段：把公共前置抽成 fixture 并按需执行、把长流程拆成独立的可复用步骤、用显式等待替代固定等待、并行执行相互独立的用例（按资源分组避免互相干扰）、把稳定的长尾用例从每次回归降到每日/发版前跑。最后要有判断标准：这条用例的覆盖价值是否值得它占用的时间，如果只是覆盖一个边缘配置，用接口层或单测覆盖比走 UI 更划算。

**「怎么确保 AI Agent 抓取的内容是对的」是这批面试里最有区分度的题。** 答案要分层：**抓取层**做结构校验（字段是否齐全、类型是否合法、必填项是否为空）、来源校验（URL 与页面标题是否匹配预期、是否被重定向到登录页或错误页）、以及用 DOM 选择器命中的元素做二次确认；**内容层**做规则校验（金额格式、日期范围、枚举值合法性）与交叉校验（同一条信息从两个来源抓，比对是否一致）；**语义层**用小模型或规则做抽取后回填校验，或者抽样人工复核并统计准确率。再补工程手段：失败重试与降级、把每次抓取的原始快照留存以便回溯、给 Agent 的输出加置信度阈值，低置信度转人工。最后一定要说清「怎么量化」——抽样 N 条算准确率与漏抓率，而不是凭感觉说「挺准的」。

**UI 自动化相关的追问通常会落到「为什么用、覆盖了多少、稳定性怎么保证」。** 要能说出框架（Selenium/Playwright/Cypress/Appium）、设计模式（Page Object）、元素定位策略（优先用稳定的 `data-testid` 而不是 XPath 绝对路径）、以及怎么处理不稳定用例（重试机制只能兜底，真正的解法是消除对时序与共享状态的依赖、隔离测试数据）。如果被问「为什么不大面积铺开」，诚实回答投入产出比：UI 层用例维护成本高、执行慢，适合覆盖核心链路的冒烟，细节分支交给接口与单测。

**continue 与 break：** break 直接跳出当前整个循环（在 switch 里跳出 switch），continue 结束本次迭代、进入下一次循环；嵌套循环里两者都只作用于最内层，要跳出多层得用标志位、goto 或把循环抽成函数用 return。顺带可能要说出「循环里改了迭代变量会怎样」这类边界。

**深拷贝与浅拷贝：** 浅拷贝只复制对象本身与其中值的引用，嵌套的对象/数组仍指向同一块内存，改一个另一个也变；深拷贝递归复制所有层级。实现上浅拷贝可以用展开运算符、`Object.assign`、或语言内置的 copy 构造；深拷贝用 `structuredClone`、序列化反序列化（会丢函数、Date 变字符串、循环引用报错）或手写递归（要考虑循环引用、Map/Set、原型）。工程上更推荐不可变数据，从源头避免共享引用带来的问题。

**登录界面测试设计要按维度铺开，而不是罗列用例。** 功能维度：账号密码正确/错误/为空、大小写与前后空格、超长输入、特殊字符与 SQL 注入/XSS 载荷、验证码正确/错误/过期/重复使用/不区分大小写、验证码刷新后旧码失效、密码是否明文传输与是否可复制粘贴。安全维度：连续错误锁定与解锁、验证码是否可绕过（直接调接口）、是否防暴力破解与撞库、会话固定与登出后 token 失效、记住密码的存储方式。兼容与体验维度：不同浏览器与分辨率、移动端键盘与自动填充、回车提交、Tab 顺序、错误提示是否泄露账号是否存在、加载中与网络超时/断网的表现、多端同时登录的互踢策略。性能与可用性：并发登录、验证码服务不可用时的降级。回答时先说「我会按功能、安全、兼容、性能四个维度拆」，再各举两三个例子，结构感比数量重要。

**反问环节问什么，取决于你想知道什么。** 这场里作者问到了整体业务流程、AI 使用占比、测试排期（一个需求多久、回归多久）、内部 CI/CD 流程——这些都是判断团队成熟度的好问题：有明确排期与回归节奏、CI 能自动化跑起来，说明测试不是纯手工救火。要避免问「加班多吗」这类容易踩雷的问题，改成「团队一个版本的节奏是怎样的」。
