### 《参考解析》

**字符设备驱动的骨架是“设备号—cdev—file_operations—设备节点”。** 初始化时申请主次设备号，初始化 `cdev` 并绑定 `file_operations`，再创建 class/device 让 udev 生成 `/dev` 节点；退出时按相反顺序释放。资源管理要覆盖内存、IO 映射、中断、DMA 缓冲和锁，任何一步失败都要能回滚。并发访问要区分场景：多个进程同时 `open` 时，设备状态是共享还是每文件私有；`read/write/ioctl` 与中断处理之间要不要加锁；阻塞操作要用等待队列，别在持锁时睡眠。应用层接口通常包括 `open/close/read/write/ioctl/mmap/poll`，其中 `ioctl` 负责控制命令，`mmap` 把内核缓冲映射到用户态，`poll` 支持事件等待。

**V4L2 多缓冲采集是“队列轮转”，不是简单的 read。** 驱动维护 `queued`、`active`、`done` 三个状态，应用先 `REQBUFS` 申请若干 buffer，`QBUF` 入队，`STREAMON` 启动；硬件填满一帧后驱动把 buffer 移到 done 队列并唤醒 `poll`，应用 `DQBUF` 取走处理，处理完再 `QBUF` 还回去。多缓冲的意义是让采集和处理并行，避免每帧都等应用。生产者消费者队列要用互斥锁保护队列本身，用条件变量在“空/满”时阻塞等待，判断条件必须放在循环里防止虚假唤醒；无锁 SPSC 队列则用 head/tail 两个原子索引，生产者和消费者各自只写一个，再用 acquire/release 屏障保证数据可见，缓存行对齐避免伪共享。

**DMA-BUF 解决的是跨设备、跨进程的零拷贝共享。** 同一进程里的多硬件流水线，如果每个设备都各自拷贝一份，带宽和延迟都受不了；DMA-BUF 用一个 fd 表示一块底层缓冲区，exporter 负责分配，importer 通过 `dma_buf_attach`、`dma_buf_map_attachment` 建立设备映射，多个设备可以共享同一块内存。用户态可以通过 `DMA_HEAP_IOCTL_ALLOC` 或设备节点申请，再用 `mmap` 访问。同步靠 fence：生产者完成写入后给出 fence，消费者等待 fence 再读；跨设备还要处理 cache 一致性，非一致性架构上要在 CPU 访问前后做 `dma_sync_single_for_cpu/device`，否则 CPU 可能读到 cache 里的旧数据。

**Cache 一致性不是“有了 DMA 就不需要 Cache”。** CPU 访问普通内存仍然走 cache，DMA 设备通常不经过 CPU cache；如果设备写了内存而 CPU cache 里还有旧行，就必须 invalidate；如果 CPU 写了脏行还没回写，设备读到的可能是旧数据，就必须 flush。`dma_sync_*` 做的就是按范围清理/失效 cache，并配合内存屏障保证顺序。地址翻译方面，多核 CPU 写入用户态内存时，每个核的 MMU 把虚拟地址翻成物理地址，cache 一致性由 MESI 一类协议维护；但设备通过 IOMMU 或物理地址访问，和 CPU 的 cache 不共享同一套一致性，所以跨设备共享缓冲必须显式同步。

**C++ 小题要答准细节。** `auto` 按模板推导规则去掉顶层 const 和引用，想知道真实类型可以用 `decltype`、`typeid` 或故意触发编译错误；`static_cast` 是编译期转换，能做数值转换、`void*` 转回、上行/下行转换（下行不检查），但不做运行期类型检查，安全的下行要用 `dynamic_cast`。进程间通信常见 pipe/FIFO、消息队列、信号量、共享内存、socket；共享内存本身只提供一块共同地址空间，读写顺序和互斥仍要靠信号量或文件锁。Linux 驱动里这些概念经常串在一起考，回答时最好落到“谁分配、谁映射、谁同步、失败怎么回滚”。
