### 《面试题目》

1. 笔试题目：以 AI 平台产品经理的身份，用三天时间做一个「Agent 搭建中台」的 MVP，并产出第一期、第二期的方案 PRD。官方提供 glm5.3 与 sonnet4.6 两个模型可用（有额度限制），在 Linux 云 agent 环境里完成，交付需要带有可访问的发布链接，可以对 PRD、原型与测试用例做在线自测。

### 《参考解析》

**这类笔试真正在考什么**：不是考你能写多少字 PRD，而是考三件事——能不能在信息不全的情况下圈定 MVP 边界、能不能把一个平台型产品的能力分层讲清楚、以及有没有可验证的交付物。三天时间加限速环境，本身就在筛「会不会先规划再动手」：一上来就写全量 PRD 的人一定交不出来。合理的节奏是第一天做问题定义与能力分层、把 MVP 收敛到最小闭环并跑通原型，第二天补一期 PRD 与关键交互，第三天做二期规划与自测收口。

**Agent 中台应该怎么分层**：中台的价值是把各业务重复搭 Agent 的成本收下来，所以能力分层要对着「业务自己搭一个 Agent 需要哪些东西」来切。常见五层：模型接入层（多模型路由、密钥与配额管理、降级与兜底）、编排层（流程编排、条件分支、循环与人工介入、可复用模板）、能力层（工具注册与调用、知识库与检索、记忆存储）、治理层（权限与审批、调用审计、成本与限流、内容安全）、观测与评测层（链路 Trace、效果评测、badge 回流）。MVP 的边界建议只做「编排 + 工具调用 + 一条可观测链路」，其余留到一期二期——因为这三件是能让业务真正跑起来一个 Agent 的最小集合，而权限治理与评测体系的复杂度高、对 MVP 的验证价值反而低。

**一期、二期怎么切**：一期目标是「让业务能自助搭出可用的 Agent 并上线」，重点补治理（权限、审批、审计、成本配额）和基础评测，把中台从「能跑 demo」推到「能承接真实流量」；二期目标是「让平台自我进化」，重点做效果评测体系与自动优化闭环（badge 回流、prompt 与工具版本管理、A/B 对比、自动降级策略），以及跨业务的能力复用市场。切分的原则是每一期都要能独立交付价值：一期结束业务能自助上线，二期结束平台能回答「哪个 Agent 效果在变差、为什么」。

**写 PRD 要交代清楚的最低限度**：用户与场景（谁在什么情况下用它）、核心流程（从创建到发布到观测的完整链路，最好配流程图）、功能清单与优先级（P0/P1 明确划开，并写清每个功能解决什么痛点）、非功能要求（并发、延迟、成本上限、权限模型）、以及验收标准（每个功能如何验证做完了）。最容易失分的是只列功能不讲取舍——平台型产品的 PRD 里「我们这期不做 X，因为 Y」比功能列表更能体现判断力。原型要做到能点通主干路径（创建 → 配置 → 调试 → 发布），不需要每个状态都画。

**在额度与限速受限的环境里怎么干活**：关键在于把大模型的输出拆成小块并保留可回退的产物。把 PRD 拆成章节分别生成、每章人工过一遍再合并；原型先写静态结构再让模型补交互；测试用例单独生成一轮用于在线自测。要在早期就把「哪些环节必须自己写」想清楚——架构分层、优先级取舍、验收标准这类判断交给模型会写得四平八稳但没有观点，而文案润色、样板代码、用例枚举这类工作交给模型性价比最高。另外务必尽早跑通发布链接这一步，交付通道不通后面做得再好也没法验证。
