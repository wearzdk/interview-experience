### 《参考解析》

**数据类型、芯片参数与常用器件**：`uint8_t`、`uint16_t`、`uint32_t`、`uint64_t` 由 `<stdint.h>` 定义，宽度分别是 8、16、32、64 位，即 1、2、4、8 字节，这类定长类型正是为了避开 `int`、`long` 宽度随编译器与目标平台变化的问题。C 标准只规定最小范围与相对大小，具体宽度由 ABI 决定：32 位 ARM 上 `int` 与 `long` 都是 4 字节、`long long` 是 8 字节、指针是 4 字节；ARM 的 EABI 约定下 `char` 默认无符号，这一点在跨平台移植、位运算与比较时容易踩坑，需要显式写 `signed char` 或 `uint8_t`。STM32F103C8T6 的核心参数要能直接报出：Cortex-M3 内核、最高主频 72MHz、64KB Flash、20KB SRAM、LQFP48 封装、37 个可用 IO；片上集成 2 路 12 位 ADC（10 个通道）、3 路 USART、2 路 I2C、2 路 SPI、1 路 CAN、1 路 USB 全速设备、1 个高级定时器 TIM1 与 3 个通用定时器。子系列的区别按内核与外设答：F1 为 Cortex-M3、主频 72MHz、定位基础通用；F4 为 Cortex-M4F，带单精度 FPU 与 DSP 指令，主频 168 至 180MHz，外设更丰富；F7 为 Cortex-M7、216MHz，带 L1 缓存与更快的存储器接口；H7 为 Cortex-M7 高性能系列，主频 400MHz 以上，双核型号另带一颗 M4。常用器件按接口与用途分类：AT24C02 是 I2C 接口的 EEPROM，容量 2Kbit，用于保存参数与标定数据；W25Q 系列是 SPI 接口的 NOR Flash，用于存放字库、图片与固件备份；AMS1117 是低压差线性稳压器，固定输出 3.3V 或 5V；TLV 系列是通用运算放大器，用于小信号调理与电流检测。能说清「这个器件挂在哪条总线、地址怎么定、驱动要注意什么」，比只报型号有说服力。

**指针、static 与 const，以及帧长的定义**：指针存放地址，通过解引用访问目标内存，是嵌入式里操作寄存器、缓冲区与外设映射的基础，函数指针还用于回调与命令表。回答时要带出风险：未初始化或已释放的野指针、越界写、返回局部变量地址、指针与整数互转，这几类是嵌入式崩溃的常见来源。`static` 有三种用法：修饰局部变量时改变存储期，变量放在静态区、函数退出后值保留、只初始化一次；修饰全局变量或函数时把链接属性降为内部，作用域限定在本文件，是模块封装与避免重名的手段。`const` 定义只读对象，有类型并参与编译期检查，与 `#define` 的区别在于后者是文本替换、没有类型与作用域；`const` 修饰指针时位置决定语义，`const char *p` 是所指内容不可改、`char * const p` 是指针本身不可改、`const char * const p` 是两者都不可改。`volatile` 与 `const` 不是一类东西：前者告诉编译器该对象可能被外部改变（中断、DMA、寄存器），每次都必须真实读写。顺带把数据帧大小的定义讲清：用 `#define FRAME_MAX_LEN 64` 或 `static const uint16_t`，集中一处便于修改，禁止在代码里散落魔法数字，并用 `_Static_assert` 校验缓冲区不小于帧长。

**按键长短按与串口收数据**：按键的稳妥做法是定时器每 5 至 10 毫秒扫描一次电平，连续两次以上一致才认定状态，完成软件消抖；随后用状态机推进「空闲—按下—长按—释放」，记录按下时刻的 tick，释放时用持续时间与阈值比较判定短按或长按；长按若要连发，则在超过阈值后按固定间隔重复触发。整个过程不得使用阻塞延时，业务动作通过标志位交给任务处理。串口接收分两种实现：中断方式下每收到一字节进入一次中断，把数据写入环形缓冲区并移动写指针，主循环从读指针取数据做帧解析，读写指针的更新存在与中断的竞争，必要时用临界区保护；更高效的是 DMA 加空闲中断，DMA 把数据搬到缓冲区，总线空闲触发 IDLE 中断表示一帧结束，再由任务处理整帧。协议层要处理粘包与半包：用帧头加长度加校验（和校验或 CRC）确定边界，校验失败丢弃并重新同步，缓冲区满时明确覆盖还是丢弃策略，同时处理溢出、帧错误与噪声等错误标志。数据结构这题可以顺着这条线答：环形队列适合字节流缓冲，单向链表适合数量不定、频繁增删的设备节点管理，数组适合定长表与查表，哈希与树用于大量查找，关键是指出各自的时间与空间代价以及内存能否静态分配。

**I2C 总线**：I2C 是两线制半双工同步总线，SDA 与 SCL 均为开漏输出，必须外接上拉电阻；通过 7 位或 10 位从机地址寻址，支持多主多从，每字节传输后由接收方拉低 SDA 给出应答；有起始与停止条件，速率分为标准 100kbit/s、快速 400kbit/s、快速加强 1Mbit/s 与高速 3.4Mbit/s；多主竞争时通过仲裁与时钟同步决定谁继续发送，从机可以用时钟延展让主机等待。工程上的坑集中在电气与异常恢复：上拉阻值与总线电容（一般不超过 400pF）决定波形上升沿，地址冲突会导致总线被拉死，从机在传输中途复位可能长期占用 SDA，需要主机补 9 个时钟脉冲再加停止条件恢复。调试建议先确认从机地址（7 位地址左移一位后的写地址与读地址）、用示波器或逻辑分析仪看起始条件与应答位，硬件外设时序异常时先用 GPIO 翻转模拟时序验证从机是否正常，再切回硬件 I2C 排查配置。

**RTOS 的临界区与任务同步**：临界区保护的目的是让一段代码不被中断或任务切换打断，常用两种方式：关闭中断（Cortex-M 上操作 PRIMASK 或 BASEPRI，FreeRTOS 封装为 `taskENTER_CRITICAL` 与 `taskEXIT_CRITICAL`，中断中用 `FROM_ISR` 版本）与挂起调度器。原则是临界区越短越好，只保护共享变量的读写，不在其中调用可能阻塞的接口。信号量用于同步与计数：二值信号量常用于中断通知任务「事件到了」，计数信号量用于管理有限资源（缓冲区槽位、外设实例）；消息队列用于任务间传递数据，按值拷贝固定长度消息，天然带缓冲与阻塞超时，适合生产者消费者模型；互斥量专用于共享资源互斥，带优先级继承，能缓解优先级反转，二值信号量没有这一机制，用错会出现高优先级任务被中优先级任务长期压制。任务同步的完整清单还包括事件标志组（多事件组合等待）、任务通知（最轻量，无需额外对象）与队列集。回答时补一句取舍：能用任务通知就不用信号量，能静态创建就不用动态创建，中断里只调用 `FromISR` 结尾的接口并在退出时按需触发切换。

**实时性与可靠性：中断、CAN 与车规内存**：中断里不做耗时操作，原因是中断优先级高于任务，长时间占用会屏蔽同级与低级中断，外设事件得不到及时响应甚至溢出丢失，系统实时性被破坏；正确做法是中断里只做标记、清标志、搬运少量数据，把解析与业务放到任务，必要时用 DMA 替代 CPU 搬运。CAN 的仲裁机制同理，都是确定性设计：多个节点同时发送时逐位比较标识符，显性位 0 会覆盖隐性位 1，发送隐性位却检测到显性位的节点立即退出并转为接收，胜出的节点继续发送且报文不被破坏，因此标识符数值越小优先级越高；标准帧为 11 位标识符，扩展帧为 29 位，仲裁失败会自动重发，这也是 CAN 适合车载实时通信的原因之一。车规开发中静态与动态内存的取舍要明确站队：量产代码通常禁止 `malloc` 与 `free`，因为动态分配会产生碎片、耗时不确定、失败时机不可控，静态分配在编译期确定内存布局与最坏用量，行为可预测，符合高可靠要求；确需动态场景时用固定大小内存池替代通用堆，并在初始化阶段一次性分配。配套的两个问题要一起答：栈溢出来自局部变量过大或调用层级过深，覆盖了相邻内存，表现为随机死机或返回地址被改写，排查手段包括用已知填充值（如 0xA5）预填栈并在运行时检查水位、用 RTOS 的栈高水位接口观察余量、大数组移出栈放到静态区、必要时用 MPU 设置栈边界触发异常；内存对齐是编译器按类型宽度在成员之间插入填充，使每个成员的地址满足自然对齐，原因是多数总线与指令只保证对齐访问的原子性与效率，Cortex-M0 访问非对齐地址会直接触发 HardFault，M3 与 M4 对单字访问支持非对齐但多字与双字访问仍要求对齐，DMA 缓冲区还常要求更高对齐；因此结构体布局要考虑成员顺序以减少填充，跨设备传输的结构体不要用 `#pragma pack` 压缩后直接强转，否则在本机读写就会产生非对齐访问。
