### 《面试题目》

1. 请做自我介绍。
2. 介绍项目，重点讲沙箱设计。
3. 设计题：如果要做一个 Agent 观测后端，数据库怎么设计字段，怎么保证其空间复杂度和时间复杂度？
4. 讲一下为什么 LLM 输出是流式的。
5. 手撕题：分割统计所有回文串。

### 《参考解析》

**Agent 观测后端的数据模型**：核心实体是任务（session/task）、步骤（step）、模型调用、工具调用与产物。任务表存目标、状态、起止时间、成本汇总；步骤表存序号、类型、父子关系、开始与结束时间、状态；模型调用表存模型名、输入输出 token、缓存命中、首字延迟与总耗时、请求参数摘要；工具调用表存工具名、参数、结果摘要、错误码与重试次数；产物表存文件路径或对象存储键。所有表按任务 id 建索引，时间字段建联合索引以支持按时间范围扫描。

**空间与时间的控制**：原始 prompt 与响应体积大，不应整段入库。做法是热数据保留近期原文、冷数据只留摘要与对象存储引用，并按保留策略定期归档或删除；轨迹按任务聚簇存储，避免跨任务随机读。查询侧预聚合常用指标（成功率、平均步数、P95 延迟、成本），避免每次扫描明细；对高频维度建索引或物化视图。写入侧批量提交、异步落库，避免观测本身拖慢主链路。

**为什么 LLM 输出是流式的**：一是感知延迟，首字出来即可阅读，用户不必等到全部生成完；二是生成本身是自回归的，逐 token 产生，天然可以边生成边下发；三是长回答的传输与内存占用更平滑，连接不必长时间静默（很多网关会掐断无字节流动的长连接）。工程上要处理分片边界、增量解析与断线重连，并保证前端拼接的顺序与完整性。

**统计所有回文子串**：需要区分「回文子串的个数」与「分割方案」。若是计数所有回文子串，用中心扩展法：以每个字符和每对相邻字符为中心向两侧扩展，相等就计数，时间 O(n²)、空间 O(1)；数据量大时用 Manacher 做到 O(n)。若是「把字符串分割成若干回文串的所有方案」，则用回溯加动态规划预处理回文判定：先以 O(n²) 求出 dp[i][j] 表示子串是否为回文，再从起点深搜，每步枚举回文前缀，收集路径。面试时要先确认题目问的是哪一种，再动手。
