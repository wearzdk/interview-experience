### 《面试题目》

1. 结合项目问项目的设计方案（两位面试官各半小时）。
2. 顺着项目追问涉及的八股知识点。
3. 围绕项目涉及的线上场景出场景题。

### 《参考解析》

这类"没有独立八股、全部结合项目"的面试，准备方式和技术八股面完全不同，核心是**把项目讲成一条能被追问的链路**。

**先把项目拆成可追问的层次**：业务背景 → 整体架构 → 我负责的模块 → 关键设计决策 → 数据怎么存 → 并发怎么处理 → 单机变多机哪里会失效 → 数据量涨十倍哪里先崩。面试官基本就是沿着这条线往下挖，提前把每一层的答案准备好，比背八股有效得多。

**八股是"被带出来"的**：你说用了 Redis 做缓存，对方自然会问缓存穿透击穿雪崩；你说用了消息队列，就会问消息丢失与幂等；你说改了线程池，就会问参数怎么定、队列满了怎么办。所以准备时要做一遍"反向索引"——把项目里用到的每个中间件和设计模式，对应到它最常被追问的三五个知识点上。

**场景题要答出取舍过程**：线上场景题（如某接口 P99 抖动、某数据不一致）考的往往不是标准答案，而是排查路径——先看监控和日志定位现象，再用排除法缩小范围，最后给方案并说明代价。回答时把"我怎么验证这个假设"讲出来，比直接甩结论更能得分。
