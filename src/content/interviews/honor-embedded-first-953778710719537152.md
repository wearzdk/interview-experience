### 《面试题目》

1. C 语言里，把一个变量声明为静态的，放在代码块内和放在所有函数之外，分别改变了它的哪些属性？对编译和链接各有什么影响？
2. 给函数加上 static 修饰后，调用方和链接过程会受到什么限制？这对模块封装有什么实际意义？
3. 程序运行后，指令、已初始化全局数据、未初始化数据、函数调用产生的临时数据，通常分别落在哪些内存区域？栈和堆的边界由谁管理？
4. 函数把自身栈上对象的地址交给调用者，会埋下什么隐患？调用返回后，这个地址还有没有合法访问的可能？哪些情况看似能用其实是未定义行为？
5. 进程收到 SIGSEGV 时，通常对应哪几类非法访问？拿到 core dump 或崩溃日志后，第一步会核实哪些信息来缩小范围？
6. 需要频繁随机下标访问、元素数量基本稳定时，和需要频繁在中间插入删除、长度变化大时，分别更倾向哪种数据组织方式？理由是什么？
7. 从单向链表中摘掉一个节点时，头节点、尾节点、待删节点的前驱和后继，哪些指针赋值顺序或判空容易出错？如何避免断链或内存泄漏？
8. 你在项目里实际驱动过哪些片间或板级通信总线？当时基于带宽、拓扑、引脚数、抗干扰、成本中的哪些因素做了取舍？
9. I²C 一次完整事务从起始条件到停止条件如何推进？应答位由谁在哪个时钟相位驱动？如果某根数据线持续为低，你会从总线状态、从设备、上拉和控制器配置哪些角度排查？

### 《参考解析》

**static 的两层含义**：在代码块内，它改变的是存储期与初始化时机——变量从自动存储期变成静态存储期，放在 `.data`（有初值）或 `.bss`（无初值或零初始化），生命周期贯穿整个程序，只初始化一次，函数多次调用之间共享同一份；作用域仍限于该代码块，外部不可见。在所有函数之外，它改变的是链接属性——从外部链接变成内部链接（internal linkage），符号只在当前翻译单元可见，别的文件即使写了 `extern` 也链接不到；同时它仍具有静态存储期。对编译与链接的影响体现在符号表：文件作用域的 static 变量与函数在目标文件里是局部符号（`t`/`d`/`b`，而全局是 `T`/`D`/`B`），不参与跨文件的符号解析，因此不同文件可以重名而不冲突。

**函数加 static 的封装意义**：函数默认是外部链接，别的文件声明同名原型即可调用；加了 static 后它成为本编译单元的私有函数，链接器不会把它导出，其他文件调用会得到未定义引用（链接错误）。实际意义有两点：一是把「只在本文件使用」的辅助函数收进内部，避免命名污染与误用，接口边界由编译器强制；二是编译器可以做更激进的内联与优化（知道不会被外部引用）。代价是无法被单元测试直接调用，通常通过暴露一个包装接口或把测试放在同一编译单元解决。

**内存分区**：指令在 `.text`（通常只读、可执行，部分平台放在 Flash）；已初始化的全局与静态变量在 `.data`（占用可执行文件空间，运行时拷到 RAM）；未初始化或零初始化的在 `.bss`（不占文件空间，运行时清零）；函数内的自动变量、参数、返回地址在栈上；`malloc` 得到的在堆上；此外还有只读数据段 `.rodata`（字符串字面量、const 全局）与内存映射区。栈的边界由内核在创建进程/线程时设定（`ulimit -s`、线程属性里的栈大小），溢出会触发 SIGSEGV 或栈保护；堆的边界由 `brk`/`mmap` 与分配器管理，`malloc` 向内核申请、`free` 归还给分配器而不一定还给内核。嵌入式上还要区分 Flash 与 RAM 的放置（链接脚本里的 section 分配）。

**返回栈上对象地址的隐患**：函数返回后其栈帧被回收，后续的函数调用会复用这块内存，通过悬垂指针读写得到的是别的函数的局部变量或垃圾值，行为不可预测。C 标准下这是未定义行为，不是「可能还能用」——编译器可以假设它不会发生并做优化（例如把读提到调用之前、或直接返回常量）。看似能用的情况包括：返回后立刻使用且中间没有别的调用（栈内容恰好没被覆盖）、在 `-O0` 下调试通过、或者该地址恰好落在未被覆盖的栈槽；这些都不是合法保证。正确做法是由调用方传入缓冲区、返回堆上分配的内存（并约定所有权）、返回 static 缓冲区（注意不可重入），或返回值本身而不是地址。

**SIGSEGV 的典型原因与排查第一步**：常见是解引用空指针或野指针、访问已释放内存、数组越界写坏指针、栈溢出（递归过深或大局部数组）、写只读段（修改字符串字面量）、非对齐访问（部分架构）、以及执行不可执行内存。拿到 core dump 后第一步是确认「崩在哪一行、是什么操作」：用 `gdb ./bin core` 看 `bt full` 拿到调用栈与各帧参数，确认故障地址（`info registers` 看 PC 与访问地址），再判断是地址为空、地址非法还是权限问题；同时核对二进制与 core 是否同一版本（带符号表）、崩溃时的线程与栈、以及最近改动。没有 core 时从崩溃日志的 PC、LR、栈回溯与 map 文件反查。

**数组与链表的选择**：需要频繁随机下标访问、元素数量稳定时用数组（或 `std::vector`/`std::array`）：内存连续、缓存友好、下标访问 O(1)，代价是中间插入删除 O(n) 与扩容时的整体搬移。需要频繁在中间插入删除、长度变化大时用链表：已知位置时插入删除 O(1)、按需分配不要求连续内存，代价是随机访问 O(n)、每个节点额外指针开销、缓存不友好、以及分配器碎片。实际工程里常常是「数组 + 空闲位」或「分块链表」这类折中，回答时说明数据规模、访问模式与内存约束再给结论。

**单链表删除的易错点**：删头节点要更新头指针（用二级指针 `Node**` 或返回新头，避免只在函数内改副本）；删尾节点要找到前驱并把它的 `next` 置空，只把尾节点的 `next` 置空不会让前驱停止指向它；删除中间节点必须先保存 `prev->next`，再 `prev->next = cur->next`，顺序反了会断链或丢失后继；还要判空（空链表、删除不存在的值）、避免释放后继续使用（use-after-free）、以及 `free` 后把指针置空。用哨兵（dummy head）可以把头节点的情况统一掉，是更稳的写法。

**总线选型的取舍**：SPI 是四线全双工、速率可到几十 MHz，适合高带宽的屏幕、Flash，代价是引脚多、每增加一个从设备多一根片选；I²C 两线、支持多从机与地址寻址，速率通常 100k/400k/1M/3.4M，适合传感器与低速外设，代价是带宽低、总线电容限制长度、时钟拉伸与仲裁带来复杂度；UART 点对点、无时钟线，适合调试与模块间低速通信，靠约定波特率；CAN 差分、抗干扰、多主仲裁，适合车载与长距离；此外还有 I2S（音频）、USB、以太网。选型时按带宽需求、拓扑（点对点还是总线）、引脚预算、距离与抗干扰、成本与生态综合判断，回答时结合自己做过的具体外设说明理由。

**I²C 的完整事务与应答时序**：起始条件是 SCL 为高时 SDA 由高变低；随后逐位发送 7 位从机地址 + 1 位读写方向，第 9 个时钟由从机拉低 SDA 作为 ACK；写操作接着发寄存器地址与数据，每字节后都有一个 ACK；读操作先写地址，再发重复起始条件（Sr）+ 读方向，由主机在每个字节后给 ACK、最后一个字节给 NACK，最后主机在 SCL 为高时把 SDA 由低拉高产生停止条件。数据在 SCL 低电平期间变化、在高电平期间保持稳定（起始与停止是唯一例外）。应答位由接收方驱动：主机发地址/数据时由从机 ACK，主机读数据时由主机 ACK/NACK。SDA 持续为低的最常见原因是总线死锁——从机在传输中途被复位、停在拉低 SDA 的状态等待下一个时钟，主机侧表现为起始条件都发不出去。排查顺序：先用示波器/逻辑分析仪看 SCL 与 SDA 的实际电平，确认是 SDA 被拉死还是 SCL 被从机时钟拉伸卡住；再断开从机逐个接入定位是哪个器件；然后检查上拉电阻阻值与总线电容（阻值过大导致上升沿变缓、高速下读错）、供电与地从机是否共地、地址是否冲突；软件侧补 9 个时钟脉冲的恢复流程（主机把 SCL 打 9 个周期让从机把剩余字节发完并释放 SDA，再发停止条件），并在初始化时检查总线空闲状态。
