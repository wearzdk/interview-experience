### 《面试题目》

1. 围绕实习经历展开追问（约 20 分钟）：做了什么、怎么做的、难点在哪。
2. 反问环节（面试官得知候选人是前端方向后直接转入反问）。

### 《参考解析》

**这是一场以实习经历为主的面试**。原帖提供的信息很少，能提炼出的关键事实是：面试官本人是后端方向、全程没开摄像头、20 分钟围绕实习展开、发现候选人是前端之后就转成反问、整场 25 分钟结束，没有问八股。这类面试的结果通常取决于实习讲述的质量，而不是算法或八股。

**实习经历怎么讲（STAR + 技术取舍）**：面试官连续追问 20 分钟，意味着他关心的是「你是不是真的做过」。建议按四段组织，每段一到两分钟：① 背景与约束——业务是什么、数据量/用户量/QPS 大概什么级别、有哪些硬约束（工期、合规、已有系统）；② 我的动作——我负责哪一部分（务必把「我做的」和「团队做的」分清楚），具体改了什么、为什么这么选（给出至少一个被否掉的备选方案及原因）；③ 结果——可量化的收益（耗时从多少降到多少、错误率、覆盖率、接口耗时、覆盖多少用户），没有精确数据就用可核验的相对量；④ 复盘——踩过什么坑、如果重做会怎么改。追问环节最常见的是「为什么不用另一个方案」「数据怎么测的」「还有什么没想到的边界」，所以每个技术点都要准备这三问。

**被反问时怎么接**：当面试官说「你有什么想问我的」，不是结束信号，而是最后一次展示匹配度的机会。有效的反问分三类：① 业务与技术现状——团队现在做什么方向、技术栈是什么、当前最大的技术挑战是什么（可以顺势承接自己的经历：「这块我实习时也做过类似的，想了解你们的做法」）；② 岗位期望——这个岗位入职后前三个月的重点是什么、团队怎么评估一个人的成长；③ 流程与团队——面试流程还有几轮、团队规模和协作方式。要避免的是直接问薪资福利、加班情况（可放到 HR 面）以及「我表现得怎么样」这类无效问题。原帖这个案例里，候选人是前端背景面 Agent 开发岗，反问阶段其实是很好的补救窗口——可以主动说明自己对 Agent/后端的自学与实践（做过的项目、写过的 Skill/工具链），把话题拉回「能力匹配」而不是「方向不符」。

**前端转 Agent / 后端的准备清单**：① 补齐后端基础——一门主力语言（Go/Java/Python 任选其一深挖）、HTTP 与 RPC、数据库（索引、事务、连接池）、缓存与消息队列、Linux 常用排查（`top`/`iostat`/`ss`/日志），这些是面试八股的主要来源；② Agent 特有知识——工具调用与 function calling 的参数校验、上下文管理与压缩、RAG 全链路（切分、向量检索、BM25、rerank、评测）、多 Agent 协作与状态机、以及评测与可观测；③ 项目补齐——前端同学的天然优势是「端到端做完整产品」，可以自己做一个前后端 + Agent 的完整项目（前端自己的强项 + 后端与 Agent 由自己实现），面试时就是最好的转型证据；④ 表达策略——不要回避前端背景，把它讲成优势（对用户体验与交付链路敏感，能独立闭环），同时明确说明为转向后端/Agent 做了哪些具体功课。

**面试复盘**：原帖作者的感受是「AI 时代前端太难了，已经在补后端八股」。这个案例给两个提醒：一是当面试官的方向与你不同、又不问技术时，面试的胜负手就是实习讲述和反问的质量，务必提前准备一份 90 秒和一份 5 分钟两个版本的实习介绍；二是投递 Agent / AI 工程类岗位时，简历上最好直接体现后端与 Agent 相关经历，否则容易像这场一样「聊完实习就转反问」，全程没有展示技术深度的机会。
