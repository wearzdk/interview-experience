### 《面试题目》

1. 项目整体介绍、个人职责和项目难点是什么？
2. 智能 Agent 调度平台的完整调用链路如何设计？
3. Agent 异步并发调用工具时，如何匹配乱序的请求与响应？
4. 并行工具调用何时需要对结果排序？
5. 如何判断批量并行工具调用全部返回？单个工具超时如何处理？
6. Agent 平台如何通过重试和证据列表校验防止幻觉？
7. 长轮次执行导致上下文膨胀时如何压缩治理？
8. 电商拼团场景如何设计高并发库存扣减？
9. Redis 与数据库库存不一致时如何巡检补偿？
10. 流量大时直接执行补偿会不会影响性能？
11. Spring 声明式事务在哪些场景会失效？

### 《参考解析》

1. **异步工具调用**：每次调用生成唯一 requestId，将请求上下文与回调结果按 ID 关联；并行结果只有在业务需要稳定顺序时才排序，超时任务要有截止时间、取消或补偿状态。
2. **Agent 防幻觉**：工具失败应按错误类型有限重试，成功结果附带来源证据并做结构校验；不可验证的结果应标记失败或转人工，而不是静默编造。
3. **库存一致性**：先在 Redis 做原子扣减和幂等记录，再通过可靠消息落库；定时对账只处理差异，使用分片、限速和批量更新降低高峰影响，数据库唯一约束和条件更新作为最终防线。
4. **事务失效**：同类内部调用绕过代理、方法不是 public、异常被吞掉、回滚规则不匹配、异步线程脱离事务上下文等都会导致声明式事务不生效。
