### 《参考解析》

**权限测试要建矩阵，不只看接口能不能调。** 维度包括角色（普通用户、管理员、跨区域管理员）、资源归属（本人、同租户、跨租户）、操作（读、写、删、导出）、入口（页面、API、批量任务）。每条用例验证四件事：无权限时被拒绝、有权限时成功、越权访问不泄露数据（响应体、错误信息、日志、导出文件都不能带出）、拒绝行为被审计。水平越权（改 ID 访问他人资源）与垂直越权（低权限调用高权限接口）要分别覆盖；批量接口、分页、搜索、缓存与消息队列都是常见绕过点。自动化上用不同角色令牌跑同一组请求，断言状态码与响应内容。

**知识库切分按结构而非固定字数。** 模块地图这类图结构数据应保留节点、边、层级路径，转成「节点 + 关系 + 描述」的文本并附元数据；结构化元数据包括文档 ID、标题路径、版本、生效时间、适用区域、权限标签、来源。差异化策略：说明文档按标题层级切，表格按行或整表保留，代码按函数切，FAQ 按问答对切；长文档用父子块，子块检索、父块补上下文。切分质量用「能否独立回答一个问题」检验。

**BM25 与 embedding 各有所长。** BM25 适合精确词、型号、错误码、专有名词，对词形变化与同义表达不敏感；embedding 适合口语化描述、语义相近但用词不同的查询，对精确数字与罕见实体可能失灵。混合检索分别召回再融合，按业务查询类型调权重。

**漏召回按链路排查。** 先确认文档是否入库、版本是否最新、权限过滤是否把文档排除；再看切分是否丢了关键段、索引是否包含该段；然后看查询改写、召回数量、融合与重排是否把它挤掉；最后看生成是否忽略了已召回的证据。每一步都用同一条查询与文档做可复现的实验，定位后再改参数。重排权重不要凭感觉，用标注集做网格搜索或学习排序，目标看 NDCG 与业务指标，并监控不同查询类型的表现。

**RAG 与 MySQL 的存储差异。** MySQL 存结构化行，按主键与索引精确查询，强一致、支持事务；RAG 存文本块与向量，按语义相似度检索，最终一致性、需要 embedding 与索引构建。两者不是替代关系：结构化字段、权限、订单状态仍放数据库，RAG 负责非结构化知识的召回。

**分片上传 md5 缺失的测试点。** 正常路径：全部分片上传后合并，md5 与本地一致。异常路径：缺片（少传一个分片、分片序号跳号）、重复分片（同一序号传两次）、乱序到达、分片内容被篡改、分片大小不一致（最后一片除外）、并发上传同一文件、断点续传后继续、上传中断后重试、合并时超时或失败、合并后文件大小与分片总和不一致、秒传命中但内容不同、空文件与超大文件、文件名特殊字符、存储层写入失败。校验点包括：后端是否在合并前校验分片数量与序号连续性、是否对每个分片校验 md5、合并后是否整体校验、失败是否清理临时分片、错误信息是否可定位。MD5 是 128 位摘要，用于校验完整性，不是加密；抗碰撞要求高时用 SHA-256。

**随机均匀分流的测试。** 功能上验证同一用户多次调用落在同一桶（如果要求稳定）、不同用户分布均匀、输入为空或重复 ID 时的行为；统计上用卡方检验比较 100 个桶的观测频数与期望频数，样本量要足够（每桶至少几十个），并重复多轮看是否稳定；边界上验证 ID 哈希冲突、负数与超长 ID、列表顺序变化不影响结果。若分流用于实验，还要验证桶与实验组的映射一致、扩缩容时不会大面积重排。

**库存扣减的并发控制。** 数据库层面用 `UPDATE stock SET count = count - 1 WHERE id = ? AND count > 0`，受影响行数为 0 说明库存不足，这是乐观锁；也可以用 `SELECT ... FOR UPDATE` 悲观锁，或分布式锁；高并发下用 Redis 预扣减加消息队列串行化，数据库最终对账。要点是「判断与扣减在同一原子操作里」，先查再改会有竞态；还要处理超卖回补、幂等与失败重试。
