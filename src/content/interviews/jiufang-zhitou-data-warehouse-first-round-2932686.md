### 《面试题目》

1. 一面的八股主要问了哪些方向？（原帖把具体题面放在配图里，正文只说明「全程基本都是八股，直接开始吟唱」）
2. 反问：公司的数仓架构是怎么搭的？（面试官答：基本都是基于 DataWorks 做的）

### 《参考解析》

**这篇帖子的信息量不在题面，在技术栈。**「基于 DataWorks 做」这一句基本把这个岗位的日常框定了：底层存储与计算是 MaxCompute（ODPS），调度用 DataStudio，数据集成走 DataWorks 的离线/实时同步节点，表存在 ODPS 里、用 ODPS SQL 写，配合 DataWorks 的数据质量、血缘和基线。所以它问的八股不会离开「离线数仓 + SQL + 建模」这三块，不会像互联网大厂那样追 Flink 状态后端、湖仓一体的事务实现。

**纯八股场次里最高频的四组问题**，按出现概率排：

一是**数仓分层与建模**。ODS / DWD / DWS / ADS 各层职责、为什么要分层（复用、隔离、口径收敛）、维度建模里星型和雪花型的取舍、事实表的三种类型（事务型、周期快照、累积快照）、缓慢变化维 Type1/Type2 与拉链表怎么开链闭链。这类问题面试官通常会顺着追问一句「你们的 DWD 是怎么切的」，答的时候要能说出粒度（一行代表什么）和主键，说不出来就说明只是背了分层名字。

二是**SQL 与优化**。ODPS 上没有索引，优化手段和 MySQL 完全不是一回事：分区裁剪、避免全表扫描、用 `DISTRIBUTE BY` / `CLUSTER BY` 控制数据分布、小表走 map join、处理数据倾斜（加随机前缀打散、热点 key 单独处理）、减少 shuffle 和中间表落盘。被问到「一条 SQL 跑得很慢怎么查」时，正确的顺序是先看执行计划里的 Scan 量和 Stage 耗时，而不是上来就说加索引。

三是**增量与全量、口径与一致性**。全量重算 vs 增量刷新的取舍、幂等重跑（按分区覆写而不是 append）、迟到数据与回刷历史、同一个指标在两张报表里对不上时怎么定位（先查口径定义、再查过滤条件、最后查调度时序）。

四是**调度与数据质量**。基线、依赖、补数据、任务失败告警、空值率与主键唯一性校验——DataWorks 里这些是现成能力，答得上来说明真用过。

**「全程八股、不深挖项目」对这种岗位其实是好事也是坏事**：好在不用讲故事，坏在没有任何加分项，答案的完整度和术语准确度就是全部。准备时把每个知识点压成「定义 + 为什么这么设计 + 一个具体的坑」三段，比背长段落更抗追问。另外这场没有笔试，简历里写了数仓相关项目就会被直接拉去面，投递前把 ODPS/DataWorks 的关键词对齐一下，被问到的概率会明显不同。
