### 《参考解析》

1. **SDK 怎么设计**：对外只暴露稳定接口、内部实现可替换；分层为寄存器操作层、外设驱动层、业务接口层；错误码统一、回调机制明确；配文档和示例，保证调用方不需要看源码。嵌入式 SDK 还要考虑资源占用、可裁剪（按宏关闭模块）和跨芯片移植。

2. **SPI 收发过程**：主机拉低片选，按配置的极性（CPOL）和相位（CPHA）在时钟边沿移出数据、另一边沿采样，全双工意味着发送的同时接收；一次传输可以只发不收（丢弃 MISO），也可以只收（发 dummy 字节）。多从机时片选要独立，时钟频率受从机器件上限约束。

3. **什么时候用中断**：数据量小、需要及时响应时用中断（比如传感器寄存器读取）；大批量传输用 DMA 加传输完成中断，避免 CPU 被逐字节打断；轮询只适合确定很快完成且实时性要求不高的场景。

4. **CAN 拓扑**：总线型，所有节点挂在同一对差分线上，两端各接 120Ω 终端电阻，中间节点用短支线接入。速率越高允许的总线长度越短，节点数受收发器驱动能力限制。

5. **CAN 收发器输入**：收发器把 MCU 的 TX 单端信号转成 CAN_H/CAN_L 差分信号，接收侧把差分电压比较后输出 RX 给控制器；它提供总线故障保护、共模抑制和隔离（隔离型收发器）。所以控制器只处理协议，物理层交给收发器。

6. **CAN 仲裁**：基于标识符的非破坏性逐位仲裁，显性位（0）覆盖隐性位（1），ID 越小优先级越高；发隐性位却检测到显性位的节点退出仲裁转为接收，赢的节点继续发。仲裁在数据帧的仲裁段完成，不影响任何节点的数据。

7. **CAN 驱动层设计**：分硬件抽象（寄存器、mailbox 操作）和协议层（报文 ID 过滤、收发队列、超时与错误处理）；提供发送队列和接收回调，错误帧和总线关闭要能上报；对上暴露「按 ID 发、按 ID 注册回调」的接口，屏蔽具体控制器差异。

8. **Mailbox 的作用**：控制器里用于存放待发或已收报文的硬件缓冲，发送 mailbox 可以排队多个报文，接收 FIFO 缓存收到的帧；数量有限，用满时要阻塞或丢帧，驱动必须处理「mailbox 满」的返回值。

9. **I 帧与 P 帧、H264**：H264 里 I 帧是帧内编码的完整图像，可独立解码；P 帧是前向预测帧，只编码与参考帧的差异，体积小但依赖前面的帧；还有 B 帧做双向预测。丢一个 I 帧会导致后续整段无法解码，所以传输要做分片、重传和关键帧请求。

10. **信号量与互斥锁**：信号量用于同步和计数（生产者通知消费者、限制并发数），没有所有权概念；互斥锁用于保护共享资源，有所有权、支持优先级继承，能避免优先级反转。在 FreeRTOS 里两者 API 不同，用错会引入优先级反转或死锁。

11. **STM32 启动流程**：上电后从固定地址取初始 MSP 和复位向量，执行启动文件里的 Reset_Handler，初始化 .data（从 Flash 拷到 RAM）、清零 .bss、调用 SystemInit 配时钟，再跳到 main。代码默认从内部 Flash 起始地址执行，也可以做 bootloader 加跳转到 APP 区，或在 RAM 中运行调试。

12. **AUTOSAR 与 MCAL 的 SPI**：AUTOSAR 分应用层、运行时环境、基础软件层，MCAL 是最底层直接操作外设的驱动。SPI 相关接口通常包括初始化、配置通道、异步传输（`Spi_AsyncTransmit`）、同步传输、获取状态与结果，配合 Job（一次具体传输任务）和 Sequence（一组 Job 的执行序列）描述传输顺序。
