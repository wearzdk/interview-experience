### 《参考解析》

**C# 与 C++ 的底层差异按四点讲。** 内存管理：C# 由 GC 回收托管堆，C++ 手动 `new` / `delete` 或智能指针；值类型与引用类型：C# 的 `struct` 在栈或内联在对象里，`class` 在托管堆，C++ 的 `struct` 与 `class` 只有默认访问权限差别；编译与运行：C# 编译成 IL，由 JIT 或 AOT 转成机器码，C++ 直接编译成机器码；泛型：C# 泛型在运行时保留类型信息（具体化），C++ 模板在编译期展开。再补一句 Unity 的 IL2CPP 把 IL 转成 C++ 再编译，能解释为什么移动端还要关心 GC 与反射开销。

**Unity 生命周期与协程。** `Awake` → `OnEnable` → `Start` → 每帧 `FixedUpdate`（物理）→ `Update` → `LateUpdate` → `OnDisable` → `OnDestroy`。协程由 MonoBehaviour 驱动，`yield return null` 等到下一帧，`WaitForFixedUpdate` 等物理帧，对象销毁或禁用后协程停止。资源加载要区分 Resources、AssetBundle、Addressables，关注引用计数与卸载；GC 方面避免每帧分配（字符串拼接、装箱、闭包、`GetComponent` 频繁调用），用对象池与缓存。

**图形学按渲染管线顺序回答。** 顶点数据 → 模型、视图、投影变换 → 裁剪 → 光栅化 → 片元着色（光照、纹理）→ 深度测试 → 混合输出。透明物体要关闭深度写入、按相机距离从远到近排序；半透明混合依赖 `srcAlpha`、`oneMinusSrcAlpha`。光照模型能讲清 Lambert 漫反射与 Blinn-Phong 高光即可；阴影用 shadow map，要提到偏移与分辨率导致的锯齿。被追问时把「为什么这样排」讲出来，比背术语更有效。

**设计模式要绑定场景。** 例如对象池用于子弹与特效、状态机用于角色行为、观察者用于 UI 与事件、命令模式用于撤销。回答结构是「当时的问题、为什么选这个模式、代价是什么」，不要只报模式名。

**转行动机讲成可验证的路径。** 土木背景转游戏，面试官关心的是基础是否补齐、是否有持续投入。可以讲自学路线（C# → Unity → 图形学 → 小项目）、做过的完整作品、遇到的坑与修复，以及测试题里体现的工程习惯。帖主复盘的结论是「相比科班差了许多基础知识，网游开发经验过少」，这是准确的自我判断：补 C# 语言特性、数据结构与网络同步，比再堆一个 demo 更有用。
