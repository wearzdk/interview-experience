### 《面试题目》

1. 英文自我介绍。
2. Java 和 Python 的区别（英文作答）。
3. 解释性语言和编译性语言的区别。
4. 面向对象编程和面向过程编程的区别。
5. 用面向对象编程设计一个系统，并追问设计。
6. 用面向对象编程设计第二个系统，并追问设计。
7. 三道 MySQL 八股。
8. 二面：介绍一个后端项目，追问后端八股。
9. 三面：你的 RAG 系统里文章数量有多少？
10. 在这个文章数量下，是不是可以用另一种方法？
11. Agent 相关八股。
12. 用英文表达自己找工作的期望。
13. 用英文表达对这个岗位的理解和期望。
14. 反问。

### 《参考解析》

**解释性语言与编译性语言**：编译型语言在运行前把源码整体翻译成机器码，运行时直接执行，启动快、执行效率高，但跨平台需要重新编译（C、C++、Go）；解释型语言在运行时逐行翻译执行，跨平台性好、开发迭代快，但执行效率较低（Python、Ruby）。Java 是混合模式：先编译成字节码，再由 JVM 解释执行，热点代码由 JIT 编译成机器码。现代语言界限模糊，Python 也有字节码编译，JavaScript 有 JIT。回答时点出「编译与解释是执行策略，不是语言属性」会更准确。

**面向对象与面向过程**：面向过程以「步骤」为中心，把问题拆成函数与数据流，适合逻辑线性、状态少的场景；面向对象以「对象」为中心，把数据与行为封装在一起，通过接口与多态应对变化，适合领域模型复杂、需要扩展的场景。设计一个系统时的答题结构：先列领域实体与职责、再定义实体间关系与接口、再说明扩展点（新增类型时改哪里）、最后讲取舍（为什么不用继承而用组合）。

**英文表达岗位理解**：准备三个短句即可：这个岗位做什么（build and maintain backend services for X）、需要什么能力（distributed systems, API design, reliability）、我为什么匹配（做过什么、能带来什么）。发音不必完美，重点是结构清楚、不背长句。

**RAG 文章数量与方案选择**：文章数量决定检索策略。几百到几千篇可以用向量检索加关键词混合召回，全量放内存索引也够；上万到十万级要考虑分片索引、增量更新与元数据过滤；百万级以上要引入专用向量数据库、分层召回（先粗排再精排）与缓存。另一个维度是「是否真的需要 RAG」：如果文章总量很小且更新不频繁，直接把全文放进上下文（长上下文模型）可能更简单、更准；如果问题集中在少数文档，用关键词或结构化查询更快。面试官问「这个数量下是不是可以用另一种方法」，考的是你会不会按规模与更新频率选方案，而不是默认上向量库。

**Agent 相关**：准备三个概念的区别：工作流编排（固定步骤）、Agent（模型自主规划与调用工具）、多 Agent（分工与协作）。再准备一个你实际做过的例子，说清工具定义、失败重试、上下文管理与评测方式。

**三面挂掉的复盘方向**：三面通常考深度与匹配度，失分常见于「项目讲得浅、方案说不出取舍」。改进是把每个项目准备到能回答「为什么不用另一种方案」「数据量变大十倍怎么办」「失败了怎么发现」。
