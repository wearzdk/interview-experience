### 《面试题目》

1. 自我介绍。
2. Skill 和 MCP 的 token 消耗对比？如果基础配置长度相同呢？
3. 一个 query 输入到 Agent 到输出结果的完整流程是怎样的？
4. AI 开发的流程是什么？
5. 工作中排查代码问题的流程是什么？
6. 怎么判断一个 Skill 是不是足够好？
7. 平时怎么学习最新的知识？
8. AI Coding 题：拆解任务、完成实现、测试，再开一个新窗口对比实现与需求。

### 《参考解析》

**Skill 与 MCP 的 token 消耗差异在「注入方式」**。MCP 是常驻的工具定义，每个工具的名称、描述、参数 schema 都会进上下文，工具多了基础开销就大；Skill 更像按需加载的能力包，先给一句描述，命中后再展开详细指令和资源，静态开销小。如果基础配置长度相同，差异主要在「按需展开的时机」和「工具结果的回灌量」，要结合具体场景说，别一口咬定谁更省。

**一个 query 的链路**：用户输入 → 意图识别与路由 → 组装上下文（系统提示、历史、检索、工具定义）→ 模型决策（直接回答 / 调工具 / 追问）→ 工具执行与结果回灌 → 循环直到终止 → 输出与落库。每一段都要有超时、重试和日志。

**判断 Skill 好不好，看四点**：触发是否准确（该用的时候用、不该用的时候不误触发）、工具调用是否正确（选对工具、参数合法）、执行是否稳定（失败可恢复、有兜底）、安全边界是否清楚（权限、敏感操作确认）。再配上评测集和线上埋点。

**AI Coding 题的答法是「先对齐再动手」**：读需求列验收点 → 拆成小任务 → 让 AI 实现 → 自己跑测试和边界用例 → 开新窗口让另一个模型对照需求 review。这套流程本身就是考点。
